# Risks And Open Questions

## 가장 큰 리스크

Phase 0 검증이 아직 없다. 기획과 POC는 많지만 실제 사용자가 체크리스트를 받았을 때 쓰는지 검증된 데이터가 없다.

이번 주 우선 액션:

1. 백신 접종 체크리스트 또는 이유식 4개월 시작 체크리스트를 하나 만든다.
2. 지인 부모 10명에게 보낸다.
3. 실제 사용 여부, 복사/저장 여부, 피드백을 받는다.
4. 10명 중 5명이 실제 사용하면 Web MVP를 진행한다.

## 제품 리스크

- 비전이 크다. 체크리스트, 소셜, 광고, 토큰, 포트폴리오, 매칭을 한 번에 말하면 초점이 흐려진다.
- MVP 카피는 "복붙해서 바로 시작"과 실제 동작이 일치해야 한다. Phase 1이 클립보드/CSV라면 문구도 그렇게 명확해야 한다.
- 첫 카테고리인 육아는 강한 수요가 있지만 건강/의료성 정보 리스크가 있다. 공인 정보 기반 백신 체크리스트처럼 안전한 시작점이 낫다.
- 제작자 락인 전략이 미검증이다. 통계 대시보드, 수익 정산, 인증 뱃지, 광고 매칭은 후보일 뿐이다.

## 기술 리스크

- Versioning: 제작자 항목 수정이 사용자 체크 데이터를 깨면 안 된다. Immutable item row 정책이 필요하다.
- AI scraping: Claude API는 URL을 직접 읽지 못한다. Jina Reader 또는 유사한 본문 추출 계층이 필요하다.
- OAuth: Google Calendar/Sheets write scope는 심사 병목이 있다. Phase 1에서는 클립보드/CSV로 피한다.
- Supabase 무료 플랜 한계는 MVP 단계에서는 낮은 리스크지만, 성장 시점에 비용/쿼리 최적화가 필요하다.

## 남은 의사결정

### MVP 카테고리

최신 문서는 육아를 권장하지만, 실제 Phase 0 결과를 보고 유지/변경한다.

후보:

- 백신 접종 체크리스트: 명확하고 긴급도가 높음.
- 이유식 4개월 시작: 단계형 구조 검증.
- 어린이집 입소 D-90: timeline형 검증.

### 비로그인 미리보기 범위

옵션:

- 전체 공개: 전환 설득에 유리.
- 일부 공개 후 로그인: 가입 전환에 유리하지만 이탈 위험.

초기 권장: 전체 또는 거의 전체 공개. 로그인 장벽을 늦춘다.

### D-day/anchor 입력 타이밍

옵션:

- 상세 페이지에서 먼저 입력해 미리보기.
- CTA 후 입력.
- 로그인 후 입력.

초기 권장: 공개 상세에서는 선택적 미리보기, 실제 저장은 CTA 후 입력.

### 오늘 할 일 기준

실행 앱으로 확장할 때 결정한다.

- 날짜가 도달한 항목.
- 선행 조건이 완료되어 시작 가능한 항목.
- 두 조건의 교집합.

의존성 UX를 강조하려면 교집합이 가장 명확하지만, 초기에는 단순 날짜 기준이 빠르다.

### 연쇄 조정 UI

옵션:

- 토스트: 빠르지만 변경 이해가 약함.
- 모달: 명확하지만 흐름을 끊음.
- 인라인 배너: 변경 맥락 보존.

권장: 변경이 1개면 토스트/배너, 여러 개면 미리보기 모달.

## 중장기 보류

- 토큰/코인.
- 코호트 커뮤니티.
- 지인 피드.
- 헤드헌팅/소개팅/매칭.
- 광고 경매.
- 네이티브 모바일 앱.
- AR/VR, IoT.

이 기능들은 핵심 검증 이후에만 논의한다.
