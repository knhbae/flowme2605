# FLOW Agent Entry Point

This repository uses a lean, AI-agnostic harness. `agent.md` contains the concise FlowMe guardrails; detailed product truth stays in the linked canonical documents.

Repo skills live canonically under `.agents/skills/`. `CLAUDE.md` is a one-line `@AGENTS.md` adapter, `.claude/skills/` is generated by `npm run skills:sync`, and `npm run skills:install:codex` refreshes optional Codex user-scope copies for tasks opened above the repo root.

## Default Start

1. Read [agent.md](./agent.md).
2. Read the user's request and the files, code, and tests directly involved.
3. Before editing, inspect current Git state and treat every pre-existing dirty path as unowned.
4. Load additional context only through the task routes below. Do not sweep the full document graph for a small, clear task.

Use `npm run workflow:session-start` only for a new or resumed broad task, a context switch, overall status/release review, or work in a mixed or unclear worktree.

## Context Routes

| Task | Add this context |
| --- | --- |
| Current status, priorities, or what comes next | [STATUS.md](./docs/STATUS.md) and [ROADMAP.md](./docs/ROADMAP.md) |
| Product direction, UX, or content policy | [PRODUCT_PRINCIPLES.md](./docs/PRODUCT_PRINCIPLES.md), relevant entries in [DECISIONS.md](./docs/DECISIONS.md), and the matching FLOW skill |
| Deferred direction or idea review | Relevant entries in [IDEAS.md](./docs/IDEAS.md); do not load it by default for implementation |
| Routes, components, data ownership, or architecture | [SERVICE_STRUCTURE.md](./docs/SERVICE_STRUCTURE.md) and the relevant code/tests |
| Tooling, harness, CI, hooks, or release process | [TOOLING.md](./docs/TOOLING.md), [harness README](./docs/harness/README.md), and the specific QA/workflow document involved |
| Approved multi-step work | The relevant folder under [docs/specs](./docs/specs/README.md) |
| UX/calendar/todo/routine research | [REFERENCE.md](./docs/REFERENCE.md) only when external-pattern context is needed |

Search large logs such as `DECISIONS.md` and `IDEAS.md` for request-relevant terms before reading them end to end.

## Working Policy

- Treat user statements as situated evidence, discomfort, or desired direction unless they are explicit instructions. Judge from evidence, assumptions, and tradeoffs; neither user nor agent is automatically correct.
- Identify relevant unstated constraints and risks, but label inference as inference.
- Prefer the repo's existing patterns and the smallest change that handles the request.
- For substantial work, separate product framing, implementation, review, and evidence/QA passes. Use only the specialist lenses needed from [ROLES.md](./docs/harness/ROLES.md); do not create a default role swarm.
- Use Request Interview only when unresolved ambiguity could materially alter scope, risk, product direction, or success evidence.
- Capture only durable decisions, actionable deferred ideas, approved specs, current blockers, or release facts. Do not turn every conversational thought into project memory.
- Keep the repo canonical. Project to Notion only when a human decision, review, or external action is active.
- Never edit `.env`, credentials, `old/`, `claude_ver/`, or legacy dumps unless the user explicitly asks.

## Verification

| Change | Minimum check |
| --- | --- |
| Docs, policy, skill, or harness | `npm run docs:check` |
| Pure logic | Targeted test, then `npm test` when shared behavior changes |
| Runtime or app behavior | `npm test` and `npm run build` |
| User-facing route or flow | Relevant browser/E2E check in addition to logic/build checks |
| Dependency or release tooling | `npm run security:audit`, `npm run docs:check`, `npm test`, and `npm run build` |

Git hooks and CI remain the deterministic enforcement layer. Run `npm run workflow:closeout` only for substantial completion, handoff, commit/push/PR/merge/deploy work, overall status reporting, or a mixed worktree that needs scoped ownership evidence.

Core commands:

```powershell
npm run docs:check
npm test
npm run build
npm run test:e2e
npm run dev
```
