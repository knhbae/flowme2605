P4는 닫혔다.
남은 싸움은 겹침과 날짜, 그리고 반복되는 라벨이다.

이번엔 스크린샷을 픽셀로 직접 확인했습니다. 지난 라운드의 High 3종("…Flow" 접미 · 저장 직후 raw ISO · "검수 필요" 배지)은 화면에서 실제로 사라졌습니다. 홈은 가벼워졌고, 저장 목록은 행당 카운트 1종으로 정리됐고, 공유 shell→앱 shell 전환도 성립합니다. 그래서 P4-01~05는 모두 close 가능. 대신 픽셀에서만 보이는 세 가지 새 문제가 P5입니다: ① 하단 sticky 바가 마지막 행·보조 CTA를 가림(공유·냉장고·세탁기 반복), ② "먼저 할 일/밀린 할 일" 라벨이 한 화면에 2~3번, ③ workbench·공유 확인부에 raw ISO가 아직 남음.

SECTION 1

P4-01 ~ P4-05 닫힘 / 재오픈 판정

audit.md의 P4 정의 기준. 5개 전부 close. 단, 2건은 close + 파생 P5(원 항목은 닫히되 픽셀에서 새 문제가 갈라져 나옴).

P4-01

제목 "…Flow" 접미 제거

CLOSE ✓

확인 · 홈("원룸 이사 D-30"), /flows("원룸 이사 D-30" · "중1 수학 목차 진도"), /f/("자동차검사 D-14 준비"), 저장 목록("원룸 이사 준비"), 캘린더까지 제목 끝 "Flow"가 전부 사라짐. 브랜드/탭 문맥의 FLOW·Flow 찾기·내 Flow는 유지. baseline 위반 해소.

파생 P5(작음) · 대신 "…일정 지도"(Flow Map의 한글 잔재)와 source slug("Mathbang 중1 목차")가 부제목에 노출. → §5 P5-06.

P4-02/03

공개 /f/ 공유 shell + 저장 CTA

CLOSE + 파생 P5

확인 · 4탭 없는 공유 shell 유지, 하단 단일 "내 Flow에 저장" sticky, 저장 후 sticky가 "저장됨 · 내 Flow에서 보기"로 바뀌며 헤더 CTA도 전환(s03-03). 공유→앱 이어짐 성립.

파생 P5 · ① sticky 바가 그 아래 "검사일 입력으로 시작" 버튼을 절반 가림(s03-01/03). ② 저장 전 입력부가 [검사일+입력] + "또는" + 3선택지로 과밀. ③ 저장 확인 문구에 raw ISO "2026-07-17". → P5-02·P5-05.

P4-04

홈 설명형 카드 축소

CLOSE ✓

확인 · 홈이 headline + 단일 primary CTA("콘텐츠 고르러 가기") + 대표 추천 카드 1장으로 압축(01-home). "시작 경로"식 단계 설명 스택 사라짐. 첫 화면이 설명서가 아니라 입구로 읽힘. baseline 부합.

P4-05

특수 workbench visual polish

CLOSE + 파생 P5

확인 · 냉장고 시트(s06-04)·세탁기 관리(s06-06)·이유식·홈트 모두 warm 배경 + #E7E4DD border + 16px card + 결과 중심 sticky("캘린더 파일 받기")로 하나의 FlowMe 앱처럼 보임. slate/blue utility 잔재 눈에 안 띔.

파생 P5 · ① sticky 진행률 바가 시트/리스트 마지막 행을 가림(s06-04/06). ② 세탁기 반복 관리일이 raw ISO 리스트("2026-07-05 이번 관리일"). ③ 빈 시트가 placeholder 행만 반복돼 미기입 폼처럼 보임. → P5-02·P5-05·P5-07.

종합 판정

P4-01 · P4-04 = 완전 close. P4-02/03 · P4-05 = 원 항목 close이되 픽셀에서 파생 문제가 나와 P5로 승계. 재오픈해야 할 P4 항목은 없음. 지난 라운드 High 3종이 모두 화면에서 사라진 것은 실질 진전입니다.

SECTION 2

Route별 UX/UI 문제

근거는 스크린샷 파일명. 상태 배지는 이번 픽셀 판정.

/

홈

양호

headline·primary CTA·추천 카드 1장으로 가벼움(01-home). 사소 · CTA 아래 "저장한 콘텐츠 보기 · 캘린더 보기" 텍스트 링크 2개가 primary와 근접해 시선이 분산될 여지. 유지해도 무방.

/flows

Flow 찾기

밀도·CTA 문구

제목 접미 해소 ✓, "무엇을 저장할까요?" 헤더·결과 약속·먼저 할 일 칩 좋음(02-flows). 문제 1 · 카드마다 full-width 파란 버튼 "저장 전 보기"가 들어가 390px에서 카드 1.7장만 보임 — 스캔이 느리고 버튼 무게가 카드 정보를 압도. 문제 2 · "저장 전 보기" 문구가 모호(저장하러 가는 건지, 미리 보는 건지). → 카드 CTA는 무게를 낮추고 "열어보기/저장하러 가기"류로. (P5-04)

/f/[slug]

공개 Flow 상세 (공유 shell)

겹침·입력 과밀

shell·단일 저장 CTA·저장 후 전환 성립 ✓. 문제 1(가림) · 하단 저장 sticky가 그 아래 "검사일 입력으로 시작" 버튼을 절반 덮음(s03-01/03-public). 문제 2(과밀) · 저장 전에 [검사일 입력]+[입력]+"또는"+[아직 안 정함]+[예시로 둘러보기]+미리보기까지 선택지 6개 — 주 입력 1개가 안 보임. 문제 3 · 저장 확인 "2026-07-17" raw ISO. → P5-02·P5-05.

/my?savedMap=

저장 직후 · 내 Flow

ISO 해소 ✓ 라벨 중복

"저장됨" 칩 + 첫 실행 항목 + "먼저 열기" 패널 확인(14-post-save). raw ISO 사라지고 "6월 22일" 표기 ✓. 문제(중복) · 그 아래 "밀린 할 일" 섹션에서 eyebrow "밀린 할 일" + 카드 제목 "밀린 할 일" + 카드 내부 "밀린 할 일"이 3번 반복. 수학 fallback도 "먼저 할 일" 3번(s04-02). 같은 라벨이 세로로 쌓여 정보가 아니라 잡음. → P5-03.

/my (전체)

반복 사용자 저장 목록

양호

"2개 저장 · 13개 남음 / 다음 1 · 밀림 1" 요약 + 행당 "0/5 완료" 하나 + 진행바 + 다음 할 일 프리뷰(s05-02). 지난 라운드 done/total+% 이중 카운트 해소 ✓, "검수 필요" 배지 없음 ✓. 스캔 빠름. 유지.

/calendar

캘린더 (저장 후)

양호

모바일 선택일 agenda가 월 그리드 위에 먼저(15-calendar). 지난 라운드 "N일정·N루틴·N남음" 3중 카운트 안 보임 — schedule-first 성립 ✓. 확인요 · 마지막 agenda 행이 하단 4탭에 가리는지(§5 P5-02 공통).

workbench /f/

냉장고·세탁기·이유식·홈트

겹침·ISO

톤·카드·결과 sticky 통일로 하나의 앱처럼 보임 ✓(P4-05). 문제 1 · 진행률 sticky가 시트/리스트 마지막 행을 가림(s06-04/06). 문제 2 · 세탁기 반복 관리일이 raw ISO 리스트(s06-06). 문제 3 · 냉장고 빈 시트가 placeholder 행 반복이라 미기입 폼처럼 보임(s06-04).

SECTION 3

Scenario별 UX/UI 문제

s01 처음 온 사용자 — 통과

홈 → Flow 찾기 → 첫 카드까지 정보량이 상용 수준으로 낮음. 유일한 걸림돌은 카드 CTA "저장 전 보기" 문구·무게(P5-04).

s02 이사 D-30 저장 → My Flow → 캘린더

저장 후 첫 항목·"먼저 열기"·캘린더 agenda 전부 동작 ✓. 걸림돌 = 저장 직후 "밀린 할 일" 라벨 3중 반복(P5-03).

s03 공유 링크 저장 — 겹침

저장→"내 Flow에서 보기" 전환은 매끄러움 ✓. 저장 CTA sticky가 아래 보조 버튼을 가리고, 입력 선택지 6개가 과밀. 공유는 앱 밖 첫 인상이라 파급 큼(P5-01·P5-02·P5-05).

s04 날짜 없는 콘텐츠(수학) — 통과

저장 후 빈 상태 대신 "1. 소인수분해" fallback 첫 항목 + "날짜 없음" 배지 ✓. 지난 최대 우려 닫힘. 잔여 = "먼저 할 일" 라벨 3중(P5-03) + "Mathbang" slug(P5-06).

s05 반복 사용자 — 통과

방금 저장분과 기존 저장분이 충돌 없이 목록화, 행당 카운트 1종. 반복 사용자 스캔 빠름. 신규 문제 없음.

s06 특수 workbench/export

export-first·시트·이유식·홈트·세탁기 모두 결과 라벨("캘린더 파일 받기") 예측 가능, 톤 통일 ✓. 잔여 = sticky 겹침 + raw ISO + 빈 시트 폼감(P5-02·P5-05·P5-07).

SECTION 4

Blocking / High / Medium / Low

Blocking — 없음

찾기→저장→실행→캘린더/공유→앱 전환 흐름을 끊는 문제는 픽셀에서 관측되지 않음. 아래는 모두 흐름을 막지 않으나 실행 앱 신뢰·완성도를 깎는 항목.

High — 가림 = 기능 손실 위험

HI-1하단 sticky 바가 마지막 행·보조 CTA를 가림 (다중 route 반복)

공유 /f/의 "검사일 입력으로 시작" 버튼, 냉장고 시트 마지막 재고 행, 세탁기 관리일 리스트가 저장/진행률 sticky 뒤로 잘림(s03-01/03·s06-04/06). 콘텐츠 영역에 sticky 높이만큼 하단 패딩이 없어 실제 조작 대상이 손가락에 안 닿음. 캘린더·저장 목록 마지막 행도 동일 리스크. → 스크롤 컨테이너에 padding-bottom(=sticky+safe-area) 일괄. (P5-02)

Medium — 밀도 · 문구 · 잔여 ISO

ME-1"먼저 할 일 / 밀린 할 일" 라벨 2~3중 반복 — eyebrow+제목+카드가 같은 말. 섹션 라벨 1회로. (P5-03)

ME-2공유 /f/ 저장 전 입력 과밀 — 주 입력 1 + 대안 5. "그냥 예시로 둘러보기"를 접거나 후순위로. (P5-05)

ME-3잔여 raw ISO — 공유 저장 확인·세탁기 관리일 리스트. formatMyFlowDisplayDate 전역 적용. (P5-05)

ME-4/flows 카드 CTA 무게·문구 — full-width 파란 버튼×카드 → 밀도↑. "저장 전 보기" 의미 모호. (P5-04)

Low — polish · tone

LO-1"…일정 지도"·source slug("Mathbang") 부제목 노출 — 표시 레이어 정리. (P5-06)

LO-2냉장고 빈 시트가 placeholder 행 반복 → 미기입 폼감. 첫 행만 활성 + 나머지 흐리게. (P5-07)

LO-3홈 CTA 아래 텍스트 링크 2개가 primary와 근접 — 간격/위계만 조정.

바로 개발 가능한 P5 백로그

위→아래가 착수 순서. 전부 표시·레이아웃·문구 정리이며 데이터/저장/실행/export 스키마는 건드리지 않음.

ID우선순위화면/영역수정 지시완료 기준검증
P5-01High 공유 /f/ 저장 CTA 공유 shell의 상시 저장 sticky를 유지하되, 화면 안에 중복된 "검사일 입력으로 시작" 버튼은 제거(=주행동 sticky 1개). 저장 후 sticky만 "내 Flow에서 보기". 공유 화면 주행동 버튼 1개, 가려진 버튼 0. /f/ 저장 e2e + 390px 샷.
P5-02High 모든 sticky 하단 바 스크롤 컨테이너에 padding-bottom: calc(sticky높이 + env(safe-area-inset-bottom) + 16px). 공유·냉장고·세탁기·캘린더·저장 목록 공통. 390px에서 마지막 행/버튼이 sticky 위로 완전히 노출. 각 route 하단 스크롤 샷.
P5-03Med My Flow 오늘/저장 직후 섹션 eyebrow·카드 제목·카드 내부에 반복되는 "먼저 할 일"·"밀린 할 일"을 섹션 헤더 1회로. 카드 안은 항목 제목만. 한 섹션에 같은 라벨 1회. 저장 직후·오늘 탭 샷 비교.
P5-04Med /flows 카드 CTA 카드 하단 full-width 파란 버튼 → 카드 전체 탭 + 우측 화살표/약한 텍스트 링크로 무게↓. "저장 전 보기" → "열어보기"(또는 결과 중심 "저장하러 가기"). 첫 뷰포트 카드 ≥2.5장, CTA 문구 일관. /flows 샷 전/후.
P5-05Med 공유 입력부 + 잔여 ISO 공유 저장 전 입력을 [날짜 입력]+[입력] 주행동만 노출, "아직 날짜 안 정함/예시로 둘러보기"는 접기(더 보기). 저장 확인·세탁기 관리일 등 raw ISO를 formatMyFlowDisplayDate로. 저장 전 주 선택지 ≤2, 사용자 표면 YYYY-MM-DD 0건. 공유·workbench 샷 + 날짜 스캔.
P5-06Low 부제목 잔여 내부어 "…일정 지도"의 "지도", source slug("Mathbang")를 표시 레이어에서 정리(원본 데이터 보존). 부제는 사람이 읽는 출처명으로. 사용자 부제목에 slug·"지도" 0건. 금지어 스캔에 추가.
P5-07Low 냉장고 등 빈 시트 저장 전 빈 시트는 첫 행만 활성, 나머지는 흐리게/접기. placeholder 반복이 미기입 폼처럼 보이지 않게. 빈 시트 첫 화면에 활성 행 1~2. 냉장고 샷 전/후.

가장 먼저 — P5-02 (sticky 하단 패딩)

여러 route에서 실제 조작 대상이 가려지는 유일한 항목이라 High. 스크롤 컨테이너 패딩 한 줄로 공유·workbench·캘린더·저장 목록이 동시에 풀립니다. 이어 P5-01(공유 저장 버튼 단일화)·P5-03(라벨 중복)은 화면별 국소 작업이라 병렬 가능합니다.

SECTION 8

특히 확인할 질문 — 답

Q. 공개 /f/ 공유 shell이 저장 전 진입 화면으로 자연스러운가?

대체로 예. 4탭 없는 단일 저장 화면 + 상시 "내 Flow에 저장"은 공유 링크 첫 인상으로 적절. 단 저장 CTA가 아래 버튼을 가리고(P5-01/02) 입력 선택지가 과밀(P5-05)해, "자연스럽다"에서 "매끄럽다"로 가려면 이 둘을 정리해야 함.

Q. 저장 후 My Flow·캘린더가 충분히 실행형 앱처럼 보이는가?

예. "저장됨" 확인 → 첫 항목 → "먼저 열기", 저장 목록 행당 진행바+다음 할 일, 캘린더 agenda-first까지 실행 앱 골격이 화면에 있음. 남은 잡음은 라벨 반복(P5-03)뿐 — 구조가 아니라 표기 문제.

Q. 특수 workbench가 하나의 FlowMe 앱처럼 보이는가?

예. 냉장고·세탁기·이유식·홈트가 같은 warm 톤·카드·결과 sticky를 공유해 이질감 없음. P4-05 목표 달성. 잔여는 sticky 겹침·raw ISO·빈 시트 폼감(P5-02/05/07)으로 완성도 영역.

Q. 홈·Flow 찾기 정보량이 상용 서비스 수준으로 낮아졌는가?

홈은 예. 입구로서 충분히 가벼움. Flow 찾기는 거의. 정보량 자체는 낮지만 카드마다 full-width 버튼이 밀도를 되올림 — CTA 경량화(P5-04)로 마무리.

Q. 다음 루프는 어디부터?

P5-02(sticky 하단 패딩) → P5-01(공유 저장 버튼 단일화) → P5-03(라벨 중복) → P5-05(입력·ISO). 앞 둘은 "가려서 못 누름"을 없애는 기능 안전 작업이라 최우선, 뒤는 신뢰·밀도 마감입니다.
