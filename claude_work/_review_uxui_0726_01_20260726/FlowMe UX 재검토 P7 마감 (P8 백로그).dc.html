SECTION 1

P7-01 ~ P7-06 — 실제 화면 유지 판정

6개 전부 화면에서 유지 확인. 다만 P7-01·P7-06은 잔여 정리/일반화가 남은 조건부 유지.

P7-01

/restart 친화 날짜 + 조용한 export 위계

유지 ✓ (잔여 정리 있음)

날짜는 해결됨 · 할 일 행이 "D-30 · 2026-05-28"에서 "5월 28일 (목) · D-30"으로 바뀌었습니다(s21). restart raw ISO 스캔 0. 하단 sticky도 "내 도구로 가져가기" 단일 버튼(restartExportButtons [1,1,1]). 다만 잔여 · 본문에 "내 도구로 가져가기" 인라인 4버튼 블록이 그대로 있고 하단 sticky와 같은 제목이 두 번 노출됩니다(s22). 스캔은 sticky testid만 세어 인라인 4버튼을 못 봅니다. → P8-02.

P7-02

오늘/다음/밀린 큐 dedupe

유지 ✓

확인 · 다중 저장 상태에서 오늘·다음은 인라인("오늘 실행 1개" + "다음 항목 3개", 서로 다른 제목), 밀린 항목은 "지난 일정" 시트로 분리(s16·s17, 시트 4행)됩니다. 인라인에 보인 "필기와 실기 시험 범위 나누기"(오늘)와 시트의 "이사 방식 정하기"(지난) 등 같은 제목이 두 큐에 동시 노출되지 않음. P5의 "제목 세로 반복"이 밀도 상태에서도 재발하지 않았습니다.

P7-03

5개+ 긴 목록 하단 clearance

유지 ✓

확인 · 6개 저장 상태(s18 "6개 저장 · 111개 남음")에서 전체 탭 목록과 재고 시트 하단까지 확인. 재고 시트 최하단 행 "컴퓨터활용능력 학습"이 잘리지 않고 완전 노출(s20). P6-02의 2개 저장 한계가 실제 긴 목록으로 메워졌습니다.

P7-04

홈 추천 = 소수 큐레이션(고정 1개 아님)

유지 ✓

확인 · 홈 "바로 시작 · 2개 추천"으로 "원룸 이사 D-30"(primary) + "중1 수학 목차 진도" 2장(s01, homeRecommendationCards: 2). P6의 고정 1개 실험이 소수 큐레이션 세트로 바뀌었고, 홈은 여전히 primary 1 + 추천으로 가벼움 유지.

P7-05

공개 /f 브라우즈 링크 = 저장의 보조

유지 ✓ (관찰 1건)

확인 · 공개 /f 저장형에서 "내 Flow에 저장"이 주행동, "콘텐츠 더 보기"는 상단 보조로 유지(s06, browseLinkSecondaryCandidate: true). 관찰 · DOM/탭 순서상 "콘텐츠 더 보기"가 저장 CTA보다 앞에 옵니다(우상단 배치라 시각적으로는 보조지만, 키보드/보조기술 순서에서는 저장보다 먼저 닿음) — 위계는 통과, 순서만 P8 관찰.

P7-06

회귀 스캔 = 상시 green

현재 green · 그러나 일반화 부족

현재 화면은 전 버킷 0이 맞습니다. 하지만 스캔이 잡는 대상이 레거시 문자열에 하드코딩돼 있어, 같은 회귀가 새 seed·새 브랜드·새 제목으로 재유입되면 통과해 버립니다. 이건 화면 결함이 아니라 guardrail 설계 결함이라 별도 섹션으로 뜯었습니다 → Section 3, 조치는 P8-01(High).

종합 판정

P7-01 ~ P7-06 = 화면 기준 전부 유지(6/6). 정상 라우트 Blocking·High·Medium = 0, 되돌린 회귀 = 0. 이번 루프의 결론은 "화면은 출시 가능, 그러나 guardrail은 아직 출시 가능이 아니다"입니다. P8은 화면을 더 다듬는 루프가 아니라 가드레일을 일반화해 회귀 방지를 진짜로 잠그는 루프여야 합니다. 화면 잔여는 전부 restart 프로토타입 버킷 + 라벨 통일이라 Medium 이하입니다.

SECTION 3 · 핵심

P7-06 guardrail은 충분한가? — 부분적으로 아니다

스캔 소스(capture-…mjs의 scanPage + spec.ts의 헬퍼)를 직접 읽고 찾은 구멍 6개. 전부 "지금은 0이지만 다음 회귀를 못 잡는" 종류입니다.

① slug 스캔이 AJD·Mathbang 두 개만 하드코딩

// capture 스캔
const sourceSlugTerms = [/\bAJD\b/, /\bMathbang\b/];
// E2E는 더 좁음 — AJD 뒤에 한글/D-가 와야만 실패
expect(text).not.toMatch(/\bAJD\s+(?:[가-힣A-Z0-9]|D-)/i);

앱에는 겟차 · 차근차근 모빌리티 · TS한국교통안전공단 · 생활 루틴 코치 · 펀맘 · FLOW 큐레이션팀 등 브랜드가 이미 여럿입니다. 새 seed가 다른 브랜드 slug를 제목·부제로 흘려도 이 스캔은 통과합니다. 사용자 기준 3의 "AJD, Mathbang 같은 slug"는 클래스인데, 스캔은 두 인스턴스만 봅니다.

② raw ISO 스캔이 "원문/근거/URL 포함 줄"을 통째로 면제

const rawIsoLines = lines
  .filter(line => /\b20\d{2}-\d{2}-\d{2}\b/.test(line))
  .filter(line => !/source|원문|근거|https?:|\.com|\.kr|\.net/i.test(line));

이 앱은 거의 모든 카드에 "원문 보기"가 붙습니다. 그래서 raw ISO가 출처 줄 근처에 다시 새어도 면제 필터에 걸려 0으로 집계됩니다. 실제로 restart 날짜 행("D-30 · 2026-05-28")은 원문이 없어서 이번엔 잡혔지만, source 카드 안에서 재발하면 놓칩니다. (E2E expectNoUserFacingRawIsoDate는 면제가 없어 더 낫지만, 고정 route 목록에만 돕니다.)

③ 제목 반복 스캔이 화면에 없는 문자열을 세고 있음 (dead check)

movingFirstTaskTitle: countText('이사 방식과 견적 후보 정하기'),
// 그러나 s13 화면의 실제 제목은 "이사 방식 정하기"
// → countText 가 0 을 돌려주고 검사는 공허하게 통과
expectTextOccurrenceAtMost(section, '이사 방식과 견적 후보 정하기', 1);

반복 방지 스캔이 특정 seed 제목 문자열에 묶여 있는데, 그중 하나(이사 방식과 견적 후보 정하기)는 현재 표시 제목(이사 방식 정하기)과 불일치합니다. 즉 /my?savedMap=moving-d30 경로에서 이 반복 가드는 사실상 죽어 있고, 실제 제목이 두 번 나와도 통과합니다. "제목 1회" 유지가 스캔이 아니라 눈으로만 지켜지는 상태.

④ 구조형 표현 스캔이 "지도" 계열만 — 새 구조어를 못 봄

structuralDisplayTerms는 일정 지도 / 저장한 지도 / 지도 일정 / 지도 루틴 4개뿐. 화면에는 이미 "Flow 상태판"(지난 일정 시트 헤더, s17), "생성된 캘린더"(restart, s21), eyebrow "restart / moving-d30" 같은 다른 계열의 구조형/내부 표현이 있습니다. 지금은 대부분 프로토타입/시트라 정상 라우트 위반은 아니지만, "지도"만 막는 스캔은 구조어 클래스 전체를 대표하지 못합니다.

⑤ 하단 clearance가 요약 JSON에서 수치로 단언되지 않음

스캔은 fixedRects(sticky·탭·export bar의 top/bottom)를 기록만 하고, "마지막 콘텐츠 bottom ≤ 고정 레이어 top − 16"을 summary에서 계산하지 않습니다. 실제 clearance 단언은 E2E expectElementClearsFixedLayer에만 있는데, 대상이 moving-d30 · math-1 · vehicle · fridge · washer 몇 개 route로 하드코딩입니다. 나머지 다수 /f 워크벤치(신차·중고차 등 4000px+ 페이지)는 clearance가 자동 단언되지 않고 스크린샷 눈검사에 의존합니다.

⑥ 카운터가 히어로 부제로 오염 (신호가 흐려짐)

My Flow 히어로 부제가 "오늘, 다음, 밀린 할 일을 먼저 봅니다."라서, overdueLabel·nextTaskLabel 카운트가 부제 한 줄 때문에 +1씩 잡힙니다. 예: 밀린 섹션이 없는 날짜 없는 수학 화면(s15)도 overdueLabel: 1. 위반은 아니지만, 반복 카운터를 신호로 쓰려면 설명 부제를 카운트에서 제외해야 숫자가 의미를 갖습니다.

그래서 결론

P7-06은 "현재 동결된 화면이 깨끗하다"는 증빙으로는 충분합니다(스냅샷 + E2E). 하지만 "미래 회귀를 막는 상시 가드"로는 부분적으로 불충분합니다 — slug 2개·제목 문자열·"원문 줄 면제" 때문에 새 seed로 같은 회귀가 재유입되면 통과합니다. 사용자 기준 2·3에 대한 정확한 답은: 지금 위험 낮음, 그러나 확장 시 중간 위험 — 가드를 일반화하기 전까지. 이게 P8-01(High)입니다.

SECTION 4

Blocking / High / Medium / Low

Blocking — 없음

찾기→저장→실행→캘린더/공유를 끊는 문제 0.

High(화면) — 없음

정상 라우트 사용자 화면에 High 결함 0. 신규 회귀 0.

High(프로세스) — 1

P8-01 guardrail 일반화. 화면이 아니라 회귀 방지력의 High.
