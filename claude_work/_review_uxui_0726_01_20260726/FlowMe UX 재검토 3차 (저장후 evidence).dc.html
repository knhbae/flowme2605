SECTION 1

전체 UX/UI 총평

FlowMe는 이제 저장 전·후 모두 실행형 앱의 골격을 갖췄다. 마지막 남은 "설명형 냄새"는 화면 구조가 아니라 단어와 숫자에서 난다.

이번에 닫힌 것 (진짜 진전)

  • 저장 직후 post-save 패널이 첫 실행 항목을 렌더 + "먼저 할 일 열기"
  • 날짜 없는 콘텐츠(수학)도 빈 상태 대신 fallback 첫 항목 (하네스 assert 확인)
  • 캘린더가 선택일 agenda + 그리드로 실행 가능
  • 오늘 카드가 formatMyFlowDisplayDate로 "M월 D일" 표기

가장 크게 남은 것

  • "…Flow" 접미가 seed 제목 40여 개에 전면적으로 — 모든 route로 노출 (baseline 위반)
  • 저장 직후 요약에 raw ISO "다음 일정 2026-07-22"
  • 저장 목록 행에 "검수 필요" 배지 + done/total·% 중복 카운트

밀도가 아직 높은 곳

  • 오늘 탭: "지금 이어하기" 카드 + "오늘 할 일" 카드 2겹 (제목 중복)
  • 캘린더 선택일: "N개 일정 · N개 루틴 · N개 남음" 3중 카운트
  • 공개 /f/ hero + "Flow"를 콘텐츠 뜻으로 쓰는 체크 화면 문구

설명형 vs 실행형

구조는 실행형. 남은 설명형 신호는 문구·카운트뿐.

찾기→저장→다음 행동

저장 후 "먼저 할 일 열기"로 한 번에 이어짐. 코드상 끊김 없음.

저장 후 정보 과잉?

부분적으로 예 — 카드 2겹·3중 카운트·배지.

CTA·밀도는 양호. 탭 겹침은 픽셀 확인 필요(§7).

SECTION 3

Blocking / High / Medium / Low

Blocking — 없음

찾기→저장→실행→캘린더 흐름을 끊는 문제는 이번 라운드에 관측되지 않음. 지난 라운드 Blocking(저장 후 빈 상태)은 fallback 첫 항목 렌더로 닫힘. 아래는 모두 흐름을 막지 않으나 "실행 앱 신뢰"를 깎는 항목.

High — 신뢰·이해를 크게 깎음

HI-1"…Flow" 제목 접미가 seed 전반에 (baseline 위반)

"이사 D-30 준비 Flow", "전세계약 전 서류 체크 Flow", "여권 재발급 준비 Flow" 등 40여 개 seed 제목이 "Flow"로 끝난다(seed-flows.ts). /flows·지도·/f/·저장 목록·post-save·캘린더 그룹까지 모든 사용자 표면으로 노출. "Flow/Step/Item 내부어 비노출" 기준의 정면 위반. → 표시 레이어 접미 스트립(데이터 보존). (P4-01)

HI-2저장 목록 "검수 필요" 배지 = 내부 검토어 노출

비데모 저장 콘텐츠에 amber "검수 필요" 배지가 뜬다(getMyFlowContentReadiness). "검수"는 review/audit 계열 내부어이고, 서비스가 추천해 저장시킨 콘텐츠가 곧바로 경고로 바뀌는 자기모순. → 카탈로그 노출 콘텐츠는 저장 후 배지 미표시(seed 정합). (P4-03)

HI-3저장 직후 요약의 raw ISO 날짜

post-save 요약이 "N개 할 일 · 다음 일정 2026-07-22"로 기계 날짜를 노출(L5299~). 저장 성공을 확인하는 첫 화면이라 인상이 크다. → formatMyFlowDisplayDate 적용 + "다음 일정" 라벨을 "다음 할 일"로. (P4-02)

Medium — 밀도·중복

ME-1저장 목록 카운트 중복 — done/total 칩 + % 칩 동시(L5378~). 진행바 + "n/n" 하나로. (P4-04)

ME-2오늘 탭 카드 2겹 — "지금 이어하기" + "오늘 할 일" 중복. 하나로 합쳐 제목 1회. (P4-05)

ME-3캘린더 선택일 3중 카운트 — "N일정·N루틴·N남음" → "N개 · N개 남음"으로. (P4-06)

ME-4체크 화면 "Flow" 개체명 — "체크할 Flow를 먼저 선택" → "체크할 콘텐츠". (P4-01 묶음)

ME-5공개 /f/ hero 밀도·저장 CTA — 카드 3장 → 인라인 칩 + 결과 한 줄, 하단 단일 저장 sticky. (P4-07)

ME-6홈 하단 설명 축소 — 추천 결과 한 줄화, 설명 카드 정리. (P4-08)

Low — polish · tone

LO-1상태어 통일 — "지난 일정 정리"·"밀림"·"밀린" → "밀린 할 일" 1개.

LO-2지도 원문 제목 코드 접두 제거, 결과 약속 2줄 이내.

LO-3데모 배지("데모 기준일" 등)는 데모 시나리오에서만 — 노출 조건 재확인.

LO-4slate/gray 잔여 유틸 → FlowMe 토큰(workbench·캘린더 카드 테두리).

SECTION 4

바로 개발 가능한 P4 백로그

위→아래가 착수 순서. 전부 표시·문구·밀도 정리이며 데이터 스키마·저장/실행/export 로직은 건드리지 않음. 줄번호는 근사치.

ID목표 · 화면UI/Copy 변경 지시완료 기준검증
P4-01 "…Flow" 접미 제거
전 사용자 표면 · seed 제목 제목 표시 유틸 toContentDisplayTitle() 추가 — 끝의 "Flow"/" Flow" 스트립. 카탈로그·지도·/f/·저장 목록·post-save·캘린더 그룹·체크 화면 헤딩("체크할 콘텐츠")에 적용. seed 원본 문자열은 보존. 사용자 라우트 렌더에 "Flow" 개체명 0건, 제목만 정상. 금지어 스캔에 "Flow$" 추가, 스냅샷.
P4-02 post-save ISO 날짜 정리
/my?savedMap= 요약 postSaveContinuationDate를 formatMyFlowDisplayDate(row.date)로. "다음 일정 2026-07-22" → "다음 할 일 · 7월 22일 (수)". 오늘/지난도 동일 포맷. post-save 요약에 YYYY-MM-DD 0건. 저장 후 요약 텍스트 e2e.
P4-03 "검수 필요" 배지 제거
저장 목록 행 카탈로그 노출(seed) 콘텐츠는 showContentReadinessBadge=false. readiness는 내부 화면에만. 저장 표면에서 review/audit 계열 단어 제거. 저장 목록에 "검수" 문구 0건. 저장 후 목록 스캔 e2e.
P4-04 저장 목록 카운트 단일화
renderFlowListRow done/total 칩 + % 칩 → 진행바 + "n/n" 하나. % 제거 또는 진행바 내부 캡션으로. 행당 진행 표기 1종. 시각 확인.
P4-05 오늘 카드 2겹 통합
now-section + today-summary "지금 이어하기"와 "오늘 할 일"을 한 카드로. 상단 = 날짜 + 남은 개수, 본문 = primary 항목 카드. 3-count 그리드는 지금처럼 sm+에서만. 오늘 탭 상단 카드 1개, "오늘 할 일" 제목 1회. 오늘 탭 스크린샷 비교.
P4-06 캘린더 카운트 압축
selected-day 요약 "N개 일정 · N개 루틴 · N개 남음" → "N개 · N개 남음"(루틴은 아이콘으로 이미 구분). 그룹 칩도 동일. 선택일 요약 카운트 ≤2. 캘린더 스크린샷.
P4-07 공개 /f/ hero 정리
PublicFlow · 공유 shell 제목 접미(P4-01 적용), 결과/입력/먼저 할 일 카드 3장 → 인라인 칩 + 결과 한 줄, 하단 persistent "내 Flow에 저장" 단일 sticky, 저장 후 /my?savedMap=로. 저장 전 읽기 블록 ≤4, 주행동 1개. /f/ 저장 e2e + 스크린샷.
P4-08 홈 하단 축소 + 상태어 통일
HomeLanding · 상태 라벨 추천 카드 결과 한 줄화, 설명 카드 정리(LO-1~4 묶음). "밀린 할 일"로 상태어 통일, slate 잔여 토큰화. 홈 스크롤 CTA→추천에서 종료, 상태어 1종. 시각 리뷰.

가장 먼저 — P4-01

저장 후 흐름이 닫힌 지금, 단일 최대 문제는 "…Flow" 접미다. 한 곳이 아니라 seed 40여 개에 박혀 모든 route에서 동시에 baseline("내부어 비노출")을 위반한다. 표시 레이어 유틸 하나면 전 화면이 한꺼번에 정리되므로 노력 대비 효과가 가장 크고, 이후 P4 항목(요약·배지·밀도)은 화면별 국소 작업이라 병렬 가능하다.
