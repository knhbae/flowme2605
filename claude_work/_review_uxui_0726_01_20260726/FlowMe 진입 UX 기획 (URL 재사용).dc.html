FLOWME · ENTRY UX URL 붙여넣기 → 기존 Flow 재사용 → 옵션 변경 → 수정/fork → export · My Flow 저장

남의 콘텐츠를 실행 가능한 계획으로.
진입은 URL 한 줄에서 시작한다.

사용자는 블로그·유튜브·공식문서·커뮤니티에서 따라 하고 싶은 계획을 발견하고 FlowMe에 그 URL을 붙여넣습니다. FlowMe는 AI를 다시 쓰기 전에 같은 URL(또는 canonical URL)의 기존 Flow를 먼저 찾습니다. 이 문서는 그 진입 여정 전체와 필요한 화면 상태, 엣지케이스 UX, MVP 범위를 제품 백로그로 옮길 수 있게 정리한 기획서입니다.

SECTION 0

진입 UX가 지켜야 할 원칙

이 여정의 모든 화면·버튼·문구는 아래 4개 원칙에서 파생됩니다. 충돌이 생기면 위쪽 원칙이 이깁니다.

01

재사용 우선, AI는 최후

URL을 받으면 가장 먼저 기존 Flow를 검색한다. AI 변환은 "없거나 품질이 낮을 때만" 켜지는 fallback이지 기본 경로가 아니다.

02

한 화면에 한 결정

"이 Flow를 쓸까 / 고칠까 / 새로 만들까"를 한 번에 묻지 않는다. 상태마다 다음 행동 1개를 primary로 세운다.

03

출처는 항상 따라다닌다

Flow는 원 콘텐츠에서 파생된 것이다. 원문 링크·작성자·변환 시점이 카드부터 상세·export까지 끊기지 않고 붙어 있어야 한다.

04

저장은 끝이 아니라 시작

저장·export는 목적이 아니라 실행으로 넘어가는 문이다. 저장 직후 "오늘 뭐부터"가 바로 보여야 한다.

비용 모델과 UX의 연결. AI 변환 1회는 비용이 든다. 그래서 "기존 Flow 발견 → 옵션만 바꿔 재사용"이 가장 빠르고 가장 싼 경로가 되도록 화면을 설계한다. 사용자가 굳이 "새로 생성"을 누르지 않게 만드는 것이 이 여정의 성공 지표다.

SECTION 1

핵심 사용자 여정

URL 한 줄에서 시작해 실행(저장/export)으로 끝나는 한 흐름. 굵은 화살표가 가장 저렴하고 흔한 경로(재사용), 점선이 fallback(AI 생성)입니다.

1

URL 붙여넣기

사용자가 블로그/유튜브/문서/커뮤니티 링크를 붙인다. 입력창 하나 + "Flow로 만들기" 버튼. 텍스트를 직접 붙여넣는 진입(메모)도 같은 입력창에서 받는다.

2

정규화 + 기존 Flow 검색 AI 안 씀

URL을 canonical로 정규화(추적 파라미터 제거, m.·모바일 도메인 통일, youtu.be→watch 등)한 뒤, 그 canonical에 이미 있는 Flow를 조회한다. 이 단계에서 비용이 갈린다.

▶ 굵은 경로 · 기존 Flow 있음

3a. 기존 Flow 보여주기

AI 재실행 없이 즉시 표시. 후보가 여럿이면 목록으로. → 옵션 변경(시작일·강도·반복·목적지) → 그대로 저장/export.

비용 0 · 가장 빠름

┈ 점선 경로 · 없음/품질 낮음

3b. AI 변환 (fallback)

기존 Flow가 없거나 품질 기준 미달일 때만 원문을 가져와 AI로 계획화. 결과를 확인 → 저장하면 그 canonical의 첫 Flow로 축적된다.

비용 발생 · 다음 사람은 다시 3a

4

내 것으로 만들기 — 옵션 변경 또는 수정/fork

옵션 변경은 원본 Flow를 건드리지 않고 내 인스턴스에만 적용(시작일·강도·반복·목적지). 내용 자체가 마음에 안 들면 fork — 내 사본을 만들어 단계를 고치고, 원본과의 관계(파생)는 유지한다.

5

실행처로 내보내기 — My Flow 저장 또는 export

최종 사용처는 FlowMe 내부 My Flow이거나 캘린더·투두·엑셀·마크다운·옵시디안 export. 저장 직후 "오늘 뭐부터"가 바로 이어진다(원칙 04).

되감기 지점

어느 상태에서도 "다른 URL 넣기"로 1단계로 복귀 가능. fork·옵션 변경은 저장 전이면 언제든 되돌릴 수 있어야 한다.

로그인 시점

검색·미리보기까지 비로그인 허용. 저장/export/fork에서만 로그인을 요구해 진입 마찰을 뒤로 미룬다.

성공 지표

전체 저장 중 3a(재사용) 비율이 클수록 성공. "새로 생성" 클릭률·AI 호출 수는 낮을수록 좋다.

SECTION 2

필요한 화면 상태 9종

한 화면(진입)의 상태 머신입니다. 각 상태마다 목적 · 첫 화면에 보일 것 · 첫 행동(primary) · 접거나 뒤로 미룰 것을 정의합니다. 색 라벨은 재사용(싸다) / AI(비쌈) / 실행 전환 계열입니다.

S1

URL 입력 전 (빈 진입)

목적"링크만 붙이면 계획이 된다"를 1초 안에 이해시킨다. 보일 것큰 입력창 1개 + "Flow로 만들기". 붙여넣기 아이콘, 예시 URL 2~3개(칩). 첫 행동URL 붙여넣기 / 예시 칩 탭. 접기기능 소개·4단계 설명은 접거나 아래로. 입력이 화면의 주인공.
S2

분석/검색 중

목적"기존 Flow를 먼저 찾는 중"임을 보여 신뢰를 준다(AI 도는 게 아님). 보일 것정규화된 URL 미리보기(도메인·제목·작성자 뱃지) + "이미 있는 Flow를 찾는 중…" 진행 문구. 첫 행동대기(취소 가능). 결과 오면 자동 전환. 접기스피너만 도는 무의미 로딩 금지 — 무엇을 하는지 문장으로.
S3

기존 Flow 발견 (단일)

굵은 경로
목적"AI 안 돌리고 바로 쓸 수 있다"를 즉시 제시. 보일 것Flow 제목·단계 수·소요·작성자/출처·"N명이 사용" 신뢰 신호 + 미리보기 3~4단계. 첫 행동"이 Flow 쓰기"(primary). 보조: 옵션 변경 · 수정/fork · 새로 생성. 접기"새로 생성"은 눈에 띄지 않는 하단 텍스트 링크로(비싼 경로).
S4

여러 후보 발견

목적같은 URL에서 파생된 여러 Flow 중 하나를 빠르게 고르게 한다. 보일 것추천 1개를 맨 위 강조(사용 수·최신·품질). 나머지는 리스트 — 작성자·강도·기간·fork수로 구분. 첫 행동추천 Flow "쓰기". 각 항목에 미리보기. 접기정렬/필터는 접어둠. 기본 정렬만 먼저.
S5

새 Flow 생성 필요

fallback
목적기존 게 없음을 알리고, AI 변환을 의식적 선택으로 만든다. 보일 것"아직 이 링크의 Flow가 없어요" + 원문 미리보기 + "AI로 Flow 만들기". 첫 생성자라는 점을 살짝 보상 문구로. 첫 행동AI 생성 시작. 접기원문이 얇거나 못 읽으면 → 텍스트 붙여넣기 대안 제시(메모 경로로 합류).
S6

생성 결과 확인

목적AI 결과를 저장 전에 검토·신뢰하게 한다. 보일 것단계 목록 + 각 단계가 원문 어디서 왔는지(근거 매핑) + 신뢰도 배지. "원문과 비교" 토글. 첫 행동저장 / 옵션 변경 / 단계 수정. 접기모델·프롬프트 등 내부 정보 노출 금지.
S7

옵션 변경

목적내용은 그대로, 내 상황에 맞게 파라미터만 조정. 보일 것시작일 · 강도(느슨↔집중) · 반복 · 목적지(export 대상). 변경 시 일정 미리보기가 즉시 갱신. 첫 행동옵션 조정 → "이대로 저장". 접기원본을 바꾸는 게 아님을 명시("내 사본에만 적용"). 고급 옵션은 더보기로.
S8

수정 / fork

목적단계 내용 자체를 바꾸되 원본과의 파생 관계는 남긴다. 보일 것"내 사본으로 편집합니다" 배너 + 단계 추가/삭제/재정렬/문구 편집. 원본 대비 변경 표시. 첫 행동단계 편집 → "내 Flow로 저장". 접기편집 없이 나가면 fork 취소 확인. 저장 시 "원본 기반 · 내가 수정" 배지 부여.
S9

export / My Flow 저장

실행 전환
목적계획을 실제 실행처로 넘기고, 바로 다음 행동을 준다. 보일 것대상 선택: My Flow / 캘린더(ics) / 투두 / 엑셀·CSV / 마크다운 / 옵시디안. 저장 직후 "오늘 할 일" 1개. 첫 행동My Flow 저장(기본) 또는 export 대상 탭. 접기"저장 완료"에서 멈추지 않기 — 빈 성공 화면 금지(기존 07·08 회귀 방지).
SECTION 3

엣지케이스를 UX로 다루는 법

"URL로 Flow를 축적한다"는 모델은 아래 5개를 못 다루면 무너집니다. 각 항목: 무엇이 문제인가 · UX가 어떻게 막는가 · 사용자가 보는 것.

E1

중복 URL · 표기 흔들림

문제같은 글이 ?utm=…, m.도메인, 앱 공유 링크, youtu.be 등 다른 모양으로 들어와 같은 Flow가 조각조각 중복 생성된다 → 축적 실패, AI 비용 낭비. UX 처리입력 즉시 canonical 정규화(추적 파라미터 제거·도메인 통일·플랫폼별 규칙). 정규화 결과를 S2에서 사용자에게 미리 보여주고, 일치하는 기존 Flow로 붙인다. 원문에 rel=canonical이 있으면 우선 신뢰. 사용자 뷰"이 링크는 원글 A와 같은 콘텐츠예요 — 이미 만들어진 Flow가 있어요" 배너.
E2

원문 변경 · Flow와 어긋남

문제Flow 생성 후 원 글이 수정·삭제되면, 저장된 Flow가 현재 원문과 달라진다. 사용자는 오래된 계획인지 모른다. UX 처리생성 시 원문 스냅샷 + content hash + 변환 시점을 저장. 재방문 때 원문 해시가 바뀌면 "원문이 업데이트됨" 배지 → "변경분 반영해 새로고침(AI 1회)" 선택지 제시. 자동 재생성은 안 함(비용·의도). 사용자 뷰Flow 상세 상단에 "2026-06-01 기준" + 원문 링크. 삭제된 원문은 스냅샷으로 계속 실행 가능.
E3

품질 낮은 Flow

문제기존 Flow가 있어도 단계가 엉성하거나 근거가 약하면, 재사용이 오히려 나쁜 경험이 된다. 품질 없는 재사용은 축적을 오염시킨다. UX 처리품질 점수(단계 구체성·근거 매핑률·완주/사용률·신고). 임계값 미만이면 S3에서 "품질 낮음 — 다시 만들까요?"로 AI 재생성을 조건부로 제안. 좋은 fork가 생기면 그걸 추천 Flow로 승격. 사용자 뷰카드에 품질/사용 신호. 낮으면 "이 Flow는 아직 다듬는 중" 톤.
E4

저작권 · 출처 표기

문제남의 콘텐츠를 계획으로 바꾸는 서비스다. 원문 전체 복제·무출처 재배포는 위험하다. UX 처리Flow는 원문의 절차 요약(변형 저작물)이지 본문 복붙이 아니게 만든다. 원문 링크·작성자·매체를 카드→상세→export 전부에 강제 표기(export 파일 하단에도 출처 주석). 원문 긴 인용은 짧은 발췌+링크로. 작성자 삭제 요청 처리 창구. 사용자 뷰"출처: 블로그 A · 작성자 · 원문 보기" 가 항상 함께.
E5

작성자 · 원본 신뢰도

문제출처가 개인 블로그인지, 공식 문서인지, 검증 안 된 커뮤니티 글인지에 따라 계획을 따를 위험이 다르다(특히 건강·금융·법률). UX 처리매체 유형 배지(공식/블로그/영상/커뮤니티) + 사용·완주·fork 수 같은 집단 신호. 민감 카테고리는 "참고용, 전문가 확인 권장" 안내. 신뢰도를 별점처럼 단정 짓지 않고 맥락으로 제시. 사용자 뷰"공식 문서 기반 · 128명 사용 · 완주율 62%" 식 근거 신호.
SECTION 4

MVP에 넣을 것 vs 미룰 것

기준: "URL → 재사용 or 생성 → 저장"의 한 줄기를 끊김 없이 완성하는 데 필요한 것만 MVP. 축적·소셜·고급 export는 뒤로.

MVP · 꼭 필요

  • URL 입력 + canonical 정규화(기본 규칙: utm 제거, m.·youtu.be 통일)
  • 기존 Flow 정확 일치 검색 → S3 발견 / S5 생성 분기
  • 단일 발견(S3) 재사용 · 미리보기 · "이 Flow 쓰기"
  • AI 생성(S5·S6) fallback + 저장 시 canonical에 첫 Flow 축적
  • 옵션 변경(S7): 시작일·강도 최소 2종
  • My Flow 저장 + 저장 직후 "오늘 할 일" (빈 성공 화면 금지)
  • export 최소 2종: 캘린더(ics) + 마크다운
  • 출처 표기(원문 링크·작성자·시점) 카드→상세→export 관통
  • 원문 스냅샷 + content hash(E2 최소 대응)

나중 (P2+)

  • 여러 후보(S4) 목록·정렬·필터 — 데이터 쌓인 뒤
  • fork(S8) 편집 + 원본 대비 diff, 좋은 fork 승격
  • 품질 점수(E3) 자동 산정 + 조건부 재생성
  • 반복·목적지 등 고급 옵션, 강도 슬라이더 세분화
  • export 확장: 투두 앱 연동, 엑셀/CSV, 옵시디안 vault 포맷
  • 작성자 신뢰 배지·집단 신호(E5) 고도화
  • 원문 변경 자동 감지 + 재생성 알림(E2 풀버전)
  • 커뮤니티 축적 UI("N명이 이 Flow 사용")

MVP 단계에서도 절대 빼면 안 되는 것 — canonical 정규화(없으면 축적·비용 목표 자체가 성립 안 함)와 저장 직후 실행 연결(빈 성공 화면은 기존 07·08 회귀). 이 둘은 "나중" 칸으로 못 내린다.

SECTION 5

가벼운 메모 → 계획 (3번 사용성)

옵시디안·메모장처럼 내가 직접 쓴 짧은 계획을 실행 가능한 Flow로 만드는 사용성. URL 진입과 같은 입력구를 공유해 자연스럽게 이어집니다.

핵심 아이디어 — 입력구는 하나, 소스는 둘

진입 입력창은 URL만 받는 게 아니라 "링크 붙여넣기 · 직접 쓰기" 두 탭을 가진다. FlowMe가 자동 감지: 붙여넣은 게 URL이면 재사용 검색(1~3a), 자유 텍스트면 메모 경로로. 사용자는 "지금 뭘 하는 앱인지" 고민하지 않는다.

A

받아쓰기처럼 쓴다

줄바꿈·대시로 대충 적은 단계도 그대로 저장. 구조화는 선택(AI "정리해줘"는 원할 때만). 안 쓰면 비용도 0.

B

같은 옵션·export를 그대로

메모로 만든 Flow도 시작일·강도(S7), 캘린더·마크다운 export(S9)를 똑같이 쓴다. 학습 곡선 재사용.

C

URL이 붙으면 합류

메모에 참고 링크를 넣으면 그 URL이 출처로 붙고, 나중에 canonical 검색·축적 대상이 될 수 있다. 두 사용성이 한 데이터 모델.

왜 이게 자연스러운가. 사용자의 진짜 동사는 "계획을 실행 가능하게 만들기"다. 소스가 남의 링크든 내 메모든 결과물(Flow)·조작(옵션·fork)·출구(export)가 동일하므로, 3번 사용성은 새 기능이 아니라 입력 소스 하나 추가로 얹힌다. FlowMe가 Notion/Todo 대체가 아니라 "변환기"라는 정체성과도 일치한다.

SECTION 6

제품 백로그

그대로 이슈로 옮길 수 있는 형식 — ID · 우선순위 · 유저스토리 · 완료 조건 · 연결 화면상태. 우선순위는 Blocking / High / Medium / Later.

EPIC A · 재사용 검색 파이프라인

ENTRY-01BlockingS1·S2 · E1

URL을 붙이면 canonical로 정규화되어 같은 콘텐츠가 하나로 모인다.

완료 조건: utm/추적 파라미터 제거, m.·youtu.be·앱 공유 링크 통일, rel=canonical 우선. 정규화 결과를 S2에서 노출. 동일 콘텐츠의 3가지 변형 입력이 같은 키로 수렴.

ENTRY-02BlockingS2→S3/S5

정규화 키로 기존 Flow를 조회해 발견/생성으로 분기한다. AI는 발견 실패 시에만 호출.

완료 조건: 기존 Flow 있으면 S3, 없으면 S5. 발견 경로에서 AI 호출 0회(로그로 검증). 검색까지 비로그인 허용.

EPIC B · 재사용 · 옵션 · 저장

ENTRY-03HighS3

발견된 Flow를 미리보고 "이 Flow 쓰기"로 즉시 재사용한다.

완료 조건: 제목·단계 수·소요·출처·사용 신호 + 3~4단계 미리보기. primary는 "쓰기", "새로 생성"은 하단 약한 링크.

ENTRY-04HighS7

시작일·강도를 바꾸면 원본을 건드리지 않고 내 인스턴스 일정이 즉시 갱신된다.

완료 조건: 옵션 변경은 원본 Flow 불변. 미리보기 즉시 반영. "내 사본에만 적용" 명시.

ENTRY-05BlockingS9 · 원칙 04

My Flow 저장 직후 빈 화면이 아니라 "오늘 할 일" 1개로 이어진다.

완료 조건: 저장 후 채워진 My Flow·캘린더 상태를 스크린샷으로 증명(기존 07·08 회귀 방지). 저장→실행 전환 CTA 1개.

EPIC C · 생성 fallback · 출처

ENTRY-06HighS5·S6

기존 Flow가 없을 때만 AI로 생성하고, 저장하면 canonical의 첫 Flow로 축적된다.

완료 조건: S5에서 명시적 "AI로 만들기". S6에서 단계별 근거 매핑 + 원문 비교. 저장 시 같은 URL 다음 방문자는 S3로 진입.

ENTRY-07BlockingE4 · 전 화면

원문 링크·작성자·매체·변환 시점이 카드→상세→export까지 끊기지 않는다.

완료 조건: 모든 표면에 출처 표기. export 파일(ics·md) 하단에 출처 주석. 원문은 발췌+링크(전문 복제 금지). 삭제 요청 창구.

ENTRY-08MediumE2

원문 스냅샷·content hash를 저장해 원문 변경을 감지하고 알린다.

완료 조건: 생성 시 스냅샷+hash+시점 저장. 재방문 시 hash 변경이면 배지 + "반영해 새로고침(AI 1회)". 자동 재생성 없음.

EPIC D · 확장 (Later)

ENTRY-09Later · S4

여러 후보 목록·추천 승격·정렬/필터.

ENTRY-10Later · S8

fork 편집 + 원본 diff, 좋은 fork 승격.

ENTRY-11Later · E3·E5

품질 점수·신뢰 신호 자동화, 조건부 재생성.

ENTRY-12Later · S9

export 확장: 투두 연동·엑셀·옵시디안 vault.

ENTRY-13Later · S5

메모(직접 쓰기) 입력 탭 + "정리해줘" 선택형 AI (3번 사용성).

첫 스프린트 권장 순서 ENTRY-01 → 02 → 03 → 05 → 07 — "URL → 발견 → 재사용 → 저장 후 실행 → 출처"의 한 줄기를 먼저 닫고, 06(생성)·04(옵션)을 이어 붙인다.
