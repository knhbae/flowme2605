URL-first · export-first · memo-to-Flow
기존 4탭 IA를 깨지 않고 화면 흐름 얹기

현재 앱은 홈 / Flow 찾기 / 캘린더 / 내 Flow 4탭 위에서 이미 대부분의 실행 단위(Step export, fork, source 표기, 원문 변경 감지, 메모 파싱)를 가지고 있습니다. 비어 있는 것은 URL 입력구와 그 뒤의 lookup-first 흐름입니다. 이 문서는 새 서비스를 상상하지 않고, 그 빈 곳만 기존 화면에 얹는 wireflow와 화면별 저충실도 와이어프레임입니다.

■ 재사용 = 싸고 빠른 기본 경로 ┈ AI 생성 = lookup miss일 때만 fallback ▣ export / 저장 = 기존 도구로 내려보내기

먼저 — 코드에서 확인한 것 (상상 아님)

붙여넣은 브리프는 flow-mvp/ 경로를 참조했지만, 실제 앱은 레포 루트에 있습니다(components/flow/, docs/). 아래는 이 설계가 기대는 이미 존재하는 조각들입니다 — 대부분의 실행 로직은 이미 있고, URL 입구만 없습니다.

이미 있음 · 재사용

  • cloneBundleForEditing() — fork/내 버전(초안화·소유자 이전)
  • buildMyFlowStepIcs / …PortableText — Step 단위 export
  • parseTextFlow() — 텍스트/메모 → Flow 파싱
  • assessSourceBackedFlowMapUpdate() — 원문 변경 감지
  • SourceContentCard — 원문·출처 표기

비어 있음 · 신규

  • URL 입력구 (지금 /flows/new는 수동 텍스트 작성만)
  • canonical URL 정규화 + lookup 인덱스
  • lookup 결과 상태(hit/중복/저품질/miss) 화면
  • 공유 링크 → 원문 comment 되돌림 루프

이미 결정됨 · 준수

  • DECISIONS 2026-07-02: lookup → AI는 fallback
  • 저장 후 = confirmation-first, 캘린더 CTA 중복 금지
  • 원문 변경은 알림만, 자동 재생성 안 함
  • fake 사용량/리뷰 금지, source-backed 신호만

SECTION 2

전체 wireflow

두 개의 입구(URL·메모)가 하나의 결과 모델로 수렴합니다. 초록은 재사용(AI 비용 0), 주황은 AI fallback(비용 발생), 파랑은 실행·저장, 보라는 공유 루프. 12개 요구 노드에 ①~⑫ 번호를 답니다.

ENTRY · 두 입구

① URL 입력

블로그·유튜브·사이트·PDF·커뮤니티 링크를 붙여넣음. 홈/Flow 찾기 상단 입력 바.

⑫ memo-to-Flow 입력

직접 쓴 계획을 붙여넣거나 타이핑. 같은 입력구의 두 번째 탭. parseTextFlow 재사용.

↓

정규화 + lookup AI 안 씀

canonical URL 정규화(utm 제거·m.·youtu.be 통일·rel=canonical) → 인덱스에서 기존 변환 조회. 여기서 비용이 갈린다. 메모 입력은 이 단계를 건너뛰고 바로 초안으로.

lookup 판정에 따라 4갈래

HIT · 좋은 기존 Flow

② 기존 Flow hit

즉시 표시. AI 재실행 0. 바로 옵션 변경으로.

DUP · 후보 여럿

③ duplicate URL reuse

같은 URL 파생 목록. 추천 1개 강조 + 나머지. 하나 선택 → ②로 합류.

LOW · 품질 낮음

④ low-quality hit

기존 Flow는 보여주되 "다시 만들까요?" 제안. 재사용 or ⑥ 선택.

MISS · 없음

⑤ lookup miss

원문 row 미리보기 → 변환 가능 판정. row 없으면 억지 생성 안 함(Park).

② ③ ↓ 재사용
④ ⑤ ↓ AI fallback

⑥ AI fallback (생성) — miss / 저품질 / 사용자의 재생성 요청일 때만

원문을 계획으로 변환 → 단계별 근거 매핑과 함께 결과 확인. 저장하면 그 canonical의 첫/새 버전으로 축적 → 다음 사람은 ②로 진입.

↓   재사용·생성 결과가 여기서 합류   ↓

⑦ 옵션 변경

시작일·기간·강도·목적지. 원본 불변, 내 인스턴스에만 적용. 일정 미리보기 즉시 갱신.

⑧ thin edit / fork

Step 제목·날짜·메모·체크만 얇게 수정, 또는 cloneBundleForEditing로 내 버전 fork. 편집기 안 열어도 됨.

↓
DISTRIBUTE · 실행처로

⑨ export

캘린더(.ics)·투두 복사·마크다운/옵시디안·시트/CSV. 비로그인도 복사·다운로드 가능.

⑩ My Flow 저장

로그인 후 저장 → confirmation-first → 오늘/Flow/캘린더에서 계속 실행.

↓

⑪ 공유 / comment loop → adoption

내가 만든 Flow 링크를 원문 댓글·커뮤니티·SNS에 공유 → 다른 사용자가 그 링크로 진입(다시 ②로) → 누적되면 원작자가 자기 콘텐츠의 Flow를 발견해 공식 활용. 이 화살표가 ① 입구로 되돌아가 성장 루프를 닫음.

LOOP BACK ⑪ 공유 링크 → ① URL 입력(다른 사용자) → ② hit(비용 0). 재사용률이 오를수록 AI 호출·비용이 내려가는 구조.

SECTION 4

Export UX — 목적지별 기준과 노출 위치

export는 FlowMe의 정체성입니다("변환기"). 같은 Flow라도 목적지마다 다른 형태가 자연스러워야 합니다(FUB-02). 함수는 이미 export.ts / my-flow-step-export.ts에 있으므로, 남은 일은 UI에서 어디에 어떻게 노출하느냐입니다.

📅 캘린더 .ics

출력: 짧은 일정 제목 · 날짜 · 반복(RRULE) · 설명 · 원문 URL. 노출: Step detail 내 도구로 옮기기(단건), Flow 상세 저장 전(전체), export 바텀시트. buildMyFlowStepIcs / buildIcsCalendar

✓ 투두 · 체크리스트

출력: 한 줄 action · 완료 기준 · 메모 fallback(체크박스 텍스트). 노출: export 바텀시트 "복사" 버튼(클립보드). Todoist·MS To Do 붙여넣기용 plain text. buildMyFlowStepPortableText / buildText

📝 마크다운 · 옵시디안

출력: heading · - [ ] 체크리스트 · 원문 링크 · 개인 메모 · 회고 섹션. 노출: export 바텀시트 "복사"(md), 긴 맥락 사용자 대상. Notion 붙여넣기도 이 포맷 재사용.

▦ 시트 · CSV/엑셀

출력: 행/열 · 상태 · 날짜 · source row · 메모. 진도표/시트형 Flow에 적합. 노출: export 바텀시트 "다운로드"(.csv/.xlsx). buildWorkbookSheets / buildXlsxBuffer

노출 원칙 3가지. ① 단건 export는 Step detail 안(내 도구로 옮기기), 전체 export는 Flow 상세/저장 후 바텀시트. ② 목적지 선택은 결과 미리보기를 함께(어떤 모양으로 나가는지). ③ 직접 계정 연동(OAuth)보다 portable export를 먼저 — 이건 금지 목록에도 있는 원칙(파일·클립보드 우선).

SECTION 5

비로그인 / 로그인 경계

진입 마찰을 뒤로 미룹니다. 가치를 먼저 맛보게 하고, 상태를 남길 때만 로그인을 요구합니다.

비로그인 · 허용

  • URL 붙여넣기 → lookup → 기존 Flow 미리보기
  • 옵션 변경 미리보기(시작일·강도) — 저장 전까지 로컬 상태
  • export 복사·다운로드(.ics·md·csv·클립보드)
  • 원문 보기, 공유 링크 열람

"내 도구로 바로 옮기기"까지는 로그인 없이 끝낼 수 있어야 함 — export-first 정체성.

로그인 · 필요

  • My Flow 저장(오늘/Flow/캘린더에서 계속 실행)
  • 수정 이력 · fork한 내 버전 보관
  • 재-export(저장된 상태에서 다시 내보내기)
  • 공유 관리(내가 만든 Flow 링크·공개 범위)

저장 시점에 "이 Flow를 계속 쓰려면 저장" 한 번만 로그인 유도 — 진입에서 막지 않음.

경계 한 줄 요약. 비로그인 = "가져가기"(복사·다운로드·미리보기), 로그인 = "쌓기"(저장·이력·재export·공유). 현재 앱은 로컬 저장 기반이므로, 계정 도입 전에도 이 경계를 localStorage 익명 상태 → 계정 승격 형태로 흉내 낼 수 있음.

SECTION 6

Flow 컨텐츠화 흐름 — private draft → shareable → creator loop

개인 실행용과 공유·발행을 명확히 분리합니다. 승격은 자동이 아니라 사용자의 의식적 선택이며, 각 단계에 게이트가 있습니다(FUB-05).

STAGE 1

개인 draft

메모·URL 변환 결과. 기본은 비공개. 실행하며 자유롭게 수정. 출처만 내부 보관.

언제 여기 머무나 · 나만 쓸 때, 원문 그대로일 때

STAGE 2 · 게이트

shareable Flow

공유 링크 생성. 승격 전 필수 점검: 원문 출처 표기, 원문에 없는 Step 제거, 민감영역 주의, 완료 기준, export 샘플 확인.

언제 여기로 · 남에게 유용하다고 판단할 때

STAGE 3 · 후행

creator / source-owner loop

공유 링크가 원문 댓글·커뮤니티로 확산 → 원작자가 자기 콘텐츠의 Flow를 발견 → 공식 채널로 채택. P0에서 크게 다루지 않음.

언제 열리나 · 재사용·공유 루프가 먼저 생긴 뒤

경계 원칙. 개인 draft는 status:'draft'·소유자 본인(이미 cloneBundleForEditing이 이렇게 만듦). 공유는 별도 승격 액션에서만. 사용자 화면과 크리에이터/검토 화면은 계속 분리(DECISIONS 2026-06-24) — 개인 실행 공간에 발행 UI를 섞지 않음.

P0 · 바로 구현

URL→재사용/생성→저장의 한 줄기

SECTION 8

사용성 리스크

① 사용자가 헷갈리는 지점 — "왜 AI가 안 돌지?"

lookup HIT 시 사용자는 "내 링크가 처리 안 된 것" 아닌가 오해할 수 있음. → S2에서 "이미 만들어진 Flow를 찾는 중/찾았어요"를 문장으로 명시하고, 정규화된 URL을 보여줘 "같은 콘텐츠"임을 납득시킴.

② 기존 구조와 충돌 — 탭이 늘어날 위험

URL 흐름을 새 탭으로 만들면 4탭 IA(DECISIONS 2026-06-28)와 충돌. → URL은 홈·Flow 찾기 안의 상태로, lookup 결과도 Flow 찾기의 화면 상태로 흡수. 새 글로벌 탭 금지.

③ 너무 복잡해지는 지점 — 옵션·fork·export 동시 노출

한 화면에 옵션·수정·fork·export·저장을 다 깔면 캘린더/투두 수준 복잡도를 넘김. → 한 화면에 primary 1개. fork·상세 수정은 Step detail 안으로, export는 바텀시트로 접음.

④ 저작권 · 신뢰 — 원문 복제/과장 위험

Flow가 원문 본문 복붙이 되면 저작권 문제. fake 사용량은 신뢰 훼손. → 절차 요약(변형 저작물)+출처 표기 강제, source-backed 신호만(fake 금지, 이미 결정됨). 민감영역은 "참고용, 전문가 확인" 톤.

SECTION 9

만들지 말아야 할 방향

  • 기존 앱과 무관한 새 서비스처럼 재설계 — 4탭·기존 컴포넌트 위에 얹기만
  • 새 랜딩페이지 중심 제안 — 홈은 그대로, 입력구만 추가
  • AI-first 생성 UX — lookup이 먼저, AI는 miss/저품질/재생성 요청 때만
  • 원문에 FlowMe 링크가 이미 붙어 있다는 가정 — 1차 입구는 사용자의 URL 붙여넣기
  • fake 사용량·리뷰·창작자 인증 — source-backed 신호만
  • full auto-scheduler — 옵션은 시작일·강도 수준, 날짜는 Step별 선택
  • Notion/Obsidian 대체 workspace — export로 내려보내는 변환기에 머무름
  • creator marketplace를 P0로 — P2 후행
  • heavy editor / version graph를 P0로 — thin edit는 P1, 무거운 편집기 금지
  • OAuth 직접 연동을 portable export보다 앞세우기 — 파일·클립보드 우선
FINAL

바로 구현 가능한 P0 slice

7개 작업으로 압축. 순서대로 닫으면 "URL 붙여넣기 → 재사용 → 저장 → export"의 한 줄기가 실제로 동작합니다. 대부분 기존 함수를 잇는 일이라 신규 코드가 적습니다.

S1

URL 입력 컴포넌트 + canonical 정규화 유틸

홈·Flow 찾기 공용. utm 제거·m.·youtu.be·rel=canonical. lib/flow/에 순수 함수 + 테스트 먼저.

S2

lookup 인덱스 + HIT/miss 분기

canonical → Flow 조회. HIT면 결과 표시, miss면 AI 버튼. 발견 경로 AI 호출 0회를 로그로 검증.

S3

lookup 결과 화면 상태(HIT) + "이 Flow 쓰기"

기존 flow-map-public 미리보기 재사용. primary 1개, "새로 생성"은 약한 링크.

S4

옵션 바(시작일·강도) — 원본 불변

내 인스턴스에만 적용, 일정 미리보기 즉시 갱신. "내 사본에만 적용" 명시.

S5

AI 생성 fallback + canonical 축적 저장

miss에서만. 저장 시 canonical 키로 기록 → 다음 방문자는 S2에서 HIT. 원문 스냅샷+hash 동봉.

S6

저장 후 "다음 할 일" 연결

confirmation-first → 오늘/Flow. 빈 성공 화면 금지, 캘린더 CTA 중복 금지(기존 결정 준수).

S7

export 2종(.ics + 마크다운) + 출처 주석

기존 buildIcsCalendar / buildText 재사용, 바텀시트 노출. export 파일 하단에 원문·작성자 주석. 비로그인 허용.

권장 순서 S1 → S2 → S3 → S6 → S7 → S4 → S5 — 재사용·저장·export 줄기를 먼저 닫고, 옵션(S4)·AI 생성(S5)을 붙임.
