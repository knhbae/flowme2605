SECTION 1

UX 진단

상용 실행 앱처럼 보이는 정도

골격은 상용 앱이고, 표면은 아직 기획 데모입니다. 4탭 IA, 저장 → 실행 루프, 결과 중심 export 라벨, 접힌 원문·근거 등 구조적 결정은 이미 상용 수준입니다. 그러나 거의 모든 화면이 "라벨 붙은 설명 카드"를 위에서 아래로 나열하는 같은 문법을 쓰고 있어, 사용자가 행동하기 전에 읽어야 할 블록이 화면당 4~6개입니다. Notion·네이버 캘린더 같은 상용 앱은 첫 화면에서 "내가 만질 것" 1개를 주고 나머지를 숨깁니다. FlowMe는 지금 "내가 이해할 것" 4개를 먼저 줍니다. 이번 루프의 핵심은 새 기능이 아니라 위계 압축과 언어 교정입니다.

가장 큰 병목 3

  1. 모바일 홈에 첫 행동 버튼이 없음 — hero CTA가 hidden sm:flex (01)
  2. 저장 직후 "먼저 할 일부터 열어보세요"와 "남은 할 일이 없습니다"가 동시에 보임 (10)
  3. 지도 상세에서 필수 입력(이사일)은 상단, 저장은 하단 sticky — 행동이 두 곳으로 찢어짐 (03)

유지해야 할 좋은 방향 3

  1. "저장 전 보기 → 저장하고 시작 → 먼저 할 일" 실행 루프 설계
  2. 결과 중심 export 라벨("캘린더 파일 받기 · 시트로 받기 · 메모로 복사")
  3. 원문 · 근거 · 메모를 삭제하지 않고 접어두는 신뢰 구조 (sourceTrace 보존)

설명형 화면처럼 보이는 지점

  • 홈의 "시작 경로 · 고르고 저장하고 이어가기" 4단계 카드 — 앱 사용법을 슬라이드처럼 설명 (01, HomeLanding)
  • Flow 찾기의 이중 헤더: h1 "저장할 실행 콘텐츠" 바로 아래 h2 "내 상황에 맞는 콘텐츠 고르기" + 각각의 보조 문장 (02, FlowList)
  • 공개 상세의 약속 박스 + 설명 문단 + 칩 3줄 + "저장 후 일정과 체크로 이어집니다" 안내 박스 — 저장 전 읽을 블록 6개 (05 · 06)
  • 지도 상세의 "저장되는 결과물" 전폭 카드 3장 — 단어 하나를 카드 한 장으로 (03 · 04)
  • 내 Flow 오늘의 카드 안 카드 — eyebrow + 제목이 겹겹이 반복 (08)

이미 실행형 앱처럼 보이는 지점

  • 카탈로그 카드의 "입력 → 결과" 약속 한 줄과 "먼저 확인할 일" 프리뷰 (02)
  • 모바일 sticky 저장 바 + "전체 저장하고 시작" 단일 주행동 (03)
  • 저장 직후 배너의 "먼저 할 일 열기 / 전체 할 일 보기" 라우터 (10)
  • 오늘 / 전체 2탭과 진행률 · 다음 할 일 프리뷰 (08 · 09)
  • 할 일 행 안의 "체크 N개 열기", "메모 · 원문" 접힘 (03 ~ 06)

5초 안에 이해 못할 가능성이 높은 화면

  • 홈(모바일) — hero에 버튼이 없어 첫 행동이 "스크롤"뿐 (01)
  • 지도 상세 — 무엇을 입력하고 어디를 누르는지가 화면 양끝으로 분리 (03)
  • 저장 직후 내 Flow — 상반된 두 메시지가 동시에 보임 (10)
  • 내 Flow 오늘 — 첫 카드가 "남은 할 일이 없습니다" 공지, 실제 행동은 그 아래 (08)
  • 캘린더 — 헤더 2벌 + 빈 그리드가 화면 대부분, 일정은 4px 칩 하나 (11)

저장 후 다음 행동이 약한 지점

  • 날짜 없는 콘텐츠(수학 진도표) 저장 시 오늘 탭이 "남은 할 일이 없습니다"로 시작 — 방금 할 일 8개를 저장했는데 "없다"고 답함 (10, MyFlows today)
  • 배너의 "먼저 할 일"과 워크스페이스의 첫 카드가 서로 다른 항목/상태를 가리킴 (10)
  • 다음 할 일 제목이 "2026-06-22 예정 할 일" — 기계 날짜가 헤드라인 (08)
  • 빈 상태에서 "Flow 찾기"와 "새 Flow 만들기" 2개 CTA가 경쟁 — 첫 저장 유도가 갈라짐 (07)

내부 모델이 사용자에게 노출되는 지점

  • "1개 묶음 · 5개 할 일 · 8개 체크" — 내부 계층(Map→Flow→Step→Item)의 카운트 언어가 카탈로그 · 지도 상세 · 저장 바 · 저장 배너에 반복 (02 · 03 · 04 · 10, SourceBackedFlowMapPage.tsx)
  • 공개 상세 제목의 "~체크 Flow" 접미 — 콘텐츠 이름에 내부 개체명 (05)
  • "원문 기반 데모" · "데모 기준일" · "실제 오늘과 다른 고정 기준일" 배지 — QA 언어가 사용자 화면에 (08 · 11)
  • 카탈로그 상태 "확인 가능" — 검수 상태의 번역이지만 사용자에겐 무의미 (02, userFacingStatus)
  • 저장 목록의 "검수 필요" amber 배지 — 서비스가 추천한 콘텐츠가 저장 후 경고로 변함 (getMyFlowContentReadiness, SERVICE_STRUCTURE.md에도 금지로 명시)
  • 제작자 화면의 "Flow 후보 · 샘플 후보 · 원본 검토" 통계 — 보조 화면이지만 public 링크로 접근 가능 (CreatorDirectory)
SECTION 2

우선순위 개선안

Blocking = 첫 사용 여정이 끊기는 것. High = 5초 이해 · 밀도 문제. Medium = 일관성 · 중복. Low = 다듬기. 각 항목의 근거는 화면 번호(01~12)와 소스 위치입니다.

Blocking — 이번 루프에서 반드시

B1

모바일 홈에 주행동 버튼이 없다

근거01 · HomeLanding의 CTA 컨테이너가 hidden sm:flex — 390px에서 렌더되지 않음 혼란첫 화면에서 누를 것이 없어 "읽는 페이지"로 인식. 첫 행동이 우연한 스크롤과 카드 발견에 의존
수정hero 안에 전폭 primary 버튼 "콘텐츠 고르러 가기"를 모바일 포함 상시 노출 (→ /flows) 효과홈 5초 테스트 통과: "무엇을 해주는 서비스 + 어디를 누르는지"가 한 뷰포트에
B2

저장 직후, 배너와 워크스페이스가 반대 말을 한다

근거10 · renderPostSavePanel(≈L5287)은 "먼저 할 일부터 열어보세요", 바로 아래 오늘 카드(≈L6147)는 "남은 할 일이 없습니다" — 날짜 없는 콘텐츠(수학 진도표)는 오늘 큐에 잡히지 않음 혼란방금 할 일 8개를 저장했는데 화면이 "없다"고 답함. 저장이 실패한 것처럼 읽히고, 배너를 놓치면 다음 행동이 사라짐
수정post-save 진입 시 오늘 첫 슬롯이 방금 저장한 콘텐츠의 먼저 할 일(날짜 없으면 첫 항목)을 표시. 배너의 항목과 동일 대상. "남은 할 일이 없습니다"는 post-save 모드에서 미노출 효과저장 = 실행 시작이라는 서비스 약속이 화면에서 증명됨. 첫 저장 이탈 감소
B3

필수 입력과 저장 CTA가 화면 양끝으로 분리

근거03 · SourceBackedFlowMapSaveButton.tsx — 이사일 입력은 hero, 저장은 하단 sticky. 미입력 시 sticky에 "이사일 필요" 11px 텍스트만, 버튼을 눌러야 에러 발생. 에러 문구는 화면 밖 hero에 뜸 혼란버튼을 눌렀는데 아무 일도 안 일어난 것처럼 보임 (에러가 뷰포트 밖)
수정미입력 상태의 sticky 버튼 라벨을 "이사일 입력"으로, 탭하면 입력 필드로 스크롤 + 포커스 + 하이라이트. 입력되면 "저장하고 시작"으로 전환 (§4.3 목업) 효과입력 → 저장이 한 동선이 됨. 지도 저장 완료율 상승
B4

ISO 날짜가 제목으로 노출된다

근거08 · 10 — "2026-06-22 예정 할 일", "2026-07-03 기준 할 일"이 카드 헤드라인. 캘린더 셀도 "22일" 접미 반복 (11) 혼란기계 문자열이 제목 자리를 차지해 데이터 덤프처럼 읽힘. "기준 할 일"은 시스템 말투
수정날짜 표시 포맷터 1개를 추가해 사용자 표면 전체에 적용: "6월 22일 (월)", 오늘/내일은 "오늘 · 6월 22일". 제목은 행동 언어("오늘 할 일", "다음 할 일")로 효과내 Flow · 캘린더가 즉시 "일정 앱" 톤으로 바뀜. 비용 대비 체감 가장 큰 수정

High — 5초 이해와 밀도

H1

Flow 찾기의 이중 헤더

근거02 · FlowList — "저장할 실행 콘텐츠" + 보조문, 바로 아래 "저장할 콘텐츠 / 내 상황에 맞는 콘텐츠 고르기" + 보조문. 첫 카드가 뷰포트 밖으로 밀림 혼란같은 말을 두 번 읽게 하고, 정작 고를 물건은 스크롤해야 보임
수정헤더 1벌로 통합: "무엇을 저장할까요?" + "저장하면 일정과 체크리스트가 생깁니다." 개수 배지는 목록 위 12px 텍스트로 강등 효과390×844에서 검색 + 칩 + 카드 1.5장이 첫 뷰포트에 들어옴
H2

카탈로그 카드가 판단 1번에 정보 9조각을 요구

근거02 · FlowMapCatalogCard(L923) · DirectoryFlowCard(L808) — 메타 1줄 + 제목 + 약속 + 요약 문단 + 먼저 할 일 박스 + 메타 2줄 + CTA + 링크 2개. 카드 1장 ≈ 뷰포트의 ⅓ 혼란비교 단위가 커서 스캔이 느림. "바로 시작"과 "저장 전 보기"의 차이를 카드 단계에서 알 수 없음
수정카드 = 카테고리 1개 + 제목 + 약속 한 줄 + 먼저 할 일 + CTA 1개 (§4.1 목업). 요약 문단 · 두 번째 메타 줄 · 하단 링크 2개는 상세로 이동 효과카드 높이 ≈230px → ≈160px. 첫 화면에서 2→3장 비교 가능
H3

공개 상세 hero가 저장 전에 6블록을 읽게 한다

근거05 · 06 · PublicFlow(L8048) — 약속 박스, 문단, 칩 3~5개, CTA, "원문은 아래에서 확인", 날짜 영역엔 적용 · 날짜 미정 · 예시 보기 버튼 3개 + 예시 문구 혼란입력이 CTA보다 아래에 있어 날짜 없이 저장하거나, 날짜 영역에서 뭘 눌러야 할지 망설임
수정hero = 카테고리 · 제목 · 결과 한 줄 · 날짜 입력(변경 즉시 반영, 적용 버튼 삭제) · 저장 CTA · 먼저 할 일 한 줄 (§4.2 목업). 문단 · 안내 박스는 접힘으로 효과입력 → 저장 → 먼저 할 일이 한 뷰포트, 읽기 시간 절반 이하
H4

"묶음" 카운트와 "~Flow" 접미 — 내부 계층 언어

근거02 · 03 · 05 · 10 — "1개 묶음 · 5개 할 일 · 8개 체크", "N개 묶음 저장", 제목 "전세계약 전 서류 체크 Flow" 혼란"묶음"은 Map→Flow 구조를 알아야 이해됨. 사용자 판단에 필요한 수는 "할 일 몇 개" 하나뿐
수정사용자 표면 카운트는 "할 일 5개" (필요시 "체크 8개"까지만). 콘텐츠 제목에서 "Flow" 접미 제거. "묶음"은 지도 상세의 소제목 구분에서만 효과내부 모델을 몰라도 전 화면이 읽힘 — 검토 기준 #4 충족
H5

내 Flow 오늘: 빈 상태 문구가 첫 슬롯을 차지

근거08 — 첫 카드 "남은 할 일이 없습니다…", 두 번째 카드가 실제 다음 행동. 카드 안에 eyebrow+제목 카드가 또 중첩되어 "다음 할 일" 라벨이 3회 반복 혼란실행 허브의 첫 시선이 "할 게 없다"는 공지. 중첩 카드로 어디를 눌러야 할지 모호
수정첫 슬롯 = 항상 다음 행동(오늘 → 밀린 → 다음 순 fallback). 오늘이 비면 "다음 할 일" 카드가 첫 슬롯, "오늘은 남은 일이 없어요"는 그 아래 캡션 한 줄. 카드 중첩 1단계 평탄화 (§4.4 목업) 효과내 Flow가 목록 보관함이 아니라 실행 허브로 읽힘
H6

캘린더가 일정 앱이 아니라 달력 위젯처럼 보인다

근거11 — 헤더 2벌("일정 보기/캘린더" + "내 Flow/월간 일정"), 셀마다 "일" 접미, 이벤트는 잘린 칩 1개, 선택일의 할 일 목록은 첫 뷰포트에 없음 혼란날짜를 눌러도 무엇이 나오는지 예측 불가. schedule-first 목적이 전달 안 됨
수정헤더 1벌 + 그리드(숫자만, dot 표시) + 그리드 바로 아래 선택일 agenda 고정. 진입 시 가장 가까운 일정 날짜 자동 선택(SERVICE_STRUCTURE 기준) (§4.5 목업) 효과진입 3초 안에 "다음 일정 + 그날 할 일"이 보임 — 캘린더 탭의 존재 이유 증명
H7

  • source 링크 — 카드에서 제거. 원문은 상세의 원문 섹션에서만. 새 탭 이탈을 카탈로그 단계에서 만들지 않음
  • "바로 시작" 링크 — 카드에서 제거. 목적지 1개 원칙(카드 전체 = 저장 전 보기)
  • 높이 · 밀도 — padding 16px, 내부 gap 8~12px, 목표 높이 150~170px (현재 ≈230px). 390×844 첫 뷰포트에 카드 2장 + 3장째 상단이 보여야 함
  • 탭 영역 — 카드 전체가 하나의 링크(현행 DirectoryFlowCard 방식으로 통일). CTA는 시각 요소

4.2 공개 Flow 상세 — hero와 접힘 구조

hero 정보 구조 (한 뷰포트 안, 이 순서)

  1. 카테고리 · "출처 확인됨" — 11px 한 줄 (칩은 이 1개만)
  2. 제목 — "Flow" 접미 제거: "전세계약 전 서류 체크"
  3. 결과 한 줄 — "계약일만 넣으면 D-3 · 당일 · D+1 일정과 체크 7개가 저장됩니다" (기존 약속 박스 + 문단 + 칩 3줄을 이 한 줄로 압축)
  4. 입력 — 계약 예정일 date input 1개. 변경 즉시 아래 일정 프리뷰 갱신(적용 버튼 삭제). 우측에 "날짜 없이 저장" 텍스트 링크
  5. 저장 CTA — "내 Flow에 저장" 전폭 1개. 저장 전 화면에 두 번째 저장 버튼 금지
  6. 먼저 할 일 한 줄 — "먼저 할 일 · 시세와 등기부등본 확인"

본문 접힘 구조 (hero 아래, 이 순서)

  1. 저장되는 일정 · 체크 — 첫 3개 항목 펼침 + "전체 7개 보기". 입력한 날짜가 반영된 실제 날짜로 표시
  2. 원문 · 출처 — 접힘. 원문 링크 + 전환 노트 + 원문 근거(sourceTrace) 순. 데이터 삭제 금지, 라벨만 통일
  3. 메모 — 접힘
  4. 내보내기 — 저장 후 활성. 저장 전엔 "저장하면 캘린더 · 시트 · 메모로 가져갈 수 있어요" 한 줄. 모바일 sticky는 저장 CTA 하나만 (export 중복 압박 금지)

제거: "저장 후 일정과 체크로 이어집니다" 안내 박스, "원문은 아래에서 확인" 문구(원문 섹션이 대신), 예시 보기 버튼(placeholder 날짜로 대체), 5칩 나열.

4.3 Flow Map 상세 — 큰 흐름 요약과 sticky CTA

큰 흐름 요약 + 저장 전 preview

  1. eyebrow "저장 전 보기" 유지 + 제목
  2. 결과 한 줄 — "이사일 하나면 할 일 5개가 날짜별 일정으로 저장됩니다" (현재의 3문장 요약 대체)
  3. 결과물 칩 1줄 — "캘린더 일정 · 체크리스트 · 원문 링크" 인라인 칩. 현재의 전폭 "저장되는 결과물" 카드 3장 대체
  4. 날짜 입력 — hero 안 유지, 라벨 + 힌트 1줄
  5. 저장되는 할 일 preview — 행 5개: D-배지 + 제목. 행 안에서 "체크 N개" · "원문 · 메모"는 현행처럼 접힘. 묶음 구분은 소제목으로만

모바일 sticky CTA — 2단계 상태 기계 (B3)

  • 미입력 — 좌: "이사일을 입력하세요" / 버튼: "이사일 입력" → 탭하면 입력으로 스크롤 + 포커스 + 테두리 하이라이트. 비활성처럼 보이는 회색 처리 금지(행동을 안내하는 버튼)
  • 입력됨 — 좌: "할 일 5개 → 내 일정" / 버튼: "저장하고 시작"
  • 레이어 — sticky 바 노출 시 하단 탭과 한 층으로 도킹(M5). fixed 레이어는 항상 1개

4.4 My Flow — 저장 직후 · 오늘 · 저장 목록 · 상세

저장 직후 confirmation

  • 배너 3행: [저장 완료 배지 + 콘텐츠명] / ["할 일 8개가 준비됐어요"] / [먼저 할 일 · {제목}]
  • 버튼 2개: "바로 시작"(primary) + "전체 보기"(ghost). 닫기(×) 제공, 새로고침 후 미표시
  • 배너 아래 오늘 워크스페이스의 첫 카드 = 배너와 같은 항목 (B2). 날짜 없는 콘텐츠는 첫 항목이 "다음 할 일"로 등장
  • 배너 안 미니 목록 · 항목 상세 금지 (SERVICE_STRUCTURE 원칙 유지)

오늘 / 다음 / 밀린 우선순위

  • 슬롯 순서: 오늘 할 일(체크 행, 최대 5) → 밀린 할 일(amber 카운트 배지, 접힘) → 다음 할 일(최대 3, 컴팩트)
  • 오늘이 비면 첫 슬롯 = 다음 할 일 1개 (라벨 "다음 할 일 · 6월 22일 (월)"), 그 아래 "오늘은 남은 일이 없어요" 캡션 1줄
  • 행 구조 = 체크박스 + 제목(15px/700) + 보조 줄 1개(콘텐츠명 · D-n) — 카드 중첩 금지
  • 날짜는 전부 "M월 D일 (요일)" (B4)

저장 목록 스캔 구조 (전체 탭)

  • 행 = 컬러 dot + 제목 + 진행바 + "n/n" + "다음: {할 일}" 1줄 + chevron. 목표 높이 ≈88px
  • 요약 헤더 칩은 값이 있는 것만 ("오늘 0" 숨김, M4)
  • 행 탭 → 항목 목록(5개 + "전체 보기") → 항목 탭 → 상세 inline. 같은 행 재탭 = 닫기 (현행 유지)

memo / source / export 위치

  • 항목 상세 하단 접힘 행 4개, 순서 고정: 메모 → 일정 변경 → 원문 · 출처 → 내보내기
  • 내보내기 3버튼: "캘린더 파일 받기 · 시트로 받기 · 메모로 복사" (§5 라벨 세트)
  • 콘텐츠 단위 export는 콘텐츠 행의 ⋯ 메뉴로 — 목록 표면에 버튼 나열 금지

4.5 캘린더 — schedule-first 구조

구조

  • 헤더 1행: "캘린더" + 월 표시 + 이전/다음. "일정 보기" eyebrow, "내 Flow / 월간 일정" 카드 헤더 제거 (H6)

  • 진입 시 기본 선택일 = 오늘 이후 가장 가까운 일정 날짜 (없으면 오늘) — SERVICE_STRUCTURE 기준 구현

첫 행동과 역할 분리

  • 날짜 선택 후 첫 행동 = agenda 행 탭 → 항목 상세(내 Flow 상세와 동일 컴포넌트)

  • scope 필터(전체/일정/루틴)는 두 유형이 실재할 때만 노출

여정 1 — 처음 저장한 사람

  • 홈 → Flow 찾기 → 지도 상세 → 이사일 입력 → 저장 → 내 Flow
  • 확인: 홈에 버튼(B1), sticky 상태 전환(B3), 배너 = 첫 카드 항목(B2), "바로 시작" → 상세 열림 → 체크 1개 완료
  • 빈 상태 → 저장 → 복귀 시 같은 탭 골격 유지 (인터페이스 재학습 없음)

여정 2 — 여러 개 저장한 사람

  • demo fixture(오늘 있음 / 오늘 없음 / 밀림 있음) 3종으로 오늘 탭 첫 슬롯 검증
  • 날짜 없는 콘텐츠(수학)만 저장한 상태에서 "남은 할 일이 없습니다" 미출현
  • 전체 탭: 행 → 목록 → 상세 → 재탭 닫기. 0개 요약 칩 숨김

캘린더 + export + 접힘

  • export: 3표면(공개 상세 · 내 Flow 상세 · 시트) 라벨 동일, .ics 파일이 캘린더 앱에서 열림, 복사 성공 피드백
  • 원문 · 출처 / 메모 기본 접힘, 펼치면 원문 근거(sourceTrace 데이터) 보존 확인

SECTION 8

유지할 것과 건드리면 위험한 것

유지할 것

  • 4탭 IA (홈 · Flow 찾기 · 캘린더 · 내 Flow)
  • "저장 전 보기 → 저장하고 시작 → 먼저 할 일" 루프
  • 결과 중심 export 라벨 3종 체계
  • 원문 · 근거 · 메모의 접힘 보존(삭제 금지) 신뢰 구조
  • read-first 항목 상세, 오늘/전체 2탭
  • 배너 = 확인 + 라우터 원칙 (미니 목록 금지)

건드리면 위험한 것

  • storage.ts 키와 스냅샷 스키마 — 기존 사용자의 저장 데이터 호환성
  • source-backed-my-flow.ts의 seed 병합/dedupe 로직
  • sourceTrace · sourceUrl 데이터 — 라벨은 바꿔도 값은 보존
  • e2e가 잡고 있는 data-testid — 마크업 변경 시 testid 이관 필수
  • 앵커 날짜 재계산 · 루틴 반복(recurrence) 로직

지금은 하지 말 것

  • 전면 리디자인 · 리브랜딩 (이번 루프는 위계 압축 + 언어 교정)
  • AppClient.tsx 대규모 분할 리팩터 — UX 수정과 동시 진행 시 충돌 비용이 더 큼
  • IA 변경 · 탭 추가 (4탭 결정은 사용자 근거가 생길 때 재개)
  • 계정/서버 저장 도입

2차 이후로 미뤄도 되는 것

  • 제작자 디렉터리 내부어 정리 (L4)
  • 홈 추천 개인화, 캘린더 주간 뷰
  • 카탈로그 확장(20개+) 시 필터 재설계
  • 화면 단위 컴포넌트 분리 — 이번 루프 수정이 끝난 화면부터 순차로

별도 의견 — AppClient.tsx 구조가 UX 속도에 미치는 영향

10,858줄 단일 파일에 홈 · 카탈로그 · 공개 상세 · 내 Flow · 캘린더가 함께 있고, MyFlows 하나가 useState 50여 개를 듭니다. 이번 검토에서 발견된 문제의 상당수(라벨 3종 혼용, 같은 개념의 카드 2벌, 데모 분기 누수)는 이 구조에서 같은 UI를 여러 곳에 복붙하면서 생긴 것입니다. 다만 이번 루프의 우선순위는 사용자 경험이므로, 리팩터는 "수정이 끝난 화면을 파일로 떼어내는" 후행 방식을 권합니다. 문구 상수화(§6 Medium)가 그 첫 단추입니다.
