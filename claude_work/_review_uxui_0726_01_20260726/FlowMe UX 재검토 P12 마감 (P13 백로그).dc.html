SECTION 1

Overall Judgment — P12 닫힘, 리스크는 출력 상태로 이동

현 상태 판단 — 정상 + URL-first 모두 견고

P11이 남긴 최대 구멍 — "URL-first가 정상 라우트인데 스캔 밖" — 이 닫혔습니다. 4상태가 정상 스키마로 캡처되고(hit·custom-start·miss·candidate) 전 버킷 0. P11이 육안으로만 잡던 slug(Mathbang)·raw ISO·내부 단계어(P0)가 이제 측정된 0입니다. 공개 sticky 9/9 저장·입력, before-primary 0, 워크벤치 행 상세 source 0/접근 5, restart D-30 그룹 유지, flow-lab noindex 격리. 정상·URL-first에 Blocking·High 없음.

P13에서 가장 먼저 볼 사용자 리스크

스캔은 "각 화면의 기본 상태 + 보이는 DOM"만 잽니다. 그 정의 밖 두 곳에서 기준선이 샙니다. ① url-first-lookup.ts의 exportModes는 여전히 ['calendar','markdown','checklist'] — 캡처는 기본 calendar만 렌더해 visibleMarkdown 0이지만, flow-mvp.spec.ts는 여전히 "Markdown 받기" 버튼과 toContainText('Markdown')를 단언. ② "요청 정리본 복사"가 클립보드에 넣는 문서는 url-first-supply-queue.test.ts가 확인하듯 "Step·sourceTrace·handoff·Canonical URL"을 포함 — 전부 금지어인데 화면이 아닌 클립보드라 스캔이 못 봅니다. P9→P12가 증명한 교훈 그대로: 안 재는 상태는 조용히 되돌아갑니다.

한 줄 판정 — P12는 정상 4탭·공개 공유·URL-first 기준으로 출시 가능합니다(Blocking 0, High 0). 남은 것은 전부 스캔 정의의 확장 문제입니다. P13의 순서: ①export 모드를 토글해 전 상태를 캡처(Markdown 라벨 정합) → ②클립보드/다운로드 산출물에도 금지어 스캔 적용(Step·sourceTrace) → ③프로토타입 버킷을 2계층으로 명문화(/restart 全0 게이트 ≠ /flow-lab 내부 콘솔). 순서가 곧 우선순위입니다.

SECTION 3

남은 구멍 — 스캔이 렌더하지 않는 출력 두 곳, 그리고 2계층 프로토타입

아래 셋은 전부 화면 스캔은 통과했습니다. ①②는 스캔 정의(기본 상태·보이는 DOM) 밖의 출력이고, ③은 한 플래그 아래 숨은 서로 다른 게이트입니다.

공통 진단 — 스캔의 정의가 좁다. P12는 "어떤 화면을, 그 화면의 기본 상태에서, 보이는 DOM으로" 잽니다. 그래서 ①토글된 export 모드, ②클립보드/다운로드로 나가는 산출물이 정의 밖입니다. 두 곳 모두 사용자가 한 번의 탭으로 도달하고, 둘 다 금지어(Markdown 지향어 · Step/sourceTrace 하드금지)를 담습니다. P13-01·02는 스캔 대상을 "상태×산출물"로 넓혀, 지금의 0을 모든 상태에서 잰 0으로 승격합니다. 이건 P11의 교훈("안 재면 되돌아온다")을 화면 축에서 출력 축으로 한 칸 옮긴 것뿐입니다.

P13-02 · High · guardrail

"요청 정리본 복사" 산출물에서 금지어 분리 + 클립보드 스캔

무엇을 · buildUrlFirstSupplyCandidateProductionMarkdown은 현재 사용자 "요청 정리본"과 개발 handoff를 한 문서로 만듭니다(# Flow 제작 후보 handoff · Canonical URL · Step으로 나눌 수 있는 · sourceTrace). ① 사용자 버튼("요청 정리본 복사")은 사용자어 요약만 복사(원문 링크·내 제목/메모·상태·마지막 조회), ② handoff 스캐폴딩(Step·sourceTrace·handoff·Canonical URL 라벨)은 내부/운영 경로로 분리하거나 사용자어로 치환. 가드레일 스캔을 visible DOM 외에 클립보드/다운로드 문자열까지 확장해 금지어(Step·Item·sourceTrace·partial_draft·source_import_required·review·audit)를 잡음. AC · 사용자 복사 산출물에서 금지어 0 · url-first-supply-queue.test.ts의 handoff 단언은 내부 함수 대상으로 이동 · 사용자 요약엔 금지어 음성 테스트 추가.
