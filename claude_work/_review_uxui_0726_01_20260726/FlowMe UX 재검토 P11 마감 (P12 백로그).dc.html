SECTION 1

Overall Judgment — P11 닫힘, 리스크는 스캔 밖으로 이동

현 상태 판단 — 정상 4탭은 견고

P11이 목표한 두 가지가 모두 닫혔습니다. ① 밀도 규칙 확산 — 지난 할 일 시트(s17)가 그룹 헤더 1회 구조로 바뀌고(statusSheetGroupMeta 1 · ungroupedRow 0), 인벤토리 3중 지표가 1개로(duplicateProgressMetric 0). ② 주장의 측정화 — 이어하기·agenda·aria가 이제 JSON marker로 판정됩니다(continuationActionable 4 · explanationOnly 0 · rowControlAccessibleName context 4/4). 정상 26캡처 전 버킷 0, overflow 0, 공개 저장경로 9/9. 정상 IA에는 Blocking·High가 없습니다.

P12에서 가장 먼저 볼 사용자 리스크

URL-first 진입 표면이 가드레일 밖에 있습니다. 27~32는 supplement evidence에 marker가 0개 — 스크린샷 메타(bytes·hash·scrollHeight)만 담겨 있습니다. 그리고 그 미스캔 영역이 정상 라우트(/flows)의 상태인데도, 4탭이 0으로 지켜온 것을 그대로 노출합니다: source slug(Mathbang·s27), raw ISO(2026-07-07·s30), 내부 단계어(P0·s29), 제작 전문어(Canonical URL·handoff·Claude review용·제작용 정보·s30). 스캔이 닿지 않으면 기준선은 조용히 되돌아갑니다 — P9→P11이 증명한 그 교훈이 새 표면에서 반복됩니다.

한 줄 판정 — Post-P11은 정상 4탭 기준으로 출시 가능합니다(Blocking 0). 단, URL-first는 아직 실험 표면인데 정상 라우트 위에 렌더되고 스캔도 안 됩니다. P12의 1번은 기능 추가가 아니라 ①URL-first 사용자 상태(hit/miss/candidate)를 정상 스캔에 편입 → ②거기서 드러나는 slug·ISO·내부어 회귀를 봉합 → ③/flow-lab 프로토타입 게이트를 /restart와 동급으로. 순서가 곧 우선순위입니다.

SECTION 3

남은 구멍 — 스캔이 닿지 않는 표면에서 세 개의 기준선이 샌다

아래 셋은 전부 정상 라우트 /flows의 상태입니다(4탭 nav 노출, h1 "무엇을 저장할까요?"). 그런데 정상 스캔(s02)은 URL을 입력하기 전의 빈 상태만 찍었고, 아래 결과 상태는 supplement로만 캡처돼 marker가 없습니다.

구멍 ④ — 증거 형태 자체. url-first-supplement-evidence.json은 6개 시나리오에 screenshotBytes·screenshotHash·scrollHeight·bodyTextLength만 담습니다. internalHits·sourceSlugHits·rawIsoLines·structuralDisplayHits 같은 판정 필드가 하나도 없습니다. 즉 ①~③은 지금 이 문서의 육안 검토로만 잡혔고, capture는 이 상태들을 "찍기만" 하고 "재지" 않습니다. 정상 26장에는 있는 marker 계층이 URL-first 6장에는 통째로 빠져 있는 것 — P12-01이 이 구조적 공백을 메웁니다.

Baselines To Preserve — P4~P11에서 닫힌 것

아래는 P12 어떤 작업도 깨면 안 되는 기준선입니다. 특히 URL-first 수정(P12-02~04)은 노출 카피만 손대고 canonical lookup·source-backed 재사용 구조는 그대로 둡니다.

  • 4탭 IA: 홈 / Flow 찾기 / 캘린더 / 내 Flow — 변경 금지
  • 공개 /f/[slug]는 공유 shell 유지, 4탭 app shell로 강제 편입 금지
  • primary는 내 Flow에 저장 또는 입력/setup, 콘텐츠 더 보기는 뒤·focusable(before-primary 0 유지)
  • seed/source-backed 데이터 구조, 저장/실행/export 스키마 불변
  • sourceUrl · sourceTrace · detail · memo · export 접근 삭제 금지
  • guardrail 판정 정본은 lib/flow/user-surface-guardrails.ts — capture·E2E·유닛 전부 lib 경유
  • 정상 route 스캔 0 유지: internal · slug · 구조어(...지도·trailing Flow) · raw ISO(visible+input) · 첫 할 일 반복 · overflow
  • native date input ISO 값은 면제 버킷에만 기록, label/help/card로 승격 금지
  • URL-first는 canonical lookup 우선 — hit는 기존 source-backed Flow로 연결, miss/needs_review는 non-executable local candidate로 보류
  • 내 Flow continuation은 실제 열기 가능한 행/컨트롤(continuationActionable · explanationOnly 0)
  • 지난 할 일 시트 · 캘린더 agenda: 공통 메타 그룹 헤더 1회, 행은 제목+컨트롤만
  • 인벤토리 행 진행 지표 중복 0 · 전체 탭 헤더 대형 잔여 총계 0
  • 행 컨트롤 visible 라벨 짧게(열기·수정·완료), aria에 행 맥락 유지(context 4/4)
  • /restart/moving-d30 프로토타입 버킷 분리 + display 게이트 승격 전 필수 · D-30 마일스톤 그룹 헤더
  • 워크벤치: 행 상세 source 링크 0 · source 접근 영역 ≥1 · 반복 상세 문장 0
  • 패키지 메타: UI baseline commit ≠ package commit 표기 분리
