그런데 손잡이가 화면마다 다르다. 같은 "완료"가 어디선 버튼, 어디선 체크박스고, 캘린더 라벨은 "이…"로 잘리고, 진행 숫자는 5군데서 반복된다.

이번 P18-00도 UI polish가 아니라 제품 방향 판단 요청입니다. 결론부터: FlowMe는 개인 실행 도구가 맞고, P18은 P17 백로그를 전부 닫았습니다 — 캘린더 Flow 구별(같은 날짜 distinct Flow 2), 내 Flow 오늘 1프레임·1카운트·인라인 완료(frame 1 · count source 1 · inline 5), 공개 /f 저장 primary·내보내기 Flow 단위 secondary(sticky 9), 캘린더=날짜 우선·내 Flow=할 일 우선 분리, URL-first 개인 overlay(이사일 수정 + 저장 후 항목 날짜 override), 정직한 miss draft gate(implies live AI: false). 방향을 바꿀 이유가 없습니다. 다만 P18이 각 화면을 빠르게 마감하는 동안 화면들이 아직 "하나의 도구"로 안 읽힙니다 — 완료 컨트롤이 화면마다 다르고, 캘린더 Flow 라벨이 잘려 P18이 넣은 Flow 구별이 무력화되고, progress 숫자가 모든 층에 붙습니다. P19의 축은 새 표면이 아니라, 세워둔 실행 화면들의 손잡이·라벨·숫자를 하나로 맞추는 것입니다. Studio/AI draft는 그 다음입니다.

SECTION 1

Executive Summary — 화면은 다 지어졌다, 이제 하나로 읽혀야 한다

P18은 P17 백로그를 전부 닫았다

P17이 "부엌은 아직"이라 남긴 것들이 실제로 들어왔다 — 캘린더가 Flow별 색·마커·그룹으로 구별(43·44), 내 Flow 오늘이 "오늘 2개 남음" 단일 프레임 + 인라인 완료(16), 공개 /f가 Flow 단위 저장 primary·내보내기 secondary(06), URL-first에 이사일 수정 + 저장 후 항목 날짜 override(13b·13c), miss는 "지금 바로 Flow를 만들지 않습니다"로 정직(29). evidence도 frame 1 · count 1 · inline 5 · sticky 9 · anchor edit true · live AI false · overflow 0로 닫혔다.

그런데 화면들이 아직 "하나의 도구"가 아니다

P18이 각 화면을 빠르게 마감하며 부품이 안 맞은 채 남았다 — 같은 "완료"가 오늘 카드에선 버튼, 상세 헤더·캘린더 모바일에선 체크박스(16 vs 43·14). 캘린더가 Flow 라벨을 넣었는데 모바일 그리드에서 "이…"/"8…"로 잘려 구별이 무력화되고 같은 Flow가 똑같은 점 3개로 쌓인다(43). progress 숫자가 Flow·오늘 행·캘린더·하위 항목·공개까지 5층에 붙는다. wide 캘린더는 헤더가 두 번 찍힌다(44). 사용자가 남긴 의문("깔끔·일관?", "1/5가 무슨 뜻?", "완료가 체크박스+버튼 혼재")의 직접 근거다.

중심축(재확인)

개인 실행 도구로 확정. "URL/메모 → 실행 Flow → 내 Flow/캘린더/export"의 앞·뒤 절반이 모두 화면에서 작동한다(01·27·13·43). P17이 약하다던 "뒷절반(실행 종착지)"이 P18에서 실제로 채워졌다 — 남은 건 방향이 아니라 마감 일관성.

P19의 성격

P17→P18은 없던 것을 짓는 백로그였다. P18→P19는 지어둔 것을 맞추는 백로그다 — 완료 컨트롤 통일 · 캘린더 라벨 가독성 · progress 위계 · 중복 헤더 제거. 전부 4탭·스키마·공유 shell을 안 건드리는 표시/컨트롤/카피 레벨. 눈에 보이는 변화는 크고 리스크는 작다.

Studio/AI draft

아직 열지 않는다. 다만 P18이 저장 후 항목 편집 overlay(13c)와 Studio "초안" 탭(39)을 이미 만들었다 — AI draft가 재사용할 그릇이 생겼다. 그래서 순서는 명확하다: 실행 화면 일관성 먼저 → 그 overlay 위에 첫 AI draft slice. P19에선 spec만.

한 줄 판정 — FlowMe는 개인 실행 도구가 맞고, P18이 실행의 방들을 다 지었다. 이제 문제는 빈 방이 아니라 방마다 손잡이·라벨·숫자가 다른 것이다. P19는 새 방을 늘리지 말고 세워둔 화면들을 하나의 도구로 맞춘다 — 그 첫 단추는 어디서든 "완료"가 같은 모양이고, 캘린더가 잘리지 않은 Flow 이름을 말하는 것이다. 부엌은 갖췄다. 이제 그릇을 맞출 차례다.

Persona Findings — 7개 페르소나

페르소나 1

처음 온 사용자 — "URL/메모 → 실행 Flow"가 한 문장으로 읽히는가

부분 문제

양호 · 홈 h1 "콘텐츠를 일정과 할 일로 저장" + 서브 "블로그·유튜브·공식 안내에서 따라 할 부분만 골라 일정과 체크리스트로 저장"이 "콘텐츠 → 일정/할 일"을 한 줄로 전달한다(01). 추천 카드가 "이사일만 넣으면 D-30 일정·할 일 5개", "입력 없이 8개 단원 진도표"로 저장하면 뭐가 생기는지를 결과어로 약속. 4탭 / → /flows → /my → /calendar도 이해됨.

남은 문제(P17 이월) · 제품 가설의 핵심인 "URL/메모를 붙여넣는" 입력이 홈의 첫 행동이 아니다. primary는 여전히 "콘텐츠 고르러 가기"(카탈로그)이고 URL 붙여넣기는 /flows 안쪽(29). 홈만 보면 "추천 콘텐츠 카탈로그"로 읽혀, FlowMe를 범용 투두가 아닌 "내 URL/메모를 바꿔주는 도구"로 각인시킬 첫 문장이 약하다.

사용자 영향 · 자기 URL/메모를 가진 신규 사용자가 "어디에 붙여넣지?"를 홈에서 못 찾는다. 저순위(방향 아님, 카피/entry). → 근거: 01 primary=카탈로그행. §3 P19-06, 결정 §4 밖(방향 유지).

페르소나 2

URL-first hit / custom-start — 찾아 가볍게 고쳐 시작하는 가치

양호

양호 · P18이 P17-05 우려를 닫음 · hit이 "그대로 시작 / 조금 고쳐 시작" 토글 + 기준일(학습 시작일/이사일) + export 3모드(캘린더·메모 문서·체크리스트)로 정리됐다(27·28b). custom-start는 Step을 ☑로 포함/제외한다. 무엇보다 기준일 카피가 두 화면에서 동일하다 — "바꾸면 전체 일정 기준이 다시 맞춰집니다. 따로 바꾼 할 일 날짜는 그대로 유지됩니다"(27=내 Flow 13b와 같은 문장). 이사일은 "D-30부터 D-Day까지 배치합니다"로 기준=이사일임을 명시(28b) — 사용자 피드백 1번("기준일이 이사일인지 헷갈렸다")의 직접 대응이 들어왔다.

판단 · 저장 전엔 Step 포함/제외 + 기준일까지, 개별 항목의 날짜·문구는 저장 후 내 Flow에서(13c) — 이 분업이 이번 리뷰에서 옳게 잡혔다. 저장 전 화면을 가볍게 유지하고, 세밀한 편집은 실행 공간으로 넘긴다. → 근거: 27·28b 기준일 카피 일관 · export 3모드. 결정 §4-4(저장 후 유지).

페르소나 3

URL-first miss / candidate / draft-gate — 정직하게 읽히는가

양호 · AI draft는 P19 spec

양호 · 정직성 확보 · miss가 "URL과 메모를 초안 요청으로 보관하고, 바로 만들지는 않습니다", "지금 바로 Flow를 만들지는 않습니다"로 실제 AI 생성을 과장하지 않는다(29, miss draft gate implies live AI: false). 나중에 매칭되면 카드가 "이제 실행 가능 · Flow 결과로 이동"으로 승격되고, "요청 내용 보기·제목/메모 수정·삭제"까지 사용자어로 닫힌다(30, candidate 내부어 hit 0).

남은 판단(피드백 4번) · miss의 종착은 여전히 "보관"이다 — 초안을 만들어 손보는 흐름은 아직 없다. 첫 AI draft slice를 언제·어떻게 열지가 P19 결정 대상. 결론은 §4-5 — 지금 열지 않고 spec만. 근거: 초안은 사용자가 손볼 overlay가 있어야 가치가 있는데, 그 overlay를 P18이 방금 만들었다(13c). 실행 화면 일관성 마감 뒤 그 위에 얹는 게 안전하다. → 근거: 29·30. §3 P19-08, 결정 §4-5.

페르소나 4

공개 /f 공유 진입 — Flow 단위 저장이 primary로 읽히는가

부분 문제 · 저장 전 항목 체크

양호 · 하단 sticky 주 행동이 Flow 단위 "내 Flow에 저장"으로 고정(06, sticky save/setup 9), 셋업(검사일 입력)이 저장 앞에 놓여 "값 넣고 통째로 저장" 흐름이 선다. 내보내기는 저장 뒤 Flow 단위 secondary로 내려갔다(P18-03 반영).

남은 문제(피드백 3번) · 워크벤치형 /f에서 저장 전인데 항목마다 □ 체크박스가 눌리고 하단에 "진행률 0/12"가 뜬다(25). 이 상태에서 옆의 "내 Flow에 저장"과 만나면 "항목을 체크해서 진행을 저장하는 것"인지 "Flow를 통째로 저장하는 것"인지 경계가 흐리다. 항목 체크가 개별 저장/내보내기 단위처럼 오해될 여지가 아직 남아 있다.

사용자 영향 · 공유로 처음 온 사용자가 저장 전에 항목을 만지작거리다가 "이게 저장되나?"에서 멈춘다. → 근거: 25 저장 전 체크+진행률. §3 P19-05, 결정 §4-3(Flow 단위 유지 + 저장 전 체크 톤 분리).

페르소나 5

My Flow 반복 사용자 — 오늘·완료·기준일·항목 날짜·progress

핵심 문제 · 완료 컨트롤/숫자

양호 · P18이 P17-02를 닫음 · 오늘이 "오늘 2개 남음" 단일 프레임 + 단일 카운트(16, frame 1 · count source 1)로 정리됐고, 오늘 카드에서 펼치지 않고 인라인 완료가 가능(inline 5). 그리고 기준일 수정入口가 훌륭하다 — "개인 사본 → 설정 조정 → 이사일 바꾸기"가 "이사일을 바꾸면 전체 일정 기준이 다시 맞춰지고, 따로 바꾼 할 일 날짜는 유지된다"는 기준일 vs 개별 항목 날짜를 명확히 구분(13b). 개별 항목은 상세에서 "이 할 일 날짜"로 override(13c). 피드백 1번이 실제로 해결됐다.

문제 ① 완료 컨트롤 혼재 · 같은 "완료"가 오늘 카드에선 초록 테두리 버튼(16), 상세 헤더에선 □ 체크박스(13c), 그 안 "확인 항목"은 또 하위 □ 체크박스 3개(13c), 공개 워크벤치는 □ 항목 체크박스(25). 한 동작(완료 표시)에 버튼·헤더 체크박스·하위 체크박스가 섞여 "무엇을 누르면 끝나는지"가 화면마다 다르다(피드백 6번).

문제 ② progress 숫자 과잉 · "0/9 완료"가 오늘 카드마다(16), "0/24 완료"가 Flow 행마다(18), "확인 항목 0/3"이 상세에(13c) — 같은 화면에서 서로 다른 분모가 겹친다. 오늘 할 일 옆의 "0/9"은 오늘과 무관한 Flow 전체 분모라 노이즈다(피드백 2번, "1/5·2/5가 무슨 뜻?").

문제 ③ 편집入口 깊이 · 기준일·항목 편집이 좋지만 "전체 탭 → 개인 사본 → 설정 조정 → 펼침"으로 깊다(13b). 발견 가능성이 낮다.

사용자 영향 · 실행 허브가 실제로 잘 지어졌는데 "완료를 어떻게 누르지 · 이 숫자가 뭐지"에서 매일 미세하게 걸린다. → 근거: 16·13b·13c·25. §3 P19-02·P19-03·P19-07, 결정 §4-1·4-2.

페르소나 6

Calendar-heavy — 같은 날짜 여러 Flow가 깔끔·일관되게 구별되는가

핵심 문제 · 이번 리뷰 1순위

양호 · P18이 P17-01을 닫음 · 캘린더가 이제 "색과 라벨로 Flow를 구분하고, 반복 항목은 아이콘으로 표시"(44)한다. 같은 날짜에 서로 다른 Flow가 그룹으로 분리되고(같은 날짜 distinct Flow 2 · agenda grouped by Flow true), 선택일 agenda는 Flow 초성 배지(●이/●컴)+색으로 묶인다. wide에선 이게 꽤 깔끔하다.

문제 ② wide 헤더 중복(회귀) · wide에서 "날짜별 실행 / 캘린더 / …" 헤더가 위·아래로 두 번 렌더된다(44). 첫 번째는 "언제 할지 정해진 항목을…", 두 번째는 "Flow별 항목을 날짜 기준으로…" — 같은 제목이 중복돼 "정돈 안 된" 인상. P18 마감 중 생긴 표시 회귀로 보인다.

SECTION 4

명확히 결정할 5가지 — 요청한 판단

사용자가 콕 집어 결정을 요청한 5개입니다. 각각 한 방향으로 결론내고 근거 screenshot과 백로그 ID를 붙였습니다.

1

Calendar progress "1/5" 류 숫자 → 캘린더에선 뺀다(상세/내 Flow로 이동).

캘린더는 "이 날 뭐 하지"를 묻는 날짜 화면이다. Flow 완료 분수("2개·2개 남음", "0/24")는 Flow 상태지 날짜 상태가 아니다. 캘린더엔 그 날 잔여("4개 남음")만 남기고 Flow 완료 분수는 내 Flow 전체 탭 1곳으로. 유지도 상세화도 아닌 "실행 중엔 숨기고, Flow 볼 때만 보이게"가 답. → P19-03, 근거 44·16·18.

2

My Flow 인라인 완료 컨트롤 → 체크박스로 통일.

완료는 되돌릴 수 있는 토글 상태다 → 체크박스가 정직하고 스캔·일관에 유리하다. 지금 이미 상세 헤더·하위 항목·공개 워크벤치가 체크박스(13c·25)라 다수 패턴에 수렴시키면 된다. 오늘/agenda 카드의 "완료" 버튼이 예외(16·44)이니 이를 체크박스로 바꾸고, 버튼은 "열기"(이동)에만 남긴다. "확인 항목" 하위 체크박스는 상세 안 별도 레벨로 유지. → P19-02, 근거 16·13c·43·44·25.

3

공개 /f export → Flow 단위 secondary로 충분. 별도 unit model 만들지 않는다.

저장·내보내기 단위는 Flow 하나로 유지가 맞다 — 항목 단위 저장/내보내기를 신설하면 단위가 늘어 오히려 혼동이 커진다. 지금 실제 문제는 unit model 부재가 아니라 저장 "전" 항목 체크·진행률이 개별 저장처럼 읽히는 것(25). 그래서 저장 전 체크를 미리보기 톤으로 낮추면 Flow 단위 secondary로 충분하다. → P19-05, 근거 25·06.

4

URL-first 항목 편집 → 저장 후 내 Flow 편집이 맞다(저장 전으로 당기지 않는다).

저장 전은 가볍게 — Step 포함/제외 + 기준일(28b)까지. 개별 항목의 날짜·문구·메모는 저장 후 내 Flow overlay(13c)에서. 전체 항목 편집을 저장 전으로 당기면 진입 화면이 무거워지고, 대부분은 "일단 저장하고 조정"을 원한다. P18의 이 분업은 옳은 결정 — 바꾸지 않는다. 대신 발견성만 개선(P19-07). → 근거 28b·13c.

5

Studio/AI draft를 P19에서 열까 → 아니다. 캘린더/내 Flow/공개 일관성이 먼저.

P18이 AI draft가 재사용할 그릇(13c 편집 overlay + 39 초안 탭)을 이미 만들었다 — 그래서 "언젠가"는 가능하다. 하지만 지금 열면 손잡이·라벨·숫자가 안 맞는 실행 화면 위에 신기능을 쌓는다. 순서: ① 완료 컨트롤·캘린더 라벨·progress 정리(P19-01/02/03) → ② 그 위에서 "AI 제안 → 13c overlay 확인/수정 → 내 Flow 저장" slice(P19-08은 spec만). Studio는 보조 표면으로 유지(5번째 탭·publishing 확대 아님). → P19-08, 근거 29·30·39.

SECTION 5

Evidence Gaps — 더 찍어야 판단이 닫히는 것

아래는 UI 결함과 구분되는 "증거만 부족한" 항목입니다. 다음 캡처에 이 viewport/state/fixture를 추가하면 P19 판단이 확정됩니다.

  1. 완료 "후" 상태 — 지금 캡처는 전부 미완료(0/N)다. 체크 후 카드/캘린더/공개가 어떻게 바뀌는지(취소선·이동·잔여 감소) 미캡처. P19-02 통일의 완료-상태 스타일 검증에 필요.
  2. 저장 3개 이상 캘린더의 색 구별 — 43·44는 2 Flow. 3~5 Flow에서 색/배지가 서로 구별되는지(색약 대비 포함), 모바일 셀 축약("+N")이 몇 개까지 견디는지 미캡처. P19-01 핵심.
  3. 같은 날 같은 Flow 다항목의 모바일 렌더 — 43은 "이사 준비 ●×3"이 잘린 채. 이걸 "Flow 1점 + N"으로 축약한 목표 상태 fixture가 없다.
  4. 공개 /f 저장 "후" 화면 — 저장 전(25)만 있고, 저장 후 항목 체크가 "진행 표시 전용"으로 활성화되는 화면 미캡처. P19-05 단위 분리 검증.
  5. 오늘 카운트 규칙 — "오늘 2개 남음"이 완료 시 실시간 감소하는지, 지난/다음과의 스코프 경계가 evidence로 미확정(P19-03).
  6. URL-first custom-start·miss의 wide — hit wide(37)는 있으나 custom-start·miss + 캘린더 다중 Flow의 wide 상호작용(필터 적용 후) spot check 부족.
  7. 개인 사본 overlay의 되돌리기·충돌 — 기준일 변경이 개별 override와 부딪칠 때(13b "따로 바꾼 날짜 유지")의 실제 동작·되돌리기 UI 미캡처. P19-07/AI draft(P19-08)의 선행 조건.
  8. 실기기 미검토 — 스크린샷 근거. 실제 터치 타깃(체크박스 44px)·스크롤·키보드·햄버거 상호작용은 별도.

P19 Recommendation

가장 먼저 할 1개 slice

P19-02 · 완료를 하나의 컨트롤로. 매일 가장 많이 반복하는 동작이 화면마다 버튼/체크박스로 갈리는 걸 체크박스 1종으로 통일. 작업량 대비 "하나의 도구" 인상을 가장 크게 끌어올리고, P19-01·03·05의 "체크의 의미"를 정렬하는 기준이 된다.

그다음 후속 slice

  1. P19-01 캘린더 모바일 라벨·같은 Flow 식별
  2. P19-03 · P19-04 progress 위계 + wide 헤더 중복(같은 캘린더 화면군, 함께)
  3. P19-05 공개 /f 저장 전 체크 톤 분리
  4. P19-06 · P19-07 홈 URL entry · 편집入口 발견성

당장 하지 말아야 할 것

  • AI draft 개방(실행 화면 일관성 전에 열면 불일치 위에 신기능)
