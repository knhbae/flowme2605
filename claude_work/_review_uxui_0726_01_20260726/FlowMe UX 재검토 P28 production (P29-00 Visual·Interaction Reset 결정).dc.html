SECTION 8 · Claude Design

Shared visual grammar & component anatomy

공통 문법은 이미 flow-ui.ts에 있다(surface·inset·toolbar·primary/secondary/tertiary action·segmented·input·selection row·execution row·status·disclosure + --flowme-* 토큰). 문제는 부재가 아니라 불균일한 조립이다. P29-01은 새 시스템을 만들지 않고, 이 primitives로 5 surface를 다시 조립하는 anatomy 규칙을 정한다.

Screen header (4 frame 공통)

eyebrow(카테고리) · 제목 · source trust · 3 count chip(내 조건/결과/전체). frame이 달라도 동일 순서. 새 chip 추가 금지.

Task row (한 anatomy)

[상태/번호] · [timing] 제목 · [보조 1줄] · [행 명령은 selection 시에만]. completable 아닌 role(resource/warning/reference)은 체크박스 없이 구분 표기.

Command hierarchy

primary 1(PRIMARY_ACTION) · secondary(SECONDARY) · 나머지는 overflow/tertiary. 화면당 primary는 하나. selection 모드와 completion 체크를 동시 노출 금지.

Disclosure 규칙

common path는 요약, advanced는 DISCLOSURE로 접기(routine 6필드, 원문 상세, 전체 outline). 저장 전에 필수값만.

Density & card weight

모든 블록을 카드로 감싸지 않는다. 구획은 border-y/여백으로, 카드(SURFACE)는 결과·결정 같은 실제 객체에만. chip은 count/trust에 한정.

State vocabulary

done·reopen·skip·hold·excluded·archived를 색·라벨로 구분(같은 완료 level 아님). count는 항목/날짜/행수로 통일해 receipt까지 이어짐.

참고 reference pattern (복제 아님 · 기대치 대조군)

가져올 것 · 단일 quick-add 결정 표면(Todoist·Google Calendar) → H-2 · summary→"더 보기" 진행형 설정(Fantastical·Sunsama) → H-3 · 다음-행동 우선 실행 화면(Things Today·Fitbod의 "지금 이 세트") → H-4 · scope 그룹핑(TripIt·Notion의 최근/즐겨찾기) → M-3. 가져오지 않을 것 · 무한 nested planner(Notion), 전문 기록/그래프(Strava·Fitbod의 분석), 자체 캘린더 소유(Google Calendar 편집 전권), 마켓/결제. FlowMe는 portable execution layer이지 이 도구들의 대체가 아니다.
