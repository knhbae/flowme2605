## 1. UX 진단

**상용 실행 앱처럼 보이는 정도** — 골격은 상용 앱이고, 표면은 아직 기획 데모다. 4탭 IA, 저장→실행 루프, 결과 중심 export 라벨, 접힌 원문·근거 등 구조적 결정은 이미 상용 수준. 그러나 거의 모든 화면이 "라벨 붙은 설명 카드"를 위에서 아래로 나열하는 같은 문법을 써서, 행동 전에 읽어야 할 블록이 화면당 4~6개다. 상용 앱은 첫 화면에서 "내가 만질 것" 1개를 주고 나머지를 숨긴다. FlowMe는 지금 "내가 이해할 것" 4개를 먼저 준다. 이번 루프의 핵심은 새 기능이 아니라 **위계 압축과 언어 교정**이다.

**가장 큰 병목 3**
1. 모바일 홈에 첫 행동 버튼이 없음 — hero CTA가 `hidden sm:flex` (01)
2. 저장 직후 "먼저 할 일부터 열어보세요"와 "남은 할 일이 없습니다"가 동시에 보임 (10)
3. 지도 상세에서 필수 입력(이사일)은 상단, 저장은 하단 sticky — 행동이 두 곳으로 찢어짐 (03)

**유지해야 할 좋은 방향 3**
1. "저장 전 보기 → 저장하고 시작 → 먼저 할 일" 실행 루프 설계
2. 결과 중심 export 라벨("캘린더 파일 받기 · 시트로 받기 · 메모로 복사")
3. 원문 · 근거 · 메모를 삭제하지 않고 접어두는 신뢰 구조 (sourceTrace 보존)

**설명형 화면처럼 보이는 지점**
- 홈 "시작 경로 · 고르고 저장하고 이어가기" 4단계 카드 — 사용법 설명 슬라이드 (01, `HomeLanding`)
- Flow 찾기 이중 헤더: h1 "저장할 실행 콘텐츠" + h2 "내 상황에 맞는 콘텐츠 고르기" + 보조문 2벌 (02, `FlowList`)
- 공개 상세: 약속 박스 + 문단 + 칩 3~5개 + "저장 후 일정과 체크로 이어집니다" 박스 — 저장 전 읽을 블록 6개 (05 · 06)
- 지도 상세 "저장되는 결과물" 전폭 카드 3장 — 단어 하나를 카드 한 장으로 (03 · 04)
- 내 Flow 오늘의 카드 안 카드 — eyebrow + 제목 겹겹 반복 (08)

**이미 실행형 앱처럼 보이는 지점 (유지)**
- 카드의 "입력 → 결과" 약속 한 줄 + "먼저 확인할 일" 프리뷰 (02)
- 모바일 sticky 저장 바 + 단일 주행동 (03)
- 저장 직후 배너의 "먼저 할 일 열기 / 전체 할 일 보기" 라우터 (10)
- 오늘/전체 2탭, 진행률 · 다음 할 일 프리뷰 (08 · 09)
- "체크 N개 열기", "메모 · 원문" 접힘 (03~06)

**5초 안에 이해 못할 가능성이 높은 화면**
- 홈(모바일): hero에 버튼 없음 → 첫 행동이 스크롤뿐 (01)
- 지도 상세: 입력과 CTA가 화면 양끝 (03)
- 저장 직후 내 Flow: 상반된 두 메시지 동시 노출 (10)
- 내 Flow 오늘: 첫 카드가 "남은 할 일이 없습니다" 공지 (08)
- 캘린더: 헤더 2벌 + 빈 그리드, 일정은 4px 칩 (11)

**저장 후 다음 행동이 약한 지점**
- 날짜 없는 콘텐츠(수학 진도표) 저장 시 오늘 탭이 "남은 할 일이 없습니다"로 시작 (10)
- 배너의 "먼저 할 일"과 워크스페이스 첫 카드가 다른 항목/상태 (10)
- "2026-06-22 예정 할 일" — 기계 날짜가 헤드라인 (08)
- 빈 상태 CTA 2개("Flow 찾기" + "새 Flow 만들기") 경쟁 (07)

**내부 모델이 사용자에게 노출되는 지점**
- "1개 묶음 · 5개 할 일 · 8개 체크" — Map→Flow→Step→Item 카운트 언어가 카탈로그·지도 상세·저장 바·배너에 반복 (02 · 03 · 04 · 10)
- 공개 상세 제목 "…체크 Flow" 접미 (05)
- "원문 기반 데모" · "데모 기준일" · "실제 오늘과 다른 고정 기준일" 배지 (08 · 11)
- 카탈로그 상태 "확인 가능" — 사용자에게 무의미한 검수 상태 번역 (02)
- 저장 목록 "검수 필요" amber 배지 — 추천 콘텐츠가 저장 후 경고로 변함 (`getMyFlowContentReadiness`)
- 제작자 화면 "Flow 후보 · 샘플 후보 · 원본 검토" (`CreatorDirectory`, 보조 화면이라 2차)

## 2. 우선순위 개선안

### Blocking — 이번 루프에서 반드시

**B1. 모바일 홈에 주행동 버튼이 없다**
- 근거: 01 · `HomeLanding` CTA 컨테이너 `hidden sm:flex`
- 혼란: 누를 것이 없어 "읽는 페이지"로 인식, 첫 행동이 우연한 스크롤에 의존
- 수정: hero 안에 전폭 primary "콘텐츠 고르러 가기" 모바일 상시 노출 (→ /flows)
- 효과: 홈 5초 테스트 통과 — 서비스 목적 + 첫 행동이 한 뷰포트에

**B2. 저장 직후, 배너와 워크스페이스가 반대 말을 한다**
- 근거: 10 · `renderPostSavePanel`(≈L5287) "먼저 할 일부터 열어보세요" vs 오늘 카드(≈L6147) "남은 할 일이 없습니다" — 날짜 없는 콘텐츠는 오늘 큐에 안 잡힘
- 혼란: 방금 할 일 8개를 저장했는데 "없다"고 답함. 저장 실패처럼 읽힘
- 수정: post-save 진입 시 오늘 첫 슬롯 = 방금 저장한 콘텐츠의 먼저 할 일(날짜 없으면 첫 항목). 배너와 동일 대상. "남은 할 일이 없습니다"는 post-save 모드에서 미노출
- 효과: "저장 = 실행 시작" 약속이 화면에서 증명, 첫 저장 이탈 감소

**B3. 필수 입력과 저장 CTA가 화면 양끝으로 분리**
- 근거: 03 · `SourceBackedFlowMapSaveButton.tsx` — 입력은 hero, 저장은 하단 sticky. 미입력 시 버튼을 눌러야 에러, 에러 문구는 뷰포트 밖 hero에
- 혼란: 버튼을 눌렀는데 아무 일도 없는 것처럼 보임
- 수정: 미입력 상태 sticky 버튼 라벨 "이사일 입력" → 탭하면 입력 필드로 스크롤 + 포커스 + 하이라이트. 입력되면 "저장하고 시작"으로 전환
- 효과: 입력→저장이 한 동선, 지도 저장 완료율 상승

**B4. ISO 날짜가 제목으로 노출된다**
- 근거: 08 · 10 — "2026-06-22 예정 할 일", "2026-07-03 기준 할 일". 캘린더 셀 "22일" 접미 반복 (11)
- 혼란: 기계 문자열이 제목 자리 차지, "기준 할 일"은 시스템 말투
- 수정: 사용자 표면 날짜 포맷터 1개 — "6월 22일 (월)", 오늘/내일 프리픽스. 제목은 행동 언어("오늘 할 일" 등)
- 효과: 내 Flow · 캘린더가 즉시 일정 앱 톤으로. 비용 대비 체감 최대

### High — 5초 이해와 밀도

**H1. Flow 찾기 이중 헤더** — 02 · `FlowList`. 같은 말 2벌, 첫 카드가 뷰포트 밖. → 헤더 1벌("무엇을 저장할까요?" + "저장하면 일정과 체크리스트가 생깁니다."), 개수 배지는 목록 위 텍스트로. 효과: 첫 뷰포트에 검색+칩+카드 1.5장.

**H2. 카탈로그 카드가 판단 1번에 정보 9조각 요구** — 02 · `FlowMapCatalogCard`(L923) · `DirectoryFlowCard`(L808). 카드 1장 ≈ 뷰포트 ⅓. → 카드 = 카테고리 1 + 제목 + 약속 한 줄 + 먼저 할 일 + CTA 1 (§4.1). 요약 문단·2번째 메타 줄·하단 링크 2개 제거. 효과: 높이 ≈230→160px, 첫 화면 비교 2→3장.

**H3. 공개 상세 hero가 저장 전 6블록** — 05 · 06 · `PublicFlow`(L8048). 입력이 CTA보다 아래, 날짜 영역에 버튼 3개. → hero = 카테고리·제목·결과 한 줄·입력(onChange 즉시 반영, 적용 버튼 삭제)·CTA·먼저 할 일 (§4.2). 효과: 입력→저장→먼저 할 일 한 뷰포트.

**H4. "묶음" 카운트와 "~Flow" 접미** — 02 · 03 · 05 · 10. "묶음"은 내부 계층을 알아야 이해됨. → 카운트는 "할 일 5개"(필요시 "체크 8개"까지), 제목 접미 제거, "묶음"은 지도 상세 소제목 구분에서만. 효과: 내부 모델 몰라도 전 화면 읽힘.

**H5. 오늘 탭: 빈 상태 문구가 첫 슬롯 차지** — 08. 카드 안 카드 중첩, "다음 할 일" 라벨 3회 반복. → 첫 슬롯 = 항상 다음 행동(오늘→밀린→다음 fallback), 오늘 비면 "다음 할 일" 카드가 첫 슬롯 + "오늘은 남은 일이 없어요" 캡션 한 줄, 중첩 1단계 평탄화 (§4.4). 효과: 실행 허브로 읽힘.

**H6. 캘린더가 달력 위젯처럼 보임** — 11. 헤더 2벌, 셀 "일" 접미, 선택일 목록이 첫 뷰포트에 없음. → 헤더 1벌 + 그리드(숫자만, dot) + 그리드 아래 선택일 agenda 고정, 진입 시 가장 가까운 일정일 자동 선택 (§4.5). 효과: 진입 3초 안에 다음 일정+그날 할 일.

**H7. 데모 · 검수 배지가 사용자 표면에 샌다** — 08 · 11 · `getMyFlowContentReadiness`. → 데모 배지는 `?demo=` 파라미터에서만 렌더, 카탈로그 노출 콘텐츠는 저장 후 readiness 배지 미표시(seed 정합). 효과: 사용자/내부 화면 분리 원칙 실현.

### Medium — 일관성과 중복

- **M1** 홈 "시작 경로" 4단계 카드 — 탭과 중복 (01) → 제거 또는 추천 콘텐츠 2~3장으로
- **M2** export 라벨 불일치 — "캘린더 파일 받기" vs "캘린더 .ics 받기" vs "캘린더에 넣기 · .ics" (L8579 · L8741 · L10620) → 상수 1세트로
- **M3** 공개 상세 날짜 영역 버튼 3개(적용·날짜 미정·예시 보기) (05) → input 1 + "날짜 없이 저장" 링크 1
- **M4** 저장 목록 "오늘 0 · 다음 0 · 밀림 0" + %칩/n·n칩 중복 (09) → 0개 칩 숨김, 진행바 + n/n 하나
- **M5** 고정 레이어 2층 — sticky 저장 바가 하단 탭 위에 또 뜸 (03 · 04) → 한 층으로 도킹
- **M6** 12개 콘텐츠에 필터 UI 과다 (02) → 검색 컴팩트 1줄, 칩 유지
- **M7** 빈 상태 CTA 2개 경쟁 (07) → 단일 "콘텐츠 고르러 가기", 만들기는 메뉴 유지
- **M8** "지난 일정" vs "밀림" vs "밀린 할 일" 3중 라벨 (08~10) → "밀린 할 일"로 통일

### Low — 다듬기

- **L1** 홈 추천 카드 입력/저장/결과 3분할 truncate (01) → 결과 한 줄로
- **L2** 브랜드 표기 불일치 (FLOW / FlowMe / 내 Flow) → 기준 1개
- **L3** 색 토큰 이원화 (#3654FF vs blue-700, #6E6B64 vs slate-600) → §9
- **L4** 제작자 화면 내부어 — 2차 루프에서

## 3. 화면별 Revised UX Spec

### ① 홈 (01 · HomeLanding)
- 목적: 서비스 약속을 한 줄로 증명하고 30초 안에 콘텐츠 고르기로 보낸다
- 첫 화면 정보: 헤드라인 + 추천 콘텐츠 1장(제목·결과 한 줄·먼저 할 일)
- 첫 행동: "콘텐츠 고르러 가기" 전폭 버튼 — 모바일 포함 상시 (B1)
- 낮출 것: 추천 카드 입력/저장/결과 3분할 → 결과 한 줄 (L1)
- 접을 것: 없음 — 홈은 한 뷰포트 반이면 충분
- 제거/이동: "시작 경로" 4단계 카드(M1), "만들기" 노출 → 보조 메뉴
- 유지: 헤드라인 방향, 추천 1장 원칙, 카탈로그 비복제 규칙

### ② Flow 찾기 (02 · FlowList)
- 목적: 저장할 콘텐츠 하나를 5초 스캔으로 고르게 한다
- 첫 화면 정보: 헤더 1벌 + 검색/상황 칩 + 카드 1.5장
- 첫 행동: 카드 탭 = 저장 전 보기 (카드 전체 단일 링크)
- 낮출 것: 개수 배지 → 목록 위 12px 텍스트, 검색 카드 테두리 (M6)
- 접을 것: 태그/카테고리/정렬 상세 필터 — 현행 details 유지
- 제거/이동: 중복 h2 블록(H1), 카드 "바로 시작 · 원문" 링크 → 상세(H2), 상태 라벨 "확인 가능"
- 유지: 상황 칩, 약속 한 줄 + 먼저 할 일 구조, "저장 전 보기" CTA, 통합 목록

### ③ Flow Map 상세 (03 · 04 · SourceBackedFlowMapPage.tsx)
- 목적: 무엇을 넣으면 무엇이 저장되는지 확인시키고 한 번의 탭으로 저장시킨다
- 첫 화면 정보: 제목 + 결과 한 줄 + 날짜 입력 + 결과물 칩 1줄
- 첫 행동: 이사일 입력 → sticky "저장하고 시작" (B3)
- 낮출 것: 카운트("1개 묶음 · 5개 할 일 · 8개 체크" → "할 일 5개"), 카테고리/상태 칩
- 접을 것: 할 일별 전체 체크("체크 N개 열기" 유지), 메모·원문 details 유지
- 제거/이동: "저장되는 결과물" 카드 3장 → 인라인 칩, hero "원문 보기" → 원문 섹션 헤더 링크
- 유지: "저장 전 보기" eyebrow, sticky 저장 바(개선형), 원문 구조 보존

### ④ 공개 Flow 상세 (05 · 06 · PublicFlow)
- 목적: 이 콘텐츠 하나를 저장하면 무엇이 생기는지 보여주고 저장시킨다
- 첫 화면 정보: 제목("Flow" 접미 제거) + 결과 한 줄 + 필요 입력 + 먼저 할 일 한 줄
- 첫 행동: 날짜 입력(있는 콘텐츠만) → "내 Flow에 저장"
- 낮출 것: 설명 문단(2줄 클램프), 신뢰 칩 "출처 확인됨" 1개만
- 접을 것: 일정/체크 전체 목록(첫 3 + 전체 보기), 원문·출처, 메모, 내보내기 상세
- 제거/이동: "저장 후 일정과 체크로 이어집니다" 박스, 적용/예시 버튼(M3), D-칩 중복, 운영 문구
- 유지: 저장 CTA 1개 원칙, 원문 링크 보존, 경고 문구 위치와 톤

### ⑤ 저장 완료 직후 My Flow (10 · renderPostSavePanel)
- 목적: 저장이 끝이 아니라 실행의 시작임을 행동 1개로 보여준다
- 첫 화면 정보: "저장 완료" + "할 일 8개가 준비됐어요" + 먼저 할 일 제목
- 첫 행동: "바로 시작" (먼저 할 일 상세 열기)
- 낮출 것: 저장 요약 카운트 → "할 일 8개"
- 접을 것: 없음 — 배너는 3행 + 버튼 2개 이내, 닫기(×) 제공
- 제거/이동: 배너 아래 "남은 할 일이 없습니다" 오늘 카드 (B2)
- 유지: 배너 = 확인 + 라우터 원칙(미니 목록 금지), "전체 보기" 보조 CTA, /my 리다이렉트

### ⑥ My Flow 빈 상태 (07)
- 목적: 첫 저장으로 보내는 것, 하나만 한다
- 첫 화면 정보: "저장한 콘텐츠가 아직 없어요" + 저장하면 생기는 것 한 줄
- 첫 행동: "콘텐츠 고르러 가기" 단일 CTA (M7)
- 제거/이동: "새 Flow 만들기" 버튼 → 보조 메뉴 (P2 job)
- 유지: 저장 후와 동일한 헤더/탭 골격 — 인터페이스 재학습 없게

### ⑦ My Flow 오늘 (08 · MyFlows today)
- 목적: 오늘 처리할 것을 체크 가능한 행으로 바로 준다
- 첫 화면 정보: "7월 3일 (금) · 남은 할 일 2개" 헤더 + 첫 할 일 행
- 첫 행동: 행 체크, 또는 행 탭 → 상세
- 낮출 것: 소속 콘텐츠명/진행률 → 행의 보조 줄 한 줄
- 접을 것: 밀린 할 일(카운트 배지 + 펼침), 다음 7일, 완료 항목
- 제거/이동: 카드 중첩(H5), "기준 할 일"(B4), 데모 배지(H7), 빈 상태 문구의 첫 슬롯 점유
- 유지: 오늘/전체 2탭, 날짜 없는 콘텐츠 fallback 큐 로직

### ⑧ My Flow 저장 목록 (09 · renderFlowListRow)
- 목적: 저장물을 훑고 이어갈 것을 고른다
- 첫 화면 정보: 콘텐츠 행 — 제목 + 진행바 + "다음: {할 일}" 한 줄
- 첫 행동: 행 탭 → 항목 목록 펼침 (재탭 = 닫기, 현행 유지)
- 낮출 것: 0개 요약 칩 숨김, %칩 + n/n칩 → 진행바 + n/n (M4)
- 접을 것: 항목 전체 목록(프리뷰 5 + 전체 보기), 숨김/관리
- 제거/이동: "검수 필요" amber 배지(H7), 중복 카운트
- 유지: 다음 할 일 프리뷰, 행→목록→상세 3단 드릴다운, 원문 링크

### ⑨ My Flow 할 일 상세 (MyFlows detail · my-flow-step-export.ts)
- 목적: 한 항목을 실행(체크)하고 닫는다
- 첫 화면 정보: 제목 + 날짜 + 체크리스트 (없으면 "바로 할 일" 힌트 1줄)
- 첫 행동: 체크
- 접을 것: 접힘 행 4개 순서 고정 — 메모 → 일정 변경 → 원문·출처 → 내보내기
- 제거/이동: 기본 화면의 편집 컨트롤 (read-first 유지·강화)
- 유지: read-first, 완료 기준/주의, 항목 단위 export 재생성

### ⑩ 캘린더 (11 · MyFlows surface="calendar")
- 목적: 날짜를 기준으로 저장된 일을 실행한다 (schedule-first)
- 첫 화면 정보: 월 그리드(dot) + 가장 가까운 일정 날짜의 agenda 함께
- 첫 행동: 날짜 탭 → agenda 행 탭 → 상세
- 낮출 것: 월 이동 컨트롤, scope 필터(유형 2개 이상일 때만)
- 접을 것: 날짜 없는 할 일 — 하단 한 줄 링크로
- 제거/이동: 이중 헤더(H6), 셀 "일" 접미, 데모 배지, "내 Flow" eyebrow
- 유지: 글로벌 탭 지위, 그리드 + agenda, 가장 가까운 일정 기본 선택 규칙

### ⑪ source / detail / memo / export 영역
- 목적: 신뢰(원문)와 이동성(내보내기)을 필요할 때만, 예측 가능하게
- 첫 화면 정보: (상세 안) "원문 보기" 링크 1개만
- 낮출 것: 저장 전 export 버튼 → "저장하면 캘린더·시트·메모로 가져갈 수 있어요" 한 줄
- 접을 것: 원문·출처(원문 근거 포함), 메모, 내보내기 — 항상 접힘, 라벨 §5로 통일
- 제거/이동: 표면별 제각각 export 라벨(M2). 데이터(sourceTrace·sourceUrl) 삭제 금지
- 유지: 결과 중심 라벨 3종, 포맷 힌트는 보조 줄, 편집 상태 기준 재생성

### ⑫ 내부 검토 화면 (12 · /content-flows · /flow-lab)
- 목적: 내부자의 평가·전환 작업대. 사용자 화면과 완전 분리
- 제거/이동: 사용자 nav·홈·카탈로그에서 진입 링크 0개 보장. "우선 · 적합 4.5 · 검토" 평가 언어 반출 금지
- 유지: 숨김 라우트 규칙(SERVICE_STRUCTURE "Do Not Expose"), 제작자 미리보기 → map별 /my 프리뷰 규칙

## 4. 구체 UI Spec

### 4.1 Flow 찾기 카드 Redesign

정보 순서 (위→아래, 고정):
1. **카테고리 1개** — 11px #8A857B. 상태·원문 신호 제거. 우측 끝 규모 1개("할 일 5개")
2. **제목** — 18px/1.35 · 700 · 최대 2줄
3. **결과 약속 한 줄** — 14px · 700 · #3654FF. 형식 `{입력}만 넣으면 {결과}로 저장` / 입력 없으면 `바로 {결과}로 저장`
4. **먼저 할 일 박스** — bg #FAFAF8 · radius 12 · 라벨 "먼저 할 일" 11px + 제목 14px 1줄 클램프
5. **CTA "저장 전 보기"** — 전폭 · min-height 44px · #3654FF

처리 규칙:
- metadata: 카드에 남는 메타는 카테고리 + 규모 2개뿐. "1개 묶음 · 8개 체크 · 원문 연결 · 확인 가능" 전부 제거(상세에서)
- 요약 문단: 제거 — 약속 한 줄이 대신
- source 링크: 카드에서 제거, 상세 원문 섹션에서만 (카탈로그 단계 이탈 방지)
- "바로 시작" 링크: 제거 — 목적지 1개 원칙(카드 전체 = 저장 전 보기)
- 높이·밀도: padding 16px, 내부 gap 8~12px, 목표 150~170px (현재 ≈230px). 390×844 첫 뷰포트에 카드 2장 + 3장째 상단
- 탭 영역: 카드 전체가 하나의 Link (현행 DirectoryFlowCard 방식으로 통일)

### 4.4 My Flow

저장 직후 confirmation:
- 배너 3행: [저장 완료 배지 + 콘텐츠명] / ["할 일 8개가 준비됐어요"] / [먼저 할 일 · {제목}]
- 버튼: **"바로 시작"**(primary) + "전체 보기"(ghost). 닫기(×), 새로고침 후 미표시
- 배너 아래 오늘 첫 카드 = 배너와 **같은 항목** (B2)
- 배너 안 미니 목록/항목 상세 금지 (SERVICE_STRUCTURE 원칙)

오늘/다음/밀린 우선순위:
- 슬롯 순서: 오늘 할 일(체크 행, 최대 5) → 밀린 할 일(amber 카운트, 접힘) → 다음 할 일(최대 3, 컴팩트)
- 오늘 비면 첫 슬롯 = 다음 할 일 1개("다음 할 일 · 6월 22일 (월)") + "오늘은 남은 일이 없어요" 캡션
- 행 = 체크박스 + 제목(15px/700) + 보조 줄 1개(콘텐츠명 · D-n). 카드 중첩 금지
- 날짜 전부 "M월 D일 (요일)" (B4)

저장 목록 스캔 구조:
- 행 = 컬러 dot + 제목 + 진행바 + n/n + "다음: {할 일}" 1줄 + chevron, 높이 ≈88px
- 요약 칩은 값 있는 것만 (M4)
- 행 탭 → 항목 목록(5 + 전체 보기) → 항목 탭 → 상세 inline. 재탭 = 닫기

memo/source/export 위치:
- 항목 상세 하단 접힘 행 4개 순서 고정: 메모 → 일정 변경 → 원문·출처 → 내보내기
- 내보내기 3버튼: "캘린더 파일 받기 · 시트로 받기 · 메모로 복사"
- 콘텐츠 단위 export는 행의 ⋯ 메뉴로 — 목록 표면 버튼 나열 금지

### 4.5 캘린더

구조:
- 헤더 1행: "캘린더" + 월 표시 + 이전/다음 ("일정 보기" eyebrow, "내 Flow/월간 일정" 카드 헤더 제거)
- 셀: 숫자만("일" 접미 제거) + 일정 dot. 오늘 = outline, 선택 = filled #3654FF
- 그리드 바로 아래 선택일 agenda 고정: "6월 22일 (월) · 1개" + 체크 가능 행
- 진입 시 기본 선택일 = 오늘 이후 가장 가까운 일정 날짜 (없으면 오늘)

첫 행동과 역할 분리:
- 날짜 선택 후 첫 행동 = agenda 행 탭 → 항목 상세(내 Flow 상세와 동일 컴포넌트)
- 캘린더는 날짜 있는 항목만. 날짜 없는 할 일은 하단 "날짜 없는 할 일 N개는 내 Flow에서" 한 줄 링크
- 빈 날: "이 날은 일정이 없어요". 빈 캘린더: "아직 날짜가 있는 할 일이 없어요" + "콘텐츠 고르러 가기"
- scope 필터(전체/일정/루틴)는 두 유형이 실재할 때만

## 7. 수정 후 Validation Plan

**공통 조건**
- 뷰포트: **390×844** 필수, 360×800 · 768 · 1280 보조
- 각 화면 첫 뷰포트 스크린샷으로 5초 테스트: 초면 사용자가 "목적 + 첫 행동" 지목
- 기존 e2e(`tests/e2e/flow-mvp.spec.ts`) 전체 통과 + localStorage 스키마 무변경

**여정 1 — 처음 저장한 사람**
- 홈 → Flow 찾기 → 지도 상세 → 이사일 입력 → 저장 → 내 Flow
- 확인: 홈 버튼(B1), sticky 상태 전환(B3), 배너 = 첫 카드 항목(B2), "바로 시작" → 상세 → 체크 1개 완료
- 빈 상태 → 저장 → 복귀 시 같은 탭 골격 (인터페이스 재학습 없음)

**여정 2 — 여러 개 저장한 사람**
- demo fixture 3종(오늘 있음 / 오늘 없음 / 밀림 있음)으로 오늘 탭 첫 슬롯 검증
- 날짜 없는 콘텐츠(수학)만 저장한 상태에서 "남은 할 일이 없습니다" 미출현
- 전체 탭: 행 → 목록 → 상세 → 재탭 닫기. 0개 요약 칩 숨김

**캘린더 + export + 접힘**
- 캘린더 진입 시 가장 가까운 일정일 선택 + agenda 노출. 날짜 탭 → 상세 → 체크
- export: 3표면(공개 상세 · 내 Flow 상세 · 시트) 라벨 동일, .ics가 캘린더 앱에서 열림, 복사 피드백
- 원문·출처 / 메모 기본 접힘, 펼치면 원문 근거(sourceTrace) 보존

**내부 문구 노출 스캔 (자동화 권장)**
- 사용자 라우트(`/` `/flows` `/f/*` `/flow-maps/*` `/my` `/calendar`) 렌더 결과에서 다음 문자열 0건 단언:
  `Flow Map` `Step` `Item` `sourceTrace` `review` `audit` `partial_draft` `source_import_required` `검수` `후보` `데모 기준일` `원문 기반 데모` `묶음`
- e2e에 스캔 테스트 1개 추가로 회귀 방지

## 8. 유지할 것과 건드리면 위험한 것

**유지할 것**
- 4탭 IA (홈 · Flow 찾기 · 캘린더 · 내 Flow)
- "저장 전 보기 → 저장하고 시작 → 먼저 할 일" 루프
- 결과 중심 export 라벨 3종 체계
- 원문·근거·메모의 접힘 보존(삭제 금지) 신뢰 구조
- read-first 항목 상세, 오늘/전체 2탭
- 배너 = 확인 + 라우터 원칙 (미니 목록 금지)

**건드리면 위험한 것**
- `storage.ts` 키와 스냅샷 스키마 — 저장 데이터 호환성
- `source-backed-my-flow.ts`의 seed 병합/dedupe 로직
- sourceTrace · sourceUrl **데이터** — 라벨은 바꿔도 값은 보존
- e2e가 잡고 있는 `data-testid` — 마크업 변경 시 testid 이관 필수
- 앵커 날짜 재계산 · 루틴 반복(recurrence) 로직

**지금은 하지 말 것**
- 전면 리디자인 · 리브랜딩 (이번 루프는 위계 압축 + 언어 교정)
- AppClient.tsx 대규모 분할 리팩터 — UX 수정과 동시 진행 시 충돌 비용이 더 큼
- IA 변경 · 탭 추가 (사용자 근거가 생길 때 재개)
- 계정/서버 저장 도입

**2차 이후로 미뤄도 되는 것**
- 제작자 디렉터리 내부어 정리 (L4)
- 홈 추천 개인화, 캘린더 주간 뷰
- 카탈로그 확장(20개+) 시 필터 재설계
- 화면 단위 컴포넌트 분리 — 수정 끝난 화면부터 순차로

**별도 의견 — AppClient.tsx 구조가 UX 속도에 미치는 영향**
10,858줄 단일 파일에 홈·카탈로그·공개 상세·내 Flow·캘린더가 함께 있고, `MyFlows` 하나가 useState 50여 개를 든다. 이번 검토에서 발견된 문제의 상당수(라벨 3종 혼용, 같은 개념의 카드 2벌, 데모 분기 누수)는 이 구조에서 같은 UI를 여러 곳에 복붙하면서 생긴 것. 다만 이번 루프의 우선순위는 사용자 경험이므로, 리팩터는 "수정이 끝난 화면을 파일로 떼어내는" 후행 방식을 권함. 문구 상수화(§6 Medium)가 첫 단추.
