# 콘텐츠별 renderer 규칙

공통 shell은 같고, **전체 구조를 보여주는 방식**과 **최소 입력**만 shape별로 다르다.
사용자가 저장 전에 결과 형태를 고르지 않는다 — 콘텐츠가 primary artifact를 정한다.

## 공통 shell (5개 shape 전부 동일)

| 요소 | 규칙 |
| --- | --- |
| header | 원문 한 줄 · 제목 · 결과 요약 한 줄(개수 + 결과형태 + 범위) |
| 결과 요약 | `N개 <결과형태>` 문자열은 preview → receipt → 목록 → workspace에서 동일 |
| 완료·다시 열기 | 행 왼쪽 사각 토글, 같은 자리에서 되돌리기 |
| Item detail | 제목 → 날짜 → 메모 → 완료 기준 → 완료 (순서 고정) |
| 가져가기 | 범위 → 형식 → receipt |
| 관리 | 보관 · 복구 · 영구 삭제 · 새 기준일로 다시 쓰기 |

## Shape별

| Shape | 실제 콘텐츠 | Primary renderer | 최소 입력 | Shape 전용 UI | 제공하지 않을 artifact |
| --- | --- | --- | --- | --- | --- |
| 기준일 역산 | 이사 D-30 준비 (24개, 6섹션) | 날짜 그룹 timeline (D-30 / D-10 / D-3 / D-1 / D-Day / D+1) | 이사일 1개 | 기준일 입력, 항목별 날짜 고정 표시, 날짜 범위 요약 | 진도표(순서 개념 없음) |
| 날짜 없는 체크리스트 | 자동차검사 준비 (10개, 3섹션) | 섹션 체크리스트 | 없음 | `날짜 없음` 표기, 항목 하나만 날짜 지정 | 캘린더를 기본 결과로 제시하지 않음 |
| 반복 series | 아침 5분 홈트 (source item 1개) | 반복 요약 + 다음 8회 목록 | 요일 + 시작일 | series 카드(요일·시간·종료 조건), 이번 회차 카드, 자료 링크 분리 | 체크리스트(회차 개념이 사라짐) |
| 순서·진도 | 중1 수학 목차 진도 (8단원, 하위 개념 4~15개) | 순서 목록 + 현재 위치 | 없음 | 단원별 하위 개념 개수, `현재 단원` 승격, 진도 메모 | 캘린더(날짜를 억지로 묻게 됨) |
| 개인 draft | 제주 여행 준비 (메모에서 5개) | 체크리스트 + 구조 조정 | 없음 | 입력 문장 대비 제안 목록, 추가·삭제·복구·순서 | 원문 기반 표기(원문이 없음) |

## 정보 종류 표기

- **source 값**: 원문에서 온 제목·설명·완료 기준·링크. 회색 메타 + 원문 링크. 개인 편집으로 원문을 덮어쓰지 않는다.
- **personal 값**: `내 메모`, `이 할 일 날짜`, `저장 이름` — 라벨에 소유를 명시한다.
- **execution 값**: 완료·다시 열기·회차 기록. 초록 계열 하나만 사용한다.

## shape가 달라도 같아야 하는 것

1. 저장 동사는 `N개 <결과형태>로 시작` 하나다.
2. 첫 viewport 순서는 결과 → 최소 입력 → 시작이다(최소 입력이 없으면 결과 → 시작).
3. 완료·다시 열기·메모·가져가기의 위치와 라벨은 동일하다.
4. 개수 표기는 항상 effective included rows 기준이다.

## shape가 달라도 되는 것

- 전체 구조를 그리는 방법(날짜 그룹 / 섹션 / 회차 / 순서)
- 최소 입력의 유무와 라벨(`이사일` / 없음 / `시작일` / 없음 / 없음)
- 자료(resource)의 존재 여부

## 하지 않을 것

- 지원하지 않는 결과 형태를 tab으로 노출하기
- 한 shape에 3개 이상의 결과 형태 제시
- 저장 전에 결과 형태 고르게 하기
- 진도형에 날짜를 요구하기, 반복형을 체크리스트로 평탄화하기
