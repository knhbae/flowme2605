P5는 거의 닫혔다.
마지막 잡음은 저장 직후 화면의 제목 반복과 하단 바 확증이다.

이번에도 41장을 픽셀로 직접 확인했습니다. 지난 P5 백로그의 핵심이 화면에서 실제로 해소됐습니다 — 공유 /f/의 중복 시작 버튼이 사라지고 저장 sticky가 단일화됐고(P5-01), 냉장고 빈 시트가 "오늘 먼저 기록" 한 행 + 안내로 바뀌었고(P5-07), 세탁기·저장 확인 날짜가 "7월 6일 (월)"·"7월 17일 (금) (D-13)"으로(P5-05), "…일정 지도"·"Mathbang"이 사라졌고(P5-06), /flows 카드가 full-width 파란 버튼에서 "열어보기 ›" 경량 링크로(P5-04) 바뀌었습니다. 그래서 5개는 깨끗이 close. 남은 둘: ① P5-02(겹침)은 캘린더·냉장고·세탁기·내 Flow 하단에선 확인됐지만 /f 저장형·/flow-maps 상세 최하단 evidence가 없고, ② P5-03(라벨 반복)은 "밀린/먼저 할 일" 라벨은 1회로 줄었지만 저장 직후 화면에서 첫 할 일 '제목'이 히어로+섹션+카드로 2~3중 쌓입니다. Blocking은 없습니다.

이번 검토 근거

Vercel 실행 화면은 보지 않았습니다. GitHub의 P5 review package(audit.md·route-evidence.json)와 screenshots 41장을 레포에서 픽셀로 직접 확인했습니다. audit의 자동 스캔은 P5-01~07 전부 "유지 확인 · hit 0"으로 보고하지만, 지난 P4 라운드처럼 최종 판단은 스크린샷의 사용자 이해도·시선 흐름·행동 명확성 기준입니다. "hit 0" 스캔이 못 잡는 제목 반복·화면 밀도·문구 불일치를 눈으로 다시 봤고, 아래 판정은 전부 실제 화면 근거입니다.

SECTION 1

P5-01 ~ P5-07 — Close / Reopen / Follow-up

지난 라운드 P5 백로그 정의 기준. 5개 clean close · 1개 close+follow-up · 1개 partial(재오픈).

P5-01

공유 /f/ 입력·저장 CTA hierarchy

CLOSE ✓

확인 · 지난 라운드의 중복 "검사일 입력으로 시작" 버튼이 사라짐. 입력은 카드 안 [검사일]+[입력], 저장은 하단 단일 sticky "내 Flow에 저장" 하나로 정리(s04-01). 저장 후 헤더·sticky가 동시에 "내 Flow에서 보기"로 전환(s04-03). 대안 선택지는 "▶ 다른 방법" 디스클로저로 접힘. 주행동이 명확해짐.

P5-02

sticky bottom clearance (겹침)

CLOSE + FOLLOW-UP

확인된 화면 · 캘린더 월 그리드 마지막 행(s02-06), 냉장고 하단 면책 카드(s05-03), 세탁기 하단 출처 카드(s05-05), 내 Flow 저장 목록 마지막 카드(s06-03) 모두 sticky/4탭 위로 완전히 노출. 지난 라운드 High였던 "가려서 못 누름"이 이 화면들에선 해소.

미확인(재검증 필요) · ① /f 저장형(vehicle): s04-01 하단에 "내 Flow에 저장" sticky 아래로 다음 섹션 텍스트가 반쯤 보임 — 최하단 스크롤 evidence 없음. ② /flow-maps 상세: "저장하고 시작" sticky + 4탭 바가 이중으로 쌓임(03-flow-map-moving) — 최하단 evidence 없음. → P6-02·§9.

P5-03

My Flow 상태 라벨 반복 제거

PARTIAL · REOPEN → P6-01

절반 성공 · "밀린 할 일 / 먼저 할 일" 라벨 자체의 3중 반복은 사라짐 — 이제 섹션 eyebrow 1회. 저장 목록(전체 탭)은 행당 "다음 할 일 · [제목]" 한 줄로 깔끔(s06-02).

남은 문제(형태만 바뀜) · 저장 직후·오늘 탭에서 첫 할 일 '제목'이 세로로 2~3번 쌓임: ①"저장됨" 히어로 카드 제목 + ②"밀린/먼저 할 일" 섹션 제목 + ③그 섹션의 카드 제목이 모두 "이사 방식과 견적 후보 정하기"(s02-03)·"1. 소인수분해"(s03-02·s06-01). 확장 상세에선 "확인할 항목 · [제목]"으로 한 번 더(s02-04). 라벨은 줄었지만 제목이 그 자리를 채움.

P5-04

/flows 카드 CTA 경량화

CLOSE ✓

확인 · 카드마다 있던 full-width 파란 "저장 전 보기" 버튼이 우측 "열어보기 ›" 경량 텍스트 링크로 바뀜(02-flows). 결과 약속·"먼저 할 일" 칩은 유지되고 버튼 무게가 빠져 첫 뷰포트 카드 수가 늘어남.

파생 P6(작음) · 정작 홈 추천 카드와 /flow-maps eyebrow는 여전히 "저장 전 보기"(01-home·03-flow-map-moving) — 같은 행동에 두 문구가 공존. → P6-04.

P5-05

날짜 입력 선택지 · 사용자용 날짜 포맷

CLOSE ✓

확인 · 저장 전 대안은 "▶ 다른 방법" 디스클로저로 접혀 주 입력 1개만 노출(s04-01). 저장 확인은 "검사일: 7월 17일 (금) (D-13)"(s04-02), 세탁기 반복 관리일은 "7월 6일 (월)·8월 6일 (목)…"(s05-04)로 친화적 한글 포맷. 사용자 노출 텍스트에 raw ISO 없음 — 남은 "2026-07-17"은 브라우저 네이티브 <input type="date">의 값 표시라 예외로 인정.

P5-06

내부어 표시 제거 (일정 지도·Mathbang·저장한 지도)

CLOSE ✓

확인 · Flow Map 제목이 "원룸 이사 D-30 일정 지도" → "원룸 이사 D-30 일정"(03-flow-map-moving). 수학 저장 후 부제가 "중1 수학 목차 진도표 · 중1 목차"로 "Mathbang" slug 사라짐(s03-02). "저장한 지도" 표현도 안 보임 — 이제 "저장한 콘텐츠 / 저장한 일정".

감시(Low) · "원문과 실행 항목" 헤더의 출처 브랜드명 "AJD 이사 준비 체크리스트"(03-flow-map-moving)는 출처 인용 문맥이라 정당하나, slug가 제목·부제로 새지 않는지 스캔 유지. → P6-08.

P5-07

냉장고 workbench 빈 placeholder 정리

CLOSE ✓

확인 · 빈 시트가 placeholder 행 반복 대신 "먼저 채울 행" 안내 카드 + "오늘 먼저 기록" 활성 행 1개(우선 재료/메뉴 후보/장보기 보류/상태에 "예: …" 힌트)로 정리(s05-02). "나머지 날짜는 필요할 때만 펼칩니다" 문구로 나머지는 접힘. 미기입 폼이 아니라 지금 채우는 실행 시트로 읽힘.

종합 판정

P5-01 · P5-04 · P5-05 · P5-06 · P5-07 = clean close(5). P5-02 = close + follow-up(2개 화면 하단 evidence 부재). P5-03 = partial → 재오픈(P6-01): 라벨은 줄었지만 저장 직후 제목이 2~3중으로 그 자리를 채움. 흐름을 막는 Blocking·되돌린 회귀는 없음. 이번 루프의 실질 진전은 큽니다 — 남은 건 밀도·확증 마감입니다.

SECTION 2

Route별 UX/UI 문제

근거는 스크린샷 파일명. 배지는 이번 픽셀 판정.

/

홈

양호

headline + 단일 primary "콘텐츠 고르러 가기" + 추천 카드 1장으로 가벼움(01-home). 사소 1 · CTA 아래 텍스트 링크 "저장한 콘텐츠 보기 · 캘린더 보기"가 하단 4탭(내 Flow·캘린더)과 기능 중복. 사소 2 · 추천 카드 CTA가 "저장 전 보기" — /flows의 "열어보기 ›"와 문구 불일치. → P6-04·P6-06.

/flows

Flow 찾기

개선됨

"무엇을 저장할까요?" 헤더 + 검색 + 카테고리 칩 + 카드(결과 약속·먼저 할 일 칩·"열어보기 ›")(02-flows). 지난 라운드 full-width 버튼 밀도 문제 해소. 카드 스캔이 빨라짐. 신규 route 문제 없음 — CTA 문구 통일만 남음(P6-04).

/flow-maps/[map]

Flow Map 상세 (저장 전)

이중 하단 바

제목 "지도" 접미 해소 ✓, 결과 약속·칩·"먼저 할 일" 좋음(03-flow-map-moving). 문제 · "저장하고 시작" 액션 sticky가 4탭 바 위에 겹쳐 하단 고정 UI가 2단으로 뷰포트 ~140px 점유, 그 사이로 다음 카드가 반쯤 보임. 최하단 clearance evidence 없음. → P6-02·P6-03. 사소 · eyebrow "저장 전 보기" 문구(P6-04).

/f/[slug]

공개 상세 · 저장형 (공유 shell)

CTA 단일화 ✓ 하단 확증

단일 저장 sticky·"다른 방법" 접기·저장 후 전환 성립(s04-01~03). 저장 후 /my 이어짐도 확인(s04-04). 남은 것 · s04-01 하단에 sticky 아래 다음 섹션이 반쯤 보임 — 최하단 스크롤 evidence로 clearance 확증 필요(P6-02).

/f/[slug]

공개 상세 · workbench (냉장고·세탁기·신차·중고차)

톤 통일 ✓

warm 톤·카드·칩·배지·결과 sticky("캘린더 파일 받기")가 전부 동일해 하나의 앱으로 읽힘(s05-01·s05-06·s05-07·09-washer). 빈 시트도 활성 1행 정리 ✓(P5-07). 사소 · 본문 인라인 "시작일 입력으로 시작" 버튼(s05-01)이 상단 입력 카드와 같은 행동을 2번 노출 — /f 저장형은 이미 단일화됐으니 워크벤치도 정리(P6-07).

/my (오늘 · 저장 직후)

내 Flow — 오늘 / 저장 직후

제목 2~3중

"저장됨" 히어로 + [오늘/전체] + "밀린/먼저 할 일" 섹션 + "지금 이어하기" + "다음 항목"으로 실행형 골격은 있음(s02-03·s03-02·s04-04). 문제 · 첫 할 일 제목이 히어로+섹션 제목+카드 제목으로 2~3번 세로로 쌓이고, 확장하면 "확인할 항목 · [제목]"으로 한 번 더(s02-04). 정보가 아니라 잡음. → P6-01. (구조가 아니라 표시 위계 문제.)

/my (전체)

내 Flow — 저장 목록 (전체)

양호

"2개 저장 · 13개 남음 / 다음 1 · 밀림 1" 요약 + 카드당 "0/5 완료 + 진행바 + 다음 할 일 · [제목]" 한 줄(s06-02·s06-03). 여기엔 제목 반복 없음 — 오늘 탭이 참고해야 할 정답 패턴. 하단도 4탭 위로 노출. 유지.

/calendar

캘린더

agenda-first ✓

선택일 "7월 8일 (수)" agenda(저장한 일정 + 할 일 카드)가 월 그리드 위에 먼저(s02-05) — "언제 무엇을" 이해가 먼저. 빈 상태도 "일정이 생길 콘텐츠를 먼저 고르세요"로 명확(13-calendar-empty). 하단 그리드 마지막 행이 4탭 위로 노출(s02-06). 문제 없음.

SECTION 3

Scenario별 UX/UI 문제

s01 처음 온 사용자 — 통과

홈("콘텐츠 고르러 가기") → Flow 찾기("무엇을 저장할까요?") → 첫 카드까지 정보량 낮고 첫 행동 하나 분명. 3~5초 내 목적 이해 가능. 잔여는 "저장 전 보기/열어보기" 문구 통일(P6-04)뿐.

s02 이사 저장 → My Flow → 캘린더

저장하고 시작 → "저장됨" 히어로 → 첫 항목 → 캘린더 agenda 전부 동작 ✓. 걸림돌 = 저장 직후 "이사 방식과 견적 후보 정하기" 제목이 히어로+섹션+카드로 3중(P6-01).

s03 날짜 없는 콘텐츠(중1 수학) — 대체로 통과

저장 후 "날짜 없음" 배지 + fallback 첫 항목 "1. 소인수분해" + 열면 8개 개념 체크리스트(s03-03) ✓. "Mathbang" 사라짐 ✓. 걸림돌 = "1. 소인수분해" 제목 3중(P6-01).

s04 공유 /f 저장 전/후 — 대체로 통과

단일 저장 CTA·"다른 방법" 접기·친화 날짜·저장 후 /my 이어짐 매끄러움 ✓. 걸림돌 = 최하단 clearance 미확증(P6-02). 공유는 앱 밖 첫 인상이라 확증 가치 큼.

s05 특수 workbench/export — 통과

냉장고 활성 1행 ✓, 세탁기 친화 날짜 ✓, 신차·중고차 톤 통일 ✓, 결과 sticky 예측 가능. 하단도 노출. 잔여 = 인라인 "…으로 시작" 중복(P6-07, 작음).

s06 여러 Flow 저장 상태 — 혼합

전체 탭 목록은 카드당 1줄로 깔끔(s06-02/03). 반면 저장 직후(오늘) 화면은 제목 반복(s06-01). 같은 데이터, 두 표시 위계 — 오늘 탭을 전체 탭 패턴으로 맞추면 해결(P6-01).

SECTION 4

Blocking / High / Medium / Low

Blocking — 없음

찾기→저장→실행→캘린더/공유→앱 전환을 끊는 문제는 픽셀에서 관측되지 않음. 빈 상태·전환·agenda-first 모두 성립. 아래는 흐름을 막지 않으나 신뢰·완성도·밀도를 깎는 항목.

High

HI-1저장 직후·오늘 탭에서 첫 할 일 '제목' 2~3중 노출 (P5-03 재오픈)

"저장됨" 히어로 카드 · "밀린/먼저 할 일" 섹션 제목 · 그 섹션의 카드 제목이 모두 같은 첫 항목 제목(s02-03·s03-02·s06-01·s04-04). 확장하면 "확인할 항목 · [제목]"으로 한 번 더(s02-04). 저장 직후는 "지금 할 일이 먼저 보이는가"가 걸린 가장 중요한 화면인데 같은 문장이 세로로 쌓여 신뢰를 깎음. 명명된 P5 목표가 형태만 바뀐 회귀라 High. → P6-01.

HI-2/f 저장형 · /flow-maps 상세 하단 clearance 미확증 + 이중 고정 바

지난 라운드 최상위 High(가림)의 잔여. 캘린더·냉장고·세탁기·내 Flow는 해소 확인했지만, s04-01은 저장 sticky 아래로 다음 섹션이 반쯤 보이고 03-flow-map-moving은 "저장하고 시작" sticky + 4탭이 이중. 두 화면의 최하단 evidence가 없어 "가려서 못 누름"이 남았는지 단정 불가 — padding 보정 + 재캡처로 닫아야 함. → P6-02·§9.

audit.md 확인 질문 — 답

Q1. P5-01~P5-07을 닫힌 기준선으로 봐도 되는가?

5개는 예(P5-01·04·05·06·07). P5-02는 close+follow-up — 4개 화면은 확인, /f 저장형·/flow-maps 최하단만 확증 필요. P5-03은 아직 아니오 — 라벨은 줄었으나 제목이 2~3중으로 자리를 채워 재오픈(P6-01).

Q2. 저장 후 My Flow·Calendar가 충분히 실행형 앱처럼 보이는가?

캘린더는 예(agenda-first, 선택일 할 일 먼저). My Flow는 구조는 예, 표시는 거의 — 히어로→항목→체크리스트 골격·전체 탭 목록은 실행형인데, 저장 직후 오늘 탭의 제목 반복(P6-01)만 정리하면 완성.

Q3. 공유 /f/ shell은 계속 공유 진입 예외로 유지해도 되는가?

예, 유지. 4탭 없는 단일 저장 화면 + 저장 후 /my 전환은 공유 링크 첫 인상으로 적절하고 저장형·workbench 모두 성립. 4탭 강제 편입은 하지 말 것.

Q4. 특수 workbench들이 하나의 FlowMe 앱 톤으로 보이는가?

예. 냉장고·세탁기·신차·중고차가 같은 warm 톤·카드·칩·배지·결과 sticky를 공유해 이질감 없음. 빈 시트도 활성 1행으로 실행 시트처럼 보임. 잔여는 인라인 CTA 중복(P6-07, 작음).

Q5. 다음 루프는 어디부터?

P6-01(제목 반복 · 전체 탭 패턴 이식) → P6-02(하단 패딩+재캡처) → P6-03(이중 바) → P6-04(문구 통일). 앞 둘이 신뢰·안전을 좌우하니 최우선, 뒤는 밀도·일관성 마감입니다. Blocking·회귀가 없어 P6는 순수 정리 루프로 진행 가능합니다.
