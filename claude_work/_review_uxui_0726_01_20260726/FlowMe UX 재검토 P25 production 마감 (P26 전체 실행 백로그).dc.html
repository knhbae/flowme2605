P25의 기록은 과장이 아니었다 — 구조(전체 Flow 작업공간·실행/배치 분리·가역 완료·scope-first export)는 production에서 실제로 서 있다.
그러나 직접 들여다본 production은 첫 만남에서 스스로를 배신한다: 예시 미리보기가 과거 날짜를 "다가오는 할 일"로 보여주고, 저장 결정 표면이 하나가 아니라 셋이며, 내 Flow와 캘린더의 빈 화면이 같은 문장으로 말한다.

P26은 새 구조가 아니라 이해도·정합·완성도 프로그램입니다. Blocking 0 · High 3 · Medium 8 · Low 2. 백로그는 P26-01(날짜 정합)부터 P26-14(final review)까지 6단계로 구성했고, 각 항목의 /goal 프롬프트가 준비되어 있습니다.

SECTION 2

10개 우려 판정

1 · 날짜 없는 할 일의 이유 부분 해결

실행처(내 Flow)·배치처(캘린더) 분리와 용어(날짜 없는 할 일 / 날짜 정하기)는 정착. "왜 날짜 없이 두는가"의 개념 온보딩은 없음 → P26-05

2 · 조정이 필드 나열인가 구조 해결 · 길이 잔존

제목/날짜/메모 우선 + 세부 일정 접힘은 구현됨(repo_evidence). 경로 길이는 P25 스스로 Medium 인정 → intent-first는 P26-06

3 · 저장 직후 확신 자동화로 지지

첫 저장 = 전체 Flow 확인, 저장 Flow 자동 선택(repo_evidence). 단 F-01이 저장 전 신뢰를 깎고, 저장 결과 1줄 명세(날짜 n·날짜없음 m)는 없음

4 · 전체 Flow 가독성 부분

outline/detail·wide rail 성립. 1024 캘린더 3영역 밀도(F-07)와 다중 Flow 스캔은 잔존 → P26-08

5 · 내 Flow vs 캘린더 미해결

두 빈 상태가 같은 문장·같은 CTA(F-03). 역할이 설명 없이 이해되지 않음 → P26-05

6 · 완료~순서변경 연쇄 자동화로 지지

기능 존재는 P25-03B/05A로 증명. 발견성은 정적 검토로 확인 불가 — 사용자 확인 가정(F-11) → P26-07

7 · export 예측 해결

scope(Flow 전체/직접 선택/현재 항목)+count 선표시, undated는 list 포함/ICS 제외. 사후 확인 surface만 없음 → P26-10

8 · 설명문 과다 부분

설명 접힘은 됐다. 본질은 카피가 아니라 CTA·표면 중복(F-02) — 구조로 풀어야 함 → P26-04

9 · 모바일 복잡 / wide 늘어짐 부분

앱 4탭의 wide 구성은 개선됨. public /f wide는 여전히 늘어진 단일 컬럼(F-06), 캘린더 밀도(F-07) → P26-08·12

10 · 상용 대비 완성도 미달

raw yyyy-mm-dd+입력 버튼(F-09), 과거 날짜 예시(F-01), 빈 상태의 데이터 관리 승격(F-13), 로그체 카피(F-14) → P26-11

6개 persona journey scorecard

단계별 supported/hidden/partial/missing/blocked 전체는 journey-scorecard.json. blocked는 0 — 막힌 여정은 없고, 여정마다 이해도 층의 partial이 남는다.

A · 이사 준비(역산형) partial

저장→전체 확인→이사일 변경→날짜 고정→완료→export→재사용 전부 supported(repo_evidence). 단 진입 route 자체가 missing(F-10) — 검증부터 필요.

B · 날짜 없는 차량 점검 partial

undated 실행·배치·해제·checklist/ICS parity 모두 supported. "왜 날짜 없이 두는가"는 hidden, 저장 전 예측은 F-01로 partial.

C · 월간 반복 루틴 partial

canonical projection·회차 완료 1컨트롤·ICS parity supported. 다음 회차 기본 날짜가 F-04로 partial(재현 필요).

D · 개인 메모 draft partial

분할 검토(필러 0)·저장·날짜/시간/반복 supported. 추가/삭제/복구/순서 변경은 존재하지만 발견성 미확인(F-11) — partial.

E · 다중 Flow 반복 사용자 partial

지금/내 Flow/완료·rail·선택 export supported. 같은 날 다중 Flow 캘린더 스캔(F-07)·수정 경로 길이(F-08) partial.

F · public 첫 방문자 partial−

artifact 1개·저장 전 완료 0은 성립. 예측은 F-01·F-02로 partial, 저장 후 탭 역할은 F-03으로 hidden. 여섯 여정 중 가장 약함.

SECTION 6

외부 UX 참고 — 패턴만 대조, 복제 없음

아래는 각 도구군의 오래 안정된 공개 패턴을 heuristic 기준선으로 쓴 것이다(이번 턴에 각 제품 화면을 재캡처하지는 않음). FlowMe에 그대로 이식하라는 뜻이 아니라, 사용자가 이미 학습한 기대치가 무엇인지의 대조군이다.

undated/inbox 처리 — Things·Todoist·Microsoft To Do

날짜 없는 일은 이름 있는 집(Inbox/Anytime/Someday)을 갖고, 그 집의 존재 이유가 UI 위치만으로 학습된다. FlowMe의 '날짜 없는 할 일' 섹션은 집은 있으나 이유 문장이 없다 → P26-05.

저장/import 직후 — TickTick·Notion·Wanderlog·TripIt

import 계열은 "무엇이 몇 개 생겼고 어디 있는지" 결과 명세를 즉시 보여준다. FlowMe는 전체 Flow는 보여주나 수량·목적지 1줄 명세가 없다 → 저장 배너·P26-10.

빠른 수정 vs 고급 수정 — Fantastical·Google Calendar·Sunsama

탭 1번 = 가벼운 시트(제목·날짜), "옵션 더 보기"가 전체 편집으로. FlowMe P25 구조와 같은 방향 — 남은 건 intent-first 압축(P26-06).

날짜 입력 — Todoist·Fantastical·Apple Reminders

피커+프리셋(오늘/내일/주말)+자연어. raw yyyy-mm-dd+확정 버튼 2단계는 이 군에서 존재하지 않는 패턴 → P26-11.

batch scheduling — Sunsama·Structured·TickTick

선택 → 날짜 끌어놓기/일괄 이동 + 영향 미리보기. FlowMe의 임시 선택 모드는 동급 — keep. 발견성만 점검.

완료와 reopen — Things·Todoist·Microsoft To Do

체크 즉시 undo + 완료 목록(Logbook)에서 재개방. FlowMe P25-05A는 이 기대치에 정확히 부합 — keep.

반복 회차 — Google Calendar·Fitbod·Nike Training Club

"이번/다음 회차"를 항상 미래형 날짜+요일로 말하고 지난 회차는 기록으로 분리. FlowMe의 "이번 관리일 7/19(어제)"는 이 문법을 깬다 → P26-01·09.

project/timeline 전체 보기 + wide — Notion Calendar·Wanderlog·Strava

wide는 컬럼을 늘리는 게 아니라 pane 역할을 나눈다(리스트|상세, 일정|지도). public /f wide 단일 컬럼과 캘린더 상시 3영역이 대조점 → P26-08·12.
