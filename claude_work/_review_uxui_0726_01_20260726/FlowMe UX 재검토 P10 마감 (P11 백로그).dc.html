P10-03

My Flow 이어하기 — 실행 가능한 첫 행 중심

조건부 — 픽셀 OK, 증거 marker 없음

픽셀은 닫힘 · s13/s15/s16 모두 이어하기 카드에 실제 첫 할 일(제목+메타+"열기" 컨트롤)이 있습니다 — 설명-only 카드 아님. 그러나 ① route-evidence.json에 actionable 여부를 재는 marker가 없습니다(my-flow-now-section 존재 boolean과 제목 반복 카운트뿐 — "열기" 컨트롤의 존재·focusable을 아무도 안 셉니다). ② 바로 아래 "오늘 상태" 카드가 새 설명-only 카피를 다시 들여왔습니다: "저장한 콘텐츠의 첫 할 일을 위 카드에서 엽니다"(s13·s15), "위 카드에서 오늘 할 일을 바로 엽니다. 전체 목록은 전체 탭에서 봅니다"(s16). UI 사용법을 서술하는 meta 카피는 P10-03이 지우려던 바로 그 부류입니다 → P11-02·03.

P10-04

Calendar agenda 그룹 헤더 밀도

P10-05

짧은 visible 라벨 + aria 맥락 보존

반쪽 — visible은 확인, aria는 package로 검증 불가

visible 절반은 픽셀로 닫힘 · 행 컨트롤이 전부 짧습니다: "열기"(s13·15·16·17·20), "수정"(s21), "완료/편집"(s22·24), "Flow 보기"(s20). aria 절반은 이 package로 검증할 수 없습니다 — route-evidence.json은 aria-label을 input의 라벨 추출에만 쓰고, 행 컨트롤의 accessible name을 어디에도 기록하지 않습니다. "열기"가 스크린리더에 "열기, 열기, 열기, 열기"로 들리는지 "이사 방식 정하기 열기"로 들리는지 증거상 알 수 없음. 코드에 있더라도 주장≠증거 → P11-02.

P10-06닫힘 ✓

GitHub 링크 base · README의 4개 링크(E2E 2종·flow-mvp·capture 스크립트)를 실제 repo 경로로 전부 열어 확인 — /flow-mvp 중복 세그먼트 없음, githubBase = repo root + branch로 생성. capture 스크립트도 링크된 경로(scripts/content-audit/…p7….mjs)에 실재.

P10-07닫힘 ✓ (잔여 2)

raw ISO 3분리 · lib의 scanRawIsoInputValues가 type=date+정확히 ^ISO$인 값만 면제로 분류(그 외 input 값은 hit 유지) — 보수적으로 올바른 설계. 증거: visible 0 · input hit 0 · 면제 normal 2(flow-map 이사일)+restart 4, 전부 route·label·reason 기록. 잔여: 면제 6건 전부 testId: ""(이사일 input에 testid 없음), 그리고 캡처 브라우저가 locale 미설정이라 s21의 date input이 한국 기기와 달리 ISO로 렌더됨 → P11-06.

요약 — P10의 인프라 항목(01·06·07)과 접근성 항목(02)은 요구한 방식 그대로 닫혔습니다. 남은 건 두 종류: ① 밀도 규칙의 확산 — P10-04의 원칙을 캘린더에만 적용하고 내 Flow 시트(s17)와 인벤토리(s20)에는 안 했습니다. ② 주장의 측정화 — 03·04·05는 "픽셀로 보이니 닫힘"인데, 이 프로젝트가 P9→P10에서 배운 교훈이 바로 "증거 없는 닫힘은 다시 열린다"입니다.

P11-01 · High
