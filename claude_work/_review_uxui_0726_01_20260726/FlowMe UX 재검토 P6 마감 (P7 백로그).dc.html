SECTION 1

P6-01 ~ P6-08 — Close / Reopen / Follow-up

지난 라운드에서 정의한 P6 백로그 기준. 8개 전부 close — 그중 2개는 감시 스캔을 계속 켜두는 조건부 close.

P6-01

My Flow 첫 할 일 제목/상태 라벨 반복 제거

CLOSE ✓ (P5-03 재오픈 해소)

해소 확인 · 저장 직후·오늘 탭이 전체 탭 카드 패턴으로 통일됐습니다. 섹션 헤더가 이제 "밀린 할 일 · 1개 밀림"(라벨+개수)이고 그 아래 카드에 제목 "이사 방식과 견적 후보 정하기"가 딱 1회만 나옵니다(s02-03). 날짜 없는 콘텐츠도 "먼저 할 일 · 1개 대기" + [날짜 없음] 배지 + "1. 소인수분해" 1회(s03-02·s06-01). 확장 상세도 카드 상단 제목 1회 후 본문은 "필요한 항목만 체크…" 안내로 이어져 제목 재노출 없음(s02-04). 히어로 배너는 첫 할 일 제목이 아니라 콘텐츠명("원룸 이사 D-30 일정")만 칩으로 노출. P5가 지목한 2~3중 세로 반복이 픽셀에서 사라졌습니다.

P6-02

/f · /flow-maps 하단 sticky clearance

CLOSE ✓ (evidence 확보)

확증됨 · P5에서 "최하단 evidence 없음"으로 남았던 두 화면을 위해 s07 최하단 5장이 새로 추가됐고, 픽셀에서 clearance가 확인됩니다. /f 저장형: 단일 저장 sticky 위로 마지막 면책 카드가 여백까지 두고 완전 노출(s07-01). /flow-maps 상세: 마지막 카드 "정산과 전입신고 확인"이 "저장하고 시작" sticky + 4탭 2단 바 위로 완전히 노출(s07-03). 수학 flow-map·캘린더 최하단도 동일(s07-04·s07-05). 지난 라운드 최상위 High(가려서 못 누름)의 잔여가 닫혔습니다.

P6-03

/flow-maps 저장 CTA + 4탭 하단 조작 영역 통합감

CLOSE ✓ (의도된 패턴)

수용 · "이사일 입력됨 · 저장하고 시작" 액션 sticky가 4탭 바 바로 위에 시각적 구분선을 두고 앉아, 두 줄이지만 정렬·간격이 하나의 하단 조작 영역으로 읽힙니다(s07-03·03-flow-map-moving). 이는 SERVICE_STRUCTURE.md가 명시한 기준선 — "Flow Map sticky save sits above the tabs with visible separation" — 그대로라 결함이 아니라 문서화된 의도입니다. clearance도 P6-02로 확증. 남은 것 · 2단이 ~130px를 점유하므로, 더 짧은 뷰포트(360px·짧은 높이)에서 오탭·콘텐츠 가림이 없는지는 실사용 테스트로만 확정 가능 → P7-02 감시 항목(코드 수정 아님).

P6-04

`열어보기` CTA 문구 통일

CLOSE ✓

확인 · P5에서 "저장 전 보기"(홈·flow-map)와 "열어보기 ›"(/flows)로 갈렸던 진입 CTA가 세 곳 모두 "열어보기"로 통일됐습니다. 홈 추천 카드 = "열어보기"(01-home), /flow-maps eyebrow = "열어보기"(03-flow-map-moving), /flows 카드 = "열어보기 ›"(02-flows). 같은 "저장 전 미리보기" 행동에 두 문구가 공존하던 불일치가 사라졌습니다.

P6-05

`확인할 항목`/`확인 항목` 중복 라벨 정리

CLOSE ✓

확인 · 할 일 확장 상세에서 근접 중복이던 두 라벨이 "확인 항목" 하나로 정리됐습니다(s02-04). P5에서 지적한 "확인할 항목 · [제목]" 상세 헤더(제목 재노출 포함)가 사라지고, 대신 "필요한 항목만 체크하고 완료로 표시하세요." 안내 + 체크리스트 헤더 "확인 항목 · 0/3"만 남았습니다. P6-01의 제목 정리와 함께 처리됐습니다.

P6-06

홈 보조 링크 중복 완화

CLOSE ✓

확인 · P5에서 4탭(내 Flow·캘린더)과 기능 중복이던 홈 primary 아래 "저장한 콘텐츠 보기 · 캘린더 보기" 텍스트 링크가 제거됐습니다. 이제 홈 첫 뷰포트는 단일 primary "콘텐츠 고르러 가기" + 추천 카드 1장("열어보기")뿐이라 주행동 하나가 분명합니다(01-home). SERVICE_STRUCTURE의 "홈은 두 번째 카탈로그가 되면 안 된다" 원칙에 부합.

P6-07

workbench 중복 시작 CTA 제거

CLOSE ✓

확인 · P5에서 상단 입력과 같은 행동을 2번 노출하던 본문 인라인 "…으로 시작" 버튼이 사라졌습니다. 냉장고 워크벤치는 이제 단일 구조화 카드 — "시작일만 넣으면 저장됩니다: 시트" 안에 [입력 · 시작일 입력] / [저장 결과 · 시트] / [먼저 할 일]로 정리(s05-01). 신차·중고차·세탁기도 동일 톤(s05-06·s05-07·s05-04). 주행동이 입력 카드 1개로 단일화됐습니다.

P6-08

source brand/slug 표시 정리 (AJD · Mathbang)

CLOSE ✓ (스캔 유지)

확인 · "AJD"·"Mathbang" prefix 스캔 0건, 픽셀에서도 브랜드 slug가 제목·부제로 새지 않음. 출처는 "원문과 근거"/"by 제작자" 인용부에만 등장 — 예: "by 차근차근 모빌리티", "원문과 근거 · TS한국교통안전공단 자동차검사 절차 안내 · main.kotsa.or.kr"(s07-01). 이는 정당한 출처 표기입니다. 조건 · 새 seed가 들어올 때 slug가 제목·부제로 누출되지 않도록 브랜드 slug 금지 스캔은 상시 유지(P7-06 guardrail).

종합 판정

P6-01 ~ P6-08 = 전부 close(8/8). 그중 P6-03·P6-08은 감시 조건부 close(2단 바 실사용 관찰 + 브랜드 slug 스캔 유지). 정상 사용자 라우트 기준 Blocking·High·Medium = 0, 되돌린 회귀 = 0. 이번 루프는 P5에서 남긴 두 High(제목 반복·하단 확증)를 정확히 겨냥해 둘 다 닫은 성공적 정리 루프입니다. 유일한 잔여는 4탭 IA 밖 /restart 프로토타입의 raw ISO 16건 — 다음은 close가 아니라 P7 게이트 설계입니다.

양호

하단 확증 ✓

/my (오늘 · 저장 직후)

제목 반복 해소 ✓

내 Flow 전체 · 캘린더

/restart/moving-d30

이사 restart (프로토타입 · 4탭 IA 밖)

raw ISO 16건 · P7 게이트

할 일 행마다 "D-30 · 2026-05-28" raw ISO 날짜가 렌더 텍스트로 노출(s05-08·09·10, 총 16건). 네이티브 input이 아니라 실제 표시 텍스트라 친화 날짜 기준선(P5-05) 위반. 단, SERVICE_STRUCTURE가 /restart를 "Do Not Expose As Primary Nav Yet"로 명시 — 4탭 밖, 정상 discovery에서 도달 불가. 정상 라우트 ISO=0. 따라서 P6 blocker 아님 → P7 게이트(승격 전 정리). 부차 · 하단 export sticky가 본문 "내 도구로 가져가기"와 3버튼 중복(s05-10) — 같이 정리.

SECTION 3

Scenario별 UX/UI 상태 (s01–s07)

s01 첫 진입 · Flow 찾기 스캔 — 통과

홈("콘텐츠 고르러 가기") → Flow 찾기("무엇을 저장할까요?") → 첫 카드까지 정보량 낮고 첫 행동 하나 분명. CTA 문구도 "열어보기"로 통일돼 스캔 마찰 없음.

s02 이사 저장 → My Flow → 캘린더 — 통과

저장하고 시작 → "저장됨"(콘텐츠명) 히어로 → "밀린 할 일 · 1개 밀림" + 카드 제목 1회 → 캘린더 agenda-first 전부 동작. P5 걸림돌(제목 3중) 해소(s02-03·05).

s03 날짜 없는 콘텐츠(중1 수학) — 통과

저장 후 "먼저 할 일 · 1개 대기" + [날짜 없음] 배지 + "1. 소인수분해" 1회, 열면 8개 개념 체크(s03-02·03). fallback 첫 항목·제목 1회 모두 성립. "Mathbang" 없음.

s04 공유 /f 저장 전/후 — 통과

단일 저장 CTA·"다른 방법" 접기·친화 날짜·저장 후 "내 Flow에서 보기" 전환·/my 이어짐 매끄러움(s04-01~04). P5 걸림돌(최하단 미확증)이 s07-01로 닫힘.

s05 특수 workbench + restart — 혼합

냉장고·세탁기·신차·중고차 톤 통일 + 중복 시작 CTA 제거 ✓(s05-01·04·06·07). 반면 restart는 raw ISO "2026-05-28" 노출(s05-08~10) — 프로토타입이라 P7 게이트로 분리.

s06 여러 Flow 저장 반복 사용 — 통과

저장 직후(오늘)와 전체 탭 목록 둘 다 제목 1회로 일관(s06-01/02). P5의 "같은 데이터 두 표시 위계" 불일치 해소. 하단도 4탭 위 노출(s06-03).

s07 하단 sticky/fixed layer 최하단 — 통과 (이번 라운드 핵심 신규 evidence)

P5 evidence 공백을 정확히 메운 5장. /f 저장형 단일 sticky(s07-01)·공유 이사(s07-02)·/flow-maps 2단 바(s07-03)·수학 flow-map(s07-04)·캘린더(s07-05) 모두 최하단 마지막 카드/버튼이 고정 UI 위로 완전 노출. "가려서 못 누름"이 픽셀에서 부재. 지난 라운드 최상위 High를 닫은 결정적 evidence.

SECTION 4

Blocking / High / Medium / Low

SECTION 8

audit.md 확인 질문 — 답

Q1. P6-01~P6-08을 닫힌 기준선으로 봐도 되는가?

예 — 8개 전부 close. 그중 P6-03(2단 바)·P6-08(브랜드 slug)은 감시 조건부: 전자는 실사용 관찰로 영구 확정, 후자는 새 seed 대비 스캔 상시 유지. 정상 라우트 회귀·Blocking·High 없음.

Q2. 저장 후 My Flow·Calendar가 충분히 실행형 앱처럼 보이는가?

예. My Flow는 히어로(콘텐츠명)→라벨+개수 섹션→제목 1회 카드→"지금 이어하기"로 실행형(s02-03·s03-02), 캘린더는 선택일 agenda가 그리드 위에 먼저(s02-05). P5의 제목 반복이 사라져 "지금 할 일"이 바로 읽힙니다. 남은 건 다중 큐 상태 재캡처(P7-02)뿐.

Q3. /flow-maps 하단 CTA와 4탭이 아직 2단 fixed UI처럼 보이는가?

2단인 것은 맞습니다 — 그러나 결함이 아니라 문서화된 의도입니다(SERVICE_STRUCTURE: sticky above tabs, visible separation). 정렬·구분으로 하나의 조작 영역처럼 읽히고 clearance도 확증(s07-03). 코드 수정 없이 close, 단 짧은 뷰포트 실사용 관찰만 P7 감시로 남깁니다.

Q4. 공유 /f/ shell은 계속 공유 진입 예외로 유지해도 되는가?

예, 유지. 4탭 없는 단일 저장 화면 → 저장 후 "내 Flow에서 보기" 전환이 공유 링크 첫 인상으로 적절하고, 저장형·워크벤치 모두 성립(s04·s05·s07-01). 4탭 강제 편입 금지.

Q5. 다음 루프가 필요하면 P7 backlog를 Blocking/High/Medium/Low로.

Blocking·High = 없음. Medium(게이트) = P7-01 /restart raw ISO + export 중복(승격 전 필수). Low = P7-02 다중 큐 evidence · P7-03 긴 목록 clearance · P7-04 홈 추천 규칙 · P7-05 워크벤치 상단 링크 · P7-06 회귀 스캔 guardrail. 정상 라우트는 출시 가능 수준 — P7은 회귀 방지·확증 루프.
