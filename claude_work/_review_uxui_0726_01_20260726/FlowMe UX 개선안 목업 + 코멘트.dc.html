FlowMe UX 개선안 — 목업 + 코멘트 (핸드오프)
FLOWME · UX 개선안 여러 피드백(사용자 · QA · 코드 리뷰) 종합 → 목업 + 코멘트 · 개발 핸드오프 1장

모든 피드백을 관통하는 한 문장은 "글로 설명하는 게 너무 많다."
상태를 텍스트로 설명하는 대신 화면에서 바로 보이고·바로 조작되게 바꾸는 7개 안 + 그 코멘트입니다.

각 안은 왼쪽에 목업(390px 모바일 기준), 오른쪽에 코멘트로 구성했습니다. 코멘트는 문제 → 제안 → 기대효과 → 하지 말 것 순서이고, 목업 위 1 핀 번호가 코멘트의 같은 번호와 연결됩니다. 목업은 실제 스크린샷이 아니라 방향을 보여주는 스케치이니, 픽셀보다 구조·순서·상태 표현을 봐주세요.

먼저 · 버그 A 편집 폼 B 완료 C 날짜없음 D 내보내기 E 날짜이동 F 중복표현 G 회고 우선순위
디자인보다 먼저

이건 UX가 아니라 버그입니다 — 여기부터 고쳐야 아래 개선안이 의미가 있어요

피드백이 UX 문제와 섞여 있는데, 아래는 화면 설계로 풀 수 없는 엔지니어링 결함입니다. 특히 날짜가 하루 밀리는 문제는 아래 E안(날짜 이동)을 아무리 잘 설계해도 기준 날짜 자체가 틀리면 신뢰가 무너지므로 가장 먼저 고쳐야 합니다.

B1 · 빌드/접근

빌드 실패 · Vercel SSO로 URL 테스트 불가. 안 고치면 "URL 테스트 안 됨" 피드백이 계속 반복됨.

B2 · KST 날짜 하루 밀림

toISOString() UTC 변환으로 한국 시간 기준 날짜가 하루 앞당겨짐. E안의 전제 조건.

B3 · 저장 유실

반복 회차가 1개만 저장됨 · 분할한 항목이 사라짐. 데이터 정합성 문제.

→ 아래 A~G는 이 버그들이 해결됐다는 전제로 그린 UX/UI 방향입니다.

2

반복·소요시간·결정상태는 "세부 설정"으로 접기. 필요한 사람만 펼침. 덜 보여주는 게 "설명을 줄이는" 가장 빠른 길.

3

결정 상태(구매/거절/보류)는 콘텐츠 타입이 맞을 때만. "예약", "정하기" 같은 항목엔 아예 렌더하지 않음 — 지금처럼 무관한 필드가 뜨는 게 혼란의 핵심.

기대효과

폼 높이 절반 이하 · "체크리스트답다"는 첫인상 회복.

하지 말 것

접었다고 기능 삭제 아님 · 이미 값이 있는 필드는 펼친 상태로 노출.

'계약금 입금' 완료실행 취소

한 리스트 안 · 완료는 취소선 처리 후 아래 "완료" 섹션으로.

High피드백 #4 · "완료 취소가 4단계"
1

완료해도 사라지지 않는다. Things · TickTick · Todoist 공통 패턴 — 그 자리에서 취소선 처리되고 리스트 맨 아래로 내려감. 완료취소는 그냥 다시 탭.

2

탭 분리 대신 한 리스트 안 "완료" 섹션. 오늘/전체 탭으로 나누면 "완료한 게 어디 갔지?"가 또 다른 설명거리가 됨. 접힌 섹션으로 두면 스크롤로 바로 보임.

3

완료 직후 3~5초 Undo 스낵바. 실수로 체크한 경우 대부분 여기서 끝남 — 굳이 완료 섹션까지 안 들어가도 됨.

기대효과

완료취소 4단계 → 1탭 · "완료가 사라진다"는 불안 제거.

하지 말 것

완료 후 자동 화면 이동·모달 금지 · 순서 재정렬은 애니메이션으로 부드럽게.

High · 가장 깊음피드백 #5 · B4 · B5
1

기준일(앵커)을 화면 맨 위 하나로. "이사일" 같은 기준 날짜 하나가 Flow 전체 일정의 원점. 여기를 옮기는 게 "날짜 이동"의 정식 진입점.

2

항목마다 두 모드를 뱃지로 구분. 🔗 연동 = 기준일 대비 상대(이사 10일 전) → 기준일 바뀌면 재계산. 📌 고정 = 내가 직접 정한 날짜 → 기준일 바뀌어도 유지. 지금 B4/B5는 이 구분이 없어서 유지 옵션을 골라도 리셋됨.

3

이동 결과를 실행 전에 문장으로 예고. "연동 2개는 다시 계산, 고정 1개는 유지" — 뱃지가 있으니 설명 없이도 이해됨. 항목의 날짜를 직접 고치면 자동으로 📌고정으로 전환.

기대효과

"내가 바꾼 날짜가 리셋" 버그의 근본 원인(모드 부재) 제거.

하지 말 것

B2(KST 하루 밀림) 안 고치고 착수 금지 · 기준일 없이 상대 날짜 계산 금지.
