SECTION 1

P9-01 ~ P9-07 — 닫힘 판정

7개 중 6개 완전 닫힘, 1개 조건부(P9-04 — lib은 닫힘, 증거 스캐너는 미반영). 각 항목을 코드/픽셀 어디서 확인했는지:

P9-01

가드레일 커버리지 — seed 데이터 전수 자동 검사

닫힘 ✓

요구한 그대로 구현됨 · display-title.test.ts의 "canonical seed and source-backed user-facing text pass display guardrails without route registration" 테스트가 [...seedBundles, ...homepage, ...curatedSourceAppSeed] 전체를 순회하며 collectSourceSlugSignals로 사전을 파생하고 subject별 scanUserSurfaceGuardrails 실패를 0으로 단언합니다. 새 seed는 추가되는 순간 자동 검사 대상 — P8의 "프로즌 커버리지" 문제가 데이터 레벨에서 닫혔습니다. 잔여: 이 테스트는 seed 텍스트를 검사하고, 렌더된 route 커버리지는 여전히 capture의 고정 목록입니다(수용 가능 — 렌더 주변 문구는 공용 컴포넌트라 기존 26장이 대표함).

P9-02

공개 /f 브라우즈 링크 — 접근 가능 + 저장 뒤 순서

닫힘 ✓ (경계는 P10-02)

P8-10의 접근성 문제 해소 · E2E가 이제 not.toHaveAttribute('tabindex','-1') + not.toHaveAttribute('aria-hidden','true')를 단언 — 정확히 반대 방향으로 뒤집혔습니다. 증거: 9개 share 캡처 전부 browse focusable, primary가 있는 5개 캡처 전부 browse가 primary 뒤(before-primary 0). s06에서 "내 Flow에 저장"이 focusable 0번째, browse는 18번째. 단 primary가 측정에 안 잡히는 워크벤치 4캡처가 남는데, 이건 P9-02의 실패가 아니라 측정·표기 공백입니다 → 구멍 ②.

P9-03

"Flow 상태판" 구조어 제거

닫힘 ✓

픽셀 확인 · s17 시트 eyebrow가 "놓친 항목 정리"(P8 리뷰 제안 문구 그대로), 제목 "지난 할 일" 유지. 스캔 쪽도 STRUCTURAL_DISPLAY_PATTERNS에 상태판 · Flow 보드 · Flow 패널 · 실행 큐 · 트레이스 클래스가 lib과 capture 스크립트 양쪽에 추가됐고, 유닛 테스트가 구조어 양성 케이스를 잠갔습니다.

P9-04

slug 문장부호 스캔 — lib은 닫힘, 증거 스캐너는 구버전

조건부 (파이프라인 드리프트)

lib은 진짜 닫힘 · findSourceSlugHits lookahead가 (?=$|\s|\p{Script=Hangul}|D-|\.(?!단어)|문장부호)로 확장됐고 "DeskLab·"·"DeskLab." 양성 유닛 테스트 존재. 그러나 증거를 만드는 capture 스크립트는 다른 패턴들(프로토타입 게이트·ISO·구조어)은 스크립트 상단 상수를 .source로 페이지에 넘기면서, slug lookahead만 page.evaluate 안에 옛 버전으로 하드코딩돼 있습니다: (?=$|\s|[가-힣]|D-). 즉 이 패키지의 sourceSlugHits: 0은 P9-04 이전 규칙으로 잰 0입니다. 지금 seed가 깨끗해서 실질 leak은 없지만(유닛 테스트가 신규칙으로 seed 전수를 커버), 같은 규칙의 사본이 두 벌이 된 게 문제의 본질 → P10-01.

P9-05닫힘 ✓

프로토타입 영어 게이트 확장 · download|copy|sync|import UI 동사 + Jan–Dec·AM/PM 클래스가 lib·capture 양쪽에 동일하게 존재(이쪽은 드리프트 없음). 양성/음성 유닛 테스트 확인. 증거 전 버킷 hit 0.

P9-06닫힘 ✓

D-30 마일스톤 그룹 헤더 · s24에 "D-30 마일스톤 3개 ── 5월 28일 (목)" 헤더가 픽셀로 보이고, D-10·D-1 그룹도 같은 패턴. 증거는 moving-schedule-date-group-heading testid에서 동적으로 읽음 — 고유 날짜 5개 유지.

P9-07닫힘 ✓

가드레일 헬퍼 유닛 테스트 · display-title.test.ts에 함수별 양성+음성 케이스("helpers lock positive and negative display cases" 외), ISO "원문 줄 면제 없음" 테스트 포함. npm test 목록에 포함 확인 — 도는 테스트입니다. 별도 파일이 아닌 건 감점 아님.

요약 — P9는 선언 대비 실제 닫힘률이 높습니다. 화면(P9-03·06)과 규칙+테스트(P9-01·05·07)는 완결. 유일한 잔여는 P9-04의 반쪽 적용: 규칙의 정본은 lib인데, 증거를 만드는 쪽이 정본을 안 씁니다. P10은 기능이 아니라 이 단일화가 1순위입니다.

SECTION 3

남은 구멍 — P10이 다룰 것

① 증거 파이프라인 드리프트 — 규칙 정본과 측정기가 다른 코드 High

capture 스크립트는 ISO·구조어·프로토타입 게이트 패턴을 상단 상수에서 .source로 페이지에 주입하는데, slug 매칭 정규식만 page.evaluate 안에 문자열로 하드코딩돼 있고 그게 P9-04 이전 버전입니다. 이번 한 번은 무해하지만(유닛 테스트가 seed 전수를 신규칙으로 커버), 규칙이 바뀔 때마다 측정기가 조용히 낡는 구조가 남았습니다. 첫 3행 반복 검사(findRepeatedTitleHits)도 페이지 안에 사본이 있습니다. 해법은 기능 추가가 아니라 단일화: lib이 정규식 소스를 export하고, 스크립트는 그걸 주입만. 또는 페이지에서 라인만 추출하고 hit 계산은 Node에서 lib 함수로.

② 워크벤치 share shell의 저장 경로 — 실제 구멍 1 + 측정 구멍 2 High

공개 /f 6개 slug 중 vehicle·moving·used-car만 저장 경로가 focusable로 증거에 잡힙니다. new-car(s11·25)는 "바로 저장됩니다: 시트"라고 말하면서 저장 요소가 DOM엔 있는데 focusable 목록에 없음 — 키보드/SR 사용자는 저장 못 하는데 "콘텐츠 더 보기"에는 도달합니다. P8-10에서 "보이는 컨트롤을 a11y에서 지우지 말 것"과 같은 계열의 문제입니다. fridge·washer는 화면상 setup이 있으니 실사용 문제는 아닐 가능성이 높지만, primary testid가 없어 측정이 -1로 찍히고 E2E 단언이 안 걸립니다(spec의 primary 단언은 6개 중 2개 route만). "저장이 primary"라는 기준선이 워크벤치 계열에선 검증되지 않는 선언인 상태.

③ "지금 이어하기" 빈 설명 카드 + 캘린더 칩 반복 Medium ×2

/my의 "지금 이어하기 → 오늘 할 일" 카드가 s13·15·16 세 화면 모두 행동 없는 설명문입니다 — "저장한 콘텐츠의 첫 할 일을 보여줍니다"라고 쓰고 정작 그 할 일은 위 카드에 있습니다. 이 프로젝트의 원칙("설명 문장 추가로 문제 해결 금지")에 정면으로 걸리는 잔여물. /calendar(s14)는 한 날짜의 4행이 동일 칩 2개씩을 복제 — 공통 맥락은 그룹 헤더로 올리면 행은 제목+체크만 남아 가벼워집니다.

④ Low 묶음 — 라벨 중복 · 깨진 문서 링크 · input value 사각 Low ×3

① restart 행마다 "[전체 제목] 편집" 버튼(s22·24)과 /my 시트의 파란 "항목 열기" 4연발(s17) — 반복 컨트롤은 라벨을 줄이고 위계를 낮출 것. ② README의 GitHub 링크가 전부 …/flow-mvp/… 경로라 이 브랜치에서 404 — capture 스크립트의 githubBase가 flow-mvp를 하드코딩. 리뷰어가 링크로 검증 못 하는 건 evidence 패키지의 자기모순. ③ restart 날짜 input이 raw "2026-06-27"을 표시(locale 의존)하는데 스캔은 innerText만 봐서 input value가 영구 사각.
