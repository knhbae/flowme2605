현 상태 — P13은 닫혔다

지난 루프의 최대 리스크였던 URL-first 무검증 표면이 사라졌습니다. export mode 6/6 스캔에서 Markdown 0, candidate 사용자 copy 내부어 0, trigger URL 4개로 상태 재현 가능, resolved-hit 분기까지 캡처. 프로토타입은 release-preview(restart, hit 0)와 internal-console(/flow-lab, noindex·nav 0·허용 7) 두 티어로 명시 분리. post-save "내 Flow에 저장됨" 첫 할 일 반복 0. 정상 IA에 Blocking·High 없음.

P14에서 가장 먼저 볼 리스크

가드레일이 한 폭에서만 참이다. flow-lab nav-부재 E2E·사용자 표면 스캔·31개 모바일 캡처가 전부 390px. 그런데 이번 wide 5장이 처음으로 다른 폭을 찍자마자, My Flow wide(s36)에 모바일엔 없는 "스튜디오" 내비 버튼이 나타납니다. flowLabPrototypeLinkedFromUserNavCount 0은 모바일에서 잰 값이고, ≥768px에서 그 0이 유지된다는 증거가 없습니다. 게다가 wide 레이아웃은 "overflow 0"만 통과할 뿐 빈 열이 크게 남는 미완성 상태(s32·s35)입니다.

한 줄 판정 — Post-P13은 정상 4탭 기준 출시 가능(Blocking 0). P14의 1번은 기능이 아니라 가드레일의 축 확장: ①"스튜디오" 목적지 확인 + flow-lab/manual-QA nav-부재 스캔을 ≥768px로 확대 → ②사용자 표면 guardrail을 wide breakpoint에서도 실행 → ③wide 레이아웃에 "overflow 0"을 넘는 품질 기준 부여. 순서가 곧 우선순위입니다.

SECTION 4

폭 사각지대 — 다른 폭을 처음 찍자마자 새 내비가 나왔다

P13은 wide를 evidence 티어로 승격시켰지만, 가드레일 자체는 아직 390px에만 삽니다. 그 첫 wide 캡처가 곧바로 두 가지를 드러냅니다.

핵심. 이건 "wide가 깨졌다"가 아니라 "0이 한 폭에서만 참임이 처음 드러났다"는 신호입니다. P9→P13 내내 배운 교훈 — 스캔이 닿지 않으면 기준선은 조용히 되돌아간다 — 이 이번엔 텍스트/라우트 축이 아니라 뷰포트 폭 축에서 반복됩니다. "스튜디오"가 정당한 기능이어도, 그것이 wide에서만 등장하고 nav-부재 스캔이 그 폭을 안 본다는 사실 자체가 P14의 1번입니다.

Baselines To Preserve — P4~P13에서 닫힌 것

아래는 P14 어떤 작업도 깨면 안 되는 기준선입니다. 특히 wide 레이아웃(P14-03)과 nav 확대(P14-01)는 4탭 IA·공유 shell·저장 primary를 폭이 바뀌어도 그대로 유지합니다.

  • 4탭 IA: 홈 / Flow 찾기 / 캘린더 / 내 Flow — 모바일 하단바·wide 상단 pill 모두 동일 4탭
  • 공개 /f/[slug]는 공유 shell(header "공유 화면") 유지, wide에서도 4탭 app shell 강제 편입 금지
  • 공개 primary는 내 Flow에 저장 또는 setup/입력, 콘텐츠 더 보기는 focusable하되 primary 뒤(before-primary 0 · sticky 1차 저장계열 9/9)
  • seed/source-backed 데이터 구조, 저장/실행/export 스키마 불변
  • sourceUrl · sourceTrace · detail · memo · export 접근 삭제 금지(sourceTrace는 사용자 표면 노출만 금지, 접근은 유지)
  • guardrail 정본은 lib/flow/user-surface-guardrails.ts — capture·E2E·유닛 전부 lib 경유
  • 정상 route 스캔 0: internal · slug · 구조어 · raw ISO(visible) · 첫 할 일 반복 · overflow
  • URL-first는 canonical lookup 우선 — hit는 source-backed Flow 재사용(resolved-hit executable), miss/needs_review는 non-executable local candidate 보류
  • URL-first 사용자 표면 버킷 0: Markdown·slug·rawISO·내부어 — export mode 전 모드 유지
  • native date input ISO 값은 면제 버킷에만(url-first-start-date-input·moving-restart-date-input testid), label/help/card 승격 금지
  • /restart/moving-d30 = release-preview 티어(display gate hit 0) · D-30 마일스톤 그룹 헤더 유지
  • /flow-lab/url-first-p0 = internal-console 티어: noindex·정상 nav 링크 0·"내부 실험 콘솔" context 유지 시에만 lab 라벨 허용
  • 내 Flow continuation은 실제 열기 가능한 행(continuationActionable 5 · explanation-only 0)
  • post-save confirmation "내 Flow에 저장됨"은 유지하되 첫 할 일 제목 반복 0
  • 워크벤치: 행 상세 source 링크 0 · source 접근 영역 유지(≥1) · 반복 상세 문장 0 · 공통 주의 1회
  • 패키지 메타: UI baseline commit ≠ package commit 표기 분리

  3. post-save confirmation 지속성 불명 — "내 Flow에 저장됨"이 영구 배지인지 자동 소멸 토스트인지 evidence에 시간축 없음. 소멸형이면 스크린샷 타이밍 의존.
  4. candidate 2-카드 스택 단일샷 — s30에 "아직 준비 전" 카드와 "이제 실행 가능" resolved-hit 카드가 세로로 겹쳐 보임. 실제로 동시 노출인지 상태 전이인지 한 장으론 불명 — 사용자 혼동 가능성 미검증.
  5. ≥768px E2E 부재 — nav-부재·사용자 표면·public CTA·source-density E2E 모두 390px 고정. wide 회귀를 잡는 자동 게이트가 없음(P14-01/02가 신설).
  6. s33 flows wide 하단 잘림 — 캡처가 뷰포트 높이에서 잘려 4번째 카드 이하 미확인. 레이아웃 문제 아니라 캡처 범위 문제로 판단하나 full-page wide 1장 권장.
  7. 실기기 미검토 — 스크린샷·E2E 근거. 실제 터치 타깃·스크롤·키보드 흐름은 별도.
