P20은 닫힌 문을 열었다. miss는 이제 "메모 복사"로 끝나지 않고 앱 안에서 초안을 만들어 내 Flow로 착지하고, 스튜디오 선반·캘린더 요약·저장 전/후 체크 경계까지 P20-01~05가 전부 닫혔다.
그런데 문을 열고 들어간 방이 거의 비어 있다 — 초안은 아직 "단계 1개짜리 빈 골격"이라, URL/메모가 실제 실행 단계로 펼쳐지지 않는다.

P19에서 지적한 단 하나의 막힌 문(URL-first miss dead-end)이 P20에서 정확히 열렸습니다. 이제 miss는 "직접 손볼 초안으로 시작" → 초안 제목·기준일·첫 할 일 편집 → "내 Flow에 초안 저장"으로 이어지고(missDraftInAppEntry yes · savePath yes · impliesLiveAI no), 그 초안이 내 Flow에 "주말 준비 초안 · 전체 0/1 완료"로 착지해 기준일·항목·메모를 고칠 수 있고 캘린더/내보내기에 반영됩니다(draftFlowMyFlowLanding yes · CalendarProjection yes · ExportProjection yes). 스튜디오 "내 초안" 탭은 5번째 탭이 아니라 보조 선반으로만 작동하고(draftEditDestinations → /my), 공개 /f 저장 전 preview(completion-like 0)와 저장 후 활성 완료 체크(postSave active yes)의 경계가 캡처로 닫혔으며, 캘린더 월 그리드는 2 라벨 + 외 N개로 압축되고 agenda는 전체 상세를 유지합니다(gridVisibleLabels 2 · overflowSummary yes · overflow 0). P18/P19 기준선(완료 체크박스 1종·진행 숫자 맥락·홈 입구·CTA 순서·source density)도 모두 유지됩니다. P20은 재작업 없이 정직하게 닫혔습니다. 그래서 P21의 축은 마감이 아니라 "열어놓은 방을 채우는 것"입니다 — 지금 초안은 missDraftEditableItemCount 1, 즉 사용자의 URL/메모가 "원문에서 필요한 단계 정리하기"라는 단계 1개짜리 빈 초안으로만 생깁니다. 배관은 증명됐고, 그 안을 흐르는 물(실제 초안 내용)이 아직 없습니다.

SECTION 1

P20-01~05 판정 — 닫힘 / 부분 미흡 / 미해결

다섯 항목 모두 제품 흐름 기준으로 닫혔습니다. 아래는 각 항목의 판정 + 근거 마커 + screenshot입니다. "부분 미흡"은 P20 범위가 아니라 P21로 넘어갈 다음 단계를 뜻합니다.

P20-01 · 닫힘

URL-first miss → 앱 안 초안 Flow 흐름

P19의 유일한 dead-end가 열렸다. miss는 "아직 준비된 Flow가 없어요 · 바로 만들지는 않습니다"로 정직하게 유지되면서(29), candidate에 "앱 안에서 이어가기 · 직접 손볼 초안으로 시작 · 초안 편집 시작"이 생겼고 → 초안 제목·기준일·첫 할 일 편집 → "내 Flow에 초안 저장"으로 이어진다(30).

근거 · missDraftGateVisible yes · missDraftInAppEntryVisible yes · missDraftSavePathVisible yes · missDraftImpliesLiveAI no · missDraftLiveAiCopyHits 0 · missDraftInternalHits 0 · candidate user-copy internalHits 0 · visibleMarkdown 0. 과장·내부어 재노출 없음.

P21로 넘어갈 것 · missDraftEditableItemCount 1 — 초안이 아직 단계 1개짜리 빈 골격. 실제 내용 생성은 다음 단계(§4 P21-01).

P20-02 · 닫힘

초안 Flow가 My Flow에 착지·수정

저장한 초안이 내 Flow에 "주말 준비 초안"으로 착지하고(39a), 기준일 바꾸기·항목 날짜 override·제목 alias·사용자 메모 편집이 모두 열린다(39b). P19에서 지적한 wide 기준일 입구 0 문제도 해결됐다 — draftFlowAnchorEditVisibleByViewport {390:2, 1024:1}, 일반 편집도 {"1024":{anchor:1, item:1}}으로 wide anchor가 1로 올라왔다.

근거 · draftFlowMyFlowLandingVisible yes · draftFlowEditEntryVisible yes · draftFlowItemEditEntryVisible yes · draftFlowAnchorOverridePolicyVisible yes · draftFlowCalendarProjectionUpdated yes · draftFlowExportProjectionUpdated yes. 기준일↔항목 정책 카피 노출("따로 바꾼 날짜는 그대로 유지").

P20-03 · 닫힘

스튜디오 초안 탭 = 보조 선반

/u/my-flow-studio의 "내 초안" 탭에 URL-first 초안이 카드로 모이고(39e), 카드의 수정 경로가 "내 Flow에서 수정" → /my 한 곳으로만 간다. Studio는 5번째 탭으로 승격되지 않았다 — /my·/calendar 헤더의 보조 버튼으로만 진입하고 noindex다.

근거 · draftTabVisible yes · urlFirstDraftCardCount 2 · draftEditDestinations [{label:"내 Flow에서 수정", href:"/my"}] · studioEntryUnexpectedRouteCount 0 · draft shelf noindex true · creatorProfileGuardrailHits 0. 4탭 IA 밖 유지.

P20-04 · 닫힘

공개 /f 저장 전 preview ↔ 저장 후 완료 경계

P19에서 evidence 공백이던 저장 후 상태가 캡처됐다. 저장 전 89개 체크는 전부 preview/선택(완료 아님)으로 유지되고(completion-like 0), 저장 후 같은 콘텐츠가 내 Flow에서 활성 완료 체크박스로 바뀐다(12b). Flow 단위 저장 primary·Flow 단위 내보내기 위계도 그대로.

P20-05 · 닫힘

캘린더 그리드 3+ Flow 압축 · agenda 전체 상세

같은 날짜에 4개 Flow가 겹쳐도 월 그리드 셀은 최대 2 라벨 + "외 2개"로 압축되고(44b: "해외여행 …, 외 2개, 일본 eSIM…"), selected-day agenda는 모든 Flow 그룹·할 일을 그대로 보여준다(43b). 모바일·wide 가로 overflow 0.

사용자 여정 기준 남은 UX 문제

"URL/메모 입력 → 초안 → 내 Flow 실행 → 캘린더/내보내기" 여정을 따라가며 지금 사용자가 실제로 걸리는 지점만 정리했습니다. P20 마감 자체는 깨끗하므로, 아래는 대부분 "열린 흐름의 다음 병목"입니다.

여정 ② 초안 · 핵심

초안이 "단계 1개짜리 빈 골격"이라 URL/메모가 실행 계획으로 펼쳐지지 않는다

miss 초안을 저장하면 내 Flow에 "주말 준비 초안 · 전체 0/1 완료 · 날짜 항목 1개 · 단계 1: 원문에서 필요한 단계 정리하기"만 생긴다(39a). 사용자가 넣은 URL/메모가 여러 실행 단계로 분해되지 않고, 제목도 "새로 보고 싶은 준비 체크리스트" 같은 자리표시자다(30). 배관은 완성됐지만, 사용자 입장에선 "내가 URL을 넣었는데 할 일이 딱 1개, 그것도 '단계 정리하기'라는 빈 항목만 생겼다" — 실제로 쓸 계획이 아니다. 이게 P21에서 채워야 할 방의 핵심. → §4 P21-01

전 여정 · 신뢰

구조 표시 누수 2건이 정상 라우트에 남아 있다

normalRouteStructuralDisplayHitCount 2, wideViewportStructuralDisplayHitCount 2 — 0이 아니다. 다른 모든 버킷(internal·sourceSlug·rawISO·visibleMarkdown·candidate internal)은 0인데 구조 표시만 2건 남아, "완전히 닫혔다"고 말하려면 이 2건의 정체를 찾아 없애야 한다. 사용자가 특정 화면에서 구조/타입 용어를 볼 가능성. → §4 P21-03

여정 ② → ③ · 증거

초안이 이제 "쓰기 경로"인데 실패·빈·완료-후 상태 캡처가 없다

P20에서 초안 저장이 실제 데이터를 쓰는 경로가 됐다. 그런데 초안 저장 실패·중복 초안·빈 내 Flow·완료 후(취소선/잔여 0)·오프라인 캡처가 전무하다(모든 체크박스 checked:false). 쓰기 경로가 열린 만큼 실패·경계 상태의 증거 공백이 P19 때보다 더 중요해졌다. → §4 P21-04

여정 ① 입력 · 폴리시

홈 입구 라벨에 구분자 누락 — "Flow 찾기링크 붙여넣기"

홈 입구 라벨이 "URL이나 메모로 Flow 찾기링크 붙여넣기 · 요청 메모 · 준비된 Flow 확인"으로 기록된다 — "찾기"와 "링크" 사이 구분자·공백이 빠져 한 단어처럼 붙는다. 화면상 2줄로 렌더돼 치명적이진 않지만, 첫 입구의 마이크로카피 결함. → §4 P21-05

여정 ④ 캘린더 · 폴리시

그리드 압축은 됐지만 라벨이 "해외여행 …"까지 잘려 식별성이 낮다

P20-05로 "외 N개" 압축은 닫혔지만, 남는 2개 라벨도 "해외여행 …", "일본 eSIM…", "컴퓨터활…"처럼 잘려 어느 Flow인지 색 외엔 구별이 어렵다(44b). 실사용 지장은 작고 P21-01 뒤로 미룰 수 있는 폴리시. → §4 P21-05

P21-01 · High · url-first/my-flow

초안 내용 첫 slice — URL/메모를 여러 실행 단계로 펼친다

문제 · 초안이 단계 1개짜리 빈 골격(missDraftEditableItemCount 1)이라, 사용자의 URL/메모가 실제 실행 단계로 분해되지 않는다. 제목·항목 모두 자리표시자.

사용자가 겪는 상황 · "이사 준비 블로그 URL을 넣고 초안을 저장했더니, 내 Flow에 할 일이 딱 1개 — 그것도 '원문에서 필요한 단계 정리하기'라는 빈 항목만 생겼다. 결국 내가 다 직접 써야 한다."

봐야 할 route/screenshot · /flows miss·candidate(29·30) → /my 초안 착지(39a) · missDraftEditableItemCount.

권장 수정 방향 · miss 초안을 3~7단계로 펼친다. 1단계: 결정론적 파싱(URL 제목/메모 문장 → 후보 단계, 기준일 기준 날짜 배분)으로 실제 여러 항목을 생성 → 사용자가 13c overlay에서 확인·수정·삭제 → 저장. 실제 LLM 생성은 2단계(P21-02, gate 뒤)로 분리해 impliesLiveAI false를 유지.

구현하지 말아야 할 것 · 실제 외부 AI API를 이 slice에서 붙이지 말 것(정직성 위반 위험). 저장 전 full editor로 되돌리지 말 것 — 편집은 저장 후 내 Flow 모델 유지. 초안을 "완성된 Flow"로 표시하지 말 것(항상 "초안·제안" 톤).

검증 기준 · missDraftEditableItemCount ≥ 3 · 각 항목이 기준일 기준 날짜를 가짐 · 사용자어 internal hit 0 · missDraftImpliesLiveAI no 유지 · 저장 후 캘린더/내보내기 반영 · overflow 0.

P21-02 · Low · url-first · spec·gate

실제 AI 생성 + 초안 자동 제목 — P21-01 뒤 spec만

문제 · P21-01의 결정론적 파싱은 URL 구조가 약하면 빈약하다. 진짜 가치(원문에서 단계 자동 제안 + 의미 있는 제목)는 LLM이 필요하지만, 지금 열면 정직성 기준선을 위협한다.

사용자가 겪는 상황 · "제목이 '주말 준비 초안'처럼 뻔하고, 파싱이 안 되는 URL은 여전히 빈 초안이다."

봐야 할 route/screenshot · 30(초안 제목 자리표시자) · 39e(스튜디오 초안 카드 제목).
