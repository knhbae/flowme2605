SECTION 3 · 핵심

P8 이후에도 남은 구멍 — 코드에서 확인

가드레일 소스를 줄 단위로 읽고 찾은 실제 구멍 5개. 지금은 전부 green이지만, 다음 seed/route에서 회귀를 놓칠 수 있는 종류입니다.

① 커버리지가 프로즌 — 규칙은 일반, 검사 대상은 고정 route

P8-01은 규칙(slug 사전 파생, 동적 제목, ISO 면제 제거)을 훌륭히 일반화했습니다. 하지만 이 규칙이 돌아가는 대상은 여전히 flow-mvp.spec.ts·capture가 손으로 나열한 route뿐입니다. 새 seed(seedBundles에 항목 추가)를 만들어도, 그 route를 spec/capture에 수동 등록하기 전까지 slug/ISO/구조어 검사를 한 번도 받지 않습니다. 즉 "일반화된 스캐너"가 있어도 "일반화된 커버리지"는 없습니다. → P9-01(High): 모든 seedBundles 제목·출처·날짜를 스캐너에 통과시키는 데이터 구동 단위 테스트를 추가.

② 구조어 스캔이 "지도" 계열만 — "Flow 상태판"을 못 봄

STRUCTURAL_DISPLAY_PATTERNS = [/Flow Map/i, /일정 지도/, /저장한 지도/, /지도 일정/, /지도 루틴/];
// "Flow 상태판"(s17 /my 시트 eyebrow)은 여기에 없음 → hit 0
// trailingFlowSuffix는 "…Flow"로 끝나는 줄만 → "상태판"으로 끝나 놓침

"상태판·보드·패널·큐·트레이스" 같은 내부 구조 명사가 사용자 화면에 뜨는데 스캔이 "지도"만 봅니다. 실제로 정상 /my에 "Flow 상태판"이 살아 있습니다(s17). → P9-03(Med): 문구를 사용자어로 바꾸고(예: "지난 할 일" 시트엔 eyebrow 불필요/"놓친 항목"), 구조어 목록을 클래스로 확장.

③ slug가 ASCII 문장부호에 붙으면 lookahead가 놓침

new RegExp(`(^|[^\p{L}\p{N}_])${slug}(?=$|\s|[가-힣]|D-)`, 'iu')
// 뒤가 공백/한글/"D-"/끝일 때만 매치.
// "AJD·", "Mathbang)", "KKday," 처럼 ·)·, 앞이면 lookahead 실패 → 놓침

slug가 가운뎃점·괄호·쉼표에 바로 붙으면 검사를 빠져나갑니다. 한국어 UI에서 "브랜드·설명" 패턴은 흔합니다. → P9-04(Low): lookahead에 문장부호/word-boundary 포함.

④ 프로토타입 언어 게이트가 "export"·"Sun–Sat" 단어만 — 클래스가 아님

MIXED_EXPORT_LANGUAGE_PATTERN은 literal "export"만, ENGLISH_WEEKDAY_PATTERN은 Sun–Sat만 봅니다. 같은 회귀 클래스인 download·copy·sync·import(영어 UI 동사)나 Jan–Dec·AM/PM(영어 월/시간)은 못 잡습니다. restart를 넘어 새 프로토타입이 생기면 재발 가능. → P9-05(Low): 영어 UI 동사/월 클래스로 확장.

⑤ firstClickableLabels 증거가 P8-10 주장과 모순

route-evidence의 firstClickableLabels는 tabindex/aria-hidden을 필터하지 않아 여전히 "콘텐츠 더 보기"를 2번째로 나열합니다(s06 등). E2E는 focusable에서 제외됐다고(green) 하는데, 대표 증거 배열은 반대로 보입니다. 리뷰어가 JSON만 보면 P8-10이 실패한 것처럼 읽힙니다. → P9-02에 포함(Low): 증거 배열을 실제 focusable 순서로 기록하거나 aria-hidden 표식 병기.

그래서 결론

P8은 P7의 가드레일 하드코딩을 실제로 풀었습니다(구멍 ①~③ 중 규칙 부분은 닫힘). 남은 건 성격이 다릅니다 — 커버리지 자동화(①), 잔여 구조어 1건(②), 그리고 스캔 클래스의 폭(③④)과 증거 정합(⑤). 어느 것도 화면을 막지 않지만, ①과 ②는 다음 seed·현재 사용자에게 직접 영향이라 P9의 머리입니다.

P9-01가드레일 커버리지 자동화 — 모든 seed를 스캐너에 통과

Section 3 구멍 ①. user-surface-guardrails.ts는 이미 순수 함수라 단위 테스트에 바로 물립니다. seedBundles + getSourceBackedHomepageFlowMaps + getCuratedSourceAppSeedFlowMaps의 모든 제목·출처·날짜 문자열을 scanUserSurfaceGuardrails에 넣어 hit 0을 단언하는 데이터 구동 테스트를 추가. 그러면 새 seed는 route를 손으로 안 넣어도 자동으로 검사됩니다. 화면·스키마 불변.

지시: "상태판"은 내부 구조어. 사용자에겐 이 시트가 "무엇인지"(놓친 것)만 필요. 내부 컴포넌트명/testid는 그대로, 표시 문구만. 동시에 스캔 패턴에 상태판 클래스 추가(P9-03 코드분).

제안

aria-hidden 제거, 포커스 가능 유지. DOM/tab 순서를 저장 CTA·입력 뒤로. 시각 위치(우상단)는 CSS로 유지 가능.

지시: "저장이 먼저 닿게"는 순서 문제지 가시성 문제가 아닙니다. 보이는 링크를 a11y 트리에서 지우면 SR 사용자는 공개 페이지에서 /flows로 갈 길이 사라집니다. E2E는 "browse가 저장 뒤"를 단언하도록 수정(현재 "browse 부재"를 단언).

검토 기준 9개 — 답

1. P8-01 가드레일 일반화가 충분한가?

규칙은 충분, 커버리지는 미완. slug 사전 seed 파생·동적 제목·ISO 면제 제거 — P7 3개 구멍 규칙부는 닫힘. 하지만 스캐너가 고정 route만 훑어, 새 seed는 자동 검사 안 됨. → P9-01(High).

2. P8-02 restart 표시 게이트가 충분한가?

충분. 원시 slug·영문 요일·영어 동사·중복 export 4종 전부 정리(s21·s24), scanPrototypeRouteGuardrails가 정식 검사. 잔여는 같은-날짜 묶음 헤더(P9-06 Low)뿐.

3. P8-03/04 "지난 할 일" 라벨·상태 정확성이 유지되는가?

유지. 3표기 → "지난 할 일" 하나(s16·s17), E2E가 expectTextOccurrenceAtMost(…,'지난 할 일',1)로 못박음. 과거 항목 "다음 할 일" 오표기 재현 안 됨. 단 시트 eyebrow "Flow 상태판" 구조어는 별개 문제(P9-03).

4. P8-05 source/export vs bottom 프레임이 분리됐는가?

분리됨. s22(scrollY 2846, hash 36b7…) ≠ s23(3141, c28e…), 신규 s24 full-schedule 추가. P7 바이트-동일 해소.

5. P8-06 라벨 카운터가 실제 queue/section 스코프를 보는가?

본다. countScope: my-flow-queue-label-surfaces로 히어로 부제 오염 제거, 홈·수학 overdueLabel: 0. 카운트가 다시 신호.

6. P8-07 restart 날짜 의미가 혼동 없는가?

의도 문서화 O, 시각 폴리시 △. 첫 3행 동일 날짜는 "의도된 D-30 마일스톤 묶음"(전체 5개 고유 날짜, s24), 각 행 "D-30" pill이 근거. 다만 묶음 헤더가 없어 첫인상엔 여전히 반복돼 보임 → P9-06(Low, 프로토타입).

7. P8-08 커밋 메타가 헷갈리지 않는가?

명확. uiBaselineCommit·packageGeneratedFromCommit·packageCommitRef이 README·audit·JSON에 분리 명시(둘 다 fd78f21, 리뷰 대상 0552d21이 이를 포함). P7 혼선 해소.

8. P8-09 워크벤치 출처 밀도가 충분히 낮아졌는가?

낮아짐. 행 상세 다 펼쳐도 행별 출처 링크 0(s25·s26, 실행/완료/이유/주의만), 출처는 출처 카드 1곳. E2E가 details a[href]=0으로 못박음.

9. P8-10 "콘텐츠 더 보기"가 tab order/접근성에서도 보조로만 남는가?

tab 경로에선 O, 접근성 방식은 X. tabindex=-1로 tab 경로에선 빠졌지만, aria-hidden=true로 보이는 링크를 SR에서 통째로 제거 — 공개 shell에서 SR 사용자의 /flows 도달 경로가 사라짐(WCAG 4.1.2/2.4.3 부적절). 게다가 증거 firstClickableLabels는 아직 이 링크를 2번째로 나열(모순). → P9-02(Med): aria-hidden 제거 + 저장 뒤로 재정렬.
