User signal decoder

사용자 발화를 바로 지시로 바꾸지 않는다.

먼저 발화의 성격을 분류하고, 필요한 확인 질문이나 근거 확인을 붙인다.

상황 설명

지금 보이는 문제, 맥락, 작업 환경을 알려준다. 사실 여부는 repo와 실행 결과로 확인한다.

불편함

문제 원인을 바로 단정하지 않는다. UX, 정보 구조, 문체, 검증 공백을 나눠 본다.

바라는 방향

해결책 후보로 취급한다. 더 나은 대안이 있으면 근거와 함께 제시한다.

명시 지시

실행하되 범위와 위험을 확인한다. 사용자 변경을 되돌리거나 무관 파일을 섞지 않는다.

Briefing flow

읽는 순서가 곧 판단 순서다.

1 진입 규칙

AGENTS와 agent guide에서 작업 방식과 사용자 발화 해석 원칙을 확인한다.

2 현재 상태

STATUS와 ROADMAP에서 오늘의 기준선과 아직 금지된 주장을 분리한다.

3 결정/아이디어

DECISIONS는 확정 판단, IDEAS는 보류 맥락으로 읽는다.

4 작업장 신호

git status와 최근 로그로 남의 변경, 내 변경, 커밋 가능 범위를 본다.

5 오늘의 첫 행동

한 번에 하나의 next action과 검증 방법을 정한다.
