# FLOW Execution Model Redesign Spec

> 작성일: 2026-05-22  
> 상태: 수정 기획서 초안  
> 범위: 랜딩, 채널 탐색, Flow 상세, 내 Flow, 콘텐츠 타입별 입력/가공/출력 규칙  
> 전제: Stage 0 데모/검증 단계. 로그인, DB, 외부 API 직접 연동은 아직 전제하지 않는다.

## 1. 왜 다시 잡는가

최근 UX 정리는 중복과 혼란을 줄이는 데에는 일부 효과가 있었지만, FLOW의 본질인 "원본 콘텐츠를 실행 가능한 목록, 일정, 루틴, 내보내기 결과물로 바꾸는 경험"을 충분히 보여주지 못했다.

특히 다음 문제가 크다.

- Flow 첫 화면에서 체크리스트나 투두리스트처럼 실행 항목이 한눈에 길게 보이지 않는다.
- 월별 캘린더 보기가 약해지거나 사라져서 날짜 기반 Flow의 결과물을 상상하기 어렵다.
- 루틴 Flow에서 한 가지 또는 여러 가지 항목이 어떤 주기로 반복되는지 보이지 않는다.
- 콘텐츠 타입별로 어떤 정보를 보여주고, 어떤 입력을 받고, 어떻게 가공하고, 어디로 내보내는지 정의가 부족하다.
- 사용자가 원본 블로그/유튜브에서 설명을 듣고 들어왔을 때 "아, 내가 읽은 내용을 바로 따라 할 수 있게 정리했구나"라는 확신이 약하다.
- 서비스 안에서 검색하거나 채널을 돌아다닐 때도 "이거 따라하면 되겠다"는 느낌보다 카드와 설명을 해석해야 하는 부담이 크다.

이번 문서는 현재 UI를 바로 고치는 세부 지시서가 아니라, 앞으로의 UI와 데이터 구조가 따라야 할 제품 계약을 정리한다. 와이어프레임은 이 문서를 기준으로 별도 작성한다.

### 1.1 이번 범위에서 제외하는 것

이번 재기획은 실행 UX와 콘텐츠 구조를 잡는 문서다. 원본 콘텐츠 권리, 저작권, 라이선스 검토는 이번 범위에서 제외한다. 이후 별도 법무/운영 정책으로 다룬다.

## 2. 제품 약속

FLOW는 콘텐츠 소비 후 남는 "그래서 이제 뭘 해야 하지?"를 실행 객체로 바꿔준다.

```text
원본 콘텐츠
  -> 실행 객체로 구조화
  -> 사용자가 기준값을 입력
  -> 리스트, 루틴, 달력, 표, 메모로 변환
  -> 사용자의 도구로 복사/내보내기
```

사용자가 FLOW 페이지에 도착했을 때 10초 안에 느껴야 하는 것은 다음이다.

- 이 Flow가 어떤 원본 콘텐츠 또는 채널을 기반으로 했는지 알 수 있다.
- 내가 해야 할 항목이 리스트로 보인다.
- 날짜나 반복 주기를 조금만 입력하면 달력/표/메모로 바뀔 것 같다는 기대가 생긴다.
- 내 상황에 맞지 않는 항목은 스킵하거나 메모할 수 있다.
- 필요하면 캘린더, 엑셀, 메모, 투두리스트로 옮길 수 있다.

## 3. 핵심 사용자 여정

### 3.1 외부 콘텐츠 유입

사용자 상황:

- 블로그, 유튜브, 뉴스레터, 커뮤니티 글에서 설명을 읽거나 본다.
- "전체 체크리스트는 FLOW에서 보기" 또는 "일정표로 받아보기" 링크를 누른다.
- FLOW 상세 페이지로 도착한다.

페이지가 해야 할 일:

- 원본 콘텐츠 제목, 채널, 도메인을 즉시 보여준다.
- 원본의 긴 설명을 실행 항목으로 바꿨다는 사실을 보여준다.
- 첫 화면에 실행 리스트 일부와 전체 규모를 보여준다.
- 기준 날짜나 반복 주기를 입력하면 달력/표가 바뀐다는 미리보기를 제공한다.

### 3.2 서비스 내부 탐색

사용자 상황:

- FLOW 랜딩, 카테고리, 채널 페이지에서 쓸만한 Flow를 찾는다.
- 아직 원본 콘텐츠를 보지 않았을 수 있다.

페이지가 해야 할 일:

- 카드에서 "무슨 상황에 쓰는 Flow인지"와 "어떤 출력물이 나오는지"를 보여준다.
- 카드는 설명보다 실행 결과를 먼저 암시해야 한다.
- 채널별 탐색은 유지한다. 사용자는 "누가 만든 실행 가이드인지"로도 신뢰를 판단한다.

### 3.3 재방문과 이어하기

사용자 상황:

- 같은 브라우저에서 나중에 다시 돌아온다.
- 로그인은 없다.

페이지가 해야 할 일:

- localStorage 기반으로 진행률, 기준 날짜, 체크/스킵/메모를 복구한다.
- `/my`는 제작자 스튜디오가 아니라 "내가 진행 중인 Flow"를 먼저 보여준다.
- 단, 다른 기기 동기화가 안 된다는 한계는 정직하게 안내한다.

## 4. 실행 객체 모델

FLOW는 모든 콘텐츠를 단순한 체크박스 목록으로만 보지 않는다. 각 항목은 사용자가 옮겨 담을 도구에 맞는 실행 객체여야 한다.

| 실행 객체 | 의미 | 필요한 정보 | 대표 출력 |
| --- | --- | --- | --- |
| Checklist Task | 언젠가 체크하면 되는 일 | 제목, 완료 조건, 섹션, 선택/스킵 가능 여부 | 리스트, 투두, 엑셀 |
| Deadline Task | 특정 날짜까지 해야 하는 일 | 마감일 또는 D-day offset, 완료 조건 | 투두 due date, 캘린더 all-day, 엑셀 |
| Scheduled Event | 특정 날/시간에 발생하는 일정 | 날짜, 시작 시간, 종료/소요 시간, 장소 | 캘린더 ICS, 월별 달력 |
| Time Block | 시간을 확보해야 하는 작업 | 날짜, 시작 시간, 소요 시간, 작업 내용 | 캘린더 block, 주간 일정 |
| Routine Action | 반복 루틴 안의 한 행동 | 행동명, 소요 시간, 완료 기준, 순서 | 루틴 세션 체크리스트 |
| Routine Session | 반복되는 실행 회차 | 반복 규칙, 회차 날짜, 포함 행동들 | 주간/월간 달력, 루틴 로그 |
| Decision Row | 비교/결정해야 하는 항목 | 후보, 기준, 점수/메모, 결정 상태 | 엑셀, 비교표 |
| Reference Note | 실행에 필요한 참고 정보 | 원문 링크, 요약, 주의, 출처 유형 | 메모, 카드, export description |
| Reminder | 놓치지 않기 위한 알림 후보 | 알림 시점, 대상 작업, 메시지 | 캘린더 알림 문구, 메모 |

### 4.1 공통 항목 필드

Stage 0에서는 DB가 없어도 seed 데이터와 클라이언트 상태가 아래 개념을 따르도록 맞춘다.

```ts
type FlowItemKind =
  | 'checklist_task'
  | 'deadline_task'
  | 'scheduled_event'
  | 'time_block'
  | 'routine_action'
  | 'decision_row'
  | 'reference_note';

type FlowItem = {
  id: string;
  title: string;
  kind: FlowItemKind;
  sectionId?: string;
  order: number;
  dayOffset?: number;
  defaultDate?: string;
  defaultTime?: string;
  estimatedMinutes?: number;
  completionCriteria?: string[];
  why?: string;
  how?: string[];
  sourceUrl?: string;
  sourceLabel?: string;
  riskNote?: string;
  skippable?: boolean;
  dependsOn?: string[];
  exportTargets: Array<'list' | 'calendar' | 'sheet' | 'memo' | 'todo'>;
};
```

## 5. 콘텐츠 타입별 제품 계약

### 5.1 Checklist Flow

대표 예시:

- 중고차 구매 현장 점검
- 이사 당일 체크리스트
- 서류 준비 체크리스트
- 여행 짐 체크리스트

사용자가 보는 핵심:

- 한눈에 긴 체크리스트가 보여야 한다.
- 날짜 입력 없이도 바로 체크할 수 있어야 한다.
- 섹션별로 접을 수 있어도, 첫 화면에서는 "리스트가 있다"는 감각이 강해야 한다.

사용자 입력:

- 필수 입력 없음.
- 선택 입력: 상황 필터, 예산/차종/가족 구성/여행지 같은 조건.
- 항목별 입력: 체크, 스킵, 메모.

가공 방식:

- 항목을 섹션별로 묶는다.
- 상황 필터가 있으면 불필요한 항목을 숨기거나 "해당 없음 후보"로 표시한다.
- 체크/스킵 상태를 진행률에 반영한다.

기본 화면:

- 기본 탭은 `리스트`.
- 달력은 기본 필수가 아니다. 단, 사용자가 날짜를 붙이고 싶을 때만 "알림 날짜 추가"로 확장한다.
- 엑셀/메모/투두 내보내기가 주 출력이다.

첫 화면 규칙:

- 최소 6개 이상의 항목 제목이 보여야 한다.
- "전체 N개 항목"보다 실제 항목 제목이 먼저 보여야 한다.
- 항목 카드에는 체크박스, 제목, 섹션, 메모, 스킵이 명확히 보여야 한다.

### 5.2 Timeline Flow

대표 예시:

- 이사 D-30
- 결혼 D-180
- 해외여행 D-14
- 시험 D-30
- 건강검진 D-7

사용자가 보는 핵심:

- 기준 날짜 하나를 입력하면 전체 날짜가 계산된다.
- 입력 전에도 예시 날짜로 월별 캘린더와 리스트가 보여야 한다.
- 리스트는 실행 내용, 달력은 날짜 배치와 밀도를 보여준다.

사용자 입력:

- 필수 입력: 기준 날짜. 예: 이사일, 예식일, 출국일, 시험일.
- 선택 입력: 시작 가능일, 제외 요일, 주말만 보기, 알림 희망일.
- 항목별 입력: 체크, 스킵, 메모, 날짜 조정.

가공 방식:

```text
actualDate = anchorDate + dayOffset
```

- 기준 날짜가 없으면 sample anchor를 사용한다.
- sample mode에서는 "예시 날짜로 보는 중" 배너를 항상 표시한다.
- 기준 날짜 입력 후에는 모든 항목의 실제 날짜와 요일을 계산한다.
- 이미 지나간 offset은 "지났음", "오늘 처리", "스킵 후보" 중 하나로 분류한다.
- 같은 날짜의 항목은 agenda 묶음으로 보여준다.

기본 화면:

- 기본 탭은 `리스트`.
- `월별 달력`은 유지한다. 제거 대상이 아니다.
- `주별 보기`는 월별 달력이 충분히 커버하지 못할 때만 둔다.
- 리스트와 달력은 같은 데이터를 다른 관점으로 보여준다.

첫 화면 규칙:

- Hero 아래에 기준 날짜 입력과 실행 리스트 미리보기가 함께 보여야 한다.
- 리스트에는 `D-30 · 2026-06-15`처럼 D-day와 실제 날짜를 함께 표시한다.
- 달력 preview는 접힌 카드라도 첫 화면 근처에서 보여야 한다.

### 5.3 Routine Flow

대표 예시:

- 4주 러닝 루틴
- 매일 10분 스트레칭
- 매주 냉장고 정리 루틴
- 시험 공부 매일 반복 루틴

사용자가 보는 핵심:

- 언제 반복하는지 보인다.
- 한 회차에 무엇을 하는지 보인다.
- 한 가지 행동 루틴과 여러 행동 묶음 루틴이 모두 표현된다.
- 달력에 반복 일정이 찍히는 것을 바로 볼 수 있다.

사용자 입력:

- 필수 입력: 시작일 또는 시작 주.
- 필수 또는 추천 입력: 반복 주기. 예: 매일, 매주 월/수/금, 주 3회, 매월 1일.
- 선택 입력: 시간대, 회차당 소요 시간, 종료일/기간, 쉬는 날, 놓쳤을 때 처리 방식.
- 항목별 입력: 회차 완료, 행동별 완료, 메모, 스킵/연기.

가공 방식:

```text
occurrences = expandRecurrence(startDate, repeatRule, endCondition)
session = occurrence + orderedRoutineActions
```

- 한 가지 루틴은 각 occurrence가 곧 하나의 체크 항목이 된다.
- 여러 가지 행동 루틴은 각 occurrence 안에 action set을 포함한다.
- 예: 월/수/금 20분 루틴이면 월/수/금 날짜마다 `준비 운동 -> 본 운동 -> 정리 운동` 세부 항목이 들어간다.
- 루틴은 미뤄진 빚처럼 쌓이지 않게 한다. 놓친 회차는 `건너뜀`, `오늘로 이동`, `다음 회차부터 계속` 중 하나로 처리한다.

기본 화면:

- 기본 탭은 `이번 주`.
- `월별 달력`은 반복 패턴을 이해시키는 핵심 보기다. 유지한다.
- `리스트`는 오늘 또는 다음 회차의 세부 행동을 보여준다.
- `기록`은 Stage 0에서는 간단한 완료 로그만 둔다.

첫 화면 규칙:

- 루틴 요약을 한 줄로 보여준다. 예: `월/수/금 · 4주 · 회차당 20분 · 3개 행동`.
- 반복 주기를 선택하면 오른쪽 또는 아래 달력에 즉시 반영된다.
- 한 회차 안에 들어가는 행동 목록이 첫 화면에 보여야 한다.

### 5.4 Program Flow

대표 예시:

- 5K 러닝 4주 프로그램
- 시험 D-30 + 매일 2시간 공부
- 다이어트 2주 챌린지

사용자가 보는 핵심:

- Timeline과 Routine이 섞인 구조다.
- 날짜마다 해야 할 내용이 달라질 수 있다.
- 단순 반복이 아니라 주차별 강도가 변한다.

사용자 입력:

- 시작일 또는 목표일.
- 반복 가능 요일.
- 회차당 가능한 시간.
- 난이도 또는 현재 수준.

가공 방식:

- 프로그램 템플릿의 week/day 구조를 사용자의 시작일에 맞춰 펼친다.
- 회차별 action set이 다르면 occurrence마다 다른 세부 항목을 붙인다.
- 휴식일도 캘린더에 표시할지 선택하게 한다.

기본 화면:

- `이번 주 계획`, `전체 리스트`, `월별 달력`을 모두 제공한다.
- 첫 화면은 이번 주 계획과 전체 진행 구조를 함께 보여준다.

### 5.5 Phase Flow

대표 예시:

- 이유식 단계별 준비
- 아기 월령별 발달 체크
- 반려동물 성장 단계 관리

사용자가 보는 핵심:

- 날짜보다 단계가 중요하다.
- 사용자의 현재 단계 또는 기준일을 넣으면 지금 볼 단계가 정해진다.

사용자 입력:

- 현재 단계.
- 생년월일 또는 시작일.
- 민감 카테고리에서는 공식 정보 확인 여부.

가공 방식:

- stage index 또는 age/month를 계산한다.
- 현재 단계, 다음 단계, 나중 단계를 분리한다.
- 민감한 정보는 공식 출처와 경험 팁을 분리한다.

기본 화면:

- `지금 단계`, `다음 단계`, `전체 단계`.
- 달력은 보조 출력이다. 단계 전환일이 있는 경우만 월별 달력에 표시한다.

### 5.6 Decision / Comparison Flow

대표 예시:

- 중고차 구매 후보 비교
- 웨딩홀 후보 비교
- 이사 업체 견적 비교
- 보험/요금제 비교

사용자가 보는 핵심:

- 해야 할 체크와 비교해야 할 기준이 다르다.
- 결과물은 체크리스트보다 표에 가깝다.

사용자 입력:

- 후보 이름.
- 가격/점수/메모.
- 필수 조건 충족 여부.

가공 방식:

- 후보별 row를 만든다.
- 체크 항목은 column 또는 sub-checklist로 연결한다.
- 결정 기준을 통과/주의/탈락으로 시각화한다.

기본 화면:

- `비교표`, `체크리스트`, `메모`.
- 달력은 계약/방문/마감일이 있을 때만 쓴다.

## 6. 첫 화면 정보 구조

모든 Flow 상세 페이지는 첫 화면에서 다음 네 가지를 보여줘야 한다.

```text
1. 내가 뭘 따라하는지
2. 실제 해야 할 리스트
3. 내가 넣어야 할 기준값
4. 결과물이 어디로 나갈 수 있는지
```

권장 구조:

```text
[출처/채널 신호] [카테고리/타입 최소 배지]

# Flow 제목
한 줄 설명: 어떤 상황에서, 얼마 동안, 몇 개 항목을 실행하는지

[기준값 입력 또는 반복 주기 선택]

[실행 리스트 미리보기]
- 체크박스 항목 6~8개
- 섹션/날짜/반복 정보가 같이 보임
- "전체 N개 보기"로 이어짐

[출력 미리보기]
- 날짜형: 월별 달력 preview
- 루틴형: 반복 달력 preview + 다음 회차
- 체크리스트형: 엑셀/메모 preview
```

중요한 원칙:

- 메타 카드만 위에 많이 쌓지 않는다.
- 실제 항목 제목이 첫 화면에 보여야 한다.
- 월별 달력은 날짜/루틴 Flow의 핵심 가치이므로 제거하지 않는다.
- 달력은 날짜 입력 전에도 sample mode로 보여준다.
- 고급 설명은 리스트와 출력 미리보기보다 아래에 둔다.

## 7. 보기 체계

보기는 모든 Flow에 동일하게 강제하지 않는다. 콘텐츠 타입에 따라 필요한 보기만 제공한다.

| 보기 | Checklist | Timeline | Routine | Program | Phase | Decision |
| --- | --- | --- | --- | --- | --- | --- |
| 리스트 | 필수 | 필수 | 필수 | 필수 | 필수 | 보조 |
| 오늘/이번 주 | 선택 | 추천 | 필수 | 필수 | 선택 | 선택 |
| 월별 달력 | 선택 | 필수 | 필수 | 필수 | 조건부 | 조건부 |
| 비교표 | 조건부 | 조건부 | 불필요 | 조건부 | 불필요 | 필수 |
| 내보내기 preview | 필수 | 필수 | 필수 | 필수 | 필수 | 필수 |

### 7.1 리스트

리스트는 실행의 중심이다.

- 체크박스가 명확해야 한다.
- 제목, 날짜/반복, 완료 조건, 메모, 스킵이 분리되어야 한다.
- 항목이 많아도 전체 감각이 있어야 한다.

### 7.2 월별 달력

달력은 날짜 기반 Flow와 루틴 Flow의 핵심 출력이다.

- 날짜 입력 전: 예시 날짜로 preview.
- 날짜 입력 후: 사용자 날짜로 실제 표시.
- 루틴: 반복 occurrence를 표시.
- 여러 행동 루틴: 달력 칸에는 session 제목과 행동 개수를 표시하고, 클릭/확장 시 세부 행동을 보여준다.
- 너무 많은 항목은 `+3개`처럼 축약하고 agenda로 연결한다.

### 7.3 이번 주 / Agenda

Agenda는 "오늘 또는 이번 주에 뭘 해야 하지?"를 답한다.

- Timeline: 가까운 날짜순 항목.
- Routine: 다음 회차와 이번 주 반복 회차.
- Program: 이번 주 프로그램 세션.

### 7.4 Export Preview

내보내기는 버튼만 보여주면 안 된다. 결과물이 어떻게 생기는지 보여줘야 한다.

- 텍스트/메모 preview: 복사될 문장 일부.
- 엑셀 preview: column 5~7개와 row 3개 샘플.
- 캘린더 preview: 월별 달력 또는 ICS event 제목.
- 투두 preview: due date와 title 예시.

## 8. 입력값과 변환 규칙

### 8.1 공통 입력

| 입력 | 적용 타입 | 설명 |
| --- | --- | --- |
| 기준 날짜 | Timeline, Program, 일부 Phase | D-day 계산 기준 |
| 시작 날짜 | Routine, Program | 반복 시작일 |
| 반복 규칙 | Routine, Program | 매일, 매주 특정 요일, 주 N회, 매월 |
| 시간/소요 시간 | Routine, Scheduled Event, Time Block | 캘린더 export 품질 개선 |
| 상황 필터 | Checklist, Decision, Phase | 불필요한 항목 제거 또는 스킵 후보 |
| 체크/스킵/메모 | 모든 타입 | 개인 진행 상태 |

### 8.2 Sample Mode

입력 전에도 사용자는 결과물을 봐야 한다.

규칙:

- 입력 전에는 sample anchor 또는 sample start date를 사용한다.
- 화면 상단에 "예시로 보는 중"을 명확히 표시한다.
- 사용자가 기준값을 입력하면 sample data는 즉시 실제 data로 대체된다.
- sample mode에서도 리스트, 월별 달력, export preview는 보여준다.

### 8.3 Local Mode

로그인 전 단계에서는 이 브라우저에만 저장한다.

저장 대상:

- anchor date
- repeat rule
- checked item ids
- skipped item ids
- memo
- custom date/time adjustment
- last opened at

표시 문구:

```text
진행 상황은 이 브라우저에 자동 저장됩니다.
다른 기기에서 보려면 엑셀이나 텍스트로 백업하세요.
```

## 9. 내보내기 계약

FLOW는 전체 관리 앱이 아니라 사용자가 쓰는 도구로 잘 옮겨가는 실행 레이어다.

### 9.1 텍스트 / 메모

목적:

- 카카오톡, 메모장, Notion, 블로그 댓글, 개인 문서에 붙여넣기.

포맷:

```text
[Flow 제목]
기준: 2026-06-22 이사일

D-30 · 2026-05-23
- [ ] 이사 방식 정하기
  완료 조건: 포장이사/반포장이사/일반이사 중 하나로 결정
  메모: ...

출처: ...
```

### 9.2 엑셀 / Sheet

목적:

- 항목이 많거나 후보 비교, 진행 관리, 백업이 필요할 때.

기본 column:

```text
상태, 날짜, 요일, 섹션, 제목, 종류, 반복, 소요시간, 완료조건, 메모, 출처, 주의
```

Decision Flow 추가 column:

```text
후보명, 가격, 조건충족, 점수, 결정상태
```

### 9.3 캘린더

목적:

- 날짜 기반 항목, 반복 루틴, 시간 확보가 필요한 작업을 캘린더로 옮긴다.

이벤트 필드:

```text
title: [FLOW] 항목 제목
date: actualDate 또는 occurrenceDate
time: defaultTime 또는 userTime
duration: estimatedMinutes
description: 완료 조건, 메모, 원문 링크, 주의 문구
```

규칙:

- 모든 체크리스트 항목을 무조건 캘린더에 넣지 않는다.
- 날짜가 있는 항목, 반복 루틴, 사용자가 선택한 항목만 캘린더 대상이다.
- Stage 0에서는 ICS 또는 calendar text preview가 우선이다. Google Calendar API 직접 연동은 후순위다.

### 9.4 투두리스트

목적:

- Todoist, Microsoft To Do, Apple Reminders 같은 도구로 옮겨갈 수 있는 구조를 만든다.

필드:

```text
title, dueDate, notes, section, sourceUrl, priority optional
```

규칙:

- Routine은 모든 미래 회차를 너무 많이 만들지 않는다. 기본은 다음 7~14일 또는 선택 기간이다.
- 완료 기준과 원문 링크는 notes에 들어간다.

## 10. Demo 데이터와 통계 표시 원칙

데모 목적상 숫자가 필요한 경우는 있다. 하지만 public user-facing 화면에서 fake social proof처럼 보이면 신뢰를 잃는다.

원칙:

- 실제 사용 수가 아니면 `실행 1,201`, `복사 311`처럼 표시하지 않는다.
- 데모 발표용 화면에서는 `예시 지표`, `데모 데이터`라고 명시한다.
- 일반 랜딩/Flow 카드에서는 통계 대신 더 유용한 메타를 보여준다.

권장 메타:

```text
12개 항목
6개월 흐름
월별 달력으로 보기
엑셀/캘린더 내보내기 가능
베타 운영 중
```

## 11. 채널 탐색 원칙

채널별 탐색은 유지한다.

이유:

- 사용자는 주제뿐 아니라 "누가 만든 실행 가이드인지"로 신뢰를 판단한다.
- 외부 콘텐츠 유입과 내부 탐색 모두에서 제작자/채널 맥락이 중요하다.
- FLOW가 콘텐츠의 실행 레이어라면 원본 채널과의 연결이 제품 정체성에 포함된다.

단, 채널 페이지는 내부 운영 대시보드처럼 보이면 안 된다.

채널 카드 기본 정보:

```text
채널명
채널 유형: 공식 / 경험자 / 큐레이션
주요 주제
대표 Flow 3개
출처 확인 또는 베타 표시
```

표시하지 않을 것:

- 검증되지 않은 실행 수/복사 수
- 내부 점수처럼 보이는 실행성 점수
- 사용자가 의미를 모르는 `official`, `sample`, `score` 같은 영어 라벨

## 12. 검증용 대표 콘텐츠 세트

다음 Flow로 새 UX를 검증한다. 한 타입만 좋아 보이는지 확인하지 말고, 리스트/달력/루틴/표/출처가 모두 작동하는지 본다.

| Flow | 타입 | 검증 포인트 |
| --- | --- | --- |
| `moving-d30-basic` | Timeline | 기준 날짜 입력, 리스트, 월별 달력, 엑셀 export |
| `wedding-d180-basic` | Timeline + Decision | 장기 D-day, 예산/후보 비교, 재정 주의 |
| `overseas-travel-d14` | Timeline + Safety | 출국일 기준, 공식 확인, 여행 안전 주의 |
| `used-car-buying-check` | Checklist + Decision | 날짜 없는 체크리스트, 후보 비교, 현장 점검 |
| `running-5k-4week` | Program + Routine | 주차별 프로그램, 반복 일정, 운동 안전 |
| `daily-stretch-10min` | Routine | 한 가지 행동 반복, 월별 반복 표시 |
| `study-exam-d30-plan` | Timeline + Routine | 시험일 역산과 매일 공부 루틴 결합 |
| `baby-food-menu-recipe` | Phase + Meal Plan | 단계, 식단/레시피, 건강 민감 주의 |

각 Flow는 아래 질문에 답해야 한다.

- 첫 화면에서 실제 실행 리스트가 보이는가?
- 필요한 입력값이 무엇인지 바로 아는가?
- 입력 전에도 sample mode로 결과물을 이해할 수 있는가?
- 입력 후 리스트와 달력이 함께 업데이트되는가?
- 루틴은 반복 주기와 회차 구성이 보이는가?
- 캘린더/엑셀/메모/투두 중 어떤 출력으로 갈 수 있는지 보이는가?
- 출처와 주의 정보가 실행 항목과 구분되는가?

## 13. 수정 방향 우선순위

### P0: 제품 구조 복구

- Flow 상세 첫 화면에 실행 리스트 spine을 노출한다.
- Timeline과 Routine에서 월별 달력 preview를 복구한다.
- Routine repeat rule과 occurrence preview를 정의한다.
- 콘텐츠 타입별 view set을 분리한다.
- `/my`는 진행 중인 Flow를 우선 표시한다.
- 채널 탐색을 유지하되 일반 사용자용으로 정리한다.

### P1: 출력 기대감 강화

- 내보내기 버튼 옆에 결과물 preview를 붙인다.
- 엑셀 column, 캘린더 event, 텍스트 복사 예시를 각 Flow 타입에 맞춘다.
- sample mode와 actual mode를 명확히 구분한다.
- Program Flow에서 주차별 변화가 보이게 한다.

### P2: 제작자/콘텐츠 품질 시스템

- 제작자가 Flow를 만들 때 타입별 필수 필드를 입력하게 한다.
- 항목별 why/how/completion/source/risk가 없으면 상세 영역을 숨긴다.
- 루틴/프로그램/결정표 템플릿을 만든다.

## 14. 다음 와이어프레임 범위

기획서 다음 단계에서는 아래 5개 화면을 먼저 와이어프레임으로 만든다.

1. Timeline Flow 상세 첫 화면  
   - 예: 이사 D-30  
   - 리스트 spine + 기준 날짜 입력 + 월별 달력 preview

2. Routine Flow 상세 첫 화면  
   - 예: 매일 10분 스트레칭  
   - 반복 주기 선택 + 이번 주 회차 + 월별 반복 preview

3. Program Flow 상세 첫 화면  
   - 예: 5K 러닝 4주  
   - 주차별 계획 + 반복 가능 요일 + 세션별 행동 목록

4. Checklist / Decision Flow 상세 첫 화면  
   - 예: 중고차 구매 점검  
   - 긴 체크리스트 + 비교표 preview + 엑셀 export preview

5. 랜딩 / 채널 탐색 카드  
   - 카드에서 Flow 타입, 실행 리스트 감각, 출력 목적지가 보이도록 재설계

## 15. 구현 전 결정 사항

와이어프레임으로 들어가기 전에 다음 결정을 고정한다.

- 월별 캘린더는 Timeline/Routine/Program의 핵심 보기로 유지한다.
- 날짜 입력 전에도 sample mode로 달력과 리스트를 보여준다.
- Routine은 단일 행동 루틴과 다중 행동 루틴을 모두 지원한다.
- Flow 첫 화면에는 실제 항목 제목이 보여야 한다.
- 채널 탐색은 유지한다.
- fake 통계는 public 화면에서 social proof처럼 쓰지 않는다. 데모 지표가 필요하면 명시적으로 `예시 지표`라고 표시한다.

## 16. 성공 기준

새 UX는 아래 기준을 통과해야 한다.

- 사용자가 첫 화면에서 "이거 따라하면 되겠다"고 느낄 수 있다.
- 체크리스트형 Flow는 긴 리스트가 즉시 보인다.
- 날짜형 Flow는 기준 날짜 입력 전후의 차이를 달력에서 이해할 수 있다.
- 루틴형 Flow는 반복 주기와 반복 결과가 달력에 보인다.
- 프로그램형 Flow는 주차별/회차별 변화가 보인다.
- 내보내기는 버튼명이 아니라 결과물 preview로 이해된다.
- 원본 콘텐츠와 실행 항목, 출처/주의 정보가 섞이지 않는다.
- 로그인 없이도 진행 상태가 유지되고, 그 한계가 안내된다.
