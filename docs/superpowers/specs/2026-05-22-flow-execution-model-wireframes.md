# FLOW Execution Model Wireframes

> 작성일: 2026-05-22  
> 연결 문서: [FLOW Execution Model Redesign Spec](./2026-05-22-flow-execution-model-redesign.md)  
> 상태: 1차 low-fidelity wireframe  
> 목적: 구현 전 정보 구조, 첫 화면 구성, 리스트/달력/루틴/내보내기 preview 위치를 고정한다.

## 1. 공통 화면 원칙

모든 Flow 상세 화면의 첫 viewport는 아래 네 가지를 동시에 보여준다.

```text
1. 이 Flow가 무엇인지
2. 실제 실행 리스트가 있다는 것
3. 사용자가 넣어야 하는 기준값
4. 입력 결과가 달력/엑셀/메모/투두로 바뀐다는 것
```

공통 컴포넌트:

| 컴포넌트 | 역할 |
| --- | --- |
| Source Strip | 원본 콘텐츠/채널 신뢰 신호 |
| Flow Header | 제목, 짧은 설명, 기간/항목 수/출력 가능성 |
| Input Composer | 기준 날짜, 시작일, 반복 주기, 상황 필터 입력 |
| Execution Spine | 체크리스트처럼 보이는 실제 항목 목록 |
| Output Preview | 월별 달력, 엑셀 표, 메모 복사, 투두 preview |
| View Switcher | 타입별 필요한 보기만 노출 |
| Local Save Notice | 로그인 없이 이 브라우저에 저장된다는 안내 |

## 9. 와이어프레임 검수 기준

각 화면은 구현 전 다음 질문을 통과해야 한다.

- 첫 화면에서 실제 항목 제목이 보이는가?
- 날짜형/루틴형에서 월별 달력이 보이는가?
- 루틴에서 반복 주기와 한 회차의 행동 목록이 분리되어 보이는가?
- 내보내기 버튼을 누르기 전에도 결과물이 상상되는가?
- 채널/출처와 실행 항목이 섞이지 않는가?
- 모바일에서 첫 체크 항목까지 너무 오래 스크롤하지 않는가?
