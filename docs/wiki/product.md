# 제품 맥락 한 장

2026-10-30 · 기획 세션 초안 · 위키에 옮길 한 장이고, 진행판 7f(원칙·결정 문서 정본화, ★5)의 초안을 겸한다. 확정되면 7절을 `agent.md`와 `docs/PRODUCT_PRINCIPLES.md`에 반영한다. 계정 주소·ID·사용자 글 원문은 넣지 않았다. 총괄 반영(배포 규칙 문장을 10/30 결정으로 고침).

## 한 줄로

FlowMe는 개인 쓰기 공간이다. 할 일·일정·메모를 글로 적고 체크하고 저장하고 다시 연다. 필요하면 그 글을 Flow로 묶어 공개하거나, 남이 공개한 Flow를 가져다 쓰거나, 기존 도구로 내보낸다.

## 1. 처음 비전과 지금

사용자의 1월 메모(Notion, 비공개)의 요지는 이렇다. 경험을 남이 따라 할 수 있는 Flow로 만들고, 그 실행이 쌓이면 개인에게 어떤 경험이 가치 있고 어떻게 하면 잘할지 알려 준다. 기능 메모는 비슷한 Flow 안내, 모든 Flow를 늘어놓는 게시판형 대신 검색·개인 맞춤, 여러 체크 방식(단순 체크·메모·시간), 대충 쓰는 사람과 열심히 쓰는 사람을 함께 받는 쓰기를 적었다. 사업화·배포 아이디어와 메모 원문은 공개 문서에 옮기지 않았다.

| 비전 | 지금 Alpha |
| --- | --- |
| 경험을 따라 할 수 있는 Flow로 | 있음. 내 글을 Flow로 공개(판본·철회), 남의 Flow를 사본으로 가져와 실행, 고친 내용을 작성자에게 제안 |
| 실행이 데이터로 쌓임 | 일부. 체크·진행값·날짜가 계정에 저장된다. 쌓인 기록을 돌려주는 조언은 없다 |
| 개인 맞춤 조언·추천 | 없음. 관측 사용자가 0이라 근거 데이터도 없다 |
| 게시판형 피하기, 검색 중심 | 일부. Flow 찾기는 검색·분야·상황으로 찾고 인기 순위를 두지 않는다. 공급할 콘텐츠가 아직 거의 없다(공식 콘텐츠 준비 중) |
| 여러 체크 방식 | 일부. 체크, 진행값, 메모 줄, 시간, 반복 |
| 대충 쓰는 사람과 열심히 쓰는 사람 | 쓰기 A(목록 이어쓰기 + 명시 도구)가 이 둘을 같이 받으려는 설계다. 실폰 확인 전 |
| 저장할 때 가입 | 9/20 결정. Google 로그인 우선, 누구나 가입 |

## 3. 핵심 여정과 Alpha 원칙

핵심 여정은 쓰기 → 한글 입력 → 체크 → 저장 → 다시 열기다. Flow 가져오기·공개·둘러보기는 그 위에 얹는다.

1. 핵심 여정이 먼저다. 여정마다 눈으로 확인할 완료 기준을 1~3개 둔다. 요청하지 않은 리팩터링·추상화는 하지 않는다.
2. 자료를 잃지 않는다. 저장·재열기 무결성과 되돌릴 길을 먼저 본다. 자료 형식 변경과 기존 자료 이행은 따로 승인받는다.
3. 승인 경계를 지킨다. 운영 배포는 정해진 검사와 통합 QA를 통과하면 총괄이 판단하고 근거를 기록한다(10/30 결정). DB 변경, 새 권한, 실데이터 접근은 사용자 승인 대상이다.
4. 증거를 섞지 않는다. 구현, 내부 QA, 배포, 관측 사용자 증거를 따로 적는다.
5. 출처와 권리를 공개 전에 끝낸다. 출처, 제작자 경험, 사용자 수정, 주의 문구, 개인 실행 기록은 다른 층이다.
6. 지어내지 않는다. 원문에 없는 행동·날짜·완료 기준·결과를 만들지 않는다. 건강·법·돈·가족·자동차·안전 정보는 근거 없이 단정하지 않는다.
7. 가짜 신호를 쓰지 않는다. 가짜 사용자 수·평점·후기·순위는 없다. 설명 문장은 줄이고 첫 행동을 먼저 보인다.
8. 공개 저장소다. 계정 주소·ID·사용자 글을 문서·위키·커밋에 넣지 않는다.
9. 무료 범위 안에서 검증한다. 자동 읽기나 응답 크기를 바꾸는 변경은 전송량 영향을 같이 적는다.

## 6. 관측 사용자

- 지금 0명이다. Supabase의 월간 사용자 수(MAU 4)는 관측 사용자 수가 아니다.
- 검증으로 치는 것: 외부 사용자가 스스로 핵심 여정을 해 보는 모습을 관찰한 기록.
- 검증이 아닌 것: 합성 QA, 자동 시험, 배포 성공, 001·002 실계정 확인, 내부 리뷰, 데모와 화면 캡처.
- 경과: 7월 관찰 계획(P24, 5명 × 3회)은 막혔고, 7/14 사용자 판단으로 외부 모집을 보류했다. 10/29에는 지금 목표를 마친 뒤 피드백을 받기로 했다. 진행판의 다음 일로 "N1 반영 뒤 피드백 라운드·관측 사용자 계획"이 있다.
- 그래서 지금 문서의 '완료'는 모두 내부 기준이다. 사용자 가치가 확인됐다고 쓰지 않는다.
- 관찰을 시작하면 처음 물을 것: 첫 화면에서 무엇을 하는 서비스인지 바로 알 수 있는가. 예전 P0 앱 시험에서 사용자가 불편하다고 적은 점이다.

## 7. 원칙 정본화 초안 (7f)

**`PRODUCT_PRINCIPLES.md` 중심 문장 (안)**

- 'Stage 0 export-first' 절은 '경과'로 옮긴다. 내보내기는 지금도 여러 끝맺음 가운데 하나로 남긴다(10/26 인수).
- 'Long-Term Direction'은 9/06 큰 방향(개인 공간·공유 지식·참여)으로 바꾼다.
- UX 원칙 중 "첫 행동을 먼저", "층을 나눈다", "실제 사용 전에는 검증됐다고 하지 않는다"는 그대로 둔다.
