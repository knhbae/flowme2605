# K1-B 화면 평가

2026-09-05. 대상은 standalone Plan/Item/Quick 편집의 확인창·저장 실패·복구 화면이다. 전체 제품 UX나 실제 기기 평가가 아니다.

## 검사와 직접 평가를 구분

최종 브라우저 실행 (로컬 전용 근거: `../../../output/poc-gap-implementation/k1b/browser-journal-final.json`)은 19/19 PASS, 격리 context 27개다. B10의 확인/실패와 B14/B17의 prepared/confirmed 복구 화면을 각각 5개 크기로 검사했다. 최종 캡처는 43장이다. 자동 검사는 가로 넘침, 핵심 행동의 스크롤 후 노출·hit-test, 키보드 접근과 오류 로그를 확인한다.

주 작업자는 확인창 5장·저장 실패 5장·prepared gate 5장을 `k1b-journal-current`에서, confirmed gate 5장을 `k1b-journal-final`에서 직접 열어 평가했다. 총 20개의 화면이며 43장 전체를 직접 평가했다고 주장하지 않는다. 두 실행 사이 제품 변경은 메모리 Map 초기화 표현과 history 완료 후 초점 복귀다. 레이아웃/CSS 변경은 없다. 전 실행의 1건 간헐 초점 실패는 최종 실행에서 실제 native Back을 100ms 늦춘 순서 회귀까지 포함해 통과했다.

전체 페이지 캡처에서 native dialog의 배경 막은 당시 viewport 높이만 덮는다. viewport 바깥까지 보이는 긴 캡처를 실제 화면 전체가 동시에 노출된 것으로 해석하지 않는다. 가로 탐색의 일부 항목이 스크롤 영역 끝에서 잘리는 모습도 문서 전체의 가로 넘침과 구분한다.

## 동작으로 확인한 범위

- dirty 확인은 자식 Item 변경과 부모 Plan 전체 변경의 손실 범위를 구분한다. 첫 초점은 계속 편집이며 Escape는 확인 상태만 해제한다.
- 계속 편집에서 같은 편집 DOM, textarea selection과 control scroll을 복구했다. 이것은 OS 가상키보드/IME 스크롤 검사가 아니다.
- 실제 Chromium HTTP/file의 `page.goBack()`을 확인했다. Android 시스템 Back, iOS 제스처, 주소 이동·탭 종료 보호를 검사했다고 쓰지 않는다.
- backdrop의 경우 native dialog가 그대로 열려 있으면 명시적인 계속 편집으로 복귀하도록 시험했다. 모든 backdrop 클릭이 자동 취소한다는 판정은 하지 않는다.
- prepared는 이전 상태 복구 후 미저장 초안으로 이어가고, confirmed는 저장된 내용을 롤백하지 않고 복구 기록만 정리한다. 둘 다 열기만으로 자동 저장·삭제하지 않는다.

실제 Android Chrome·iOS Safari·TalkBack/VoiceOver·OS IME는 **NOT_RUN**, 관찰 사용자 **0명**이다. K1-B의 기능 통과와 위 시각 잔여를 함께 다음 단계에 넘긴다.
