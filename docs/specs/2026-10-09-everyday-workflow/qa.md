# 검증 원장

시작 상태: 기존 행 메뉴의 로컬139검사/48브라우저 판정은 이전 코드의 근거다. 새 변화의 PASS로 복사하지 않는다. 현재 source와 직접 관계가 있는 검사만 시작하고 게시 시 정상 필수 hook/CI를 유지한다.

가상 데이터의 실제 브라우저 조작/합성 메모리 저장소/실제 서버 저장/실물폰/OS IME/관찰 사용자 검증을 구분한다. 실패 원자료는 보존한다. 실계정 ID·원문·계정·인증정보는 출력/공개하지 않는다.

관련 단계의 실제 결과는 아래와 같다. `output/playwright/everyday-workflow/`는 로컬 비공개 실행 근거이며 공개 후보에 포함하지 않는다.

## A — 작성 연속성

동일 가상 자료의 데스크톱1440/390px에서 폴더 선택 전에는 커서가 이름 앞에 남았다. 연결 성공 후 실제 연결 줄 끝으로 돌아가 다음 입력을 이어 쓰도록 수정했다. 저장 대기 중 새 키/포인터/포커스/입력/조합 동작이 있으면 그 동작을 우선하고 포커스를 다시 빼앗지 않는다. 저장 거절·편집기 교체에도 복귀하지 않는다.

일반 TXT 복붙은 문자·들여쓰기·명시 날짜/메모를 복사하지만 폴더 연결/진행 이력을 옮기는 작업이 아니다. 기존 하위 묶음 이동은 같은 Item·연결·기록을 보존한다. 기록 있는 원문 잘라내기는 기존 보호로 거절된다. 원본 앞의 동일 블록 복붙은 텍스트만으로 어느 블록이 원본인지 구별할 수 없는 한계가 있다. 새 정책이나 자동 연결 추론은 넣지 않았다.

초기 수정판의 TXT 전환은 짧은 글 약26~27ms,120행 약21~22ms였다. 지연을 재현하지 못해 성능 도구나 편집 엔진을 바꾸지 않았다. 이 수치는 해당 시험일 뿐 모든 문서의 상한이 아니다.

## B — 범위와 편집 대상

다른 글에 기존 분류의 내용이 없으면 그 빈 범위만 해제한다. 같은 글의 의도한 범위와 다른 글에 실제 있는 범위는 유지한다. 범위를 바꾸기 전에 열린 모든 편집기의 입력을 저장하며 실패/조합 중이면 기존 글·범위·입력을 유지한다. 외부 경로의 연속 이동은 최신 요청을 놓치지 않도록 순서대로 처리한다.

현재 글과 분류 경로/하위 분류 포함을 함께 표시하고 전체 문서 확인 동작을 유지한다. 제작 초안 복제 후에는 현재 원본인지 명시하고 정확한 새 사본을 여는 버튼을 제공한다. 기존 미저장 원문 보호 경로를 재사용한다.

실제 Chrome/가상 메모리 저장소의 현재 판본 B34판정은 통과했다. 저장 실패 세부 캡처는 같은 사례의 추가 확인이며 고유 판정 수에 더하지 않는다. 실제 서버 저장 성공으로 부르지 않는다.

## C — 현재 Alpha 실제 사용

현재 Alpha 기준판에서 접근 가능한 기존 자체작성 가상4항목 자료를 골랐다. 기존 원본은 읽기만 하고, 명시적으로 제작 시험 사본을 만들고 저장한 뒤 개인 계획으로 인계했다. 개인 날짜·메모·완료는 서버 저장 표시, 새로고침, 정상 서버 재확인, 새 접속에서 같은 문서/본문으로 유지됐다.

제작 사본을 다시 저장해도 기존 개인 계획의 날짜·메모·진행이 자동 변경되지 않았다. 별도 명시 시험 사본에서 시작한 새 계획은 수정된 제작 내용과 초기 미완료/빈 개인 메모를 받았다. 재방문은 기존 플랜을 열며 불필요한 사본을 만들지 않았다. 원본의 저장 판본1·본문을 최종 대조했다. 의도적으로 만든 비교용 시험 사본2개와 자동 추가 사본0을 구분한다.

날짜 입력란의 두 시도는 저장 결과가 바뀌지 않아 성공으로 세지 않았다. 기존 오늘로 이동 동작으로 날짜 저장은 확인했다. 로딩 중/보이지 않는 보존 편집기/기본 경로 URL을 사용한 초기 판정은 원장에 보존하고 표시된 편집기·같은 문서로 다시 대조했다. 이를 제품 실패 수나 통과 수로 합산하지 않는다.

설명·링크·하위 항목을 함께 갖춘 허용된 기존 자료는 확보하지 못했으므로 그 형식은 미실행이다. 다른 자료를 임의로 기존 자료라 만들지 않았다. 실물폰, OS 한글 입력기, 설명 없는 실제 사용자 이해도, 이번 새 UX의 Alpha 제공은 이 단계에서 미실행이다.

## 통합 판정

마지막 편집기 수정 뒤 표적83 PASS/0FAIL/0SKIP. 모델/저장 계약·DB/Auth/schema 변경0. 타입/빌드/게시/CI/Alpha는 정확 판본에 별도 연결하며 이전 빌드/CI를 새 성공으로 복사하지 않는다. 초기 실패와 각각의 독립 검토는 로컬 원장에 보존한다.
