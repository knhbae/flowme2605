# 단계별 실행 계획

| 단계 | 기획·UX/설계 | 구현·검증 |
| --- | --- | --- |
| 1 기준선 | 방향·26항목·중간 보완·반영/후보 구분 | 소유·보호 hash와 요구 대조 |
| 2 폴더 | 같은 줄/바로 아래/묶음 뒤/폴더 안의 실제 위치 | 읽기 전용 preview·stale snapshot·동일 transition |
| 3 작성 | 내용/빈 Enter·메모·속성/자식·부분/전체 | 누락 조합 회귀·발견한 계약 위반만 보완 |
| 4 날짜 | 오늘/지난 미완료·현재 출처·미결 선택 구분 | 표현 레이어·같은 Item·독립 조작 HTML |
| 5 통합 | 폴더/문서/기간·실패·취소·Undo/reload | 표적→동결→npm/통합/타입/사본 build→5크기 앱 |
| 6 평가 | UX 감산·발견성·요구 충족/후속 | HTML 시각·키보드·보고·closeout |

root는 ProgramTextEditor 통합·공통 스타일·문서/HTML·전체 검증을 소유한다. 폴더 담당은 신규 preview/helper tests, 날짜 담당은 ProgramSpace 표현·신규 helper/표적, 작성 담당은 신규 회귀 파일만 소유한다. 검증 중 source drift가 있으면 최종 판정으로 쓰지 않는다. 기존 시험은 이번 실행 수로 계산하지 않는다.

브라우저는 loopback 전용 합성 QA 서버에서 실행하며 제공 주소를 변경하지 않는다. 앱 사본 build는 명시 소유 입력만 복사하고 실제 제공 중 자산·credentials·외부 pack은 복사하지 않는다. 디자인은 기존 앱/HTML의 토큰과 레이아웃을 유지하는 좁은 수정으로 이미지 생성·Figma·전면 재디자인을 하지 않는다.
