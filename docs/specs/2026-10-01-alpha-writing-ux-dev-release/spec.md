# 작성 UX 세 후보의 개발계 반영

2026-10-01. 사용자가 다음 목표의 등록·실행을 승인했다. [방향 점검](../2026-10-01-direction-and-next-goal/spec.md)의 개인 텍스트 관리·공유 경험/지식·선택적 기여와 v4.1·개발1·개발2 연결을 유지한다. 지금은 UX/사용성 개선을 실제 개발계에서 확인할 수 있게 하는 단계이며 사용자 관찰 시험은 보류한다.

## 범위

- [작성 여정](../2026-10-01-alpha-ux-journey/spec.md), [폴더 작성](../2026-10-01-alpha-folder-writing-ux/spec.md), [작성 입력](../2026-10-01-alpha-writing-interactions/spec.md)의 같은 채팅 소유 변경을 하나의 후보로 반영한다. 기존 개발계 호스트 호환 코드 `1eb9be68`는 기반 의존성으로 보존한다.
- 모바일 목록에서 작성란으로 접근하는 좁은 보완은 지원/원문/입력 보호 범위에서 검토한다. 새 집중 모드·상시 안내·영구 폴더 정책을 추가하지 않으며 작은 보완이 커지면 별도 후속으로 남긴다.
- 정확한 공개 파일·private source/증거 경계를 확인하고 commit·push·검토용 Draft PR·CI를 진행한다. main 병합은 제외한다.
- 기존 `alpha.wikiplans.com` Tunnel의 `127.0.0.1:3105` 앱만 교체한다. 현재 앱/build·설정이 복귀 기준이며 이전 runbook에 남은 더 오래된 build를 최신 복귀본으로 가정하지 않는다.

## 경계

DB·Auth·실제 계정/개인 데이터·Tunnel/DNS·유료 서비스·Render/Vercel/Production 배포·새5D 활성화·운영 migration·관찰 사용자 시험·다른 worktree의 dirty 파일 수정/정리/게시를 제외한다. 원래 `/my`·운영 key/schema와 source/Item/lineId/숨은 bytes·IME·Undo·CAS/receipt를 유지한다.

정본 설계·코드·테스트·검증 요약만 Git에 게시한다. `output/`의 원시 JSON/로그/PNG/trace, `.tmp` 설정·실계정·비공개 catalog 원문은 로컬에 보존하고 게시하지 않는다. 기존 catalog는 명시 파일을 읽기만 한다.

## 완료 조건

1. 세 후보의 요구/소유 연결과 새 모바일 delta를 분리해 공개 manifest가 확인된다.
2. 고정 소스의 보안·출처·기본/통합·타입·build·관련 브라우저 검사와 해당 게시 commit의 CI가 통과한다. 실패/중단 이력은 따로 보존한다.
3. 이전 앱/build·설정 hash와 프로세스 소유가 확인되고 복귀 절차가 준비된 뒤 앱만 교체한다.
4. 외부 HTTPS 보호 응답·로컬/배포 정적 자산 hash·다섯 viewport의 합성 핵심 동선이 통과한다. 실제 Auth/DB를 합성 검사 결과로 승격하지 않는다.
5. 구현·게시·개발계 반영·실기기 미실행·후속을 분리해 보고한다. 전체 UX나 모든 피드백/제품 요구의 완료를 주장하지 않는다.

일정: 다른 Creator/Flow Map/공개·커뮤니티/5D 후속을 기다리지 않고 이 목표 안에서 개발계 반영까지 진행한다. 배포 차단 결함 또는 새 권한이 발견되면 그 조건만 명시한다.
