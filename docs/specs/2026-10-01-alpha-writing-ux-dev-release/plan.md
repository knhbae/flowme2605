# 단계 계획

| 단계 | 실행 | 판정 |
| --- | --- | --- |
| 1 기준·소유 | 현재 Git/remote main·세 후보·현재 앱/build·게시 자동 배포 연결 확인 | 소유 manifest, 미소유/비공개 제외, 이전 통과와 이번 실행 분리 |
| 2 좁은 모바일 보완 | 목록 선택→작성 접근의 임시 UI/focus 계약 검토, 필요한 최소 구현·독립 검토 | IME/pending 거절은 이동0, 원문·Item·쓰기 경계 유지. 전면 UX 정책 제외 |
| 3 고정 후보 검사 | 보안/출처·순수/컴포넌트·npm/통합·타입/build·다섯 크기 관련 브라우저 | 실제 실행 수·hash·실패 이력, 실계정 전달0·범위 밖 저장0 |
| 4 게시·CI | 정확한 파일만 commit/push, stacked Draft PR, 현 commit 비공개 CI 포함 | main/서비스 자동 배포 없음, 전체 required jobs 판정. CI-only 결함은 별도 기록 후 보완 |
| 5 개발계 교체 | 현재3105 소유·설정·이전 build 재대조, 후보 앱 교체·readonly 외부/합성 자산 검사 | 실패 시 현재 이전 build로 복귀. DB/Auth/Tunnel/원본 변경0 |
| 6 마감 | 정본·짧은 HTML 보고·실기기/관찰/게시 상태·잔여 | 사용자에게 같은 주소의 반영 판본을 안내 |

검사와 게시 중 source가 바뀌면 해당 근거를 최종 통과로 사용하지 않는다. 파일이 다른 작업과 겹치면 hunk 소유를 확인하고 범위를 분리한다. 변경 없는 기존 검사를 매 단계 중복 실행하지 않으며 hooks/CI의 실제 필수 검사는 유지한다.
