# 개별 Flow 가져오기

## 목표와 승인 범위

전체 비공개 자료실을 저장하지 않아도 열람한 Flow 하나를 명시적으로 제작 사본으로 가져온다. 기존 `AlphaCatalogCopyActions`와 정상 인증된 creator 저장 경로를 재사용한다. 전체 자료실 보관은 별도 선택 동작으로 남긴다.

기준은 b785d08843530e0c4f72baa0654f4398172f51ec이다. 별도 깨끗한 후보에서 구현·표적 검사·정상 게시/Draft PR·정확 CI·필요 Alpha 적용을 진행한다. DB allowlist 보완은 이미 별도 완료됐으므로 재실행하지 않는다. 성능 후보와 기존 작업트리는 포함하지 않는다.

## 유지 조건

- 열람만으로 저장하지 않는다. 개별 가져오기는 source/version locator와 명시 확인을 사용한다.
- 기존 정확 판본 사본은 다시 열며 중복 생성하지 않는다. 보관된 사본, 미확인 출처, 원본 대조 불일치의 거절은 유지한다.
- 기존 작성 중 입력·개인 계획·날짜·메모·진행·출처는 덮어쓰지 않는다.
- 전체 자료실 보관, 공개 발행, 개인 실행 계획 시작은 서로 다른 동작이다.
- 인증·권한·DB·운영 guard/TTL·관리 방식은 변경하지 않는다.

## 순서

1. 자료실의 stored 의존성만 분리하고 전체 보관을 접힌 선택으로 둔다.
2. 미저장 자료실의 단일 가져오기·정상 서버 명령·실패/중복 보호를 표적 검사한다. 데스크톱/390px 합성 브라우저에서 실제 UI 경로를 확인한다.
3. 정상 훅·새 Draft PR/CI를 확인한 뒤 기존 절차로 정확 후보를 Alpha에 반영한다. 전환 영향과 복구 대상은 실행 전에 별도 확인한다.
4. 허용된 정상 시험 세션에서 검토 완료 대상만 필요한 만큼 등록/재사용하고 대표 계획의 날짜·반복·메모·진행·재접속을 확인한다. 개인 값은 공개 근거에 넣지 않는다.

## 검증과 미완료 구분

자료실/복사 UI, creator controller, 기존 import 회귀와 타입/build 및 실제 렌더를 확인한다. 합성 저장소 성공을 실제 서버 저장으로 표현하지 않는다. 게시·CI·제공판·실계정 재접속은 각각 실제 근거가 생긴 뒤 기록한다. 사용자 이해도·실물폰·OS 입력기는 자동화로 검증했다고 하지 않는다.
