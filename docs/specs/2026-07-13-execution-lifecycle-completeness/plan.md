# Plan

## Phase 0 - Baseline

- Classify the existing dirty worktree by owner and scope.
- Confirm the current Vercel observation build points to the intended commit.
- Freeze representative fixtures for six Flow shapes.

## Phase 1 - P23-00 Audit

- Build capability, state-transition, and export-projection matrices.
- Simulate the full lifecycle at 390px and 1024px.
- Separate absent behavior from hidden behavior and inconsistent behavior.
- Rank findings Blocking, High, Medium, or Low.

## Phase 2 - Conditional Product Slices

1. P23-01 reversible execution state and optional scheduling.
2. P23-02 personal task add/delete/reorder and recovery.
3. P23-03 effective-model export parity.
4. P23-04 history and reuse detail.

Only open a slice when Phase 1 provides a concrete user problem, data owner, acceptance test, and migration boundary.

## Phase 3 - Observed Use

- Deploy one frozen build.
- Run five participants through three sessions each.
- Record task depth, confusion, failure, recovery, export use, and return reason.
- Re-test any Blocking or High correction with the matching participant type.

## Phase 4 - Product Fork

Choose one next investment from observed evidence:

- account-backed persistence,
- creator/update pilot,
- production URL/AI backend,
- or continued execution-model refinement.
