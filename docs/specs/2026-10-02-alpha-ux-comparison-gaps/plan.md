# 단계 계획

## 1. 기준·요구 대조

- 현재 개발계 d1cc 판본과 새 clean 작업본을 구별한다. session-start 실행과 초기 diff0을 확인한다.
- 원본 26피드백의 중간 정정/보충을 포함해 읽고 세 산출물의 관련 요구를 매칭한다.
- UX2 네 시안은 코드·모형 비교와 실제 렌더를 구분한다. 차단된 file: 요청을 우회하지 않는다.
- 외부 UX2에 새 QA/기존 캡처가 생기면 다시 읽고 기본 진입·탭 밀도·탐색 구조·Today/기록/제안/출력/복구의 제품 차이를 명시한다. 외부 모형 검사와 이 세션의 제품/새 HTML 검사를 합산하지 않는다.
- 외부 정적 보고서는 원본 해시·코드 경로와 현재 제품의 대응 화면을 대조한다. 이번 수신5건의 묶음별 보완·재검사 후보는 [수신 대조](../../content-audit/2026-10-03-flowme-ux2-static-review-followup-ko.md#보완-후보와-재검사-계획)에 둔다. 원본 수정 승인이나 실제 클릭 PASS로 취급하지 않으며 다음 UX-N1 우선 범위는 유지한다.

## 2. 개선 범위 선택

- 첫 행동·대상·원본/사본·완료 신호·돌아갈 곳·실패 복귀를 같은 기준으로 검토한다.
- 현재 `내 공간 / 둘러보기 / 내 활동`을 유지한 조합안을 제안한다. 네 시안 중 하나를 제품 전체에 무조건 덮지 않는다.
- 날짜 이동/복제/반복, 메모 귀속, 예정일/마감일은 별도 결정표로 남긴다.
- 서버가 명확히 쓰지 않았다고 확인한 일반 social 거절→수정→재저장부터 좁게 구현한다.

## 3. 구현

- 실제 client/controller 미지원 경로를 실패 테스트로 재현한다.
- 세션 내 거절 증거, 동일 actor·baseline·target·revision·intent 경계를 보존한다.
- unknown/malformed/network/재전송·다른 세션/대상/기준값은 재시도 후보가 아니다.
- UI 실패 문구와 기존 입력 보호/서버 재확인을 같은 snapshot 계약에 연결한다. 필요 없는 추가 설명·버튼은 만들지 않는다.
- Dots 자유 편집 대조에서 확인한 독립 등록 하위 항목은 해당 행 메뉴에서만 현재 등록·기록 유지 사실을 표시한다. 기간 목록 노출을 보장하거나 등록 해제·Undo·새 parser 정책을 추가하지 않는다. 메뉴 열기·닫기·Escape는 무저장이며 신규 하위 체크·참조·다른 행에는 표시하지 않는다.

## 4. 내부 검증

- 신규 표적·관련 private/native/social 회귀·npm test·타입·production build.
- 실제 HTTP 제품 번들 + 합성 Auth/API로 대표 작성·재사용·기여와 거절 복귀를 조작한다. 실제 계정/DB 요청은 0이어야 한다.
- 재개 시 HTTP200·build ID만으로 로그인 가능을 판정하지 않는다. 기존 `verifyFeedbackServerHtml`과 같은 합성 공개 키·개발계 활성화 검사를 beforeAll에 적용하고, candidate label은 local3107에만 묶는다. 실제 receipt lookup은 비어 있지 않아야 한다.
- 390×844, 375×812, 844×390, 1024×768, 1440×900. overflow·가림·오류·키보드와 취소/같은 위치/unknown ACK를 구분한다.
- 독립 감사의 보강: UC1은 신규 할 일→일정/완료→원문 행 복귀, UC2는 이전 판본 선택/출력 후 무저장 종료까지 포함한다. Dots R05의 검색 교차·필터 해제·구획 상속/개별 예외·미정 시간 보존을 UC6로 추가해 최종 후보는6경로×5크기30개다. 기존 판본의 보강 검사는 후보 검사와 구분한다.
- 브라우저가 거절한 로컬 HTML은 NOT_RUN으로 남기고 정적/모형 검사는 별도 집계한다.

## 5. 결과와 후속

- 조작 HTML·요구 대조·실제 결과·선별 후속을 제공한다. HTML은 모형이며 앱 저장/DB 증거가 아니다.
- 다음 UX 업무의 정본은 [UX-N1 초안 복구 화면](results.md#다음-ux-개선-범위--초안-복구-화면)이다. 대상·6상태·유지/제외·산출물·완료 기준을 고정하며 다음 배치안/구현을 이번 완료 근거로 앞당기지 않는다.
- 새 정책 제안과 구현한 결함을 구별한다. 기존 개발계는 그대로 둔다.
- 승인된 필수 화면 QA가 미완료이면 목표는 active 유지, 같은 차단이 세 목표 turn 동안 반복되고 더 이상 안전한 진전이 없을 때만 blocked로 처리한다. 10/3 사용자가 제외한 독립 HTML2건은 NOT_RUN 후속이며 이번 목표를 차단하지 않는다. 나머지 완료 조건과 저장·운영 경계는 유지한다. [수정 정본](spec.md#103-승인된-완료-범위-수정)을 따른다.
