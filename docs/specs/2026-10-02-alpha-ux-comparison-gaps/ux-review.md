# UX 비교 검토 — 목적별 동선과 감산

2026-10-02. 현재 제품 baseline `d1cc8dd1`, 최신 원본 피드백26개, UX2 네 디자인 시안을 [대표 요구 18군](requirements.md)으로 대조했다. 코드/설계 검토에 후속 원본의 기존 캡처 검토를 추가했다. 제품 구현·이 세션의 새 시안 브라우저 검사·사용자 선호 조사와 구분한다.

검토에는 이 작업본의 [flow-ux-review](../../../.agents/skills/flow-ux-review/SKILL.md)와 [quality rubric](../../flow-rules/quality-rubric.md)·[quality gate](../../flow-rules/quality-gate.md)·[ux-copy](../../flow-rules/ux-copy.md)를 적용했다. 다음 행동·필요 상태·오류 방지·복구를 바꾸지 않는 UI부터 줄이는 기준이다. 숫자 점수/평균/사용자 등급을 부여하지 않는다.

후속 정적 근거 `FLOWME-STATIC-REVIEW-20261002-1821UTC`는 [별도 대조](../../content-audit/2026-10-03-flowme-ux2-static-review-followup-ko.md)에서 다룬다. portable 네 시안의 입력·초점·좁은 화면 진입·줄바꿈·선택 상태5건을 현재 제품에 하나씩 매칭했다. 원본 공통 문제의 실제 클릭 재현은 미실행이고, 제품에 같은 결함이 있다고 확대하지 않는다. 이 검토로 UX-N1 우선 범위를 바꾸지 않았다.

## Findings

1. **High — 날짜·메모 의미의 미결을 인터페이스로 확정할 위험.** 현재 구획/개별 날짜 출처 표시와 반복 메모 속성 이어쓰기는 지원하지만 구획 이동·미정·공통/회차 메모·독립 due는 아직 같은 상태가 아니다. 시안의 조작을 곧바로 제품 규칙으로 옮기면 같은 Item의 기록/원문 문맥을 바꿀 수 있다. C03/C09~C11과 PC01~PC04를 먼저 비교한다.
2. **High — 부분 보기와 전체 보기의 권한을 같게 보일 위험.** 같은 native 편집기를 재사용해도 부분 구조 변경·다중 identity 치환은 보호 제한이다. 부분 보기마다 편집기를 추가하거나 숨은 원문을 조각으로 저장하면 데이터 의미가 달라진다. 현재 전체 작성 인계·입력 보존을 유지하며 지원 범위만 필요한 때 표시한다. C02/C04.
3. **High — 공개 없음과 비공개 기존 자료를 섞을 위험.** 기존 콘텐츠의 보존/열람·제작 사본과 공개 목록은 owner/자격이 다르다. 기대한 Flow가 안 보인 #7은 실제 slug/상태/필터 미확인이다. 모형 목록을 잘 렌더하거나 공개 개수를 늘려 해결로 표시할 수 없다. C14/F7/F8.
4. **High — 네 시안의 단순 모형으로 제품 입력을 대체할 위험.** 시안의 같은 ID·진행·사본·Undo 로직은 비교 도구다. 기존 v11/native parser·입력/저장 Undo·source identity·Auth/권한과 동등하지 않다. A의 문서형 표현을 선택해도 전체 기능은 실제 컴포넌트에서 유지해야 한다. C01~C04/C13/C16.
5. **Medium — 첫 화면의 목적을 모든 화면의 공통 대시보드로 확장할 위험.** A는 문서, B는 질문/경험, C는 오늘, D는 주제/단계에서 시작한다. 네 시작 객체를 한 화면에 모두 올리면 사용자 목적보다 카드와 이동이 앞선다. 목적 전환은 `내 공간 / 둘러보기 / 내 활동`에서 가능하게 두고 각 화면에서는 현 작업의 다음 행동만 앞세운다.
6. **Medium — 폴더·날짜·시간의 설명을 반복할 위험.** 현재 경로·대상 제목·적용 날짜·연결 위치 preview가 있다. 같은 사실을 제목/보조문구/상태 배지로 반복해도 #4/5/9/11의 발견성이 입증되지는 않는다. 문서 보관 위치·Item 소속·조회 범위처럼 결과가 다른 정보는 남기고 나머지는 감산 후보로 둔다. C05~C09/C18.
7. **High — 저장 거절의 재시도 범위를 넓혀 보일 위험.** native 최초 인계의 limit retry는 이미 좁게 보완됐지만 일반 social controller 직접 retry는 후속이다. unknown ACK는 동일 ID/payload 확인이며 자동 새 게시와 다르다. 모형 ‘재시도’ 버튼이나 component 수락 mock을 모든 social 재저장 성공으로 표현하지 않는다. C16.
8. **Medium — 제한된 시안 캡처를 반응형 완성으로 표시할 위험.** 최초 검토에는 CSS 선언만 있었다. 후속 UX2 QA의 네 안×3크기와 기존 캡처를 읽었지만 이 세션의 독립 DOM/겹침/초점 검사·모바일 키보드 증거가 생긴 것은 아니다. 정책 차단된 `file:` 접근을 다른 주소·설정·렌더 도구로 우회하지 않는다. 현재 HTTP 제품 앱 검사는 시안 렌더의 대체가 아니다. C18.

## Rubric

Finding7의 좁은 후속으로 이번에는 참여 초안 저장만 구현했다. 명확한 거절에는 잘못된 외부 변경 안내를 숨기고 현 입력의 수정/재보관을 안내한다. pending·외부 변경·실제 conflict 보호는 유지한다. 일반 social 전체 재시도·공개/제안까지 해결했다는 뜻이 아니며 [후보 검증](qa.md)은 아직 별도로 진행한다.

## 증거와 소유 경계

### 새 자유 편집 사례의 우선 UX 갭

[Dots FE01~FE06](dots-review.md#추가-자유-편집-피드백--fe01fe06)을 같은 문서의 메모·들여쓰기·기간 왕복에 연결했다. 원v11 계약/현재 코드와9개 메모리 진단은 독립 등록 후 하위 복원에도 일정 노출이 유지되는 경로와 중간 저장 전후 차이를 설명한다. 이것은 원문이 같으므로 전체 state도 같아야 한다는 새 계약의 채택이나 데이터 손상 확정이 아니다. 현 UI는 `subcheck` 외형과 `isCanonical` 상태를 별도로 갖지만 날짜/소속 차이가 없는 줄에는 독립 등록 표시가 없다.

추천하는 첫 비교는 해당 줄에서만 별도 할 일 등록 상태와 되돌릴 대상을 찾게 하는 안이다. 후속 격리 구현에서는 등록된 구조상 하위 원줄의 기존 메뉴에만 등록/기록 유지 설명을 추가했다. 모든 줄의 badge·상시 도움말·새 확인창·해제 버튼은 늘리지 않았다. ‘기간 목록 표시’는 실제 제외 조건과 맞지 않아 약속하지 않는다. 새 canonical 해제·완료 초기화·이력 복제·메모 문법 변경은 PC01/PC03 선택 뒤 별도 구현한다. 당시 컴포넌트4/4·전체58/58 이후r4의 실제 메뉴다섯크기를 확인했으며 Tab순환FAIL과 어절/밀도 문제를 구별했다. 수정후64/64는 브라우저재검사 성공을 대신하지 않는다. 실제clipboard·저장경계별 앱Undo/reload는9진단과메뉴검사에 포함되지 않았으며 기존UC1/UC2/UC6 PASS로 대체하지 않는다.

이번 문서 담당자의 편집은 `requirements.md`와 이 `ux-review.md` 두 파일뿐이다. 현재 코드/검사와 로컬 전용 원본26·UX2 정본·외부 후속 원장을 읽었다. 원본 `flow-mvp`의 dirty/untracked·UX2 시안·제품 코드·설정·서버·계정/DB/Auth는 변경·복사하지 않았다. `file:` 브라우저 정책 차단을 우회하거나 렌더 도구로 대체하지 않았다.

이 문서의 최초 담당자는 새 앱/HTML/브라우저/실기기·사용자 점수·fidelity 수치·관찰 사용자 증거를 만들지 않았다. 후속으로 주 담당자가 UX2의 현재 QA/source·기존18캡처를 직접 읽고 시안별 제품 차이만 추가했다. 원본26 정본 hash와 대표18군의 파일 연결을 유지하며 실제 검사·명령·결과·누락은 [QA](qa.md)에서 구분한다. 이 문서 보완에서 테스트/빌드·Git 게시·개발계 교체·외부 쓰기는 실행하지 않았다.
