## 목적과 현재 위치

v4.1 개인 관리, 개발1 공개 콘텐츠·재사용·선택적 기여, 개발2 원문 작성을 한 제품으로 연결한다. 개인 텍스트 계획, 공유 경험·지식, 선택적 커뮤니티의 세 목적을 유지하며 계정 모드나 강제 순서를 새로 만들지 않는다. 이번에는 UX2 네 시안·현재 앱·최신 피드백을 대조하고 정책 변경이 필요 없는 좁은 갭을 구현한다.

기준은 현재 개발계 소스 `d1cc8dd1cbc1a220054f458aea369393642f71ed`다. 제공 중인 `flow-two-ux-dev-release-20261002`는 동결하고, clean Git worktree `flow-ux-comparison-gaps-20261002` / `agent/ux-comparison-gaps-20261002`에서만 수정한다. 원본 `flow-mvp`와 UX2 작업본의 dirty/untracked 변경은 읽기만 한다. 미소유 파일을 복사·stage·게시하지 않는다.

직전 개발계 반영 완료 근거는 로컬 전용 `D:/flowme2605/flow-two-ux-dev-release-closeout-20261002/docs/specs/2026-10-02-alpha-two-ux-dev-release/qa.md`다. 이 작업본에 상속된 이전 STATUS와 results의 ‘미반영’ 표현은 해당 시점의 기록이다.

## 범위

- 개인 작성→같은 Item의 기간 실행.
- 공개 Flow 찾기→선택 판본→개인 사본→실행. 외부 출력만 하고 종료도 허용한다.
- Flow 없는 질문을 포함한 선택적 기여→명확한 저장 거절→입력 수정·재저장.
- 요구별 현재 구현, 내부 QA, 개발계 반영, 시안 제안, 원환경 미확인을 구별한다. 전체 424조건 또는 26피드백 완료율로 환산하지 않는다.
- 일반 social의 명확 거절 후 재시도는 조사·실패 재현 후 기존 identity/CAS/ownership 경계 안에서 최소 보완한다. unknown ACK와 재전송의 거절은 새 요청 허용 근거가 아니다.
- Dots 자유 편집의 등록 유지 계약은 바꾸지 않고 등록된 하위 원줄의 해당 메뉴에서 상태 설명만 보완한다. 자동 등록 해제·이력 삭제/복제나 기간 목록의 무조건 노출을 추가하지 않는다.
- 조작 가능한 로컬 HTML과 비교·구현·검증·후속 결과를 남긴다.

## 제외

새 반복·마감일·메모 귀속·폴더 기본 위치 정책의 확정, 새 DB/schema/로그인 정책, 실제 계정 쓰기, Tunnel/DNS, 서비스 교체, commit/push/PR/merge, Preview/Production, 관찰 사용자 시험. 현재 살아 있는 3105를 종료·재빌드하지 않는다. 큰 백업 5D를 이번 UX 개선의 선행 조건으로 붙이지 않는다.

## 완료 조건과 증거 한계

1. [요구 대조](requirements.md)와 [UX 검토](ux-review.md)에 세 원천·26피드백·네 시안의 대표 요구 및 후속을 연결한다.
2. 정책 불필요 갭의 red→green과 negative boundary를 확인하고 제품 코드·내부 합성 API·실제 서비스 쓰기를 구별한다.
3. runtime 변경은 표적·관련 회귀·npm test·production build와 허용된 HTTP 앱 브라우저 검사로 확인한다. 다섯 크기의 overflow·page/console 오류·핵심 행동 접근과 저장 경계를 기록한다.
4. 로컬 HTML 브라우저 접근이 정책으로 차단되면 우회하지 않는다. 이 세션의 새 시안 DOM/클릭·새 HTML 렌더는 NOT_RUN이며 정적·모형 검사를 화면 QA로 대신하지 않는다. 후속 외부 UX2 QA·기존18캡처를 읽은 근거는 따로 기록한다. 10/3 사용자의 아래 범위 수정에 따라 이 두 독립 검사는 이번 필수 완료 조건에서 제외하고 후속으로 남긴다. 실제 제품 HTTP 화면 검사와 저장 안전성 조건은 제외하지 않는다.
5. [결과](results.md)에 구현/QA/반영/실기기/관찰·공개 상태와 미완료·재개 조건을 분리한다.

## 10/3 승인된 완료 범위 수정

사용자: “야 그럼 그냥 그거 생략하고 목표 진행하자”. 바로 앞에서 논의한 독립 HTML 검사2건만 이번 목표의 필수 조건에서 제외한다. 필수 앱 QA는 이미 실행한 r6의 실제 HTTP 앱30/30과 같은 제품 소스의 관련·전체 테스트·타입·빌드 근거로 판정한다. 새 요구 대조·기획 인수·결과·후속 계획은 마무리한다.

- UX-D01 — 새 비교 HTML의 실제 렌더: **NOT_RUN·후속**.
- UX-D02 — 이 개발 세션의 독립 UX2 시안 DOM/클릭: **NOT_RUN·후속**.

두 후속의 재개 조건은 해당 검사가 허용되는 검사 환경의 확인과 후속 업무 범위 승인이다. 사용자 또는 다른 세션의 실제 검사 결과를 받으면 대상·판본·날짜·경로를 확인해 별도 근거로 인수하되 이 세션의 실행으로 바꾸지 않는다. 전체 제품 UX 완성·실기기·IME·AT·관찰 사용자 검증을 선언하지 않는다. 검사 실패 이력과 도구의 우회 금지는 유지한다.

이 변경은 이번 명세의 완료 범위 수정이다. 영구 제품 정책, 전역 도구 제한 해제, 개발계 교체 또는 commit·push·PR·배포 승인이 아니다. [마감 판정](completion-audit.md)과 [후속 목록](tasks.md#이번-목표에서-제외한-후속-검사)을 연결한다.

## 실행 중 확인한 도구 경계

인앱 브라우저는 사용 가능하지만 UX2 `tool-portable.html`의 file: URL 요청을 프로토콜 정책으로 거절했다. HTTP 미러·다른 브라우저·raw CDP 등으로 같은 차단 작업을 우회하지 않는다. 처음에는 원 코드·모형·콘셉트만 읽었고, 이후 외부 UX2에 생긴 후속 QA/source와 기존18캡처를 직접 읽어 대조를 보강했다. 여기서 시안 서버에 접속하거나 새 HTML을 실행한 것은 아니다. 실제 제품 HTTP 시험은 별도 허용된 대상이며 시안 렌더 성공으로 합산하지 않는다.
