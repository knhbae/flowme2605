### 코드 경로와 표시 공백

`text-workspace.ts`의 model은 vendor `editText` → `editTextResult`를 호출하고, 그 안에서 `reconcile`/`parseDocument` → `assignNewTaskScopes` 순으로 같은 줄ID와 등록을 유지한다. `parseDocument`는 현재 구조와 registry를 함께 읽는다. `rowMeta`538~540행은 R02를 `{kind:'subcheck', isCanonical:true}`로 내보내며 `textEditorRows`는 이를 editor로 전달한다. editor961·969~972행은 하위 체크 외형을 쓰고 날짜/소속 불일치에만 보조 버튼을 보여준다. 수정 전 C 사례는 날짜와 소속도 같아서 독립 등록을 알리는 신호가 없었다. canonical 등록 해제 행동은 없고 ‘이 연결만 해제’는 참조만 대상이다. 아래 좁은 후보 수정은 상태 설명만 추가한다.

이 연결은 현재 source를 읽은 근거이지 화면의 모든 상태가 검증됐다는 뜻은 아니다. 특히 자동 저장 완료 전 역편집과 완료 후 역편집을 구분하지 않으면 Dots와 서로 다른 결과가 나올 수 있다. source의 v11 계약은 원본 작업 공간에만 있어 읽기 전용으로 대조했으며 여기로 복사하거나 제품 schema를 바꾸지 않았다.

### 다음 좁은 UX 개선의 추천

1. 기존 등록·ID·이력을 먼저 보존한다. 원문을 같게 고쳤다는 이유로 `taskScopes`나 과거 기록을 지우는 ‘수정’을 하지 않는다.
2. 구조상 하위지만 별도 일정인 줄에만 맥락 표시를 비교한다. 상시 도움말·모든 줄의 badge를 늘리지 말고, 해당 줄 메뉴에서 ‘기간 목록에도 표시됨’을 확인하고 기존 입력 되돌리기의 대상/저장 상태를 알 수 있는 안부터 검토한다. 아직 제품에 구현한 안내가 아니다.
3. 장기적인 ‘하위 체크로만 사용’ 행동은 등록 해제 이후 ID/진행 기록/참조/폴더/날짜/Undo의 처리 규칙을 따로 선택해야 한다. 삭제·다시 만들기로 대체하지 않는다. 이는 PC03에 연결한 후속 설계이며 새 승인 정책이 아니다.
4. 텍스트 복사와 명시 이동은 별도 사례로 설명·검사한다. 복사의 완료 초기화/이력 복제 정책을 정하지 않고 기존 사본을 소급 변경하지 않는다.

우선 추천은 **기록 보존을 유지한 해석/복원 상태의 발견성 개선**이다. 제품 이동·복사 정책 전면 교체나 원문-only 재계산은 지금 선택하지 않는다. 기존 후보 저장 보완과 실제 화면 검사 잔여도 이 문서 진단으로 완료되지 않는다.

### 독립 진단과 한계

격리 작업본의 ignored `.tmp/dots-free-edit-diagnostics.test.cjs`6개와 `.tmp/dots-free-edit-draft-diagnostics.test.ts`3개, 총9개를 실제 실행해9/9 PASS했다. 프로그램의 순수 모델과 실제 `createProgramTextDraft`를 쓰되 CSS를 제외한 기존 JSX transpile/VM 검사 방식을 사용했다. commit callback은 메모리의 true/false만 반환했다. 외부 Auth/API·실 storage·서버 writer 호출은0이다. 이 진단은 해당 계약을 관찰/단언한 것이지 새 요구를 모두 충족하거나 FE01의 사용성 갭을 해결했다는 뜻은 아니다.

## FE01의 좁은 후보 개선 — 등록 상태 설명

[ProgramTextEditor](../../../components/flow/integrated-poc/ProgramTextEditor.tsx)의 기존 행 메뉴에서만 `kind==='subcheck' && isCanonical===true && !isReference`인 줄에 다음 문구를 표시한다.

> 이 하위 항목은 별도 할 일로 등록돼 있습니다. 들여쓰기를 바꿔도 등록과 진행 기록은 유지됩니다.

`flow-ux-review`의 감산 기준에 따라 모든 줄의 배지·상시 도움말·확인창·새 버튼은 추가하지 않았다. `flow-copy-editor` 검토에서 ‘기간 목록에도 표시’는 제외/보관/공개 사본 하위 항목의 실제 eligibility와 맞지 않아 쓰지 않았다. 현재 `rowMeta`를 읽는 설명이며 별도 등록 상태를 복제하지 않는다. parser·registry·원줄ID·progressRecords·저장 writer는 그대로다. 기존12px/줄높이1.55의 독립 `small`을 사용하며 화면 가독성은 실제 후보 검사 전에는 판정하지 않는다.

[새 컴포넌트 회귀4개](../../../components/flow/integrated-poc/ProgramTextEditor.test.tsx)는 최초3FAIL/1PASS로 안내 부재를 확인한 뒤4/4 PASS했다. 같은 파일 전체58/58 PASS다. 현재 메뉴에서만1개 표시, 신규 하위 체크/상위/메모/빈 입력/참조 제외, 닫기/Escape/dialog cancel0쓰기와 ID·원문·40% 이력 보존, 새 workspace의 상태 반영과 read-only 행동 차단을 검사했다. 이 검사는 실제 JSX/callback과 메모리 draft를 사용하며 브라우저·실제 clipboard·서버 reload·Undo 결과가 아니다.

후보 UC1에 등록된 하위 항목/새 하위 체크의 키보드 메뉴·Escape0쓰기·원문/계정 보존·좁은 메뉴 overflow 확인을 준비했다. 전체30경로/크기 조합의 UC1을 보강한 것이며 새 실행 수를 만들지 않았다. 3107이 없으므로 이 단언들은 NOT_RUN이다. 서비스에는 미반영이며 등록 해제·복원 발견성·텍스트 사본 의미의 전체 UX 갭을 완료로 올리지 않는다.

## R05와 연결 여정의 내부 추가 검사

원본 Dots의 실제 QA 자료는 건드리지 않고 제공 중인 판본에 합성 Auth/API를 붙여 UC6를 검사했다. 최종 `baseline-r05-20261002e`의5/5는 폴더·주간·검색 교차, 빈 결과의 키보드 필터 해제0쓰기, 구획 날짜 변경과 개별 예외, 날짜만 미정 이동 시09:10 유지, 날짜·시간 직접 비우기, 같은 ID/메모/원본 문서/reload 보존을 확인했다. 최종 다른 Item의10/9·11:20과 inherited10/3도 다시 확인했다. 최초 seed/selector 실패와 보완 전d의5PASS는 [QA](qa.md)에 남겼다.
