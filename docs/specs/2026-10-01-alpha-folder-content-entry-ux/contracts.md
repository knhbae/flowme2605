# 이번에 채택한 UX 계약

## 입력과 명시 연결

일반 입력과 구조 변경을 분리한다. `- 이름`을 쓰거나 붙여넣는 것만으로 폴더를 만들거나 연결하지 않는다. 제안을 보거나 닫는 동작은 추가 명령0건이다. 일반 텍스트의 자동 저장은 별도로 센다.

| 현재 줄 | 제안 / 허용 동작 |
| --- | --- |
| 자식 없는 미연결 목록 메모, 정확한 기존 이름 | 경로를 표시하고 정확한 폴더ID 선택. 원문·줄ID는 유지. 조상 순환을 만들 선택은 제외. |
| 같은 조건, 없는 이름, 기존 생성 모델이 허용하는 위치 | `새 폴더로 연결…` → 기존 패널에 이름·생성 위치 표시 → `만들어 연결`. |
| 중첩 일반 메모/Flow 내부, 깊이·이름 제한 등 생성 불가 위치 | 없는 이름의 생성 제안을 숨긴다. 기존 이름 연결은 기존 모델이 허용한 경우만 남긴다. |
| 할 일·속성·참조·이미 연결된 줄·하위 항목 있는 목록 | 이번 제안 대상 아님. 목록 전체 전환 완료를 주장하지 않는다. |
| 부분 보기·읽기 전용·입력 잠금·무효 초안·조합 중 | 제안 숨김. 부분 구조 변경 권한을 늘리지 않는다. |

현재 줄·커서·선택 범위·제목·원문과 committed 권한을 다시 확인하고 기존 `linkProgramFolder`·writer를 사용한다. 이름만으로 owner를 바꾸지 않는다. 기존 폴더ID·Item 소속·누적 기록·다른 행은 보존한다. 새 폴더는 명시 확정 뒤에만 ID를 소비한다.

연결 실패는 저장하지 않은 입력으로 남기고 재저장·입력 원문 받기·저장본 복귀의 기존 복구를 유지한다. Undo의 대상은 마지막 성공 명령이며 제안 닫기의 대상이 아니다. 외부판본/CAS/잃어버린 ACK의 전 조합이 이번 새 브라우저 범위에 들어 있지는 않다.

## 탐색과 제작

세 목적 진입 `내 공간 / 둘러보기 / 내 활동`은 유지한다. 기존 savedBindings가 있으면 나타나는 네 번째 `개인 Flow 상세`는 보존한다. 정확히3개 버튼이 모든 상태에 있다고 주장하지 않는다.

- 둘러보기는 게시글 유무와 무관하게 `Flow 찾기`로 진입한다. 경험·질문·지식은 같은 하위 단계에 남긴다.
- 목록 제목은 `Flow 찾기`, 상세·오류의 복귀는 `Flow 목록`이다. 검색·분야·상황과 읽던 판본의 기존 복원 상태는 유지한다.
- 공개 목록 자체가 비었을 때와 필터 결과가 비었을 때를 구분한다. URL 진입의 기존 disclosure는 재사용한다.
- 알파에서는 계정의 공개 목록·개인 사본·비공개 제작 초안을 구분한다. 기존 로컬 PoC 호출은 `storageScope` 기본값과 기존 문구를 유지한다.
- 제목 옆 `Flow 만들기`는 호스트가 콜백을 제공할 때만 보인다. Alpha의 기존 `navigate` 보호를 사용해 기억한 비공개 초안을 열며 생성·공개·추가 저장 명령0건이다.
- 공개 Flow 개인 사용은 명시 가져오기이고 공개 원문·개인 실행 기록의 자동 공개가 아니다. 이번 검사는 합성 판본1개이며 전수 Map/Flow 품질, 실제 외부 도구 import, 제작→개인 실행 인계의 새 end-to-end 검사는 아니다.

## 파일 조작본

HTML은 독립 합성 UX 모델이며 앱의 parser/writer·계정 동기화가 아니다. 전용 단일PoC키에만 저장한다. 이름 입력·명시 확인·취소·Undo·공개 예시 가져오기·비공개 초안 제작만 조작한다. 실패한 일반 입력은 화면 간 보존하고 제안을 숨긴 뒤 직접 재저장한다. 실패 상태의 브라우저 전체 종료·기기 동기화·실자료 백업은 지원했다고 주장하지 않는다.
