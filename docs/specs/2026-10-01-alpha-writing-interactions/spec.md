# 부분·전체 작성 입력 일관성

## 방향과 현재 위치

개인 자유 원문 계획·메모, wiki형 경험/지식과 Flow 재사용, 선택적인 커뮤니티 기여의 3축을 유지한다. 이번 목표는 그중 개인 문서 작성의 조작 문제를 좁혀 개선한다. 공개/제작/기여를 개인 작성의 필수 경로로 만들지 않는다. 사용자 관찰 시험은 보류하며 지속 피드백은 별도 세션에서 받는다.

[직전 방향 점검](../2026-10-01-direction-and-next-goal/spec.md), [v4.1·개발1·개발2 요구 대조](../2026-10-01-alpha-ux-journey/requirements.md), [피드백1~21](../2026-10-01-alpha-folder-writing-ux/feedback-map.md)을 이어받는다. 직전 폴더 후보의 전체 통합2,676/2,676·npm2,258/2,258·build는 이전 실행이다. 이번 목표의 새 코드 검증으로 재사용하지 않는다. Cloudflare 개발계의 확인된 반영은905c4c31이고, 직전 폴더 후보와 이번 후보는 미반영이다.

2026-10-01 사용자의 “한번에 쭉할 수 있는 목표 잡고 ㄱㄱ”로 제안했던 다음 묶음의 설계·조작 HTML·최소 구현·검증·보고를 승인받았다. `flow-ux-journey-20261001`의 현재 채팅 소유 변경을 유지한다. 다른 worktree의 dirty/untracked 파일은 미소유 읽기 전용이다.

## 목표

부분/전체 작성기에 같은 native 입력 엔진을 사용한다. 지원 가능한 Enter·메모 줄 추가·들여쓰기 역연산을 개선하고, 부분 범위에서 허용되지 않는 조작은 입력을 보존한 채 같은 전체 문서의 위치로 이어진다. 실제 조작 HTML과 합성 앱 브라우저 검증은 별도로 기록한다.

## 입력 계약

1. 제목 있는 할 일의 끝에서 Enter는 메모·시간·하위 할 일을 포함한 기존 묶음 뒤에 같은 깊이 checkbox 작성 틀을 만든다. 기존 Item의 속성·자식을 새 항목으로 넘기지 않는다. 제목 중간·선택·Shift+Enter와 일반 목록·들여쓴 원문 Enter는 기존 의미를 유지하며 부분 보호 검사를 거친다.
2. `- 메모: 내용`의 줄 끝 Enter/Shift+Enter는 같은 깊이의 `- 메모: `를 추가한다. 반복 속성은 이미 parser가 줄바꿈으로 합친다. 새 영구 문법·schema나 일반 본문의 자동 메모 귀속을 만들지 않는다.
3. 일반 원문 Shift+Enter는 기존 literal 줄바꿈이다. 메모를 자동 Todo/Calendar로 승격하지 않는다.
4. Tab/Shift+Tab은 기존 두 칸/하위 묶음 단위다. 바로 반대로 조작할 때 성공 판본·선택·변경 epoch가 같을 경우 최초 이동 묶음을 사용한다. 입력/선택/외부 변경 후 lease는 버린다.
5. 부분의 자동 조작은 재구성한 전체 candidate의 지역 planner가 허용할 때만 native transaction으로 실행한다. 기존 줄의 구조·소속·날짜·완료·ID 변화, 숨은 줄/다른 문서 변화는 거절한다. 거절 키의 기본 줄바꿈/Tab mutation도 하지 않는다. Escape 다음 Tab은 초점 탈출이다.
6. 직접 입력/붙여넣기의 지역 검증 실패는 입력을 남긴다. “전체 문서에서 계속 편집”은 현재 capability·workspace·같은 문서 판본과 목적지 native의 정확한 원문 설치 성공을 확인하고 서버 쓰기0으로 전체 local draft에 인계한다. 설치 거절이면 draft·부분 입력·보기 범위를 그대로 두어 재시도할 수 있다. 전체 수정도 기존 보호 검증과 writer를 거친다.
7. IME/229·읽기 전용·저장 중·잠금·stale는 강제 전환/변경을 하지 않는다. native command 미지원 시 `.value` 대입으로 Undo 성공을 꾸미지 않는다.
8. 미저장 native 입력 Undo와 저장 변경 Undo는 별개다. 서로 다른 textarea의 브라우저 Undo stack을 합쳤다고 약속하지 않는다.
9. 저장된 빈 줄에 잠시 뒤 일반 메모를 입력하는 경우, 지역 안의 단일 old blank→ordinary note와 바로 뒤 같은 깊이/삽입 문맥의 신규 blank/note 최대1줄, 다른 모든 기존 원문/ID/순서 동일·Item/binding/소속/기록 없음이 확인될 때만 기존 blank ID를 유지한다. 일반 메모→task 변경이나 여러 old blank·여러 문장 재해석을 허용하는 예외가 아니다. 넓은 변경은 입력을 보존해 전체 문서에서 계속한다.
10. 인증 host가 외부 변경을 보관 중이거나 pending/busy/conflict이면 local 전체 인계도 거절한다. 단순히 자식의 old workspace가 같다는 이유로 host의 stale 상태를 무시하지 않는다. 부분 커서 복원은 명시적 인계 성공의 1회 lease로 한정해 기간→정확한 원문 Item 복귀를 덮어쓰지 않는다.

## 설계 경계

현재 컴포넌트/디자인 시스템의 작은 조작 개선이므로 새 ImageGen/Figma 컨셉은 만들지 않는다. 기존 색·타이포·버튼·native mirror를 재사용하며 새 설명은 거절/복구에 필요한 시점에만 보인다. 큰 집중 모드·원문 문법 전면 변경·폴더 정책·반복/상대 날짜·Creator 전체 입력 개선은 제외한다.

실제 계정/DB/Auth/Tunnel·5D·운영 데이터·설정 변경, commit/push/PR/merge·개발계 교체·배포, 실제 기기/보조기술/관찰 사용자 시험은 제외한다. 문법·소속·반복의 새 영구 정책이 필요하면 그 선택만 분리해 요청한다.

## 완료 기준

- 요구 대조·계약·기술 설계와 직접 조작 가능한 standalone HTML 제공.
- 같은 native engine 연결, 지원 조작과 거절/전체 인계 동작 구현.
- 순수/컴포넌트 테스트 및 합성 Auth/API 앱의 실제 키 입력·Undo·실패·stale·조합 보호 검사.
- 390×844,375×812,844×390,1024×768,1440×900의 앱·HTML 넘침/핵심 행동·콘솔/page 오류 평가.
- npm test·전체 통합·production build·docs 검사 결과와 실제 실행 개수, 실패/보완 이력 보고.
- 기존 운영 데이터 불변은 이번 합성 sentinel/요청 차단 증거와 실제 운영 미접촉을 구분. mock 검증을 실기기/사용자 관찰로 표현하지 않음.

전체 피드백21개·424개 요구·제품 UX 완성이나 Creator 입력 계약 충족으로 확대 판정하지 않는다. 남은 F5~F10·실기기·요청량·장시간 운영은 [직전 다음 원장](../2026-10-01-direction-and-next-goal/spec.md)에 남긴다.
