# 실행 계획

1. 현재 방향·직전 완료/개발계 반영/후보·피드백 delta와 소유 범위를 확인한다.
2. 전체/부분 입력·지역 저장·범위 전환을 추적하고 v4.1·개발1·개발2 및 UX1/UX2 요구와 연결한다.
3. 기존 native engine 재사용, 메모 반복 속성, 즉시 들여쓰기 역연산, 지역 자동 키 사전판정, local 전체 인계 계약을 고정한다.
4. 엔진/helper·부분 surface/planner·전체 인계를 독립 소유 파일로 구현하고 표적 순수/컴포넌트 회귀를 먼저 확인한다.
5. 동일 엔진을 포함한 standalone 조작 HTML을 만든다. HTML은 앱/서버 저장의 증거가 아니라 입력 계약의 독립 시뮬레이션이다.
6. 고정 소스의 production build와 합성 앱 브라우저를 실행한다. 실제 press로 Enter/ShiftEnter/Tab/ShiftTab/Undo를 검사하며 hidden bytes/ID/Item·날짜·소속·기록·다른 문서를 비교한다.
7. 독립 코드 검토·UX subtraction pass, 다섯 viewport 이미지 확인, 최종 넓은 회귀·docs 검사 후 실패/제한/후속을 분리해 보고한다.

추가로 실행한 검사·재실행은 QA 원장에 남기고 이전 결과와 새 실행을 합쳐 제품 충족률로 만들지 않는다. 공개 앱3105·Tunnel3864와 기존 HTML preview는 건드리지 않는다. 새 QA server는127.0.0.1의 별도3106을 소유하고 종료한다.
