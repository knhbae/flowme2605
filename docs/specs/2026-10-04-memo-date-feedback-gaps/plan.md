# 단계 계획

1. 기준선: 새 clean worktree·main 관계·최신 피드백 원문/hash·세 원천 요구·기존 코드 계약을 확인한다.
2. 설계: 날짜 입력→기간→원문 복귀와 부분 선택→붙여넣기→복구의 예상 상태·ID·저장 수를 정한다. 새 정책과 현행 지원을 나눈다.
3. 구현: failing regression을 먼저 남긴 뒤 기존 계약을 깨는 결함만 소유 파일에서 수정한다. 서로 독립적인 감사·테스트는 병렬로 진행한다.
4. 검증: 표적 모델/컴포넌트, npm test, production build, 정확한 로컬 후보의 합성 브라우저·다섯 viewport·저장 경계 검사를 수행한다. 인증/API는 메모리 fixture로 가로채고 실제 backend로 보내지 않는다.
5. 마감: UX 검토·독립 diff 검토, 문서 검사·closeout, 판정표·실행 수·불변 근거·잔여·다음 단계 보고. 반영/게시 권한은 이번 실행에 포함하지 않는다.

선택기 popup과 실제 모바일 키보드는 자동 DOM 검사로 대신 통과시킬 수 없다. 미실행을 기록하되 지원되는 fill·키보드·취소 경로는 계속 검사한다.
