# 이번 후보의 UX 검토

2026-10-04. flow-ux-review의 별도 감산/여정/부하/안전 검토다. 실제 앱 viewport 측정, root가 확인한 390·844가로·1440 capture, 키보드·부분 paste·거절 복구 근거를 썼다. 사람의 선호나 전체 접근성을 점수로 추정하지 않는다.

## Findings

1. Medium / 상세 창: 날짜·시간 적용, 오늘/내일/미정 바로가기, 날짜별 진행, 순서, 문서 연결/원문 이동이 한 창에 있어 길고 빽빽하다. 짧은 가로에서는 내부 스크롤이 필요하다. 실제 가림·가로 넘침은 없었지만 인지 부담을 해결했다고 볼 수 없다.
2. Medium / 날짜 이해: 구획 기본값과 개별 실행 날짜를 구분하는 출처·결과 안내는 필요하다. 같은 날짜에서 시간만 편집하면 기존 handler가 개별 날짜도 고정하는 계약은 유지되며, 의미 변경은 미결 정책이다.
3. Resolved / 입력 보호: 저장 shortcut의 늦은 응답이 새 입력/다른 상세 draft를 덮어쓰던 결함은 수정 전 failing regression·실제 race2로 재현했고 수정 후 통과했다. 원 피드백의 정상 날짜 되돌림과 원인 동일성은 미확인이다.

## Rubric

- User Need Fit: 개인 문서의 날짜·메모를 잃지 않는 요구와 연결했다. 긴 상세 창의 선호와 발견성은 미검증이다.
- Execution Clarity: 입력→적용→기간→같은 원문→저장 복원이 확인됐다. 같은 제목의 두 독립 ID와 정확 대상 복귀를 검사했다.
- Content Fidelity: 부분 메모·인접 메모·원문·소속·기록 보존을 모델/컴포넌트에서 확인했다. 텍스트 copy를 기록 복제나 명시 이동과 합치지 않았다.
- Portability: 내부 기간 projection과 원문 왕복을 확인했다. 외부 calendar/export의 새 검사는 하지 않았다.
- Cognitive Load: 새 화면 요소0. 기존 긴 상세 창의 부하가 남았다. 진행/연결 등의 점진 노출은 후속 비교 대상이다.
- Copy Specificity: 새 copy0. 기존 날짜 출처·미정 시간 유지 안내는 결과 차이를 설명하므로 유지했다.
- Source/Safety: Auth/API 외부 전달0, 운영/dirty 원본 불변. 합성 저장 거절을 실제 DB 검사라고 표현하지 않았다.
- Accessibility/Operability: 주요 버튼 높이48px·hit-test·Escape·날짜 키보드를 확인했다. AT·물리 모바일·OS IME·선택기 popup은 NOT_RUN이다.

## Recommended fixes

1. 다음 화면 재구성에서 날짜 편집과 진행 기록/연결·이동을 목적에 맞게 구분하는 안을 비교한다. 필요한 조작을 근거 없이 삭제하거나 새 정책을 추가하지 않는다.
2. 원 날짜 되돌림은 원 조작/판본이 확인되면 같은 경로로 재현한다. 이번 지연 응답 결함의 해결로 원 관찰을 닫지 않는다.

## Subtraction

- Removed: 이번 runtime 변경에서 화면 요소 삭제0·추가0. 목적은 지연 응답 보호이며 화면 재설계를 함께 처리하지 않았다.
- Kept because: 날짜 출처·개별 지정 결과·미정 이동의 시간 보존은 적용 결과가 달라지므로 유지했다. 오류·저장 상태·Undo/재저장·접근성 이름도 복구와 조작에 필요하다.

이 검토는 [26개 원장](requirements.md)의 #3/#11/#14/#22/#24 후속과 연결한다. 새 제품 방향 결정·사람 시험·개발계 반영 완료가 아니다.
