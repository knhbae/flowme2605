# 개인공간 핵심 작성·일정 동선 UX

2026-09-30. 사용자 승인: 앞서 제안한 1~4를 목표로 등록하고 진행한다. 실사용 시험·사용자 참여·관찰 사용자 검증은 제외하며 기존 피드백 세션의 기록을 참조한다.

## 목표

1. v4.1·개발1·개발2의 기존 요구와 UX 결정/제안을 현재 화면에 대조한다.
2. 안전한 합성 자료에서 문서 생성 → 메모/할 일 작성 → 날짜·시간·폴더 → 오늘/주간/월간 → 완료/날짜 변경/Undo → 원문 복귀 → 새로고침/재열기를 브라우저로 조작한다.
3. 재현한 입력·발견성·정보 계층·저장 상태 문제를 좁게 개선한다.
4. 같은 시나리오, 5개 화면 크기, 키보드/비드래그, 한글 텍스트/합성 조합 이벤트와 관련 회귀를 재검증한다.

실제 한국어 IME·기기·보조기술·관찰 사용자 시험은 자동 Chromium 결과와 구분해 미실행으로 기록한다. 이번 범위의 종료 조건에 사용자 참여를 넣지 않는다.

## 경계

- 작업 위치는 기존 격리 `flow-alpha-backup-5d-publish-20260929`다. dirty 파일은 기존 증거와 겹침을 확인하고 이번 좁은 변경만 추가한다. 원래 `flow-mvp`와 UX worktree는 읽기만 한다.
- 실행 중인 3105 일반 앱·20249 Tunnel, `.next`, 개인 설정/자료·DB/Auth·백업 writer를 변경하지 않는다. 새 백업 off와 기존 백업 경로를 유지한다.
- 별도 합성 fixture는 실제 React 컴포넌트와 모델을 사용하되 인증/저장 응답은 가짜이며 외부 요청을 차단한다. 실제 계정·운영 데이터 검증으로 표현하지 않는다.
- 문서 보관 폴더와 본문 연결/Item 소속을 혼동하지 않는다. 시간은 기존 `HH:MM` 필드·명령만 연결한다. 날짜·폴더·순서·원본 Flow·지난 기록은 분리한다.
- 메모 여러 줄의 새 문법, 폴더 이름/삭제 정책, 달력 신규 화면, 개인 상대·반복/Creator 일괄 일정, 전체 Map 편집, 공개 부분채택은 자동 승격하지 않는다.
- 기존 5D·6~9 후속 원장 (로컬 전용 근거: `../2026-09-12-flowme-integrated-product-poc-program/alpha-follow-up-register-20260930.md`; 이번 게시 제외)을 보존한다. 서버 실행 계획 (로컬 전용 근거: `../2026-09-30-alpha-runtime-save-stability/spec.md`; 이번 게시 제외)은 별도 후속이며 이번 동선을 막는 저장 문제만 함께 다룬다.
- commit/push/PR·Windows 등록·현재 개발계 교체·배포는 별도 승인이다.

## 첫 개선 후보

UI 조작으로 확인한 뒤 최종 판정한다: 조합 중 전체 원문 전환, 이름 있는 폴더 줄의 중복 삽입, 날짜만 있는 상세의 시간 진입, 기간 목록의 폴더/필터 맥락, 작성보다 앞서는 상시 관리 UI. 입력 보호·오류/충돌·복구·Undo는 단순화 때문에 없애지 않는다.

## 완료 조건

[요구 대조](requirements.md)의 각 항목에 현재 지원·재현·수정/유지·후속·근거를 연결한다. 확인한 우선 문제를 수정하고 같은 브라우저 시나리오에서 다시 확인한다. 미실행과 실제 실행 수, 제품 변경·QA fixture·개발계 미반영을 [검증 원장](qa.md)에 분리한다. 전체 424조건 충족이나 UX 전체 완성으로 확대하지 않는다.
