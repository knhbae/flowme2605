# 실행 계획

1. 기준점·요구: 현재 Git/프로세스와 기존 v4.1·개발1·개발2/UX/피드백을 대조한다. 이미 해결/현재 재현/사용성/정책 미결로 분류한다.
2. 조작·평가: 현재 실제 컴포넌트를 합성 Auth·메모리 저장소와 묶은 별도 browser fixture로 먼저 조작한다. 실행 중 앱과 빌드 산출물은 보호한다.
3. UX/개발 설계·구현: 같은 Item·원문·기록을 유지하면서 조합 표시, 폴더 줄, 시간 입력, 조회 맥락·상시 UI의 확인된 문제를 최소 변경한다. 필요 없는 관리/설명은 접고 중요한 상태·복구는 남긴다.
4. 재검증·보고: 같은 시나리오와 실패/취소/같은 위치·Undo/reload, 390×844·375×812·844×390·1024×768·1440×900, 키보드 경로를 확인한다. 표적 → 관련 회귀 → npm test·격리 build·필요 타입 검사 → 문서/실제 화면 보고 순서다.

동일 파일의 동시 편집을 피한다. main은 편집기 패널/상단 shell, IME 담당은 native vendor, fixture 담당은 신규 QA 스크립트를 소유한다. 추가 담당은 별도 소유 범위를 정한 뒤 배정한다. 실사용·새 사용자·원격 writer·현재 호스트 교체는 실행하지 않는다.
