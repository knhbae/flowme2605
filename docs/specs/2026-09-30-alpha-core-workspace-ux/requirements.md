- E08 — 같은 폴더의 `rejected-draft.json`, `retry.json`, `retry.png`는 최초 실패·입력 보존 근거다. `retry-fixed-success.json`도 이름과 달리 polling이 거절 근거를 지운 중간 실패 자료다. 최종 수정 후 `rejection-final2-before.json`과 `rejection-final2-after-poll.json`은 같은 최신본을 5회 성공적으로 읽어도 거절 근거가 유지됐음을 기록한다. `rejection-button-final.json`은 거절 후 실제 `다시 저장` 버튼으로 revision 1→2·operation 1→2가 된 성공 근거다. `rejection-final2-success.json`과 `rejection-final2-reload.json`은 입력 수정 뒤 자동 저장 revision 0→1 및 reload 원문 보존 근거이며 직접 버튼 재시도로 분류하지 않는다. `unknown-same-request.json`은 별도 결과 불명 경로다. 서버는 같은 요청 ID로 revision 0→1·operation 1개를 확정했지만 열린 편집기의 dirty와 잘못된 충돌 안내가 남았다. 입력 손실은 없었으나 이 상태 정리는 후속이다.
- E09 — 같은 폴더의 `keyboard-indent.json`은 `restoredRaw=false`. 실제 vendor `onKeydown`·`indent` 함수와 모델을 로컬로 실행해 첫 행 caret가 같은 행에 남아도 마지막 형제 줄의 깊이가 2→4칸이 되는 최종 원문을 재현했다. 첫 내어쓰기 후 뒤 형제가 새 하위 묶음에 포함돼 두 번째 들여쓰기에 함께 이동하는 원인이다. 구조 재분류 후 반대 키를 Undo로 취급할지의 정책은 미결이다. 별도 `keyboard-undo-valid.json`은 `rawRestored=true`지만 모델이 Shift+Tab 저장을 거절해 서버 commit이 0회였다. native 입력 Undo의 복구만 확인했으며 저장된 구조의 복구 성공을 뜻하지 않는다.

## 해석 경계와 남은 사항

피드백과 UX2 인계는 관측·기존 계약·제안을 나누어 사용했다. 피드백 #2를 동기화 결함으로 다시 열지 않는다. 메모 Enter의 이어쓰기 문법, 연결 폴더의 실제 소속 변경, 새 폴더 문법/이름 정책, 100% 재클릭 정책은 확정하지 않았다. Tab↔Shift+Tab의 역연산 기대도 이번 완료 범위로 조용히 처리하지 않는다.

알려진 저장 거절 후 재시도는 최종 버튼 성공까지 확인했다. 결과 불명 요청이 서버에서 확정된 뒤 열린 편집기의 dirty·충돌 안내가 남는 문제와 들여쓰기의 구조 재분류 정책은 별도 후속이다. 따라서 U14 및 전체 핵심 작성 동선을 모두 완료했다고 쓰지 않는다. 합성 자료와 격리된 응답으로 실행했으며 개인 데이터·실제 계정/Auth·운영 DB 또는 현재 개발계의 변경·배포 근거가 아니다. 실제 IME·실기기·보조기술·관찰 사용자 검사는 제외 상태를 유지한다.
