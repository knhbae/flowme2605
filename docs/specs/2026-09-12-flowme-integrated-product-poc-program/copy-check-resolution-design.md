# 재추가된 하위 체크 — 개인 문구 보존과 원문 수용 설계

2026-09-14 · [요구별 검증](copy-check-resolution-review.md)을 남겼다. P02/P03/P07/P08의 제한된 완료 범위이며 복잡한 조합·전체 목표는 진행 중이다. 일반·반복의 실제 체크 행과 불변 원문 항목 ID를 대조하고 문구가 다르면 자동 덮어쓰지 않는다. 새 기능 범위나 운영 정책을 확정하는 문서는 아니다.

## 원래 요구와 결정 화면

원본에서 빠진 체크는 개인 본문·완료와 함께 보관한다. 같은 원문 체크 ID가 다시 추가됐을 때 보관된 문구와 새 원문이 다르면 체크별로 `내 문구 유지` 또는 `새 원문 받기`를 명시 선택한다. 아무 선택도 기본 확정하지 않는다. 다른 체크의 원문 변경도 미리보기에 포함하고, 개인적으로 수정된 활성 체크를 이 확인으로 덮어쓰지 않는다. 취소/Escape는 입력만 닫고 저장하지 않는다.

`내 문구 유지`는 같은 체크 행을 복원하고 개인 실행/출력에도 그 문구를 쓴다. 새 원문 판본과 개인 표시값을 구분하며 원문 근거를 바꾸지 않는다. `새 원문 받기`는 같은 행의 제목만 명시적으로 바꾸고, 이전 문구는 선택 이력에 남긴다. 날짜·완료·메모·하위 내용·다른 문서 참조와 반복 회차 기록은 바꾸지 않는다.

## 교체 가능한 Program v1 계약

- 선택 이력은 개인 사본의 선택적 버전 계약에 보관하며 기존 payload를 읽기만 해서는 추가하지 않는다. 같은 Flow/Item/체크/행과 불변 판본을 엄격히 검사한다.
- 전환 직전의 개인 상태와 다시 계산한 미리보기를 비교하고, 선택해야 할 체크가 정확히 일치할 때 한 Program 거래로 적용한다. 다른 필드 수용과 섞지 않는다.
- 원문 수용 판본은 갱신하되 개인 문구를 원문 값으로 위장하지 않는다. 반복의 개인 표시값과 공개 원문/지난 기록의 근거는 다른 층으로 읽는다.
- 실패한 요청은 입력·선택·같은 요청 ID를 유지한다. 중복·취소·잘못된 선택·stale 상태·저장 실패는 성공 mutation0, Undo/Redo/reload는 같은 기록을 복원한다.
- 이력 상한을 넘기면 기존 기록을 삭제하지 않고 거절한다. 외부 게시·계정·운영 migration·기존 writer는 사용하지 않는다.

## 검증 순서

1. 일반/반복의 기존 재추가 차단과 개인 제목·완료 보존을 재현한다.
2. 선택·지속 저장·엄격한 검증과 개인 실행/출력 reader를 연결한다.
3. 기존 비교 화면·입력 보호·오류/재시도·키보드/복귀를 재사용한다.
4. 실제 작성물의 체크 삭제/재추가 판본으로 개인 사용·실패·Undo/reload를 검증한다. 모델 fixture와 실제 공개 과정을 구별한다.
5. 원래 요구/현재 동작/남은 조합·자동 검사·실제 화면·운영 경계를 보고한다.

## 같은 항목의 개선 제안 연결

사전 코드 대조에서 `ProgramCopyProposal`/공개 patch/검토 비교가 제목·설명·완료 기준·일정만 지원하고 하위 체크는 받지 않는 것을 확인했다. 제작 공개기는 체크를 보존하지만 사본에서 체크 개선을 제안→검토→새 판본으로 잇는 경로는 별도로 누락돼 있었다. 실제 판본 생성에 fixture 삽입이나 저장소 직접 변경을 쓰지 않고 이 기존 제안 경로를 확장한다.

Program v1의 선택적 `patch.subchecks`는 공개 ID/문구만 받는 순서 있는 목록이다. 개인 완료·날짜·메모와 알 수 없는 필드는 거절한다. 빈 목록은 전체 체크 제외 제안이며 같은 목록은 보내지 않는다. 새 체크는 새 ID, 과거 체크 복원은 같은 Flow/Item의 기준 판본 이하 공개 이력에서 명시 선택한 ID를 사용한다. 동명 문구·행 순서로 정체성을 추측하지 않는다. 체크마다 문구·순서·제외를 편집하며 ID나 JSON 입력을 사용자에게 요구하지 않는다.

기존 고정 판본 context·검토 CAS·공개 whitelist·실제 불변 판본 writer·미제출 입력 보호·실패 재시도를 재사용한다. 개인 Undo는 전송된 공개 제안이나 공개 판본을 철회하지 않는다. 체크 복원 수용은 별도의 개인 transaction/Undo이며 두 동작의 소유를 합치지 않는다.
