# 제작 원본 업데이트와 기존 개인 문서 승계

2026-09-12 20:43 UTC · 전체 목표의 중간 구현 묶음. P01~P08/S01~S10과 두 전체 개선 루프의 종료 조건을 줄이지 않는다.

1. 기존 제작 문서의 원본 업데이트 모델에서 원본 사실과 사용자가 선택한 ‘없음’을 분리한다. 과거 v1의 값 유실은 실제 journal 근거로만 명시 복구하고, 원래 운영 저장본은 변경하지 않는다.
2. 제작 원문 화면에 붙여넣은 새 원문 준비→실제 항목 연결 확인→이전 원본/내 작업/새 원본 비교→필드별 유지·반영·나중에→적용·보류·거절·원본 Undo를 연결한다. 외부 수집·게시자 인증 성공으로 표현하지 않는다.
3. 원본 준비 입력과 실패한 선택은 이동·다중탭·실패에도 보존한다. 작성 중인 제작 원문/상세 입력과 경쟁하면 먼저 적용·취소하도록 안내한다. 저장 성공 뒤 열린 원문과 저장 working을 함께 갱신한다.
4. 기존 raw 개인 문서와 native 제작 항목 사이의 정확한 승계는 독립 모델로 구현한다. 제목/배열 위치로 연결하지 않고 원래 행 identity·명시 연결로 개인 기록과 참조를 보존한다.
5. 표적 모델/실제 부모 handler/SSR→strict→동결 전체 검사와 production build→허용된 loopback 브라우저에서 취소·quota·재시도·부분 선택·Undo·reload·모바일/가로/키보드를 검사한다. 이전 Ojj 실행판의 성공을 후속 소스 성공으로 소급하지 않는다.

UX 판단: 기존 구성·네이티브 입력을 재사용한다. 비교에 필요한 값은 펼치고 전체 원문/원본 식별 정보는 필요할 때 연다. 44px 조작 영역, 오류 옆 재시도, 저장 상태, Escape와 초점 복귀를 제공한다. 잘못된 ‘읽기 전용’ 문구가 실제 개인 실행 연결을 부정하지 않게 범위를 바로잡는다.

이번 묶음도 앱 전체 백업·새 run·철회 후 재공개 정책, 계정·운영 migration·발행·배포를 승인하지 않는다. 실제 기기/OS IME/보조기술/외부 계정/관찰 사용자는 실제 수행 전까지 미검증이다.
