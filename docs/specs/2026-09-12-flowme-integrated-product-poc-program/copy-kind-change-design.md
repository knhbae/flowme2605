# 공개 사본의 일반↔반복 전환 — 구현 계약

2026-09-14. P02/P03/P07/P08의 양방향 전환을 구현했고 [요구별 실제 검증](copy-kind-change-review.md)에 확인한 조합과 잔여를 구분했다. 같은 종류의 새 일정 수용과 구분한다. 기존 `legacy-source-execution.ts`의 일반 canonical ID 보존·보관 문서·복귀 방식을 재사용하되, 공개 사본의 필드별 불변 판본과 전용 반복 참조를 함께 검사한다. 이 설계 문서 자체는 완료 근거가 아니다.

## 사용자가 결정하는 것

원문 일정 비교에서 종류가 달라질 때 `항목 형태 전환 검토`를 연다. 원래 일정→새 일정, 보관할 일반 본문/하위 체크/진행/참조, 이전 반복의 회차 기록·개인 계획과 되돌릴 수 있는 범위를 보여 준다. 확인 전에는 쓰지 않는다. 일반 기록을 매회 완료로 복사하지 않으며 반복 기록을 일반 항목의 완료로 합치지 않는다. 취소/Escape/같은 요청 재시도/저장 실패는 기존 controller 계약을 따른다.

## 교체 가능한 PoC 계약

- 일반 행과 반복 metadata 행은 서로 다른 안정 ID를 사용한다. 한 종류로 돌아왔을 때 이전 일반 행 ID와 개인 하위 구조를 복원한다. 제목·배열 위치로 동일 항목을 추정하지 않는다.
- 비활성 형태의 실제 본문은 기존 `retentionDocuments`의 읽기 전용 문서에 둔다. 완료·메모·날짜·낯선 하위 행·진행 기록과 다른 문서의 참조를 삭제하거나 새 형태에 복제하지 않는다.
- 공개 사본의 선택적 `kindHandoffs.version:1`은 두 형태의 실제 행/하위 체크, 당시 필드별 판본, 개인 날짜·시작 선택과 명시 전환 이력만 보관한다. 공개 repository나 운영 schema는 바꾸지 않는다. 없는 필드는 읽기만으로 추가하지 않는다.
- 공통 원문 필드의 수용 판본은 종류 변경으로 되돌리지 않는다. 이전 일반 본문을 복원할 때 당시 원문과 같던 원문 필드만 이미 수용한 공통 값으로 맞춘다. 개인적으로 바뀐 필드·하위 본문은 유지하고 일반 비교의 충돌로 남긴다. 개인 실행 날짜/완료/메모/시간은 별도다.
- 반복 참조는 일반 항목으로 자동 재연결하지 않는다. 비활성 반복의 정확한 원문 행·기록으로 돌아갈 수 있어야 한다. 일반 참조도 보관된 일반 행을 계속 가리킨다.
- 미정 반복의 개인 시작과 기존 개인 계획은 정확한 판본/항목에 남긴다. 다른 판본의 새 실행에 완료나 계획을 자동 이식하지 않는다.
- 전환 직전 전체 개인 상태/CAS와 다시 계산한 미리보기를 비교한다. 무관한 actor/Flow/판본/행, stale 입력, 변조된 보관 metadata와 모호한 subtree는 거절한다. 이력 상한에 도달하면 기존 기록을 자르지 않고 명시 거절한다.

## 구현·검증 순서

1. 원래 전환과 공개 사본 consumer를 대조하고 읽기 전용 전환 계획·엄격한 저장 계약을 만든다.
2. 양방향 보관/복원과 공통 원문 필드 수용을 한 개인 거래로 연결한다. 회차 reader/기록 복구/참조/입력 잠금도 같은 계약으로 확인한다.
3. 기존 비교 화면에 명시 확인·취소·오류/재시도·정확 초점을 연결한다.
4. 일반→반복→일반→반복, 개인 수정/하위 체크·여러 문서 참조·원문 판본 변경·과거 회차/계획·Undo/Redo/reload·손상/CAS/quota/운영 key 불변을 검증한다.
5. 같은 실제 작성물에서 새 공개 판본을 만들고 화면 왕복을 확인한다. 계약 fixture와 실제 공개 과정, 부분 확인과 전체 S01~S10/두 개선 루프를 분리한다.

실제 다른 구조에서 문맥 상속/개인 수정의 보존이 깨지거나 전환 영향이 모호하면 계약과 화면을 함께 재검토한다. 계정·외부 공개/배포·운영 migration·새 실행 정책은 열지 않는다.
