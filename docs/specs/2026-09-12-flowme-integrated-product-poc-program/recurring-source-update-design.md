# 반복 원본 변경 비교·부분 수용 D — 실행 설계

2026-09-14. [출력 연결](recurring-output-review.md) 다음 작업이다. [전체 반복 설계](recurring-publication-design.md)의 원본 비교·수용/제안과 실제 공개부터의 연속 검증을 모두 남긴다. 이번 구현은 실제 사본의 metadata 필드 비교·수용부터 진행하며 반복 공개 제한을 열지 않는다.

## 요구와 확인 순서

1. 실제 import로 만든 반복 사본을 같은 판본과 비교해 수정하지 않은 제목·하위 확인을 개인 변경으로 오인하는지 재현한다. 새 판본 설명을 수용할 때 일반 체크박스 writer가 반복 header를 찾지 못하는지도 재현한다.
2. 사본의 정확한 header·field·child 행 ID를 따라 원래 metadata를 읽는다. 제목/하위 확인의 본문 편집은 충돌로 드러내며 개인 내용이나 원문 행을 추정으로 덮지 않는다. 일반 Item reader/writer는 기존 경로를 유지한다.
3. 선택한 필드만 한 Program transaction으로 반영한다. 반복 제목과 하위 확인은 metadata이며 일반 체크박스나 실행 owner로 바꾸지 않는다. 새 하위 확인도 실행 기록이 없는 원문 확인으로 만들고, 원문에서 빠진 확인의 행/개인 내용은 보존한다. 기존 field별 수용 판본과 Undo/CAS/실패 계약을 재사용한다.
4. 일정 수용의 영향은 별도로 검사한다. 원래 규칙·공개 시작을 바꾸면 새 회차의 날짜가 달라질 수 있다. 지난 실행 기록·개인 계획을 자동 재작성하지 않는다. 일반↔반복 전환이나 별도 개인 계획과의 충돌은 필요한 전환 경로를 만들기 전까지 설명 가능한 미지원으로 남긴다. 이것을 영구 정책이나 전체 수용 기능 완료로 확정하지 않는다.
5. 기존 비교 UI를 재사용한다. 바뀐 필드를 앞에 두고 같은 정보는 접는다. 충돌/미지원 사유와 반복 일정 수용의 실제 결과를 알린다. 새 화면·Figma 파일은 만들지 않는 Code-only 작업이다.
6. 실제 import·선택 수용·record/reference 보존·동일/실패/Undo/reload의 순수/저장/화면 검사를 수행한다. 관련 기존 회귀·전체 검사·strict·build와 허용 브라우저를 구분한다. 근거가 확보된 범위만 원장에 올린다.

다음 연결은 반복 제안/채택, 복구 화면의 정확한 원본 근거, 실제 작성물의 공개부터의 연속 검증이다. 단계별 안전 제한을 끝난 제품 기능으로 대체하지 않는다. 운영 데이터·기본 `/my`·기존 writer·다른 세션 자료를 변경하지 않고 commit/push/PR/배포/외부 게시를 하지 않는다.

## 실제 검증에서 추가한 UX 수정

[D 실제 수용 대조](recurring-source-update-review.md)에서 긴 비교창의 적용 버튼과 오류 안내가 멀리 떨어진 문제를 발견했다. 필드 수용의 저장 중·실패·성공을 해당 적용 버튼 앞에 한 번만 표시한다. 기존 선택·취소·저장/Undo 계약과 다른 동작의 피드백은 유지하며 새 저장 필드는 만들지 않는다. 동일 실패 입력·재시도, 다섯 크기에서 오류와 재시도의 동시 가시성을 확인한 뒤 이 범위를 완료로 올린다.

## D 연결의 실제 코드 접점과 후속 판정

아래1·2의 공개 원본 표시 연결은 [49M7 원장](public-source-facts-review.md)에서 새7검사/관련27·전체1397·실제후속22확인으로 검증했다. 3의 반복 제안/채택과 개인 시작일/계획 충돌 해결은 다음 구현이다. 아래 설명은 구현 전 발견 근거로 보존한다.

1. `recurrence-recovery.ts`의 `programOccurrenceSourceFacts`는 현재 `source.flow/source.contexts`를 읽는다. 공개 사본의 실제 token은 `public-copy-source/1`의 exact copy/Flow와 항목별 일정 판본이므로 같은 reader로 읽으면 원본 근거가 비게 된다. `public-copy-recurrence.ts`의 strict token/owner 검증과 불변 공개 판본을 재사용해 기록 당시/현재 근거를 별도로 읽는다. 다른 Flow·같은 제목·최신 판본으로 대신하지 않으며, 원본이 없으면 없다고 표시한다.
2. `ProgramRecurrence.tsx`의 보존 회차 비교에서 위 두 근거와 재연결 가능/불가 이유를 확인한다. 근거 표시만으로 기록 identity·완료·개인 날짜·재연결 권한을 바꾸지 않는다. 실제 이번 v1 완료→v3 일정 수용 자료에서 두 일정과 지난 기록을 검증한다.
3. 반복 제안 편집은 `ProgramCopyInspector`의 기존 차단을 단순 삭제하지 않는다. `ProgramPublisher`가 사용하는 typed 반복 draft/parser와 공개 patch/review의 같은 규칙을 연결하고, 사용자 제안→로컬 owner 검토→새 불변 판본→사본 명시 수용을 함께 확인한다. 일반↔반복·개인 계획/시작일 충돌의 미지원 처리도 별도 기능으로 남긴다.

위 내용은 읽은 코드에 근거한 다음 구현 접점이며 완료 기록이 아니다. 실제 사용자 반복 공개 제한을 여는 일은 필요한 consumer와 E 연속 검증이 준비된 뒤 수행한다.
