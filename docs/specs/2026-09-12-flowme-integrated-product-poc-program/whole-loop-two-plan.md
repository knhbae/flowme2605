# 전체2 — 학습 자료 활용·반복 연습·선택 공유의 연결 평가

## 실행 종료 — 2026-09-20

A–D 실행·개선은 [최종 평가](final-evaluation-2026-09-20.md)와 [실행 근거 원장](final-scenario-ledger-2026-09-20.md)에 따라 종결했다. 아래는 실행 전/진행 중 계획 기록이며 당시의 ‘남는다·미실행’을 현재 상태로 읽지 않는다. 원래 계획을 결과에 맞춰 지우거나 전체 조합 검증으로 확대하지 않았다.

2026-09-14 작성, 2026-09-20 진행 갱신. A는 완료했으며 B는 주간 제작·개인 실행·이후 계획과 기존 Map의 기준일/포함 선택까지 진행했다. B의 제작 복구·구조 조작/Map 진행·참조와 C~D는 남는다. 실제 수행/미수행과 실패는 [전체2 평가 원장](whole-loop-two-review.md)이 정본이다. 이 문서는 [전체 계약](spec.md) P01~P08과 [S01~S10 실행표](final-whole-loop-plan.md)를 다른 목적·내용 구조로 수행할 계획이다. [첫 루프 결과](whole-loop-one-review.md), [상황별 이력](journey-closeout.md), [실행 순서](plan.md)를 대체하거나 과거 부분 검사를 두 번째 전체 루프로 재분류하지 않는다.

계획 최초 작성 시 ordinary 프로필은 S09의 revision376 저장 이후 복귀를 진단 중이었다. 그 계획 작성 자체에서는 UI에 접근하거나 자료를 변경하지 않았다. 현재는 이 값에서 진행됐으므로376을 다음 실행의 고정 시작값으로 사용하지 않는다. [현재 체크포인트](current-checkpoint.md)와 마지막 실제 원장의 revision/hash/generation을 인계받아 실행한다.

## 평가하려는 사용 목적

“여행 준비 항목을 가져와 실행한다”와 달리, 이번에는 학습 자료를 찾는 사람이 외부용 파일만 받아 나가거나, 원하면 반복 연습에 활용하고, 긴 개인 기록에서 남에게 유용한 확인 목록만 공유하는 상황을 다룬다. 학습 성과·교육 효과를 평가하는 실험은 아니다. 내용에는 `로컬 QA / 실제 수강·성취 경험 아님`을 표시하며 출처의 사실과 QA가 작성한 계획을 구별한다.

각 경로는 사용자에게 강제하는 순서가 아니다. 파일만 받은 사람, 개인 문서만 쓰는 사람, 경험을 쓰지 않고 Flow를 사용하는 사람, Flow 없이 질문하는 사람 모두 각자의 목적에서 종료할 수 있어야 한다. QA 실행자는 아래 경로를 차례로 잇되 같은 계정 모드나 실제 다중 사용자로 표현하지 않는다.

## 시작 계약과 원본 선정

실행 책임자가 한 번에 한 프로필만 조작한다. ordinary와 기존 Map 프로필의 결과를 같은 저장소의 연속 revision처럼 합치지 않는다. 동시 탭 검사는 아래 D의 지정 구간에서만 의도적으로 수행한다.

1. 첫 루프 종료 인계에 `artifact 경로 / profile·CLI session / actor / revision / raw SHA256 / document BUILD_ID / 실제 route chunk`를 기록한다. fresh snapshot·disk readback이 모두 일치해야 시작한다. 입력 미제출, 저장 중, 경고 dialog, 해결하지 않은 비교·복구 상태가 남으면 먼저 그 작업의 담당자에게 돌려준다.
2. ordinary의 기존 S01~S09 문서·S05 치앙마이 사본·S06 지식/사진 관련 개체·S07 제작물·S08 판본/제안/개인 기록은 보호 집합이다. 새 자료의 이름은 `QA 전체2 학습 기록 <runId>`처럼 식별하되 실제 ID는 UI 생성 결과로만 얻는다. 기존 초안을 새 용도로 소비하거나 원래 문장을 바꾸지 않는다.
3. root가 확인해 전달한 현재 Map 프로필은 `map-child-removal-20260914`, revision7이다. S05 legacy transfer의 새 프로필은 준비 중이며 이름·revision·원본 ID를 아직 고정하지 않는다. root의 별도 준비/seed artifact가 나온 뒤 실제 CLI session·profile·raw SHA·원본 tuple을 대조해 B/D에서 사용할 대상을 정한다. 예전 `program-map-removal` / `program-map-recurrence-removal` 이름을 현재 프로필로 가정하지 않는다. [Map 원장](map-removal-review.md)의 원본 선언·snapshot·persistence·bundle·child tuple을 함께 확인한다. 실제 OPIc 자료가 인계 상태에 없으면 비슷한 제목으로 대체하지 않고 인계 대상부터 재확인한다. 첫 루프와 같은 삭제/복원 동작만 재실행한 것은 두 번째 평가로 세지 않는다.
4. 새 주간 작성물은 기존 작성 틀의 지원 필드만 사용한다. 내용은 QA용 발표 연습과 준비 체크로 하고, 고정 또는 상대 시작·반복 규칙·하위 확인 중 실제 compiler가 함께 지원하는 조합을 입력한다. 지원하지 않는 혼합 구조는 안전한 거절로 기록하며 단순 메모로 바꾸어 반복 동등성 PASS를 만들지 않는다.
5. 보호 manifest는 key 개수와 정확 bytes, 모든 기존 원본/판본/개인공간, 실행·참조·제작 저장본·미제출 초안·Undo 이력을 포함한다. ordinary의 운영 key가 0개면 그 사실을 유지한다. 채워진 Map 보호 key의 결과는 별도 기록한다. 읽기용 메모리 복제본의 비교는 가능하지만 저장값 주입·seed·reset·원래 fixture 덮어쓰기는 금지한다.

root의 현재 ordinary `public.flows` 확인에서 등록 factory catalog는 이사·치앙마이 두 원본이며 학습용 등록 URL은 없다. 이를 필수 제품 갭으로 승격하거나 catalog 추가 권한을 확장하지 않는다. A의 학습 계획은 미지원 URL→사용자 원문 보완이고, Map은 root가 인계한 실제 구조화 원본이다. C에서 새로 만드는 F-week도 이 기존 catalog나 Map의 새 판본이 아니다. 원본 후보 ID·현재 지원 여부·주간 틀의 typed schedule 계약은 실행 전 source/실제 화면 대조로 확정한다. 이 문서 수정에서는 브라우저를 다시 확인하지 않았다.

## 연결 실행: 네 가지 목적 작업

### A. 저장을 결정하기 전에 외부로 가져가기

자신의 연습 계획을 가져오려는 사람의 명시 QA 미지원 URL로 시작한다. 미지원 결과에 다른 예시가 반환되지 않는지 확인한 뒤 QA 원문을 붙여넣고 직접 확인·조정한다. 첫 루프와 다른 학습 준비 메모·일반 날짜 항목을 사용하며, 실제 지원되는 TXT/CSV/ICS를 받아 미리보기와 파일 bytes·선택 항목·날짜 의미를 대조한다. 새 문서·사본·공개물 증가는 0이어야 한다. 실제 외부 수집이나 학습용 등록 원본을 사용했다고 표현하지 않는다.

등록 URL lookup의 최종판 연결 증거가 필요하면 실제 이사 원본의 다른 항목 선택·기준일로 짧게 재확인한다. 이는 첫 루프와 겹치는 회귀 검사이며 두 번째 루프의 새로운 학습 원본이나 별도 개선 횟수로 세지 않는다. 등록 URL의 정확한 source·판본과 무저장 경계를 확인하고 catalog를 수정하지 않는다.

일반 붙여넣기 compiler의 반복·시간대 지원을 가정하지 않는다. A의 일반 pasted ICS 성공은 반복 출력 완료가 아니다. 반복·시간대는 B의 작성 틀→C의 실제 typed schedule 공개 이후로 의존 순서를 미룬다. 현재 ICS의 종일 일정과 미정 제외 범위를 유지하며 timed event·외부 캘린더 등록·동기화를 주장하지 않는다.

출력 직전 원문/선택/필터와 출력 취소 뒤 복귀를 기록한다. 파일 링크로 돌아갈 경우 정확한 원본·판본·선택 대상을 확인한다. 이 단계의 private raw는 URL/hash/history state·공개 payload에 들어가면 안 된다. 받은 파일은 의도한 출력이며 외부 전송은 하지 않는다.

### B. 긴 개인 기록과 원래 제작 기능으로 연습을 이어가기

UI에서 긴 독립 학습 기록과 짧은 참조 문서를 만든다. 기록은 도입 메모, 같은 제목의 두 준비 항목, 하위 체크, 비공개 사정·링크가 있는 부분을 구분한다. 필요한 분량은 내부 스크롤과 검색 결과 복귀가 실제 발생할 정도로 정하고 인위적으로 수천 행을 채우지 않는다. 없는 검색어→검색 해제→작성 행 재진입 후 이어 쓴다. 빈 폴더/보관·복원은 이 자료를 정리하는 맥락에서 수행한다.

새 주간 제작 초안에서는 틀 입력→미리보기 취소→명시 적용→명시 저장→저장 이력 선택·복구→native Undo/Redo를 이어 쓴다. 같은 제목과 하위 확인이 있는 지원 원문에서 날짜순 정렬과 구조 이동의 의미를 비교한다. CRLF 입력은 실제 지원 입력 경로와 원래 bytes를 확보했을 때만 포함한다. textarea에서 이미 LF로 정규화된 문자열을 CRLF 보존 근거로 부르지 않으며, 파일 입력이 불가능하면 해당 검사를 미실행으로 남긴다. 틀 예시 읽기만으로 기존 제작기 전체 동등성을 대신하지 않는다.

이 명시 저장본을 개인 실행에 연결해 한 회차를 완료하고, 이후 회차의 개인 계획을 변경한다. 과거 회차·일반 메모·하위 체크 완료는 새 회차에 복제하지 않는다. 문서/일/주/월/전체·폴더와 짧은 참조 문서에서 같은 target을 확인한다. 회차 이동, 문서 원문 이동, 폴더 정리를 각각 다른 변경으로 판단한다. 전역 Undo는 실제 거래 순서를 따르고 native 편집 Undo와 혼동하지 않는다.

기존 OPIc Map은 경험 작성 없이 찾아 사용한다. 현재 유효한 일부 child/항목과 개인 계획·기록을 확인하고, 이번 학습 목적에 맞는 포함/기준일 또는 이후 계획 선택을 한 뒤 정확한 문서로 돌아온다. 새 제작물로 Map을 대체하거나 가짜 TXT로 변환하지 않는다. 이미 통과한 Map의 삭제 기능 자체를 반복하는 대신, 이 실행 기록·참조가 생긴 상태에서 D의 원본 변경과 연결한다.

이때 기존 네 origin인 `legacy-saved-plan / personal-draft / canonical-personal-copy / source-backed-map`을 실제 저장된 owner별로 한 번씩 열고 원래 문서·출처로 돌아온다. 각 tuple과 기록, 부분 연결이 있으면 `existing/new/source-only` 및 보존 항목의 현재 대응을 확인한다. 없는 origin을 이름 변경으로 만들지 않는다. 이미 기록이 있는 부분 연결은 별도 새 원본 거래 없이 읽기만 한 범위를 명시한다. `program-origin-enum-from-live.cli.js`는 원본을 손상시키는 gate 준비가 포함되어 있으므로 이 누적 프로필에 그대로 실행하지 않는다.

### C. 개인 기록에서 필요한 것만 공유하고 짧게 질문하기

긴 독립 문서에서 확인 목록 일부만 선택해 새 로컬 공개 원본 `F-note`를 만든다. 비공개 문단·개인 일정·진행·메모·낯선 private 링크를 명시적인 누출 탐지값으로 기록한다. 미리보기 취소/다시 열기와 확정 경계를 지나 공개 whitelist를 대조한다. 개인 원문은 문장·공백·행 ID까지 보존한다.

반복 주간 제작물은 별도 공개 원본 `F-week`로 만든다. 실제 typed schedule의 시작·주기·종료·시간대를 명시 저장본과 공개 v1에서 대조하고 반복이 메모나 고정 회차 목록으로 축소되지 않는지 확인한다. 지원되는 다른 시간대 값은 이 작성 틀의 실제 입력 계약에서 선택한다. 반복·시간대를 지원하지 않는 일반 붙여넣기로 대체하지 않는다.

이 공개 v1을 읽고 사본을 가져오기 **전에** TXT/CSV/ICS를 실제로 받는다. 공개 typed schedule·선택 회차·원문/출력 날짜·시간대 표기와 파일 bytes/SHA를 대조하고, 출력 링크로 같은 판본·항목/회차에 복귀한다. 이 출력 구간의 기준선은 F-week 공개 직후다. 구간 중 새 문서·사본·공개물 증가와 저장은 0이어야 하며 앞선 제작·공개까지 무저장이었다고 주장하지 않는다. 종일 ICS의 지원 범위를 유지하고 파일 전체를 RRULE 이벤트나 실제 외부 계정 등록으로 해석하지 않는다. A의 일반 파일과 이 typed 반복 파일은 별도 증거로 남긴다.

출력 확인 후 실제 공개된 v1에서 UI로 정확한 새 사본을 가져온다. `F-note`의 사본도 해당 원본에서 별도로 만든다. 두 source와 S05/S07의 기존 source를 재연결하지 않는다. 추가 사본은 D의 서로 다른 일반 필드/반복 구조 검증에 필요한 두 개로 제한하며, 각 생성 직후 source·version·item·anchor·targetDocumentId와 생성 receipt를 인계한다.

커뮤니티에서는 이 자료와 별개로 “반복 연습 기록을 어떤 기준으로 정리하는가”라는 짧은 QA 질문 한 개를 Flow 없이 작성한다. 실제 도움이나 학습 경험을 꾸미지 않는다. 기존 로컬 다른 인물의 답글 한 개와 반응 on/off, 질문 수정, 내 활동→정확 답글→글 복귀를 확인한다. 인물 전환은 인증/실제 사용자 검증이 아니다. 첫 루프의 긴 경험·사진·삭제된 근거 지식은 보존하고 그 성공을 이번의 새 작성으로 합산하지 않는다. 사진을 새로 만들거나 기존 글을 불필요하게 삭제할 필요는 없다.

### D. 다른 수정 목적을 충돌·중단과 함께 마치기

`F-note`는 사본의 제목과 설명을 각각 개인 수정하고, 로컬 작성자가 그 두 필드와 별도 완료 기준을 수정한 새 불변 판본을 만든다. 실제 구판이 된 v1에서 고정 항목 제안을 제출하고 검토한다. 새 판본이 생겨도 기존 사본은 자동 변경 0이다. 비교에서 충돌한 제목은 내 값 유지, 충돌한 설명은 새 값 명시 선택, 비충돌 완료 기준은 별도 선택 수용한다. 필드별 거래를 한꺼번에 합치지 않는다. 선택/취소/Escape→한 번의 quota 실패→동일 선택 재시도→개인 기록과 행 보존→거래별 Undo/reload를 연결한다. 개인 값을 기준값으로 되돌려 충돌을 없애는 우회는 하지 않는다.

`F-week`는 지원되는 일정 또는 하위 확인 변경을 같은 원본의 제안·작성자 검토·새 불변 판본으로 잇는다. B에서 만든 개인 계획·과거 회차·하위 체크와 새 원본의 비교를 읽고, 실제 UI가 지원하는 명시 유지/수용을 선택한다. 일반 필드 선택이 반복·하위 구조 전체 해결의 증거는 아니다. source owner·종류/회차 identity가 바뀌는 경우 보관된 기록과 새 실행을 분리하고, 지원하지 않는 구조는 필수 미충족인지 지원 밖인지 원래 계약과 대조해 기록한다.

미저장 제안 입력을 가진 탭 A와 같은 프로필의 탭 B를 이 구간에서만 사용한다. B가 허용된 새 QA 대상에 정상 UI 변경을 저장한 뒤 A의 오래된 확정을 시도한다. 정확한 expected revision/CAS 거절, B의 변경 보존, A의 입력·선택 보존을 확인한다. 이후 인물 전환·뒤로·다시 열기에서 다른 owner에 입력이 적용되지 않아야 한다. 정상 저장된 결과를 재제출하지 않고 실제 복구 UI로 읽는다. 손상 payload는 누적 프로필에 넣지 않으며 별도 일회성 gate로 분리한다.

Map에서는 B의 새 기록·참조와 일부 child 선택이 있는 상태에서 실제 제공된 전체 원본 증거의 삭제→동일 child 재등장을 검토한다. 원본 자체의 변화가 필요하면 root가 별도 소유한 기존 로컬 factory 시뮬레이션 계약을 사용한다. 저장 envelope·snapshot을 직접 덮거나 기존 fixture를 수정하지 않는다. 읽기 전용으로 현재 증거만 확인한 것은 새 원본 변화의 실제 실행으로 세지 않는다. 자동 재연결 0, 정확한 child만 제외/명시 복원, 과거 기록·참조·다른 child 보존과 구성 Undo의 범위를 확인한다. 전체 Map 비우기·새 child 생성 등 미승인 계약은 추가하지 않는다.

마지막으로 `F-note`만 명시 철회한다. 공개 목록 변화와 기존 고정 판본·사본·개인 기록·활동 복귀를 확인하고 `F-week`는 유지한다. 철회를 영구 삭제로 보거나 재공개 정책까지 확대하지 않는다. 이는 첫 루프의 제작물 공개와 다른 독립 개인 문서의 종료 목적이다.

## 기록할 증거와 평가 기준

각 목적 작업은 하나의 immutable 실행 기록에 시작/끝 state·runtime·행동별 실제 결과를 남긴다. 새 파일은 경로·bytes/SHA와 미리보기 결과를 함께 저장한다. UI 선택·포커스·caret/selection range·문서 내부 및 window scroll·현재 route·필터는 저장 데이터와 별도의 화면 증거로 기록한다. 화면 복귀에 따라 정상 변경되는 위치 필드를 기존 전체 데이터 불변 비교에 무조건 섞지 않고, 해당 UI 행동으로 허용한 위치 delta를 정확히 지정한다. raw의 공백/줄바꿈 전체 trim이나 제목 기반 매칭은 금지한다.

허용 delta는 각 거래 전에 실제 모델의 owner와 receipt 기준으로 정한다. 새 생성은 ID 집합의 예상 추가만, 편집은 지정 필드/행만, 삭제는 지정 QA 개체의 tombstone만, Undo는 실제 직전 거래만 허용한다. 새 공개 사본이 `text.flows`를 정상 추가하는 것을 이전 배열 전체 동일 검사로 막지 않으며, 반대로 전체 배열을 검사에서 빼지도 않는다. 기존 entry 불변과 예상 신규 entry 수·fingerprint를 함께 확인한다. 읽기·취소·중복·실패는 성공 쓰기 0, 허용 namespace 밖 시도는 0이어야 한다.

평가는 `충족 / 부분 / 실패 / 미실행`으로 기록하고 각 판단에 화면 또는 거래 증거를 붙인다.

- 목적 달성: 파일만 받기·개인 기록만 쓰기·경험 없이 실행·선택 공유 각각에서 불필요한 다음 단계가 강제되지 않는가.
- 다음 행동과 맥락: 현재 원본/사본/날짜·선택한 결과와 다음 조작을 찾을 수 있는가. 원래 글·문서·회차로 돌아왔는가.
- 입력 부담: 같은 내용을 재입력했는가, 필수 정보와 참고 설명이 구분되는가, 긴 본문/비교 때문에 핵심 행동이 가려지는가. 관측한 행동·대기만 기록하며 가상 선호/완료 시간은 만들지 않는다.
- 복구: 실패 뒤 입력·선택과 이미 성공한 저장을 구별하는가. 정상 저장을 다시 누르게 하지 않는가. 취소/Undo가 무엇을 되돌렸는지 실제 자료로 확인할 수 있는가.
- 공개 경계: 선택 외 raw·개인 메모/날짜/진행·다른 owner의 입력이 새 공개물·주소·history에 없는가. 사진/근거는 기존 개체의 허용 상태 그대로인가.
- 모바일·키보드: 375/390, 1024×768/1194×834, 1440 크기에서 해당 목적의 핵심 행동·오버레이·가로 넘침·실제 hit 영역을 확인한다. 좁은 높이의 비교는 세로 스크롤을 허용하되 버튼이 가려져 조작할 수 없는 상태와 구별한다. 모든 행동을 모든 크기에 반복하지 않고 각 크기에 대표 경계를 배분한다.

## 실패 보존과 두 번째 개선의 종료

첫 실행 전에만 전제를 확인하고, 쓰기가 한 번이라도 발생하면 최초 runner를 처음부터 다시 돌리지 않는다. 실패 artifact, 마지막 readback raw/hash·revision, 생성한 정확한 ID, 미제출 입력·비교 선택·dirty 상태·화면 위치를 보존한다. 저장 완료가 늦으면 먼저 readback과 receipt를 읽고 중복 요청을 보내지 않는다. 제품 결함, QA selector/비교 가정 오류, 현재 지원 밖 의미를 분리한다. 실패 지점에서 시작하는 별도 tail은 새 predecessor와 허용 delta를 root가 읽은 뒤 실행한다.

실제 변화나 보호 fingerprint가 예상과 다르면 해당 profile mutation을 멈춘다. 같은 profile의 독립 경로도 보호 상태가 확인되기 전에는 진행하지 않는다. 원래 데이터가 온전한 다른 profile의 독립 읽기·준비는 가능하다. 기능 누락을 메모로 바꾸거나, 현재 private 값을 기준값으로 고쳐 충돌을 없애거나, 초기화/이력 축소로 성능·용량 실패를 숨기지 않는다.

네 목적 작업을 한 번 평가한 뒤 영향이 큰 실제 필수 문제부터 개선한다. 한 번의 수정 묶음은 우선순위 상위 1~2개로 제한해 원인·수정·같은 자료 재확인을 연결하되, 나머지 필수 문제를 완료 처리하지 않는다. 새 문제가 없으면 개선 효과 재평가와 잔여 근거를 남기며 두 번째 “재수정 완료”를 꾸며내지 않는다. 첫 루프에서 발견한 결함의 표적 재실행만으로 두 번째 평가를 대체하지 않는다.

마지막 소스가 바뀌면 같은 최종 build/route에서 S01~S10 핵심 왕복 증거를 모은다. 변경마다 과거 수백 확인점을 전부 반복하지 않는다. 이 문서의 목적별 신규 경로, 기존 근거 중 영향받는 경계, 최종 10행 연결을 구분한다. 미해결 핵심 목적·데이터 손상·개인 노출·중대 회귀가 있으면 전체 완료는 불가하다. 원래 npm 출처 기한·의존성 실패와 별도 권한 경계도 [현재 검증](current-validation.md)에 따라 남긴다.

이번 계획과 이후 자동 UI 시뮬레이션은 관찰 사용자 평가가 아니다. 실제 Android/iOS·OS 입력기·보조기술·외부 계정 왕복은 수행했을 때만 별도로 보고한다. 현재 이 계획의 브라우저 실행 0, 실기기·관찰 사용자 검증 0이며 어떤 목적도 통과로 주장하지 않는다. 새 기능/운영 정책·실제 외부 게시·계정 변경·commit/push/PR/배포 권한은 추가하지 않는다.
