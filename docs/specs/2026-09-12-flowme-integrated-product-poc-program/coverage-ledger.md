## 1. 판정 기준과 시간 경계

승인 정본 (로컬 전용 근거: `../../../../flow-text-integration-plan-20260908/docs/specs/2026-09-12-flowme-integrated-product-poc-program/spec.md`) §3·§6·§7을 [개발 실행 계약](spec.md)의 P01~P08에 연결한다. [실행 순서](plan.md)는 순서, [진행 원장](progress.md)은 시점별 실행 기록이다. 아래 세부 ID는 추적용이며 새 요구나 종료 조건이 아니다.

- **구현**: 현재 파일에 기능·가드가 있는가. 테스트 파일이 있다는 사실과 실행 통과는 별개다.
- **연결**: exact gate의 현재 React 소스에서 해당 함수·화면까지 이어지는가. 연결된 소스가 실행 중인 빌드에 들어 있다는 뜻은 아니다.
- **검증**: 어떤 입력·빌드·저장 상태에서 실제 확인했는가. 단위/SSR, 브라우저, 실기기, 관찰 사용자를 구별한다.
- **정본 충족**: 요구 전체의 정상 경로와 취소·오류·재진입까지 같은 통합판에서 확인했는가. 부분 성공이나 테스트 수로 충족률을 만들지 않는다.
- **부분**은 확인한 하위 결과가 있다는 뜻이다. **미충족**은 확정 요구의 구현/연결이 남았다는 뜻이며, **미검증**은 코드만으로 통과를 판정할 수 없다는 뜻이다.

아래 최초 표의 production build는 **07:43:32~07:44:13 UTC**에 성공한 과거 판이다. 그 당시 확인 근거는 진행 원장과 E3이며, 이후 추가된 입력 잠금/외부 변경 보호·정확한 답글/판본 이동·개인 출력·기존 실행 transaction 등을 당시 검증에 소급하지 않는다. 최신 실행판과 후속 소스의 차이는 위 최신 대응과 current-validation을 따른다.

기존 세 축을 새 UI 존재 여부로 합산하지 않는다. 원본 요구의 연결 근거는 [K4 gate의 세 원본 대응표](../2026-09-05-flowme-integrated-poc-gap-implementation-v1/k4-implementation-gates.md), [CreatorDraft 계약](../2026-09-03-flowme-integrated-poc-creator-draft-library-v1/spec.md), 승인 정본 §8이다.

| 원본 축 | 현재 재사용·보존 | 아직 동등하게 연결/검증하지 않은 범위 |
| --- | --- | --- |
| 개발1 개인 계획·이사/여행 | catalog의 기존 이사24·여행6, source metadata/raw snapshot, 개인 사본 선택·anchor·기간 실행 | 개발2 이사27과 같은 Flow의 v2로 취급하지 않음. 기존 저장 사본 전체/구간 포함·복원, 개인 기준일과 원문·fixed 실행 날짜 영향, 반복 회차 선택, Map owner 조건까지 새로운 공개 사본의 선택 기능으로 대체할 수 없음 |
| 개발2 작성·결과·CreatorDraft | owner parser/validator, 기존 초안 read-only library, current와 실제 one-Undo raw 가져오기, 새 문서 checkpoint | 기존 작성 중 draft/CreatorBinding, 결과 탭/템플릿/출처·첨부·Step/Item·원문 속성 편집, 명시 저장·복제·이름 변경·보관/복원, 다시 결과→개인 인계까지 기능별 접점 필요. 개인 문서에 raw를 가져오는 경로는 기존 제작 도구 전체 수명주기와 다름 |
| 개발3 v4.1 실행·K1~K3·v11 원문 편집 | exact-query, tuple identity, old read model·실행 renderer, v11 model/editor 소스, snapshot/개인 transaction | 반복/Map/source lifecycle 및 원문 전체 조작 보존을 각 owner별 검증. 과거 HTML/차단된 wrapper를 새 앱처럼 실행하지 않으며, 그 소스 재사용과 캡처 참고를 브라우저 동등성으로 계산하지 않음 |

ProgramLegacyWorkspace의 현재 `support` 안내도 기존 제작·원본 갱신, 삭제·휴지통, QuickItem 문서 간 이동, 반복 회차, 검토 대기 Map의 미연결을 명시한다. 읽기 보존·정확한 미지원 안내는 데이터 유실을 막는 중간 결과이며, 기존 제품 기능을 모두 유지했다는 완료 근거가 아니다.

## 6. 별도 검토 제안과 종료 전 행동

다음은 이번 원장에서 제품 정책으로 확정하지 않는다.

- 문서 폴더 이동을 내부 모든 task의 실제 소속 이동으로 해석할지: 현재의 문서 분류·task owner·기간 순서 계약을 먼저 설명하고, 동작 변경은 별도 판단한다.
- 같은 Flow의 **새 실행(run)** 생성·진행 초기화: 현재 재가져오기 중복 방지/기존 실행 재진입과 다른 정책이다. 새 run을 자동 생성하거나 과거 기록을 지우지 않는다.
- 앱 전체 백업/복원·기기 간 이동: 원문/선택 실행 출력과 별개다. 백업 포맷·암호화·병합/복원 정책은 미승인 제안으로 둔다.
- 공개 철회 후 재공개 정책: 현재 보관 원본의 고정판본 읽기와 catalog 제외·새 가져오기/출력 제한을 유지한다. 링크 보존을 재공개 권한으로 해석하지 않는다.

다음 실행자는 먼저 위 미충족 범위의 owner와 연결 지점을 확정하고, 최신 소스의 표적 검사·전체 회귀·새 production build를 기록한다. 그 판에서 S01~S10을 시작/행동/도착/상태/취소·오류·복귀 단위로 실행하고, 발견한 문제→수정→재검사를 남긴다. 이어 처음 쓰지 않은 구조·목적의 추가 상황으로 두 번째 평가·개선을 수행한다. E1~E3의 부분 성공을 두 번의 전체 개선 루프로 재계산하지 않는다.

최종 보고 전에는 운영 저장소가 채워진 격리 fixture의 허용 prefix 밖 bytes와 실제 writer 호출, 실패/충돌의 no-write, 주요 크기·키보드·오버레이, 결과 파일 bytes를 함께 확인한다. 실기기·관찰 사용자·외부 계정 검증의 미수행은 별도로 적는다. commit/push/PR/merge/Preview/Production 배포·실제 게시/전송은 이 원장의 승인 범위가 아니다.
