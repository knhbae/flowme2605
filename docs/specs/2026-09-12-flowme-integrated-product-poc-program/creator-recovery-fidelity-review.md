# 제작 working·임시복구·sidecar 요구 대조

2026-09-15 소스·정본 읽기 감사. [S10 기존 제작기 검증](s10-legacy-creator-gap.md)의 마지막 잔여 범위를 구체화한다. 이 감사에서 제품 검사 실행, 브라우저 접근·조작, 프로필 변경은 모두 0이다. 아래 테스트와 브라우저 결과는 기존 소스와 불변 원장을 읽은 근거이며 이번 실행 결과가 아니다.

## 판정 기준

[승인 P06](spec.md#L23)의 기존 제작기·초안 보관함 재사용과 저장 판본 복구를 유지한다. [재사용 충실도 검토 29–31행](reuse-fidelity-review.md#L29)은 전체 document 복구와 StructureDraft 빈 원문 복구·연결 해제를 명시한다. 잘 동작하는 현재 raw-only 경로로 요구를 줄이지 않는다.

현재 Program working 복구, 원래 D2 저장 판본 복구, 옛 D2 임시복구본 인계는 다른 계약이다. 현재 UI의 미지원 안내만으로 원래 기능을 보류나 범위 밖으로 재분류하지 않는다. 반대로 모든 옛 저장 key를 자동 migration하거나 복구본을 자동 병합하는 정책도 추가하지 않는다.

## 다음 실행 순서와 보호 경계

1. **현재 native 미반영 입력의 실제 UI 복구를 확인한다.** 실제 native owner의 canonical raw·명시 저장본과 다른 pending raw를 UI에서 입력한다. 보관 성공 후 화면 이동/reload에서 같은 draft·owner·미반영 입력이 이어지는지 확인하고 비교 취소·명시 반영을 분리한다. 실패 때 입력을 보존하며 중복 요청하지 않는다. native 검토 정보·기존 원문 identity·sidecar·개인 실행·공개 상태의 허용 변경과 불변 집합을 실행 전에 고정한다. 현재 주간 제작 흐름의 근거와 연결하되 단순한 새 raw 문서 저장으로 대체하지 않는다.
2. **옛 복구본의 명시 읽기·선택·인계 요구를 설계한 뒤 구현·검증한다.** 마지막 저장 이후 복구본과 첫 저장 전 복구본, 정확한 draft/recovery/revision, 명시 저장본과의 차이 및 원래 UI 단계/선택 맥락을 읽는다. 지원 가능한 실제 payload인지 먼저 확인한다. 사용자가 고른 복구본만 Program의 작성 중 상태로 인계하며, 옛 명시 저장 이력을 복구본으로 덮거나 복구본을 가짜 명시 저장으로 꾸미지 않는다. 읽기/닫기0쓰기, stale/손상/취소/저장 실패 보존, 성공 거래와 재시도, 재진입을 별도 검증한다. 구체적인 UI·저장 계약은 이 요구 설계 뒤 고정하며 여기서 자동 병합 정책을 확정하지 않는다.

두 단계 모두 운영 저장 key writer, 원본 key 수정·삭제, 자동 migration, 누적 프로필 reseed/reset은 금지한다. 옛 sidecar import가 필요해지는 경우 실제 남은 자료와 승인 요구를 먼저 대조한다. 현재 sidecar 기능을 다시 만들거나 읽을 수 없는 옛 상태를 임의 변환해 PASS로 만들지 않는다.

이 문서는 요구 대조 원장이다. 전체 S10, 두 번째 전체 루프, 기존 제작기 전체 동등성, 실기기·관찰 사용자 검증 완료를 선언하지 않는다. 제품 테스트·브라우저 검사의 이번 실행 수는 0이며, 문서 정적 검사는 별도 기록한다. 후속 갱신 조건은 위 1단계 실제 UI 결과 또는 2단계의 명시 계약·구현·검증 근거가 생길 때다.
