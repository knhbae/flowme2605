## 현재 코드의 접점

- [원래 factory](../../../lib/flow/source-backed-my-flow.ts)는 `repeat_rule`을 `calendar.repeatRule`로 보존한다. 반복 의미를 실제 기존 데이터에서 읽을 수 있다.
- [structured 원본 판본](../../../lib/flow/integrated-poc/legacy-map-source.ts)은 실제 snapshot/persistence/bundles와 saved-copy/Flow/Step tuple을 보존한다.
- [lifecycle의 readRevision](../../../lib/flow/integrated-poc/legacy-source-lifecycle-contract.ts)은 structured 판본에서 빈 `contexts`를 반환한다. 따라서 정확한 규칙은 원본 증거에 남아도 개인 계획의 `attributes.recurrence`로 이어지지 않는다.
- [개인 계획 reader](../../../lib/flow/integrated-poc/program-legacy-plan.ts)는 그 context의 recurrence를 읽는다. 원본이 있기만 한 것과 개인 회차·기준일 변경·기록·출력으로 동작하는 것은 다르다.

이 진단은 규칙이 실행 연결에서 빠진 것을 보여준다. 전체 화면에서 사용자가 어떤 결과를 보게 되는지는 아직 별도 브라우저 증거가 필요하다. 기존 작성형 반복이나 합성 Map 그룹 검사로 이 실제 원본 연결을 통과 처리하지 않는다.

## 다음 구현·검증 순서

1. 원본/기존 개인 설정/Program 개인 계획의 규칙과 날짜 소유를 먼저 대조한다. 특히 ALLBLANC의 요일은 기존 quality decision에서도 사용자 일정 설정으로 구분된다. 이를 영상 원문의 고정 일정이라고 표시하지 않는다.
2. 실제 structured 근거를 입력으로 하는 반복 reader/adapter와 음성 회귀를 만든다. 기존 expander·bounded 조회·정확 identity·취소/실패/Undo 계약을 재사용한다. 가짜 TXT·Creator 판본·공개 판본이나 제목 기반 연결을 만들지 않는다.
3. 개인 기준일·회차 선택·기간 보기·완료/다시 열기·기록·출력을 같은 owner로 연결한다. 원본 변경·항목 제외/재포함·다른 문서 참조·Undo/reload에서 지난 기록을 보존한다.
4. 위 실제2-child Map과 다른 주기의 단일 Map을 별도 상황으로 검증한다. 원문 근거/품질 보류를 수정하거나 해제하지 않는다. 모델 근거와 브라우저6크기/키보드/저장 경계 근거를 나눠 남긴다.
5. 전체 신규/관련 기존/npm/build와 운영 저장소 불변을 다시 확인하고 요구 원장·캡처 보고를 갱신한다. 이것은 전체 P01~P08/S01~S10와 두 개선 루프 중 하나의 갭 처리다.

새 작성기를 만들거나 원래 운영 key/schema를 고치는 작업이 아니다. 원본 `repeat_rule`을 임의 확대 지원하거나 종료 조건을 만들어 넣지 않는다. 미지원 규칙·불명확한 날짜/소유·손상은 그 근거와 입력을 남기고 실행을 거절한다. 실제 기기·외부 계정·관찰 사용자·공개 배포는 별도 경계를 유지한다.
