# 일반 일정의 시간·시간대 통합

2026-09-14 · 일반 시간 연결 구현과 실제 여행 공개/사본/파일 대조를 수행했다. [결과·남은 범위](ordinary-publication-time-review.md), [최신 판정](current-checkpoint.md)을 따른다. 아래는 실제 손실에서 도출한 설계 계약이다.

## 원래 요구와 재현

개발2 여행 작성 틀의 `공항에서 숙소로 이동`에는15:00·Asia/Tokyo가 있다. 실제 보존 작성물 검사 (로컬 전용 근거: `../../../output/playwright/integrated-program/ordinary-time-before-2026-09-14T08-38-48-347Z.json`)는 vJ949의269→270에서 같은 문서의 공개 초안만 만들고 원문/개인/이전판을 유지했다. 일반 공개 일정에는 날짜 외 시간 필드가 없어 정체성을 보존한 구조화 전달이 불가능하다. 기존 반복의 시간 지원이나 첫 항목의 성공으로 이 차이를 가리지 않는다.

## 설계와 구현 순서

1. Program 전용 선택 계약 `timing:{version:1,time,timeZone}`을 일반 공개 일정에 추가한다. 시간은HH:mm 또는null, 시간대는 검증된IANA 문자열 또는null이다. 시간대 없는 시각은 기존 출력처럼floating이며 임의 기기/UTC 시간대를 채우지 않는다. 날짜 없는 시간도 원문 정보로 보존하지만 미정 ICS는 기존처럼 제외한다.
2. 일반 공개 초안은 같은 version1의 문자열 입력을 별도 보존한다. 잘못된 입력도 비공개 초안에서 복구하되 공개는 거절한다. 원문 시간·시간대 가져오기는 현재의 명시 필드 비교에 추가하며 기본 미선택이다. 개인 시간/날짜/메모에서 원문 후보를 만들지 않는다. 원문 날짜와 공개 날짜 선택은 별도다.
3. 공개 whitelist·새판/제안/비교·사본 읽기·TXT/CSV/ICS·정확 복귀를 연결한다. 시간대 변환과 ICS folding은 기존 검증된 출력 도구를 재사용한다. 없는 종료시각·기간을 만들지 않는다. 이전 필드가 없는 판본/초안은 그대로 읽고 읽기만으로 migration·저장하지 않는다.
4. 사본 최초 가져오기는 원문 시간을 개인 시간의 시작값으로 제공한다. 이후 원문 일정 수용은 기존 개인 날짜/시간을 자동 덮지 않고 원문 시간·시간대와 개인 실행을 구별한다. 출력은 개인 시간에 수용한 원문 시간대 근거를 사용하며 원문 시간과 다른 값도 표시한다. 개인 시간대 편집/복합 충돌 정책을 새로 확정하지 않는다.
5. 실제 원래 여행 문서/초안270을 이어 시간 선택·명시 공개 날짜·미리보기·새판·개인 사본·실제3파일·복귀/Undo/reload를 확인한다. 취소·같은 값·잘못된 시간·실패/재시도와 이전 개인/공개 불변을 검사한다. 작은 화면과 키보드를 함께 확인한다.

변경은 소유한 integrated-poc 모듈과 이 spec/검사에 한정한다. 기본/my·원래 제작기vendor·운영writer/key/schema와 과거 source DTO는 바꾸지 않는다. 이 작업은 일반 시간의 연결이며 전체Map/복합충돌/전체10상황·두전체개선의 완료를 뜻하지 않는다.
