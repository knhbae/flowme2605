# 반복의 표시·출력 연결 D — 실행 설계

2026-09-14. [전체 반복 설계](recurring-publication-design.md)의 D를 구현한다. 현재 반복 공개 허용은 닫혀 있으며 출력만 통과했다고 공개나 전체 목표를 완료하지 않는다.

## 먼저 재현할 손실

현재 public `output.ts`는 recurring을 날짜 미정으로 처리한다. TXT/CSV에서 규칙·시간대가 사라지고 ICS에서는 항목이 빠진다. 공개 상세도 같은 항목을 날짜 미정으로 표시한다. C3의 개인 시작·회차 실행 검증은 이 경로의 증거가 아니다.

## 출력 계약과 UX

- 공개 원본은 한 typed 반복 항목으로 보존한다. TXT/CSV는 시작 미정이어도 전체 규칙·종료 조건·시간·시간대를 남긴다. 사용자의 시작일 입력은 무저장 개인화 값이며 공개 원본을 바꾸지 않는다.
- 캘린더 출력은 명시한 범위에서 기존 D2 계산기가 만든 실제 회차를 한 VEVENT의 DTSTART/RDATE 집합으로 전달한다. 원래 반복 규칙과 출력 범위를 설명 및 버전 표식에 남긴다. 끝없는 반복 전체를 출력했다고 표시하거나 이 집합을 공개 원본 정의로 저장하지 않는다. 범위 밖 회차는 다른 범위를 선택해 출력할 수 있다.
- 범위 계약은 교체 가능한 version 1이다. 종료가 있는 반복은 회차 offset/limit, 종료가 없는 반복은 주 offset/길이를 사용한다. 계산 자원 한도는 기존 public recurrence window를 재사용하며 초과 입력은 자르지 않고 거절한다.
- 명시 시작일이 요일 규칙과 달라도 원래 첫 회차를 유지한다. 일반 RRULE로 바꾸면 날짜가 달라질 수 있으므로 무검증 치환하지 않는다. RFC 5545 §3.8.5.3의 DTSTART/RRULE 불일치 및 §3.8.5.2의 RDATE 집합을 근거로 한다: https://datatracker.ietf.org/doc/html/rfc5545
- 시간 없는 항목은 종일, 시간만 있는 항목은 floating local time, 명시 시간대가 있는 항목은 각 회차의 실제 UTC 시각으로 출력한다. 이름 있는 시간대를 브라우저 현재 시간대로 대체하지 않는다. DST 중복 시각은 첫 발생, 존재하지 않는 시각은 전환 전 offset이라는 RFC 5545 §3.3.5 의미를 검사한다. 원래 벽시계 시간·시간대도 파일에 남긴다. 없는 기간/알림/완료를 만들지 않는다.
- 같은 판본·항목·시작·범위의 출력 identity는 안정적이며 서로 다른 범위의 파일이 같은 UID로 서로 덮이지 않게 한다. source/개인 실행 판본과 출력 identity는 구분한다.
- 공개 상세는 원래 규칙과 실제 개인화 시작을 구별한다. 선택한 반복이 있을 때만 출력 범위 입력과 실제 회차 수를 표시한다. 일반 항목의 기존 파일 bytes와 UI를 바꾸지 않는다. 취소/실패/뒤로 복귀에서 선택을 보존한다.

## 검증과 후속 연결

손실 재현 → 순수 출력·날짜/월말/종료/시간대/범위/손상/보안 회귀 → 공개 상세/개인 사본 소비 경로 → strict·전체 검사·build → 보존 C3 자료의 실제 파일·5크기·키보드·쓰기 경계 확인 순서다. 실제 외부 계정 import와 실기기 관찰은 별도 미실행이다. 원본 비교/수용·제안 D와 실제 공개 E도 별도 남겨 전체 목표를 유지한다.
