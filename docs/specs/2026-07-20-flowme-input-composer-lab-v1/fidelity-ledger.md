# Concept fidelity ledger

검토 대상은 `concept-desktop.png`와 생성된 판단용 HTML의 첫 화면이다. 최종 화면은 concept의 장식보다 실제 source-backed 데이터와 입력 경계를 우선했다.

## 유지한 구조

| 비교점 | Concept | 구현 | 판정 |
| --- | --- | --- | --- |
| 작업대 | 좌측 경로, 중앙 입력, 우측 결과 | 동일한 3열 구조 | 유지 |
| 입력 경로 | 4개 경로 | 한 줄, 여러 줄, URL, 표·강의계획 | 유지 |
| 예시 선택 | 좌측 실제 사례 목록 | 8개 source-backed 사례 | 확대 |
| 출처 확인 | 초록색 원문 확인 줄 | 출처 제목, URL, 확보 범위 표시 | 유지 |
| 최소 입력 | 이사일 1개를 먼저 요청 | 사용자 단계에서 이사일 1개 | 유지 |
| 결과 전환 | Calendar/Checklist/Todo/Sheet/Memo | 동일한 5개 projection 탭 | 유지 |
| 입력 비용 | 사용자 입력과 원문 값을 구분 | 사용자 입력, 원문 묶음, 실행 Item 수를 분리 | 강화 |

## 첫 화면 문구 비교

| 위치 | Concept | 구현 | 변경 이유 |
| --- | --- | --- | --- |
| 상단 설명 | `FlowMe Input Composer Lab 베타` | `입력 실험 · 판단용 시제품` | 내부 제품명보다 검토 상태를 먼저 알림 |
| 제목 | `이사 준비 Flow 만들기` | `이사 D-day Flow 만들기` | 날짜 역산 결과를 제목에서 예고 |
| 필수값 | `이사일 *` | `이사일 / 첫 결과에 필요` | 별표 대신 필요한 시점을 설명 |
| 출처 줄 | 일반적인 공식 페이지 설명 | 실제 원문 제목, URL, `6개 확인` | 확보한 범위를 검증 가능하게 표시 |
| 행동 | `결과 미리보기` | 결과 preview를 즉시 갱신하는 동일 의미 행동 | 유지 |
| 하단 계수 | `내가 입력 1 · 원문에서 채움 24` | `내가 입력 1 · 원문에서 채움 4묶음 · 실행 항목 24` | source 묶음과 Item 수를 혼동하지 않게 분리 |

## 의도적으로 달라진 점

- Concept의 단일 이사 사례를 8개 사례 전환이 가능한 workbench로 확장했다.
- K-MOOC와 LibriVox는 체크리스트가 아니라 전체 행을 펼치는 진도 Sheet로 구현했다.
- 세탁조 관리는 월간 Calendar가 아니라 원문 조건에 반응하는 Todo로 구현했다.
- 폭염 대응과 로그인 원문 부족 사례는 그럴듯한 가짜 artifact 대신 blocked boundary를 표시한다.
- 모바일에서는 경로·사례 목록만 내부 가로 스크롤을 허용하고 문서 자체의 가로 overflow는 없앴다.

## 시각 확인 결과

- 데스크톱: 좌·중·우 열이 겹치지 않고 첫 viewport에서 입력과 Calendar 결과가 함께 보였다.
- 모바일 390px: `입력 경로 → 사례 → 입력 composer → 결과` 순서로 한 열이 되며 문서 overflow는 0이었다.
- 날짜 input은 보이는 `이사일` label과 연결되며, 선택형 입력은 이름이 있는 group으로 노출된다.

이 비교는 화면 구현 충실도와 에이전트 검토 결과이며 실제 사용자 사용성 검증을 뜻하지 않는다.
