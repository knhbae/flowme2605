# 개인 문서의 같은 요청 저장 복구 확인

2026-09-30. 사용자 승인: 저장 결과 표시 문제를 먼저 수정·검증한 뒤 직전 핵심 UX 개선과 이번 소유 변경만 커밋·푸시한다. 개발계 런타임 교체·배포는 별도 승인 대상이다.

## 목표와 경계

- 결과 미확정 저장을 같은 요청으로 확인한 뒤, 서버에 반영된 **그 입력**만 현재 문서 편집기에 저장됨으로 확인한다.
- 요청 ID/kind, 계정, 예상 판본과 receipt 판본, 전체 개인공간 변경, 공개 context 불변을 대조한다. receipt 이후 다른 판본은 확인 처리하지 않는다.
- 편집기는 제출 스냅샷과 현재 workspace/raw/입력 세대가 같고 저장 중·invalid·IME 조합 중이 아닐 때만 baseline/dirty/error를 갱신한다. textarea 교체·재마운트·입력 덮어쓰기는 하지 않는다.
- 실제 외부 변경, 더 새 입력, 반복 설정과 다른 편집기의 미저장 입력, 다른 계정 및 기존 충돌 보호를 유지한다.
- 합성 fixture만 쓴다. 실제 계정/DB/Auth/개인 파일과 기존 3105 앱·20249 Tunnel·일반 .next는 변경하지 않는다.
- 기존 dirty는 근거로 소유가 입증된 hunk만 게시한다. build/output/원본 증거/비밀 값은 제외한다. 푸시의 자동 배포 안전성을 확인하지 못하면 푸시는 보류한다.
- 모바일 밀도·문서 구조 키보드 계약·기존 6~9/5D 후속은 이번 구현 범위가 아니다.

## 종료 조건

같은 요청 복구 전후 operation/revision이 한 번만 증가하고 현재 편집기 저장됨·충돌 없음이 확인된다. 이미 서버 반영된 receipt lookup, 추가 입력/조합/실제 외부 변경 보호를 구분해 검사한다. 관련 회귀·npm test·격리 production build·문서 검사를 기록하고 소유 변경의 게시 상태 및 남은 게이트를 각각 보고한다.

## 게시 선행 작업 승인 — 9/30 후속

사용자는 `선행 보안·출처 검증 해결 포함` 및 `계속 진행`을 승인했다. 기존 혼합 worktree의 관련 dirty를 통째로 가져오지 않고, clean candidate에서 소비자별 의존성 보안·API 호환과 기한이 지난 기존 Flow 6건의 원문 대조를 별도 소유 변경으로 해결한다. 감사 임계값·현재 날짜·공개 노출·의료 실행 보류는 유지한다. 근거는 [보안 기록](./security-prerequisite.md)과 [원문 대조 기록](../../content-audit/2026-09-30-core-ux-publish-source-review.md)에 남긴다.

CI 경로 질문 뒤 사용자의 `더 나은 선택으로 진행`에 따라 기존 PR #204의 head를 기준으로 새 브랜치와 별도 Draft PR을 사용한다. 기존 PR의 범위·main·호스팅 설정을 변경하지 않고 merge·배포도 하지 않는다. 비공개 CI의 기존 검토 승인 절차는 우회하지 않는다.

## 후속 테스트·게시 승인 — 10/1

사용자는 `해당 테스트 보완·후속 게시·CI 허용`을 승인했다. 같은 목표의 회귀 보완·후속 commit/push·기존 비공개 CI는 반복 승인 없이 진행한다. 현재 화면의 버튼·관리 메뉴 동선에 테스트를 맞추고, 과거 월간 예시의 날짜만 고정해 기존 상세 검증을 유지한다. skip·전역 timeout 확대·검증 기준 완화·CI 승인 규칙 변경은 하지 않는다. merge·배포·DB 변경·접근 범위 확대는 이 승인에 포함하지 않는다.

두 번째 CI에서 확인한 frozen catalog 비교 회귀도 이 승인 범위에서 보완한다. 9월23일 고정 원본을 현재 seed와 영구 동일하다고 보는 테스트 가정만 수정한다. 승인된 여섯 출처의 정확한 과거/현재 날짜와 업체 URL·파생 type을 대조한 뒤 나머지 전체 내용 hash를 비교한다. 원본 pack·version·seal·validator·현재 날짜 freshness·공개 정책은 변경하지 않는다.
