제품 코드 반영 전 정리

기존 제품은 무엇이었고, 지금 새 UX는 무엇을 반영하려는가

My Flow에 새 UX를 바로 덮어쓰기 전에, 기존 제품의 역할과 새 PoC에서 얻은 판단을 분리해 정리한 문서입니다. 결론은 단순합니다. 기존 제품은 public Flow, 저장, 실행, export, 리뷰 경로가 이미 꽤 갖춰져 있고, 새 UX는 그것을 대체하는 화면이 아니라 저장한 Flow를 더 쉽게 관리하고 실행하게 만드는 정렬 레이어입니다.

대상: My Flow / public Flow / creator surface 기준: Flow Map > Flow > Step > Item 상태: 제품 반영 전 정리 근거: PR #114, v11 PoC
핵심 결론 기존 제품 새 UX 방향 다음 반영 순서

핵심 결론

지금 반영하려는 것은 새 앱을 만드는 일이 아닙니다. 기존 FlowMe의 public route, 저장된 Flow, export, content review 체계를 유지하면서 사용자가 저장한 Flow를 오늘 할 일, 일정, Flow, 지도 단위로 더 명확하게 실행하게 만드는 UX 정리 작업입니다.

기존 제품은 무엇이었나

Public Flow

원컨텐츠를 실행 가능한 Flow로 보여주는 화면

예: 전세계약 점검, 이사 D-30, 생활 체크리스트. 사용자는 원문을 보고 저장할 수 있고, 화면에는 일정, 체크, 메모, URL 같은 실행 단서가 남아야 합니다.

My Flow

저장한 Flow를 다시 찾아 실행하는 공간

기존 제품에도 내 Flow, 저장, 진행, 항목 확인 흐름이 존재합니다. 다만 여러 Flow가 쌓였을 때 무엇을 오늘 해야 하는지, 어느 Flow의 어느 Step인지가 덜 선명했습니다.

Export / Data

캘린더, 투두, 메모로 나갈 수 있는 데이터

Step은 외부 앱에 저장될 수 있는 최소 단위이고, Item은 FlowMe 내부에서는 체크리스트로, 외부 앱에서는 일정 description이나 메모 텍스트로 내려갈 수 있습니다.

왜 새 UX 정리가 필요했나

문제 1

검토용 화면과 사용자 화면이 섞였습니다

이전 PoC 일부는 source fit, 평가, 개발자용 설명 같은 내부 판단이 사용자 화면에 남아 있었습니다. 사용자는 이런 설명이 아니라 저장 후 바로 실행할 항목을 봐야 합니다.

문제 2

Flow 구조와 화면 구조가 흔들렸습니다

어떤 화면은 단일 Flow처럼 보이고, 어떤 화면은 Flow Map처럼 보였습니다. 이 때문에 Step, Item, 메모, 일정이 어느 깊이에 속하는지 판단하기 어려웠습니다.

문제 3

원문보다 복잡해지는 경우가 있었습니다

진행 페이스, 불필요한 상태 버튼, 반복되는 안내 문구가 들어가면서 원컨텐츠를 Flow화한 결과가 오히려 더 무겁게 느껴지는 문제가 있었습니다.

문제 4

여러 Flow를 저장한 상태가 부족했습니다

실제 사용자는 Flow 하나만 저장하지 않습니다. Step이 하나인 Flow도 있고, 10개 이상인 Flow도 있습니다. My Flow는 이 차이를 담아야 합니다.

지금 반영하려는 UX 방향

Flow Map 여러 Flow를 담는 상위 지도. 예: 중1 수학 전체, 영유아 검진/접종 관리.
Flow 사용자가 저장하는 실행 묶음. 예: 정수와 유리수, 4-6개월 검진.
Step 캘린더/투두/시트에 저장되는 최소 실행 단위.
Item Step 안의 체크 항목 또는 description에 들어갈 세부 메모.
사용자 화면

오늘 먼저 할 일, 일정, Flow, 지도

사용자는 저장한 Flow를 오늘 실행할 Step 중심으로 봅니다. Flow 이름과 Map 이름은 맥락으로만 보여주고, Step을 누르면 같은 자리에서 Item이 열려야 합니다.

제작자 화면

내 콘텐츠가 어떤 Flow 구조로 저장되는지 확인

제작자는 URL과 원문 구조를 바탕으로 Flow Map, Flow, Step, Item을 확인합니다. 사용자 화면처럼 단순해야 하지만, 원문 근거와 저장 결과 미리보기는 필요합니다.

PR #114는 어떤 의미인가

PR #114는 최종 제품 UX가 아니라 제품 반영을 위한 브리지입니다. source-backed Step contract, export 경계, My Flow v11 PoC, 리허설 리포트를 묶어 “원문 기반 Flow를 My Flow에서 어떻게 실행할 수 있는지”를 증명하는 근거입니다.
  • source-backed-step-contract.md: Step/Item 저장 경계와 export 의미를 정리한 계약 문서.
  • v11 사용자 PoC: 저장한 Flow를 오늘/일정/Flow/지도 표면에서 보는 실험.
  • v11 리허설 리포트: 사용자 관점 클릭 시뮬레이션 결과.
  • GitHub PR #114: 현재 브랜치에 올라간 구현/문서 묶음.

기존 제품과 새 UX의 차이

영역 기존 제품 새 UX에서 반영하려는 것 제품 반영 기준
Public Flow 원컨텐츠를 Flow 화면으로 보여주고 저장할 수 있음. 사용자 화면에서 검토용 문구를 제거하고, 저장 결과를 더 예측 가능하게 만듦. 전세 Flow 수준의 단순함을 유지합니다.
My Flow 저장한 Flow를 볼 수 있으나 여러 Flow가 쌓였을 때 우선순위가 흐려짐. 오늘, 일정, Flow, 지도 표면으로 나누어 Step 중심 실행을 강화. 첫 화면에서 오늘 할 일을 바로 찾을 수 있어야 합니다.
Flow Map 명시적 상위 지도 개념은 약했음. 중1 수학, 영유아 검진/접종처럼 여러 Flow가 반복 구조를 가질 때만 사용. 단일 Flow로 충분한 것은 억지로 Map으로 만들지 않습니다.
Step / Item 체크리스트와 일정 설명이 섞일 수 있었음. Step은 저장 최소 단위, Item은 내부 체크리스트 또는 외부 텍스트 fallback으로 정의. 원문에 없는 Item을 AI가 만들어내지 않습니다.
Export 캘린더/메모/체크리스트 export 가능성을 다룸. ICS 수준의 날짜, 시간, 반복, description 필드는 제품 반영 시 별도 챙김. 지금은 UX 구조 검증, 다음은 실제 데이터 매핑 검증입니다.

유지할 것, 바꿀 것, 보류할 것

유지

기존 제품에서 유지

  • public Flow route와 저장 흐름
  • 기존 Flow 컨텐츠 변환 원칙
  • 캘린더/투두/메모로 나갈 수 있는 export 방향
  • 전세 Flow 수준의 낮은 입력 복잡도
변경

새 UX로 정리

  • My Flow 첫 화면을 Step 중심으로 재정렬
  • Flow Map, Flow, Step, Item 깊이 구분
  • Step 클릭 시 같은 자리에서 Item 열기
  • 검토용 문구와 사용자용 문구 분리
보류

지금 바로 넣지 않음

  • 복잡한 편집기
  • 제작자용 전체 운영 CMS
  • 모든 Flow의 고정 카드 패턴
  • 원문보다 많은 입력 필드

제품 코드에 반영하기 전 체크리스트

01. 기존 route와 데이터 모델을 먼저 읽고, 이미 있는 기능을 중복 구현하지 않습니다.
02. 사용자 화면, 제작자 화면, 리뷰 화면을 파일/route 수준에서 분리합니다.
03. Step은 캘린더/투두에 저장 가능한 최소 단위로 유지합니다.
04. Item은 체크리스트 또는 description text fallback으로 내려갈 수 있어야 합니다.
05. Flow Map은 반복되는 하위 Flow가 있을 때만 사용합니다.
06. 원문에 없는 실행 항목을 AI 일반론으로 채우지 않습니다.
07. 모바일에서 Step을 눌렀을 때 세부 Item이 멀리 떨어진 위치에 열리지 않게 합니다.
08. 월 변경, 날짜 클릭, Step 열기/닫기 같은 기본 상호작용을 실제로 검증합니다.

추천 다음 작업

1단계

제품 코드의 현재 My Flow 구조를 재확인

route, component, storage, export 경계를 읽고 새 UX를 어디에 붙일지 정합니다. 새 UI를 바로 덮어쓰기보다 기존 기능 위에 선택적으로 반영하는 방식이 맞습니다.

2단계

한 경로만 제품 코드에 얇게 반영

중1 수학 또는 영유아 검진/접종 중 하나를 골라 saved Flow detail에서 Step 중심 실행 화면을 먼저 구현합니다. 성공하면 My Flow 목록과 캘린더로 넓힙니다.

3단계

실제 source-backed 데이터로 교체

PoC용 텍스트를 줄이고, 원문 URL, Step title, Item, description, date/repeat 필드를 실제 모델에 맞춰 연결합니다.

4단계

사용자 리허설을 제품 route에서 다시 수행

HTML PoC가 아니라 실제 route에서 저장, 열기, 체크, 메모, 날짜 이동을 검증합니다. 이때 사용자 검증과 내부 리뷰 문서를 다시 분리합니다.

이 문서는 제품 반영 전 판단을 돕는 한국어 읽기용 문서입니다. 원본 메모는 my-flow-before-after-ux-alignment.md에 보관합니다.
