My Flow v11 UX 제품 코드 반영 및 반복 검증 리포트

이번 작업은 HTML PoC를 더 만드는 것이 아니라, 기존 제품 코드의 `/my` 저장 실행 화면에 지금까지 정리한 Flow Map > Flow > Step > Item 모델을 얇게 반영할 수 있는지 검증한 것이다. 사용자 화면은 캘린더/투두 앱 수준의 단순함을 유지하고, 검토용 문구는 제품 화면에 넣지 않았다.

반영 범위

Storage

저장된 Flow Map 맥락

flow:map:saved:{mapId} 스냅샷을 읽어 `/my`의 child Flow 카드에 부모 지도 맥락을 붙였다.

Step Detail

Item 체크리스트

Step은 최소 실행 단위로 유지하고, 원문에서 온 하위 Item은 상세 안의 체크 항목으로만 노출했다.

Mobile

단일 저장 기본 화면

날짜형 단일 Flow는 Today, 비날짜형 진도/시트 Flow는 Flow 카드 화면으로 바로 열리게 했다.

기존 제품에서 유지한 것

영역 유지한 이유
기존 FlowBundle / FlowItem / FlowItemDetail 새로운 사용자 노출 타입을 늘리지 않고도 Step과 Item을 표현할 수 있었다.
기존 `/my` Today / Calendar / Flow / Checklist / Routine 축 이미 저장 Flow 개수와 날짜형 여부에 따라 화면을 줄이는 UX가 있었으므로 대체하지 않았다.
기존 완료 체크와 메모 저장 구조 Step 완료와 Item 체크를 분리해야 해서 기존 완료 상태를 건드리지 않고 별도 키로 저장했다.

Persona A · 단일 Flow

중1 수학 목차 진도 저장 사용자

  • 원문 기반 Flow Map을 저장하면 `/my`에 단일 Flow 카드가 보인다.
  • 글로벌 탭은 숨겨져 화면은 가볍게 유지된다.
  • 비날짜형 진도 Flow는 Flow 카드 화면이 기본이라 Step 상세와 Item 체크가 바로 열린다.
  • 모바일 390px에서 가로 overflow 없음.

Persona B · Flow Map

영유아 검진/접종 지도 저장 사용자

  • 생년월일 1개 입력 후 건강검진 Flow와 예방접종 Flow가 함께 저장된다.
  • 각 카드에 부모 지도명이 조용한 맥락으로 표시된다.
  • 다음 할 일은 캘린더 기준으로 열리고, 지도 원문으로 돌아가는 링크는 지도 보기로 표시된다.
  • 모바일 390px에서 가로 overflow 없음.

반복 개선에서 잡은 문제

등급 문제 수정 결과
High 모바일 단일 저장에서 비날짜형 Flow가 Today로 고정되어 Step 상세가 열릴 위치가 없었다. 단일 저장 기본 화면을 Step shape에 따라 분기했다. 날짜형은 Today, 비날짜형은 Flow 카드 화면. 중1 수학 저장 후 Step 상세와 Item 체크가 바로 열림.
Medium Item 체크가 memo에도 반복되면 설명이 중복되어 검토용 화면처럼 보일 수 있었다. detail.how의 bullet은 상세 체크리스트로 빼고 memo에는 반복하지 않게 했다. Step 상세가 체크 + 메모 중심으로 정리됨.
Low 전체 e2e는 시간 제한으로 한 번에 116개를 끝내지 못했다. 96개 통과 지점 이후 남은 뒤쪽 묶음을 분리 실행했다. 관련 묶음과 남은 e2e 묶음 모두 통과.

남은 리스크

  • 이번 변경은 localStorage 기반의 얇은 제품 반영이다. 서버 저장, 계정 동기화, 제작자 발행 버전 관리는 다음 축이다.
  • Item 체크는 현재 FlowMe 내부 체크로만 저장된다. 외부 캘린더/투두 export의 description fallback은 별도 export QA에서 더 봐야 한다.
  • Flow Map 전용 탭이나 지도 drilldown을 새로 만들지 않았다. 지금 단계에서는 child Flow 카드에 부모 맥락을 붙이는 수준이 적절하다.
