# P3-K 실행 계획

1. 기준 고정: session-start, Git·스킬·설정, 원본과 후속 계약 확인. 제품 파일의 시작 SHA 보관.
2. 병렬 조사: 개발1 원본/현재, 개발2 최신 원본/현재, 전체 trace inventory. 주 담당은 v4.1·화면 연결·브라우저를 조사한다.
3. 실제 조작: 아래 QA inventory를 따라 대표 흐름을 실행하고 다섯 viewport를 캡처한다. 코드 의심과 재현 결함을 분리한다.
4. 판정: 부모 요구를 빠짐없이 목록화하되 새 증거가 없는 조건은 미검사로 남긴다. 기능 여부와 UX/UI 적합성을 따로 적는다.
5. 설계: 발견된 차이를 원본/현재/제안으로 설명하고 상태·행동·데이터 owner·모바일 배치를 명시한다.
6. 구현 묶음: 안전·오조작 → 여정 연결 → 원본 UI 적합성 순으로 묶고 기획/설계/개발/검증 완료 조건을 정한다.
7. 보고서 QA·docs 검사·보호 파일 비교·인계. 제품 수정은 다음 목표다.
