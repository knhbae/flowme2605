# P3-K 세 산출물 통합 UX 감사

- 승인: 2026-09-05, 현재 작업의 사용자 요청 `목표 세우고 진행해볼까?`
- 목표: 원래 요구와 승인 결정을 현재 제품에 대조하고, 수정 설계와 다음 구현 묶음을 만든다.
- 대상: v4.1 78개, 개발1 26개, 개발2 64개, 통합 연결 BP 86개 부모 요구. 원자 조건 수는 생성 trace에서 검산한다.
- 이번 작업은 감사·설계·계획이다. 제품 수정 완료나 전체 요구 재시험 완료를 뜻하지 않는다.

## 정본과 판정

현재 사용자 보호 경계 → 통합 blueprint → 해당 범위를 대체한 승인 후속 결정 → 세 원본 명세·화면 순으로 적용한다. 코드와 테스트는 구현 증거이며 제품 결정을 대신하지 않는다. A0, P2, P3의 결정은 적용 범위를 표시한다. 전체 문서를 통째로 폐기하지 않는다.

비교원장은 원본 제품, 요구 ID, 여정·화면·상태, 원본 anchor, 결정 근거, 기대 행동과 결과, React·단일 HTML 각각의 증거, 기능·UX·UI·증거 판정, 차이 원인, 수정안, 완료 조건을 연결한다. 역사 trace는 덮어쓰지 않는다. `구현 확인`, `실제 차이`, `의도적 변경`, `과거 판정 미갱신`, `미검사`, `범위 밖`을 구분한다.

## 검증 범위

대표 흐름을 격리 Chromium context에서 조작한다. 지정 크기 390×844, 375×812, 844×390, 1024×768, 1440×900에서 첫 행동·내부 잘림·초점·빈/긴 내용 상태를 검사한다. 모든 원자 조건을 이번에 재실행한 것으로 쓰지 않는다. 기존 시험 로그는 과거 증거로 분리한다.

새 보고서는 기존 보고서의 평면·흰색·청록 문법을 재사용한다. 원본 화면과 현재 화면은 실제 캡처만 사용하고, 개선 구조는 `제안·미구현`으로 표시한다. 이미지 생성으로 원본이나 실제 결과를 대체하지 않는다.

## 보호 경계

- 기존 격리 worktree 유지. 시작 시 수정 181개·미추적 277개는 미소유다.
- 제품 코드·단일 HTML·과거 trace·운영 key/schema/writer·기본 `/my`는 변경하지 않는다.
- 테스트 샘플은 별도 context에만 둔다. 제품 행동에 의한 쓰기는 `flow:poc:personal-workspace:v1:*`만 허용한다. `clear`는 금지한다.
- 원본 worktree들은 읽기 전용이다. 과거 접근이 거부된 P3-I HTML은 열거나 자동화하지 않는다.
- 스킬 자동 동기화·설치·전역 설정 변경·새 영구 정책 확정 없음.
- 실제 Android/iOS·보조기술·관찰 사용자 검사는 완료 조건에서 제외한다. `NOT_RUN`, 관찰 사용자 0명으로 보고한다.
- commit·push·PR·Preview·Production 없음.
