# 문서·폴더·기간 보기의 일관된 작성 UX

2026-10-01. 사용자 요청: 추가 피드백을 확인하고 한 번에 진행할 수 있는 다음 목표를 등록한다. 요구 대조·조작 HTML·안전 계약·최소 구현·합성 시나리오·회귀·화면 평가·결과 보고를 격리 작업본에서 완료했다. 개발계 반영과 관찰 사용자 검증은 범위 밖이다. 전체 UX나21개 피드백 전부 해결의 완료가 아니다.

첫 체크포인트는 목표·계획 등록이었으며, 목표 계속 실행에서 아래 로컬 구현·검증 단계로 진행했다. 제품 정책·운영 데이터 계약 변경이나 발행 권한을 얻은 것으로 해석하지 않는다.

## 목표

문서에 폴더 이름을 쓰고 기존 폴더를 연결한 뒤, 필요한 폴더 영역을 보며 작성하고 기간 목록과 같은 원문을 오가는 흐름을 개선한다. 피드백20·21을 중심으로 기존 폴더/문서 맥락과 작은 화면 본문 공간을 함께 다룬다. [21개 피드백 처리 범위](feedback-map.md), [실행 계획](plan.md), [단계 원장](tasks.md)을 따른다.

한 목표 안에서 요구 확인 → UX/조작 비교 → 안전 계약/개발 설계 → 최소 구현 → 시나리오/회귀 검사 → 결과 보고를 순서대로 진행한다. 이미 보완한 폴더 변환·기간 경로 표시를 새로 만들지 않는다. B 전체 집중 모드와 문서의 폴더 영역 보기는 다른 기능이다.

## 범위

1. 이름 있는 일반 목록 줄의 기존 폴더 연결 **제안**. 동명 다른 경로를 구별하고 확정 전에는 텍스트를 유지한다. 기존 같은 줄 변환을 재사용한다.
2. 문서 전체/선택 폴더 영역/폴더 전체 할 일의 역할 비교. 문서 보관 위치, 본문에 연결된 폴더, Item 실제 소속, 현재 조회 범위를 섞지 않는다.
3. 기간의 실제 폴더 경로·원문 문서명·조회 범위와 원문 복귀를 유지하고 다중 문서/동명 중첩 폴더에서 회귀 검사한다.
4. 낮은 화면에서 본문과 주요 작성 행동을 확보한다. 계정/관리 설명·반복 도구를 감산하되 저장·오류·복구·Undo 접근을 잃지 않는다.
5. 현재 경로와 합성 자료로 재현하고 원문/identity/입력/저장 보호 계약을 확인한 변경만 최소 구현한다.

## 경계

- 공개 앱3105·기존 Tunnel·DB/Auth·실제 계정/개인 자료·운영 저장소는 바꾸지 않는다. 원격 요청을 막은 합성 Auth/API와 별도 QA 서버만 사용한다.
- 기존 `/my` exact gate, writer·schema·CAS·receipt·Item/Flow 소속·완료 기록·날짜/폴더/순서 전이를 재사용한다. 조회/제안/취소로 쓰기를 만들지 않는다. 이를 변경해야 하는 대안은 조용히 승격하지 않고 영향과 필요한 결정을 보고한다.
- 기존 계약 밖의 자동 폴더 생성/연결, `@`·`#` 새 문법, 이름 정규화/중복 정책, 메모 줄바꿈·구조 키보드의 영구 정책은 확정하지 않는다.
- 부분 보기의 비연속 텍스트를 새 문서나 전체 저장 payload로 사용하지 않는다. 안전한 부분 편집 계약을 확보하지 못하면 이를 구현 완료로 판정하지 않는다.
- 공개 Flow/제작/커뮤니티는 기존 기능과 전체3축 맵을 유지한다. 전체 UX 재설계·콘텐츠 전수 반입·캘린더 신설은 별도다.
- B 전체 집중 모드, 신규5D·장시간 인증/운영·자동 시작, 실기기/IME/보조기술·관찰 사용자 시험, commit/push/PR/merge·배포/개발계 교체는 제외한다.

## 완료 조건

- 피드백1~21 각각이 신규 개선/기존 보완의 회귀/재현 필요/별도 후속/오류 종료로 연결되며 전체 요구 충족률을 주장하지 않는다.
