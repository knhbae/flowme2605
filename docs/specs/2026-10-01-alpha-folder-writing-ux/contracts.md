# 폴더 작성 UX 후보 계약 v1

상태: 격리 작업본의 구현·합성 검증용 계약이다. 영구 제품 정책, 운영 schema, 공개 반영 승인이 아니다. [목표](spec.md)와 [피드백 범위](feedback-map.md)를 따른다.

## 화면과 의미

1. 기존 폴더 선택을 문서/기간의 조회 범위로 사용한다. 문서 보관 위치와 Item 소속은 그대로다. 보관 폴더만으로 일반 본문을 해당 폴더 영역으로 추정하지 않는다.
2. 선택한 폴더의 문서 안 영역을 원문 순서로 보여 준다. 비연속 영역을 한 새 문서로 합쳐 저장하지 않는다. 부모 폴더는 하위 폴더/그 폴더의 Flow를 포함한다. 동일 이름은 전체 경로와 ID로 구분한다.
3. 빈 결과에서는 ‘전체 문서 보기’와 해당 폴더의 모든 할 일로 이동할 수 있다. 다른 문서의 할 일을 현재 문서에 복제하지 않는다.
4. 기존 이름을 쓴 자식 없는 미연결 목록 메모에는 정확 일치 폴더 제안을 표시한다. 입력/무시만으로 연결하지 않는다. 명시 선택은 기존 연결 전이를 사용하고 같은 lineId를 유지한다. 새로운 이름 정규화·부분 일치 정책은 확정하지 않는다.
5. 낮은 가로 화면은 기존 상단 요소의 여백과 배치를 줄여 첫 편집 줄을 확보한다. 관리 기능은 접되 저장·오류·복구와 48px 행동 목표는 유지한다. 별도 집중 모드로 문제를 가리지 않는다.

## 원문 편집과 안전

- reader는 full workspace 판본, fullRaw, 원래 lineId와 연속 범위를 가진 로컬 보기 capability를 만든다. serialized/변조/외부 판본 capability는 쓰기를 허용하지 않는다.
- 일반 메모·canonical 할 일·메모/시간 속성을 연속 영역에서 편집한다. 새 일반 메모와 명시 Todo 추가를 지원한다. 기존 줄 삭제·메모의 Todo 승격·소속/날짜/진행 토큰·구조 경계 변경은 이 후보에서 거절한다.
- 날짜/폴더/참조/소속 불일치 등 필요한 문맥은 읽기 전용으로 표시한다. 기존 native fold는 partial editing 구현으로 간주하지 않는다.
- 부분 입력은 원래 fullRaw의 정확한 범위에 재조합한 뒤 기존 전체 원문 모델에 전달한다. 필터 결과 또는 fragment를 전체 문서 writer에 전달하지 않는다.
- 결과 검사는 숨은 줄의 bytes/ID/순서, 다른 문서, 기존 소속, 날짜와 진행 기록을 보존한다. 참조 동기화가 다른 문서를 바꾸는 제목 편집은 명시 거절하고 전체 문서 경로를 제공한다.
- 기존 모델이 인접 메모·시간 두 속성을 동시에 교체할 때 줄 ID를 재생성하는 경우도 거절한다. 각 속성의 순차 편집은 지원한다. identity 보정이나 parser 변경으로 이 제한을 우회하지 않는다.
- 입력 시작 판본을 보존한다. 다른 저장/동기화가 도착해도 미저장 fragment를 덮지 않는다. 실패한 입력은 남기고 이유와 전체 원문 받기/수정 경로를 제공한다.
- 조합 중에는 parse·범위 전환·저장·강제 focus 변경을 막는다. 자동 저장과 명시 저장은 기존 단일 저장 경로/expectedWorkspace 계약을 사용한다.
- 범위 전환은 pending flush 성공 후만 진행한다. 실패 시 같은 입력에 남는다. 원문 복귀는 폴더 범위를 해제한 뒤 기존 원래 줄 focus를 사용한다.
- 새 문서 생성도 같은 입력 저장/잠금 장벽을 거친다. 자신이 시작한 연속 저장의 성공 receipt만 expected 판본을 갱신한다. 외부 판본·계정 변경·실패는 생성 권한으로 채택하지 않는다. 생성 성공 시 문서 보관 폴더는 유지하고 조회 폴더만 해제해 새 전체 작성란을 연다.
- 지역 입력 Undo는 아직 저장하지 않은 지역 textarea 입력에 적용한다. 성공 저장 이후의 되돌리기는 기존 workspace Undo를 사용한다. reload는 마지막 성공 상태만 복구한다.

## 근거와 검증 경계

독립 HTML은 `flow:poc:personal-workspace:v1:folder-writing-lab` 정확 key를 사용하는 합성 시뮬레이션이다. 모델은 inline 단일 원본이며 앱 parser/Auth/서버 writer 검증을 대신하지 않는다. 앱 구현은 별도 helper/컴포넌트와 합성 서버 시나리오로 확인한다. 실제 IME·기기·관찰 사용자 검증은 미실행으로 남긴다.

지원 제한을 읽기 전용 완료로 숨기지 않는다. 정상 지역 편집이 실제 동작해야 이 목표의 최소 구현을 충족한다. 구조 변경과 참조 제목 동기화는 전체 문서 경로와 명시 후속으로 구분해 보고한다.
