# 요구별 적용과 후속

정본 조사와 이전 상태는 [피드백 대조](feedback-map.md), 실행 수·실패 이력은 [QA](qa.md), 지원 범위는 [후보 계약](contracts.md)에서 확인한다. 21은 원장 항목 수이며 전체 해결 수나 제품 요구 충족률이 아니다. 아래 새 기능은 격리 후보에만 있으며 공개 개발계에 반영하지 않았다.

## 시나리오 연결

| 코드 | 실제 앱 합성 시나리오 |
| --- | --- |
| F1 | 폴더 조회·비연속 영역·부모/동명/다른 문서·전체 복귀, 조회0쓰기 |
| F2 | 지역 메모·제목·시간 편집→전체 원문·기간→저장 Undo→reload, 숨은 자료·ID 보존 |
| F3 | 정확 이름 제안 무시0쓰기→명시 선택→같은 줄/폴더 ID |
| F4 | 조합/경계 위반 입력 중 폴더·기간 이동 차단, 전체 원문 받기·취소·복귀 |
| F5 | 실제 브라우저 키 입력→지역 toolbar Undo/Ctrl+Z, 저장 전0쓰기 |
| F6 | 저장 제한 거절→입력 보존→직접 재저장, 숨은 자료 유지 |
| F7 | 저장했으나 응답 유실→같은 요청 receipt 확인, 중복 저장0 |
| F8 | 외부 합성 판본이 먼저 저장됨→이전 지역 입력 거절·보존 |
| F9 | 다섯 화면 초기 scroll0 source 행·가로 넘침 계측/캡처 |
| F10 | 미저장 지역 입력을 자기 성공 receipt 판본으로 저장→새 문서 생성, 보관 폴더 유지·조회 범위 해제·새 작성란 노출 |
| R1 | 새 폴더→새 문서 작성→날짜/시간→reload, 보관 위치와 조회 범위 분리 |
| R2 | 기존 전체 작성기의 응답 유실·동일 요청 확인 회귀 |
| J1 | 같은 Item 작성·날짜 이동·오늘/주간/월간·완료/재열기·정확 원문 복귀·reload |
| J2 | 보조 도구 키보드 접근·Escape·취소0변경 |
| J3 | 긴 문서의 접힌 줄→기간→정확한 원래 줄 펼침·커서/스크롤,0변경 |

각 앱 시나리오는 다섯 화면에서 검사한다. HTML의 고정 row 시뮬레이션은 실제 앱의 자유 텍스트 parser·서버 writer 검사를 대신하지 않는다. F9 폴더 fixture의 첫 source 행은 날짜 행이며, 일반 메모의 첫 줄 확보는 J1의 같은 초기 메모 fixture로 별도 비교한다.

## 후속 순서

다음 좁은 UX 후보는 부분/전체 작성기의 조작 차이와 구조 키보드·Enter·메모 줄바꿈의 입력 계약이다. 원래 환경이 미확인인 탐색·캘린더·제작은 피드백 세션에서 새 URL/화면 근거가 추가될 때 delta로 확인한다. 사용자 전수 시험을 이번 목표의 완료 조건으로 다시 요구하지 않는다. 게시·개발계 반영, 장시간 운영/5D, 실제 기기·관찰 사용자 검사는 별도 승인/목표로 남긴다.
