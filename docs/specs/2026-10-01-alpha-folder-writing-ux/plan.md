# 단계별 실행 계획

정본은 [목표/경계](spec.md)와 [피드백 처리 범위](feedback-map.md)다. 단계0→[후보 계약](contracts.md)/조작 HTML→로컬 구현→검증→[요구별 결과](results.md)/[QA](qa.md)를 완료했다. 아래는 실행 순서와 승인 경계이며 후속 정책·공개 반영 승인이 아니다.

## 0. 출처·기준선 확인

신규20·21과21개 원장을 대조한다. v11 코드 관찰, 사용 환경 미확인, 현재 Alpha 구현, 과거 QA를 구분한다. 이전 격리 후보의 소유 변경만 이어받고 다른 worktree의 dirty를 포함하지 않는다. 현재 기본 경로/HTML/QA와 새 후보의 차이를 기록한다.

## 1. UX 비교와 조작 시뮬레이션

- 연결 제안: 기존 이름 입력 뒤 비강제 제안 vs 기존 명시적 폴더 연결 경로. 정확 일치·동명 경로·없음·무시/취소·자식 있는 줄·한글 조합·연속 입력·중복 클릭을 비교한다. 제안을 매 글자 입력마다 modal로 띄우지 않는다.
- 보기 범위: 문서 전체, 현재 문서의 폴더 영역, 모든 문서의 해당 폴더 할 일을 같은 자료로 비교한다. 한 영역/비연속 여러 영역/상하위/다른 문서에만 있는 폴더/폴더 밖 문장·할 일/긴 경로/빈 결과를 포함한다.
- 본문 공간: 기본 레이아웃의 상시 관리/도구를 먼저 줄인다. B 전체 집중 모드로 기본 화면의 문제를 가리지 않는다. 저장·오류·복구와 편집 Undo는 유지한다.
- 시뮬레이션은 원격 호출 없는 독립 로컬 HTML. `localStorage.clear()` 금지, 정확한 전용 PoC key만 사용. 이 단계에서 새 영구 문법/이름/소속 정책을 확정하지 않는다.

출력: 조작 HTML, 대안별 채택/보류와 이유, 좁은 내부 평가. 사용자 관찰 결과로 표현하지 않는다.

## 2. 안전 계약과 개발 설계

- 연결은 이름이 아닌 기존 folderId를 사용한다. 현재 childless/unbound 목록 메모 변환 조건과 lineId 유지 계약을 재사용한다.
- 폴더 범위는 저장과 분리된 보기 상태다. 보관 폴더로 본문 영역이나 Item 소속을 추정하지 않는다. 조회 범위·전체 복귀·빈 결과의 다음 행동을 명시한다.
- 부분 편집은 원문 documentId/lineId와 판본을 확인해 같은 원문에 반영한다. 숨긴 줄, 날짜/폴더 상속에 필요한 선행 문맥, 일반 메모, 참조/반복/완료 기록을 보존한다. 필터 결과를 전체 원문으로 저장하지 않는다.
- 전환 전 pending/dirty/IME/입력 잠금/권한/저장 실패 보호와 커서·선택·스크롤·원문 복귀·Undo를 설계한다. 숨긴 경계를 넘는 이동/붙여넣기/복수 선택은 명시적으로 검토한다.
- 현재 선택적 부분 보기/편집의 지원 범위를 적는다. 기존 parser/writer/identity/소속 전이 변경이 필요한 경우 구현 전에 대안과 영향/결정 지점을 보고한다.

출력: 계약과 테스트 매트릭스, 재사용 helper/컴포넌트, 소유 파일. 필요한 정책을 agent 판단만으로 영구 확정하지 않는다.

## 3. 최소 구현

연결 제안 helper·UI → 문서 영역 reader/보기·안전 편집 연결 → 조회 맥락/원문 복귀 → 낮은 화면 CSS 순서다. 구현 파일 소유가 겹치는 작업은 병렬 수정하지 않는다. 독립 계약/UX 리뷰와 테스트 fixture 검토만 병렬화한다. 이전 연결·날짜/시간·기간 경로·ACK 복구 수정은 재구현하지 않고 회귀 조건으로 둔다.

예상 파일: ProgramTextEditor, ProgramSpace, AlphaWorkspace CSS, 기존 folder-link-slot 및 필요한 범위 reader/test, 합성 browser fixture. 최종 소유 범위는 계약 단계에서 확정한다. vendor 전체 rewrite나 새 저장소를 먼저 만들지 않는다.

## 4. 시나리오·검증·평가

1. 기존 이름 입력→제안 무시/취소→0변경; 명시 선택→같은 줄/폴더 ID, 중복0.
2. 같은 폴더의 한 곳/여러 곳→범위 왕복→같은 원문 순서/ID, 복제0.
3. 동명 중첩·상하위·다른 문서만 일치→경로/빈 결과/전체 복귀, 조회 쓰기0.
4. 부분 편집→전체 복귀→기간/원문→Undo→reload에서 숨은 줄·메모·날짜·소속·진행 기록 보존.
5. 미저장/조합 중/외부 판본/권한/실패 상태의 범위 전환·원문 이동·입력 복구. 합성 composition과 실제 IME를 구분한다.
6. 키보드·메뉴 등 비드래그 경로와 포커스/커서/스크롤 확인. 구조 들여쓰기 정책 전체 완료로 확대하지 않는다.
7. 다섯 크기에서 같은 합성 상태/초기 scroll0 전후 계측. 가로844×390의 첫 편집 줄을 직접 확인한다.
8. 저장 시 합성 운영 sentinel bytes 불변·허용 밖 storage 쓰기/clear0·원격 전달0. 실제 개인 DB 전체 불변 증거로 확대하지 않는다.

검사 순서: helper/컴포넌트 표적 → 기존 브라우저+새 여정 → 소스 동결 → npm test/전체 통합/타입/build/docs → 최종 bundle 화면 확인 → 독립 diff 리뷰. 실행 중 소스가 바뀌면 해당 결과를 마지막 소스 통과로 쓰지 않는다. 실제 계정/remote DB를 쓰지 않는다.

## 5. 마감과 후속

피드백 ID → 이전 상태 → 이번 설계/구현 → 시나리오/근거 → 남은 한계를 연결했다. HTML 파일 링크와 결과를 제공한다. 지원하지 않는 부분은 명시적 별도 후속으로 남겼고 읽기 전용 시안만으로 편집 완료를 주장하지 않는다. commit/push/PR/merge/배포/개발계 교체와 관찰 사용자0을 분리해 기록한다.
