# 쓰기·오늘·분류 로컬 구현 결과

현재 글을 이어 쓰는 ‘쓰기’, 날짜로 실행하는 ‘오늘’, 날짜와 무관하게 같은 일을 찾는 ‘분류’를 기본 이동으로 정리했다. 기존 보기와 Item을 재사용했고 새 저장소·분류 정책·복사 동작은 추가하지 않았다.

## 화면에서 달라진 점

| 기준 Q2 | 이번 후보 |
| --- | --- |
| 문서 목록과 문서 작업 진입점이 나뉘어 있음 | ‘더보기’ 한곳에 새 글·문서 작업·찾기·기존 글 목록을 배치 |
| 기본 작성에서 문서/보기 선택이 앞에 노출됨 | 쓰기·오늘·분류를 바로 이동하고 현재 글을 계속 사용. 새 글은 명시 동작 |
| 날짜 속성 TXT와 뜻을 알기 어려운 짧은 날짜 | 일반 표시에 ‘예정일 10월 8일’, 기록에는 ‘진행 기록 10월 7일 · 100%’. 원문 보기에서 TXT 확인 |

문서 관리에서 ‘내 문서·할 일 찾기’와 기존 목록을 유지했다. 다른 날짜 보기·이름을 정해 새 문서 만들기·관리 동작은 접었으며, 오늘/분류의 추가 양식도 필요할 때 연다. 현재 보기와 선택 분류는 화면에 표시한다.

기존 collectionMode는 문서 모음이고 Item 분류 선택 기능이 없으므로 그 모드의 all 보기를 ‘분류’로 바꾸지 않고 ‘전체 할 일’로 표시한다. 문서 모음과 Item 분류의 의미를 합치지 않았다.

## 완료한 동작

데스크톱에서 가상 업무·생활 할 일을 한 글에 작성 → 업무/생활 분류·예정일 지정 → 오늘에서 회의 미루기·장보기 완료 → 분류에서 두 항목 다시 찾기 → 같은 글 이어쓰기 → 회의에만 연결한 비교 메모 열기를 수행했다. 390px에서는 같은 자료로 오늘의 미루기·완료와 분류 재찾기·같은 글 이어쓰기·기존 연결 메모 재진입·새로고침을 확인했다. 모바일에서 글과 메모를 다시 생성하지 않았다.

이동·원문 왕복·새로고침 후 글/Item ID와 예정일·분류·본문·메모 연결·진행 기록이 유지됐다. 최종 글은 원래 글과 명시적으로 만든 비교 메모 두 개, canonical Item은 두 개, 추가 사본은0이다. 기본 이동은 글을 새로 만들지 않는다. 연결 메모는 기존 ‘더보기 → 문서 목록’에서 연다. 새로고침은 마지막 편집 위치가 기록된 원래 글을 열었고, 저장된 메모를 목록에서 다시 열어 본문 일치를 확인했다.

키보드로 기본 이동·예정일 열기/취소·문서 찾기·원문 보기/닫기를 확인했다. native 입력 후 Ctrl+Z로 임시 입력을 되돌려 원문을 복원했다. 쓰기·오늘·분류·문서 관리 네 상태에서 데스크톱/390px 가로 넘침과 문서 작업 메뉴 중복은 없었다.
