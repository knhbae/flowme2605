# 1~2명 시험 시작 준비

2026-10-03. **준비 문서이며 초대·관찰 시험은 아직 하지 않았다. 관찰 사용자 0명.** 현재 시작 판정은 조건부다. CP1/CP2의 게시·개발계 반영과 최종 후보 QA가 끝나기 전 최신 UX 판본을 제공했다고 안내하지 않는다. 최신 반영 상태는 [QA](qa.md)를 따른다.

## 시험 범위와 자료 보호

- 목적은 개인 작성/실행, 공개 자료 활용, 선택적 질문의 핵심 동선에서 막힌 지점을 찾는 것이다. 세 과제를 의무 순서나 계정 모드로 강제하지 않는다.
- 기존 로그인 계정과 검증용 자료만 사용한다. 실제 비밀번호·인증 링크·토큰은 피드백이나 캡처에 넣지 않는다. 중요한 자료의 유일본·의료/세금 의사결정 자료를 넣지 않는다.
- 백업은 암호화되지 않은 개인 자료다. 본인이 고른 위치에 보관하고 공개 Git/채팅/공유 폴더에 올리지 않는다. 이번 안내는 전체 서비스 복원이나 삭제된 과거 첨부 복원을 약속하지 않는다.
- 공개 행동은 명시 preview/확인 뒤에만 한다. 개인 사본과 원본을 구분하고, 시험 때문에 기존 공개 콘텐츠·다른 계정 자료를 변경하지 않는다.
- 노트북이 꺼지거나 앱/터널이 중단되면 접속할 수 없다. 미저장 입력이 있으면 새로고침·입력 버리기를 누르지 말고 현재 입력을 보관한 뒤 신고한다. 결과 불명과 확정 거절의 행동을 구분한다.

## 선택할 과제

| 과제 | 사용자가 해볼 일 | 확인할 점 |
| --- | --- | --- |
| 개인 계획·메모 | 검증용 문서에 일반 메모와 할 일을 쓴다. 할 일 하나에 날짜·시간을 지정하고 기간 보기에서 실행한 뒤 원문으로 돌아간다 | 같은 항목인가, 메모가 할 일로 바뀌지 않는가, 날짜 출처·미정 시간·완료 결과를 이해하는가 |
| 찾기와 메뉴 | 폴더·검색 조건으로 빈 결과를 만든다. 전체 할 일로 범위를 넓히고 항목 메뉴를 연 뒤 취소한다 | 조건과 실제 소속을 구분하는가, 메뉴 대상과 진행·날짜를 찾는가, 취소 후 입력/선택이 남는가 |
| 공개 활용 | 제공된 안전한 공개 자료를 찾고 특정 판본을 선택한다. 출력 후 종료하거나 개인 사본으로 실행한다 | 선택 판본·원본/사본을 구분하는가, 사본이 필요 없는 종료 경로가 있는가, 내 문서로 돌아가는가 |
| 선택적 질문 | Flow 없이 질문 초안을 쓰고 나중에 이어 쓰기로 보관한다. 실패가 실제 발생한 경우에만 안내와 다음 행동을 기록한다 | 무엇이 저장됐고 남았는가, 원 요청 확인과 현재 입력 저장을 구분하는가. 의도적으로 실제 서비스 오류를 만들지 않음 |
| 백업 발견성 | 계정 관리에서 복원 진입과 대상 계정을 확인한다. 필요하면 백업 미리보기까지만 진행하고 닫았다 다시 연다 | 대상을 이해하는가, 닫기와 취소를 구분하는가. 실제 복원은 별도 정확 범위 허용 후에만 수행 |

## 피드백 양식

한 건마다 아래를 기록한다. 테스트자가 느낀 불편과 개발자가 확인한 원인을 섞지 않는다.

```text
시각 / 기기·브라우저 / 제공 판본:
하려던 일:
문서·기간·폴더·검색 조건 (개인정보 제외):
실제로 누른 순서:
기대한 결과 / 실제 결과:
보이는 저장 상태·안내·다음 버튼:
입력이 남아 있는지 / 다시 시도·새로고침 여부:
화면 캡처 또는 검증용 자료 ID (비밀번호·토큰 제외):
불편 정도: 막힘 / 돌아서 가능 / 이해하기 어려움 / 제안
원관찰: 사용자 말 그대로
개발 확인: 미재현 / 재현 / 조건 차이 / 미확인
해석·개선 제안·승인·반영 판본: 별도 기입
```

## 시작·중단 기준

시작 전 정확한 제공 head/build, HTTP/정적 자산, 인증 경계, 보호값, 대표 진입/복귀와 이전판 복귀 가능성을 확인한다. 실제 계정 로그인이 가능한지도 해당 계정 범위에서 확인한다. 합성 로그인 QA를 실제 계정 로그인 성공으로 쓰지 않는다. 참여자는 원할 때만 과제를 고르고, 자동 조작 검사를 사람이 사용한 증거로 바꾸지 않는다.

막힌 저장·결과 불명·다른 기기 충돌·다른 계정 자료 노출·입력 소실이 보이면 그 과제의 쓰기를 멈춘다. 남은 입력과 대상 ID를 보호한 뒤 현재 저장 상태를 확인한다. 계정·자료를 바꾸거나 복원해서 문제를 감추지 않는다.

개발계 교체가 끝났다면 새 요청 전에 새 판본을 확인한다. 열린 탭에 미저장 입력이 있으면 먼저 보관하고 안내에 따라 새 판본을 연다. 이전판 복귀는 운영 담당자가 정확한 제공 사본·프로세스와 보호값을 확인해서 수행한다. 사용자가 임의의 복원 파일로 서비스 전체를 되돌리도록 안내하지 않는다.

실제 Android Chrome/iOS Safari·IME·touch·보조기술·관찰 결과는 재개 요청 이후 별도 원장에 기록한다. 이 문서 작성은 그런 검사의 실행이나 전체 UX 완성 판정이 아니다.
