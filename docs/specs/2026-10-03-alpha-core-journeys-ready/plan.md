# 단계별 실행 계획

정본: [목표·범위·경계](spec.md). 현재 목표의 실행·선별 게시/CI·개발계 앱 교체/복귀가 승인됐으며 이 작업본은 보존된 r6의 CP1 게시 준비만 담당한다. CP2의 새 설계·구현 진행은 격리 개발 작업본에서 기록한다. 이 문서의 단계표는 전체 목표의 계획이며 완료를 뜻하지 않는다.

## 진행 순서

| 단계 | 수행할 일 | 단계 종료 산출물 | 반영/시험 시점 |
| --- | --- | --- | --- |
| 0. 기준선·범위 확인 | 최신 피드백 원문/중간 삽입, Git/원격·소유 파일·제공 판본, 직전 QA의 소스 일치 대조. 구현 완료·갭·미확인·정책 필요 구분 | 요구-화면-행동-근거 연결표와 소유 manifest | 코드·서비스 변경 없음 |
| 1. CP1 기존 후보 반영 | 기존 수정본을 재개발하지 않고 판본/게시 권한·CI·보호값·교체/복귀 절차 확인 후 선별 반영 | 기존 후보의 정확 build 및 반영 후 확인 기록 | 모든 새 UX 개선을 기다리지 않고 첫 개발계 체크포인트 |
| 2. UX·개발 설계 | 개인 연결부·UX-N1 6상태·UX-N2·공개 진입/복귀를 묶음별 비교. 현행/후보·감산 이유·상태/행동/초점·데이터 owner·실패/취소 계약 정리 | UX 대조와 기술 계약, 구현 대상/보존 대상 목록 | 정책 필요 항목은 따로 남김 |
| 3. 좁은 구현 | 아래 P/C/N/F 순서로 기존 컴포넌트·transition·writer 재사용. 결함은 가능한 red→green. 이미 충족한 기능은 보존 | 후보 코드와 변경 이유·요구 연결 | 실제 계정 쓰기 없이 격리 개발/합성 QA |
| 4. 최종 후보 검증 | 표적/관련 회귀 후 final npm·타입·build. 정확 판본 HTTP 앱에서 대표 경로·5크기·키보드·저장 경계 확인 | 실제 실행 개수·판본·오류/미실행·보호 근거 | 새 화면 검사는 허용된 실제 제품 경로에서만 |
| 5. CP2 개선본 반영 | 최종 manifest·유효 승인·CI 확인 후 새 개발용 제공 사본으로 선별 교체. 이전판 복귀 가능성 및 반영 후 안전 점검 | 반영된 head/build·자산/보호값·복귀/오류 기록 | 개선본의 두 번째 개발계 체크포인트 |
| 6. 시험 시작 준비·정리 | 1~2명용 과제/피드백 양식·자료 보호·판본 확인·복귀/오류 신고 안내, 접속/권한 조건 판정. 잔여에 재개 조건 연결 | 준비 문서 + 시작 가능/조건부/불가 + 전체 목표 결과 | 실제 초대·관찰 시험은 아직 하지 않음 |

CP1의 외부 권한만 대기할 경우 단계2의 안전한 설계는 진행할 수 있다. 새 구현 기준은 격리 후보에 고정하고, 미반영 상태를 숨기지 않는다. CP1/CP2를 “게시했으니 반영됨”으로 합치지 않는다. 반영 없이 끝내기로 범위를 바꾸려면 사용자 결정이 필요하다.

## 단계3 구현 묶음

1. **P: 개인 작성/실행의 연결부.** 같은 Item의 문서·기간·원문 위치, 날짜 출처와 지난 미완료, 조회 범위/필터/빈 결과/미정 시간 안내. 새 날짜/폴더 의미를 정하지 않고 기존 계약의 표시와 이동을 정리한다.
2. **C: UX-N1 초안 복구.** 6상태의 저장 대상·미저장 입력·주 행동을 구분하고 중복 설명을 줄인다. input/selection·명시 retry·정확 receipt·실제 충돌 보존을 먼저 확인한다.
3. **N: UX-N2 메뉴·등록·복원 발견성.** 조작 대상·등록 결과·복원 대상과 초점 복귀를 보완한다. 장시간 백업/복원 닫기·재진입은 기존 기능 회귀 범위에서 다루고 대형 proof를 새로 붙이지 않는다.
4. **F: 공개 탐색/개인 활용 연결부.** 기존 권한으로 확인 가능한 대상에서 없음/검색 없음/내 비공개를 구분하고, 현재 지원하는 판본·사본·실행·원문/출력 후 복귀의 표현을 정리한다. 권한 없는 비공개 자료의 존재/메타데이터를 노출하지 않는다. 새 주제 가이드·단계 탐색 채택은 별도 설계 후보로 남기며 이번 구현에 포함하지 않는다.

각 묶음의 설계와 검증은 별도로 판정한다. 정책 선택 없이 기존 계약을 표현할 수 없는 항목은 그 항목만 분리하고 나머지 묶음을 이어간다. 발견하지 않은 결함을 구현 할당량을 채우려고 만들지 않는다.

## 검증의 크기와 비용

- 작은 문구·문서 변경에는 해당 회귀/문서 검사를 적용한다. 런타임 변경 후에는 영향을 받는 모델·화면·연결부를 먼저 검사한다.
- 최종 runtime 후보마다 전체 npm·타입·production build를 수행한다. 같은 소스/판본에 유효한 검증을 매 계획 문단마다 다시 실행하지 않는다. 소스 또는 보호 계약이 바뀌면 해당 근거를 갱신한다.
- 다섯 크기의 대표 상태·동선을 검사한다. 상태마다 모든 화면 전체를 캡처하거나 대형 trace를 무제한 보관하지 않는다. 실패/수정 비교·핵심 경계 중심의 필요한 원본과 요약을 남긴다.
- local HTML 시안은 필요한 설계 보조물로만 사용한다. 이전 접근 거절 작업을 HTTP mirror·다른 브라우저·다른 세션으로 대행해 우회하지 않는다. 기존 NOT_RUN2건을 이번 목표의 숨은 선행 조건으로 되돌리지 않는다.
- 반영 후 기본 점검은 가용성·정확 build/자산·인증 경계·보호값·대표 진입/복귀다. 실제 계정 작성·복원·공개 쓰기가 필요하면 정확 시험 자료·권한을 별도로 확인한다.

## 역할과 인수

이 개발 세션이 전체 원장·기술 설계·구현·QA·반영을 책임진다. UX 검토는 기존 UX2 인수 결과를 사용하고 필요하면 독립 에이전트가 후보와 계약을 읽기 전용으로 대조한다. 사용자 소유 UX 세션에 새 업무를 보내는 것은 별도 명시 요청이 있을 때만 한다. 설계 산출물을 구현 완료로, 다른 세션의 실행을 이 세션의 새 검사로 바꾸지 않는다.

권한·정책·환경 문제가 생기면 멈출 단계/대상과 계속할 안전한 단계/대상을 함께 보고한다. 큰 백업·모든 원문 편집·공개 운영을 해결할 때까지 작은 UX 개선 전체를 정체시키지 않는다.
