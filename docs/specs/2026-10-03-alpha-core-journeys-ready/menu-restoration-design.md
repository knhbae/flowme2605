# N — 항목 메뉴·복원 진입 발견성

현재 제품 계약과 직전 requirements C08/C12/C16, UX-N2의 메뉴 밀도·복원 대상 발견성을 대조했다. UX2 독립 HTML의 실제 조작을 이번 제품 검증으로 재사용하지 않는다.

| 대상 | 현행 | 좁은 변경 | 보존·검증 |
| --- | --- | --- | --- |
| 원문 항목 메뉴 | 여러 추가·연결 행동 뒤에 진행/날짜가 있으며 메뉴 제목만으로 실제 대상 줄을 알기 어렵다 | 대상 원줄의 제목, 진행·날짜/추가·연결/문서 구조의 행동 구분. 기존 진행/날짜를 위로 이동 | 같은 handler·Item·CAS·삽입 offset·키보드 Tab trap·Escape 선택 복귀·취소0쓰기 |
| 등록된 하위 항목 | 기존 메뉴에 등록·기록 유지 안내가 있다. 작은 화면에서 어절이 나뉜다 | 새 배지·해제 버튼 없이 필요한 안내에 어절 보존 | canonical 해제·완료 초기화·이력 복제·새 소속 정책 없음 |
| 계정 관리 진입 | ‘자료 가져오기 · 백업’ 이름은 복원도 지원하는 실제 결과를 드러내지 않는다 | ‘백업 · 복원 · 가져오기’로 같은 진입/창 제목을 맞춤 | 현재 계정 표시·미리보기·확인 체크·취소·writer 그대로 |
| 자료 선택 | ‘자료 선택’만으로 복원 파일을 넣는 곳인지 추측해야 한다 | ‘복원·가져올 자료 선택’으로 목적 명시 | 동일 file input·손상/다른 owner 거절·새 정책/업로드 없음 |
| 장시간 창 닫기·재진입 | 기존 요청 중 닫기/취소 제한과 durable pending 재조회가 있다 | 동작 변경 없음. 기존 회귀와 합성 제품 재진입에서 보존 확인 | 새 대형 job·전체 비동기 복원 정책을 도입하지 않음 |

메뉴의 기존 행동을 접힘으로 숨기거나 새 필수 확인을 넣지 않는다. 제목과 구분은 각 행동의 대상/의미를 드러내기 위한 것이며 문구를 상시 본문에 추가하지 않는다. 실제 화면 발견성은 후보 HTTP QA 이후 판정한다.

## C 부모 연결

부모는 동일 owner·명령 payload·expected·receipt와 정확한 개인공간 결과를 확인한 경우에만 참여 초안의 복구 안내를 현재 composer에 넘긴다. 실제 다른 변경·계정/스토리지 오류는 전역 경고를 유지한다. 원 요청 receipt가 확인돼도 이후 입력은 미저장으로 분리하며 기존 입력 보관→저장본 열기 경로만 제공한다. 새 baseline 채택·자동 후속 저장·게시·retry authority 추가는 없다.

CP1의 r6 소유34파일은 `D:/flowme2605/flow-core-cp1-r6-snapshot-20261003`에 먼저 byte 동일 사본으로 보존했다. 이 설계와 이후 코드 변경은 CP2이며 CP1 r6 근거로 표시하지 않는다.
