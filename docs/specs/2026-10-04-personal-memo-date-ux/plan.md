# 단계별 실행 계획

정본은 [목표와 경계](spec.md)다. 새 목표는 직접 사용자 시험을 강제하지 않는다.

| 단계 | 작업 | 완료 산출물 / 검사 |
| --- | --- | --- |
| 0 기준선 | clean CP2 격리·최신 main 관계·직접/dots 피드백 및 제공본 보호 확인 | baseline / 소유 경로 / 세 원천 연결 |
| 1 요구·계약 | PC01·02 source와 tests를 추적. PC03·04의 의미 충돌과 이미 완료된 범위를 분리 | requirements / 현재·갭·미결 표 |
| 2 UX 비교 | 기존 디자인 체계의 좁은 조작 HTML. 메모·날짜 시나리오의 현행과 제안 비교 | 단일 HTML / 설계 및 감산 검토 |
| 3 개발 설계 | 구현할 기존 의미 보존 변화와 정책 선택 필요 기능을 분리. handler/identity/authority/Undo 연결 | design / 표적 회귀 목록 |
| 4 구현 | 전용 작업본에서 좁은 runtime·tests 변경. HTML은 합성 in-memory state만 사용 | scoped diff / 모델·컴포넌트 검사 |
| 5 검증 | 관련 통합·npm test·build·실제 브라우저와 다섯 viewport. 실패 수정 및 보호값 비교 | qa / 실제 실행 수·PASS/FAIL/NOT_RUN |
| 6 보고 | 결과 HTML/설계·구현·갭·미결 및 다음 범위. 후보와 현재 DEV를 분리 | results / 사용자 조작 링크 / closeout |

서로 독립적인 PC01·PC02 read-only 계약 감사와 UX 감산 검토는 병렬로 진행한다. root가 작업 경계와 설계 인수를 책임진다. 초기 구현 전 근거를 읽고, 변경 후 독립 검토를 수행한다. 코드 관계는 `rg`로 먼저 추적하며 Graphify가 꼭 필요한 경우에만 사용한다.

## 검증과 자원

실계정·DB 요청 없이 합성 시나리오를 사용한다. 필요 시 이 작업본의 localhost 시험 서버만 실행하고 현재 3105/13105 서비스와 기존 Tunnel은 그대로 둔다. 비교 HTML은 네트워크·지속 저장 없이 사용자 메모를 임시 상태에서 조작한다. QA 산출물은 필요한 화면/요약만 보존하고 반복 대형 trace를 만들지 않는다.
