# 메모·날짜 UX 목표 결과

2026-10-04. 이번 격리 후보의 요구 확인·설계·좁은 구현·시뮬레이션·검증·보고를 마쳤다. **개발계에는 아직 반영하지 않았다.** 전체 UX나 PC01~04의 모든 정책 구현을 완료한 것은 아니다.

사용자가 조작할 산출물은 [단일 HTML](../../content-audit/2026-10-04-flowme-memo-date-ux-ko.html)이다. 서버·로그인 없이 파일로 열어 메모 Enter, 일반 문장, 원문 위치/날짜 이동, 취소·Undo·기간/원문 왕복을 비교한다. 아래의 `이번 목표에서 구현·검증한 범위`를 펼치면 결과와 미검증을 볼 수 있다. 저장은 임시 상태뿐이며 새로고침하면 초기 예시로 돌아간다.

## 구현한 기능

| 제품 후보의 변화 | 이유·기존 의미 |
| --- | --- |
| 메모 속성 메뉴의 실제 owner·이어쓰기 안내 | root/child를 구분해 같은 Item 메모로 이어짐을 설명. 일반 문장에는 표시하지 않음 |
| 문서 날짜 창의 현재 출처·실행 날짜 안내 | 구획 기본값과 개별 예외를 보여주고, 변경은 원문 위치를 옮기지 않는 개별 날짜임을 설명 |
| 시간만 변경할 때의 기존 날짜 고정 안내 | 현행 handler가 날짜와 시간을 함께 patch하는 효과를 숨기지 않음. 날짜 고정 정책 자체는 변경하지 않음 |

writer·API·schema·native 입력/IME·동일 ID·원래 Flow/폴더 소속·Undo의 의미는 바꾸지 않았다. helper는 읽기만 한다. HTML의 `구획 날짜 따르기`는 미결 결과 비교이며 제품 버튼·명령으로 구현하지 않았다.

## 요구·흐름별 판정

[요구 대조](requirements.md)의 MD01~05는 이번에 정한 표시·비교·보호 범위에서 충족했다. MD06 반복/복제/due는 충돌 검토만 완료했다. 작업 중 추가된 MD07 날짜 되돌림은 문서 편집의 fill·키보드·다시 열기·reload만 확인해 부분 판정이며, MD08 자유 문구/미정은 현재 계약을 확인했지만 새 전환은 미결, MD09 해당 부분 붙여넣기·취소·반복 범위는 NOT_RUN 후속이다. 이 9행을 전체 v4.1·개발1·개발2 충족률로 나누지 않는다.

세 원천의 원 ID→현재 함수/테스트→갭/미결→후보 연결은 [계약 감사](contract-audit.md)와 요구표에 남겼다. 직접 사용 피드백, dots/재검사 전달 보고, 이번 독립 합성 검증을 서로 구분했다. 새 원본 PDF/ZIP·캡처 11장은 미열람이며 전달된 PASS를 이번 검사 수에 더하지 않았다.
