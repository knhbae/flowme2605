# 공개 출처 40개 재검토 후 승인 범위

2026-10-10 사용자 승인은 원문에 없는 고정 날짜·반복을 개인 설정으로 분리하고, 처음 보류된12개와 추가 승인된12개(총24개)의 신규 발견·시작만 제한하는 범위다. 기존 개인 계획·날짜·반복·메모·진행·원본 판본은 보존한다.

## 채택한 경계

- 보류 집합은 `lib/flow/public-source-review-policy.ts`의 정확한24개 slug다. 추가12개는 미확인된 행동·조건·권리를 해결한 것으로 표시하지 않으며, 검토 완료된 수정판14개는 별도 정확 판본으로 공급한다.
- 신규 공개 목록·직접 시작·새 제작 사본 입력에서 같은 판정을 사용한다. 저장된 원문 자료실과 이미 있는 개인 사본의 재진입·멱등 응답은 별도다.
- 동결 카탈로그 payload·version·seal·과거 source validator를 다시 쓰거나 현재 정책을 과거 판본 검증에 넣지 않는다.
- 원문 검토일은 실제 수정판의 행동·조건·일정 대조를 마친 뒤 해당 판본에만 갱신한다. 날짜만 일괄 바꾸지 않는다. 기존 90/180일 기준과 미확인·기한 초과 검사도 유지한다.

## 일정 분리의 남은 적용 조건

이 절은 초기 classic reader의 위험 진단이다. 후속 구현은 신규 수정판의 sourceVersion·Flow ID·slug를 함께 기록하고, 기존 source binding이 없거나 다른 저장본은 무변이 거절한다. 구판 raw seed와 reader fallback은 보존하고 현재 수정판14개만 정확 token으로 선택한다. 신규 원문 밖 요일 선택을 만들지 않으며 개인 날짜·반복은 명시 입력으로 저장한다. 실제 서버 적용은 후속 게시·CI·운영 근거로 구분한다.

현재 classic 개인 계획은 완전한 원문 snapshot을 저장하지 않는 경로가 있고, 같은 seed ID는 최신 seed로 합쳐진다. 원시 seed 일정 값을 먼저 삭제하면 예전 개인 일정이 달라질 수 있으므로 삭제·자동 전환하지 않는다.

새 공개 계획의 일정 projection과 기존 저장본 reader를 구분한 뒤, 원문이 실제 지원하는 반복·조건·기간은 유지하고 미지원 값만 개인 선택으로 분리한다. frozen-v2의 신규 제작 사본은 별도 원본 공급이므로 현재 seed 수정만으로 해결됐다고 표시하지 않는다. 새 공급 판본이 필요하면 원본·기존 사본 보존과 실제 차이를 먼저 검토한다.

## 검증·마감

정확24개 신규 차단, 비보류 출처의 기존 기한 검사, 직접 import의 쓰기0, 기존 사본의 같은 ID 재사용을 확인한다. 미확인 출처는 신규 공급에서 보류한 사실을 남기며 이를 출처 검토 성공으로 표시하지 않는다. 검토 완료14개와 UX 후보의 정상 게시·새 정확 CI·Alpha 적용 및 재접속은 각각 실제 근거로 마감한다.

## 2026-10-10 계속 진행

1. 실제 출처 대조 제안은 같은 행동·ID의 새 원문 판본에만 적용한다. 제안의 입력 SHA/현재 필드/원 객체가 모두 맞아야 하며, 미결 필드를 삭제하거나 다른 행동으로 바꾸지 않는다.
2. 새 공개 판본과 저장된 개인 계획의 `sourceVersion`을 명시적으로 연결한다. 예전 날짜형 버전·누락·알 수 없는 버전은 기존 원문을 읽고, 새 판본은 정확 slug/Flow ID/version이 모두 맞을 때만 선택한다. 개인 overlay, CAS와 같은 사본 재진입은 유지한다.
3. 새 판본에서 원문 밖 일정은 자동 배치하지 않는다. 명시 개인 날짜·반복은 저장→새 reader→일정/내보내기에서 같은 의미로 읽는다. 과거 frozen 계약·seal·원문 replay는 그대로 둔다.
4. 콘텐츠 담당에게 실제 새 판본을 전달해 행동·조건·raw와 구조화 필드를 대조한다. 이 대조와 관련 회귀/type/build가 끝난 판본만 정상 게시·CI·기존 Alpha 절차에 연결한다. 미확인 콘텐츠를 날짜 갱신만으로 통과시키지 않는다.

## 검토 완료 판본의 신규 저장 연결

정확 본문 대조를 통과한 registry 판본을 reviewed 저장 locator와 capability에 함께 연결한다. 공개 노출이나 기계적인 projection 성공만으로 미검토 source를 허용하지 않는다. 정확 slug·Flow ID·판본 token·전체 본문 SHA와 지원 shape 검사는 필수이며 승인된 hold24가 먼저 적용된다. 과거 v1/v2/v3 allowlist·seal·validator와 이미 저장한 원문 replay는 유지한다.

reviewed-only routine 입력은 원문에 근거한 `매일`과 Item/전체 반복 목록의 일치를 검사한다. skincare에는 반복을 만들지 않고, 아침 루틴은 실제 매일 반복만 보존한다. 시작 날짜가 없으면 기존 시작일 미정 issue와 Calendar 회차0을 유지한다. 오늘/D0·30회·종료일·권리 확인은 자동 생성하지 않는다. 개인 시작일·종료 횟수는 기존 inspector의 명시 입력·저장으로만 정한다.
