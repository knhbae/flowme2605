통합 준비도는 API 가능성이 아니라 증명된 export friction으로 판단한다

이 게이트는 Flow 목적지가 copy, file export, manual import를 넘어 직접 integration이 필요한지 판단한다. 통과해도 light integration 검토가 가능해질 뿐, OAuth, account sync, token storage, automation, platform clone을 바로 승인하지 않는다.

기본값: stage0_export_only Stage 1 후보: Calendar direct save · Sheets append Hard stop: token · webhook · broad account write
Ask

API가 가능한가?

아니다. 직접 account write가 검증된 friction을 줄이는지 묻는다.

Evidence

여섯 게이트

반복 사용, import friction, stable schema, permission clarity, reversibility, source/safety transfer.

Boundary

Stage 0에는 통합 없음

증거가 없으면 export-only를 유지하고 export shape를 개선한다.

1. Stage States

stage0_export_only

모든 destination의 기본값. copy, .ics, CSV/XLSX, Markdown, Todoist CSV, Notion handoff만 허용한다.

stage1_light_integration_candidate

좁은 artifact에서 반복 export friction이 증명된 뒤 scoped direct save/append를 별도 계획으로 검토한다.

future_platform

유용하지만 workspace, task inbox, automation app 비용이 현재 evidence보다 크다.

reject_for_now

misaligned, too risky, clone/platform으로 너무 빨리 가는 요청은 boundary만 기록한다.

2. 여섯 게이트

하나라도 없으면 destination은 export-only로 남기고 export shape를 개선한다.

1

Repeated destination use

같은 artifact type에 같은 외부 도구를 반복 선택한다.

2

Import friction

copy/file import가 실제 병목이라는 관찰 증거가 있다.

3

Stable artifact schema

event fields, sheet columns, task fields가 여러 Flow 후보에서 안정적이다.

4

Permission clarity

요청할 account permission을 한 문장으로 설명할 수 있다.

5

Reversibility

사용자가 외부 destination에서 생성 항목을 찾고, 수정하고, 삭제할 수 있다.

6

Source/safety travels

source URL, caution, completion criteria, stop/hold state가 destination item에도 간다.

4. Review Questions

  1. 어떤 exact Flow artifact가 반복 export되고 있는가?
  2. 어떤 outside destination이 반복 선택되는가?
  3. manual import가 어디에서 실패하거나 느려지는가?
  4. fields가 third-party account에 쓸 만큼 안정적인가?
  5. 가장 작은 permission scope는 무엇인가?
  6. 사용자는 나중에 생성 항목을 어떻게 찾고, 수정하고, 삭제하는가?
  7. source URL, caution, completion criterion이 item과 함께 이동하는가?
  8. destination API가 실패하거나 rate-limit될 때 support burden은 무엇인가?
  9. 쓸모없을 때 integration을 닫을 user behavior evidence는 무엇인가?

5. Hard Stops

멈출 조건: platform desirability만 있고 repeated behavior가 없거나, schema가 변하고 있거나, broad write access가 필요하거나, Stage 0에 OAuth/token/API key/webhook URL을 저장해야 하거나, source/safety boundary가 destination에서 사라지면 통합으로 가지 않는다.

6. Export Fit과의 관계

Export Destination Fit은 artifact가 어디로 가야 하는지를 정한다. 이 게이트는 그 destination이 direct integration을 받을 만큼 증거가 있는지 판단한다. 순서는 항상 export fit 먼저, export behavior evidence 이후 integration readiness다.
