My Flow v10 제품 데이터 연결 기준

v9에서 확인한 원문 기반 My Flow 화면을 실제 제품 모델로 옮길 때의 기준이다. 새 사용자 UI를 만들지 않고, 기존 `FlowBundle / FlowItem / FlowItemDetail` 계약으로 먼저 표현 가능한지 확인한다.

v10 사용자 PoC v9 사용자 화면 v9 리허설 Step 계약 문서 실행 타입 기준

핵심 판단

v9를 위해 새 사용자 모델을 만들지 않는다

사용자에게 보이는 것 오늘, 일정, Flow, 지도. Step을 누르면 원문 링크, Item 체크, 메모만 보인다.
제품에 저장되는 것 FlowBundle, FlowItem, FlowItemDetail. Step은 FlowItem, Item은 detail/description/link/memo로 내려간다.
아직 결정하지 않는 것 진도형 Step을 별도 `progress_step` 타입으로 만들지 여부. 지금은 gap으로 기록한다.

계층 매핑

Flow Map > Flow > Step > Item을 기존 모델에 붙이는 법

v9 개념 제품 객체 화면 노출 외부 도구 fallback
Flow Map 부모/그룹 관계 지도 탭에서만 parent로 보임 내보내기 제목 또는 폴더/시트 그룹명
Flow `FlowBundle.flow` 개별 Flow 카드 또는 지도 안 child Flow 캘린더 이름, 시트 파일명, 메모 제목
Step `FlowItem` 오늘/일정/Flow/지도에서 누르는 최소 실행 row 캘린더 이벤트, todo row, 체크리스트 row, 시트 row
Item `FlowItemDetail` 또는 description/link Step 상세 안의 내부 체크 또는 보조 텍스트 캘린더 설명, todo body, 시트 note, 메모 bullet

v9 fixture 해석

각 컨텐츠는 현재 모델로 어디까지 표현되는가

Flow 실행 타입 자연 artifact 현재 모델 적합도 남은 gap
전세계약 전 확인 3가지 process/check todo + memo + dated reminder 좋음 법률/부동산성 주의는 check row가 아니라 source/detail에 유지.
원룸 이사 D-30 준비 timeline calendar + checklist 강함 업체명/견적/연락처는 memo로 충분. 별도 vendor form 금지.
온라인 여권 재발급 process checklist + dated reminder 좋음 사진 오류/취소 제한은 caution row가 아니라 Step detail/export body에 둔다.
중1 수학 목차 progress progress list + optional dates 부분 적합 My Flow item type에 `progress_step`이 없다. 체크/일정으로 버틸지 별도 타입이 필요한지 판단 필요.
영유아 검진·접종 일정 timeline/process calendar + memo 좋음 의료 판단처럼 보이지 않게 공식 일정 확인과 보호자 메모를 분리.

Step export

사용자 화면은 단순하게, export body는 충분하게

사용자 Step 상세 일정, 저장 위치, 진행 상태, 원문 링크, Item 체크, 메모.
캘린더/투두/시트로 나갈 때 Step title, source URL, completion 기준, Item bullet, memo hint가 description/body/note로 들어간다. 
SUMMARY: 원룸 이사 D-30 준비 - 이삿짐센터·입주청소 예약
DESCRIPTION:
이사 한 달 전 예약해야 하는 항목만 먼저 처리합니다.
Items:
- 이삿짐센터 견적 3곳 비교: 포장 범위와 비용을 같이 봅니다.
- 입주청소 예약: 청소 날짜와 포함 범위를 확인합니다.
- 줄일 짐 메모: 버릴 물건과 줄일 짐을 짧게 적습니다.
Memo:
업체명, 견적, 포함 범위, 연락처만 남기세요
Source:
KB Think 원룸 이사 체크리스트

다음 구현 slice

코드로 바로 들어가기 전 필요한 최소 작업

  1. v9 fixture를 `FlowBundle` 형태로 표현하는 작은 adapter 또는 seed fixture를 만든다.
  2. Step이 `FlowItem`, Item이 `FlowItemDetail`/description/link로 보존되는지 테스트한다.
  3. dated Step이 기존 ICS export에서 충분한 description을 갖는지 확인한다.
  4. 중1 수학 같은 progress row가 현재 item type으로 충분한지, 아니면 `progress_step`이 필요한지 한 번 더 본다.
