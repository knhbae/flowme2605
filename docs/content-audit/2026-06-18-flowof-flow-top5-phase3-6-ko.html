Phase 5: 사용자/제작자 시뮬레이션과 반복 개선

1차 문제 → 수정 방향 → 재판정
후보 사용자 시뮬레이션 제작자 시뮬레이션 발견 문제 적용한 개선 방향
NHS Couch to 5K 러닝 초보가 원문을 보고 전체 9주를 저장한다. 며칠 뒤 내 앱에서 오늘 Run 1만 본다. 운동 제작자가 주차별 러닝 세션을 가져와 같은 세션 패턴으로 발행한다. 27개 세션을 한 번에 보여주면 과하다. 저장 전은 9주 구조만, 내 앱은 오늘 세션만. 전체 지도는 접어둔다.
JustinGuitar 기타 초보가 Grade 1 전체를 저장하지 않고 Module 1만 먼저 저장한다. 음악 제작자가 각 모듈의 연습 루틴과 통과 기준을 반복 패턴으로 묶는다. 레슨 내용을 FLOW 안에서 다시 설명하려는 유혹이 크다. FLOW는 연습 일정/통과 체크만 담당하고, 자세한 레슨은 원문 링크로 보낸다.
freeCodeCamp RWD 학습자가 인증 전체를 저장하고, 이번 주에는 HTML/CSS 모듈만 실행한다. 코스 제작자가 모듈/프로젝트/퀴즈를 가져와 진도표로 발행한다. 외부 LMS와 중복되어 FlowMe 가치가 약해질 수 있다. 코드 학습 콘텐츠를 복제하지 않고, 진도/목표일/프로젝트 상태만 관리한다.
RHS Crop Planner 초보 가드너가 키울 작물 3개만 골라 작물별 캘린더를 만든다. 가드닝 제작자가 작물 행을 가져와 파종/정식/수확 패턴을 반복 적용한다. 지역/기후가 맞지 않으면 일정이 틀릴 수 있다. 원문 지역을 명시하고, 로컬 변환 전에는 "RHS 기준 일정"으로 표시한다.
Solid Starts 보호자가 아기 생년월일을 넣고 현재 월령대 식사 스케줄을 확인한다. 육아 제작자가 월령별 식사 전환 흐름을 공식/경험/주의로 나눠 발행한다. 영양/의료 판단 앱처럼 보이면 위험하다. 권장/처방처럼 쓰지 않고 월령별 참고 일정, 메모, 원문 확인으로 제한한다.

1차 공통 문제

  • 전체 구조를 너무 많이 보여주면 내 앱 화면이 다시 설명서처럼 보인다.
  • 하위 Flow를 너무 잘게 쪼개면 사용자는 왜 저장해야 하는지 잃는다.
  • 교육/코스 후보는 외부 LMS를 복제하는 순간 FlowMe 가치가 약해진다.
  • 육아/건강 후보는 source/risk 분리가 없으면 공개 후보로 두면 안 된다.

재설계 후 기준

  • 상위 지도는 저장 전과 진행 보기에서만 보인다.
  • 내 앱 첫 화면은 오늘 실행, 체크, 메모, 원문 링크만 둔다.
  • 제작자는 하위 Flow 패턴을 만들고 원문 근거를 붙인다.
  • 사용자는 전체 저장과 일부 저장을 선택할 수 있다.

최종 판단: 수학 외 Flow of Flow도 가능하다. 하지만 다음 클릭 PoC는 5개 전체가 아니라 NHS 러닝, RHS 작물표, JustinGuitar 세 개부터 만드는 것이 맞다. freeCodeCamp와 Solid Starts는 구조 검증용/조건부 후보로 둔다.

다음 작업 정의

바로 할 작업

  1. NHS Couch to 5K 사용자용 클릭 PoC를 만든다.
  2. 같은 원문을 제작자 화면에서 가져와 하위 Flow 패턴으로 발행하는 화면을 만든다.
  3. 내 Flow 관리 화면에서 "러닝 9주 플랜"이 어떻게 보이고 오늘 실행으로 내려오는지 만든다.
  4. 사용자/제작자 시뮬레이션을 한 번 더 돌리고, 과하면 줄인다.

성공 기준

  • 사용자가 첫 화면에서 저장 결과를 예측한다.
  • 제작자가 하위 Flow 패턴을 이해한다.
  • 내 앱 화면은 전세 Flow처럼 가볍다.
  • Flow of Flow가 단순 묶음이 아니라 반복 하위 실행 구조로 보인다.

연결 문서

  • 100개 원컨텐츠 스캔과 Top 5 후보
  • Context Split 확산 원칙

이 문서는 실제 사용자 행동 데이터가 아니라, 원컨텐츠 구조와 UX 운영 가능성을 판단하기 위한 PoC 전 단계 리포트다.
