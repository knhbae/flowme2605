1. 현재까지의 답

나온 것

URL-first 실행 루프

현재 구현과 문서는 URL을 붙여넣고 기존 Flow를 찾은 뒤, 시작일과 export를 골라 My Flow로 저장하는 흐름까지 상당히 구체화되어 있다.

나온 것

My Flow 개인 사본

개인 저장 이름, 시작일, 포함/제외 Step, Step detail export, Calendar 반영까지 이어지는 실행 모델은 방향이 잡혀 있다.

부족한 것

URL과 메모의 한 장짜리 이야기

기존 산출물은 URL-first와 source-backed QA에 강하지만, 메모 입력이 같은 진입 UX로 들어와 export/My Flow까지 수렴하는 스토리보드는 따로 필요하다.

결론: 원래 목표에 맞추려면 “URL을 찾는 화면”이 아니라 “URL이나 메모를 실행 가능한 계획으로 바꾸는 시작 화면”으로 봐야 한다. 이 보드는 그 통합 그림을 눈으로 검토하기 위한 기준안이다.

2. 통합 모델: 같은 입구, 같은 준비 패널, 같은 실행 결과

사용자는 “콘텐츠 URL을 붙여넣는 사람”과 “메모장에 계획을 적는 사람”으로 나뉘지만, FlowMe 안에서는 같은 구조로 만난다. 차이는 원천이 URL인지 메모인지뿐이고, 결과는 모두 가벼운 수정, export, My Flow 실행으로 수렴한다.

1. 가져오기 URL 붙여넣기 또는 메모 쓰기. 사용자는 아직 편집기를 열지 않는다.
2. 판별 URL은 hit/needs_review/miss, 메모는 초안 가능/정보 부족/관련 Flow 추천으로 나뉜다.
3. 미리보기 실행 가능한 항목, 날짜, 반복, 출처 또는 메모 근거를 먼저 보여준다.
4. 가볍게 조정 시작일, 저장 이름, 포함/제외 Step, 내보내기 방식을 고른다.
5. 옮기기 Markdown, 체크리스트, ICS, TSV 또는 My Flow 저장으로 보낸다.
6. 실행·재사용 My Flow Today, Calendar, Step detail, export 재생성에서 개인 상태를 유지한다.

3. URL·메모 상태 설계

URL 입력 상태

상태사용자에게 보이는 의미허용 행동
hit 같은 원문 기준으로 이미 실행 가능한 계획이 있다. 그대로 시작, 조금 고쳐 시작, export, My Flow 저장.
needs_review 원문은 알지만 바로 실행시키기엔 검토가 필요하다. 제작 후보 저장, 원문 열기, 나중에 다시 조회. 실행/저장/export는 막는다.
miss 아직 FlowMe 안에 연결된 실행 계획이 없다. 제작 후보 저장, 제목/메모 남기기, 제작용 Markdown 복사.
resolved-hit 전에 저장한 후보가 나중에 실행 가능한 Flow로 바뀌었다. 후보 목록에서 바로 hit 결과와 시작 흐름으로 이동.

메모 입력 상태

상태사용자에게 보이는 의미허용 행동
memo draft 메모에서 실행 항목, 날짜, 반복, 준비물이 어느 정도 보인다. 초안 미리보기, 항목 포함/제외, Markdown/checklist/TSV/ICS export.
needs detail 메모가 너무 짧거나 날짜·행동 단위가 모호하다. 질문 1~2개만 보강, 메모 저장, 텍스트 복사. 과한 폼은 열지 않는다.
related Flow 메모와 비슷한 기존 Flow가 있어 가져다 쓸 수 있다. 기존 Flow 추천, 개인 사본 만들기, 내 메모를 시작 전 조정값으로 반영.
plain note 일단 메모로만 남기는 편이 더 빠르다. Markdown 복사와 My Flow 메모 보관만 제공. 실행 Flow처럼 과장하지 않는다.

중요 제약: 이 보드의 메모 입력 흐름은 향후 방향 검토용이다. 여기서 AI 자동 생성, 크롤링, 서버 저장, 외부 API 연동을 구현했다는 뜻이 아니다.

4. 통합 스토리보드

아래 장면들은 실제 화면 설계를 확정한 것이 아니라, 사용자가 어떤 판단을 어떤 순서로 해야 하는지 검토하기 위한 와이어플로우다. 화면 이름은 구현 라우트와 연결하되, 문구는 일반 사용자가 이해하는 말로 적었다.

시작: URL이든 메모든 같은 곳에서 시작

홈이나 Flow 찾기에서 사용자는 “링크 붙여넣기”와 “메모로 쓰기”를 같은 진입 카드에서 본다.

Flow 찾기
콘텐츠 URL을 붙여넣거나 오늘 계획을 적어보세요
URL로 가져오기 메모로 쓰기
  • 처음부터 “AI 만들기”를 앞세우지 않는다.
  • 기존 URL 조회와 가벼운 메모 초안을 같은 모델로 보이게 한다.

URL hit: 이미 만들어진 계획을 찾음

같은 canonical URL로 등록된 source-backed Flow가 있으면 바로 실행 가능한 결과로 보여준다.

찾은 결과
원룸 이사 D-30 준비실행 가능
원문출처 추적 있음
그대로 시작 조금 고쳐 시작
  • 사용자는 “찾았다”와 “바로 실행 가능하다”를 먼저 이해해야 한다.
  • 출처와 원문은 보이되 첫 화면을 무겁게 만들지 않는다.

시작 전 조정: 전체 편집기 없이 개인 사본 만들기

사용자는 시작일, 저장 이름, 포함/제외 Step, 내보내기 방식만 고른다.

조금 고쳐 시작
시작일8월 1일
저장 이름우리집 이사 준비
Step견적, 주소 이전 포함 / 가구 구매 제외
내보내기체크리스트 + 캘린더 파일
  • 원본 Flow는 유지하고 My Flow에는 개인 사본으로 저장한다.
  • excluded Step은 실행 목록에서 빠지거나 별도 “제외됨”으로 분리한다.

URL needs_review/miss: 실행이 아니라 제작 후보

바로 실행할 수 없는 URL은 사용자의 관심을 잃지 않도록 후보로 저장하되, Flow처럼 과장하지 않는다.

아직 실행할 수 없음
제목: 따라 하고 싶은 블로그 계획
메모: 9월에 해보고 싶음. 준비물과 기간이 있는지 확인 필요.
제작 후보로 저장 원문 열기
  • AI 생성, 크롤링, 자동 seed 생성은 하지 않는다.
  • 저장 정보는 canonical URL, 원 URL, 제목/메모, 상태, 저장일로 충분하다.

후보 관리: 나중에 다시 찾고 운영으로 넘김

후보 목록은 단순 저장함이 아니라 원 URL 열기, 다시 조회, 제목/메모 수정, 제작용 Markdown 복사를 제공한다.

내가 요청한 후보
블로그 계획 A제작 대기
공식 안내 B원문 확인 대기
다시 조회 제작용 정보 삭제
  • 운영자는 후보 Markdown을 보고 source-backed Flow 등록 checklist를 수행한다.
  • 사용자 화면에서는 아직 실행 가능한 Flow가 아니라고 분명히 표시한다.

resolved-hit: 후보가 실행 가능한 Flow로 바뀜

같은 canonical URL이 나중에 hit으로 바뀌면 후보 카드에서 바로 시작 흐름으로 이동한다.

후보 업데이트
예전에 저장한 콘텐츠이제 실행 가능
계획 열고 시작 원문 보기
  • 후보 저장 루프가 My Flow 시작 루프로 닫힌다.
  • 중복 canonical URL은 “기본 hit 1개” 정책을 유지한다.

메모 입력: 메모장처럼 빠르게 쓰기

사용자는 앱 구조를 배우기 전에 일단 본인이 하던 방식대로 계획을 적는다.

메모로 쓰기
8월 말 이사 예정. 이번 주 부동산 연락, 다음 주 견적 3곳, 8/20 주소 이전, 전날 냉장고 비우기.
실행 초안 보기 메모로만 보관
  • Obsidian, 메모장, 카톡 나에게 보내기 같은 습관을 대체하지 않고 받쳐준다.
  • 필수 필드를 먼저 요구하지 않는다.

메모 초안: 날짜와 할 일을 구조화해서 보여줌

메모에서 보이는 항목을 Step 후보로 나누고, 사용자가 포함/제외를 고르게 한다.

초안 미리보기
이번 주부동산 연락
다음 주견적 3곳
8/20주소 이전
전날냉장고 비우기
  • 이 단계는 “자동 완성된 정답”이 아니라 사용자 확인용 초안이다.
  • 모호한 날짜는 질문 1~2개로만 보강한다.

메모와 기존 Flow 연결: 새로 만들기 전에 먼저 찾음

메모가 이사, 예방접종, 세무처럼 기존 Flow와 맞으면 추천 Flow를 보여주고 개인 사본으로 시작하게 한다.

관련 계획 발견
비슷한 계획원룸 이사 D-30 준비
내 메모 반영8월 말 기준 시작일 제안
이 계획으로 시작 메모 초안만 쓰기
  • AI 비용을 쓰기 전에 기존 Flow 재사용을 우선한다.
  • 사용자의 메모는 시작일, 저장 이름, 제외 Step 같은 조정값으로 들어간다.

내 도구로 옮기기: export가 목적지별로 분명함

메모 앱, Obsidian, todo, calendar, sheet 사용자는 FlowMe 안에 오래 머물지 않아도 된다.

내 도구로 옮기기
Markdown 복사 체크리스트 복사 ICS 다운로드 TSV 복사
ICS날짜 있는 Step만 가능
기준원본이 아니라 내 개인 사본
  • 출처는 유지하지만 export 내용은 개인 수정 상태 기준이다.
  • 외부 API 직접 연동 없이 파일·복사 중심으로 시작한다.

My Flow 저장: 실행 큐로 이어짐

저장 후에는 카탈로그가 아니라 오늘 할 일, 다음 일정, 전체 목록으로 이어져야 한다.

내 Flow
오늘 할 일견적 후보 정하기
다음 일정8/20 주소 이전
개인 사본우리집 이사 준비
상세 열기 설정 조정
  • 개인 사본인 Flow에만 저장 이름, 시작일, Step 포함/제외 조정을 허용한다.
  • 원본 업데이트가 있어도 개인 선택을 덮어쓰지 않는다.

Calendar: 날짜가 있는 항목만 일정으로 보임

Calendar는 전체 계획 설명이 아니라 날짜가 있는 실행 항목을 빠르게 확인하는 표면이다.

날짜 없음전체 탭에서 관리
  • 시작일 변경은 Today, Calendar, ICS에 같이 반영되어야 한다.
  • 일정표와 할 일 목록의 역할을 섞지 않는다.

Step detail: 실행·메모·출처·export를 한 곳에서 확인

모바일에서는 Step 제목과 체크가 먼저 보이고, 원문·내 도구 영역은 접힌 상태로 둔다.

Step detail
할 일주소 이전 신청
체크우편, 은행, 보험
접힘원문·내 도구
Markdown 복사 ICS 받기 TSV 복사
  • Step detail export도 포함된 Step과 현재 날짜 기준만 사용한다.
  • 출처는 추적 가능하되 사용자의 실행 흐름을 방해하지 않는다.

다시 조정: 실행 중에도 가볍게 수정

전체 편집기가 아니라 저장 이름, 시작일, 포함/제외 Step만 다시 바꿀 수 있다.

저장 이름가족 이사 준비
시작일8/3로 변경
다시 포함가구 구매 Step
변경 저장 취소
  • 변경 즉시 Today, 전체, Calendar, Markdown/ICS/TSV export에 반영한다.
  • Step 내용 재작성, 버전 관리, 계정 저장은 이 범위가 아니다.

5. Obsidian·메모장·todo/calendar 사용자 기준선

기준 사용자지금 익숙한 행동FlowMe가 넘지 말아야 할 선FlowMe가 더해줄 가치
메모장 사용자 생각나는 대로 적고 자주 고친다. 처음부터 카테고리, 날짜, 우선순위, 프로젝트를 강요하지 않는다. 메모에서 날짜·할 일 후보를 보여주고 Markdown/checklist로 바로 복사한다.
Obsidian 사용자 Markdown으로 정리하고 링크·문서 구조를 중시한다. Obsidian 전체 workspace를 대체하려 하지 않는다. 원문 URL, 실행 Step, 체크리스트, TSV/ICS 링크를 깔끔한 Markdown으로 내보낸다.
기존 todo 사용자 실행 항목을 작게 쪼개 완료 처리한다. FlowMe 안에서 복잡한 task management를 새로 배우게 하지 않는다. 출처가 있는 계획을 체크리스트 텍스트나 행 데이터로 넘긴다.
기존 calendar 사용자 날짜가 있는 일정을 캘린더에서 본다. 날짜 없는 항목까지 억지로 캘린더에 넣지 않는다. 상대일과 시작일을 실제 날짜로 바꿔 ICS로 저장하고 FlowMe Calendar에서도 확인한다.

6. 다음 제품 판단

P0

통합 진입 UX를 눈으로 검토

현재 `/flows`의 URL-first 화면을 기준으로, 메모 탭이 붙었을 때 첫 화면이 복잡해지는지 검토한다.

  • URL hit/custom start/miss 후보가 이미 이해되는가
  • 메모 탭이 URL-first의 비용 절감 원칙을 흐리지 않는가
  • 시작 전 조정 패널이 너무 무겁지 않은가
P1

메모 초안 PoC를 작게 자르기

AI 자동 생성 전, 구조화 규칙과 수동 확인 UX만으로 “메모 → export/My Flow”의 최소 가치가 있는지 본다.

  • 날짜 있는 줄만 ICS 가능
  • 체크리스트와 Markdown은 항상 가능
  • 관련 기존 Flow 추천을 먼저 시도
P2

자동화와 직접 연동은 뒤로

반복 사용이 보인 뒤에 AI fallback, 서버 저장, 외부 API 연동, 공유/creator loop를 붙인다.

  • 비용과 품질 gate가 필요
  • 출처와 개인 수정본의 책임 경계가 필요
  • 계정 없는 localStorage 모델의 한계를 다시 판단

FLOW UX 자체 점검

강한 점

  • URL과 메모를 별도 제품처럼 만들지 않고 같은 실행 모델로 수렴시킨다.
  • AI 비용을 쓰기 전에 URL lookup과 기존 Flow 재사용을 우선한다.
  • 메모장, Obsidian, todo, calendar 사용자를 export-first로 받아들인다.
  • 개인 사본과 원본 source 추적의 책임 경계를 유지한다.

리스크

  • 메모 입력을 너무 빨리 강조하면 URL-first 검증 초점이 흐려질 수 있다.
  • 초안 미리보기가 자동 생성처럼 보이면 신뢰 문제가 생긴다.
  • export 옵션이 한 화면에 많으면 모바일 첫 화면이 무거워진다.
  • needs_review/miss 후보가 실행 가능한 Flow처럼 보이면 사용자 기대를 잘못 만든다.
