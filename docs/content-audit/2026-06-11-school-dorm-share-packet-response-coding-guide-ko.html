관찰 답변을 같은 기준으로 pass, fail, unclear로 나눕니다

이 문서는 학교/기숙사 공유 패킷 세션에서 나온 답변을 코딩하는 기준표입니다. 실제 관찰 결과가 아니며, matching slot이 agreed이고 3 completed usable sessions가 채워지기 전까지 evidence board의 상태는 계속 no signal입니다.

1. 공통 코딩 규칙

pass

받는 사람이 FlowMe 설명 없이 필요한 행동이나 경계를 스스로 말할 때만 씁니다.

fail

FlowMe가 출처, 저장소, 전송자, 자동 수집자, 채널 추적자라고 기대하면 fail입니다.

unclear

부분 답변이거나 모호해서 안전하게 pass로 볼 수 없으면 unclear입니다.

2. 체크별 판정 기준

관찰자가 대신 해석하지 말고, 받는 사람이 실제로 말한 내용을 기준으로 적습니다.

체크passfailunclear
First action최신 학교/기숙사 공지나 공식 출처부터 확인한다고 말합니다.FlowMe 기억이나 패킷을 최종 기준으로 봅니다.어딘가 확인한다고만 말하고 최신 공지/공식 출처를 특정하지 못합니다.
Four labels네 개 응답 라벨을 수동 응답 상태로 설명합니다.라벨을 자동 처리, 전달 보장, 전체 완료로 이해합니다.일부 라벨만 설명하거나 제품 설명을 추가로 요구합니다.
Latest-notice priority최신 공식 공지가 패킷보다 우선한다고 말합니다.패킷, FlowMe, 오래된 저장 내용이 우선한다고 말합니다.명확한 갱신 규칙 없이 상황에 따라 다르다고만 말합니다.
No-store values건강, 결제, 신원, 방, 채널, 초대, form edit, webhook, 연락처, 채팅 로그 값을 피합니다.차단된 민감값을 입력하거나 저장하자고 말합니다.일부 값은 피하지만 차단 범주를 빠뜨립니다.
Manual-copy boundary사용자가 직접 복사/전송하고 직접 답장을 확인한다고 말합니다.FlowMe가 전송, 게시, 답장 수집, 연락처 저장, 채널 추적을 한다고 기대합니다.FlowMe와 사용자의 역할을 분리하지 못합니다.

3. 세션 단위 판정

usable 조건

  • 같은 locked packet version 사용
  • 태스크 전 FlowMe 설명 없음
  • 민감값 기록 없음
  • 다섯 체크 모두 질문됨
  • 결과가 pass/fail/unclear 중 하나

candidate signal 금지선

usable session 안에 fail 또는 unclear가 하나라도 있으면 candidate signal이 아닙니다. friction 또는 no signal로 남깁니다.

Session decision쓰는 경우다음 행동
pass다섯 체크가 모두 pass입니다.rollup에 사용합니다.
frictionfail 또는 unclear가 있지만 비식별 요약은 가능합니다.rollup 뒤 패킷 문구를 수정하고 재관찰합니다.
stopped민감값, 자동화 오해, 안전 혼선으로 계속하기 어렵습니다.중단 범주만 남깁니다.
not usable버전, 진행, 메모가 일관되지 않습니다.candidate signal 근거에서 제외합니다.
