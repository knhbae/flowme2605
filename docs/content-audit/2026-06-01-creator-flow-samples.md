# 원문 기반 제작자형 정답 Flow 샘플

Date: 2026-06-01

이 문서는 자동 exampleFlow를 그대로 믿지 않고, 원문에서 확인 가능한 실행 신호를 기준으로 사람이 검토한 대표 Flow 샘플이다. 목적은 My Flow UX/UI 검증, 사용자 유용성 검증, 제작 프롬프트/로직 기준 수립이다.

## 결론 먼저

- 바로 seed로 실험할 우선 후보: 세탁기 청소/관리 Flow, 크리에이터 콘텐츠 엔진 Flow, 중고차 후보 점검 Flow, 온라인 코스 출시 준비 Flow
- My Flow UX를 가장 잘 검증하는 후보: 중고차 후보 점검 Flow, 크리에이터 콘텐츠 엔진 Flow, 초보 식물 관리 Flow
- 캘린더 과밀을 가장 강하게 드러내는 후보: 초보 식물 관리 Flow, 30일 글쓰기 챌린지 Flow, 30일 초보 운동 플레이리스트 Flow, 100일 코딩 챌린지 Flow
- 민감 영역 경계 검증 후보: 세탁기 청소/관리 Flow, 중고차 후보 점검 Flow, 초기 이유식 반응 기록 Flow, 30일 초보 운동 플레이리스트 Flow
- 지금 결론: FlowMe는 "원문을 복제하는 앱"이 아니라 "원문을 실행 가능한 일정/체크/기록/상태로 바꾸는 앱"이어야 한다.


## 요약

- 대표 샘플: 12개
- Deep sample: 3개
- Seed 후보: 12개
- 출처 구조: official_plus_creator(공식 정보 + 제작자 경험), template(Notion/Gumroad 템플릿), source_bundle(제작자 여러 URL 묶음), single_url(단일 URL), youtube_playlist(유튜브 플레이리스트), blog_series(블로그 시리즈)

## 후보 그룹

### 1. Seed 우선 후보
- 세탁기 청소/관리 Flow: 4.6점, seed 우선 후보
- 크리에이터 콘텐츠 엔진 Flow: 4.6점, seed 우선 후보
- 중고차 후보 점검 Flow: 4.6점, seed 우선 후보
- 온라인 코스 출시 준비 Flow: 4.5점, seed 우선 후보

### 2. 제작자가 공유/판매하기 좋은 후보
- 크리에이터 콘텐츠 엔진 Flow: 제작자의 운영 시스템을 실행 Flow로 바꾸기 좋음
- 온라인 코스 출시 준비 Flow: 제작자의 운영 시스템을 실행 Flow로 바꾸기 좋음
- 블로그 시작 운영 Flow: 제작자의 운영 시스템을 실행 Flow로 바꾸기 좋음

### 3. My Flow UX 한계를 드러내는 후보
- 초보 식물 관리 Flow: 루틴이 많으면 캘린더 칸이 지저분해진다.
- 30일 글쓰기 챌린지 Flow: 월간 캘린더에 30개 텍스트가 깔리면 과밀하다.
- 30일 초보 운동 플레이리스트 Flow: 캘린더 안에서 영상 제목이 길면 모바일이 깨진다.
- 100일 코딩 챌린지 Flow: 100개 반복 일정이 월간 캘린더를 압도한다.

### 4. 출처/위험 경계가 중요한 후보
- 세탁기 청소/관리 Flow: 수리, 전기, 누수 위험은 서비스 문의 트리거로만 다룬다.
- 중고차 후보 점검 Flow: 법적/정비 판단은 공식 조회와 전문가 확인 메모로 제한한다.
- 초기 이유식 반응 기록 Flow: 이상 반응은 즉시 전문가/기관 상담 메모로 제한한다.
- 30일 초보 운동 플레이리스트 Flow: 통증, 어지러움, 호흡곤란, 기존 질환 악화 시 중단/전문가 상담 문구를 둔다.


## 다음 UX/UI 우선순위

- 월간 캘린더의 루틴은 긴 텍스트 카드보다 아이콘/개수 중심으로 줄인다.
- 증빙은 모든 Flow의 기본 입력이 아니라 비교/계약/제출/결정 Flow의 선택 필드로 둔다.
- 모바일 Flow 탭은 상태판과 전체 목록을 동시에 길게 보여주지 말고, 상태 카드를 누르면 해당 목록만 펼친다.
- 민감 영역은 완료 체크보다 기록/상담/공식 확인 메모를 먼저 보이게 한다.
- 자동 변환은 출처 구조와 목적지를 먼저 고른 뒤 오늘/캘린더/상세/완료 기준으로 분리한다.

## 1. 세탁기 청소/관리 Flow

- 대표 유형: 공식 정보 + 제작자 경험 혼합형
- 출처 구조: official_plus_creator (공식 정보 + 제작자 경험)
- 목적지/구조: calendar + memo / maintenance_routine
- 평균 점수: 4.6 (seed 우선 후보)

### 실제 생성 예시
- 사용자 상황: 서울 원룸에 사는 1인 가구
- 입력값: 제품: 삼성 드럼세탁기 / 마지막 청소일: 2026-05-18 / 반복: 4주마다
- 오늘 탭: 세탁통 청소 실행 / 냄새/소음 여부 메모
- 캘린더: 2026-06-15 세탁통 청소 / 2026-07-13 세탁통 청소 / 매월 첫째 주 필터/외관 점검
- 체크/상태:
  - 공식 청소 안내 링크 열기
  - 세탁통 청소 실행 후 마지막 청소일 갱신
  - 냄새/누수/소음이 있으면 서비스 문의 보류로 표시
- 상세 메모: 공식 안내는 링크로 열고, 오늘은 세탁통 청소 완료 여부와 이상 징후만 기록한다. 블로그 후기는 준비물 참고로만 둔다.
- 사용자가 보는 결과: 다음 청소일이 자동으로 생기고, 이상 징후가 있으면 완료가 아니라 '서비스 확인 필요' 상태로 남는다.

### 원문 URL
- 공식: [Samsung Service - 세탁기 청소 방법](https://www.samsungsvc.co.kr/solution/41708)
- 경험담: [블로그 세탁기 관리 후기](https://spygogo.tistory.com/691)

### 원문에서 확인한 실행 신호
- 공식 정보는 모델/부품/안전 기준에 가깝고, 블로그는 실제 청소 경험과 준비물 맥락을 준다.
- 주기적 관리 루틴과 이상 징후 시 서비스 문의 트리거가 있다.
- 공식 정보와 개인 경험을 섞으면 위험하므로 분리 표시가 필요하다.

### 사용자 목표
세탁기 청소 주기를 놓치지 않고, 이상 징후가 보이면 공식 안내나 서비스 문의로 연결한다.

### 제작자가 공유/판매하고 싶을 이유
가전 관리 블로거가 공식 링크와 자신의 관리 루틴을 묶어 실사용 Flow로 공유하기 좋다.

### 사용자 입력 1~3개
- 제품명 또는 모델
- 마지막 청소일
- 청소 주기

### My Flow 노출 예시
- 오늘 탭: 세탁통 청소 일정 확인 / 이상 소음/냄새 여부 메모
- 캘린더: 사용자 주기 반복 - 세탁통 청소 / 월 1회 - 필터/외관 점검
- 체크/루틴/기록/상태:
  - 제품 모델 메모 (check_task): 제품명 또는 공식 안내 링크가 저장됨
  - 세탁통 청소 실행 (routine_session): 오늘 청소 완료일이 갱신됨
  - 이상 징후 기록 (log_entry): 냄새, 누수, 소음 중 해당 사항이 기록됨
  - 서비스 문의 판단 (decision_hold): 공식 확인 필요 여부가 표시됨

### 상세 메모에 들어갈 원문 요약
공식 안내 링크와 개인 후기 링크를 분리하고, Flow에는 모델, 주기, 오늘 점검 결과만 남긴다.

### 완료 기준
마지막 청소일과 다음 점검일이 갱신되고 이상 징후 메모가 정리됨

### 보류/탈락 조건
- 제품 분해나 수리 조언처럼 보이면 탈락
- 공식 정보와 블로그 경험을 같은 권위로 보여주면 탈락

### 저작권/출처/위험 경계
- 저작권: 공식/블로그 문장을 복제하지 않고 링크와 관리 필드만 둔다.
- 출처: 공식 안내와 제작자 경험을 분리 라벨링한다.
- 위험: 수리, 전기, 누수 위험은 서비스 문의 트리거로만 다룬다.

### My Flow UX에서 예상되는 문제
- 관리 루틴은 캘린더에 텍스트보다 아이콘/개수로 표시하는 편이 낫다.
- 상세에서 공식/경험 출처가 분리되어 보여야 한다.

## 2. 크리에이터 콘텐츠 엔진 Flow

- 대표 유형: 제작/운영 파이프라인형
- 출처 구조: template (Notion/Gumroad 템플릿)
- 목적지/구조: sheet + calendar / production_pipeline
- 평균 점수: 4.6 (seed 우선 후보)

### 실제 생성 예시
- 사용자 상황: 주 3회 숏폼을 올리는 1인 크리에이터
- 입력값: 채널: 인스타 릴스 / 주간 발행 수: 3개 / 다음 발행일: 2026-06-04
- 오늘 탭: 다음 발행물 상태를 '편집 중'으로 이동 / 막힌 콘텐츠 1개 보류 사유 작성
- 캘린더: 2026-06-04 릴스 발행 / 매주 월요일 아이디어 3개 정리 / 매주 금요일 다음 주 발행 슬롯 확인
- 체크/상태:
  - 아이디어 3개 입력
  - 다음 발행물 상태 갱신
  - 발행일 캘린더 등록
  - 촬영 대기 콘텐츠 보류 사유 남기기
- 상세 메모: 템플릿 전체 DB를 복제하지 않는다. Flow에는 제목, 채널, 상태, 다음 행동, 발행일만 둔다.
- 사용자가 보는 결과: 아이디어 목록이 아니라 오늘 발행에 가까운 콘텐츠와 막힌 이유가 먼저 보인다.

### 원문 URL
- 템플릿: [Ktoolz - Content Engine](https://ktoolz.gumroad.com/l/content-engine)

### 원문에서 확인한 실행 신호
- 아이디어, 제작, 예약, 발행, 재활용 같은 상태 전이가 핵심이다.
- 템플릿 전체를 복제하기보다 제작자가 반복적으로 쓰는 상태와 마감만 Flow화해야 한다.
- 콘텐츠 제작자는 자신의 운영 시스템을 판매할 인센티브가 강하다.

### 사용자 목표
이번 주 만들 콘텐츠가 아이디어에 머무르지 않고 초안, 편집, 예약, 발행 상태로 이동하게 한다.

### 제작자가 공유/판매하고 싶을 이유
콘텐츠 시스템 제작자가 Notion/Gumroad 템플릿의 실행 버전을 Flow로 판매하기 좋다.

### 사용자 입력 1~3개
- 콘텐츠 채널
- 주간 발행 수
- 다음 발행일

### My Flow 노출 예시
- 오늘 탭: 다음 발행 콘텐츠 상태 갱신 / 막힌 콘텐츠 보류 사유 남기기
- 캘린더: 사용자 지정 - 다음 발행일 / 매주 반복 - 주간 아이디어 정리
- 체크/루틴/기록/상태:
  - 아이디어 3개 입력 (check_task): 제목 후보와 채널이 입력됨
  - 다음 발행물 상태 이동 (pipeline_state): 아이디어/초안/편집/예약/발행 중 하나로 표시됨
  - 발행일 예약 (scheduled_task): 캘린더에 발행 마감이 보임
  - 막힌 이유 기록 (decision_hold): 자료 부족, 촬영 대기, 승인 대기 중 하나가 표시됨

### 상세 메모에 들어갈 원문 요약
템플릿 DB 구조를 복제하지 않고 Flow에는 최소 상태, 다음 마감, 보류 이유만 둔다.

### 완료 기준
이번 주 발행할 콘텐츠의 상태와 다음 행동이 명확함

### 보류/탈락 조건
- 입력 필드가 템플릿 수준으로 많아지면 실패
- Flow 안에서 전체 CMS를 만들려 하면 탈락

### 저작권/출처/위험 경계
- 저작권: 유료 템플릿 구조를 복제하지 않는다.
- 출처: 제작자의 템플릿 설명과 사용자의 콘텐츠 상태를 분리한다.

- 위험: 타인 촬영/장소 촬영의 개인정보와 허가 이슈를 메모로 둔다.

### My Flow UX에서 예상되는 문제
- 첨부/사진 링크 입력이 상세에서 너무 깊으면 사용성이 떨어진다.
- 메모 항목은 기본 노출하는 편이 낫다.

## UX/UI 검증 결과 요약

### 충분한 부분
- 오늘 탭, 캘린더, Flow별/상태별 관점은 대표 케이스 대부분을 담을 수 있다.
- 일정형, 루틴형, 체크형을 상위 노출 타입으로 유지하고 내부 secondary type으로 memo_evidence, log_entry, decision_hold를 두는 방향은 타당하다.
- 중고차, 콘텐츠 파이프라인처럼 완료보다 결정/상태가 중요한 Flow도 현재 모델로 표현 가능하다.

### 부족한 부분
- 루틴이 월간 캘린더 안에서 텍스트 카드로 많이 보이면 모바일과 데스크톱 모두 시인성이 떨어진다.
- 증빙은 기본 입력으로 강제하면 복잡하다. 결정 근거가 필요한 후보 비교/계약/제출 Flow에서만 선택 필드로 보여야 한다.
- Flow 탭에서 상태판과 전체 목록을 동시에 길게 보여주면 모바일 사용자는 무엇을 눌러야 할지 흐려진다.
- 민감 영역은 완료 체크보다 기록/상담 메모가 먼저 보이는 상세 구조가 필요하다.

### 제작 로직에 반영할 규칙
- 출처 구조를 먼저 판별하고 목적지를 고른 뒤 action을 만든다.
- 사용자 입력은 1~3개를 넘기지 않는다.
- 원문 본문은 요약 메모와 링크로만 두고 실행 항목에는 날짜, 상태, 결과물, 보류 조건만 남긴다.
- 캘린더 월간 칸에는 행동 제목과 아이콘/개수만 남기고 D-day, 긴 설명, 증빙 필드는 상세로 보낸다.
- 건강/육아/안전/정비/법률/재무는 기록, 공식 확인, 전문가 문의로 제한한다.
