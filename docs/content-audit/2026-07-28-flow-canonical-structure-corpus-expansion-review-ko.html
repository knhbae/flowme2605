01

무엇을 기본 데이터로 둘 것인가

ICS가 아니라 Item을 원본으로 둔다

날짜가 있는 실행도, 날짜가 없는 진도·결정·기록도 같은 구조로 보존하기 위해서다.

SourceRow는 원문 근거, Item은 독립 실행 상태다.

03

SourceRow와 Item은 왜 따로 필요한가

원문 한 줄과 사용자가 체크할 한 단위는 항상 1:1이 아니다

합치거나 나눌 때도 모든 원문 행이 어디로 갔는지 추적해야 한다.
SourceRow

원문이 실제로 말한 최소 조각

  • 제목·설명·원문 위치
  • sourceId·snapshotId
  • 행의 순서와 종류
  • 실행이 아닌 주의·맥락도 포함
Item

사용자가 독립적으로 완료·결정·기록할 단위

  • intent와 completion
  • 선택적 schedule·Field·Memo
  • SourceRef로 근거 연결
  • 개인 실행 상태의 기준 ID

05

무엇을 Item으로 만들지 말아야 하나

Item

독립 실행·확인·결정·기록

사용자가 완료 상태를 따로 남길 이유가 있을 때만 생성

Field

정렬·일정·입력·기록에 쓰는 값

Memo

방법·맥락·주의·링크·자유문

19개 Memo가 실행 항목을 부풀리지 않고 설명을 보존

확정21

Use SourceRow → Item → Step → Flow → Bundle/Flow Map → Projection.

SourceRow is the minimum evidence unit; Item is the minimum independently stateful execution unit.

Support 1:1, many:1, 1:many, and many:many SourceRow↔Item mappings.

정책 선택8

Choose per_item by default; allow step_bundle for one equal-schedule user moment with child IDs and declared completion loss.

Choose RRULE master or bounded expanded instances by destination/request.

Use source reminder when present; otherwise let product/user choose at most one reminder without changing the official window.
