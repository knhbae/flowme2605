FlowMe 운영 도구 점검 2026-07-10 우선순위 항목 반영 완료

플러그인을 더 늘리기보다, 낡은 기반과 세션 간 불일치를 먼저 없앴다

현재 FlowMe에는 기획, 디자인, 프론트 구현, 브라우저 QA, GitHub, 배포 도구가 이미 충분하다. 이번 갱신은 지원 종료 런타임과 취약 의존성을 교체하고, 다른 Codex 작업에서도 같은 FLOW 스킬을 쓰게 만들며, 실제 사용자 데이터가 생길 때 도입할 도구의 조건을 분명히 하는 데 집중했다.

종합 판단

온라인 인기도는 채택 신호로만 사용했다. 실제 적용 여부는 FlowMe의 현재 병목, 데이터 권한, 유지 비용, 출시 위험을 함께 보고 정했다.

지금 필요한 것은 추가 플러그인보다 운영 기반의 일관성이다. Node 24, 패치된 Next/Playwright, Dependabot, CI 보안 차단, 실패 리포트 보존, FLOW 스킬 동기화까지는 즉시 가치가 있다. PostHog, Sentry, Promptfoo는 유력하지만 계정과 데이터 계약 없이 설치하면 빈 설정과 중복 관측만 늘어난다.

적용 우선순위

“설치됨”과 “실제로 쓸 준비가 됨”을 구분했다. 다음 도구는 구체적인 트리거가 발생할 때 한 단계씩 연다.

지금 적용

현재 개발·출시 품질에 바로 영향을 주는 기반

Node 24 + 보안 패치

Node 20 EOL 기준을 제거하고 Next 15.5.20, Playwright 1.61.1, PostCSS 8.5.16, 안전한 tmp/uuid 버전으로 갱신했다.

완료 조건: high audit 0

Dependabot + CI 증거

npm/GitHub Actions를 주 1회 확인하고, CI에서 high 취약점을 차단하며 Playwright 실패 리포트를 14일 보존한다.

완료 조건: PR마다 자동 검사

FLOW 스킬 5개 동기화

오래된 전역 사본을 저장소 원본으로 교체하고 한국어 자연화와 출시 준비 스킬도 다른 Codex 작업에서 발견되게 했다.

npm run skills:install:codex

트리거가 생기면 다음

제품 데이터나 운영 계정이 있어야 가치가 생기는 도구

PostHog

첫 외부 사용자 묶음이 URL 입력, 저장, export, check, return을 실제로 수행할 때 도입한다. 이벤트 이름, 동의, 보존 기간이 선행 조건이다.

우선 목적: 사용자 행동 증거

Sentry

Vercel 로그나 PostHog 오류 추적으로 부족한 실제 운영 오류가 생길 때 별도 도입한다. Sentry 프로젝트가 생긴 뒤 공식 읽기 전용 Codex 스킬을 설치한다.

우선 목적: 오류 triage

Promptfoo

실제 AI URL→초안 기능을 열 때 source fidelity, 누락, 환각, Step 유용성의 golden set 회귀 검사에 사용한다.

선행 조건: AI API slice 승인

계속 보류

현재 병목을 풀지 못하거나 기존 기능과 중복되는 도구

Expo / native mobile

네이티브 전용 상호작용, 푸시, 기기 캘린더, 앱스토어 배포가 요구될 때 검토한다. 현재는 반응형 웹 검증이 우선이다.

Notion / Linear / office connectors

repo 문서와 HTML 작업판이 계획의 기준이다. 팀 자료가 외부 도구에 먼저 쌓이기 시작할 때 연결한다.

중복 Figma·GitHub·배포 스킬

독립 패키지 이름이 미설치로 보여도 현재 플러그인이 같은 기능을 제공한다. 기능 중복 설치는 하지 않는다.

실제 변경 사항

이번 결과는 추천 목록만 만든 것이 아니라 저장소와 Codex 사용자 환경에 반영한 상태다.

지원 런타임

package.json과 .node-version을 Node 24로 맞췄고, CI와 Vercel도 같은 기준을 사용한다.

의존성 보안

Next, Playwright, PostCSS, FullCalendar와 transitive tmp/uuid를 갱신했다. 최초 high 4에서 현재 high 0이다.

자동 업데이트

.github/dependabot.yml이 npm과 GitHub Actions를 매주 확인한다. patch는 묶고 큰 변경은 별도 검토한다.

CI 관측성

보안 감사 단계를 추가하고 Playwright report와 test-results를 실패 시에도 보존한다.

스킬 발견

scripts/sync-codex-user-skills.mjs가 저장소의 같은 이름 FLOW 스킬만 Codex 홈에 안전하게 갱신한다.

반복 리뷰 품질

flow-release-readiness가 MVP, 출시, 백로그, 전체 완성도 질문을 같은 증거 체계와 한국어 HTML 형식으로 검토한다.

검증 상태

문서·378개 단위 테스트·격리 설치와 빌드·홈 스모크는 통과했다. 다만 병행 중인 제품 화면과 E2E 기대값이 어긋난 항목이 있어 전체 E2E 녹색 기준은 아직 미확정이다.
