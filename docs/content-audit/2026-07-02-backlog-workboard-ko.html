1. 무엇을 만드는가

지금 제품의 약속과 장기 비전을 섞지 않는다. 지금은 콘텐츠를 실행 가능한 결과로 바꾸는 작은 루프를 증명하고, 장기적으로만 살아있는 경험 지도로 확장한다.

지금 증명할 것

사용자가 설명을 듣지 않아도 URL이나 메모를 넣고, 쓸 만한 Flow를 얻어 자기 일정과 할 일로 옮긴 뒤 실제로 체크하는가.

  • 첫 행동: URL 붙여넣기 또는 짧은 요청 메모
  • 핵심 결과: 일정, 체크리스트, 시트 행, 메모
  • 관찰 행동: 열기 → 찾기/초안 → 저장/export → 체크 → 다시 오기
  • 성공 기준: 예쁜 화면이 아니라 사용자가 실제 행동을 이어가는 것

장기적으로 만들 것

여러 Flow가 연결되고, 사용자 실행·수정·리뷰·추가 Step이 쌓이면서 계속 고쳐지는 살아있는 경험 지도다.

  • 개인 계획과 공유 Flow가 같은 실행 모델로 연결됨
  • 사용자 fork와 개선 제안이 원본에 안전하게 돌아감
  • 경험에서 얻은 지식·기술·감정·성장 가치를 기록함
  • 제작자는 팔로워의 성장을 개인정보를 침해하지 않는 집계로 봄
구현 1. 가져오기

홈과 Flow 찾기에서 URL 또는 요청 메모 입력

구현 2. 찾기·초안

기존 canonical URL 재사용 또는 3~7개 결정론적 초안

구현 3. 고쳐 저장

제목, 기준일, 항목 날짜·메모를 개인 수정본으로 저장

구현 4. 실행

내 Flow에서 오늘 할 일, Calendar에서 날짜별 할 일 확인

구현 5. 내보내기

ICS, Markdown, 체크리스트, TSV/시트 행으로 이동

증거 없음 6. 배우고 개선

실사용 feedback, 재방문, 수정·추천·성장 데이터

7. 권장 실행 순서

다음 기능을 넓히기 전에 현재 루프를 닫는다. 각 배치는 앞 배치의 결과가 다음 선택을 바꾸도록 설계한다.

  1. 기준선 고정

    출시 후보가 아니라 관찰 가능한 안정 상태를 만든다.

    • 병행 P21-04/P21-05 작업을 commit 단위로 닫는다.
    • 33개 E2E 실패를 계약 drift와 실제 회귀로 분류해 전체 기준선을 녹색으로 만든다.
    • tooling 변경을 별도 commit으로 정리하고 release 문서의 모순을 없앤다.
    • 관찰 canary 3개와 route/version을 고정한다.

  2. 사람에게 보여주기

    기능 추가보다 사용자가 어디서 멈추는지 본다.

    • 설명 없이 3~5명에게 URL hit, miss draft, save/export/check 과업을 맡긴다.
    • 개인정보 없이 첫 행동, 멈춘 지점, 실제로 사용한 결과물, 다시 쓸 이유를 기록한다.
    • 관찰 중 UI를 즉시 설명하거나 고치지 말고 동일 version을 유지한다.

  3. 증거로 다음 결정

    AI, account, creator 중 무엇을 열지 행동 데이터로 고른다.

    • lookup 재사용이 강하면 source/version/trust와 canary 공급을 강화한다.
    • miss draft가 강하면 실제 AI gate spec과 golden set을 연다.
    • 재방문·cross-device 요구가 강하면 account persistence를 연다.
    • 수정·공유 요구가 강하면 fork·Step 제안·creator review를 연다.
