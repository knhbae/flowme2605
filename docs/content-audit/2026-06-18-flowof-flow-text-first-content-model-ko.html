Text First

UI 전에 확정해야 할 Flow of Flow 컨텐츠와 사용 행태

최근 확장 PoC에서 입력 필드와 체크리스트가 원문보다 복잡해졌습니다. 이 문서는 화면을 만들기 전에, 원문에서 가져올 수 있는 행과 사용자가 실제로 남길 상태만 텍스트로 고정합니다.

UI 이전 단계 원문 행 우선 상태와 메모만 추가 불필요 입력 제거

정정

이번 PoC에서 잘못 들어간 것

1. 진행 페이스 입력

freeCodeCamp, Odin, Nomad 같은 진도형 콘텐츠에서 `진행 페이스`는 원문에서 온 값이 아닙니다. 사용자가 원하면 나중에 목표 날짜나 캘린더 계획을 추가할 수 있지만, Flow 생성 필수 입력이 되면 안 됩니다.

2. 가짜 실행 체크리스트

`원문 열기`, `오늘 완료한 step 체크`, `막힌 메시지 메모`를 모두 체크리스트로 만들면 원문 레슨보다 Flow가 복잡해집니다. 진도형의 기본 행은 원문 레슨/프로젝트 자체여야 합니다.

3. Flow 리스트 안의 억지 프로세스

Flow 리스트는 사용자가 무엇을 진행 중인지 보여주는 곳입니다. 모든 콘텐츠를 `준비-실행-메모` 프로세스로 바꾸면 Flow of Flow가 아니라 UI 패턴 복붙이 됩니다.

새 기준

원문이 레슨 목록이면 레슨 행 + 상태 + 메모. 원문이 일차 프로그램이면 날짜/회차 + 완료 + 컨디션. 원문이 공식 케어 정보면 주차/연령 + 원문 확인 + 질문 메모입니다.

공통 사용 행태

사용자는 이렇게 쓴다고 봐야 함

1. 사용자가 원문 콘텐츠를 본다.
   예: freeCodeCamp 인증 과정, Odin Foundations, Nomad JS 강의, NHS 임신 주차 가이드.

2. 사용자는 전체 묶음 또는 일부 묶음을 저장한다.
   전체 저장: 큰 지도와 모든 하위 행을 저장.
   일부 저장: 지금 필요한 단원/섹션/주차만 저장.

3. 내 Flow에는 큰 지도와 현재 위치가 보인다.
   사용자가 보고 싶은 것은 "지금 어디까지 했고 다음이 무엇인가"이다.

4. 하위 Flow 상세에는 원문 행이 보인다.
   진도형: 레슨/프로젝트 행.
   루틴형: Day/Run/회차 행.
   케어맵형: 주차/연령/공식 확인 행.

5. 사용자가 남기는 것은 최소 상태뿐이다.
   상태: 시작 전 / 진행 중 / 완료 / 보류.
   메모: 막힌 지점, 다시 볼 원문 위치, 결과 URL, 병원에 물어볼 질문.

6. 재방문하면 마지막 위치와 다음 행이 보인다.
   FlowMe가 새 과제를 만들지 않고, 원문의 다음 행으로 돌아오게 한다.

유형 정의

Flow of Flow 컨텐츠 타입

타입 상위 Flow 하위 Flow 사용자가 직접 남기는 것 UI에서 만들면 안 되는 것
진도형 인증 과정, 강좌, 커리큘럼 단원, 섹션, 레슨 목록 상태, 짧은 메모, 결과 URL 원문에 없는 공부 루틴, 진행 페이스 필수 입력
프로젝트 진도형 프로젝트 기반 과정 lesson/project 묶음 완료 상태, 저장소 URL, 막힌 오류 프로젝트를 다시 쪼갠 임의 프로세스
루틴/챌린지형 30일 프로그램, 9주 계획 Day, Week, Run 날짜, 완료, 컨디션 메모 영상에 없는 동작 체크리스트
케어맵형 공식 주차/연령 지도 주차, 연령 구간, 방문 전 확인 원문 확인, 질문 메모, 예약 메모 의료 판단, 권장/금기 결론, AI 설명 보강

Flow Content Draft 1

freeCodeCamp Responsive Web Design

원문: freeCodeCamp Responsive Web Design

Source shape:
- Certification course.
- Lesson/project rows are the source of truth.
- FlowMe should not invent "open/complete/memo" as separate checklist rows.

User job:
- "내가 인증 과정에서 어디까지 했고, 막힌 레슨/프로젝트가 무엇인지 보고 싶다."

Natural artifact:
- Progress table.
- Optional project result URL.

Required input:
- 없음.
- 선택 입력: 목표 완료일, 프로젝트 URL. 선택이지 필수 아님.

Parent Flow:
Title: Responsive Web Design Certification
Rows:
1. Learn HTML by Building a Cat Photo App
2. Learn Basic CSS by Building a Cafe Menu
3. Learn CSS Colors by Building a Set of Colored Markers
4. Learn HTML Forms by Building a Registration Form
5. Responsive Web Design Projects

Child Flow row shape:
[원문 레슨/프로젝트명] [상태] [메모] [결과 URL optional] [원문 링크]

Example rows:
- Learn HTML by Building a Cat Photo App | 진행 중 | step 56 label/checkbox 다시 보기 | 원문 링크
- Learn Basic CSS by Building a Cafe Menu | 시작 전 | - | 원문 링크
- Build a Survey Form | 완료 | CodePen URL | 원문 링크

Do not build:
- "Cat Photo App 열기" 체크박스.
- "오늘 완료한 step 체크" 체크박스.
- "막힌 메시지 메모" 체크박스.
이 셋은 행의 상태/메모/URL 필드일 뿐 별도 action item이 아님.

다음 UI 기준

이 텍스트가 통과해야 화면을 만든다

1. 하위 Flow 행이 원문에서 온 것인가?
   아니면 UI가 만든 가짜 프로세스인가?

2. 필수 입력이 정말 Flow 생성에 필요한가?
   진도형은 대체로 필수 입력이 없다.
   루틴형은 시작일만 필요할 수 있다.
   케어맵형은 현재 주차/생일/예정일 중 하나가 필요할 수 있다.

3. 사용자가 체크하는 대상이 자연스러운가?
   자연스러운 대상: 레슨, 프로젝트, Day 영상, Run, 주차, 공식 확인 항목.
   부자연스러운 대상: 원문 열기, 메모하기, 확인하기 같은 UI 동작.

4. 메모는 action item이 아니라 필드인가?
   대부분 메모는 별도 체크리스트가 아니라 각 행의 optional field다.

5. 화면 첫 진입에서 "지금 위치와 다음 행"만 보여도 충분한가?
   충분하면 추가 카드, 상태 버튼, 진행 페이스 입력을 만들지 않는다.
