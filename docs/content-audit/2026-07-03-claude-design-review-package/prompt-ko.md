# Claude Design 검토 요청 프롬프트

FlowMe UX/UI 2차 개선본을 첨부된 `review.html`과 모바일 스크린샷 기준으로 검토해주세요.

## 검토 방식

Vercel preview 링크 접속이 어렵기 때문에, 실제 390px 모바일 화면을 캡처한 스크린샷과 검토 설명을 하나의 패키지로 첨부합니다.

첨부 파일:

- `review.html`: 화면별 맥락, 개선 내용, 검토 질문
- `screenshots/01-flows-mobile.png`: Flow 찾기
- `screenshots/02-public-jeonse-mobile.png`: 공개 Flow 상세 - 전세계약
- `screenshots/03-public-moving-mobile.png`: 공개 Flow 상세 - 이사 D-30
- `screenshots/04-post-save-my-flow-mobile.png`: 저장 후 My Flow

## 서비스 전제

- FlowMe는 설명형 콘텐츠 사이트가 아니라, 콘텐츠를 일정/체크/시트/메모로 저장하고 실행하는 앱입니다.
- 4탭 IA는 유지합니다: 홈 / Flow 찾기 / 캘린더 / 내 Flow.
- 사용자는 Flow/Step/Item 같은 내부 모델을 몰라도 써야 합니다.
- 원문/source/detail/memo는 삭제하지 않고 필요할 때 확인 가능해야 하지만, 첫 화면을 방해하면 안 됩니다.
- 저장 후에는 "저장 완료"보다 "먼저 할 일"이 먼저 보여야 합니다.

## 이번 개선 내용

- `/flows` 카드의 badge와 metadata를 줄이고, 제목 -> 입력/결과 -> 먼저 할 일 -> CTA 위계로 정리했습니다.
- `/f/[slug]` 상단에 입력값, 저장 결과, 먼저 할 일을 추가했습니다.
- source 영역은 "원문과 근거" 접힘 구조로 낮췄습니다.
- 저장 후 My Flow는 "저장됨" 상태보다 첫 할 일을 먼저 보이게 했습니다.
- export 라벨을 "캘린더 파일 받기 / 시트로 받기 / 메모로 복사"처럼 결과 중심으로 맞췄습니다.

## 중점 검토 질문

1. 현재 화면이 상용 실행 앱처럼 보이나요?
2. 여전히 설명형/기획서형으로 보이는 부분이 있나요?
3. `/flows` 카드에서 아직 정보가 많은가요? 무엇을 더 줄이거나 접어야 하나요?
4. `/f/[slug]` 상세 상단의 입력/결과/첫 행동 구조가 충분히 명확한가요?
5. 저장 후 `/my`에서 첫 사용자가 다음 행동을 바로 이해할 수 있나요?
6. export 버튼 라벨과 배치가 사용자가 결과를 예측하기에 충분한가요?
7. 전체 리디자인이 아니라, 현재 구조를 유지한 상태에서 우선순위 높은 수정안을 제안해주세요.

## 출력 형식

Blocking / High / Medium / Low로 나눠주세요.

각 항목마다 아래를 적어주세요.

- 문제
- 이유
- 수정 방향
- 기대 효과

가능하면 모바일 390px 기준으로 구체적인 UI 수정안을 주세요.
