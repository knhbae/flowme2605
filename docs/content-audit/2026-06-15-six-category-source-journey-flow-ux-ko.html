6개 대표 카테고리 원컨텐츠 기반 Flow UX 설계안

전세 계약 Flow를 기준 샘플로 두고, 다른 카테고리를 같은 방식으로 억지 적용하지 않고 다시 설계했습니다. 순서는 원컨텐츠 확인, 사용자 저니, Flow 컨텐츠 추출, 전세 UX/UI 기준을 참고한 카테고리별 화면안, 사용자 관점 재검토입니다.

사용자 화면과 리뷰 화면 분리 원컨텐츠 기반 action 우선 입력 1-3개 유지 전세 UX는 기준선
이번 산출물의 성격 실제 HTML PoC 구현 전 설계안입니다. 사용자 저니와 Flow 컨텐츠가 맞는지 먼저 봅니다.
대상 이사, 중고차, 홈트, 스퀴시, 식물, 초등 입학. 냉장고 파먹기는 이번 대표 세트에서 제외합니다.
검증 경계 원컨텐츠와 UX 설계 기반 판단이며, 실제 사용자 행동 검증은 아닙니다.

1. 진행 방식

이번에는 UI를 먼저 붙이지 않습니다. 원컨텐츠가 어떤 실행 욕구를 만들고, 사용자가 어떤 도구로 옮기고 싶어 하는지를 먼저 정한 뒤 화면을 고릅니다.

원컨텐츠

블로그, 유튜브, 공식 안내, 체크리스트 중 사용자가 저장하고 다시 열 이유가 있는지 봅니다.

Flow 컨텐츠

요약문이 아니라 실제 action item, 날짜, 반복, detail, URL, 완료 기준을 추출합니다.

UX/UI안

전세 UX의 가벼움은 유지하되, 날짜형/루틴형/버킷형/현장 체크형에 맞게 화면을 바꿉니다.

2. 전세 UX/UI 기준선

전세에서 가져갈 기준

  1. 첫 입력은 하나의 기준 날짜 중심으로 둔다.
  2. 입력 후 바로 날짜별 실행 화면으로 바뀐다.
  3. 날짜를 누르면 해당 날짜의 action과 체크 항목이 나온다.
  4. 상세 설명은 메모, description, URL로 내려보낸다.
  5. 전체보기는 보조 탭으로 두고 첫 화면을 압도하지 않는다.
  6. 사용자 화면에 검토용 설명을 넣지 않는다.

그대로 복붙하면 안 되는 것

  • 모든 카테고리에 D-day 캘린더를 강제로 붙이지 않는다.
  • 진행 중, 보류, 완료 같은 공통 상태 버튼을 반복하지 않는다.
  • 원컨텐츠에 없는 세부 행동을 채우기 위해 AI 일반론을 넣지 않는다.
  • 전세 대비 수준, UX 리뷰, source fit 평가는 사용자 화면에서 빼야 한다.

2-1. 최신 PoC 시뮬레이션에서 확정한 UX 규칙

2026-06-15 사용자 PoC를 실제로 눌러본 결과, 캘린더는 “월간 미리보기”만으로 부족했습니다. 사용자는 선택 날짜의 항목, 전체 일정, 다음 실행 메모를 함께 볼 수 있어야 합니다.

긴 기간 Flow

  • 이사와 초등처럼 여러 달에 걸친 Flow는 월간 캘린더 아래에 전체 일정 타임라인을 둔다.
  • 캘린더 월에 보이지 않는 D-10, D-Day, D-21 같은 항목도 전체 일정에서 바로 열 수 있어야 한다.
  • 월 이동은 보조 기능으로 두되, 전체 일정이 사용자의 길 찾기 역할을 한다.

같은 날짜의 여러 항목

  • 중고차, 스퀴시, 식물처럼 같은 날짜에 2개 이상 항목이 있으면 날짜 클릭 후 항목 리스트를 보여준다.
  • 항목이 하나뿐이면 날짜 클릭으로 바로 실행 카드가 열린다.
  • 같은 날짜 안의 항목은 “방문 당일 / 계약 전”처럼 사용자가 구분할 수 있는 라벨을 유지한다.

다음 방문 화면

  • “재방문 보기”, “다시 열었을 때 필요한 정보” 같은 내부 표현은 쓰지 않는다.
  • 사용자 화면에서는 “다음 일정”, “다음 운동”, “다음 실행 메모”처럼 다음 행동을 예측할 수 있는 말을 쓴다.
  • 다음 화면에는 다음 항목, 상세 설명, 남겨둔 메모만 남긴다.

원컨텐츠 기반 detail

  • 체크 항목 아래에는 같은 단계 설명을 반복하지 않는다.
  • 하위 설명은 원컨텐츠에서 확인되는 실행 단서가 있을 때만 붙인다.
  • 근거가 애매한 내용은 AI 일반론으로 채우지 않고 링크, 메모, 선택 상세로 보낸다.
