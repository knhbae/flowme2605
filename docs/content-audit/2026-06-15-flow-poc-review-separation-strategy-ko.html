FLOW UX/UI POC review · 2026-06-15

최근 Flow 카테고리 PoC 리뷰와 분리 전략

최근 7개 카테고리 PoC는 전세 Flow에서 얻은 상호작용 틀을 확장하려는 목적은 맞았지만, 사용자에게 제공되는 실행 화면과 개발자가 보는 콘텐츠 변환 리뷰가 한 화면에 섞이면서 판단이 흐려졌습니다. 다음 작업은 화면을 더 예쁘게 만드는 것이 아니라, 사용자용 실행 Flow와 검토용 변환 리포트를 구조적으로 분리하는 것입니다.

핵심 이슈: 화면 목적 혼재 전세 UX는 기준 샘플로 유지 냉장고는 대표 후보에서 보류 다음은 5개 후보 재구성
현재 PoC 수준 전세 수준의 인터랙션 틀은 일부 구현됐지만, Flow 컨텐츠 문장과 화면 역할은 아직 wireframe과 리뷰 보드 사이에 걸쳐 있습니다.
가장 큰 원인 카테고리별 목적지를 먼저 정하지 않고, 공통 상태 버튼과 재방문 보기, 검토 패널을 반복 적용했습니다.
다음 목표 사용자 화면은 실행만, 검토 화면은 source-to-flow 판단만 담도록 분리한 뒤 5개 강한 후보만 다시 만듭니다.

1. 전체 진단

결론은 “PoC가 틀렸다”가 아니라 “사용자용 Flow와 개발자용 Flow 리뷰가 같은 표면에 섞여서, 실제 사용 저니를 판단하기 어렵다”입니다.

전세 Flow에서 좋았던 점

계약 예정일 입력, D-3/D-Day/D+1 일정, 체크, 메모, URL이 하나의 실행 저니로 이어졌습니다. 사용자는 “오늘 무엇을 할지”와 “내 도구로 무엇을 옮길지”를 알 수 있었습니다.

최근 PoC에서 깨진 점

모든 카테고리에 시간 지점, 상태 버튼, 재방문 보기, 검토 패널을 붙이면서 사용자가 해야 할 일보다 “왜 이 카테고리가 가능한지”가 먼저 보였습니다.

수정 방향

Flow별 primary destination을 먼저 정하고, 원컨텐츠에서 나온 실행 단위만 사용자 화면에 남깁니다. 판단 근거와 품질 평가는 별도 개발자 리뷰 화면으로 보냅니다.

2. 문제점 정리

Blocking

사용자용 화면과 개발자용 검토 화면이 섞임

“전세 UX 대비 수준”, “UX 디자이너 피드백”, “검증 아님”, source/risk 평가 같은 문구는 개발자 또는 내부 리뷰용입니다. 사용자는 이 화면에서 원컨텐츠를 저장하고 실행해야 하는데, 제품 설명과 변환 평가가 섞여 첫 행동이 흐려집니다.

High

Flow 컨텐츠가 원컨텐츠 기반 action이 아니라 공통 틀에 맞춰 생성됨

이사, 홈트, 스퀴시, 식물 모두 “등록, 설정, 재방문, 상태 선택” 같은 공통 구조가 먼저 보입니다. 실행 카드에는 원문에서 온 세부 행동과 완료 기준이 있어야 하는데, 일부는 AI가 일반론으로 채운 느낌이 납니다.

High

목적지별 UI 결정이 늦음

이사는 calendar + checklist, 중고차는 scheduled checklist, 홈트는 routine calendar, 스퀴시는 bucket + optional date, 식물은 repeat reminder입니다. 그런데 현재는 동일한 보기 탭과 상태 버튼이 먼저 들어와서 카테고리별 자연스러운 사용법을 방해합니다.

Medium

재방문 보기와 상태 버튼의 의미가 불명확함

재방문은 카테고리마다 다른 의미여야 합니다. 이사는 “다음 일정”, 중고차는 “보류 사유 다시 보기”, 홈트는 “다음 운동”, 스퀴시는 “나중에 날짜 정하기”, 식물은 “다음 물주기 확인”입니다. 하나의 공통 라벨은 사용자에게 기능 결과를 예측시키지 못합니다.

Medium

주의 문구가 사용자 action을 밀어냄

“FLOW가 판단하지 않습니다” 같은 방어적 문장은 내부 리스크 경계에는 필요하지만 사용자 실행 카드의 중심 문장으로는 약합니다. 사용자는 “무엇을 확인하고, 어떤 경우 보류할지”를 먼저 봐야 합니다.

3. 화면 분리 전략

사용자용 Flow 화면

실제 사용자가 저장하고 실행하는 화면입니다.

  • 원컨텐츠 제목과 출처 링크
  • 필요한 입력 1-3개
  • 오늘 또는 선택 날짜의 action
  • 체크리스트, detail, URL
  • 캘린더, 반복, 버킷, 메모 등 실제 목적지

개발자용 변환 리뷰

이 원컨텐츠가 Flow로 적합한지 판단하는 화면입니다.

  • source shape와 사용자 need
  • destination, structure 결정 근거
  • source fact, creator experience, caution 분리
  • 품질 rubric 점수와 hard fail
  • 보류 또는 탈락 사유

PoC/리서치 화면

전략 판단을 위한 내부 비교 화면입니다.

  • 사용자 화면 미리보기와 리뷰 메모를 명확히 구획
  • 후보별 fit score와 다음 조치
  • 실제 사용 검증 전에는 검증됨 표현 금지
  • 비교와 학습 목적을 제목에서 표시

4. 카테고리별 리뷰와 개선 방향

이사 D-30 준비

대표 후보 유지

원컨텐츠 fit은 좋지만 실행 카드와 세부 체크가 아직 사용자 실행 문장으로 충분히 다듬어지지 않았습니다.

문제

  • 이사 방식 선택이 설문처럼 저장되지 않음
  • 견적 요청 사이트 추천이 없음
  • 진행 중/보류/완료 버튼 의미가 모호함
  • 세부 체크리스트가 상위 action을 반복함
  • 캘린더 미리보기가 부족함

개선

  • 이사 방식은 segmented choice로 저장
  • D-30에 견적 사이트 2-3개와 연락 메모 제공
  • 상태 버튼 대신 항목별 체크와 보류 메모만 사용
  • D-day 캘린더 미리보기 추가
  • 재방문 보기는 다음 일정 보기로 변경

중고차 방문 당일

80점 후보

체크리스트이지만 방문일이 있는 일정형입니다. 사용자는 현장에서 바로 보고 체크해야 합니다.

문제

  • 차량번호 이력조회와 성능기록부 확인 방법이 불명확함
  • 하단 detail이 행동보다 방어 문구에 가까움
  • 구매 적합성 disclaimer가 primary action을 가림

개선

  • 방문 전, 현장, 계약 전의 scheduled checklist로 구성
  • 이력조회 링크, 성능기록부 비교 기준, 사진 메모 슬롯 제공
  • “보류 사유 남기기”를 문제 발견 시에만 노출
  • 사용자 화면에서는 보증 문구보다 stop condition을 detail에 배치

주 3회 홈트 영상

구조 재작성

원컨텐츠는 좋지만 실행 카드가 운동 실행이 아니라 설정 체크리스트처럼 보입니다.

문제

  • 오늘 실행 카드에 요일 3개 선택, 시간대 정하기가 들어감
  • 상태칩이 과해서 운동 앱보다 무거워 보임
  • 영상 원문을 따라 하는 단일 action의 장점이 약해짐

개선

  • 설정은 저장 단계로 분리하고 실행 카드는 “오늘 영상 1회 열기”만 노출
  • 반복 캘린더와 오늘 카드 중심으로 구성
  • 상태는 완료, 건너뜀, 메모 정도로 축소
  • 통증/어지러움 중단 조건은 detail에 가까이 배치

무료 도안 스퀴시

버킷형으로 축소

날짜형으로 만들기보다 “나중에 아이와 해볼 놀이”로 저장되는 것이 자연스럽습니다.

문제

  • 놀이 날짜를 눌러도 날짜 선택 행동이 명확하지 않음
  • 4개 실행 흐름은 실제 사용자 기대보다 무거움
  • Flow 컨텐츠가 놀이 실행보다 구조 설명에 가까움

개선

  • 기본은 버킷리스트에 넣기
  • 나중에 날짜를 정하면 하나의 체크리스트로 전환
  • 제목, 준비물, 도안 링크, 원문 영상만 간결하게 제공
  • 날짜 필드는 실제 date picker로 동작

식물 물주기

반복 알림형

사용자가 식물 이름까지 입력하는 구조는 과합니다. 원컨텐츠가 특정 식물이라면 입력은 시작일과 반복주기면 충분합니다.

문제

  • 식물 이름 입력이 불필요함
  • 상태 기록 앱처럼 확장될 위험이 있음
  • 상태칩과 action의 우선순위가 헷갈림

개선

  • 제목은 “스투키 물주기”처럼 원컨텐츠에서 가져옴
  • 입력은 시작 날짜와 반복 주기만 사용
  • 내용은 물 양, 흙 상태 확인, 원문 링크 정도로 제한
  • 기록은 마지막 물준 날과 간단 메모까지만 둠

초등 입학 준비

후보 유지

원컨텐츠와 사용자 need가 좋습니다. 다만 전세처럼 날짜와 현재 단계가 바로 보여야 합니다.

문제

  • 캘린더 UI가 부족함
  • detail이 일부 일반 준비물 설명으로 흐름
  • 학교 안내문과 블로그 추천의 경계가 더 필요함

개선

  • D-30/D-21/D-14/D-7/첫 주 캘린더 미리보기
  • 현재 단계와 다음 action을 첫 화면에 고정
  • 공식 학교 안내문, 부모 경험 팁, 메모를 분리
  • 각 action에 완료 기준을 붙임

냉장고 파먹기

대표 후보 제외

현재 목표인 “온라인 컨텐츠를 실행 가능한 개인 Flow로 저장”을 보여주는 대표 후보로는 약합니다.

문제

  • 사용자 입력과 재고 상태가 원컨텐츠보다 더 중요해짐
  • 식단, 장보기, 재고 앱으로 확장될 위험이 큼
  • Flow 컨텐츠와 원컨텐츠의 연결이 약함

처리

  • 이번 대표 PoC 세트에서는 제외
  • 나중에 시트형 후보가 필요할 때 별도 검토
  • 대체 시트형 후보는 출처 기반 표나 목록이 명확한 콘텐츠로 선정

5. 다음 개선 원칙

원칙 사용자 화면에 남길 것 검토 화면으로 보낼 것 판단 질문
목적지 먼저 결정 캘린더 일정, 체크리스트, 버킷, 반복 알림, 메모 structure_type, destination 선택 근거 사용자가 이 Flow를 어디에 옮겨 쓰는가?
입력은 1-3개만 이사일, 방문일, 시작일, 반복주기처럼 개인화에 필요한 값 원컨텐츠에 이미 있는 제목, 식물명, 준비물명 이 값이 없으면 일정이나 action이 바뀌는가?
action은 원컨텐츠에서 온다 사용자가 손으로 할 수 있는 세부 행동과 완료 기준 AI가 일반론으로 채운 설명, 카테고리 소개 이 문장이 다른 Flow에도 그대로 쓰일 수 있나?
공통 버튼을 남용하지 않음 해당 Flow에서 결과가 예측되는 버튼 진행 중/보류/완료 같은 범용 상태 실험 사용자가 누른 뒤 무엇이 바뀌는지 알 수 있나?
주의 문구는 decision point로 보류, 중단, 공식 확인이 필요한 조건 서비스 책임 회피성 문장 이 문구가 다음 행동을 바꾸는가?

6. 개선 계획

표면 분리

현재 PoC를 사용자용 실행 화면과 개발자용 변환 리뷰로 나눕니다. 사용자 화면에는 내부 평가, 전세 대비 수준, UX 리뷰 문구를 넣지 않습니다.

5개 후보만 재구성

이사, 중고차, 홈트, 스퀴시, 식물 또는 초등 중 우선 5개를 전세 기준으로 다시 만듭니다. 냉장고는 대표 후보에서 제외합니다.

Flow별 UI 재선택

이사와 초등은 캘린더, 중고차는 현장 체크, 홈트는 반복 오늘 카드, 스퀴시는 버킷, 식물은 반복 알림으로 각각 다른 기본 UI를 적용합니다.

저니 재시뮬레이션

원컨텐츠 소비에서 저장, 실행, 체크, 다음 방문까지 다시 시뮬레이션합니다. 사용자가 추측해야 하는 action이 남아 있으면 다시 보강합니다.

7. 다음 작업 지시안

작업 목표

최근 7개 카테고리 PoC를 사용자용 실행 Flow와 개발자용 콘텐츠 리뷰로 분리하고, 대표 후보 5개를 전세 Flow 수준의 실제 사용 화면으로 재구성한다.

  • 사용자 화면에는 “왜 이 Flow가 좋은지”가 아니라 “오늘 무엇을 할지”를 먼저 둔다.
  • 검토 화면에는 source fit, destination, structure, risk/source 분리, 탈락 사유를 둔다.
  • 각 Flow는 원컨텐츠에서 나온 구체 action, detail, URL을 보존한다.
  • 캘린더가 필요한 Flow에는 날짜 클릭 후 해당 날짜 아이템이 나오게 한다.

완료 기준

  • 사용자용 화면만 봐도 저장, 실행, 체크, 다음 방문 목적이 이해된다.
  • 개발자용 화면을 보지 않아도 사용자가 Flow를 쓸 수 있다.
  • 각 action에는 시점, 도구, 완료 기준, detail 또는 URL 중 필요한 요소가 있다.
  • 범용 상태 버튼과 재방문 보기 라벨은 Flow별 의미 있는 이름으로 교체된다.
  • 냉장고처럼 fit이 약한 후보는 억지로 구현하지 않고 보류 처리한다.
