04 · 이어쓰기

원문 해당 줄

원래 문맥으로 돌아와 내용을 고칩니다. 항목을 복제하지 않습니다.

v4.1의 정리·기간 보기, 개발1의 실행 identity·저장·복구, 개발2의 원문·문맥 편집을 함께 보존합니다. 이번 14개 요구군은 원래 424개 하위 조건의 전체 충족률이 아닙니다.

선택한 변경과 남겨 둔 비교안

A · 실제 앱의 1차 변경 범위

보조 도구를 접고 대상을 명확히

기존 화면과 데이터 계약을 유지하면서 상단에서 경쟁하는 행동을 줄입니다.

  • 계정 관리가 강제로 별도 행을 차지하는 배치를 정리합니다.
  • 날짜순 정렬·다시 실행을 ‘편집 도구’ 안에 둡니다.
  • 입력 되돌리기·저장 상태·오류 복구는 계속 보입니다.
  • 날짜 폼에 바꾸는 항목 제목을 표시합니다.

B · 시뮬레이션만

원할 때 본문에 집중

탐색과 보조 영역을 잠시 접는 방식을 A와 같은 합성 자료로 비교합니다.

  • 명시적으로 집중을 켜고 버튼 또는 Esc로 나갑니다.
  • 보기·조회 날짜·추가 전 입력을 유지합니다.
  • 저장 상태와 나가기는 접지 않습니다.
  • 실제 앱의 신규 모드나 제품 정책으로 확정하지 않습니다.

앱의 writer·schema·CAS·같은 요청 ACK·docId/lineId·날짜/폴더/순서 전이는 바꾸지 않습니다. 조작 HTML의 작은 합성 모델은 실제 제품 모델과 별개입니다.

전체 방향은 세 경로로 유지

개인 공간

자유 텍스트로 일정·할 일·메모를 관리합니다. 남의 Flow를 가져오거나 공개하지 않아도 사용할 수 있습니다.

공개 경험·지식

내 상황에 맞는 경험을 찾고 출처·한계를 확인합니다. 개인 사본으로 쓰거나 기존 도구로 가져가는 경로를 유지합니다.

선택적 기여

질문, 일부만 적용한 경험, 개선 제안을 나눕니다. 개인 기록은 공개 전에 선택하며 참여를 필수로 만들지 않습니다.

뒤의 두 경로를 이번 개인 문서 시나리오만으로 검증 완료 처리하지 않습니다. 기존 화면·owner·통합 계약을 요구표에 연결하고 신규 구현은 보류했습니다.

각 앱 브라우저 검사에서 실제 API/Auth/DB 전달 0, 허용 경계 밖 쓰기·clear 0, 합성 운영 sentinel byte 동일, 가로 넘침·page error·콘솔 오류 0입니다. 실제 사용자 DB 전체의 불변 검증이나 실기기 검사는 아닙니다. 앱·표적·prototype 검사에는 중복 영역이 있어 합산 고유 검사 수로 쓰지 않습니다.

전체 통합 초기 실행은 2,628 / 2,630, 소스 변경 4개로 실패 판정입니다. 원문 복원 경쟁과 추출 fixture 누락을 보완해 관련 99개를 통과했지만, 최종 고정 소스의 전체 통합 재실행은 아직 하지 않았습니다. 게시 전 별도 관문으로 남깁니다. 실행 명령·초기 실패·로컬 근거 · 변경 파일·반영 상태

기존 구현에서 확인된 것과 남은 경계

9월 30일 원장에는 독립 문서 작성, 날짜·시간 편집, 조회 범위·폴더/문서 맥락, 완료·다시 열기, 원문 복귀의 제한된 합성 근거가 있습니다. 당시 결과를 모든 입력·이동·기간 조합의 성공으로 확대하지 않습니다.

현재 기준선에는 같은 요청의 성공 ACK 뒤 편집기의 dirty·잘못된 충돌 표시 정리가 반영되어 있습니다. 9월 30일의 구형 U14 판정을 현재 결함으로 다시 쓰지 않습니다.

복구된 첫 저장의 server Undo 제한, 들여쓰기/내어쓰기의 구조 재분류 정책, 장시간 열린 탭 전체 안정성은 별도 남은 사항입니다. 실제 IME와 기기 검증도 별도입니다.

현재 기준선 QA · 기존 U01~U14의 정확한 관측 범위

상시 편집 버튼은 6개→5개, 노출 버튼 높이는 모두 48px입니다. 날짜순 정렬·다시 실행은 ‘편집 도구’에서 열 수 있습니다. 짧은 가로 화면에서도 스크롤로 조작할 수 있지만, 처음 보이는 본문은 확보하지 못했습니다. 이 개선을 해결 완료로 판정하지 않습니다.

화면을 덜 차지하거나 버튼 수가 줄었다는 사실만으로 사용성이 좋아졌다고 결론내리지 않습니다. 다음 행동과 변경 대상이 보이고, 오류·취소·Undo에 접근할 수 있는지도 함께 봅니다.

기존 UX 제안은 어떻게 처리했나

UX1의 본문 확보는 부분 채택, 같은 Item의 원문 복귀는 Alpha에서 결함 수정했습니다. UX2의 조회 범위·소속 구분은 기존 구현을 유지하고 날짜 대상 표시를 더했습니다. 공개 탐색·개인 사본·선택적 기여는 전체 맵에 남겼으며 이번 개인 문서 검사로 완료 처리하지 않았습니다.

UX1·UX2 원본 제안별 채택·보류 · v4.1·개발1·개발2의 14개 요구군 대조

새 native 원문 복귀는 Alpha에서만 실행합니다. 일반 ProgramApp의 기존 checkpoint 복원과 경쟁하지 않도록 분리했으며, ProgramApp의 접힌 행 복귀 UX까지 새로 구현한 것은 아닙니다. 다음 비교 후보는 작은 높이에서 본문 확보와 B 집중의 진입·탈출·입력 보존입니다. 신규 제품 모드로 확정하지 않습니다.

이번 결과의 한계

실제 Android/iOS·IME·보조기술 검사와 관찰 사용자 시험은 0건입니다. 테스트와 화면 비교는 내부 QA이며 실사용 개선을 입증한 결과가 아닙니다.

배포·개발계 교체·운영 설정 변경·실제 계정/DB 쓰기는 0입니다. 운영 자동화, 장시간 인증·탭 안정성, 신규5D, 콘텐츠 전수 편집, 공동 편집 권한은 이번 범위에 포함하지 않습니다.

전체 424개 조건의 충족률, 전체 제품 완성도, 공개 경험·커뮤니티의 실사용 검증을 이 작업으로 주장하지 않습니다.
