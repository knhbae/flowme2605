결론 먼저

대표 12개 중 우선 실험 후보는 세탁기 청소/관리 Flow, 크리에이터 콘텐츠 엔진 Flow, 중고차 후보 점검 Flow, 온라인 코스 출시 준비 Flow입니다.

이번 검증의 결론은 FlowMe가 원문을 복제하는 앱이 아니라, 원문을 실행 가능한 일정/체크/기록/상태로 바꾸는 앱이어야 한다는 점입니다.

  • 월간 캘린더의 루틴은 긴 텍스트 카드보다 아이콘/개수 중심으로 줄인다.
  • 증빙은 모든 Flow의 기본 입력이 아니라 비교/계약/제출/결정 Flow의 선택 필드로 둔다.
  • 모바일 Flow 탭은 상태판과 전체 목록을 동시에 길게 보여주지 말고, 상태 카드를 누르면 해당 목록만 펼친다.
  • 민감 영역은 완료 체크보다 기록/상담/공식 확인 메모를 먼저 보이게 한다.

UX 한계 검증

  • 초보 식물 관리 Flow루틴이 많으면 캘린더 칸이 지저분해진다.
  • 30일 글쓰기 챌린지 Flow월간 캘린더에 30개 텍스트가 깔리면 과밀하다.
  • 30일 초보 운동 플레이리스트 Flow캘린더 안에서 영상 제목이 길면 모바일이 깨진다.
  • 100일 코딩 챌린지 Flow100개 반복 일정이 월간 캘린더를 압도한다.

출처/위험 경계

  • 세탁기 청소/관리 Flow수리, 전기, 누수 위험은 서비스 문의 트리거로만 다룬다.
  • 중고차 후보 점검 Flow법적/정비 판단은 공식 조회와 전문가 확인 메모로 제한한다.
  • 초기 이유식 반응 기록 Flow이상 반응은 즉시 전문가/기관 상담 메모로 제한한다.
  • 30일 초보 운동 플레이리스트 Flow통증, 어지러움, 호흡곤란, 기존 질환 악화 시 중단/전문가 상담 문구를 둔다.

기존 자동 exampleFlow 진단

  • 기존 50개 자동 exampleFlow는 원문 실행 신호를 재해석하지 않고 action 배열을 캘린더/오늘/진행 카드로 감싸는 수준이었다.
  • structure_type만 보고 Day 1, D-14, 초안 같은 시간을 붙여 실제 원문과 맞지 않는 일정이 생겼다.
  • 완료 기준이 '완료 상태로 표시'처럼 반복되어 사용자가 무엇을 끝내야 하는지 판단하기 어렵다.
  • 출처 본문, 제작자 경험, 위험 경계를 분리하지 못해 민감 영역이나 템플릿 저작권 경계가 흐려졌다.
  • 따라서 기존 exampleFlow는 참고 로그로만 두고, 대표 샘플은 사람이 원문 구조를 읽고 다시 작성해야 한다.
