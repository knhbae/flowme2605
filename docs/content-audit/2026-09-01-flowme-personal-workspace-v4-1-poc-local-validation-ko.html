실제 PoC 화면 조작

화면 크기를 고른 뒤 iframe 안에서 기능을 직접 확인합니다.

서버 없는 독립 HTML 열기 새 창에서 실제 PoC 열기
화면이 비어 있으면 오류가 아닙니다. 실제 화면은 현재 브라우저에 이미 저장된 Flow만 읽습니다. 검증용 Flow를 만들기 위해 운영 flow:* 키를 임의로 추가하지 않습니다. 자동 시나리오의 네 origin 결과는 아래 캡처에서 확인할 수 있습니다. 서버 없는 독립 HTML은 파일을 바로 열어 네 origin과 모든 조작을 확인할 수 있습니다. 저장은 flow:poc:personal-workspace:v1:standalone-demo 한 키에만 남습니다. 서버가 꺼져 있으면 새 창 링크와 iframe이 열리지 않습니다. 해당 PoC worktree에서 npm.cmd run dev -- -p 3107을 실행하면 다시 열립니다.

S1–S8 수동 판정표

자동화 통과 여부와 별개로 직접 이해하고 조작할 수 있는지 표시합니다.

0 / 8 직접 확인
S1

네 origin이 한 번씩 보이고 상세가 열린다

미분류에서 Flow를 골라 제목·origin·Item 목록을 확인합니다.

S2

빠른 할 일을 만들고 이동한 뒤 Undo한다

날짜와 폴더를 바꿔도 마지막 한 번의 Undo로 원래 상태가 복구되는지 봅니다.

S3

Flow 폴더와 Item 실행 날짜가 독립적으로 움직인다

Flow의 폴더를 옮긴 뒤 Item 하나의 날짜만 바뀌고 Flow 소속은 유지되는지 봅니다.

S4

완료와 다시 열기가 모든 보기에서 일치한다

오늘에서 완료한 뒤 Flow 상세와 기간 목록을 확인하고 다시 엽니다.

S5

드래그·길게 누르기·메뉴·키보드가 같은 결과를 낸다

사용 방식이 달라도 동일한 이동 규칙과 안내가 적용되는지 봅니다.

S6

같은 위치와 취소에서는 아무것도 바뀌지 않는다

Escape·pointer cancel·저장 실패도 원래 상태를 유지하는지 확인합니다.

S7

새로고침 복구와 손상 데이터 차단이 동작한다

마지막 성공 상태는 복원되고 손상 payload는 기존 /my로 닫히는지 확인합니다.

S8

운영 데이터가 전후 동일하다

PoC 조작은 전용 prefix에만 기록되고 기존 flow:* 값은 byte 단위로 같아야 합니다.

v4.1 시각 기준과 비교

정적 UI 기준의 정보 구조는 유지하되, 실제 서비스 토큰과 접근 가능한 조작 상태를 적용했습니다.

기능 승인과 시각 승인을 따로 판단해 주세요

  • 정적 시안은 청록색·평면 목록·흰 배경이고, 현재 PoC는 기존 서비스의 파랑·카드형·베이지 배경을 사용합니다.
  • 모바일은 서비스 헤더, PoC 제목·관리, 상태 안내, 보기 탭이 이어져 첫 Flow나 할 일이 시안보다 아래에 나타납니다.
  • FlowMe / FLOW, 할 일 / 개인공간 / 내 계획, 이번 주 / 주간 명칭이 섞여 있습니다.
  • 844 × 390의 이동 패널 내부 스크롤과 마지막 대상 접근은 자동화로 확인했습니다. 실제 터치 감각은 기기에서 별도로 봐야 합니다.
  • 통합 정본의 /calendar parity는 이번 직접 범위의 오늘·주간·월간·날짜 미정에는 포함되지 않았습니다. 다음 통합 단계에서 포함 여부를 결정해야 합니다.
