결정

후보는 강하다. 하지만 학교별·학기별 공지가 달라질 수 있으므로, 하나의 현재 primary source를 고정하고 공개 UI 게이트를 통과하기 전에는 공개 라우트를 만들지 않는다.

왜 강한가

입사 날짜가 있고, 서류·침구·첫날 물품·반입금지·입사 당일 절차가 실제 실행 순서로 이어진다.

왜 보류인가

여러 기숙사 규칙을 하나의 전국 공통 체크리스트처럼 섞으면 source fidelity가 떨어진다.

넘지 않을 선

기숙사 플랫폼, 학교 로그인, 결제 추적, 건강서류 업로드, 룸메이트 매칭, 학생 생활 대시보드를 만들지 않는다.

사용자 행동과 수동 단절점

사용자 순간

학생이나 보호자가 학교 공지, 기숙사 페이지, 학기별 PDF를 받은 뒤 입사 날짜를 기준으로 준비한다.

현재 수동 행동

기숙사 페이지를 읽고, 캡처하고, 개인 체크리스트를 만들고, 가족에게 물품을 묻고, 반입금지 항목을 다시 확인한다.

실행 단절

  • 제출서류와 짐 목록이 섞인다.
  • 건강 관련 서류가 의료 조언이나 이미지 저장으로 오해될 수 있다.
  • 반입금지 항목은 학교별로 다르다.

FlowMe 밖에 둘 값

결제 정보, 방 비밀번호, 학생 ID, 주민번호, 건강정보, 로그인 값은 FlowMe에 들어오면 안 된다.

공개 승격 게이트

필수 조건

  1. 현재 primary source 하나를 고르고, 다른 기숙사 자료는 패턴 지원으로만 둔다.
  2. 첫 행동은 최신 학교/기숙사 공지 확인으로 유지한다.
  3. 학교별 최신 공지가 FlowMe보다 우선한다는 문구를 UI에 보여준다.
  4. D-14, D-10, D-7, D-5, D-Day 또는 동등한 source-backed sequence가 있다.
  5. 캘린더 export와 체크리스트 copy에는 source URL, latest-notice caution, completion criteria가 함께 간다.

금지 조건

  • 건강진단서 이미지, 결제 계좌, 방 비밀번호, 학생 ID, 주민번호, 카드키 번호, 로그인 정보를 묻거나 저장하지 않는다.
  • 모든 기숙사에 같은 서류·반입금지 규칙이 적용된다고 말하지 않는다.
  • 모바일 첫 화면에서 긴 설명이 실행 artifact를 밀어내지 않는다.
  • 상태는 source-review이며, validated가 아니다.
