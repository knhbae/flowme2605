My Flow v6 컨텐츠 모델 재점검

사용자 피드백에 따라 v6 PoC의 고정 3개 체크리스트 패턴을 제거하고, Flow Map > Flow > Step > Item 원칙에 맞게 다시 줄였다. 이 문서는 검토용이며 사용자 PoC에는 노출하지 않는다.

수정된 사용자 PoC 이전 과업 리허설 실제 사용자 검증 아님

문제 판정

이전 v6는 화면은 깔끔했지만 컨텐츠 모델이 다시 UI 틀에 끌려갔다. 여러 Flow에서 원문 구조와 관계없이 세부 체크를 3개씩 만들었고, 메모나 설명으로 내려가야 할 내용까지 체크리스트가 되었다.

  • 고정 3개 checklist는 source-to-Flow gate 위반이다.
  • Step은 캘린더/투두/시트로 저장되는 최소 실행 단위다.
  • Item은 선택적 상세값이며, 없을 수도 있다.
  • Item이 외부 앱에 못 들어가면 event description, todo note, memo text로 접혀야 한다.

수정 원칙

Step 먼저각 카드의 본체는 하나의 실행 항목이다. 세부 체크는 기본값이 아니다.
Item은 필요할 때만원문에서 실제로 분해할 항목이 있을 때만 1개 이상 둔다.
메모로 내리기확인 URL, 보류 이유, 다시 볼 내용은 체크가 아니라 memo/detail로 둔다.

브라우저 검증 결과

Playwright로 `single`, `few`, `mixed`, `large` 네 상태와 대표 항목 6개를 클릭했다.

  • 문서 체크: `npm run docs:check` 통과.
  • 모바일/데스크톱 overflow: 0.
  • JS console/page error: 0.
  • 작은 터치 타겟: 0.
  • item count: 전세 3, 수학 2, 홈트 1, 영유아 1, 진도 filler 0, 체크 filler 1.
  • 사용자 화면 visible text와 fallback text에서 내부 `Step` 문구 없음.

남은 판단

이번 수정은 고정 3개 checklist 문제를 제거한 것이다. 실제 서비스 기준으로는 다음 관찰에서 사용자가 Item이 없는 항목의 완료 표시를 자연스럽게 이해하는지, 1개 Item 화면이 과하지 않은지 확인해야 한다.
