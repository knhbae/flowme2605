공유 패킷을 보내기 전에 수신자가 이해하는지 보는 관찰 스크립트

이 문서는 school-dorm-share-packet-v2-2026-06-11-readable-preview의 다음 근거를 만들기 위한 스크립트다. matching role-labeled slot이 scheduling tracker에서 agreed이고 preflight가 통과된 뒤에만 시작한다. 아직 검증이나 public route 승인이 아니다.

대상 학생, 보호자, 코디네이터 역할의 수신자 3명. 현재 0 / 3.
관찰 기준 응답 라벨 4개, 금지값, 최신 공지 우선, 수동 전송 경계.
상태 no signal. 관찰 스크립트이며 검증/통합/공개 라우트 아님.
금지 자동 게시, 응답 수집, 연락처 저장, 건강/결제/학생 식별값 저장.

not invited, invited, scheduled, not run은 관찰 증거가 아니다. 이 스크립트는 agreed 슬롯의 completed usable session만 rollup으로 넘긴다.

관찰 세팅

FlowMe 제품 설명을 먼저 하지 않는다. 수신자가 실제 채팅방이나 카페 글에서 패킷을 받았다고 가정하고 읽게 한다.

보여줄 것

공유 패킷 텍스트 또는 패킷 HTML 섹션만 보여준다.

시작 조건

scheduling tracker의 matching slot이 agreed이고 preflight checklist가 통과되어야 한다.

묻는 것

무엇을 먼저 할지, 어떤 라벨을 답할지, 어디로 보낼지, 무엇을 올리지 않을지 묻는다.

보류할 것

FlowMe 로드맵, 플랫폼 게이트, `/content-flows` 후보 설명은 관찰 후에만 말한다.

진행 태스크

짧은 질문으로 수신자의 해석을 본다. 정답을 알려주기보다 헷갈리는 지점을 기록한다.

1. 첫 행동 확인

“이 패킷을 받으면 가장 먼저 무엇을 하겠어요?” 최신 학교/기숙사 공지를 먼저 확인한다고 말해야 한다.

2. 라벨 선택

네 가지 미니 상황을 주고 `공지 확인 완료`, `서류 준비 완료`, `반입금지 제외 완료`, `당일 절차 확인 필요` 중 하나를 고르게 한다.

3. 채널 선택

카카오톡, 네이버 카페, 폼/시트, 메모 중 어디에 붙여넣을지 묻는다. 계정 연결을 기대하면 실패 신호다.

4. 금지값 식별

건강서류, 결제, 학생번호, 주민번호, 방 비밀번호, 폼 편집 링크, webhook URL, 채팅 로그를 올리지 않는지 확인한다.

5. 자동화 경계

FlowMe가 자동으로 메시지를 보내거나 댓글을 수집한다고 이해하면 패킷 문구를 다시 줄여야 한다.

라벨 해석 매트릭스

네 문장만으로 각 라벨이 충분히 구분되는지 본다.

상황 기대 라벨 실패 신호
최신 공지를 열어 입사일과 시간을 확인했다. 공지 확인 완료 전체 입사 준비 완료로 오해한다.
제출서류 목록과 기한을 확인했다. 서류 준비 완료 서류 이미지를 채팅방에 올리려 한다.
전열기구, 취사도구, 반입금지 물품을 제외했다. 반입금지 제외 완료 금지 목록이 학교마다 다를 수 있음을 놓친다.
호실, 카드키, 시설점검 위치를 아직 확인해야 한다. 당일 절차 확인 필요 FlowMe가 방 번호나 비밀번호를 찾아준다고 생각한다.

외부 채널에 올리지 않을 값

FlowMe 안에 저장하지 않는 값은 외부 채팅방, 카페, 폼, 시트, 메모에도 올리지 않도록 확인한다.

건강/신분

건강확인서 이미지, 결핵검사 결과 이미지, 주민번호, 학생번호.

결제/방 정보

결제 계좌, 납부 증빙, 방 비밀번호, 카드키 번호.

채널 정보

카카오톡 방 ID, 초대 링크, 네이버 카페 멤버 정보, webhook URL.

도구 링크

폼 편집 링크, Notion 권한 링크, 비공개 댓글/채팅 로그.

통과 기준과 실패 신호

이 기준을 통과해도 검증이 아니라 `/content-flows` 리뷰 후보로 옮길 수 있는 최소 근거다.

통과 기준
  • 첫 run 3명 모두 네 라벨을 올바르게 해석한다.
  • 모든 참여자가 최신 공지가 패킷보다 우선이라고 말한다.
  • 민감값을 올리지 않는다고 말한다.
  • FlowMe가 자동으로 보내거나 수집하지 않는다고 이해한다.
  • 모바일 첫 화면에서 패킷의 목적이 읽힌다.
실패 신호
  • `공지 확인 완료`를 전체 완료로 오해한다.
  • `당일 절차 확인 필요`를 FlowMe가 방 정보를 찾는다는 뜻으로 본다.
  • 건강서류, 결제, 학생 식별값을 업로드하려 한다.
  • 자동 게시나 응답 수집을 기대한다.
  • 패킷과 공식 공지의 우선순위를 구분하지 못한다.

제품 결정 사다리

관찰 결과에 따라 다음 작업을 좁게 결정한다. 기능 확장으로 바로 뛰지 않는다.

실패

라벨이나 주의 문구를 고친다. 파일 기반 preview에 머문다.

부분 통과

수동 복사/전송 경계를 강화하고 다시 관찰한다.

통과

`/content-flows` 리뷰 후보를 준비할 수 있다. public route는 아니다.
