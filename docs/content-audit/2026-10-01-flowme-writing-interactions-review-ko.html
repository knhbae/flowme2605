시나리오별 결과와 실패 이력

앱 W1~W15, HTML L1~L8, 기존 회귀5개는 각각 다섯 크기에서 통과했습니다. 표적·기본·통합 테스트는 겹치므로 제품 커버리지 퍼센트로 더하지 않습니다.

초기 브라우저에서 원문 위치 덮어쓰기·외부 변경의 local 인계·저장된 빈 줄 뒤 메모 거절·마지막 행13px 잘림을 찾아 수정했습니다. fixture 부팅/기대 오류와 제품 결함을 검사 원장에서 나눠 보존합니다.

앱·회귀가 실제 읽은 production 자산24개의 경로별 hash가 동일합니다. 합성 경계220개에서 실제 API 전달·허용 저장 범위 밖 변경·오류0, 합성 운영 표식 byte 동일을 확인했습니다. 실제 운영 데이터 전체 byte 대조를 했다는 뜻은 아닙니다.

변경 범위·기존 데이터 보호·스킬의 기여

입력 엔진/순수 helper, 부분 영역 컴포넌트/검증 모델, 전체 작성기·개인공간·인증 host 연결, 표적/브라우저 테스트, 조작/보고 HTML과 정본 문서를 변경했습니다. 파일별 목록은 위 ‘요구별 결과’에 있습니다. 앞선 같은 채팅의 폴더/여정 후보와 이번 변경을 구분하며, 다른 작업본의 dirty 파일을 가져오지 않았습니다.

기존 /my 진입점·운영 저장 schema·API/Auth/DB·migration은 수정하지 않았습니다. HTML 저장은 flow:poc:personal-workspace:v1:writing-input-lab:v1 정확한 key만 쓰고 초기화도 이 key만 지웁니다. localStorage.clear()는 사용하지 않습니다.

UX 감산 검토로 부분 native의 행별 writer 버튼을 제거했습니다. 실제 키/화면 검사로 단위 테스트가 놓친 커서 경쟁·외부 판본 인계·마지막 행 잘림을 발견했습니다. 기존 코드/디자인 토큰을 재사용했으며 Figma·새 시각 컨셉·새 영구 문법은 만들지 않았습니다.

남기는 제한

부분 작성에서는 기존 항목의 구조·날짜·소속·진행기록을 바꾸지 않습니다. 미저장 입력 Undo와 저장 변경 Undo, 부분 textarea와 전체 textarea의 native Undo stack은 서로 다른 범위입니다. 일반 메모의 Shift+Enter를 Item 메모의 새 이어쓰기 문법으로 확정하지 않습니다.

Creator 전체 입력 UX, 큰 집중 모드, 반복/상대 날짜·Flow Map·공개/기여·대용량 백업·장시간 운영·실기기/접근성·요청량은 별도 후속입니다. 피드백21개 전체 해결이나 제품 전체 충족률로 계산하지 않습니다.

모바일에서 문서·폴더 목록을 펼친 상태의 첫 화면은 목록이 차지합니다. 부분 작성 본문은 아래로 스크롤해야 보입니다. 버튼·키보드 접근 검사가 통과해도 모든 상태의 첫 화면 사용성이 해결됐다는 뜻은 아닙니다.
