My Flow 저장 후 실행 관찰 전 드라이런

저장 개수별 My Flow가 관찰 세션에 들어갈 만큼 단순한지, UX 디자이너 관점으로 한 번 더 시뮬레이션했다. 실제 사용자 발화나 행동 데이터는 아직 없으므로, 이 문서는 관찰 준비 상태와 남은 리스크를 분리하는 용도다.

저장 개수별 UX 판정 클릭 smoke check 관찰 키트 관찰 기록지 관찰 롤업

결론

지금은 더 만들기보다 관찰을 시작할 수준

단일 저장, 4~8개 저장, 20개 이상 저장 모두 “전세/10개 Flow 수준의 단순성”에 가까워졌다. 첫 화면에서 관리 대시보드가 먼저 보이지 않고, 오늘 실행과 Flow 찾기의 역할이 분리되어 있다. 지금 바로 더 많은 UI를 붙이는 것은 목표와 반대다.

  • 관찰 전 Blocking은 보이지 않는다.
  • 남은 High 후보는 상세 안의 작은 완료 토글이 실제로 필요한지 여부다.
  • 다음 작업은 새 화면 설계가 아니라 기록지 기반 3~4회 관찰이다.

상태별 드라이런

첫 행동과 리스크

상태첫 화면 판단기대 첫 클릭남은 리스크판정
1개 저장 전역 탭이 없고, 저장한 Flow와 오늘/밀린 항목이 바로 보인다. 밀린 항목 또는 이번 주 예정 Step 열기 상세 안의 완료 토글이 메모보다 먼저 보이면 과할 수 있다. 관찰 가능
4개 저장 Today가 기본이고, 다른 Flow 탐색은 Flow 찾기로 분리된다. Today 항목 열기 사용자가 오늘 항목과 전체 Flow 목록을 혼동하는지 봐야 한다. 관찰 가능
8개 저장 Flow 찾기를 눌러야 목록/검색이 열린다. 첫 화면 과밀도는 낮다. 필요할 때 Flow 찾기 찾기 버튼명이 충분한지, 검색/필터를 바로 발견하는지 봐야 한다. 관찰 가능
20개 이상 처음 8개만 보이고 전체 보기로 확장된다. 검색/필터 또는 전체 Flow 보기 초기 8개가 너무 적거나, 전체 보기보다 검색이 약하게 보일 수 있다. 관찰 우선

UX 디자이너 피드백

더 줄일 가능성이 있는 부분

상세 완료 토글현재는 유지가 맞다. 다만 실제 사용자가 메모만 쓰고 닫는다면 상세에서는 숨기는 쪽이 더 단순하다.
완료 필터Flow 찾기 sheet 안의 완료 필터는 관리 기능이다. 처음 화면에는 없으므로 괜찮지만, 관찰에서 눌림 여부를 봐야 한다.
진행률 숫자단일 저장의 진행률은 보조 정보다. 사용자가 시선을 뺏기면 더 작게 내린다.
20개 이상 sheet검색이 먼저 쓰이는지, 전체 보기가 먼저 쓰이는지에 따라 정렬과 버튼 위치를 조정한다.

시뮬레이션 로그

가정 기반 결과

페르소나상황예상 행동문제 등급다음 확인
계약 전 확인 사용자 Flow 1개 저장, 오늘 서류 항목 확인 밀린 항목 첫 row를 열고 메모를 본 뒤 완료 토글 또는 닫기를 누른다. Medium 후보 완료 토글이 메모 행동을 방해하는지 관찰한다.
생활 Flow 여러 개 저장 사용자 전세, 이사, 홈트, 수학 Flow 저장 Today에서 현재 항목을 처리하고, 다른 Flow가 필요할 때만 Flow 찾기를 누른다. Pass 예상 Today와 Flow 찾기의 역할을 설명 없이 이해하는지 본다.
저장 목록이 많은 사용자 30개 저장 중 특정 자동차 Flow 탐색 Flow 찾기 sheet에서 검색 또는 필터를 시도한다. Medium 후보 전체 Flow 보기 30개를 먼저 누르면 목록 과부하가 생기는지 본다.

반복 기준

관찰 후 바로 바꿀 조건

관찰 신호판정수정
사용자 2명 이상이 상세 완료 토글을 “무엇을 완료하는지” 묻는다. High 상세 완료 토글을 숨기고, Step 내부 체크와 메모만 남긴다.
사용자 2명 이상이 Flow 찾기를 찾지 못한다. High 버튼명을 저장한 Flow 찾기로 바꾸고 위치를 Today 하단에 더 명확히 둔다.
20개 이상에서 모두 전체 펼침만 누르고 검색을 쓰지 않는다. Medium 검색 input을 sheet 첫 줄에 더 선명하게 두고, 전체 보기는 보조로 내린다.
