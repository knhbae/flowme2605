CEO Brief · Source / Version / Trust Ledger · 2026-07-05

FlowMe의 신뢰 자산은 ledger에 쌓인다

URL-first와 Export Pack v1을 제품으로 만들려면, Flow가 어디서 왔고 언제 확인됐고 어떤 버전으로 export됐는지가 파일 밖에서도 남아야 한다. Ledger는 P0의 신뢰 계약이다.

10최소 ledger 필드
3상태 gate
3P0 export 반영면
5민감 영역
1. Canonical source사용자 URL을 정규화하고 기존 변환본을 먼저 찾는다.
2. Trust gatehit / needs_review / miss 상태로 저장과 export 가능 범위를 나눈다.
3. Version relation원본 Flow, 사용자 수정본, fork 관계를 분리한다.
4. Export watermark.ics, Markdown, checklist 안에 출처/확인일/주의/완료 기준을 남긴다.

1. 결론

Ledger는 백오피스 기록이 아니다. FlowMe가 기존 앱과 연결될 때 신뢰와 책임 경계를 유지하는 제품 기능이다.

P0 확정

최소 10개 필드

source URL, canonical URL, title/type/status, checked date, version ref, risk, caution, export generated date를 필수 contract로 둔다.

P0 확정

상태별 gate

hit만 저장/export를 열고, needs_review는 미리보기, miss는 수집/요청으로 제한한다.

P1 확장

Diff와 connector 로그

hash, snapshot diff, API sync log는 P1/P2로 둔다. P0는 사용자가 볼 수 있는 신뢰 표식이 먼저다.

CEO 결정안: Ledger는 “나중에 데이터베이스로 정리”가 아니라 Export Pack v1과 동시에 붙는 P0 contract다.

2. P0 Ledger 필드 contract

필드는 많이 모으는 것이 아니라, URL-first와 export에서 빠지면 위험해지는 값만 P0로 고정한다.

필드 P0 여부 의미 사용 위치 P1/P2 확장
source_url 필수 원문으로 돌아가는 링크 URL lookup, My Flow, export body source availability check
canonical_url 필수 중복 URL 재사용과 AI 비용 절감의 기준 URL-first lookup key redirect history, canonical conflict log
source_title 필수 무엇을 변환했는지 사용자가 이해하는 이름 hit 결과, export header author/site/license 분리
source_type 필수 official, creator, brand, community, curation 등 출처 성격 trust badge, 민감 문구 creator permission, backlink policy
source_status 필수 real, needs_review, missing 상태 저장/export gate review queue SLA
checked_at 필수 출처가 확인된 날짜 export watermark, source card scheduled re-check
version_ref 필수 Flow 변환본의 버전 참조 save snapshot, fork relation snapshot hash, diff viewer
risk_level 필수 low, medium, medical, legal, financial 등 위험도 민감 영역 copy, export caution category-specific policy rules
caution 필수 조언처럼 보이지 않도록 하는 주의 문구 .ics description, Markdown 상단, checklist 하단 jurisdiction/localization
export_generated_at 필수 파일/텍스트가 생성된 시점 export body, future support connector sync attempt log

3. 상태별 처리

사용자에게 내부 상태어를 크게 노출할 필요는 없지만, 제품 gate는 엄격해야 한다.

hit

바로 실행 가능

  • canonical URL이 기존 Flow와 매칭된다.
  • source_status는 real이다.
  • 저장, My Flow 시작, `.ics`, Markdown, checklist export를 연다.
  • export에는 source URL, checked date, caution, completion을 남긴다.
needs_review

검토 전 잠금

  • 구조 후보는 있지만 원문 row, 일정 기준, 위험 문구가 불충분하다.
  • 미리보기와 원문 확인 CTA만 제공한다.
  • 저장과 export는 잠근다.
  • ledger에는 required_action과 reviewer note를 남긴다.
miss

아직 변환 전

  • canonical URL에 연결된 Flow가 없다.
  • P0에서는 AI-first 생성 기대를 만들지 않는다.
  • 수집/요청/대기열로 보낸다.
  • ledger에는 input URL, canonical URL, requested_at만 남긴다.

4. Export Pack v1에 들어가는 방식

Ledger는 외부 파일 안에 “작게 남는 신뢰 watermark”여야 한다. 사용자를 방해하지 않되, 출처와 경계를 잃지 않는다.

Export 반드시 들어갈 ledger 표현 위치 금지 현재 근거
.ics title, date, duration, source URL, checked_at, caution, completion DESCRIPTION, URL field, event title 의료/법률/재무 행동을 “해야 함”으로 단정 `my-flow-step-export.ts`와 `export.ts`가 description/source URL/caution을 다룸
Markdown source title, canonical/source URL, checked_at, source_status, version_ref, caution, completion 문서 상단 summary block 원문 없는 요약을 사실처럼 보이게 작성 URL-first start package가 Markdown download를 생성하고 E2E로 확인됨
Checklist item list, completion, source URL, checked_at, caution, user memo 체크 항목 아래 footer 출처와 확인일 없는 범용 조언형 checklist Step portable text가 checked items, memo, completion, caution, source를 다룸
원칙: export는 “FlowMe가 추천했다”가 아니라 “이 원문에서 확인한 실행 구조를 이 날짜에 내보냈다”라고 말해야 한다.

5. 수정과 fork의 version 관계

사용자 수정은 제품의 강점이지만, source-backed fact와 섞이면 신뢰가 무너진다. 두 계층을 분리한다.

P0 version relation

관계 저장할 값 사용자 의미
original source_url, canonical_url, source_checked_at, source_status, version_ref 원본에서 온 사실과 실행 구조
user edit edited_title, edited_date, memo, checked_items, edited_at 내 상황에 맞춘 변경
fork parent_flow_id, parent_version_ref, forked_at, fork_reason 원본을 기반으로 만든 새 개인/공유 버전
export export_mode, export_generated_at, export_version_ref 어떤 버전이 외부 앱으로 나갔는지

필드 성숙도

현재 코드에는 source URL, source checked date, risk, caution, saved snapshot, map version이 존재한다. P0 과제는 이를 한 contract로 묶어 export와 gate에 일관되게 넣는 것이다.

6. 민감 영역 trust/caution 기준

민감 영역의 핵심은 “조언을 더 잘 쓰는 것”이 아니라, 조언처럼 보이지 않게 실행 언어를 바꾸는 것이다.

영역 risk_level source_type 우선순위 export 문구 잠금 조건
의료/건강 medical_sensitive official 우선, creator/community는 참고로 제한 예약, 문의, 기록, 보호자/전문가 확인 checked_at 없음, 공식 source 불명확, 효능 보장 표현
육아 medical_sensitive 또는 medium official/병원/공공기관 우선 관찰 기록, 준비물 확인, 상담 질문 발달/건강 판단처럼 보이는 문장
법률/계약 legal_sensitive official/계약서/공공기관 우선 서류 확인, 조건 비교, 전문가 문의 계약 결정을 대행하는 표현
재무/구매 financial_sensitive 공식 공시, 견적서, 약관 우선 비용 항목 정리, 견적 확인, 보류 조건 투자/대출/구매 권유처럼 보이는 표현
커뮤니티 경험 medium community/creator는 경험 출처 표시 내 상황에 맞게 수정, 원문 경험 참고 개인 후기를 공식 기준처럼 변환

7. P0/P1/P2 확장 관계

Ledger를 먼저 고정해야 direct API, sheet, calendar feed가 나중에 안전하게 붙는다.

P0

Visible trust contract

  • 10개 최소 필드 확정
  • hit / needs_review / miss gate
  • Export Pack v1 watermark
  • 민감 영역 caution rule
P1

Review and sheet expansion

  • snapshot_ref/source_hash
  • CSV/sheet summary fields
  • review queue와 re-check date
  • fork reason과 parent version 표시
P2

Connector audit trail

  • Todoist/Notion/Google sync log
  • calendar feed version drift 처리
  • 삭제/중복/권한 실패 기록
  • creator permission과 backlink ledger
