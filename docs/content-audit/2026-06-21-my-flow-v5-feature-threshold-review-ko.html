My Flow v5 판단 기준

깔끔한 기본형을 유지하면서, 기능이 언제 필요한지 정한다

v5는 제품 전체 기능 완성본이 아니라, 저장한 Flow를 다시 열었을 때 가장 먼저 보여줄 기본 실행 화면의 기준선이다. 여기서는 “무엇을 더 넣을까”가 아니라 “어느 상황에서 기능을 노출해야 하는가”를 판단한다.

v5는 기본 홈 후보 캘린더는 조건부 핵심 기능 Flow Map은 상위 구조 있을 때만 아직 사용자 검증 아님

핵심 의견

v5는 채택하되, “모든 기능을 첫 화면에 숨기는” 기준선으로 써야 한다

기본 화면 오늘 할 Step, 체크, 메모, 원문/다른 앱 fallback 텍스트만 먼저 보인다. 사용자가 바로 실행할 수 있으면 성공이다.
조건부 화면 캘린더, 검색, 그룹, Flow Map, 반복 설정은 상황이 생겼을 때만 열린다. 기능은 남기되 첫 화면에는 다 올리지 않는다.
보류 화면 상태 대시보드, 증거 관리, 고급 필터, 업데이트 정책, 외부 연동은 아직 첫 화면 기능이 아니다.

저장 개수 기준

Flow가 몇 개 저장됐는지에 따라 필요한 기능이 달라진다

상황 v5 판단 필수 기능 숨기거나 보류할 기능
저장 1개 v5 적합 현재 Step, 체크, 메모, 원문/다른 앱 텍스트 탭, 필터, 전체 캘린더, 나중에 보기, 큰 완료 버튼
저장 2-5개 기본 유지 오늘 할 일, Flow 찾기, 이번 주/보관 정도의 가벼운 분류 상태별 대시보드, 과한 카드, 모든 Flow 전체 노출
저장 6-20개 검색 필요 검색, 짧은 필터, 날짜/보관/전체 전환, 초기 목록 제한 모든 Flow 카드 전체 펼침, 매 row마다 텍스트 완료 버튼
저장 20개 이상 관리 모드 필요 검색 우선, 그룹 접기, 최근/오늘/보관 우선, 전체 보기 명시 첫 화면에 20개 이상 나열, 카테고리별 색상 과다, 전체 관리 대시보드 기본 노출

Flow 타입 기준

기능은 Flow 타입별로 필요할 때만 올라온다

타입 대표 예시 v5에서 충분한 것 추가가 필요한 순간
일정형 전세, 이사, 검진, 출국 준비 오늘 Step + 선택 항목 상세 날짜가 3개 이상이거나 사용자가 특정 날짜를 고를 때 캘린더/타임라인 필요
루틴형 홈트, 물주기, 세탁조 청소 오늘 세션 체크 + 짧은 메모 반복 요일, 다음 회차, missed 처리까지 필요해지면 반복 설정 필요
진도형 중1 수학, 자격증 과목, 온라인 강의 현재 단원/회차 Step + 완료 체크 전체 위치, 다음 단원, 단원 목록 이동이 필요해지면 진도표 필요
프로세스형 여권 재발급, 중고차 방문, 행정 신청 현재 할 일 + 원문 링크 + 메모 선택/보류/재검토가 중요한 경우 결정 메모가 필요
보관형 스퀴시 도안, 이심 설치 링크, 나중에 볼 가이드 저장, 원문 링크, 준비물/메모 텍스트 사용자가 날짜를 붙이면 캘린더 항목으로 승격
Flow Map형 중1 수학 전체, 예방접종/검진 지도 지금 이어서 할 Step 상위 구조에서 위치를 봐야 할 때 전체 지도/부분 저장 필요

기능별 노출 기준

부족해 보이는 기능을 바로 붙이지 않고, 노출 조건을 둔다

기능 판정 노출 조건 이유
캘린더 조건부 핵심 날짜형 Flow, 2개 이상 날짜, 월/주 단위로 찾을 일이 있을 때 전세/이사/검진에는 중요하지만, 단일 체크/보관 Flow에는 첫 화면 노출이 과하다.
Flow 찾기 기본 유지 2개 이상 저장부터 복잡한 탭보다 안전한 단일 진입점이다.
검색/필터 6개 이상 저장 Flow가 6-8개를 넘거나 사용자가 스크롤로 찾기 어려울 때 초기부터 보이면 관리툴처럼 보인다.
완료 버튼 작게 유지 Step detail의 체크박스 또는 row의 작은 체크 큰 “이 항목 완료” 버튼은 단순 화면에서 불필요한 행동을 만든다.
나중에 보기 기본 보류 보관형 Flow가 많거나 날짜 없는 항목을 따로 모아야 할 때 1개 저장 상태에서는 그냥 저장되어 있으면 충분하다.
상태 대시보드 첫 화면 금지 20개 이상 저장 또는 팀/운영형 사용이 보일 때 별도 화면 v5가 좋아진 이유는 상태 설명을 줄였기 때문이다.
외부 앱 export 근처에 둠 Step detail의 fallback 텍스트, 캘린더형의 일정 텍스트 Stage 0의 핵심이지만 첫 화면 버튼이 많아지면 실행이 흐려진다.
Flow Map 전체 지도 해당 타입만 상위 지도 안에 반복 가능한 Flow가 3개 이상일 때 모든 Flow를 지도처럼 만들면 단일 Flow보다 어려워진다.

다음 테스트 세트

v5가 어디서 깨지는지 확인할 6개 시나리오

1. 전세 Flow 1개 저장탭 없이 현재 Step, 체크, 메모만으로 충분한지 본다.
2. 생활 Flow 5개 저장전세, 이사, 검진, 홈트, 스퀴시가 섞였을 때 Flow 찾기 하나로 충분한지 본다.
3. 날짜형 Flow 8개 저장오늘/이번 주/전체만으로 되는지, 캘린더 탭이 필수인지 본다.
4. 20개 이상 저장초기 8개만 보여주는 방식과 검색/전체 보기의 균형을 본다.
5. 중1 수학 진도형현재 단원만 보여도 되는지, 전체 진도표가 언제 필요한지 본다.
6. 루틴형 홈트오늘 세션 체크만으로 충분한지, 반복 설정이 언제 필요한지 본다.

판단 Rubric

v5를 평가할 때 볼 점수 항목

항목 좋은 상태 깨지는 신호
첫 행동 명확성 사용자가 첫 화면에서 지금 할 Step을 바로 연다. Flow 찾기, 날짜, 완료, 보관 중 무엇부터 눌러야 할지 망설인다.
복잡도 캘린더/리마인더/투두앱 수준을 넘지 않는다. 프로젝트 관리툴처럼 탭, 상태, 카드, 버튼이 많아진다.
Flow 타입 적합성 날짜형은 날짜, 진도형은 위치, 루틴형은 반복이 필요할 때만 보인다. 모든 Flow에 같은 캘린더/체크리스트/지도 UI를 강제로 붙인다.
외부 앱 이식성 Step은 캘린더/투두/시트로 나가고, Item은 메모 텍스트로 접힌다. FlowMe 안에서만 이해되는 상태/구조가 많아진다.
재방문성 며칠 뒤 돌아왔을 때 이어서 할 Step과 남긴 메모가 보인다. 다시 들어왔을 때 전체 목록부터 뒤져야 한다.

다음 액션

지금은 기능 추가보다 “노출 조건”을 실제 클릭으로 확인하는 단계

  1. v5를 기준으로 저장 1개, 4개, 8개, 20개 이상 상태를 모바일에서 다시 클릭한다.
  2. 각 상태에서 첫 클릭이 현재 Step인지, Flow 찾기인지, 날짜 전환인지 기록한다.
  3. 날짜형/루틴형/진도형에서 캘린더, 반복, 진도표가 없는 상태가 불편한 순간만 표시한다.
  4. 불편한 순간이 반복될 때만 v6 기능으로 승격한다.
  5. 사용자 검증 전에는 “완료/검증됨”이 아니라 “내부 PoC 기준선”으로만 부른다.
