UX/UI Simulation Report

상위 3개 Flow를 사용자 화면 기준으로 재검증

6개 카테고리를 모두 비슷한 UI에 넣는 대신, 전세 계약 Flow의 기준선에 가까운 3개를 골라 사용자 화면을 따로 만들고 실제 클릭으로 확인했습니다.

이번 결정

현재 6개 전체를 같은 깊이로 밀기보다, 제품 연결성과 source-to-flow 적합성이 강한 3개를 먼저 전세 수준에 가깝게 올렸습니다.

  • 이사 D-30: 날짜형 일정 + 체크 + 업체 메모.
  • 중고차 방문: 캘린더보다 현장 체크 순서가 중심.
  • 초등 입학: 입학일 기준 일정 + 학교 안내문 URL.

제거한 문제

사용자 화면에 남아 있던 내부 평가 문구와 범용 버튼을 제거했습니다.

  • `전세급`, `PoC`, 개발자 리뷰 문구 제거.
  • `진행 중/보류/완료` 같은 의미 불명 상태 버튼 미사용.
  • `메모 복사`, `현재 설명 복사` 같은 낮은 가치 버튼 미사용.
  • 같은 설명 반복 대신 각 항목의 실제 확인 내용 작성.

후보별 판정

Flow 자연스러운 destination 전세 기준 대비 남은 리스크
이사 D-30 이사일 기준 캘린더 + 전체 일정 타임라인 + 업체 메모 전세와 가장 유사합니다. 날짜 입력 후 D-30/D-14/D-7/D-1/D-Day로 실행하는 구조가 명확합니다. 견적 요청 사이트를 제품적으로 추천할지, 단순 원문 링크로 둘지 별도 정책이 필요합니다.
중고차 방문 현장 체크 순서 + 보류 메모 + 자동차365/카히스토리 링크 전세와 달리 캘린더보다 현장 체크가 핵심입니다. 그래서 날짜는 저장 정보로만 두고, 실행 화면은 섹션형으로 분리했습니다. 실제 사용자 관찰에서 공식 조회 링크를 어느 단계에 배치해야 가장 덜 헷갈리는지 확인해야 합니다.
초등 입학 입학일 기준 캘린더 + 학교 안내문 URL + 준비물/생활 연습 체크 전세처럼 날짜형 Flow로 성립합니다. 다만 원문보다 학교 안내문이 더 강한 기준이므로 안내문 URL 입력을 중심으로 바꿨습니다. 학교별 안내문이 없을 때 기본 템플릿을 얼마나 제공할지 정책이 필요합니다.

다음 개선 방향

이제부터는 새 카테고리를 더 늘리기보다, 약한 후보를 억지로 살리지 않고 전세/이사/중고차/초등 입학처럼 destination이 분명한 후보만 통과시키는 게 맞습니다.

  • 영유아 검진은 공식 검진 시기/문진표/병원 예약 흐름까지 확보한 뒤 다시 설계합니다.
  • 홈트는 체크리스트가 아니라 영상 루틴 플레이어/반복 일정이 핵심이므로 별도 패턴으로 다시 봅니다.
  • 스퀴시는 단일 버킷/준비물/놀이 날짜 패턴이 자연스럽습니다. 4단계 실행 Flow로 만들면 과합니다.
  • 식물 물주기는 원컨텐츠 기반 반복 일정과 간단한 상태 체크만 남겨야 합니다.
