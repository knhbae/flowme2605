우선 개선

저장 후 실행

가장 먼저 손볼 곳은 홈이 아니라 저장 후 `오늘`, `다음`, 날짜별 일정, Flow별 구조를 보는 화면입니다.

보류

홈 고도화

홈은 콘텐츠 수, 이미지, 사용 기록, 리뷰가 쌓여야 좋아집니다. 지금은 큰 구조만 유지합니다.

문제 정의

영역 현재 문제 기획 방향
내 Flow 오늘 할 일은 보이지만 다음 할 일이 약합니다. Step 카드에 Flow명, 진행률, 날짜, 설명, Item이 섞이면 정보량이 많아집니다. 첫 화면은 `오늘`과 `다음`만 먼저 보여줍니다. Step 기본 카드는 일정/투두 수준으로 줄이고, Item과 원문 링크는 열었을 때만 보여줍니다.
캘린더 월간 캘린더 자체는 자연스럽지만 날짜 선택 후 항목이 하단에 있어 스크롤이 생깁니다. 모바일에서는 선택한 날짜의 항목을 캘린더 바로 위나 바로 아래의 가까운 패널에 보여줍니다. 긴 detail은 Step을 눌렀을 때만 엽니다.
공개 Flow 상세 저장 전 화면에 원문, 입력, 저장 미리보기, 세부 항목이 함께 보여 복잡합니다. 저장 버튼 위치도 재검토가 필요합니다. 상단은 결과 예측, 본문은 저장 후 들어갈 항목 미리보기, 모바일 하단은 sticky 저장 CTA로 나눕니다. 항목 수정은 저장 후 내 Flow에서 다룹니다.
Flow 찾기 `바로 실행 Flow` 표현이 내부/AI스럽고 카드 형태 차이가 의도보다 먼저 보일 수 있습니다. 사용자 라벨은 `큰 흐름`과 `하나만 저장`으로 단순화합니다. 카드 shell은 통일하고 미리보기 밀도만 다르게 둡니다.

사용자 여정

1. 저장 전

무엇이 생길지 보기

  • Flow 찾기에서 큰 흐름 또는 하나만 저장을 고릅니다.
  • 공개 상세에서 입력값과 생성될 항목을 봅니다.
  • 모바일 하단 CTA로 저장합니다.

2. 저장 직후

첫 항목 확인

  • 저장 완료를 확인합니다.
  • 첫 Step과 다음 Step이 보입니다.
  • 전체 구조는 `전체 Flow 보기`로 들어갑니다.

3. 실행 중

오늘과 다음

  • 오늘 할 일이 있으면 먼저 보여줍니다.
  • 오늘 할 일이 없거나 끝났으면 다음 할 일을 보여줍니다.
  • Step을 누르면 Item과 메모가 그 자리에서 열립니다.

4. 재방문

캘린더와 Flow별 보기

  • 날짜가 있는 항목은 캘린더에서 찾습니다.
  • 전체 구조와 원문은 내 Flow의 Flow별 보기에서 봅니다.
  • 수정은 열린 Step detail 안에서 처리합니다.

정보 구조 결정

Step 기본 카드

기본으로 보이는 정보

  • 체크 상태
  • Step 제목
  • 날짜/시간 또는 `날짜 없음`
  • 소속 Flow 또는 Map은 작은 보조 정보 1회만
  • 진행률은 Flow 카드 상단에만, Step마다 반복하지 않음

Step detail

열었을 때만 보이는 정보

  • Item 체크리스트 또는 text fallback
  • 메모/description
  • 원문 URL
  • 완료 기준, 주의, 출처 정보
  • 수정/내보내기 컨트롤

오늘 vs 다음

정렬 규칙

  • `오늘`: 오늘 날짜에 걸린 Step 또는 기한이 지난 미완료 Step
  • `다음`: 오늘 이후 가장 가까운 미완료 Step 1~3개
  • 날짜 없는 체크리스트는 `다음`보다 Flow별 보기에서 우선
  • 완료한 항목은 기본 접힘

저장 전 수정

지금은 제한

  • 공개 상세에서는 입력값과 저장 미리보기만 제공합니다.
  • Step/Item 편집은 저장 후 내 Flow에서 다룹니다.
  • 저장 전 항목 제외/순서 변경은 P0가 아닙니다.
  • 이유: 원문 충실도와 가벼운 저장 흐름을 먼저 지킵니다.

구현 전 확인 질문

  1. `내 Flow` 첫 화면을 `오늘 + 다음` 중심으로 바꾸는 것이 맞는가?
  2. 모바일 `캘린더`에서 선택 날짜 항목을 월간 캘린더보다 먼저 보여주는 것이 맞는가?
  3. 공개 Flow 상세의 모바일 저장 CTA를 하단 sticky로 두는 것이 맞는가?
  4. `바로 실행 Flow` 대신 `하나만 저장`을 사용자 라벨로 쓰는 것이 맞는가?
  5. 저장 전 Step/Item 수정은 보류하고, 저장 후 `내 Flow`에서 수정하는 경계가 맞는가?

구현 순서 제안

순서 범위 왜 먼저인가 검증
1 내 Flow `오늘 + 다음` 구조 저장 후 실행 가치가 가장 직접적으로 보입니다. 저장 직후, 오늘 실행, 다음 할 일 시뮬레이션
2 Step 기본 카드/상세 카드 분리 정보량이 줄어야 캘린더/투두 앱 수준에 가까워집니다. Step 열기/닫기, Item 체크, 원문 링크 확인
3 캘린더 선택 날짜 패널 날짜를 눌렀는데 하단까지 이동해야 하는 불편을 줄입니다. 날짜 클릭 후 선택일 항목 위치 확인
4 공개 상세 sticky 저장 CTA 저장 전 화면에서 입력/미리보기/저장 행동을 분리합니다. 모바일 저장 전 → 저장 후 여정
5 Flow 찾기 라벨과 카드 shell 탐색 화면의 AI스러운 표현과 시각 차이를 줄입니다. 홈과 Flow 찾기 비교 리뷰
