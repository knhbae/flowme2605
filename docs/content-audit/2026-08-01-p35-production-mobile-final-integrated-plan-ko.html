1목표 UX 한 문장

사용자는 공개 Flow에서 자신에게 적용될 결과를 정확히 확인하고 필요한 만큼 한 번에 고친 뒤 저장하며, 저장된 Flow에서는 다음 1~3개 행동을 실행하고 같은 결과를 언제든 자신의 도구로 옮긴다.

공개 미리보기, 저장, 저장 결과, My Flow, export는 모두 하나의 effective snapshot을 읽습니다. 화면마다 표현 목적은 달라도 결과명·개수·날짜 상태와 사용자 수정값은 달라지지 않습니다.

공통 코어는 유지canonical source, stable Item identity, projection, 5개 renderer, recurrence·storage·export 엔진은 다시 만들지 않습니다.
화면은 상태별로 감축각 상태는 사용자 질문 하나와 primary action 하나만 소유합니다. 편집·export·복구는 필요할 때만 분기합니다.
결과 계약이 먼저시각 개편보다 effective snapshot, 원자적 편집, 저장·export parity를 먼저 닫습니다.
증거 경계 유지Production·코드·전문가 검토는 내부 결정 근거입니다. 사용자 관찰 0건이므로 성공이 검증됐다고 표현하지 않습니다.

3오너·Codex·Claude 의견 충돌 결정표

오너의 화면 불편은 문제 근거로 사용하되 팝업·별도 화면·삭제 같은 표현은 해결책 가설로 분리했습니다. Claude는 독립 UX 감축안, Codex는 전체 로컬 코드·persistence 계약을 확인한 안입니다.

7 메모 M-04/M-05: 행 메모·실행 메모·메모 일정이 같은 것으로 보임. UI entry 하나, 기존 3개 상태 모델은 즉시 병합하지 않고 목적·export 의미 보존. 내 메모 하나와 draft memo 정본, 실행 메모 무손실 이관. Item 상세의 메모 진입점 하나. 신규 기본값은 Item memo. 기존 execution/source-correction/legacy note는 adapter로 보존·표시. 데이터 보호 P0에서 물리 병합·삭제·조용한 연결 금지. 장기 migration은 P1.
8 출처·위험 F-08: 경로마다 위치·명칭·깊이가 다름. 원문만 남기자는 의견은 해결 가설. 직접 원문 항상, 위험 주의는 행동 인접, 긴 provenance만 disclosure. 원문은 제목 아래 비접힘, warning/caution은 해당 Item 안, 출처 자세히는 조건부. 직접 원문은 identity에 항상. 높은 위험 주의는 행동 옆에 펼쳐 표시. 긴 제작자·출처 설명만 접음. 안전 계약 riskLevel/sourceDisclosure/reviewState로 결정. hold는 save/export를 차단.

4공통 계약과 허용 가능한 Shape별 변형

P0의 기술적 중심은 새 화면이 아니라 하나의 EffectiveFlowSnapshot read model입니다. 이름은 구현 중 달라져도 입력·출력 불변식은 달라지면 안 됩니다.

입력층 · 보존 source baseline + title/detail/date/Item memo overlay + inclusion/order + date intent/recurrence + completion/run overlay + source/risk/review state
→
하나의 effective snapshot sourceContentVersion + personalOverlayVersion + executionOverlayVersion · stable rows · shape/count/date state · export plan · capabilities
→
소비층 · 동일 의미 Preview · save record · receipt · My Flow · Item detail · text/XLSX/ICS export · map adapter
결과 불변식같은 시점·scope의 shape label, 전체·실행 가능·날짜 있음 count, schedule state는 하나의 resolver 결과로 계산합니다.
편집 불변식source는 불변이며 Flow/Item 변경은 working draft에만 쌓입니다. Apply는 한 번, Cancel은 전부 rollback합니다.
저장 불변식저장은 source content version을 동결하고 public working overlay를 persisted personal overlay v1로 승격합니다. 저장 후 개인 수정은 overlay version만 올리고 source를 다시 쓰지 않습니다.
export 불변식public export는 frozen source + current public draft, My Flow export는 frozen source + current persisted personal overlay + current execution overlay를 입력으로 받습니다.
호환 불변식기존 localStorage key, backup/restore, archive, canonical reconciliation을 삭제·일괄 rewrite하지 않고 additive/dual-read로 확장합니다.
안전 불변식직접 원문, 위험 주의, review hold, 복구·되돌리기는 단순화를 이유로 제거하지 않습니다.

상태 경계: EffectiveFlowSnapshot = FrozenSourceContentVersion + CurrentPersonalOverlay + CurrentExecutionOverlay로 고정합니다. Preview는 working personal overlay를, save·receipt는 저장 순간 persisted overlay v1을, My Flow·Item detail·saved export는 최신 persisted personal overlay를 같은 resolver에 넣습니다. 제목·상세·날짜·포함·순서·Item memo 수정은 personalOverlayVersion을 올리고, completion·run note·source correction은 executionOverlayVersion을 올립니다. 같은 시점·scope의 모든 소비자는 이 3개 version tuple이 같은 snapshot을 읽어야 합니다. text/XLSX는 completion과 Item memo를 지원 필드로 내보내고, ICS는 포함된 Item의 title/detail/date와 Item memo를 description에 반영하되 completion·run note·event 순서는 보장하지 않습니다.
