Source Type → Flow Pattern 규칙표

원문이 어떤 형태인지 먼저 판정하고, 그 형태에 맞는 Flow Map / Flow / Step / Item만 만든다. 부족한 내용은 Park나 보류로 남기고, 드문 예외 상황은 별도 필드가 아니라 메모 안내로 낮춘다.

1차 판정Type
2차 판정Gate
생성 단위Row
예외 처리Memo
이 파일은 2026-07-01 원컨텐츠 9개를 검토하며 만든 사례 적용표다. 공식 규칙 원본은 docs/flow-rules/source-to-flow-conversion-gate.md와 docs/flow-rules/content-conversion-playbooks.md이며, 이 표는 canonical rule이 아니다.

먼저 통과해야 하는 5문장

1. 원문 row가 있는가?

날짜, 회차, 표 행, 체크리스트 항목, 영상 URL처럼 반복 가능한 source row가 없으면 Flow가 아니라 Park 또는 보류다.

2. 사용자가 어디서 관리하는가?

날짜가 중요하면 calendar, 여러 후보 비교는 sheet, 참고/예외는 memo, 즉시 체크는 internal_check, 둘 이상이면 hybrid다.

3. 원문 단위와 실행 단위가 맞는가?

영상 1개는 보통 action 1개, D-day 표는 offset별 Step, 첨부 표는 source row 또는 row group별 Step이다.

4. Item이 사용자의 다음 행동인가?

Step을 열었을 때 바로 체크하거나 기록할 수 없으면 Item이 아니다. 설명, 주의, 배경은 memo/detail/sourceTrace로 내려간다.

5. 예외 상황은 필드인가 메모인가?

정렬, 필터, 알림, 통계, export에 쓰지 않을 값이면 별도 필드로 만들지 않는다. “메모란에 기록”으로 충분하다.

Source Type별 변환 규칙

Type 1

체크리스트형

예시

신차 구매, 이사 준비

필수 source row

단계명, 체크 항목, 담당 기관/업체, 필요 시 D-day offset

Flow 패턴

Flow 또는 Flow Map. Step은 원문 단계, Item은 원문 체크 항목.

허용 기록

업체명, 금액, 예약일, 완료 여부, 메모

금지

원문에 없는 준비 팁, 과도한 하위 task, 반복되는 “자료 확인” item

판정

source row만 있으면 바로 실행 초안 가능.

Type 2

타임라인 / 월령 / D-day형

예시

결혼 준비, 예방접종, 이사 D-day

필수 source row

기준일, offset 또는 월령, 해당 시점의 원문 항목

Flow 패턴

calendar 또는 hybrid. Step은 offset/월령, Item은 그 시점에 해야 하는 source task.

허용 기록

일자, 기관/업체, 예약 상태, 완료 여부, 메모

금지

의료/법률/계약 판단 자동화, 원문에 없는 추가 일정

판정

공식/고위험 영역은 source version을 남기고 최신 row 재확인 후 적용.

Type 3

첨부 표 / 파일형

예시

오픽 XLSX, 이유식 PDF/큐브표

필수 source row

시트명, 날짜/회차/구간, 표 행, 원문 파일명과 비밀번호 여부

Flow 패턴

Flow Map. 파일 버전별 Flow, row group별 Step, 표 cell 기반 Item.

허용 기록

상태, 완료 여부, 수량, 먹은 양, 녹음 파일 위치, 메모

금지

표에 없는 장보기, 조리법, 공부법, 영상 매핑 자동 생성

판정

파일 row가 확인되면 강한 후보. 파일이 없으면 source import 필요.

Type 4

자료창고 / 채널 / 블로그 모음형

예시

펀맘, YouTube 채널 전체

필수 source row

article/video 제목, URL, 카테고리, 대상, 난이도, 자료 존재 여부

Flow 패턴

우선 Park. row import 후 목표별 Flow 후보를 만든다.

허용 기록

저장, 출력 여부, 완료 여부, 메모

금지

사이트 전체를 임의 주간 루틴으로 변환, 대상 나이/난이도 추정

판정

Park가 실패가 아니라 확장 전 단계다.

Type 5

단일 follow-along 영상형

예시

Allblanc 홈트 영상 1개

필수 source row

영상 제목, 영상 URL, 반복 요일 또는 추천 사용 맥락

Flow 패턴

영상 1개 = 루틴 Flow 1개. Step은 “영상 실행” 하나면 충분하다.

허용 기록

반복 요일, 완료 여부, 메모

금지

영상에 없는 동작/세트/횟수 생성, 중단/통증/어지러움 별도 필드화

판정

자막/설명 import 전에는 운동 동작 요약도 보류한다.

Type 6

습관/철학/경험담형

예시

독서 시스템 글

필수 source row

반복 조건, 시간대, 완료 기준, 기록 템플릿 필드

Flow 패턴

row가 있으면 가벼운 routine 또는 memo. 없으면 보류.

허용 기록

완료 여부, 책 제목, 메모. 단, 책별 템플릿 source가 있을 때만.

금지

책 1권 기록 Flow를 임의 설계, 월간 권수/리뷰 Step 추정

판정

좋은 글이어도 실행 row가 없으면 Flow 콘텐츠가 아니다.

Item / Field / Memo 분기 규칙

Item으로 만든다

사용자가 Step을 열었을 때 바로 완료 처리하거나, 원문 순서상 빠지면 Flow가 깨지는 행동이다.

이사 D-10 전출 신고 오픽 3회차 복습 D+180 식단 제공

Field로 만든다

정렬, 필터, 알림, 통계, export, 다음 Step 생성에 반복적으로 쓰이는 값이다.

시작일 완료 여부 업체명 예약일

Memo로 둔다

드문 예외, 자유 서술, 사용자가 필요할 때만 남기는 내용이다. 별도 UI 필드로 노출하지 않는다.

특이사항 몸 상태 접종 후 메모 업체와 통화 내용

생성하지 않는다

원문에 없고, 사용자의 다음 행동도 아니며, FlowMe가 판단하면 안 되는 내용이다.

9개 원컨텐츠 적용 방향

Park

1. 펀맘

사이트 전체는 Park. article 제목/URL/나이/난이도/출력 자료 여부를 먼저 import한다.

실행 초안

2. 오픽

XLSX 2주/1달 row 기반. 다음 보강은 회차별 영상 URL 매핑이다.

실행 초안

3. 이유식

식단표/큐브표 Flow는 가능. 장보기/조리/소분은 별도 레시피 source가 있어야 한다.

보류

4. 독서

현재 원문은 습관 시스템 글. 책 1권 기록 템플릿 source 없이는 Flow로 만들지 않는다.

실행 초안

5. 신차 구매

7단계 체크리스트형. 견적/계약/출고/등록/보험 항목만 유지한다.

부분 실행

6. 예방접종

공식 월령 row만 사용. 기록 필드는 접종일, 기관, 백신명/차수, 메모로 제한한다.

실행 초안

7. 이사

D-day 표가 명확하다. 기관/예약번호/정산/메모만 기록한다.

실행 초안

8. 결혼

네이버 타임라인과 A-to-Z 업체 보드를 분리한다. 후보/견적/예약/계약금/메모 중심.

부분 실행

9. 홈트

영상 1개는 루틴 1개. 제목/URL/반복 요일/완료 여부/메모만 둔다.

개발 데이터 기본 형태

source

원문 근거

sourceRows

원문에서 확인한 row, 파일명, 표 구간, 영상 URL을 그대로 보관한다.

sourceTrace

각 Item마다 어느 source row에서 왔는지 붙인다.

publicContent

사용자용 콘텐츠

Flow / Step / Item

사용자가 실제로 실행할 내용만 둔다. 내부 검토 문구는 섞지 않는다.

recordFields

완료 여부, 날짜, 업체명, 수량, 메모처럼 반복 사용되는 필드만 둔다.

review

검토용 메타

removed

삭제한 작위적 item, 원문 부족으로 보류한 항목을 남긴다.

nextImport

Flow로 승격하려면 더 필요한 row를 명시한다.

status

승격 상태

ready / partial / park / hold

앱 적용 전에 어떤 수준인지 숨기지 않는다. Park와 hold는 정상 판정이다.

sourceVersion

공식/고위험 정보는 최신 source 확인 시점을 별도로 남긴다.

이 규칙표는 2026-07-01 재작성 데이터의 후속 기준이다. 다음 콘텐츠 확장 작업에서는 먼저 이 표로 source type을 판정한 뒤, 필요한 source row가 없으면 Flow를 만들지 않는다.
