/flow-maps/[map] 큰 지도 또는 source-backed map을 보고 전체/일부 저장 판단 저장, 지도 보기, source link 기준 유지Flow Map은 단일 Flow보다 구조가 크지만 My Flow에 들어가면 Step 중심으로 가볍게 보여야 합니다. map별 source row 품질과 전체 저장/일부 저장 UX는 creator gate에서 더 봐야 합니다.
/my 저장한 Flow를 오늘 할 일, 일정, Flow 목록에서 실행 오늘, 일정, Flow, 저장한 Flow 보기, Step 완료/메모 이번 구현 대상모바일 Step detail을 하단 sheet에서 inline 확장으로 바꾸고, 탭·문구·중복 메타를 줄였습니다. 20개 이상 저장, export 재생성, account persistence는 별도 목표입니다.
/flow-maps/[map]/creator 제작자가 원문 row가 Step/Item으로 바뀌는 과정을 검토 source row 확인, draft 저장, local publish marker 분리 유지제작자 화면은 사용자 실행 컨트롤과 섞지 않습니다. 다음 목표는 creator publish gate와 version review를 더 제품적으로 만드는 일입니다.

My Flow UX 감사

사용자 관점 리허설 결과

  • 최초 저장 후: 사용자는 먼저 오늘 또는 저장 완료 패널에서 첫 Step을 열어야 합니다. 전체 Flow 관리는 보조 행동입니다.
  • 오늘 탭: Step row를 누르면 바로 아래에 detail이 열리고, 완료 체크와 메모가 같은 자리에서 가능합니다.
  • 일정 탭: 날짜를 누르면 선택 날짜 영역으로 이동하고, 해당 날짜 Step은 Flow/Map 그룹 안에서 열립니다.
  • Flow 탭: 저장 목록은 execution surface가 아니라 찾기/관리 표면입니다. 모바일에서는 많은 Flow를 바로 펼치지 않고 저장한 Flow 보기로 엽니다.
  • 체크/루틴 보기: 기존 기능은 유지하지만 1차 판단 축으로 과하게 밀지 않습니다. 사용자가 처음 보는 모델은 오늘·일정·Flow입니다.
판단: 이번 목표 범위에서는 Blocking/High UX 혼선은 줄었습니다. 다만 실제 사용자 검증은 아직 아니며, 다음 큰 목표는 creator publish gate 또는 export regeneration/account persistence 중 하나로 잡는 것이 적절합니다.
