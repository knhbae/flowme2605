2026-06-29 · 서비스 UX 남은 작업 정리

사용자용 실행 화면과 creator gate 분리 기준선

목표는 홈, Flow 찾기, 공개 Flow 상세, 저장 후 내 Flow, 제작자 gate가 서로 섞이지 않도록 현재 제품 라우트 기준선을 고정하는 것입니다. 이 문서는 검토/인수인계용이며 사용자용 화면에는 노출하지 않습니다.

이번에 정리한 기준

사용자 IA

홈 / Flow 찾기 / 캘린더 / 내 Flow

홈은 입구와 메뉴 트리, Flow 찾기는 저장할 콘텐츠 카탈로그, 캘린더는 날짜 실행 표면, 내 Flow는 저장한 Flow 관리로 둡니다.

사용자 문구

내부 모델 숨김

사용자 화면은 큰 흐름, 항목, 일정, 체크, 전체 저장 중심으로 말합니다.

제작자 gate

Source row → Step/Item

제작자 화면에서는 변환 계약을 보여주되, 사용자 실행 화면과 섞지 않습니다.

현재 라우트별 판정

라우트 역할 현재 기준
/ 서비스 입구 대표 시작점과 메뉴 트리만 노출합니다. 전체 카탈로그나 검토 후보 목록으로 만들지 않습니다.
/flows 저장할 Flow 탐색 이사, 중1 수학, 전세 같은 대표 후보 중심입니다. 약한 후보는 Park/Legacy로 분리합니다.
/flow-maps/[map] 공개 저장 전 화면 원문, 입력값, 저장 결과를 예측할 수 있게 하되 내부 평가 문구를 넣지 않습니다.
/calendar 일정 실행 화면 저장된 날짜형 항목을 월간 캘린더에서 바로 확인합니다. 일정이 없어도 빈 캘린더를 보여주고 내부 view 탭은 숨겨 중복을 줄입니다.
/my 저장 후 실행 공간 저장 직후 첫 항목과 전체 Flow 보기로 나눕니다. 날짜가 있는 항목은 글로벌 캘린더 탭에서 확인하므로 내 Flow 안에는 캘린더 보기 CTA를 반복하지 않습니다.
/flow-maps/[map]/creator 제작자 검토 원문 행이 사용자 Step/Item으로 바뀌는지 확인합니다. 저장 후 화면 링크는 해당 map의 My Flow preview로 연결합니다.

메뉴 트리

홈

서비스 입구

무엇을 하는 서비스인지 보여주고, 사용자가 Flow 찾기·캘린더·내 Flow·만들기로 갈 수 있게 합니다.

Flow 찾기

저장할 콘텐츠 선택

대표 Flow와 Flow Map을 보고 저장합니다. 홈과 달리 카탈로그 성격을 갖습니다.

캘린더

날짜가 있는 Step 실행

저장한 일정이 있으면 월간 캘린더에 배치하고, 없으면 빈 캘린더로 상태를 보여줍니다.

내 Flow

저장한 Flow 관리

오늘 할 일과 Flow별 보관 상태를 보고, 항목은 누른 자리에서 열고 닫습니다.

대표 후보와 보류 후보

대표 노출

이사 D-30, 중1 수학, 전세 Flow를 기준 후보로 봅니다. 저장 이유와 산출물이 비교적 명확합니다.

Revise / Park

영유아 검진/접종은 공식 표 기반 구조는 있으나 대표 노출 전 정보 밀도와 의료 민감도 문구를 더 봐야 합니다. 추가 5개 실험 후보는 카탈로그 대표로 올리지 않습니다.

남은 일

  • 홈 히어로에서 버튼처럼 보이던 비클릭 칩은 제거했습니다. 실제 이동은 대표 카드, 메뉴 트리, 하단 4탭으로만 처리합니다.
  • 실제 사용자 행동 데이터 없이 검증 완료라고 표현하지 않습니다.
  • 계정 기반 creator publish, 승인, 버전 배포는 아직 local draft/publish marker 밖에 없습니다.
  • 저장된 Step의 캘린더/할 일/시트 재생성은 더 강한 데이터 계약으로 다음 단계에서 다룹니다.
  • 홈에 리뷰, 사용 수, creator 신뢰 신호를 붙일지는 대표 콘텐츠 품질이 더 올라간 뒤 결정합니다.
