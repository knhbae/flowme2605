Flow of Flow v2 · 시뮬레이션

v1의 묶음형 실패를 반복하지 않기 위해 두 번의 점검 루프를 돌렸다

이 리포트는 내부 시뮬레이션이다. 실제 사용자 행동 데이터가 아니며, 제품 성과나 시장 반응을 확정하지 않는다.

v1 실패 원인 반영 Blocking 수정 완료 육아는 보수적 후보 브라우저 검증 예정

산출물

후보 재심사 리포트 Flow of Flow v2 변환 모델 사용자용 클릭 화면 제작자용 클릭 화면

사용자 시뮬레이션 A

중1 학부모가 수학방의 중1 전체 목차를 보고 FlowMe에서 중1 수학 전체 진도표를 연다.

원문 소비8개 큰 단원과 단원별 개념 링크를 확인한다.
전체 저장공부 시작일, 공부 요일, 하루 목표 개념 수를 넣고 전체 일정을 만든다.
일부 저장시험범위가 1~3단원이므로 소인수분해, 정수와 유리수, 문자와 식만 먼저 저장한다.
실행소인수분해에서 개념 링크, 대표 문제, 오답표, 복습일을 같은 화면에서 처리한다.
재방문며칠 뒤 정수와 유리수의 다음 할 일과 남은 오답을 먼저 본다.

제작자 시뮬레이션 A

수학 콘텐츠 제작자가 단원 목차를 가져와 전체 진도표를 만든다.

원문 구조단원/소단원을 반복 단위로 선택한다.
패턴 정의개념 보기, 문제 풀기, 오답 남기기, 복습 잡기 패턴을 만든다.
사용자 결과각 단원이 같은 실행 패턴을 가진 저장 결과로 보이는지 확인한다.
확장중2 또는 심화 단원을 같은 패턴으로 추가할 수 있음을 확인한다.

루프 1에서 발견한 문제

Blocking · 후보 판정이 여전히 너무 관대할 위험

러닝 재생목록, 이유식 식단표처럼 Flow로는 가능한 콘텐츠를 다시 Strong으로 올릴 수 있었다.

High · 사용자 화면이 탭형 묶음처럼 보일 위험

단순 탭 전환 UI로 만들면 큰 지도 안의 현재 위치와 다음 실행 항목이 드러나지 않는다.

High · 제작자 화면이 입력 폼처럼 보일 위험

제목, URL, 섹션만 편집하면 제작자가 자기 콘텐츠를 실행형 지도화한다는 감각이 약하다.

수정 반영

수정 1 · 후보 판정 체계 강화

Strong Flow of Flow, Flow map only, Single Flow only, Reference/Park로 나눴고 이사를 대표 PoC에서 제외했다.

수정 2 · 사용자 화면의 첫 화면 재구성

상단에 전체 지도, 현재 위치, 진행률, 전체/부분 저장 버튼을 두고 하위 단위 상세를 바로 이어 붙였다.

수정 3 · 제작자 화면의 흐름 재구성

원문 구조, 반복 단위, 실행 패턴, 사용자 저장 결과를 한 화면의 좌-중-우 흐름으로 배치했다.

루프 2 결과

중1 수학큰 단원들이 하위 실행 단위로 반복되어 가장 설득력 있는 대표 케이스로 남았다.
정보처리기사자격증 전체 로드맵이 아니라 과목별 진도판으로 좁히니 반복 구조가 보였다.
육아월령별 반복 가능성은 있으나 공식 정보/생활 메모/상담 경계가 무거워 후보 수준으로 둔다.
이사D-day timeline 단일 Flow로 충분하므로 이번 대표에서는 제외했다.

남은 리스크

원문 자동 추출 없음이번 HTML은 수동 구조화 샘플이다. URL에서 자동으로 단원/과목/월령을 가져오지는 않는다.
실제 사용자 행동 없음저장, 체크, 재방문이 실제로 일어났다는 데이터는 없다.
육아 민감도월령별 생활 지도는 의료 판단을 하지 않도록 더 강한 공식/경험 분리가 필요하다.
학습 패턴 세부화오답표, 복습일, 기출 회차의 실제 export 형식은 다음 구현 단계에서 더 구체화해야 한다.

판정

v2는 “Flow 여러 개 묶음”에서 한 단계 나아가, 상위 구조가 반복 단위를 만들고 같은 실행 패턴을 붙이는 방향으로 정리됐다. 메인 대표는 중1 수학 전체 진도표다. 정보처리기사는 과목별 공부 운영판으로 좁힐 때 설득력이 있다. 육아와 이사는 다음 라운드에서 별도 기준으로 다시 보는 편이 안전하다.
