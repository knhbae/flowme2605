FLOWME PRODUCT DECISION · 2026.07.30

공개본은 보호하고,
실행은 내 사본에서

FlowMe가 만들 것은 또 하나의 편집기가 아니다. 누구나 일반 텍스트로 Flow를 시작하되, 공개 기준본은 제안·검토·버전으로 보호한다. 사용자는 복사한 실행본에서 날짜·항목·메모를 바꾸고 익숙한 도구로 옮긴다.

ONE PRODUCT RULE 작성은 Wiki처럼 쉽게, 공개는 GitHub처럼 통제하고, 실행은 개인 사본에서 자유롭게

공개 기준본·개인 실행본·변경 제안을 같은 편집 상태로 섞지 않는다. Calendar·Todo·Sheet·Memo는 개인 실행본에서 파생되는 산출물이며 기준본으로 자동 돌아가지 않는다.

지금 승인할 제품 방향

  • 일반 텍스트 → 구조화 draft로 쉽게 시작
  • 공개본 직접 편집 대신 proposal → review
  • 날짜·항목·메모는 사용자 소유 개인본에서 변경
  • 업데이트는 새 version 비교 후 선택 적용
  • 실시간 공동편집·양방향 sync·전문 앱 복제는 보류
01 · Product decision

FlowMe의 핵심은 편집기가 아니라

04 · Build decision

지금 만들 것은
복사·제안·검토다

기준본·개인본 분리와 proposal·review는 제품 계약으로 유지한다. 실시간 공동편집·양방향 sync·marketplace는 사용 가치가 검증될 때까지 미룬다.

유지 STRATEGY CONTRACT

  • 기준본·개인본·run·projection 분리
  • 새 version의 silent overwrite 금지
  • 공용 변경 proposal + review
  • 콘텐츠별 편집 policy
  • 원작자·원문 귀속

검증 BEFORE IMPLEMENTATION

  • 1분 micro-contribution
  • 기준본·내 실행본 이해
  • 새 version 선택 적용 UX
  • maintainer 검토 비용
  • reimport+diff 실제 수요

보류 REVISIT TRIGGER

  • 제작자 직접 발행
  • OAuth·양방향 sync
  • 실시간 공동 편집
  • marketplace·평판·랭킹

미적용 DO NOT BUILD

  • 익명 canonical 직접 편집
  • 개인 기록 자동 공개
  • 좋아요 기반 자동 병합
  • 외부 silent write-back
  • 전문 vertical engine 복제

08 · State safety

상태를 분리해야 업데이트가
개인 기록을 덮어쓰지 않는다

기존 canonical 계약을 유지한다. 이번 세션의 새 가설은 공용 변경 proposal과 외부 detached projection이다. 승인된 canonical spec은 migration 계약이며 현재 runtime 구현 완료를 뜻하지 않는다.

Published version

제작자·유지관리자 검토 후 만들어지는 불변 기준본

  • source·canonical Item
  • default schedule
  • caution·rights·freshness

UserFlowCopy

사용자가 소유하는 비공개 개인 실행본

  • 포함·개인 제목
  • 일정·주기·설정값
  • 개인 메모

ExecutionRun

콘텐츠 update가 바꿀 수 없는 개인 실행 이력

  • 완료·skip·hold
  • decision·record
  • run memo

Change proposal

선택한 공용 개선과 근거만 담는 변경안

  • source correction
  • 누락 Item·canonical 문구
  • 개인 기록 제외

Occurrence

반복 Flow의 한 회차에만 적용되는 상태

  • 회차 완료
  • 회차 시간 변경
  • series 자동 변경 금지

External projection

Calendar·Todo·Sheet·Memo에 만들어진 개인 산출물

  • canonical 아님
  • 외부 수정 허용
  • silent write-back 금지

충돌 처리의 최소 계약

같은 field를 양쪽에서 변경field-level three-way review: 새 내용 적용 / 내 설정 유지 / 일부 적용
새 Item 추가포함 / 제외 / 나중에 검토 중 선택한다.
개인 상태가 있는 Item 삭제orphan으로 보존하고 명시적 확인 전 이력을 지우지 않는다.
source·risk·caution 변경자동 적용하지 않고 필수 검토와 원문 열기를 제공한다.
한 회차 시간 변경해당 occurrence에만 적용하고 series 변경은 별도 action으로 둔다.
외부 산출물 수정독립 사본으로 유지한다. 추후 수요가 확인되면 reimport+diff를 검토한다.
09 · Remaining gaps

여섯 장면 중 작성과 외부 편집은
아직 화면이 비어 있다

기능 목록보다 실제 사용자 장면에서 기준본·개인본·proposal·외부 산출물의 경계가 유지되는지 확인한다.

S01

일반 텍스트에서 작은 수정

제작자가 구조화 preview에서 Item 한 개와 출처 한 개만 고친다.

  • draft는 public 아님
  • source review 전 published 금지
S02

D-day 개인본 만들기

공개 Flow를 복제하고 기준일·포함 Item을 자기 상황에 맞게 바꾼다.

  • 날짜 diff preview
  • Calendar·Checklist가 같은 effective state 사용
S03

공식 정보 한 건 정정

오래된 공식 링크와 caution을 근거와 함께 제안한다.

  • canonical 즉시 변경 금지
  • 개인 실행 기록 payload 제외
S04

새 version 선택 적용

추가·변경·삭제를 검토하면서 내 진도·메모·일정을 보존한다.

  • 전체 / 유지 / 일부 적용
  • removed Item 상태 보존
S05

외부 Calendar에서 한 회차 이동

외부 수정은 occurrence 사본에 남고 FlowMe의 series를 자동 변경하지 않는다.

  • 자동 sync 오해 방지
  • series 변경은 별도 action
S06

레시피 개인화 후 개선 제안

인분·대체재는 개인화하고 공용 가치가 있는 개선 한 건만 제안한다.

  • 원 레시피·제작자 유지
  • 개인 메모·전체 변형은 비공개
