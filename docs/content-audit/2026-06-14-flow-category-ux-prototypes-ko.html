사용자 관점 시뮬레이션

  1. 콘텐츠 소비유튜브, 네이버 블로그, 공식 안내, 커뮤니티 글에서 “나중에 따라 해야겠다”는 실행 단서를 발견합니다.
  2. 저장 판단요약을 읽는 것이 아니라 캘린더, 체크리스트, 루틴, 시트 중 어디에 넣으면 다시 실행할 수 있을지 판단합니다.
  3. Flow 변환기준일, 반복 요일, 대상 이름처럼 0-3개만 입력하고 원문 링크와 긴 설명은 detail/URL로 보냅니다.
  4. 첫 실행저장 직후에는 오늘 할 일, 첫 체크, 원문 열기, 보류 판단 같은 한 가지 action이 보여야 합니다.
  5. 시간 경과D-day, 다음 반복일, 마지막 확인일, 현재 단계, 남은 목록처럼 시간이 지난 뒤 다시 열 이유가 생겨야 합니다.
  6. 재방문사용자는 원문을 다시 검색하지 않고 Flow에서 다음 action, 이전 체크, 보류 사유, 원문 링크를 확인합니다.

UX 디자이너 피드백

  1. 부족했던 점기존 prototype은 저장 후 첫 화면은 보였지만, 사용자가 콘텐츠를 본 직후 FlowMe로 가져오는 동기와 시간 경과 후 재사용이 약했습니다.
  2. 핵심 보강각 Flow는 1회성 task가 아니라 reminder, progress, state, history 중 하나를 남겨야 합니다.
  3. 주의할 점시간축을 넣는다고 모든 카테고리에 캘린더를 붙이면 안 됩니다. 버킷형은 나중에 배치, 기록형은 마지막/다음 확인, 시트형은 장보기 전 재방문이 시간축입니다.
  4. 판단 기준사용자가 3일 뒤, 다음 주, 다음 달에 다시 열었을 때 “왜 이 Flow가 남아 있는지”가 보여야 합니다.

공통 UI와 별도 UI

구분 공통으로 묶을 수 있는 것 카테고리별로 달라져야 하는 것
입력 0-3개 입력, 기본값, 선택 입력 분리 날짜형은 기준일, 루틴형은 반복 주기, 시트형은 빠른 추가
실행 오늘 카드, 첫 action, 완료 기준 체크 판단형은 진행/보류, 상태 기록형은 상태칩이 먼저
저장 후 사용 calendar/checklist/routine/bucket/record/memo chip 버킷형은 날짜 없음 저장, 단계형은 현재 단계 유지
출처/상세 detail/URL/memo로 분리 민감 영역은 공식 정보, 경험담, caution을 더 강하게 분리

판단 결과와 다음 구현 순서

1. 먼저 구현

이사 D-30. 전세계약 UX를 거의 그대로 재사용하므로 날짜형 공통 템플릿을 확정하기 좋습니다.

2. 바로 다음

중고차 방문 체크. 캘린더보다 진행/보류 판단이 중요한 체크리스트형의 차이를 검증합니다.

3. 확장 확인

홈트 또는 식물. 반복 루틴형과 상태 기록형이 긴 기록 없이도 충분한지 확인합니다.

이 문서는 실제 사용자 행동으로 검증된 결과가 아니라 UX prototype draft입니다. 원문 링크와 출처는 각 Flow의 detail/URL 위치를 보여주기 위한 검토용이며, 공식 판단이나 보증으로 표현하지 않습니다.
