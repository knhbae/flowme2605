FlowMe IA A/B 비교 리포트

이번 비교의 목적은 캘린더를 글로벌 탭으로 승격했을 때 저장 후 실행 흐름과 저장한 Flow 관리가 더 명확해지는지 확인하는 것입니다.

사용자 PoC /ia-compare/b는 사용자 화면처럼 구성하고, 이 문서는 검토/평가용으로 분리합니다.

비교안

안탭 구조강점리스크
A안 홈 / Flow 찾기 / 내 Flow 현재 구현과 가깝고 전역 탭 수가 적습니다. 내 Flow 안에서 오늘, 캘린더, Flow 목록이 섞여 실행과 보관의 경계가 흐립니다.
B안 홈 / Flow 찾기 / 캘린더 / 내 Flow 저장 후 실행은 캘린더, 저장한 구조 관리는 내 Flow로 분리됩니다. 모바일 4탭이 과해 보일 수 있고, 캘린더가 비어 있을 때 의미를 설명해야 합니다.

B안 PoC 설계

  • 홈: 서비스 약속과 대표 시작점만 보여줍니다. 전체 카탈로그가 되지 않게 합니다.
  • Flow 찾기: 저장 전 탐색과 상세 확인을 담당합니다. Flow Map/단일 Flow 용어는 뱃지 수준으로만 남깁니다.
  • 캘린더: 저장 후 날짜가 있는 Step의 실행 장소입니다. Step detail은 클릭한 자리에서 열립니다.
  • 내 Flow: 저장한 Flow와 Flow Map의 보관/관리 장소입니다. 실행은 캘린더로 보냅니다.

시뮬레이션 질문

저니확인할 것통과 기준
저장 직후 사용자가 캘린더로 이동했을 때 첫 Step을 바로 이해하는가? 별도 설명 없이 Step을 열고 메모할 수 있어야 합니다.
여러 Flow 저장 캘린더와 내 Flow의 역할이 분리되는가? 캘린더는 실행, 내 Flow는 보관/관리로 읽혀야 합니다.
Flow Map 구조 Flow Map/Flow/Step/Item 계층이 과하게 노출되지 않는가? 사용자는 용어보다 저장 결과와 다음 행동을 먼저 봐야 합니다.
홈과 탐색 홈이 Flow 찾기의 축소판처럼 보이지 않는가? 홈은 서비스 약속과 진입, Flow 찾기는 목록 탐색으로 역할이 갈려야 합니다.

현재 판단

B안은 사용자가 “저장한 뒤 어디서 실행하지?”라고 느끼는 문제를 더 직접적으로 풀 가능성이 큽니다. 다만 4탭이 실제 모바일에서 과하게 보이는지는 PoC 클릭 후 다시 평가해야 합니다.
