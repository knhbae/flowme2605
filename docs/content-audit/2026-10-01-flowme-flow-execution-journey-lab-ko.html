원본을 두고, 개인 사본에서 실행하기

조작 가능한 독립 HTML입니다. 제작 원문과 공개 선택 판본은 고정하고 개인 사본만 바꿉니다. 아래 연결·비교·저장은 단순화한 합성 모델이며 실제 앱, 계정, DB, 권한 검증과 연결되지 않습니다.

실험 관리 · 저장 실패와 연결 모의

보기·판본·사용자·연결 모의 선택은 저장하지 않습니다. 초기 예시는 native 제작 판본 1과 개인 문서가 이미 연결된 상황입니다. 공개 판본 가져오기는 별도 선택입니다.

이 파일은 한 키만 읽고 씁니다. 다른 FLOW 자료는 읽거나 삭제하지 않습니다. 초기화는 이 정확한 키만 삭제하며, 손상된 자료를 임의로 덮어쓰지 않습니다.

제작자 영역

이 예시는 명시 저장된 native 판본만 읽습니다. 제작 중 입력, 원본 편집, 자동 저장, 자동 인계는 구현하지 않습니다.

공개 영역

선택 판본을 읽거나 개인 사본으로 가져올 수 있습니다. 개인 완료·날짜·메모가 공개 원본으로 역전파되지 않습니다. 게시·기여 기능은 없습니다.

개인 영역

사본의 같은 항목을 문서·오늘·주간·월간에서 봅니다. 개인 실행과 되돌리기만 이 실험 키에 저장합니다. 독립 개인 사용을 제작·공개의 필수 단계로 만들지 않습니다.

  1. native 판본 1에서 ‘개인 문서 열기’를 누릅니다. 성공 저장 집계는 그대로여야 합니다.
  2. 한 항목의 내용·실행 날짜·메모를 고칩니다. ‘개인 변경 저장’ 후 오늘·주간·월간에서 같은 항목 ID를 확인합니다.
  3. 완료 → 다시 열기 → 되돌리기를 누릅니다. 원본·판본으로 돌아가 고정 원문을 확인합니다.
  4. 판본 2를 선택해 비교합니다. 기본은 모두 개인 값 유지입니다. 취소·Esc·모두 유지·동일 값은 저장하지 않습니다.
  5. 공개 판본을 선택하고 명시적으로 사본을 만듭니다. 공개의 완료 표시는 개인 완료로 가져오지 않습니다.
  6. 저장 오류 모의를 켠 뒤 개인 변경을 저장합니다. 입력은 남고 성공 저장은 늘지 않습니다. 모의를 끄고 다시 저장하거나 대기를 취소합니다.
  7. 저장본 다시 열기로 성공 저장·Undo 목록이 복원되는지 봅니다. 입력이 남았다면 폐기 확인을 거칩니다.
  8. 연결 없음·오래된 연결·다른 사용자·입력 잠금 모의에서 native 열기가 차단되는지 봅니다. 이것은 합성 가드이며 실제 권한 판정이 아닙니다.

일반 Enter/Space/Tab과 버튼으로 사용할 수 있습니다. 드래그가 필요하지 않습니다. 반응형 검토 기준은 375×812, 390×844, 844×390, 1024×768, 1440×900입니다. 이 기준은 검증 완료 표시가 아닙니다.

합성 모델에서는 두 항목과 두 판본만 다룹니다. 실제 제작 parser, writer, source/version/task identity 계약 전체, 계정 전환·동기화·저장 충돌 복구를 재현하지 않습니다. 화면·모델 QA와 실제 앱 QA, 실기기·IME·보조기술, 관찰 사용자 증거를 구분합니다.
