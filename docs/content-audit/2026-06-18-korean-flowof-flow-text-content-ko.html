한글 원문 우선

UI 전에 확정한 Flow of Flow 텍스트 컨텐츠

한글 원문을 중심으로 다시 골랐습니다. 각 후보는 원문 행이 실제로 있는지, 사용자가 체크할 대상이 자연스러운지, 필수 입력이 캘린더/투두 앱 수준을 넘지 않는지 기준으로 봤습니다.

원문 행 우선 상태/메모만 추가 필수 입력 최소화 건강 정보 판단 금지

이기적 컴활 1급 필기 Strong YES24 목차에 권/Part/Chapter가 명확함. 자격증 진도형에 적합. 시험일은 선택. 필수 입력으로 만들지 않음.

표준 예방접종 일정표 Care Strong 질병관리청 표준 일정표가 있음. 연령별 방문 확인 Flow로 가능. 아이 생일 1개만 필요. 접종 판단/권고는 원문과 의료기관으로 분리.

Content Model 1

생활코딩 WEB1

원문: 구름EDU WEB1, YouTube playlist

Source shape:
- 강좌/playlist → 수업 행.
- 예: WEB1 - 1. 수업소개, 2. How this project started, 3. Product Design, 4. Coding and HTML...

User job:
- WEB1을 어디까지 봤는지, 실습 파일이 어디 있는지 기억하고 싶다.

Natural artifact:
- 진도표 + 실습 메모.

Required input:
- 없음.

Parent Flow:
Title: WEB1 HTML & Internet
Rows:
- 수업소개
- How this project started
- Product Design
- Coding and HTML
- HTML 코딩과 실습환경 준비
- 기본문법 태그
- 줄바꿈
- HTML이 중요한 이유
- 최후의 문법 속성과 img
- 부모 자식과 목록
- 문서의 구조
- HTML 태그의 제왕
- 웹사이트 완성

Row fields:
[수업명] [상태] [실습 파일/막힌 지점 메모] [원문 URL]

Do not build:
- 하루 2강 같은 진행 페이스 입력.
- "원문 열기"를 체크리스트로 만들기.
- HTML 설명을 FlowMe가 다시 작성.

- 선택: GitHub/배포 URL.

Parent Flow:
Title: 바닐라 JS로 크롬 앱 만들기
Rows:
- #1 Introduction
- #2 Welcome to Javascript
- #3 Javascript on the Browser
- #4 Login
- #5 Clock
- #6 Quotes and Background
- #7 To Do List

Row fields:

- 없음.

UI 제작 기준

이 텍스트를 UI로 옮길 때 지킬 것

1. 진도형 UI
- 입력 없음.
- 상위에는 전체 진도와 다음 행.
- 하위에는 원문 행 목록.
- 각 행에는 체크, 상태, 짧은 메모, 원문 링크만.

2. 건강/육아 일정형 UI
- 입력은 아이 생일 1개.
- 상위에는 다음 기간과 전체 일정.
- 하위에는 공식 원문 확인, 예약 메모, 문진표 메모.
- 의료 판단은 하지 않음.

3. 공통
- 진행 페이스, 공부 요일, 반복 요일은 기본 입력으로 넣지 않음.
- 캘린더/투두앱 수준의 조작만 허용.
- 상세 설명은 URL/메모/detail로 내림.
- 사용자 화면에는 source fit, 평가, 리뷰 문구를 넣지 않음.
