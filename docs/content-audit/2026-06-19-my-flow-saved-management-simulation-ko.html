판정

현재 결론

0개시작 안내만 두고 관리 UI는 숨기는 방향이 맞음.
1개Flow 목록보다 실행 detail이 먼저 나와야 함. 중복 목록은 제거함.
2~5개오늘 할 일과 Flow별 이어보기를 함께 보여주는 수준이 적절함.
6개 이상검색/필터는 필요하지만 전체 목록은 기본 접힘이 낫다.
단일 Flow + Flow Map지도는 목록에서만 가볍게 드러내고, 상세는 현재 Step과 Item만 보여주는 방향이 맞음.
복잡도전세/10개 Flow 수준을 크게 넘지 않는 범위로 유지됨.

상황 사용자 행동 화면 반응 판정
0개 저장 처음 내 Flow에 들어온다. 관리 탭 대신 저장 안내와 예시 보기 버튼만 보인다. 시작 전 상태로 충분함.
1개 저장 전세계약 Flow를 저장하고 다음 날 다시 들어온다. 목록 없이 계약 전 서류 확인 detail이 바로 열린다. 목록보다 실행 우선 원칙에 맞음.
보류 확신 없는 항목을 나중에 보기로 둔다. 상태가 보류로 바뀌고 메모가 fallback 텍스트에 남는다. 보류 버튼의 결과가 예측 가능함.
완료 항목을 완료 처리한다. 체크 항목이 완료되고 외부 앱 텍스트도 [x]로 바뀐다. 완료 신호가 명확함.
4개 저장 중1 수학 학습 지도를 선택한다. 목록에는 지도 이름이 보이고, 상세에는 정수와 유리수 Flow의 현재 Step인 10강이 열린다. Flow Map 구조를 숨기되 뭉개지는 정도는 줄였음. 사용자는 현재 Step과 Item만 처리하면 됨.
8개 저장 여권을 검색한다. 전체 목록을 열고 여권 Flow만 좁혀 선택한다. 다수 저장 상태에서 검색/접힘이 필요함.

개선 루프

발견한 문제와 수정

등급 문제 수정
High 1개 저장 상태에서 목록과 실행 detail이 중복되어 보일 수 있었음. 1개 상태에서는 왼쪽 목록과 전체 Flow 버튼을 숨기고 detail만 보이게 수정.
Medium 8개 이상 상태에서 전체 목록을 기본으로 펼치면 관리 화면처럼 무거워질 수 있음. 8개 상태는 오늘/보류 우선, 전체 목록은 접힌 상태로 시작.
Low 자동 검증 중 한글 입력이 깨져 보일 수 있었음. 검증 스크립트에서 유니코드 입력으로 재확인. 화면 자체 문제는 아님.

  • Flow 선택, 체크, 메모 입력, 보류, 완료, 검색, 접힘 동작 확인.
  • 가로 overflow 없음.
