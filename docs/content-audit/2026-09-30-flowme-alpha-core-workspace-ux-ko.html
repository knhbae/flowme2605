합성 조합 중 주변 5행 표시, 저장 0회 → 조합 종료 후 1회. 실제 휴대폰 IME·후보창 검사는 하지 않았습니다.

본문 폴더 연결
U05·U06

‘- 새 폴더’에서 폴더를 만들면 같은 이름이 두 줄로 남던 문제를 수정했습니다. 연결 가능한 선택 줄은 같은 ID로 변환하고 이름을 자동 채웁니다.

할 일·본문·자식이 있는 줄은 그대로 유지하고 아래 새 줄에 연결합니다. 패널에서 실제 변경 위치를 안내합니다.

날짜와 시간
U07

문서와 기간 상세 양쪽에서 기존 날짜·HH:MM 시간을 지정하거나 지울 수 있습니다. 날짜·시간 Undo에서도 기존 Item과 메모·폴더·진행 기록을 유지합니다.

새 시간대·반복·상대 일정 정책은 도입하지 않았습니다.

목록의 맥락
U04·U08·U09

기간 목록에 실제 Item의 폴더 경로·문서명·시간을 표시합니다. 접힌 모바일 폴더/검색 필터도 현재 범위가 보이며 ‘필터 해제’는 조회 날짜를 유지합니다.

문서의 보관 위치와 Item 소속을 같은 값으로 바꾸지 않습니다. 날짜 정렬은 유지합니다.

작성 화면의 계층
U01·U06

계정·판본·로그아웃·서버 관리·백업은 ‘계정 · 자료 관리’에 모았습니다. 저장 상태와 되돌리기는 밖에 둡니다.

공개 범위·유일본 주의, 오류·충돌·입력 보관·닫힌 백업의 재진입은 숨기지 않았습니다. 새 백업 경로는 off 상태입니다.

확정 거절 뒤 재저장
U14

저장을 확실히 거절한 응답을 실제 충돌로 표시하던 문제와, 주기적 서버 확인 뒤 재저장이 막히던 문제를 수정했습니다.

같은 세션의 개인 변경·invalid/limit 거절·결과 대기 없음·기존 판본 일치만 허용합니다. 서버 상태가 변했거나 인증/읽기가 실패하면 차단합니다. 응답 유실·새로고침 초안·다른 계정은 이 예외에 포함하지 않습니다.

같은 자료로 실제 조작한 흐름

  1. 빈 개인공간에서 문서를 만들고 예시를 펼쳐 확인했습니다. 본문 폴더와 날짜 있는 할 일·날짜 없는 할 일·메모를 작성했습니다.
  2. 날짜·시간을 저장하고 오늘에서 완료했습니다. 주간·월간에서도 같은 Item의 완료 상태를 확인한 뒤 Enter 키로 다시 열었습니다.
  3. 날짜를 옮기고 시간을 지운 뒤 Undo로 날짜·시간·같은 행 ID를 복원했습니다. 취소와 같은 위치에서는 mutation 증가가 0이었습니다.
  4. 모바일에서 접힌 폴더·검색 범위를 확인하고 필터를 해제했습니다. 목록과 폴더/문서 맥락이 돌아왔고 조회 날짜는 유지됐습니다.
  5. 확정 거절에서 저장본 불변·입력 보존을 확인했습니다. 주기적 읽기 뒤 수정 저장과 직접 재저장 버튼을 검사하고, 새로고침 후 성공한 원문을 확인했습니다.

인증과 저장 서버는 합성 응답입니다. 실제 React 화면·편집기·모델·명령을 조작했지만 Supabase/Auth/RLS 또는 실제 개인 계정의 저장을 재검증한 결과는 아닙니다.

남은 문제와 다음 순서

전체 UX 완료는 아닙니다. 응답 유실 요청을 같은 ID로 확인해 서버 저장에는 성공해도, 열린 편집기에 미저장/충돌 안내가 남는 경우를 추가로 발견했습니다. 입력은 보존됐지만 성공 상태 반영은 후속 개선이 필요합니다.

또 Tab과 Shift+Tab을 연속 사용하면 중간 구조 재분류로 뒤 형제가 함께 움직일 수 있습니다. 두 키를 Undo의 대용으로 간주하지 않았고, 이번에는 native Undo의 원문 복구만 확인했습니다. 문법·구조 의미 변경은 별도 설계가 필요합니다.

  1. 저장 결과의 화면 반영: 응답 유실 후 내 명령의 성공을 정확히 확인한 경우에만 편집기의 저장 기준을 갱신합니다. 다른 입력·조합·계정·실제 충돌은 보호합니다.
  2. 세로 밀도·구조 이동: 모바일 오늘의 첫 항목 접근을 줄이고, 들여쓰기/내어쓰기·Undo의 구분을 설계합니다. 필요하면 UX 세션에 판단을 요청합니다.
  3. 개발계 반영: 검증된 개선을 반영하려면 기존 서버를 교체하는 별도 승인이 필요합니다. 이 보고서나 합성 화면을 열어 보는 것만으로 개발계가 바뀌지는 않습니다.

원래 6~9와 5D 후속은 기존 원장에 남아 있습니다. 일정·Flow/Map 편집·공개 자격/부분 채택·기기/접근성/폴더 정책을 이번 목표로 한꺼번에 완료 처리하지 않았습니다.
