저장 소유권
Executive decision

텍스트를 먼저 쓰고, 구조는 결과 옆에서 고친다

Markdown-first를 강제하지 않고 block editor를 제품 전체로 확장하지 않는다. 기존 3열 workbench의 관계는 보존하되 1024에서는 2열, 390에서는 단계형으로 줄인다.

판정: heuristic simulation + current source + frozen fixtures. 실제 관찰 사용자 수 0.

adopt_hybrid_text_preview 일반 텍스트와 Markdown은 입력·반출 형식, outline은 잘못 묶인 부분의 보정 도구, inspector는 날짜·반복 같은 복잡한 값에만 사용한다.

A/B/C 비교

A

Markdown-first

원문 소유감과 round-trip은 강하다. metadata 문법이 늘면 FlowMe 전용 언어가 된다.

  • 보조 원문 보기
  • Markdown export
  • 기본 UI로는 미채택
B

Block / outline

합치기·나누기·재정렬에는 가장 정확하다. 전체 편집기로 쓰면 mobile과 범위가 무거워진다.

  • 구조 오류 보정
  • 선택 Item만 편집
  • 범용 workspace 금지
C · 권장

Text + preview

문법 없이 첫 결과를 보고, 불명확한 줄과 필요한 개인 값만 보정한다.

  • 첫 preview 0~2 입력
  • source lineage 유지
  • 모바일 단계형
