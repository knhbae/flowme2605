193개 예시 이동 목적지를 깊이별로 실제 적용한 전수 검사는 신규 모델 검사에 포함된다. 별도의 사용자 관찰 수로 합산하지 않는다.

검사 범위는 부모·깊이 변경, 하위 항목의 독립 전환과 재중첩, 같은 ID·날짜·메모·시간·진행 기록·참조 유지, 순환 거부, 직접 터치 드래그·탭·키보드, Undo/Redo·저장 실패·다중 탭 충돌·재열기다. 기존 항목 아래 Picker 연결과 이동 후 TXT/JSON 보관도 검사했다.

화면은 375/390px 모바일과 1194×834 가로·834×1194 세로 태블릿에서 확인했다. Chromium/CDP 터치와 합성 IME 검사이며 실제 OS 입력기를 사용한 검사는 아니다. 실행 오류와 콘솔 오류는 최종 시나리오에서 없었고 단일 HTML의 HTTP 자산 요청도 0건이다.

## 검사 중 수정한 경계

- 참조 직속 속성이 해석 없이 남던 회귀는 기존처럼 거부한다. 참조 아래 일반 하위 체크는 허용한다.
- 속성 줄의 Tab/내어쓰기로 날짜·메모·시간이 주인을 잃으면 원문을 유지한다.
- 빈 하위 입력칸에는 기존 항목을 연결할 수 있지만, 이미 적힌 하위 내용을 덮어쓰지 않는다.
- 제목을 잠시 비웠다 다시 쓰는 동안 기존 항목의 정체성이 사라지거나, 코드 구획 안으로 넣으며 역할이 조용히 사라지는 경우를 보호한다.
- 이전 성공 알림이 새 이동 중에 남지 않도록 정리하고, 목적지 설명은 새 부모 이름을 먼저 보여준다.

초도에서 발견한 결함과 수정 근거는 [UX 검토](./ux-review.md)에 남겼다. 중간 원시 결과 14개는 보관 범위를 줄이기 위해 제외했고, 위 통과 수치는 수정 후 동결한 실행 소스의 최종 결과만 집계했다.

## 남은 확인과 범위

375px에서는 긴 목적지 설명의 뒷부분이 잘릴 수 있다. 깊이와 새 부모를 먼저 표시하고 전체 설명은 접근성 이름에 남겼지만 실제 스크린리더는 미검증이다. 매우 깊은 원문과 1,200행 긴 문서의 입력 성능 개선은 이번 완료 범위가 아니다. [UX 검토](./ux-review.md)

실기기 0대, 관찰 사용자 0명. Android/iOS 손가락 조작감·OS 키보드·스크린리더는 별도 확인이 필요하다. 다른 문서로 직접 드래그, 실제 폴더 트리 재편, 공개 원본 수정, JSON 자동 가져오기, 제품 통합은 추가하지 않았다.

문서 본문 이동은 실제 소속과 일정을 유지한다. 이전 v10 저장 키를 읽거나 자동 이전하지 않는다. 독립 키는 flowme:ux-review:text-workspace-v11:20260908이다.

## 재검사와 공개 상태

v11 폴더에서 `node verify-all.cjs`를 실행하면 임시 서버, 브라우저 runner 5개, 단일 HTML 묶음, 모델·최종 해시 검사를 순서대로 수행한다. 18개 조절/TXT runner도 `browser-v11.cjs`로 정리했다. v10 폴더는 재검사의 필수 조건이 아니다.

`npm.cmd run docs:check`와 저장소 closeout 점검을 실행했다. closeout 도구는 전체 dirty worktree를 함께 보고하므로, 커밋 후보는 이 v11 폴더와 v11 명세 폴더로 다시 한정했다. 제품 전체 test/build/e2e는 실행하지 않았다.

이번 범위는 독립 시안과 검증 근거의 보관 커밋까지다. 제품 통합·push·PR·merge·deploy는 하지 않았다. 최초 검사에 사용한 공유 서버는 건드리지 않았고, 보관 패키지의 전체 재검사는 임시 포트 서버를 자동으로 열고 닫는다. Figma 미사용(Code-only).
