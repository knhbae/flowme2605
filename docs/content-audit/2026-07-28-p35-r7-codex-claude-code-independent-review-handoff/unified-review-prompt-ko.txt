3. 제품 방향
======================================================================

FlowMe는 무거운 planner가 아니라 portable execution layer다.

외부 URL 또는 개인 메모
→ 실제 결과 미리보기
→ 필요한 값만 최소 조정
→ FlowMe에 저장하거나 익숙한 도구로 가져가기
→ 실행·완료·다시 열기
→ 수정·기록·재사용

현재 P35 방향:
- 전역 진입은 Flow 찾기 / 캘린더 / 내 Flow 3개
- public Flow는 긴 설명보다 실제 결과 우선
- 저장 전 조정은 한 번에 한 종류
- My Flow는 library와 선택한 개인 Flow workspace 분리
- Calendar는 날짜가 있는 여러 Flow의 cross-Flow lens
- export는 범위 → 개수 → 형식 → 결과
- Calendar, Checklist, Routine, Sheet, Memo는 콘텐츠별 자연스러운 projection

아래 데이터 계약은 기본적으로 유지한다.
- source / published Flow
- personal structural/value overlay
- execution run
- recurrence series / occurrence
- whole / selected / current export identity
- 기존 localStorage schema

UI 문제를 해결하기 위해 별도 임시 identity, count, 저장 경로를 만들지 않는다.

======================================================================
4. 검토 목표
======================================================================

자동 테스트가 통과했는지를 다시 요약하는 것이 목적이 아니다.

다음을 독립적으로 판단한다.

1. P35가 실제로 더 쉽고 직관적인가.
2. 설명을 읽지 않아도 첫 행동과 저장 결과를 이해할 수 있는가.
3. public preview와 저장 후 workspace가 같은 Flow의 연속된 상태처럼 보이는가.
4. 다섯 형태가 서로 다른 콘텐츠 특성을 살리면서 같은 서비스 문법을 쓰는가.
5. My Flow가 1개와 60개 Flow 모두에서 실서비스 수준인가.
6. 현재 구성을 유지할지, 제한적으로 고칠지, 구조를 다시 열지.

전체 verdict는 다음 중 하나로 선택한다.
- retain
- bounded_revision
- structural_reopen
- block_publish

5. Owner feedback 질문
======================================================================

F01. public preview와 저장 후 날짜 묶음의 UI가 너무 다른가?
같은 row anatomy를 사용하고 checkbox를 오른쪽에 두는 대안을 비교해라.

F02. 저장 완료 후 바로 Today 같은 중간 화면이 필요한가?
저장한 전체 결과와 가장 가까운 실행 묶음을 한 workspace에서 보여주는 대안과
비교해라.

F03. Calendar형 Flow의 다음 할 일은 같은 날짜 항목을 한 번에 묶어 보여줘야 하는가?
완료 후 다음 날짜 묶음으로 넘어가는 규칙까지 검토해라.

F04. Flow 조정에서 제목, 상세, 날짜를 수정하는 현재 bounded edit가 충분한가?
저장 전 full editor가 정말 필요한지 구분해라.

F05. public preview에서 자연스러운 artifact와 외부 export를 함께 예측·실행할 수
있어야 하는가?
고정 5탭을 만들지 말고 primary 1개, secondary 최대 2개 원칙을 유지해라.

F06. 되돌리기는 완료 후 항목이 현재 화면에서 사라질 때만 보여주는 것이 나은가?
항목이 남으면 checkbox의 다시 열기로 충분한지 비교해라.

F07. shape-aware 첫 실행 단위의 정체성이 여전히 모호한가?
Calendar 날짜 묶음, Checklist 다음 항목, Routine 현재 회차, Sheet 현재/다음 행,
Memo 실행 단위 없음이 설명 없이 이해되는지 검토해라.

F08. 기록 영역이 완료 history, 단계 메모, 회고, 보류를 섞고 있는가?
없으면 숨기고 필요하면 별도 문법으로 분리하는 대안을 제안해라.

F09. 60개 Flow에서 찾기, 열기, 돌아가기, export, 관리가 쉬운가?

F10. 기능은 존재하지만 설명 없이 찾기 어려운 hidden capability가 남았는가?

각 항목을 다음 중 하나로 판정한다.
- supported
- partly_supported
- rejected
- needs_observation

7. UX 평가 방식
======================================================================

각 화면에서 다음을 센다.
- 첫 viewport의 competing primary action
- 같은 대상에 대한 중복 control
- 반복되는 card/section
- 핵심 작업의 tap/click depth
- 긴 설명 블록
- unnamed visible interactive
- overflow와 fixed overlap

reference pattern은 공식 제품 자료를 우선한다.
- Todoist / Things: Today와 project, contextual item detail
- Google Calendar: month/day hierarchy, selected event detail
- Notion: database row와 page detail, progressive property editing
- Wanderlog: itinerary day grouping
- Strava / Nike Training: series, current session, history separation

화면을 복제하지 말고 adopt / adapt / reject로 판단한다.
