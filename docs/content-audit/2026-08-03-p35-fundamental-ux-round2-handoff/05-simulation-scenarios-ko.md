# 공통 시뮬레이션 시나리오

Codex는 실제 앱을 조작하고 코드를 확인합니다. Claude Design은 제공된 연속 캡처와 현재 상태 설명을 바탕으로 동일한 상태 전이를 검토합니다. 두 검토 모두 결과를 `O / △ / X / TBD`로 기록하고, 관찰과 추론을 구분합니다.

## 공통 기록 형식

```text
시나리오 ID:
관찰한 화면·코드·캡처:
현재 사용자가 보는 상태:
다음 행동을 어떻게 예측할지:
실제 결과:
판정: O / △ / X / TBD
근본 원인:
반증 가능한 가설:
대안 A / B / C:
권장안과 이유:
삭제할 요소:
유지할 요소와 이유:
데이터·호환성·접근성 위험:
사람이 결정할 질문:
확신도: 높음 / 중간 / 낮음
```

## S01. 첫 방문과 공개 상세 5초 이해

조건: 저장 데이터가 없는 390px 모바일에서 날짜형 Flow를 엽니다.

확인:

- 첫 5초 안에 무엇을 얻는 화면인지 설명 가능한가?
- 현재 결과가 예시인지, 저장된 개인 결과인지 알 수 있는가?
- 가장 중요한 다음 행동이 하나인가?
- 행별 `수정`, Flow 편집, 저장, 내보내기가 경쟁하지 않는가?
- `Flow`를 몰라도 클릭 뒤 결과를 예측할 수 있는가?

## S02. 기준일 상태 전이

조건: 이사 Flow에서 기준일을 미선택→선택→변경→삭제합니다.

확인:

- 입력값과 바로 아래 확인 문장이 같은 정보를 반복하는가?
- 미리보기 날짜가 실제로 바뀌었음을 한 곳에서 확인할 수 있는가?
- 날짜 없이 저장할 수 있는 선택이 자연스러운가?
- 잘못된 날짜, 과거 날짜, 긴 기간에서 오류와 복구가 분명한가?

## S03. 공개 Flow 편집

조건: 이름, 기준일, Item 포함 여부, 순서, Item 제목을 바꿉니다. 적용·취소·닫기·뒤로가기를 각각 수행합니다.

확인:

- 하나의 편집 세션으로 이해되는가?
- subtitle/설명처럼 필요한 필드가 누락되지 않는가?
- 적용 전에 현재와 조정 후 차이가 과도하게 반복되지 않는가?
- 취소했을 때 초안이 남지 않고 기존 화면 위치로 돌아오는가?
- 수정값이 모든 지원 미리보기에 동일하게 반영되는가?

## S04. 공개 상세의 결과 형식

조건: 날짜형, 체크리스트형, 메모형, 시트형, 반복 루틴, Flow Map을 비교합니다.

확인:

- 기본 결과 하나와 보조 결과의 관계가 분명한가?
- 캘린더·할 일·체크리스트·메모·시트가 실제로 만들 수 있는 경우에만 보이는가?
- 형식을 바꿔도 제목·Item 수·순서·날짜·사용자 수정이 일치하는가?
- 미리보기와 실제 내보내기를 혼동하지 않는가?
- Todo와 체크리스트를 나눌 사용자 가치가 있는가?

## S05. 저장과 영수증

조건: 공개 상세에서 개인 계획으로 저장합니다.

확인:

- CTA가 `완료`가 아니라 저장 결과를 말하는가?
- 저장 전과 저장 후 상태가 시각적으로 달라지는가?
- 방금 저장한 계획 상세로 바로 갈지, 짧은 영수증을 거칠지 비교합니다.
- 중복 저장, 이미 저장한 Flow, 저장 실패, 재시도의 결과가 안전한가?

## S06. 저장 전·후 내보내기 소유권

조건: 같은 Flow를 공개 상세와 `내 Flow`에서 각각 내보내려 합니다.

확인:

- 어느 화면이 실제 내보내기를 소유하는가?
- 저장 강제의 이득과 마찰은 무엇인가?
- 공개 미리보기와 저장 후 개인 수정본 중 어느 버전을 보내는지 알 수 있는가?
- 외부 권한 거절, 부분 성공, 중복 생성, 다시 보내기, 취소를 처리하는가?
- 무엇을 어디에 몇 개 만들었고 자동 동기화인지 단방향 복사인지 알려주는가?

## S07. `내 Flow` 0·1·5·20개

조건: 저장한 계획 수를 바꿔 첫 화면, 오늘 할 일, 저장한 계획, 방금 저장한 계획을 찾습니다.

확인:

- 기본 화면이 Today인지 library인지 이해되는가?
- Today가 원본 Flow와 다른 저장소처럼 보이지 않는가?
- 방금 저장 후와 일반 재방문에서 같은 기본값이 더 좋은지 비교합니다.
- 날짜 없는 계획, 완료·보관한 계획, 실행할 일이 없는 상태를 처리하는가?
- 상단 통계나 탭이 실제 다음 행동을 돕는가?

## S08. 저장된 Flow 전체 편집

조건: `Flow 관리 → Flow 편집`을 열어 이름·기준일·여러 Item을 수정합니다.

확인:

- 공개 editor와 같은 필드·순서·적용/취소 문법인가?
- 기존 내용 아래에 펼쳐져 보기와 편집 맥락이 섞이지 않는가?
- 긴 Flow에서 하단 행동을 찾을 수 있는가?
- 저장된 상태를 갱신하는 의미와 공개 초안 적용의 차이를 알 수 있는가?
- 뒤로가기·닫기·오류 시 기존 개인 상태가 보존되는가?

## S09. Item 상세와 완료

조건: Item을 열어 수정·메모·날짜·완료·완료 취소·단일 내보내기를 수행합니다.

확인:

- 파란 표면이 실제 상태 의미를 갖는가, 장식인가?
- `실행할 일` heading 없이도 무엇을 해야 하는지 명확한가?
- `수정`이 Item 수정임을 문맥으로 알 수 있는가?
- 메모와 일정이 한 Item 상세에 자연스럽게 속하는가?
- 실제 실행 완료에만 `완료`를 쓰는가?
- Flow 전체 내보내기와 Item 1개 내보내기가 과도하게 중복되지 않는가?

## S10. Flow Map

조건: `/flow-maps/middle-school-math-1`에서 전체·일부 선택, 편집 취소, 저장 보류, 재진입을 수행합니다.

확인:

- `내 조건 / 저장 결과 / 전체` 각각이 현재 결정에 필요한가?
- 필요 값은 주 행동 가까이에 한 번만 보이는가?
- 일반 `/f/*`의 editor와 같은 계약을 쓸 수 있는가?
- Flow Map을 별도 제품 구조로 유지해야 하는가, 일반 Flow로 흡수할 수 있는가?

## S11. 도움말·주의·접근성

조건: 일반 도움, 내보내기 결과, 건강·안전 주의가 있는 Flow를 비교합니다.

확인:

- 반복 설명은 먼저 삭제됐는가?
- 중요한 중단 조건은 도움말을 열지 않아도 보이는가?
- `?`와 `!`가 접근성 이름과 충분한 터치 영역을 갖는가?
- 키보드와 스크린리더로 열고 닫고 원래 초점으로 돌아갈 수 있는가?
- 모바일 뒤로가기가 dialog만 닫는가?
- 짧은 정보마다 modal을 강제해 흐름을 끊지 않는가?

## S12. 용어와 CTA

조건: `Flow`, `계획`, `실행 계획`, `저장한 계획` 라벨과 저장 CTA를 비교합니다.

확인:

- 사용자가 용어 정의가 아니라 클릭 후 결과를 설명할 수 있는가?
- `완료`가 편집 종료·저장·실행 완료 중 두 뜻 이상을 갖지 않는가?
- 콘텐츠마다 결과 이름은 달라도 CTA의 생명주기 역할은 같은가?
- 내부 모델명은 유지하면서 사용자 화면만 더 쉬운 말로 바꿀 수 있는가?

## S13. 극단값과 회귀

조건:

- Item 1개와 50개
- 매우 긴 한글 제목·메모·출처
- 날짜 있음과 없음 혼합
- 반복과 단발 혼합
- 일부 형식만 지원
- 저장된 사용자 수정 있음

확인:

- 390px에서 고정 하단 버튼이 내용을 가리지 않는가?
- 결과 형식 전환과 편집 후 Item 정체성이 유지되는가?
- 빈 상태·loading·오류·재시도·중복을 처리하는가?
- 이전 저장 데이터와 legacy Flow Map이 깨지지 않는가?

## Hard fail

- 저장 전·후 상태를 구분하지 못함
- 화면 미리보기와 실제 내보낸 결과가 다름
- 지원하지 않는 형식을 정상 결과처럼 제시함
- 중요한 주의를 아이콘을 열어야만 볼 수 있음
- 같은 편집·내보내기 행동이 여러 깊이에 반복됨
- 취소했는데 초안이 저장되거나 기존 상태가 손실됨
- `완료`가 저장과 실행 완료를 모두 뜻함
- 한 Item 수정이 Today·Flow 상세·결과 형식에서 서로 다르게 보임
