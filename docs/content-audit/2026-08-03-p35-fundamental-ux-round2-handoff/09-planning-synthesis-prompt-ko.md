## 역할과 목표

P35 사용자 피드백, Codex 로컬 시뮬레이션, Claude Design 2차 검토를 하나의 MVP 의사결정안으로 합쳐라. 이번 단계는 구현이 아니라 기획 합의다.

개별 UI 수정 목록부터 만들지 말고 다음 네 가지를 먼저 확정한다.

1. `내 Flow`의 역할과 첫 화면
2. 공개 상세→편집→저장→`내 Flow`→실행/내보내기의 상태 전이와 행동 소유권
3. 하나의 canonical 계획과 여러 결과 형식의 계약
4. 공개 초안과 저장된 계획의 공통 editor 계약

## 합치는 방법

### 1. 사실·제안·이견 분리

다음 표를 먼저 만든다.

| 쟁점 | 현재 사실 | 사용자 의도 | Codex 결론 | Claude 결론 | 공통점 | 이견 | 추가 확인 |
|---|---|---|---|---|---|---|---|

코드와 runtime 사실은 Codex 근거를 우선하되, 사용자가 실제 화면을 어떻게 이해하는지는 자동화로 확정하지 않는다. Claude의 시각 제안도 구현된 `After`로 부르지 않는다.

### 2. 네 가지 근본 결정

각 결정에 대해 반드시 아래를 작성한다.

- 선택한 안
- 해결하는 사용자 피드백 ID
- 기각한 안과 이유
- export-first·canonical data·MVP 원칙과의 관계
- 빈 상태·오류·뒤로가기·중복·legacy 예외
- 구현 전 owner 확인 필요 여부

### 3. 사용자 제안의 채택 수준

U01~U10 각각을 다음 중 하나로 판정한다.

- 채택
- 의도 채택·해결법 수정
- 일부 채택
- 기각
- 검증 필요

사용자 의견과 다른 결론은 숨기지 말고, 어떤 위험을 피하기 위해 해결법을 바꿨는지 쉬운 말로 적는다.

### 4. MVP 범위 감산

이번 구현 라운드에 필요한 것과 나중으로 미룰 것을 나눈다.

P0 후보:

- 공개 상세·저장·`내 Flow`·내보내기 책임 정리
- 저장 직후 진입 규칙
- `내 Flow` IA 기본 구조
- 공통 Flow/Item editor surface와 적용·취소 계약
- 지원 가능한 결과 형식 규칙과 미리보기/실제 전송 구분
- 중요한 주의 노출 규칙
- `완료` 등 생명주기 카피

P1 후보:

- Item 상세 시각 감산
- Flow Map 3칸 값별 삭제·통합
- 시작일 중복 제거
- `Flow` 용어 단계 조정
- 극단값·접근성 회귀

고급 필터·협업·양방향 동기화·AI 자동 재계획·복잡한 프로젝트 계층은 별도 결정 없이는 넣지 않는다.

## owner에게 물을 수 있는 질문

최대 3개만 남긴다. 우선순위 예시는 다음과 같다.

1. 저장 없는 빠른 내보내기를 완전히 없앨지, 일부 capability에 남길지
2. `내 Flow` 일반 진입의 기본을 Today와 저장한 계획 중 무엇으로 둘지
3. 사용자 화면에서 `Flow`를 `계획`으로 단계적으로 바꿀지

코드·현재 상태로 답할 수 있는 질문을 owner에게 넘기지 않는다.
