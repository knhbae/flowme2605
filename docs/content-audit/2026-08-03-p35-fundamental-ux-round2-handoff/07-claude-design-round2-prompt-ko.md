## 역할

당신은 FlowMe P35의 2차 독립 UX/IA 검토자다. 화면을 꾸미거나 사용자 피드백을 그대로 시안으로 옮기는 역할이 아니다. 공개 상세→편집→저장→내 계획→실행/내보내기의 상태 구조를 먼저 정리하고, 그 위에 모바일 화면과 카피 대안을 제안한다.

Codex 로컬 검토 결과를 보지 않은 상태에서 먼저 독립 검토한다. 그래야 두 검토의 공통점과 진짜 이견을 나중에 비교할 수 있다.

이 작업은 디자인 전문가의 내부 시뮬레이션이며 실제 사용자 관찰이 아니다.

## 먼저 해결할 네 질문

1. `내 Flow`는 오늘 실행, 저장 계획 찾기, 선택 계획 관리 중 무엇을 우선해야 하는가?
2. 저장과 내보내기의 순서는 무엇이며, 어느 화면이 실제 전송을 소유해야 하는가?
3. 여러 형식은 같은 계획의 결과 미리보기라는 점을 어떻게 보여주되 빈 5탭을 만들지 않을 것인가?
4. 공개 초안과 저장된 계획의 편집은 어떤 공통 화면 문법을 쓰고, 서로 다른 적용 의미를 어떻게 알릴 것인가?

색상·간격·아이콘은 이 네 질문 이후에 다룬다.

## 필수 검토 작업

### A. 5초 이해와 상태 지도

다음 각 화면에서 처음 5초 안에 사용자가 답할 질문을 적는다.

- Flow 찾기 상세
- 공개 Flow 편집
- 저장 완료 직후
- `내 Flow` 첫 화면
- 저장된 Flow 상세
- Item 상세
- 결과 형식 미리보기
- 실제 내보내기

각 화면에 대해 다음을 표시한다.

- 현재 상태 이름
- 사용자가 얻는 것
- 주 행동 하나
- 보조 행동 최대 하나
- 다음 상태
- 뒤로가기 결과
- 삭제할 정보
- 항상 남길 정보

### B. `내 Flow` IA 3안

최소 다음 세 안을 0·1·5·20개 Flow와 저장 직후·일반 재방문 상황으로 비교한다.

- A: `지금 할 일` 우선, 저장한 계획은 보조
- B: 저장한 계획 우선, 오늘 할 일은 파생 섹션
- C: 저장 직후와 일반 재방문이 다른 문맥형 진입

각 안의 모바일 wireflow를 만들고 다음을 평가한다.

- 첫 행동 발견성
- 원본 계획과 Today의 관계
- 저장 직후 내보내기 발견성
- 날짜 없는 계획
- 완료·보관
- Flow 20개에서 확장성
- 예측 가능성

권장안 하나를 정하고 다른 두 안을 기각한 이유를 적는다.

### C. 생명주기와 CTA

다음 대안을 비교한다.

- 공개 화면은 미리보기만, 저장 후 `내 Flow`에서 내보내기
- 공개 빠른 내보내기와 저장 후 재내보내기 병존
- 콘텐츠 capability에 따른 조건부 저장 없는 내보내기

각 안을 화면 수가 아니라 다음 기준으로 평가한다.

- 어느 버전을 옮기는지
- 저장을 강제하는지
- 중복 생성 가능성
- 수정 후 다시 옮기는 의미
- 실패와 재시도
- export-first 약속과의 일치

공개 상세 하단의 `편집 / 완료` 제안도 반증한다. `완료`가 실행 완료와 혼동되면 `수정 / 내 계획에 저장` 등 결과 중심 대안을 제시한다.

### D. 여러 결과 형식 설계

사용자가 요청한 캘린더·메모·체크리스트·Todo·시트를 모두 검토하되, 모든 Flow에 다섯 탭을 강제하지 않는다.

다음 대표를 비교한다.

- 이사: 여러 형식 가능
- 날짜 없는 학습 계획: 체크리스트·할 일·메모 중심
- 참고 자료: 메모·시트 중심
- 반복 운동: 캘린더·실행 체크 중심
- Flow Map: 여러 하위 구조

제안 화면은 다음을 구분해야 한다.

- 현재 가장 자연스러운 결과
- 실제 만들 수 있는 다른 결과
- 조건을 채우면 가능한 결과
- 만들 수 없는 결과
- `미리보기`와 `실제로 내 도구에 옮기기`

Todo와 체크리스트를 따로 보여줄 충분한 사용자 차이가 없다면 통합안을 제안한다. 숫자 5를 맞추기 위해 가짜 결과를 만들지 않는다.

### E. 공통 편집 surface

공개 Flow·공개 Item·저장된 Flow·저장된 Item·Flow Map 편집을 하나의 family로 정리한다.

모바일에서 다음을 비교한다.

- 별도 page
- 전체 높이 sheet/dialog
- 기존 내용 아래 인라인

권장 surface의 연속 wireframe을 만든다.

1. 편집 진입
2. Flow 이름·기준일·Item 목록
3. Item 상세 편집
4. 저장하지 않은 변경이 있는 닫기
5. 적용 성공
6. 오류 후 기존 상태 유지

공개 초안에는 `적용`, 저장된 계획에는 `저장`처럼 transaction 의미가 필요한지 명시한다. 단순히 모양만 같게 만들지 않는다.

### F. 도움말과 주의사항

현재 보이는 설명을 다음 네 등급으로 분류하는 설계 규칙과 예시를 만든다.

- 삭제
- `? 도움말`로 이동
- 짧은 한 줄 + 상세 확장
- 반드시 항상 표시

운동 안전 주의, 개인정보, 중복 생성, 되돌릴 수 없는 결과는 `!` 아이콘 안에만 숨기지 않는다. 아이콘에는 텍스트 이름, 충분한 터치 영역, 닫기, 모바일 뒤로가기, 초점 복귀가 있어야 한다.

Modal을 남발하지 않는 popover·inline disclosure·bottom sheet의 사용 조건을 제안한다.

### G. Item 상세 감산

[현재 Item 상세](./screenshots/06-my-flow-item-detail-current.png)를 기준으로 다음 대안을 비교한다.

- 파란 `실행할 일` 영역 제거
- 중립 surface로 전체 Style 통일
- `실행할 일` heading 삭제
- `할 일 수정`을 `수정` 또는 `항목 수정`으로 변경
- 메모·일정을 Item 상세에 통합
- 단일 Item 내보내기와 Flow 전체 내보내기의 우선순위 조정

제안 정보 순서와 이유를 적는다. 예: 제목→완료 기준/바로 할 일→날짜→메모→출처→완료/수정.

### H. 용어와 카피

다음 두 방향을 실제 화면 제목과 CTA에 적용해 비교한다.

- 브랜드에는 `Flow` 유지, 조작에는 쉬운 사용자 언어 사용
- 사용자 화면에서 `Flow`를 `계획`으로 단계적 치환

최소 비교할 라벨:

- Flow 찾기 / 계획 찾기
- 내 Flow / 내 계획
- 저장한 Flow / 저장한 계획
- Flow 관리 / 계획 관리
- Flow 편집 / 계획 수정
- Flow Map / 계획 구성 / 제거
- 더보기 / 결과 보기 / 다른 형식 보기
- 완료 / 내 계획에 저장 / 저장하고 시작
- 내 도구로 옮기기 / 내보내기

`Flow`를 설명하는 도움말이 반드시 필요하다면 용어 자체가 문제라는 가능성도 적는다.

### I. 사용자 해결안 반증

최소 세 개에 대해 `그대로 채택하지 않는 이유`를 제시한다.

- 내보내기는 무조건 `내 Flow`에서만
- 모든 도움·주의는 아이콘 popup
- 모든 Flow에 다섯 형식
- 하단은 `편집 / 완료`
- Flow Map 3칸 전부 삭제
- 공개와 저장 후 편집을 완전히 동일하게
- `Flow` 전면 교체

반대만 하지 말고 사용자 의도를 보존하는 수정안을 함께 제시한다.

## 필수 제안 화면

390×844 모바일 기준으로 최소 다음 8개 연속 화면 또는 명확한 wireframe을 만든다.

1. 공개 Flow 상세와 여러 결과 미리보기 진입
2. 결과 형식 선택 상태
3. 공통 Flow 편집
4. Item 편집
5. 저장 완료 후 선택된 `내 계획` 상세
6. `내 Flow` 첫 화면
7. Item 상세
8. 실제 `내 도구로 옮기기` 범위·형식·결과 확인

추가로 1440px 데스크톱에서 `내 Flow` 첫 화면과 선택 Flow 상세가 어떻게 확장되는지 2개 화면을 제안한다. 모바일과 다른 IA를 만들지 말고 같은 정보 관계를 넓은 화면에 배치한다.

현재 화면은 `Before`, 제안은 `Proposal`로 표시한다. 구현되지 않은 제안을 `After`라고 부르지 않는다.

## 품질 기준

- P0 구조 결정이 색상·간격보다 앞에 옴
- 화면마다 주 행동 하나, 보조 행동 최대 하나가 분명함
- 저장 전·후 상태가 다르게 보임
- 미리보기와 실제 전송이 구분됨
- 지원 불가 형식을 정상처럼 제시하지 않음
- 중요한 주의를 숨기지 않음
- 같은 editor family와 서로 다른 transaction 의미를 함께 설명함
- `내 Flow` IA 3안 중 하나를 명확히 권장함
- 사용자 제안을 최소 세 개 반증함
- 실제 사용자 관찰을 했다고 쓰지 않음
