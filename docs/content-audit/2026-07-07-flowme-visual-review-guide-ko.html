  2. 10분

    URL-first 4장 집중 확인

    27 hit, 28 custom start, 29 miss candidate, 30 handoff를 봅니다.

    판단: hit과 후보가 헷갈리지 않는가, 그대로 시작과 조금 고쳐 시작이 구분되는가, miss가 실행 가능처럼 보이지 않는가.

  3. 10분

    저장 후 실행 화면 확인

    13 My Flow 저장 직후, 14 Calendar, 16 My Flow 실행 큐, 20 전체/상세를 봅니다.

    판단: 저장이 끝이 아니라 오늘 할 일, 전체 목록, 날짜 화면, Step detail/export로 자연스럽게 이어지는가.

  4. 10분

    QA 리포트에서 lookup 가능 15개와 lookup 차단 11개의 의미가 운영자 관점에서 이해되는지 봅니다. 사용자 화면에서 보이는 Flow와 운영 보류 Flow가 섞이지 않아야 합니다.

  5. 15분

    P12로 넘길 UX 결정을 고르기

    눈검토 후 바로 개발할 항목을 하나만 고릅니다. 지금 가장 유력한 후보는 /flows URL-first 첫 화면, URL hit/custom start, miss candidate/handoff, My Flow 저장 후 실행 연결입니다.

화면별 검토 질문

화면 봐야 할 것 통과 기준 문제 신호
/flows URL 입력 사용자가 5초 안에 URL을 붙여넣는 화면임을 아는가. 검색/카탈로그보다 URL 입력과 결과 행동이 먼저 보인다. 카드 탐색, 내부 라벨, 설명문이 URL 행동을 밀어낸다.
hit 결과 이미 Flow가 있음을 신뢰할 수 있고, 바로 쓸 수 있는가. 원본 출처, 시작일, 그대로 시작, 조금 고쳐 시작, export가 선명하다. AI 생성처럼 보이거나, 추천 수/인기 수처럼 검증 안 된 신호가 보인다.
조금 고쳐 시작 전체 편집기가 아니라 개인 사본의 최소 설정으로 보이는가. 저장 이름, 시작일, 포함/제외 Step만 바꾼다는 경계가 보인다. 원본을 수정하는 것처럼 보이거나, fork/version 관리처럼 무거워 보인다.
miss/needs_review 아직 실행 가능한 Flow가 아니라 후보 저장임을 아는가. 제작 후보, 원 URL/canonical URL, 메모, 제작용 Markdown이 분리된다. My Flow 저장, ICS export, 바로 시작이 가능한 것처럼 보인다.
My Flow 개인 사본이 실제 내 작업처럼 보이고 실행되는가. Today, 전체, Step detail, 제외됨, export가 개인 수정 상태를 유지한다. 원본 Flow 설명이 개인 실행 목록보다 앞서거나, 제외 Step이 실행을 방해한다.
Calendar 날짜가 있는 Step이 일정으로 이어지는가. 시작일 변경이 날짜, Today, Calendar, ICS에 반영된다. 날짜 없는 콘텐츠가 빈 캘린더 오류처럼 보인다.
수동 등록 QA 운영자가 후보를 Flow로 만드는 기준이 보이는가. QA 통과/lookup 차단/중복/sourceTrace/sourceUrl 상태가 행동으로 이어진다. 모든 이슈가 단순 오류처럼 보이고, 다음 처리 방법이 안 보인다.

이번에 판단할 결론

지금 확인된 것

  • URL-first P0는 AI 생성보다 기존 Flow 재사용이 먼저라는 방향으로 정리됐다.
  • source-backed 수동 등록 QA는 현재 기준으로 QA 통과 15, 등록 보류 0이다.
  • duplicate canonical URL 0그룹, sourceTrace 누락 0으로 운영 큐는 닫힌 상태다.
  • Post-P11 패키지는 모바일 390px 기준 화면 캡처 32장을 갖고 있다.

아직 확인이 필요한 것

  • 실제 사용자가 /flows 첫 화면에서 URL-first 행동을 먼저 이해하는지.
  • hit, needs_review, miss가 화면상으로 충분히 다르게 느껴지는지.
  • 개인 사본과 원본/source 추적의 경계가 너무 설명적으로 보이지 않는지.
  • Markdown/ICS/TSV/export가 “내 도구로 옮기기”로 충분히 가볍게 보이는지.
