2026-07-04 · 공식 자료 기반 리서치 · FLOW backlog

생산성 도구 연결성을 기준으로 다음 기능을 다시 세운다

결론은 명확하다. FLOW는 지금 AI 일정 앱이 아니라, 외부 컨텐츠를 기존 캘린더·투두·노트·시트에서 실행 가능한 구조로 바꾸는 번역 레이어로 시작해야 한다.

결론 트렌드 점수표 재정렬 URL-first 다음 토의 Markdown 원문

핵심 판단

1. 먼저 찾는다

URL canonical lookup으로 기존 Flow hit를 확인한다. hit이면 AI를 호출하지 않는다.

2. 바로 내보낸다

ICS, Markdown, clipboard, sheet-friendly output이 첫 가치다.

3. 얇게 고친다

시작일, 강도, 제목, 날짜, 메모 정도의 thin edit가 재사용성을 만든다.

4. 일상화는 이후

memo-to-Flow와 My Flow 확장은 중요하지만 URL/export 검증 뒤에 붙인다.

한 줄 방향: FLOW의 P0는 "URL을 넣으면 기존 변환을 찾아주고, 내 캘린더/투두/Obsidian으로 가져가게 해주는 경험"이다.

외부 도구 트렌드에서 읽은 것

캘린더와 태스크 통합은 기본값

Todoist, Google Calendar, Microsoft Outlook은 일정과 할 일을 같은 운영 화면에 붙인다. FLOW가 새 캘린더가 될 필요는 없고, calendar/task가 읽을 수 있는 Step 구조가 필요하다.

AI scheduling은 강하지만 별도 시장

Motion, Reclaim은 자동 배치와 재스케줄링을 판다. FLOW가 초반에 경쟁할 영역이 아니라, duration·deadline·priority를 잘 내보내는 쪽이 맞다.

Markdown과 clipper는 기준선

Obsidian Web Clipper와 Readwise는 durable file, metadata, template export를 강조한다. FLOW도 source link와 체크리스트가 있는 Markdown을 기본 산출물로 봐야 한다.

MCP/자동화는 Later 신호

Akiflow MCP, Zapier MCP는 장기 연결성을 보여준다. 하지만 connector보다 portable export와 데이터 모델이 먼저다.

URL-first와 맞물리는 지점

보강

  • URL lookup은 AI 비용을 줄인다.
  • Export pack은 계정 없는 첫 가치를 만든다.
  • Source ledger는 reuse, edit, fork의 근거가 된다.
  • Markdown export는 Obsidian/Notion/메모 사용성 기준선을 맞춘다.

충돌

  • Direct OAuth를 먼저 만들면 권한/동기화 비용이 앞선다.
  • memo-to-Flow를 전면화하면 generic daily planner처럼 보일 수 있다.
  • AI fallback을 앞세우면 비용과 품질 기대치가 높아진다.
  • creator platform을 먼저 밀면 실제 유입 루프 검증이 늦어진다.

다음 토의 주제

가장 먼저 깊게 볼 주제는 URL canonical lookup + Export pack을 하나의 첫 사용자 여정으로 묶는 것이다.

  • URL hit, miss, low-quality hit를 어떻게 보여줄 것인가.
  • hit가 있을 때 옵션 변경과 thin edit의 최소 범위를 어디까지 둘 것인가.
  • Calendar, Todo, Markdown 중 무엇을 기본 export로 노출할 것인가.
  • 계정 없는 복사/다운로드와 로그인 후 My Flow 저장의 경계는 어디인가.
  • 원문 컨텐츠 주인에게 돌아가는 공유/comment 링크는 언제 실험할 것인가.
