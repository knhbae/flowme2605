기존 개발을 두 사용자 흐름으로 연결

전체 메뉴를 다시 만드는 안이 아닙니다. 시작·저장·복귀가 끊기는 부분만 화면으로 검토합니다.

직접 기록해서 쓰기

  1. 빈 문서에서 바로 메모
  2. 그대로 보관하거나 필요한 줄만 할 일 연결
  3. 오늘에서 완료하고 원문으로 돌아오기

다른 사람의 경험으로 시작

  1. 공개 Flow 내용·출처·버전 읽기
  2. 외부로 바로 받거나 내 사본 만들기
  3. 내 사본의 날짜·메모를 조정하고 이어 쓰기
분류대상이번 검토
유지개인 폴더·할 일·기간 목록·날짜 이동·완료·메모기존 PoC를 기반으로 봅니다. 이동 기능은 다시 설계하지 않습니다.
화면 연결 조정최근 문서 / 공개본과 내 사본 / 원문 복귀 / 외부 전달어디서 시작하고 무엇을 저장했는지 분명하게 합니다.
신규 검토자유 문서→선택한 줄의 할 일 연결, 공개 탐색→PoC 사본 연결이 HTML의 동작은 제안입니다. 제품 저장 계약과 실제 연결 구현은 별도입니다.
화면으로 비교할 결정 두 가지

1. 문장에서 할 일을 꺼내는 방법

A · 필요한 줄을 골라 연결 — 우선 검토11시 회의 참석
회의에서 새 일정 물어보기

평소처럼 쓰고 나중에 선택합니다. 연결 단계가 한 번 더 필요하지만 원문을 바꿀 필요가 없습니다.

B · 체크 문법을 직접 쓰기- [ ] 11시 회의 참석
회의에서 새 일정 물어보기

키보드 사용자는 빠릅니다. 문법을 알아야 하고 일반 문장과 완료 상태의 반영 규칙이 필요합니다. 이번에는 비교 예시만 제공합니다.

2. 공개 Flow의 첫 버튼

버튼 순서만 비교합니다. 어느 안에서도 읽기·질문·외부 전달에 사본 저장을 강제하지 않습니다.

A · 외부 도구로 받기 우선

기존 export-first와 가깝습니다. 내부에서 계속 쓸 위치는 보조 버튼으로 찾게 됩니다.

B · 내 사본으로 쓰기 우선

개인 공간으로 이어지기 쉽습니다. 외부로만 쓰려는 사람에게는 보조 경로가 됩니다.

큰 방향과 다른 사용자 흐름은 어디에 연결되나?
개인 관리개인 기록 → 오늘 → 원문 복귀. Flow 변환 없이도 끝낼 수 있습니다.
재사용·실행공개 Flow → 외부 전달 또는 개인 사본 → 계속 사용.
작성·공개내 사본 → 공개할 내용 검토. 개인 메모·날짜·완료는 제외합니다.
기여·개선공개본 또는 사본의 특정 버전 → 제안 초안. 제출·응답·반영은 후속 설계입니다.
탐색·참여공개 지식 읽기 → 관련 지식·질문. 저장이나 실행 완료가 조건이 아닙니다.

wiki와 커뮤니티는 큰 방향에 포함됩니다. 여기서는 연결 위치만 확인하며 게시판·피드·공동편집·권한 정책을 확정하지 않습니다. 한 사람도 목적에 따라 다른 경로를 쓸 수 있습니다.

설계 규칙·예외·검증 범위
  • 원문과 실행 날짜·완료·개인 메모는 별도로 보여줍니다. 원문을 고쳐도 연결 항목을 몰래 덮어쓰지 않습니다.
  • 오늘은 같은 항목을 모아 보는 화면입니다. 오늘로 갔다고 복사본이 하나 더 생기지 않습니다.
  • 공개 Flow는 고정 예시 버전입니다. 내 사본을 고치거나 완료해도 공개본은 그대로입니다.
  • 저장은 이 브라우저의 예시 데이터에만 적용됩니다. 다른 기기와 동기화하지 않습니다.
  • 외부 출력은 TXT 다운로드/복사입니다. 실제 외부 앱 사용·왕복 동기화 검증은 아닙니다.
  • 개인 기준일 일괄 재계산 등 K4는 기존 개발의 별도 설계·단계입니다. 이 화면으로 완료 처리하지 않습니다.

검사 기록은 별도 QA 문서에 남깁니다. 설계 시뮬레이션이며 실제 사용자 관찰은 아닙니다.

기존 개발 근거와 다음 작업

추천 개발 후보는 ‘자유 문서의 저장·재진입’부터 작게 연결하고, ‘선택한 줄의 할 일 연결’을 다음 단계로 분리하는 것입니다. 공개 탐색 연결과 K4의 순서는 이 검토 결과와 정리 세션의 최신 기준을 함께 보고 선택합니다.

  • 시뮬레이션·반응형 검증 결과
  • 큰 방향·개발 근거 보존 기록
