ALGORITHM VS LLM
12

날짜·사실·상태는 규칙이,
의미 제안은 LLM이, 최종 경계는 사람이 맡습니다

Deterministic rule

  • URL 정규화·cache lookup
  • 표·목록·날짜·반복 파싱
  • stable ID·hash·state transition
  • schema·SourceRef·projection 검증
  • ICS/CSV/Markdown 생성

예: `D-7`, `4주마다`, 표의 행 순서는 모델에게 계산시키지 않는다.

Bounded LLM proposal

  • 행의 의미 분류
  • 동사형 제목 윤문
  • 중복 행 묶기 후보
  • Memo·caution 후보 요약
  • 모호함과 누락 설명

금지: 원문 없는 행동·수치·날짜·의료/법률/재무 결론, 개수 맞추기.

Human-only gate

  • rights·retention·takedown
  • 민감 콘텐츠와 지역 적용성
  • 논쟁적인 Item/omit 경계
  • 사용자 overlay와 포함 여부
  • 명시적 review·save

예: 미국 출산가방 55행은 번역 완료가 아니라 한국 적용성 review 대기다.

`maxItems=7`은 처리 상한이지 목표 개수가 아니다 — 넘으면 partial/import, 부족해도 채우지 않는다

TIMEOUT / EMPTY

입력을 보존한다

완료로 표시하지 않는다. 사용자 메모에 명시된 행동이 있을 때만 compatibility fallback.

INVALID DATE

날짜를 제거한다

순차 offset을 발명하지 않는다. Item은 무일정으로 남고 ICS는 0건.

CANCEL / LATE RESULT

취소한 run은 닫힌다

늦게 도착한 provider 결과가 proposal이나 saved copy를 바꾸지 못한다.

RETRY / COST

새 attempt로 계측한다

기본 자동 retry는 0회. 비용·지연 budget 안에서 사용자가 명시적으로 다시 시도한다.
