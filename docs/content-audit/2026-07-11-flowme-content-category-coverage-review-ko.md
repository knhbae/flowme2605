# FlowMe 콘텐츠 카테고리 커버리지 재검토

작성일: 2026-07-11<br>
상태: 기획 검토안, 앱/seed 변경 없음

## 결론

FlowMe에 여행 카테고리 아이디어가 없었던 것은 아니다. [2026-05-31 카테고리 taxonomy](./2026-05-31-flowme-category-taxonomy.md)에는 이미 여행/이동이 있었고, [2026-07-04 웹 소스 스카우트](./2026-07-04-web-source-scout-category-review-ko.md)에도 여행/캠핑 후보 10개가 있다. 문제는 taxonomy와 소스 후보가 현재 `/flows`의 실행 가능한 카탈로그까지 이어지지 않았다는 점이다.

현재 `/flows`는 문서 기준 2개 대표 Map, 9개 curated Map, 1개 단일 Flow를 함께 노출한다. 그러나 이 중 이사 콘텐츠가 중복되고, 4개 Map은 `revise` 또는 `park` 상태다. 실제로 바로 판단 가능한 생활 계획은 이사, 학습, 이유식, 신차, 결혼, 전세 정도에 집중돼 있다. 여행, 일반 식사 계획, 일/커리어, 정기 행정, 가전 관리, 반려/취미는 비어 있거나 앱 카탈로그 밖에 있다.

따라서 이번에 새 변환 규칙을 만들 필요는 없다. 기존 Source-to-Flow Conversion Gate와 playbook은 유지하고, 그 위에 **포트폴리오 커버리지 층**을 추가한다.

```text
기존 규칙: 이 원문이 좋은 Flow가 될 수 있는가?
이번 검토: 좋은 Flow 후보 중 지금 비어 있는 생활 문제를 무엇부터 채울 것인가?
```

첫 번째 빈 영역은 여행이다. 다만 `여행 완벽 준비` 같은 거대한 단일 Flow를 만들면 안 된다. 준비물, 공식 출국 절차, 국가별 입국 등록, 실제 여행 코스는 각각 한 개 원문을 따르는 작은 Flow로 만들고, 사용자가 필요한 것만 고를 수 있는 Flow Map으로 묶는 방식이 맞다.

## 현재 근거

### 앱과 개발 상태

- [SERVICE_STRUCTURE](../SERVICE_STRUCTURE.md)는 `/flows`를 2개 대표 Map + 9개 curated Map + 1개 단일 Flow의 통합 카탈로그로 정의한다.
- 현재 runtime 기준 대표/후보 Map은 `moving-d30`, `middle-school-math-1`, `opic-plan-map`, `baby-food-map`, `new-car-map`, `moving-map`, `wedding-map`이다.
- `funmom-study-routine-map`은 `park`, `reading-routine-map`, `vaccination-map`, `homefit-map`은 `revise`다.
- `moving-d30`과 `moving-map`은 같은 이사 생활 문제를 다루므로 카드 수보다 실제 커버리지가 작다.
- P22 자동 구현 범위는 많이 닫혔지만 실제 반복 사용자 관찰은 아직 실행되지 않았다. 따라서 이번 결과는 콘텐츠 포트폴리오 기획이며, 대량 노출이나 사용 검증을 의미하지 않는다.

### 외부 수요 참고

- Notion 공식 Marketplace의 [Travel planner](https://www.notion.com/templates/travel-planning)는 현재 500개 이상 평가와 4.8점을 보인다. 리뷰에는 체크박스, 협업, 일자별 계획 수요가 함께 나타난다.
- Todoist 공식 템플릿의 인기 목록에는 [Meal Planning](https://www.todoist.com/templates/category/popular)과 Grocery List가 포함돼 있고, 별도 [Event Planning](https://www.todoist.com/templates/event-planning) 템플릿도 날짜와 할 일을 중심으로 제공된다.
- 이 비교는 FlowMe가 Notion/Todoist처럼 빈 계획 도구가 되어야 한다는 뜻이 아니다. 여행, 식사, 행사처럼 사람들이 이미 템플릿을 찾아 옮겨 적는 생활 문제가 존재한다는 보조 근거다. FlowMe의 차별점은 실제 원문 row와 링크를 실행물로 옮기는 데 있다.

## 기존 taxonomy를 어떻게 쓸 것인가

2026-05-31 taxonomy의 15개 대분류는 소스 탐색용으로는 충분하다. 지금 필요한 것은 또 다른 대분류 목록이 아니라 다음 두 축의 분리다.

### 축 A. 사용자가 찾는 생활 영역

앱 탐색과 포트폴리오 커버리지에는 아래 9개 영역을 임시 상위 묶음으로 쓴다. 이는 바로 내비게이션에 고정할 명칭이 아니라, 비어 있는 영역을 확인하기 위한 검토 단위다.

| 생활 영역 | 현재 상태 | 현재 근거 | 가장 큰 빈칸 |
|---|---|---|---|
| 집·살림 | 강함, 다만 편중 | 이사 2종, 전세계약 | 가전·계절 관리, 자취 시작 |
| 가족·육아 | 부분 충족 | 이유식, 예방접종, 펀맘 | 입학·방학·가족 일정, source import 완성도 |
| 공부·독서 | 강함 | 중1 수학, 오픽, 독서 | 시험/과목별 실제 진도 row 확대 |
| 돈·서류·구매 | 부분 충족 | 신차, 전세계약 | 갱신·만료, 연말정산, 생활 행정 |
| 건강·운동 | 약함 | 홈트 revise | 단계형 운동, 공식 검진 일정 |
| 여행·외출 | 비어 있음 | 카탈로그 노출 0 | 준비, 입국, 일정표, 캠핑 |
| 식사·장보기 | 비어 있음 | 일반 성인용 0 | 주간 식단, 도시락, 장보기 |
| 일·커리어 | 비어 있음 | 카탈로그 노출 0 | 면접, 입사, 이직, 사업 시작 |
| 취미·반려 | 비어 있음 | 카탈로그 노출 0 | 반려 첫 주/접종, 창작 챌린지, 주말 프로젝트 |

### 축 B. 원문을 옮기는 계획 방식

아래 방식은 새 규칙이 아니다. 기존 playbook을 사용자가 이해할 수 있는 계획 모양으로 다시 묶은 것이다.

| 계획 방식 | 원문 근거 | FlowMe 결과 | 예시 |
|---|---|---|---|
| 날짜를 향해 준비 | D-day, 월별, 주차별 row | 캘린더 + 체크 | 이사, 결혼, 시험, 출국 준비 |
| 정해진 순서대로 진행 | 절차/단계 row | 순서형 체크리스트 | 신차 구매, 출국 당일, 사업자등록 |
| 주기적으로 반복 | 원문 반복 주기 | 반복 일정 1개 + 메모 | 필터 청소, 영상 루틴, 물주기 |
| 표의 행을 따라가기 | XLSX/PDF/표 row | 시트 + 일정 | 이유식, 주간 식단, 학습 진도 |
| 자료를 하나씩 실행 | 영상/글/도안 row | 자료 큐 + 반복 일정 | 홈트 플레이리스트, 펀맘, 독서 자료 |
| 비교하고 결정 | 후보/견적/판정 기준 | 체크 + 비교 메모 | 신차, 중고차, 웨딩 업체 |

생활 영역은 `어디서 찾는가`를, 계획 방식은 `어떻게 실행물로 바꾸는가`를 답한다. 두 값을 한 category 필드에 섞지 않는다.

## 여행 카테고리 설계안

### 사용자 문제

```text
여행을 앞둔 사용자가 여러 글과 공식 사이트를 다시 찾아다니지 않고,
자신의 출발일에 맞춰 준비물과 출국 절차를 저장하고,
필요하면 목적지별 입국 Flow와 실제 일정 Flow를 추가한다.
```

### 권장 구조

```text
Flow Map: 해외여행 준비
  Flow 1: 해외여행 준비물 체크
    primary source: KKday 2026 해외여행 준비물 체크리스트
    shape: source checklist rows
    result: 체크리스트 + 원문 링크

  Flow 2: 공항 출국 순서
    primary source: 찾기쉬운 생활법령정보 출국절차
    shape: 공항도착부터 항공기 탑승까지 공식 8단계
    result: 출국 당일 순서형 체크리스트

  Flow 3: 일본 입국 등록
    primary source: Visit Japan Web 공식
    status: source_import_required
    result: 공식 row 확보 후 별도 Flow

  Flow 4: 목적지별 3박 4일 일정
    primary source: 실제 일자별 여행 코스 1개
    status: 새 source scout 필요
    result: 일자별 캘린더 일정
```

### 입력과 결과

- 기본 입력: 출발일. 목적지는 국가별 Flow를 고를 때만 사용한다.
- 선택 입력: 반복 요일이나 긴 여행용 종료일은 해당 원문에 필요할 때만 둔다.
- 메모: 항공편, 숙소, 예약번호, 개인 준비물, 동행자 메모.
- 체크: 원문에 있는 준비물/절차 row만 둔다.
- 내보내기: 준비물은 checklist/Markdown, 날짜가 있는 일정은 calendar, 예약 정보는 memo.

### 만들지 않을 것

- 준비물, 비자, 보험, 환전, 공항, 여행 코스, 여행 기록을 한 Flow로 합치지 않는다.
- `항공권 예약하기`, `호텔 정하기`처럼 특정 원문에 없는 보편 상식을 임의 Step으로 만들지 않는다.
- 항공편·숙소·예산을 각각 필수 top-level field로 만들지 않는다. 일정을 생성하는 데 꼭 필요한 값 외에는 메모에 둔다.
- 여행 후기나 명소 목록만 있는 글을 억지로 일정표로 만들지 않는다.

### 왜 여행이 첫 확장 영역인가

- 현재 카탈로그에서 완전히 비어 있다.
- 출발일이라는 명확한 anchor가 있다.
- 체크리스트, 공식 절차, 일자별 코스, creator 추천 등 서로 다른 source shape를 한 카테고리에서 검증할 수 있다.
- 사용자가 날짜와 목적지만 바꿔 다시 쓰거나 동행자와 공유할 이유가 강하다.
- 여행 제작자/플랫폼은 원문·예약 페이지로 되돌아오는 링크 가치를 얻을 수 있다.

## 새로 찾아야 할 소스 영역

기존 100개 후보만으로도 첫 확장 묶음은 만들 수 있다. 다만 아래 생활 문제는 source scout가 부족하다.

1. **실제 여행 일정표:** 준비물 글이 아니라 `1일차/2일차/3일차`가 있는 국내·해외 코스 원문.
2. **가족 행사:** 생일, 돌잔치, 집들이, 명절처럼 날짜와 준비 row가 있는 체크리스트.
3. **정기 생활비/만료 관리:** 공과금, 보험·구독 갱신, 연간 서류처럼 공식 날짜나 실제 템플릿 row가 있는 소스.
4. **학기·방학 계획:** 학교/기관 공식 일정 또는 실제 활동표가 있는 소스.
5. **반려 생활:** 입양 첫 주, 접종, 미용/구충처럼 공식·전문 source row가 분명한 일정.
6. **주말 프로젝트:** 집 정리, 셀프 페인팅, 사진 정리처럼 준비-실행-마무리 row가 있는 한 번성 프로젝트.

다음 scout에서는 이 6개 영역을 각 3~4개씩 찾고, 이사·결혼·차량 후보는 새 source evidence가 훨씬 강하지 않으면 추가하지 않는다.

## 콘텐츠 포트폴리오 운영 원칙

### 카테고리마다 최소 세 역할

모든 카테고리에 많은 Flow를 넣는 대신, 성숙한 카테고리는 아래 역할을 가진 콘텐츠를 1개씩 갖추는 것을 목표로 한다.

1. **대표 시작점:** 처음 보는 사용자도 저장 결과를 이해하는 고수요 Flow.
2. **반복/재사용:** 날짜나 주기만 바꿔 다시 쓸 수 있는 Flow.
3. **creator/community 버전:** 제작자가 업데이트하고 사용자가 fork할 이유가 있는 Flow.
4. **공식 trust anchor:** 민감하거나 날짜가 중요한 경우에만 별도로 둔다.

여행의 경우 `해외여행 준비`, `목적지별 일정`, `creator의 3박 4일 코스`, `국가별 공식 입국 절차`가 각각 이 역할을 맡는다.

### 승격 순서

```text
source URL 확인
  -> source row 추출
  -> 기존 Conversion Gate 통과
  -> 비어 있는 생활 영역/계획 방식인지 확인
  -> normalized review HTML
  -> 3~4개 canary만 앱 반영
  -> 실제 저장·실행 관찰 후 다음 묶음
```

현재 P22 사용자 관찰 gate가 남아 있으므로, source row 추출과 review artifact 준비는 병행할 수 있지만 한 번에 수십 개를 앱 카탈로그에 노출하면 안 된다.
