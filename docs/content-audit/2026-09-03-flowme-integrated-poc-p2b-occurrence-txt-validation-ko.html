02

DEC-01

회차별 완료 저장의 범위

충돌
개발 2 원 정본은 회차별 완료 저장을 당시 범위 밖으로 뒀지만, 통합 PoC 목표는 회차 이동·완료·다시 열기·Undo·reload를 요구한다.
이번 결정
운영 정책이나 migration으로 올리지 않고, occurrenceId 단위의 PoC 전용 shadow state로만 구현한다.

원본 Item, 원 일정, Flow 소속과 운영 writer는 바꾸지 않는다.
DEC-02

네 결과와 TXT의 관계

충돌

09

운영 데이터 보호선을 별도 gate로 둡니다.

자동 브라우저 fixture의 byte 비교는 실제 사용자의 브라우저 profile이나 운영 backend 검사가 아닙니다. 증거 범위를 그대로 표시합니다.

  • 진입점은 exact /my?personalWorkspacePoc=v1이다.
  • 쓰기는 flow:poc:personal-workspace:v1:* prefix 안에서만 허용한다.
  • 기존 Flow 데이터는 read model 입력으로만 사용하고 운영 writer를 호출하지 않는다.
  • localStorage.clear()는 호출하지 않는다.
  • 자동 시나리오 전후 PoC prefix 밖 flow:* key/value는 byte-for-byte 동일해야 한다.
  • 손상 payload와 unsupported origin은 기존 /my로 fail-closed한다.
  • 반복 규칙 편집·이번 이후 일괄 변경·외부 동기화·운영 migration은 범위 밖이다.
