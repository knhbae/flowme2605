# P24-00B 실제 사용자 관찰 가이드

**상태:** 관찰 준비 완료, 실제 관찰 `0 / 15` 세션<br>
**공개 테스트 URL:** <https://flowme2605.vercel.app><br>
**제품 기준:** `d6487a0d3352de358320b15ceeacd8b5405eb04e` (P24-00OPS2 merged runtime)<br>
**관찰 단위:** 5명 x 3회, 총 15세션

이 가이드는 자동화 QA를 실제 사용자 검증으로 오해하지 않도록 분리한다. 진행자는 기능을 설명하거나 버튼 위치를 알려주지 않고, 사용자가 발견-저장-수정-실행-완료 취소-내보내기-회고-재사용의 연결을 스스로 이해하는지 관찰한다.

## Claude Design 목업 반영

`FlowMe UXUI 전체 검토 (8)`의 `FlowMe UX 개선안 목업 + 코멘트`는 픽셀 복제가 아니라 검증할 구조로 사용한다. 원문의 오류 선행 조건과 A~G 번호를 아래처럼 그대로 맞춘다.

| 목업 방향 | 제품 반영 | 관찰 질문 |
| --- | --- | --- |
| 선행 오류 | 빌드·접근·날짜·저장 정합성 | 결과 날짜와 항목 수를 신뢰하는가 |
| A. 편집 단계적 공개 | 기본 편집과 세부 설정 분리 | 설명 없이 필요한 수정만 찾는가 |
| B. 제자리 완료 취소 | 행 체크 + 즉시 실행 취소 | 완료 후 원래 상태로 쉽게 돌리는가 |
| C. 날짜 없는 트레이 | Calendar의 날짜 없는 할 일 | 날짜 없는 일을 찾고 일정에 놓는가 |
| D. Flow 단위 내보내기 | 전체/선택/현재 범위 우선 | 무엇이 내보내지는지 예측하는가 |
| E. 날짜 이동 범위 | 연동/고정, 하나/선택/전체 구분 | 이동 범위와 결과를 맞게 예상하는가 |
| F. 실행 행 하나 | 현재 할 일만 완료 control, 다음은 예고 | 같은 일을 중복으로 오해하지 않는가 |
| G. 단계별 가벼운 메모 | 비공개 메모와 원본 수정 메모 분리 | 기록과 전달 요청의 차이를 이해하는가 |

현재 production과 목업 방향의 대조 결과는 [P24-00B2 디자인 준비 감사](../2026-07-14-p24-00b2-production-design-readiness/README.md)에 분리한다. 이 browser QA는 실제 관찰 세션 수에 포함하지 않는다.

## 운영 원칙

1. 같은 참가자가 세 번 돌아와 `첫 사용`, `실행 중`, `완료 후 재사용`을 경험한다.
2. 화면 설명은 하지 않는다. 과업의 목적만 읽어 주고 위치나 버튼명은 말하지 않는다.
3. 도움을 요청하면 먼저 “지금 무엇을 찾고 계세요?”라고 묻고, 90초가 지나도 진행하지 못할 때만 최소 힌트를 준다.
4. 실명, 실제 주소, 민감한 일정 대신 현실적인 가상 데이터를 사용한다.
5. 화면/음성 녹화는 동의를 받은 경우에만 하며 참가자 ID로 익명화한다.
6. 자동 테스트와 관찰 결과를 합산하지 않는다. 현재 관찰 수는 실제 세션이 끝날 때만 올린다.

| 참가자 | 대표 Flow | 1회차 | 2회차 | 3회차 |
| --- | --- | --- | --- | --- |
| P1 기준일 역산형 | 이사 준비 | 발견, 이사일 지정, 저장 | 전체 이동과 한 항목 고정, 완료 취소 | 전체/선택 export, 회고, 새 이사일로 재사용 |
| P2 날짜 없는 체크형 | 차량 점검 | 공개 Flow 저장 | 날짜 없는 일을 Calendar에서 배치, 실행 | 항목 선택 export, 비공개/수정 메모 구분 |
| P3 반복 루틴형 | 운동 또는 청소 | 반복 설정, 저장 | 회차 확인, 완료/재개 | 지난 회차 확인, 다음 회차와 전체 Flow 구분 |

| P5 공유·재사용형 | public `/f` | preview와 저장 구분 | My Flow 실행과 Calendar 확인 | 단계별 메모, 완료 회고, 다시 쓰기 |

## 공통 측정

- 결과: `성공 / 도움 후 성공 / 실패 / 제품 차단`
- 첫 행동까지 걸린 시간
- 잘못 들어간 화면과 되돌아온 횟수
- 진행자가 준 힌트 수
- 사용자가 스스로 읽은 행동 단위: 현재 항목, 선택 항목, 전체 Flow
- 예상한 날짜와 실제 반영 날짜의 일치 여부
- 완료 취소, 날짜 제거, 삭제 복구의 성공 여부
- My Flow, Calendar, export 결과의 불일치 여부
- 사용자가 요구한 설명 문구와 없애도 된다고 본 설명 문구
- 세션 후 확신도 `1~5`

## 판정

- **keep:** 5명 중 4명 이상이 도움 없이 완료하고 신뢰 문제를 말하지 않는다.
- **change:** 2명 이상이 같은 지점에서 멈추거나, 1명이라도 데이터 손실·잘못된 날짜·잘못된 export를 경험한다.
- **defer:** 관찰된 필요가 없고 현재 흐름을 단순하게 유지하는 편이 낫다.
- **blocking:** 저장 내용 소실, 날짜 오반영, 실행 기록 혼선, 공개 URL 접근 실패처럼 다음 세션을 계속하면 안 되는 문제다.

P24-00B 종료 후 P24-00C에서 모든 발견을 `keep / change / defer`로 재분류한다. 그 전에는 source v2 merge, 계정·클라우드 동기화, 직접 OAuth, 대규모 IA 변경을 열지 않는다.
