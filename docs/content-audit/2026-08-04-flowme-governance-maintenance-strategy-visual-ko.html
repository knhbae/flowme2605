06 · Risk-tiered review

모든 변경을 무겁게 검토하지 말고,
영향이 커질수록 근거와 확인자를 늘린다.

오탈자와 안전 문장을 같은 줄에 세우면 공동관리는 느려집니다. 내용의 위험과 사용자 영향에 맞춰 검토 깊이를 다르게 합니다.

LEVEL 1

표현·링크

오탈자, 끊어진 링크, 뜻을 바꾸지 않는 설명 보강

신뢰받는 공동관리자 1명
LEVEL 2

일반 실행

순서 변경, 준비물 추가, 예상 소요시간 조정

실행 조건 + 공동관리자 검토
LEVEL 3

시간·비용

신청 마감, 예약 시점, 비용 또는 환불에 영향

근거 링크 + 최근 확인일
LEVEL 4

안전·법·의료

잘못되면 신체·재산·법적 문제를 만들 수 있는 내용

즉시 경고 + 분야 확인 + 2인 검토
LEVEL 5

권리·개인정보·공격

외부 유료 자료 복제, 주소 노출, 조작·대량 제출

운영팀 별도 처리 + 이의 절차
신고 전 · 위험 가능 문장

도시가스 설비를 직접 분리하는 것으로 오해될 수 있는 내용

09 · Product direction

다음 UX 기획에서 먼저 구체화할
네 묶음.

이 보고서는 정책 문서로 끝내기보다, 다음 화면과 데이터 구조를 놓치지 않게 만드는 입력물입니다.

01

공개 Flow 신뢰 카드

처음 만든 사람, 현재 관리, 최근 확인, 적용 조건, 확인이 필요한 내용을 한 화면에 표시합니다.

  • 인기 수치와 실행 근거 분리
  • 관리 승계 이력 연결
02

개선 제안 보내기

내가 바꾼 항목 중 보낼 것만 고르고, 주소·실제 날짜·개인 메모가 제외됐는지 확인합니다.

  • `나만 사용`이 기본값
  • 공식 오류·안전 신고는 별도
03

공동관리자 검토함

변경 전후, 이유, 조건, 같은 제안, 근거를 보고 반영·상황별 분리·추가 정보 요청·유지를 결정합니다.

  • 담당 영역과 처리 기한
  • 검토 뒤 변경되면 재확인
04

관리 공백·안전 처리

다시 확인 필요, 후임 공동관리, 참고용 보관, 항목별 긴급 제한과 복구·이의 기록을 설계합니다.

  • 저자성과 관리 책임 분리
  • 개입 이유와 범위 공개

구현 전에 별도로 결정할 규칙

공개 Flow와 기여 내용의 복제·수정·외부 내보내기 범위, 유료 Flow의 관리 종료와 기존 사용자 권리, 의료·법률·안전 분야의 검토 자격은 법률·운영 검토가 필요합니다. 이 보고서는 방향과 UI 가설이며 최종 이용 규칙을 확정하지 않습니다.
