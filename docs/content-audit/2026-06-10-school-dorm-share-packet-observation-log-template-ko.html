목적 수신자 이해도 기록을 같은 형식으로 남긴다.

상태 기록 템플릿. 검증/통합/공개 라우트 아님.
금지 실명, 학생번호, 건강값, 결제값, 방 정보, 채널 ID 저장 금지.

not invited, invited, agreed, scheduled, not run은 관찰 증거가 아니다. 빈 log도 evidence board update 근거가 아니다.

사용 방식

실제 이름 대신 역할 라벨만 쓴다. 민감값은 “식별했다/올리지 않겠다고 말했다”처럼 결과만 기록한다. 기록 전에는 scheduling tracker와 preflight checklist를 확인한다.

student-like recipient

학생 본인처럼 읽는 수신자.

parent/guardian-like

보호자나 가족방 수신자.

coordinator

단체방, 카페, 제출 확인을 관리하는 사람.

other proxy

역할이 애매하면 proxy로 표시하고 해석 한계를 남긴다.

태스크 결과 체크

각 항목은 pass, fail, unclear 중 하나로만 기록한다. 판단 근거는 짧게 남긴다.

혼동 메모

실패 원인을 제품 문구 수정으로 연결하기 위한 짧은 기록이다.

라벨 혼동

`공지 확인 완료`를 전체 완료로 이해했는지, `당일 절차 확인 필요`를 FlowMe 요청으로 봤는지 적는다.

민감값 혼동

건강서류, 결제, 학생 식별값, 채널 링크를 올리려 했는지 결과만 기록한다.

자동화 기대

FlowMe가 카톡/카페/폼에 자동 게시하거나 답변을 모은다고 기대했는지 적는다.

3명 롤업

3개 이상 세션이 쌓인 뒤에만 작성한다. 한 명의 반응으로 제품 결정을 내리지 않는다.

지표 필요 신호 관찰 결과
라벨 이해 첫 run 3명 모두 네 라벨을 올바르게 해석
최신 공지 우선 모든 참여자가 공식 최신 공지가 우선이라고 말함
민감값 제외 주의 문구 후 민감값 게시 제안 없음
수동 경계 자동 전송/게시/응답 수집을 기대하지 않음
모바일 첫 화면 긴 출처 설명 없이 패킷 목적을 읽음

결정 라벨

검증처럼 보이는 표현은 쓰지 않는다. 세 가지 비검증 라벨만 허용한다.

no signal

세션 수가 부족하거나 관찰 조건이 달라 비교할 수 없다.

friction

진행은 가능하지만 라벨, 금지값, 자동화 경계, 모바일 문구가 헷갈린다.

candidate signal

이해 기준을 통과해 `/content-flows` 리뷰 후보 준비가 가능하다. 검증은 아니다.
