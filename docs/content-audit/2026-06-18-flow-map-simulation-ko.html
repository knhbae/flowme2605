Flow Map 제품 사용 방식 시뮬레이션

중1 수학과 영유아 접종·검진을 같은 원칙으로 줄여 봄

이번 검토는 실제 사용자 행동 데이터가 아니라, 원문 소비부터 저장·실행·재방문까지의 클릭 가능한 화면 시뮬레이션입니다. 사용자 화면과 제작자 화면은 분리했고, 검토 내용은 이 리포트에만 남겼습니다.

Flow Map > Flow > Step > Item 전세/10개 Flow 수준의 단순도 과한 입력 제거

핵심 판정

두 케이스 모두 Flow Map으로 성립

중1 수학 강의 목록이 단원별 Progress Flow로 반복됩니다. Step은 강의 1개이고, Item은 강의 열기·쪽수·오답 메모입니다.
영유아 접종·검진 공식 일정표가 건강검진·구강검진·예방접종 Flow로 나뉩니다. Step은 기간/연령 구간 1개이고, Item은 검진 항목 또는 접종 항목입니다.

사용자 시뮬레이션

원문을 보고 저장한 뒤 다시 들어오는 흐름

  1. 사용자가 EBS 강좌나 공식 검진/접종 페이지를 보고 “나중에 따라가야 할 구조”라고 판단합니다.
  2. FlowMe에서 전체 지도를 저장하거나, 현재 필요한 Flow만 저장합니다.
  3. 중1 수학 사용자는 단원 Flow에서 강의 Step을 열고 완료 체크와 오답 메모를 남깁니다.
  4. 영유아 사용자는 아이 생년월일을 입력하고, 기간별 Step을 캘린더/표 형태로 확인합니다.
  5. 며칠 뒤 재방문하면 완료한 Step과 다음 Step이 보이고, Item은 FlowMe 내부 체크 또는 외부 앱 설명 텍스트로 남습니다.

제작자 시뮬레이션

콘텐츠 구조를 실행형 지도로 만드는 흐름

  1. 제작자가 원문 URL 또는 원문 행을 가져옵니다.
  2. 원문 행을 기준으로 반복 단위를 Flow로 묶습니다. 중1 수학은 단원, 영유아는 건강검진/구강검진/예방접종입니다.
  3. 각 원문 행은 Step 후보가 됩니다. 제작자가 임의로 체크리스트 개수를 맞추지 않습니다.
  4. Step 안의 세부 내용은 Item으로 접습니다. FlowMe 안에서는 체크리스트처럼 보이고, 외부 앱에서는 설명 텍스트로 보입니다.
  5. 사용자 미리보기를 보고 과한 입력이나 판단 문구가 있으면 공개 전 제거합니다.

반복 개선

과해서 줄인 것

진행 페이스 입력 제거 중1 수학은 날짜 설정보다 진도 체크가 중심이라, 강제 페이스 입력을 넣지 않았습니다.
상태 버튼 제거 대기, 예약 필요 같은 버튼은 결과가 모호해서 Step 완료 체크와 메모로 줄였습니다.
긴 URL 노출 축소 사용자 fallback 미리보기에는 출처명만 두고, 실제 링크는 출처 버튼에 남겼습니다.
검토 문구 분리 사용자용/제작자용 HTML에는 내부 평가를 넣지 않고, 시뮬레이션 내용은 이 리포트로 분리했습니다.

남은 리스크

아직 검증됐다고 말하면 안 되는 부분

  • 실제 사용자가 전체 저장과 일부 저장을 어떻게 고르는지는 행동 데이터가 필요합니다.
  • 영유아 접종 일정은 공식 일정 확인과 의료기관 판단이 우선이라, FlowMe가 자동 판단하는 형태로 확장하면 안 됩니다.
  • 중1 수학은 진도표 수준은 적절하지만, 학습 계획 자동 생성이나 성취도 분석을 붙이면 복잡도가 다시 올라갑니다.
