My Flow 저장 개수별 UX 판정

현재 테스트 목표는 저장한 Flow를 내 앱에서 다시 열었을 때, 사용자가 설명 없이 오늘 실행, 체크, 메모, Flow 찾기로 이동하는지 확인하는 것이다. 결론은 “기능을 더 붙이는 것”보다 “저장 개수에 맞게 보이는 기능을 줄이는 것”이 맞다.

사용자용 v4 PoC 실제 /my 정렬 관찰 키트 관찰 기록지 관찰 롤업 클릭 smoke check 관찰 전 드라이런 저장 개수별 관찰 기준 서비스 UX 백로그

핵심 판정

1개 저장은 관리 화면이 아니다

Apple/갤럭시/토스식으로 보면, 1개 저장 상태에서 사용자는 “내가 뭘 저장했는지”와 “오늘 뭘 하면 되는지”만 알면 된다. 나중에 보기, 이 항목 완료, 상태판, 전체 탭은 사용자가 관리 앱을 배워야 하는 느낌을 만든다.

  • 1개 저장: 저장됨, 오늘 항목, 체크, 메모, 원문/외부앱 fallback만 유지한다.
  • 4~8개 저장: Today를 기본 홈으로 두고, 다른 Flow는 Flow 찾기로 연다.
  • 20개 이상 저장: 전체 목록을 처음부터 펼치지 않고, 짧은 목록과 검색/필터/전체 보기로 이동한다.

UX 렌즈

세 회사 관점으로 보면 같은 결론이다

Apple식첫 화면은 현재 맥락 하나에 집중한다. 1개 저장에서 탭과 상태 버튼은 컨텍스트보다 시스템을 먼저 보이게 한다.
Galaxy식개수가 늘어날 때만 탐색 도구를 노출한다. 4~8개는 홈 화면보다 drawer/sheet가 적합하다.
Toss식사용자가 얻는 결과를 하나의 문장과 하나의 행동으로 보여준다. “오늘 할 일 처리”와 “다른 Flow 찾기”를 분리한다.

저장 개수별 판정

보여줄 것과 숨길 것

상태보여줄 것숨길 것관찰 질문
1개 저장 Flow 제목, 오늘/밀린 Step, 작은 체크, 메모, 원문 링크 전역 탭, 상태판, 나중에 보기, 큰 완료 CTA, 전체 목록 사용자가 “그냥 이걸 하면 되네”라고 이해하는가.
4개 저장 Today 목록, 선택한 Step 상세, 필요할 때 여는 Flow 찾기 카테고리별 대시보드, 상태 버튼 묶음, 첫 화면 검색창 오늘 항목과 전체 Flow 찾기를 구분하는가.
8개 저장 Today 우선, Flow 찾기 버튼, sheet 안 검색/필터 처음부터 긴 Flow 목록, 모든 필터 상시 노출 원하는 Flow를 찾을 때만 탐색 모드로 들어가는가.
20개 이상 초기 8개, 검색, 필터, 전체 Flow 보기 30개 전체 카드 기본 노출, row마다 완료 버튼 전체 펼침보다 검색/필터를 먼저 쓰는가.

다음 수정 조건

관찰에서 이렇게 나오면 바로 줄인다

신호판정수정 방향
1개 저장에서 사용자가 탭이나 목록을 찾는다. High 단일 저장은 더 강하게 실행 카드만 남긴다. 진행률도 보조 위치로 내린다.
상세에서 작은 완료 토글도 “뭘 완료하는지” 묻는다. High 상세 완료 토글을 숨기고, Step 내부 Item 체크와 메모만 남긴다.
4~8개 저장에서 사용자가 Flow 찾기를 먼저 누르고 길게 탐색한다. Medium Today 문장과 현재 Step 제목을 더 구체화한다.
20개 이상에서 검색/필터를 발견하지 못한다. High Flow 찾기 sheet 첫 줄에 검색을 더 선명하게 두되, 전체 카드 기본 노출은 유지하지 않는다.

현재 결론

제품 방향은 맞지만, 완료 판정은 아직 이르다

현재 PoC와 실제 /my는 전세/10개 Flow 수준의 단순성에 가까워졌다. 다만 이것은 내부 UX 판단이다. 다음 단계는 이 판정표와 관찰 키트를 사용해서 1개, 4개, 8개, 20개 이상 상태에서 첫 클릭과 체크/메모 완료 여부를 실제로 기록하는 것이다.
