FlowMe 분석방 / naver-search-advisor-site-readiness scenario
작성일 2026-06-09 · 상태: review candidate, not SEO advice

Naver Search Advisor는 SEO 점수가 아니라 사이트 준비 체크로 다룬다

이 문서는 naver-search-advisor-site-readiness를 한국어 우선 검색 콘솔/웹마스터 설정 시나리오로 선택한 근거를 정리한다. FlowMe는 소유권 방식, 접근 가능성, 수집 준비, sitemap/RSS 상태, 재확인 날짜를 다루되 검증값과 성과 목표를 저장하지 않는다.

현재 상태A- /content-flows review candidate.
첫 행동사이트 단위와 접근 권한을 먼저 고른다.
저장 금지검증값, DNS 값, HTML tag, OAuth, API key, credential.
보장 금지색인, 노출, 순위, 트래픽 성과를 보장하지 않는다.

결정

범용 `site-search-console-setup-precheck`보다 먼저, 한국어 우선 시나리오인 Naver Search Advisor 사이트 준비 후보를 평가한다. 공개 라우트, 플랫폼 통합, SEO 기능은 만들지 않는다.

왜 Naver-first인가

국내 사이트 운영자에게 가장 직접적인 검색 콘솔 축이고, 소유권/수집 준비/재확인 상태를 작은 artifact로 만들 수 있다.

사용자 순간

작은 사이트, 커스텀 도메인 블로그, 크리에이터 페이지, 소상공인 사이트가 출시나 큰 업데이트 뒤 Naver 발견 가능성을 준비한다.

위험

FlowMe가 검증값, DNS record, HTML tag, OAuth grant, API key, sitemap file, ranking goal을 저장하면 안 된다.

공식 소스 스냅샷

아래 표는 기존 문서에 기록된 2026-06-09 확인 내용을 읽기 쉽게 옮긴 것이다. 이 HTML은 새 소스 재검증 문서가 아니다.

소스 FlowMe 해석
Naver Search Advisor 진단 페이지 title, description, robot blocking, 검색 친화 기본을 precheck row로 바꿀 수 있지만 점수화하지 않는다.
SEO 기본 가이드 robot access, sitemap/RSS, 사이트 검색 결과, noindex, frame, redirect, 개발자 도움을 분리한다. 노출 약속이 아니라 접근과 상태부터 시작한다.
소유권 확인 소개 웹마스터 작업은 수집/삭제 요청/리포트에 영향을 줄 수 있다. FlowMe는 방법명과 상태만 저장하고 검증값은 저장하지 않는다.
소유권 확인 문제 해결 protocol mismatch, 계정별 HTML/tag, index page, robot blocking, redirect는 ask developer/host admin 판단점이 된다.
HTML 파일 업로드 root-folder access 또는 hosting-provider help가 필요하다. FlowMe는 root upload access 여부를 먼저 묻는다.
HTML tag 방식 첫 페이지 head 편집 가능 여부만 기록한다. tag content는 저장하지 않는다.
리포트/진단 가이드 수집 제한, noindex, 진단, 리포트 지연, 재수집 대기는 status note다. 즉시 색인을 약속하지 않는다.
sitemap 존재와 수집 sitemap/RSS 상태를 기록하되 검색 반영 보장으로 해석하지 않는다.

사용자 시나리오

사용자 필요

한국어 커스텀 사이트 운영자가 Naver Search Advisor 설정을 준비하면서, 어떤 소유권 방법을 쓸 수 있는지, 수집 전제 조건이 맞는지, 무엇을 개발자나 호스팅 관리자에게 물어봐야 하는지, 언제 다시 확인해야 하는지를 알고 싶다.

제안 리뷰 artifact

UI는 플랫폼 세부 설명보다 사용자가 가진 접근 권한 선택을 먼저 물어야 한다.

1. 사이트 단위와 접근권한

custom domain, host/CMS, URL 단위를 고르고 DNS, root upload, head edit 접근 여부를 기록한다.

2. 소유권 방법 상태

HTML file, HTML tag, ask developer/host admin 중 하나를 상태로 둔다.

3. crawl/noindex 준비

robots.txt, noindex, redirect/frame, live accessibility를 확인한다.

4. sitemap/RSS/request 상태

submitted, unavailable, skipped, ask developer 상태만 기록한다.

5. 다시 볼 날짜

ownership, diagnosis, collection, sitemap/RSS, report status를 다시 볼 날짜를 둔다.

구현 게이트

충족 조건
  1. candidate id는 naver-search-advisor-site-readiness다.
  2. source type은 official이다.
  3. 첫 행동은 sitemap 제출이나 ranking improvement가 아니라 access/method selection이다.
  4. ownership verification, crawl/collection, indexing/search reflection, diagnosis/report, ranking을 구분한다.
  5. ask developer/host admin을 정상 상태로 지원한다.
금지 조건
  • 검증값, DNS 값, HTML tag, OAuth, API key, credential을 title, memo, export, test 어디에도 넣지 않는다.
  • public route, OAuth import, DNS automation, sitemap generation, IndexNow/API automation을 만들지 않는다.
  • SEO score, ranking tracker, analytics dashboard를 만들지 않는다.

첫 구현 시나리오에서 제외한 범위

범용 multi-platform

Google, Naver, Bing을 한 UI에 섞으면 첫 UI pass에는 변동성이 크다.

Google-first 또는 Bing import

유용한 비교군이지만 Korean-first가 아니거나 OAuth/account import 경계가 무겁다.

SEO ranking improvement

FlowMe artifact가 아니고 성과 기대를 잘못 만든다.
