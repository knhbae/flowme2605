# P25-00B 화면 구조 결정

프로토타입: [prototype.html](./prototype.html)

## 검토 방법

1. 기본값인 `B 작업공간`과 `390px`을 유지합니다.
2. Flow 유형을 `이사`, `차량 점검`, `반복 청소`, `여행`, `기록`, `개인 초안` 순서로 바꿔 봅니다.
3. 왼쪽의 아홉 화면을 순서대로 엽니다.
4. 필요할 때만 `A 최소 수정`과 비교합니다.
5. 각 화면에서 `유지 / 수정 / 기각` 중 하나를 선택하고, 수정이면 한 줄 메모를 적습니다.
6. 마지막에 `결정 JSON 복사`를 눌러 이 대화에 붙여넣습니다.

## 꼭 결정할 9가지

| 화면 | 추천 | 결정 | 확인할 한 가지 |
| --- | --- | --- | --- |
| 저장 전 | B | 미정 | 전체 항목을 먼저 보여주고 `먼저 조정 / 이 Flow 저장`을 둘 것인가 |
| 저장 직후 | B | 미정 | Today 대신 저장한 전체 Flow를 바로 보여줄 것인가 |
| My Flow | B | 미정 | local IA를 `지금 / 내 Flow / 완료`로 둘 것인가 |
| 전체 Flow | B | 미정 | 모바일 drill-in, wide 3-pane을 같은 component로 만들 것인가 |
| Calendar | B | 미정 | `언제든 할 일`과 `일정에 놓기`의 역할을 분리할 것인가 |
| 항목 조정 | B | 미정 | 기본 필드를 제목·언제·메모로 제한할 것인가 |
| 여러 항목 | B | 미정 | 날짜 이동·지우기·포함·가져가기 batch action을 둘 것인가 |
| 완료·재개 | B | 미정 | 즉시 undo와 완료 목록 재개를 모두 제공할 것인가 |
| 가져가기 | B | 미정 | 범위 → 예상 개수 → 형식 순서를 고정할 것인가 |

## 빠른 응답 형식

프로토타입을 직접 클릭하기 어렵다면 아래만 채워도 됩니다.

```text
저장 전: 유지 / 수정 / 기각 -
저장 직후: 유지 / 수정 / 기각 -
My Flow: 유지 / 수정 / 기각 -
전체 Flow: 유지 / 수정 / 기각 -
Calendar: 유지 / 수정 / 기각 -
항목 조정: 유지 / 수정 / 기각 -
여러 항목: 유지 / 수정 / 기각 -
완료·재개: 유지 / 수정 / 기각 -
가져가기: 유지 / 수정 / 기각 -
```

결정 전에는 P25-02 이후 runtime 화면 구현을 시작하지 않습니다. P25-01 correctness는 화면 결정과 독립적으로 진행할 수 있습니다.
