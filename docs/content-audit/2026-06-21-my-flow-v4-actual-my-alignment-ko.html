My Flow v4 기준을 실제 /my에 맞춘 결과

저장한 Flow가 1개일 때와 여러 개일 때의 모바일 복잡도를 다시 확인했다. 결론은 실제 /my도 v4 PoC처럼 “오늘 실행 먼저, 관리 기능은 필요할 때” 쪽으로 더 줄이는 것이 맞다.

v4 사용자 화면 완료 토글 A/B 판단 서비스 UX 백로그

이번에 테스트한 질문

1개 저장탭, 상태판, 목록 관리 없이 바로 실행 화면처럼 보여도 되는가.
4개 이상 저장오늘 항목과 Flow 찾기만 먼저 보여도 사용자가 길을 잃지 않는가.
보조 상태 버튼밀린 Flow, 다음 실행 같은 단축 버튼이 실제 가치보다 관리 부담을 키우는가.

확인 결과

영역이전 상태수정 후판단
1개 저장 모바일 상단에 오늘, 캘린더, Flow 탭이 남아 있어 단일 Flow도 관리 화면처럼 보였다. 모바일 단일 저장에서는 탭을 숨기고 Today 실행 화면만 보여준다. 전세/10개 Flow 기준에 더 가까움. 한 개만 저장한 사용자는 관리보다 실행이 먼저다.
Today 요약 모바일에서도 남음, 루틴, 밀림 숫자 카드가 보여 상태판 느낌이 강했다. 모바일에서는 숫자 카드가 숨겨지고 문장 요약과 실행 목록만 남는다. Apple/Galaxy/Toss식으로 보면 첫 화면의 해석 비용이 줄었다.
Flow 탭 모바일 Flow 찾기 아래에 밀린 Flow, 다음 실행 버튼이 다시 나왔다. Flow 찾기만 남기고 상태 버튼을 제거했다. 여러 개 저장에서도 첫 단계는 검색/열기 하나면 충분하다. 상태별 분류는 나중에 다시 열 수 있다.

UX 판단

지금 단계의 My Flow는 프로젝트 관리 앱이 아니라, 저장한 실행 항목을 다시 열어 체크하고 메모하는 공간이다. 따라서 사용자가 처음 보는 모바일 화면은 상태 분류보다 현재 실행 항목을 우선해야 한다.

  • 1개 저장: 바로 실행. 전역 탭은 숨김.
  • 4~8개 저장: 오늘 항목 우선. Flow 찾기는 접거나 한 번의 버튼으로 열기.
  • 8개 이상: 검색과 필터가 필요하지만, 첫 화면에 상태 버튼을 늘어놓지 않음.
