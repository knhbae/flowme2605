# 온라인 출처 유형별 Flow 적합성 1차 검증

Date: 2026-05-31
Status: 1차 검색 기반 비교 분석

## 목적

FlowMe의 원래 가설은 "사용자가 온라인 콘텐츠에서 따라 할 부분을 잘 메모하고, 그것을 보면서 계획대로 실행한다"이다. 따라서 공식 문서만 보면 충분하지 않다. 실제 사용자는 블로그, 유튜브, 후기, 브랜드 가이드, 커뮤니티 글, 상업 페이지를 함께 보고 판단한다.

이 문서는 실제 온라인 출처를 섞어 보고, 어떤 콘텐츠가 Flow로 만들기 좋은지, 어떤 콘텐츠는 조건부로만 가능한지, 어떤 콘텐츠는 Flow로 만들면 안 되는지 나눈다.

## 판정 기준

| 판정 | 의미 |
| --- | --- |
| 가능 | 날짜, 반복, 순서, 체크, 기록, 비교, 제출, 예약, 결정 같은 실행 구조가 분명하다. 필수 입력도 1-3개 정도로 줄일 수 있다. |
| 조건부 가능 | Flow 소재는 있지만 출처 확인, 위험 분리, 상업성 제거, 입력 단순화, 저작권/원문 의존성 정리가 필요하다. |
| 불가능 | 실행 구조가 없거나, 위험한 조언을 따라 하게 만들거나, 단순 광고/랭킹/연예/의견성 콘텐츠라 FlowMe의 실행 레이어가 개입할 이유가 약하다. |

## 출처 유형별 기본 판단

| 출처 유형 | FlowMe 적합성 | 이유 |
| --- | --- | --- |
| 공식 가이드/공공기관/제조사 매뉴얼 | 높음 | 기준일, 주기, 절차, 제출/예약, 주의사항이 명확한 경우가 많다. 다만 원문을 그대로 복사하지 않고 실행 항목으로 요약해야 한다. |
| 블로그/경험담 | 중간-높음 | 실제 사용자의 순서, 실수, 비교 기준이 들어 있어 Flow화 가치가 크다. 단, 개인 경험과 공식 사실을 분리해야 한다. |
| 유튜브/영상 | 중간 | 따라 하기, 운동, 요리, 청소, 공부 루틴에 강하다. 단, 영상 자체가 상세 실행 매뉴얼이므로 Flow는 "열고 따라 하기 + 기록/반복" 수준으로 얇게 만들어야 한다. |
| 커뮤니티/후기 | 중간 | 실제 시행착오와 판단 기준을 얻기 좋다. 하지만 사실 확인이 약하므로 단독 출처로 공개 Flow를 만들면 위험하다. |
| 상업 페이지/서비스 안내 | 낮음-중간 | 예약/비교/문의 Flow에는 쓸 수 있지만, 특정 업체 홍보를 중립 정보처럼 만들면 안 된다. |
| 투자/의료/법률/안전 조언 콘텐츠 | 조건부 또는 불가능 | 기록/학습/공식 확인 Flow는 가능하지만, 행동을 권고하거나 결과를 보장하는 Flow는 만들면 안 된다. |

아래 패턴은 FlowMe에 잘 맞는다.

1. 날짜/마감 기반 콘텐츠
   - 예: 이사 D-day, 시험일, 출국일, 면허 갱신일, 예방접종 기간.
   - 이유: 사용자가 기준일 하나만 넣으면 캘린더와 체크리스트가 바로 생긴다.

2. 반복 관리 콘텐츠
   - 예: 에어컨 필터 2주 청소, 정수기 필터 교체, 식물 물주기, 운동 루틴.
   - 이유: 반복 주기와 완료 체크가 명확하다.

3. 비교/결정 콘텐츠
   - 예: 중고차 구매, 가전 구매, 보험 갱신, 전월세 계약.
   - 이유: 시트, 메모, 보류/결정 상태가 일반 todo 앱보다 잘 맞는다.

4. 기록/관찰 콘텐츠
   - 예: 이유식 반응, 다이어트 기록, 반려동물 체중, 수면 컨디션.
   - 이유: "완료"보다 "기록함"이 핵심인 Flow가 된다.

5. 공식 정보 + 개인 메모 결합 콘텐츠
   - 예: 해외안전여행 공식 정보 + 내 여행국 비상카드.
   - 이유: 공식 출처는 고정하고, 사용자는 연락처/일정/메모만 채우면 된다.

## 조건부 가능 콘텐츠 패턴

아래 패턴은 소재는 좋지만 그대로 Flow로 만들면 위험하거나 복잡해진다.

1. 블로그형 "총정리"
   - 문제: 정보량이 많고, 공식 사실/개인 의견/광고 링크가 섞인다.
   - 처리: 사용자의 실행 항목만 남기고, 주의/출처/경험담은 상세 메모로 분리한다.

2. 유튜브 따라 하기 영상
   - 문제: 영상 자체가 상세 실행 설명이므로 Flow가 동작 순서를 임의로 재작성하면 왜곡된다.
   - 처리: Flow item은 "영상 열기, 따라 하기, 기록하기, 다음 반복일 정하기" 정도로 둔다.

3. 상업 서비스 페이지
   - 문제: 특정 업체의 판매 페이지를 중립 가이드처럼 만들 수 있다.
   - 처리: 예약/문의/비교표 Flow에는 쓰되, 업체 주장은 source note로 제한한다.

4. 건강/육아/다이어트 콘텐츠
   - 문제: 사용자에게 잘못된 판단이나 자기진단을 유도할 수 있다.
   - 처리: 공식 정보와 관찰 기록 중심으로 만들고, 이상 반응/중단/전문가 상담 기준을 분리한다.

5. 공부 후기
   - 문제: 개인의 합격 경험이 일반 전략처럼 보일 수 있다.
   - 처리: "기출 풀이/오답 기록/채점/복습" 같은 실행 루틴만 추출한다.

## 불가능 또는 공개 Flow 금지 패턴

아래 콘텐츠는 FlowMe에서 바로 실행 Flow로 만들면 안 된다.

1. 투자 종목/매매기법 따라 하기
   - 이유: 재무 조언처럼 보이고 사용자가 손실 위험을 직접 떠안는다.
   - 가능한 대체: 투자 공부 자료 메모, 리스크 체크, 공식 공시 확인 루틴.

2. 고난도 수리/전기/분해 작업
   - 이유: 사용자가 다치거나 제품을 손상시킬 수 있다.
   - 가능한 대체: 전문가 예약, 전원 차단 확인, 모델명/증상 메모.

3. 의료 판단/치료 지시
   - 이유: 증상 판단과 치료 선택은 FlowMe가 대신할 수 없다.
   - 가능한 대체: 증상 기록, 병원 방문 준비, 공식 안내 링크 저장.

4. 순수 랭킹/추천/연예/트렌드 콘텐츠
   - 이유: 사용자의 실행 결과물이 없거나 단순 소비에 가깝다.
   - 가능한 대체: 볼거리 저장 목록 정도지만 FlowMe 핵심 사용성 검증에는 약하다.

5. 광고성 랜딩 페이지
   - 이유: 사용자의 실행 계획보다 구매 유도에 최적화되어 있다.
   - 가능한 대체: 여러 업체 비교표의 한 후보로만 사용.

## 대표 변환 예시

상세 배치:

- [집/가전 관리 출처 상세 검증](./2026-05-31-home-appliance-source-validation.md)

### 예시 1. 에어컨 필터 관리 Flow

출처 묶음:

- 삼성전자서비스 시스템 1WAY 필터 청소 및 관리 방법
- 삼성전자서비스 여름 전 에어컨 확인 사항
- Solidtips 에어컨 청소 총정리
- 다나와 DPG 에어컨 분해 청소 체험

원 콘텐츠 요약:

- 공식 출처는 필터 분리/세척/건조/재장착/리셋과 전원 차단, 모델별 차이, 실외기 주변 정리 같은 실행 기준을 제공한다.
- 블로그와 기사형 콘텐츠는 셀프 청소 범위, 청소 주기, 분해 청소 판단, 비용 감각을 보완한다.
- 위험 정보는 전원 차단, 사다리 사용, 무리한 분해, 제품별 필터 차이, 전문 서비스 필요 영역이다.

Flow 콘텐츠화:

- 사용자 니즈: 에어컨을 쓰기 전과 사용 중에 필터/실외기/리모컨을 가볍게 점검해서 여름철 고장과 냄새를 줄이고 싶다.
- 주 목적지: 캘린더
- 구조 타입: 계절 점검 + 반복 루틴
- 기준점: 여름 사용 시작월 또는 마지막 청소일
- 필수 입력: 에어컨 이름, 마지막 필터 청소일, 반복 주기
- 선택 입력: 모델명, 제조사 링크, 전문 청소 예약 메모
- 권장 item 수: 5-7개
- 완료 모델: 점검함 / 청소함 / 전문가 예약함 / 보류함

Flow 초안:

1. 여름 전 에어컨 상태 확인
   - 타입: scheduled_task
   - 시점: 사용 시작 2-4주 전
   - 완료 기준: 전원, 리모컨, 실외기 주변, 필터 상태를 확인했다.
2. 필터 분리 전 전원 차단
   - 타입: check_task
   - 시점: 청소 당일
   - 완료 기준: 제품 운전을 멈추고 전원 차단을 확인했다.
3. 필터 세척 후 완전 건조
   - 타입: scheduled_task
   - 시점: 청소 당일
   - 완료 기준: 필터를 세척하고 그늘에서 충분히 말렸다.
4. 필터 리셋과 다음 청소일 설정
   - 타입: routine_session
   - 시점: 청소 후
   - 완료 기준: 필터 알림을 리셋하고 다음 반복 알림을 설정했다.
5. 분해 청소 필요 여부 판단
   - 타입: decision_hold
   - 시점: 냄새/곰팡이/성능 저하가 있을 때
   - 완료 기준: 직접 청소/전문가 예약/보류 중 하나로 결정했다.

판정: 가능

이유: 공식 출처로 기준을 세우고, 블로그/영상은 실전 보완 메모로 쓸 수 있다. 입력 부담도 낮다.

### 예시 2. 중고차 구매 점검 Flow

출처 묶음:

- 카히스토리 사고이력조회
- TrendMetricLab 중고차 구매 체크리스트
- Getcha 중고차 사고이력/주행거리 확인 가이드

원 콘텐츠 요약:

- 공식 서비스는 차량번호 기반 사고이력, 침수, 폐차사고, 차량기준가액 조회를 제공한다.
- 블로그/가이드는 성능점검기록부, 보험이력, 실차 확인, 시세 비교, 명의이전 등 구매 전 순서를 설명한다.
- 개인/상업 출처는 유용하지만 "피해 예방률" 같은 강한 주장은 그대로 쓰면 안 된다.

Flow 콘텐츠화:

- 사용자 니즈: 중고차 후보를 보기 전에 차량별 기록을 비교하고, 구매/보류/거절 결정을 남기고 싶다.
- 주 목적지: 시트
- 구조 타입: 비교/결정
- 기준점: 후보 차량
- 필수 입력: 차량명, 차량번호, 판매 링크
- 선택 입력: 예산, 주행거리, 판매자 연락처, 방문일
- 권장 item 수: 후보별 6-8개 체크
- 완료 모델: 구매함 / 보류함 / 거절함

Flow 초안:

1. 후보 차량 기본 정보 입력
   - 타입: check_task
   - 완료 기준: 차량명, 차량번호, 가격, 링크를 저장했다.
2. 사고/침수/폐차 이력 조회
   - 타입: scheduled_task
   - 완료 기준: 카히스토리 결과를 확인하고 메모했다.
3. 성능점검기록부와 이력 대조
   - 타입: memo_evidence
   - 완료 기준: 기록부와 조회 결과가 맞는지 확인했다.
4. 실차 확인 항목 촬영/메모
   - 타입: memo_evidence
   - 완료 기준: 외관, 타이어, 누유, 실내, 소모품 상태를 기록했다.
5. 구매/보류/거절 결정
   - 타입: decision_hold
   - 완료 기준: 최종 상태와 이유를 남겼다.

판정: 가능

이유: FlowMe가 일반 todo보다 잘할 수 있는 비교표, 메모, 결정/보류 UX가 분명하다.

### 예시 3. 이유식 반응 기록 Flow

출처 묶음:

- 어린이집 정보공개포털 이유식 식단 안내문
- 어린이집 정보공개포털 영아기 이유식 자료
- 필립스 아벤트 이유식 레시피 PDF

원 콘텐츠 요약:

- 공공/기관 자료는 월령별 재료, 형태, 제공 횟수, 알레르기 반응 시 중단/대체 기록 같은 구조를 제공한다.
- 브랜드 레시피는 메뉴 아이디어를 제공하지만 제품 홍보와 건강 표현이 섞일 수 있다.
- 의료 판단은 FlowMe가 하지 않고, 반응 기록과 출처 확인만 맡아야 한다.

Flow 콘텐츠화:

- 사용자 니즈: 오늘 먹인 이유식 재료와 아이 반응을 간단히 기록해 다음 식단을 안전하게 이어가고 싶다.
- 주 목적지: 시트
- 구조 타입: 기록/관찰 + 루틴
- 기준점: 아이 월령과 식단일
- 필수 입력: 아이 월령, 오늘 새 재료, 식단일
- 선택 입력: 메뉴명, 양, 사진, 특이 반응 메모
- 권장 item 수: 하루 2-4개
- 완료 모델: 먹임 / 반응 기록함 / 중단함 / 병원 문의함

Flow 초안:

1. 오늘 새 재료 확인
   - 타입: check_task
   - 완료 기준: 오늘 처음 먹이는 재료가 무엇인지 기록했다.
2. 이유식 제공 후 반응 기록
   - 타입: log_entry
   - 완료 기준: 피부, 구토, 설사, 호흡 이상 여부를 메모했다.
3. 이상 반응 시 중단/대체 표시
   - 타입: decision_hold
   - 완료 기준: 중단, 대체, 문의 중 하나로 표시했다.
4. 다음 식단에 반영
   - 타입: scheduled_task
   - 완료 기준: 다음 식단 또는 새 재료 일정을 조정했다.

판정: 조건부 가능

이유: 구조는 강하지만 민감도가 높다. 공식 출처와 보호자 기록 중심으로만 다뤄야 한다.

### 예시 4. 해외여행 안전 카드 Flow

출처 묶음:

- 외교부 해외안전여행
- 외교부 위기상황별 대처매뉴얼
- 외교부 국가/지역별 여행정보

원 콘텐츠 요약:

- 외교부는 국가/지역별 여행경보, 재외공관 연락처, 현지 신고번호, 의료기관 정보, 위기 상황별 대처 정보를 제공한다.
- 사용자는 여행국가와 출국일을 기준으로 비상 연락처 메모를 만들 수 있다.
- 긴 대처 매뉴얼 전체를 Flow item으로 쪼개기보다, 여행 전에 확인해야 할 항목과 비상 카드로 압축하는 것이 맞다.

Flow 콘텐츠화:

- 사용자 니즈: 출국 전에 여행국가의 공식 안전정보와 비상 연락처를 한 곳에 저장해두고 싶다.
- 주 목적지: 메모
- 구조 타입: 안전 카드 + 출국 전 체크
- 기준점: 출국일, 여행국가
- 필수 입력: 여행국가, 출국일, 동행자 연락처
- 선택 입력: 숙소 주소, 보험 정보, 현지 일정
- 권장 item 수: 5-6개
- 완료 모델: 확인함 / 저장함 / 공유함

Flow 초안:

1. 여행국가 안전정보 확인
   - 타입: scheduled_task
   - 시점: 출국 7일 전
   - 완료 기준: 외교부 국가 정보를 확인했다.
2. 재외공관/현지 신고번호 저장
   - 타입: memo_evidence
   - 완료 기준: 대사관, 경찰, 의료 연락처를 메모했다.
3. 가족/동행자에게 일정 공유
   - 타입: check_task
   - 완료 기준: 일정과 비상 연락처를 공유했다.
4. 출국 전 최종 안전 공지 확인
   - 타입: scheduled_task
   - 시점: 출국 1일 전
   - 완료 기준: 최신 안전 공지를 다시 확인했다.

판정: 가능

이유: 공식 출처와 개인 메모가 결합되는 대표적인 메모 중심 Flow다.

## 제품 관점 결론

1. FlowMe의 강점은 "콘텐츠 요약"이 아니라 "출처에서 실행 구조를 찾아 사용자의 캘린더/체크/시트/메모로 옮기는 것"이다.
2. 공식 출처는 기준과 주의사항을 제공하고, 블로그/유튜브는 실제 순서와 시행착오를 제공한다. 둘을 섞되, 같은 레벨로 보이면 안 된다.
3. 가능한 콘텐츠는 생각보다 많다. 특히 집/가전, 자동차, 여행, 공부, 육아/이유식, 반려동물 행정, 창작 운영은 구조가 분명하다.
4. 불가능 콘텐츠도 명확하다. 투자 따라 하기, 의료 판단, 위험한 분해/수리, 순수 랭킹/추천/연예/광고성 콘텐츠는 공개 Flow로 만들면 안 된다.
5. My Flow UI는 `출처`, `메모`, `상세`, `주의`, `결정/보류`를 모두 전면에 노출하면 복잡해진다. 기본은 캘린더/체크/시트/메모 앱 수준으로 두고, 출처/주의/경험담은 상세로 내려야 한다.

## 다음 검증 배치

다음 배치는 출처 수를 늘리되, 카테고리별로 같은 유형을 비교한다.

1. 집/가전 관리: 제조사 공식 3개, 블로그 3개, 유튜브/영상 3개, 상업 서비스 3개.
2. 공부/자격증: 공식 시험 안내 2개, 교재/자료실 3개, 합격 후기 5개, 유튜브 공부법 3개.
3. 여행: 외교부/공항/항공사 공식 3개, 여행 블로그 5개, 짐싸기 영상 3개.
4. 육아/이유식: 공공/병원성 출처 3개, 보호자 블로그 5개, 레시피/브랜드 3개.
5. 돈/저축: 자동이체/구독 공식 출처 3개, 저축 챌린지 블로그 5개, 투자성 콘텐츠 reject 사례 5개.

각 배치는 `원 콘텐츠 요약`, `Flow 콘텐츠화`, `가능/조건부/불가능 판정`을 같은 문서에 남긴다.
