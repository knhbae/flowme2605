연결된 내부 문서의 주요 읽기 경로는 한국어 HTML로 덮였다

이 감사 문서는 외부 생태계 분석방에서 계속 참고해야 하는 로드맵, 압축표, 제품 규칙, 게이트, 보조 분석 문서가 한국어 HTML 진입점을 갖고 있는지 확인한다. 원문 Markdown은 source-of-record로 유지한다.

주요 연결 문서: HTML entrypoint 있음 Markdown 링크: 원문 추적용 아님: 최신 소스 검증 · 사용자 행동 검증 · 통합 승인
Primary Path

운영 인덱스 → 로드맵 → 연결 허브

분석방을 다시 열 때 필요한 첫 세 문서가 모두 HTML로 연결되어 있다.

Decision Path

Phase 1 · Phase 5 · 제품 규칙

후보 순서, 압축표, export/integration 규칙이 독립 HTML로 분리되었다.

Gate Path

기숙사 · 초등 · 원격 · 검색콘솔

현재 후보와 경계 문서도 긴 Markdown 없이 읽을 수 있다.

2. 추천 읽기 경로

  1. 분석방 운영 인덱스에서 전체 방향을 잡는다.
  2. 로드맵 원문 HTML로 분석 루프를 확인하고, 로드맵 시각화로 빠르게 스캔한다.
  3. 연결 문서 허브에서 세부 문서로 이동한다.
  4. 활성 배포 채널 축은 현재 상태 시작점과 허브 실행 순서를 먼저 열어 no signal, 세션 0 / 3, 다음 초대/스케줄링 행동을 확인한다.
  5. Stage 0 phase 체크포인트로 지금 작업이 Phase 5 / Stage 0 범위인지 확인한다.
  6. 문서 추가 중단 게이트로 같은 축의 planning doc을 더 만들 조건이 있는지 확인한다.
  7. 세션을 잡기 전에는 관찰 초대 문구로 15분 이해 확인과 민감값 미수집 경계를 맞춘다.
  8. 초대 발송 직후 스케줄 트래커 snippets에서 matching role-labeled row만 invited로 바꾼다.
  9. 답장으로 참여가 확인된 뒤에만 해당 slot을 agreed로 옮긴다. invited, agreed, scheduled, not run은 관찰 증거가 아니다.
  10. 최종 초대나 세션 전에는 버전 고정표로 같은 패킷 조건을 맞춘다.
  11. 세션 답변은 응답 코딩 기준표로 pass/fail/unclear를 맞춘다.
  12. 첫 세션 전에는 preflight 체크리스트로 모든 go/no-go gate를 확인한다.
  13. 관찰 당일에는 quick start를 먼저 열고 긴 템플릿을 채운다.
  14. 3 completed usable sessions와 채워진 rollup이 생긴 뒤에만 evidence board 업데이트 절차로 보드를 바꾼다.
  15. Phase 5 압축표를 현재 결정 게이트로 사용한다.
  16. Export Destination Fit을 먼저 적용한다.
  17. Integration Readiness Gate는 export behavior evidence가 생긴 뒤에만 적용한다.

3. Markdown 링크가 남아 있는 이유

Source of record

HTML은 읽기용 진입점이고, Markdown은 결정과 수정 이력을 추적하는 원문이다.

보조 노트

일부 later public route note나 source candidate note는 HTML 읽기 경로가 아니라 의사결정 추적용으로 남긴다.

판단: 현재 연결 문서 허브의 Markdown 링크는 누락이 아니라 원문 추적용이다. 주요 읽기 경로는 HTML로 열 수 있다.

4. 다음 축 추가 시 규칙

  1. Markdown handoff를 먼저 만들거나 갱신한다.
  2. 연결 읽기 경로에 들어오면 Korean HTML view를 만든다.
  3. docs/STATUS.md에 Markdown과 HTML을 함께 연결한다.
  4. 로드맵 source list 또는 connected docs hub에 HTML entrypoint를 추가한다.
  5. npm run docs:check를 실행한다.
연결 문서 허브 로드맵 HTML 원문 Markdown
