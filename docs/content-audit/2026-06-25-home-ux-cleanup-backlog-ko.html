왜 지금 이상해 보이는가

홈이 서비스 대표 화면이 아니라 후보 전시장처럼 보이고 있다

전세와 5개 Flow 상세 화면은 괜찮았지만, 홈에서는 대표 Flow Map, 단일 Flow, 추천 카드, 제작 CTA, 실험 후보의 흔적이 같은 무게로 섞였다. 따라서 먼저 컨텐츠를 더 만들기보다 홈의 역할을 줄이고, 대표·탐색·검토 화면을 분리해야 한다. 2차 모바일 피드백에서는 서비스처럼 보이기 시작했지만 Flow Map과 단일 Flow의 시각 패턴 차이, 카탈로그에서 무엇을 고를지 알려주는 신호 부족, 메뉴·액션 트리의 오래된 흔적이 남은 것으로 정리됐다.

홈의 새 역할

홈은 이것만 해야 한다

  • FlowMe가 무엇을 하는 서비스인지 5초 안에 보여준다.
  • 대표 예시 1~2개만 눌러보게 한다.
  • 제작자 CTA는 한 번만 명확하게 둔다.
  • 나머지 탐색은 `/flows`, `/content-flows`, 내부 리포트로 보낸다.

홈에서 빼야 한다

  • 후보, 베타, 출처 연결, 운영 중 같은 내부 평가 문구.
  • 같은 Flow가 여러 카드 묶음에서 반복 노출되는 구조.
  • 미리보기 박스와 버튼이 카드마다 붙어 있는 긴 목록.
  • 단일 Flow와 Flow Map이 같은 무게로 섞이는 추천 전시장.

작업 순서

한 번에 예쁘게 고치기보다, 사용자가 보는 정보량을 줄이는 순서로 닫는다.

1 홈 IA 줄이기 상단 예시 카드와 추천 Flow 반복을 정리한다.
2 대표 예시 1~2개 Flow Map 중심으로 한 번만 강하게 보여준다.
3 단일 Flow 낮추기 보조 섹션 또는 전체 보기로 보낸다.
4 CTA 3개 이하 둘러보기, 만들기, 대표 예시 열기만 남긴다.
5 모바일 리허설 첫 화면, 스크롤, 저장 후 경로를 다시 점수화한다.

2차 모바일 피드백 반영

좋아진 점

  • 홈은 이전보다 서비스처럼 보이기 시작했다.
  • `/flows`는 덜 산만하고 대표 후보만 보는 방향이 맞다.
  • 전세 상세의 저장 액션과 저장 후 `/my` 진입은 자연스럽다.
  • 검토 문구와 설명 과다는 상당히 줄었다.

아직 남은 판단

  • Flow Map 카드와 단일 Flow 카드가 서로 다른 제품처럼 보이지 않게 맞춘다.
  • 카탈로그의 “선택 신호”는 모호한 표현이므로, 저장 후 산출물·첫 실행·내 상황 적합성으로 다시 묻는다.
  • 메뉴와 액션 트리는 별도 route map으로 감사해야 한다. 예전 기능과 새 서비스 표면이 섞인 흔적이 남아 있다.

3차 사용자 피드백 메모

현재 판단

  • 홈은 그럭저럭 서비스 입구처럼 보인다. 다만 FlowMe의 최종 성격이 creator platform, content catalog, personal execution app 중 어디에 더 가까워지는지에 따라 다시 손봐야 한다.
  • 전세 상세에서 저장 후 `/my`로 이어지는 흐름은 자연스럽다.
  • 탭 구성은 나쁘지 않지만, iOS/Android 표준 앱 패턴과 웹 서비스 패턴 사이에서 아직 약간 비표준처럼 느껴진다.
  • 버튼과 설명의 혼선은 완전히 사라지진 않았지만, 전체적으로는 나쁘지 않은 상태다.

다음에 볼 것

  • “왜 이 Flow를 골라야 하는가”라는 질문은 모호했다. 앞으로는 “저장하면 어떤 산출물이 생기고, 첫 실행이 무엇인지”로 평가한다.
  • My Flow 탭은 기능을 더 붙이기 전에 캘린더/투두 앱의 표준 행동과 비교해, 웹이더라도 자연스러운 navigation·detail expansion 규칙을 먼저 정한다.
  • 홈은 지금 더 다듬기보다, 다음 큰 포지셔닝 판단이 생길 때 재조정한다.

4차 모바일 피드백 반영 방향

이번에 바로 반영

  • 홈, `/flows`, `/flow-maps/[map]`, `/my`에 같은 서비스 프레임을 둔다. 모바일은 햄버거, 데스크톱은 탭형 상단 이동으로 보여준다.
  • Flow Map과 단일 Flow 카드는 검토용 `대표 이유`보다 `저장 후 보이는 Step`을 우선 보여준다.
  • Flow Map 공개 상세는 Step 아래 Item 일부를 보여줘 저장 뒤 생길 세부 항목을 예측할 수 있게 한다.
  • My Flow Step 상세는 읽기/체크/내보내기 기본 화면과 날짜·시간·반복·메모 수정 화면을 분리한다.

남길 백로그

  • 리뷰, 저장 수, 현재 사용 중 신호는 중요하지만 실제 데이터가 생기기 전에는 UI에 가짜 지표로 넣지 않는다.
  • Flow Map 아래 Flow가 1개뿐이면 홈에서 타입 구분은 약하게 보일 수 있다. 컨텐츠 수가 늘 때 다시 정보 구조를 조정한다.
  • 카드 수는 더 줄일 여지가 있다. 다음 검토에서는 “서비스 입구”와 “카탈로그”의 역할을 다시 분리해서 본다.

5차 IA / 저장 후 실행 피드백 반영

이번에 바로 반영

  • 유사 서비스 리서치 기준을 반영했다. 템플릿/콘텐츠 갤러리는 탐색과 저장 판단에 집중하고, 저장 후 실행은 오늘/캘린더/프로젝트 상세로 분리한다.
  • `/flows` 상단의 중복 `내 Flow 보기` CTA를 제거했다. 하단 탭이 이미 전역 D0 이동을 담당하기 때문이다.
  • Flow Map 저장 직후 기본 관점을 `Flow별 보기`가 아니라 첫 Step과 `오늘/캘린더` 실행 관점으로 바꿨다.
  • `캘린더에서 열기` 문구는 `캘린더 보기`로 낮췄다. 사용자가 캘린더에 처음 넣는 동작처럼 오해하지 않게 하기 위함이다.

남길 백로그

  • 홈은 아직 `/flows`와 비슷하게 보일 수 있다. 다음 큰 포지셔닝 판단에서 홈을 서비스 설명, 대표 사용 사례, 최근/추천 진입 중심으로 다시 잡는다.
  • Flow Map과 단일 Flow의 차이를 사용자에게 강하게 설명할 필요는 없다. 대신 저장 후 생기는 결과와 첫 실행 Step으로 차이를 느끼게 한다.
  • 캘린더는 전역 탭으로 올리지 않는다. 저장한 Step이 충분히 많아지고 사용자가 전역 캘린더를 기대한다는 증거가 생기면 다시 검토한다.
  • 컨텐츠 수는 더 늘려야 판단이 쉬워진다. 다만 기준을 통과한 대표 후보만 추가하고, 약한 후보는 카탈로그 대표로 올리지 않는다.

이번 구현 반영

1차 감량 뒤 사용자 검토에서 “홈은 줄었지만 상세·저장 경로와 예전 후보가 아직 섞인다”는 문제가 확인됐다. 그래서 홈과 `/flows`를 다시 대표 서비스 카탈로그 기준으로 좁혔다. 대표 노출은 이사 D-30, 전세계약 전 서류 체크, 초등 입학 D-30 세 후보만 남겼고, 중고차·이유식처럼 원문/저장 후 실행 경로가 약한 후보는 삭제하지 않고 direct-route 또는 검토 후보로 내렸다. 전세 상세에는 `내 Flow에 저장` → `/my` 실행 확인 경로를 붙이고, 사용자 화면의 후보/베타/적합도/전환 방식 문구는 숨겼다. 최신 preview는 https://flowme2605-8z13xs141-flowme.vercel.app 이다.
