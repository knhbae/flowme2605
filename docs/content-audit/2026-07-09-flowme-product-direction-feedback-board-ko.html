핵심 판단

FlowMe는 당분간 "URL/메모를 실행 가능한 Flow로 바꾸고, 내 Flow와 Calendar로 이어지는 개인 실행 도구"로 판단한다. Studio/creator는 보조 표면으로 유지하고, 다음 구현 우선순위는 Calendar와 My Flow의 실제 실행 품질이다.

사용자 피드백에서 나온 주요 문제

Calendar 구분 부족

여러 Flow가 같은 색과 비슷한 라벨로 보여 같은 날짜의 실행 항목을 구분하기 어렵다.

시나리오 필수 route/state 판단 질문 우선 evidence
처음 온 사용자 /, /flows, /my, /calendar 제품이 "URL/메모 -> 실행 Flow -> My Flow/Calendar"로 한 문장 안에 잡히는가. 390px, 1024px screenshot
URL-first hit /flows hit, Step include/exclude, export mode 기존 Flow를 찾고 시작하는 가치가 보이는가. 수정 자유도는 충분한가. hit matrix, export mode labels
URL-first miss/candidate /flows miss, candidate form/detail/resolved 요청 저장만으로 충분한가, AI 초안 만들기가 필요해 보이는가. candidate detail text, copy output
Public 공유 진입 /f/vehicle-inspection-prep, /f/moving-d30-basic Flow 단위 저장과 Step 단위 export가 혼동되지 않는가. top, export/body, sticky bottom
My Flow 반복 사용자 /my?savedMap=moving-d30, /my 다중 큐 오늘 할 일을 보고 체크하기까지 depth가 적절한가. post-save, today queue, detail open
Calendar-heavy 사용자 /calendar single/multiple dated Flow Calendar가 실행 화면으로 보이는가. 여러 Flow/동일 날짜가 구분되는가. multi-flow same-day fixture
Creator / Studio /u/flow-curation-team, /u/my-flow-studio 지금 키울 핵심 축인가, 보조 표면으로 둘 것인가. 390px/1024px creator profile

Claude Design에 요청할 판단

요청: 단순 UI polish가 아니라 제품 방향 판단을 해달라고 요청한다. 특히 Calendar와 My Flow가 핵심 실행 화면으로 충분한지, public /f의 저장/export 단위가 맞는지, Studio를 당장 키우는 것이 맞는지를 Blocking/High/Medium/Low로 나누어 달라고 한다.
