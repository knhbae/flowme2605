내 Flow 로컬 탭과 Flow 탭 구조 재정리

질문: 하단 전역 캘린더가 있는데, 내 Flow 상단 탭에도 캘린더가 필요할까? 결론은 아니오. 캘린더는 전역 실행 탭으로 두고, 내 Flow의 로컬 탭은 오늘 실행과 저장한 Flow 구조 관리에 집중한다.

결정

내 Flow 로컬 탭은 오늘 / Flow

날짜 중심 실행은 전역 캘린더가 맡고, 내 Flow는 지금 이어할 항목과 저장한 Flow 구조를 보여준다.

Flow 탭 역할

보관함이 아니라 구조별 이어보기

저장한 Flow별 진행률, 다음 항목, 열린 detail만 보여준다. 전체 목록과 검색은 필요할 때 열도록 둔다.

복잡도 기준

캘린더/투두 앱 수준

기본 카드에는 제목, 진행률, 다음 항목만 둔다. Item, memo, source, edit/export는 Step/detail을 열 때만 보인다.

레퍼런스 비교

인접 서비스는 대체로 시간 기준 실행 화면과 구조 기준 보관 화면을 분리한다. FlowMe도 같은 원칙을 따른다.

비교안

안 구조 판단
A 내 Flow 로컬 탭: 오늘 / 캘린더 / Flow 하단 전역 캘린더와 중복된다. 사용자는 어떤 캘린더를 눌러야 하는지 학습해야 한다.
B 전역 탭: 홈 / Flow 찾기 / 캘린더 / 내 Flow, 내 Flow 로컬 탭: 오늘 / Flow 권장. 날짜 실행과 저장 구조의 역할이 분리된다.
C 내 Flow 로컬 탭 없이 단일 대시보드 저장 Flow가 1개일 때는 좋지만, 3개 이상부터 구조 찾기가 어려워진다.

반영할 화면 구조

  1. 오늘 탭: 지금 이어할 항목 1개, 이번 주·다음 할 일, 오늘 완료 접기. 사용자가 바로 체크할 수 있는 실행 표면.
  2. Flow 탭: 저장한 Flow별 진행률과 다음 항목. 4개 이하라면 카드로 바로 보여주고, 많으면 상위 3개만 보여준 뒤 전체 목록을 bottom sheet로 연다.
  3. 캘린더: 전역 `/calendar`에서 날짜별 실행. 날짜를 누르면 가까운 위치에 해당 날짜 항목이 보이고, 항목 detail은 그 자리에서 열린다.
  4. Step/detail: 기본 카드에는 정보량을 줄이고, Item/checklist/source/memo/edit/export는 열었을 때만 보인다.

이번 개발 반영

  • `/my` 로컬 상단 탭에서 `캘린더` 제거.
  • `/calendar`를 전역 일정 실행 표면으로 유지.
  • 모바일 `Flow` 탭의 빈 허브형 문구를 줄이고, 상위 3개 Flow의 다음 항목을 바로 보여준다.
  • 전체 목록, 검색, 필터는 `전체 Flow 목록 열기`로 분리.
  • 테스트는 `/my` 로컬 캘린더 클릭이 아니라 `/calendar` 경로를 검증하도록 수정.
