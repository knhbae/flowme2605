EXECUTIVE SUMMARY

한 장 요약

결론 ① 공백은 실재하고, 아직 비어 있다

"외부 컨텐츠 → 개인 실행물" 변환은 여행(Wanderlog) · 요리(레시피 앱) 같은 버티컬에서는 이미 증명된 모델이다. 그러나 한국어 생활 전반을 가로지르는 수평 변환 계층은 2026년 6월 현재 비어 있다. ChatGPT Tasks는 캘린더 미연동 베타(작업 10개 제한)이고, Notion AI는 업무 워크스페이스 내부 자동화에 집중하고 있다.

결론 ② 정면 수평 전략은 위험, 버티컬 웨지로 진입

"아무 컨텐츠나 변환"은 범용 AI와 정면충돌하고 품질 보증이 불가능하다. 권고 전략은 옵션 B: 생활 이벤트 준비(입학 · 이사 · 계약 · 살림) 버티컬 웨지 → 인접 확장. 현재 5개 공개 라우트가 이미 이 방향에 정렬되어 있다.

결론 ③ 해자는 변환이 아니라 실행 데이터

변환 자체는 LLM 보편화로 복제 가능하다. 축적 해자는 ① 카테고리별 변환 플레이북 ② 실행률 데이터(어떤 컨텐츠가 실제 완료되는가) ③ 크리에이터 공급 관계. 따라서 발전 경로는 도구 → 기록 → 데이터 네트워크 순이다.

결론 ④ 다음 분기점은 기능이 아니라 행동 증거

현재 관찰 세션 0/3 · no signal. 이 리포트의 모든 전략은 관찰 3회의 결과를 첫 게이트로 한다. 2라운드 연속 no signal이면 패킷이 아니라 카테고리 선택 자체를 재검토한다(킬 기준 §10).

SECTION 2

수요 증거: "저장 ≠ 실행" 문제는 실재하는가

Q1에 대한 답: 그렇다. 세 가지 시장 신호가 같은 방향을 가리킨다 — 컨텐츠 소비는 폭증, "나중에 보기" 모델은 사망, 실행 관리 수요는 성장.

월 40시간 한국인 유튜브 월평균 사용시간 (2019년 21시간의 약 2배) · 이용자는 인구의 81%+ [외부] 와이즈앱 / 서울경제 · 아세안익스프레스
† 2025.7 Pocket(이용자 1,000만+) 서비스 종료 — "저장해두고 안 읽는" 모델의 상징적 사망 [외부] Mozilla / TechCrunch
500만+ 루티너리 글로벌 이용자 — 한국발 루틴/실행 관리 앱의 성장 (마이루틴 · 챌린저스 등 '갓생' 시장) [외부] Routinery 공식 · App Store

신호를 연결하면

① 사람들은 그 어느 때보다 많은 실행형 컨텐츠(준비법 · 절차 · 루틴 · 레시피)를 소비하고 있다. ② 그러나 "저장해두기"는 실행으로 이어지지 않았고, 그 모델의 대표 제품이 문을 닫았다. ③ 동시에 "실행을 관리해주는" 앱들은 성장 중이다 — 단, 이들은 모두 사용자가 직접 입력한 할 일만 다룬다.

비어 있는 연결고리

소비한 컨텐츠와 실행 관리 도구 사이를 잇는 제품이 없다. 컨텐츠는 많고, 실행 도구도 많은데, 컨텐츠가 실행 도구로 건너가는 다리는 사용자의 수작업이다. 이 다리가 FlowMe의 자리다.

단, 주의할 해석: 이 신호들은 "문제의 실재"를 지지할 뿐 "FlowMe 방식의 수요"를 증명하지 않는다. 후자는 오직 관찰 세션과 export 행동 데이터로만 증명된다. [가설→검증 대기]

SECTION 4

원천 레이어 진단: 공급은 충분한가, 안전한가

결론: 공급량은 문제가 아니다. 문제는 신뢰 계층화(공식 vs 경험담)와 권리 관계(크리에이터)다. 이 둘을 제품 규칙으로 풀었는지가 원천 전략의 품질을 결정한다.

SECTION 5

목적지 전략의 본질은 기술이 아니라 관계 설계다: 모든 목적지와 비적대 관계를 유지하면서, 연동은 행동 증거가 모인 곳에만 판다.

왜 export-first가 전략적으로도 옳은가

  • 비적대성: 연동 없이 모든 도구에 도달 → 어떤 플랫폼의 견제도 받지 않는다
  • 측정 가능성: 어떤 목적지로의 export가 반복되는지가 곧 연동 우선순위 데이터가 된다
  • 신뢰 비용 절감: OAuth · 토큰 없이 시작 → 개인정보 우려가 큰 생활 영역에서 진입 장벽 최소화

목적지 레이어의 시한

목적지들이 자체 AI import를 강화할수록(§6) "export 받아주는 그릇"의 수용력은 좋아지지만, 동시에 그들이 변환까지 삼킬 가능성도 커진다. export 친화 환경은 기회이자 카운트다운이다 — Stage 0 검증을 길게 끌 수 없는 이유.

SECTION 6

경쟁 환경: 2026년 6월, 그들은 실제로 어디까지 왔나

경쟁을 3개의 링으로 나눠 최신 동향을 조사했다. 결론: 모두가 변환 계층 근처까지 왔지만, 아무도 "외부 생활 컨텐츠 → 개인 실행물"에 서 있지 않다.

링 1 · 범용 AI

ChatGPT · Perplexity

현재 위치 [외부]: ChatGPT Tasks는 리마인더/예약 실행 베타 — 활성 작업 10개 제한, 캘린더 미연동, 모바일/맥 한정. Google/MS 캘린더 쓰기 액션은 시작됨.

판정: 방향은 명확히 이쪽이다. 다만 범용 채팅 UX는 "산출물 미리보기 → 수정 → 내보내기" 워크벤치가 아니며, 한국 생활 컨텐츠의 소스 결속 품질은 우선순위가 아니다. 시간 창은 있지만 좁다 (12~24개월 추정 [가설]).

링 2 · 생산성 플랫폼

Notion · Motion · ClickUp

현재 위치 [외부]: Notion 3.5(2026-05)는 커스텀 에이전트 · 개발자 플랫폼 · 외부 에이전트 협업으로 진화 — 초점은 업무 워크스페이스 내부 자동화. Motion/ClickUp도 팀 업무의 AI 일정화에 집중.

판정: 이들의 전장은 B2B 업무다. 생활 컨텐츠 변환은 이들의 로드맵에 없다. 단, Notion 템플릿 생태계가 "빈 구조"를 계속 공급하므로 FlowMe는 "소스에서 미리 채워진 구조"로 차별을 유지해야 한다.

링 3 · 버티컬 액션 컴파일러

Wanderlog · 레시피 앱 · Taskade류

현재 위치 [외부]: Wanderlog는 예약 메일 → 여행 일정 자동 변환으로 성공. 레시피 앱은 글 → 재료/조리 단계 변환을 보편화. Taskade · MyLens는 유튜브 → 노트/타임라인 변환기를 제공.

판정: "컨텐츠 → 실행물" 모델 자체는 버티컬에서 이미 반복 증명됐다. FlowMe의 베팅은 이 패턴이 한국 생활 카테고리군에서도 성립한다는 것 — 모델 리스크가 아니라 카테고리 선택 리스크다.

종합: 위협의 실체는 "경쟁 제품"이 아니라 시간이다. 링 1(범용 AI)이 캘린더 연동과 산출물 품질을 갖추기 전에, 링 3(버티컬 성공 패턴)을 한국 생활 영역에서 선점하고 실행 데이터를 쌓아야 한다.
SECTION 7

포지셔닝 맵: 공백의 정확한 좌표

X축 = 무엇을 다루나 (자기 입력 ↔ 외부 컨텐츠), Y축 = 무엇을 주나 (보관 · 요약 ↔ 실행 산출물). 우상단 — 외부 컨텐츠를 받아 실행 산출물을 주는 자리 — 에는 버티컬 점들만 있다.

이 좌표가 방어 가능한 이유

  • 좌상단 플레이어(실행 관리)는 컨텐츠 이해가 없다 — 입력은 사용자 몫
  • 우하단 플레이어(보관 · 요약)는 실행 구조가 없다 — Pocket의 사망이 증거
  • 버티컬 점들은 자기 카테고리를 벗어날 유인이 약하다
  • 한국 생활 맥락(공식 공지 · 네이버 생태계 · 전세 같은 로컬 절차)은 글로벌 AI의 변방

이 좌표가 뚫리는 경우

  • ChatGPT가 캘린더 연동 + 산출물 워크벤치 UX를 완성 (현재 미완 [외부])
  • 네이버/카카오가 자사 컨텐츠에 변환 버튼을 내장 (감시 필요, 현재 신호 없음)
  • FlowMe 스스로 범용화/클론화로 좌표를 이탈 (자기 리스크 §10)
SECTION 8

전략 옵션 평가: 세 갈래 중 무엇으로 시작하나

옵션내용강점약점판정
A · 수평 변환 엔진
"어떤 컨텐츠든 붙여넣으면 변환"		 URL/텍스트 입력 → 범용 변환기로 출시 시장 정의가 큼, 데모가 화려함 범용 AI와 정면충돌 · 품질 보증 불가 · 카테고리별 플레이북 부재 → 신뢰 붕괴 기각
B · 버티컬 웨지 → 인접 확장
"생활 이벤트 준비부터"		 입학 · 이사 · 계약 · 살림 등 검증된 카테고리에서 변환 품질을 보증하고, 플레이북 단위로 확장 버티컬 패턴은 이미 증명됨(§6 링 3) · 품질 통제 가능 · 현재 5개 라우트와 정렬 · 소스 결속의 가치가 가장 큰 영역 초기 시장이 작아 보임 · 카테고리 선택을 틀리면 헛수고 권고 ✓
C · 크리에이터 채널 우선
"크리에이터가 자기 컨텐츠를 Flow로 배포"		 B2C2C: 크리에이터에게 변환 도구를 주고 그들의 독자에게 배포 배포 비용 절감 · 공급 제휴 해자 · 차별화 잠재력 최대 양면 시장을 처음부터 풀어야 함 · 변환 품질이 증명되기 전엔 크리에이터 설득 불가 Stage 2 접목
권고: B로 시작 → C를 Stage 2에서 접목 → A는 영원히 하지 않는다. 범용 변환은 플랫폼의 것이고, FlowMe의 것은 "이 카테고리에서는 우리가 제일 잘 변환하고, 실제로 실행되게 만든다"는 보증이다. 순서가 곧 전략이다: 품질 증명(B) 없이는 공급 제휴(C)도 없다.

웨지 카테고리 선택 기준 (현재 5개 라우트의 일반화)

① 실수 비용이 크다(빠뜨림이 아프다) ② 공식/비공식 정보가 섞여 있어 정리 가치가 높다 ③ 날짜 앵커가 자연스럽다(D-day) ④ 반복보다 이벤트성(범용 todo와 비경쟁) ⑤ 민감정보 저장 없이 성립한다. — 다음 후보 평가 시 이 5개 기준을 채점표로 쓴다.

SECTION 9

단계별 발전 전략: 도구 → 기록 → 네트워크

단계제품 정체성하는 일진입 게이트 (앞 단계의 행동 증거)수익 가설 [가설]
Stage 0 · 현재 변환 워크벤치 (export-first) 웨지 카테고리 라우트 운영 · .ics/CSV/복사 · 손 배포 · 관찰 세션 — (진행 중: 세션 0/3, no signal) 무료 (행동 데이터가 수익)
Stage 1 마찰 없는 변환기 캘린더 직접 저장 + 시트 append (이 2개만) · 카테고리 확장은 채점표 통과분만 반복 export 행동 + import 마찰 실측 + 안정 스키마 변환 크레딧 또는 프리미엄 export
Stage 2 실행 기록이 남는 곳 체크 · 진도 · 재방문 기록 · "이어서 하기" · 크리에이터 채널(옵션 C) 접목 시작 export 후 자발적 재방문 · 체크 행동의 반복 관측 구독 (기록 · 갱신 알림) + 크리에이터 제휴
Stage 3 실행 데이터 네트워크 실행률 기반 Flow 품질 루프 · 크리에이터 피드백 대시보드 · 자동화 개방 기록 데이터 임계량 + 크리에이터 수요 신호 크리에이터/컨텐츠 사업자 대상 실행률 인사이트

KPI 트리

  • North Star: 실행된 산출물 수 — export 후 체크/재방문으로 실행이 확인된 Flow 수
  • Stage 0: 열람→변환(앵커 입력) 전환율 · 변환→export 전환율 · 관찰 세션 판정
  • Stage 1: 목적지별 export 반복률 · import 실패/마찰 보고율
  • Stage 2: export 후 7일 내 재방문율 · 체크 완료율

v1 대비 명확해진 것

  • 단계 게이트에 수익 가설과 KPI가 결합됨 — "무엇이 보이면 다음 단계인가"가 측정 가능해짐
  • 옵션 C(크리에이터)가 Stage 2의 명시적 트랙이 됨 — 막연한 "장기 방향"이 아니라 접목 시점이 정의됨
  • 광고 모델은 배제 — 실행 신뢰가 자산인 제품에서 광고는 신뢰를 판다 [가설이지만 강한 원칙]
SECTION 10

리스크와 킬 기준: 무엇이 보이면 멈추거나 꺾는가

리스크 나열로 끝내지 않는다. 각 리스크에 관측 신호와 대응 트리거를 붙인다 — 이것이 v1과의 가장 큰 차이다.

리스크관측 신호 (이게 보이면)대응 (이렇게 한다)
R1 · 범용 AI의 흡수 높음 ChatGPT Tasks가 캘린더 연동 + 산출물 편집 UX 출시 · 작업 수 제한 해제 웨지 카테고리의 소스 결속 깊이로 비대칭화 · Stage 2(기록) 진입을 앞당겨 데이터 차별화 · 한국 공식 문서 축 강화
R2 · 플랫폼 내장화 중간 네이버/카카오/Notion이 컨텐츠 옆에 "일정으로 변환" 버튼 노출 멀티 목적지 중립성 유지 · 그 플랫폼이 안 다루는 크로스 소스(공식+블로그+영상 종합) Flow로 이동
R3 · 원천 정책/권리 중간 크롤링 차단 강화 · 크리에이터 이의 제기 발생 사용자 주도 입력(가져오기)으로 전환 · 해당 크리에이터에 제휴 제안(옵션 C 조기 가동)
R4 · 자기 클론화 상시 로드맵에 워크스페이스/범용 todo/자동화 빌더성 기능이 등장 feature filter + do-not-build 경계로 즉시 차단 [내부 체계 가동 중]

킬/피벗 기준 (미리 정해두는 정직함)

  • 패킷 의심: 관찰 3회 1라운드 no signal → 패킷 수정 후 재실행 (기존 룰)
  • 카테고리 의심: 2라운드 연속 no signal → 패킷이 아니라 웨지 카테고리 선택을 재검토
  • 가설 폐기: Stage 1 진입 후에도 export 후 재방문이 관측되지 않으면 → Stage 2(기록 레이어) 가설을 폐기하고 "변환 유틸리티"로 포지션 축소를 검토

가장 통제 가능한 리스크부터

R1~R3은 외생 변수지만 R4는 전적으로 내부 선택이다. 그리고 R1의 대응(웨지 깊이, 기록 데이터)은 어차피 권고 전략 B의 실행 그 자체다 — 즉, 최선의 리스크 대응은 전략을 빨리 실행하는 것이다.

SECTION 11

결론

FlowMe는 컨텐츠 소비와 실행 도구 사이의 비어 있는 다리에 선다. 시작은 한국 생활 이벤트 준비라는 버티컬 웨지(전략 B) — 거기서 변환 품질과 실행 행동을 증명하고, 캘린더 · 시트 경량 연동으로 마찰을 줄이고(Stage 1), 실행 기록이 쌓이는 곳(Stage 2)으로, 그리고 크리에이터와 실행 데이터의 네트워크(Stage 3)로 커진다.

지키는 것

소스 결속 · 도구 중립 · 행동 증거 게이트 · do-not-build 경계

서두르는 것

관찰 3회 → export 마찰 측정 → Stage 1 진입. 범용 AI의 시간 창 안에 데이터 축적 시작

하지 않는 것

범용 변환 엔진(A) · 목적지 클론 · 광고 모델 · 증거 없는 단계 점프

즉시 다음 액션은 변하지 않는다: school-dorm-share-packet 관찰 세션 3회 실행. 이 리포트의 전략 전체가 그 첫 행동 증거 위에 서 있다.
