1. 결론

Export Pack v1은 “직접 연동 전 단계”가 아니라, URL-first 전략을 실제 사용자 행동으로 바꾸는 P0 제품이다.

P0 확정

.ics · Markdown · checklist

일정형, 문서형, 할 일형 Flow를 OAuth 없이 내보낼 수 있다. URL-first hit 결과의 기본 실행 출구로 둔다.

P1 후보

CSV / sheet · calendar feed

progress/sheet형과 decision형에는 유용하지만, P0 기본 버튼으로 두면 범위가 커진다. artifact별 선택 노출로 검토한다.

P2 보류

Todoist · Notion · Google direct API

가치는 크지만 OAuth, 권한, 동기화 실패, 데이터 삭제 책임이 생긴다. 먼저 export 행동 빈도를 확인해야 한다.

CEO 결정안: P0는 “다운로드/복사 가능한 portable export”로 고정하고, direct connector는 사용 증거가 쌓인 뒤 붙인다.

2. 포맷별 역할

P0 포맷은 목적이 겹치면 안 된다. 각 포맷은 사용자가 이미 쓰는 도구의 한 가지 행동을 명확히 맡는다.

포맷 우선순위 맡는 일 기본 노출 조건 보류/주의점
.ics P0 날짜, 시간, 반복, 기한이 있는 Flow를 캘린더로 옮긴다. Calendar형, routine형, deadline이 있는 checklist형 의료/법률/재무 영역은 “확인 일정”으로 표현하고 조언처럼 쓰지 않는다.
Markdown P0 출처, 주의, 단계, 메모를 한 번에 보존한다. 모든 hit Flow의 보편 fallback 너무 길면 실행성이 떨어지므로 요약, 체크 기준, 원문 링크를 앞에 둔다.
Checklist P0 지금 바로 할 일을 복사해 Todo, 메모, 메신저에 붙인다. Checklist형, decision형, travel/moving/precheck Flow 출처와 checked date가 빠지면 일반 조언처럼 보이므로 하단에 반드시 포함한다.
CSV / sheet P1 progress log, 비교표, 지출/반응 기록을 시트로 옮긴다. progress/sheet형, decision table형에서만 선택 노출 P0 전체 기본값으로 두면 QA와 필드 스키마가 커진다.
Calendar feed P1 반복적으로 갱신되는 캘린더 구독 경험을 제공한다. routine형이 반복 사용으로 증명된 뒤 취소, 변경, version drift 책임이 생긴다.
Direct API P2 Todoist, Notion, Google, Outlook 등으로 직접 생성한다. 특정 destination 반복 사용이 확인된 뒤 OAuth, 권한, 삭제/중복/동기화 실패 대응이 필요하다.

5. 최소 필드와 ledger 연결

Export가 FlowMe 밖으로 나가도 “어디서 왔고, 언제 확인했고, 무엇을 완료하면 되는지”가 남아야 한다.

모든 P0 export 공통 필드

1title
2source URL
3checked date
4completion
필드 필수 이유
title사용자가 기존 앱에서 검색하고 구분하는 이름이다.
date / duration.ics와 반복 루틴의 실행 시점을 만든다. 날짜가 없으면 checklist/Markdown으로 내려간다.
source URLFlowMe 밖에서도 원문으로 돌아갈 수 있어야 한다.
checked date출처가 언제 확인된 버전인지 보여준다.
caution민감 영역에서 조언처럼 보이지 않게 하는 안전장치다.
memo사용자가 자기 상황에 맞게 남긴 수정 맥락이다.
completion완료 판정이 없으면 export가 단순 텍스트가 된다.

source/version/trust ledger 최소 항목

권장 ledger key: flow_id, source_url, canonical_url, source_title, source_type, source_status, checked_at, export_generated_at, version_ref, risk_level, caution_text.
출처 추적
버전 확인
민감 문구 제어
외부 앱 동기화

해석: P0는 “외부 앱에 잘 붙는 파일/텍스트”보다 “FlowMe의 출처 신뢰가 밖으로 나가도 남는 구조”가 더 중요하다.

6. 민감 영역 문구 원칙

Export가 외부 앱에 들어가면 FlowMe UI의 안전 문맥이 사라진다. 따라서 파일/텍스트 안에 boundary를 남겨야 한다.

영역 금지 느낌 권장 표현 export 처리
의료/건강 진단, 처방, 효능 보장 공식 출처 확인, 전문가/보호자 문의, 이상 반응 기록 .ics는 “예약/확인 일정”, Markdown은 caution 상단 노출
법률/계약 법률 판단, 계약 결정 대행 서류 확인, 조건 비교, 전문가 문의 항목 Checklist 중심, 금액/계약 조언 단정 금지
재무/구매 투자/대출/구매 결정 권유 견적 확인, 비용 항목 정리, 비교 기준 기록 Markdown + checklist, sheet는 P1 decision table로 보류
커뮤니티 경험 개인 사례를 공식 가이드처럼 표현 사용자 경험 출처 표시, 본인 상황에 맞게 수정 source label과 checked date를 본문에 남김
운영 원칙: needs_review / miss 상태는 P0 export와 My Flow 저장 버튼을 열지 않는다. hit만 export 대상이다.

7. 다음 구현 slice 제안

이 보고서는 전략 확정 문서다. 구현을 새로 검증했다고 주장하지 않고, 다음 slice의 범위를 작게 제안한다.

Slice A

Export profile 통합

  1. Flow type별 기본 export를 계산한다.
  2. P0 포맷 3개에 공통 field contract를 둔다.
  3. source ledger 값을 export body에 주입한다.
Slice B

URL-first hit export 정리

  1. hit에서만 `.ics`, Markdown, checklist를 보여준다.
  2. needs_review/miss는 확인/재시도 CTA로 제한한다.
  3. canary 12개에 기본 노출을 고정한다.
Slice C

Sheet/API 보류 조건

  1. progress/sheet형에서만 CSV/sheet를 실험한다.
  2. calendar feed는 반복 사용 증거 후 검토한다.
  3. direct API는 destination별 수요가 확인될 때 붙인다.
