0. 이 문서의 목적
======================================================================

이 문서는 새 검토 요청이나 새 백로그 초안이 아니다.

이미 Codex가 수행한 아래 작업을 기획 세션에 넘기기 위한 요약본이다.

1. FlowMe 화면 책임을 MECE하게 다시 나눈 설계
2. 승인된 A-prime 방향
3. P35-01~P35-08 로컬 구현 결과
4. 구현 후 수행한 독립 UX 재검토
5. 독립 검토에서 확인된 미해결 문제
6. 전면 재설계 대신 선택한 bounded composition revision
7. P35-R0~P35-R7 후속 순서

핵심은 "P35를 처음부터 다시 설계한다"가 아니다.
이미 좋아진 구조와 안정된 데이터 계약은 유지하고, 실제 사용자 여정이 끊기는
composition만 제한적으로 다시 여는 것이다.

2. MECE 재설계에서 확정한 제품 방향
======================================================================

FlowMe는 Calendar, Todo, Notion, Sheet를 모두 대체하는 무거운 planner가 아니다.

기본 가치 사슬은 다음과 같다.

외부 콘텐츠 URL 또는 개인 메모
-> 실행 가능한 Flow
-> 필요한 최소 개인화
-> 실제 결과 미리보기
-> My Flow에서 실행하거나 기존 도구로 가져가기
-> 완료, 다시 열기, 기록, 재사용

화면 책임은 다음처럼 나눴다.

1. Flow 찾기
- 어떤 Flow를 사용할지 발견한다.
- 출처와 실제 결과를 먼저 확인한다.
- 저장 전 최소 조정을 한다.
- 실행과 개인 기록을 직접 소유하지 않는다.

2. My Flow
- 저장한 Flow를 찾는 library다.
- 선택한 한 Flow의 실행, 수정, 메모, 구조, 가져가기, lifecycle을 소유한다.
- 별도 Today와 완료 상위 view를 두지 않는다.

3. Calendar
- 날짜가 있는 실행 항목을 보는 date lens다.
- 여러 Flow의 날짜별 일정을 비교한다.
- 완료와 다시 열기만 공유한다.
- 날짜 수정, 메모, 구조 변경은 My Flow로 연결한다.

4. Entry router
- 저장한 Flow가 없으면 `/`에서 `/flows`로 이동한다.
- 저장한 Flow가 있으면 `/`에서 `/my`로 이동한다.
- 별도 Home surface를 유지하지 않는다.

5. 전역 navigation
- Flow 찾기
- Calendar
- My Flow

이 세 탭으로 고정한다.

3. 유지하기로 확정한 데이터 계약
======================================================================

아래 경계는 MECE 보정 과정에서 다시 만들지 않는다.

- source/content identity
- personal overlay
- execution run
- recurrence series와 occurrence
- export identity와 receipt
- stable Item ID
- 기존 localStorage key와 snapshot schema

중요한 의미 구분:

- 완료 / 다시 열기: execution 상태
- Flow에서 제외 / 다시 포함: source-backed 개인 구성
- 항목 삭제 / 항목 복구: 개인 draft 구조
- 보관 / 복구 / 영구 삭제: Flow lifecycle
- 날짜 이동: personal schedule

이 상태를 같은 필드나 같은 사용자 동사로 다시 섞지 않는다.

4. P35-01~P35-08에서 실제로 구현한 내용
======================================================================

P35-01 Entry router와 3탭
- 별도 Home을 제거했다.
- 저장 상태에 따라 `/flows` 또는 `/my`로 보낸다.
- 전역 navigation을 3개로 정리했다.
- marker: P35-ENTRY-ROUTER-3TAB

P35-02 Public result-first
- public `/f/[slug]`에서 긴 설명보다 실제 저장 결과를 먼저 보여 준다.
- 콘텐츠별 자연스러운 대표 결과를 우선한다.
- 예: 이사 Calendar, 차량 Checklist, 운동 routine, 학습 Sheet.
- 저장 후 입력을 제거하고 별도 receipt frame으로 전환한다.
- marker: P35-PUBLIC-RESULT-FIRST

P35-03 한 번에 한 조정
- 이름, 기준일, 포함 항목, 반복을 동시에 펼치지 않는다.
- 사용자가 선택한 조정 한 종류만 연다.
- 적용 전후 결과를 같은 화면에서 비교한다.
- source Item 삭제 없이 personalExcluded 같은 개인 계약을 사용한다.
- marker: P35-ADJUST-ONE-KIND

P35-04 My Flow 안전 분리
- 거대한 My Flow 구성에서 live Calendar surface를 분리했다.
- 죽어 있던 checklist/routine 상위 branch를 제거했다.
- `/calendar`의 실제 calendar branch는 유지했다.
- marker: P35-MYFLOW-SAFE-SPLIT, P35-DEAD-VIEW-REMOVAL

P35-05 My Flow library와 focused workspace
- `/my`를 저장 Flow를 찾는 library와 선택한 Flow에 집중하는 workspace로 나눴다.
- 모바일 목록 row는 제목, 진행, 다음 행동, 열기 중심으로 줄였다.
- 1/5/20/60개 Flow fixture에서 검색과 열기 구조를 확인했다.
- marker: P35-MY-LIBRARY-ONLY, P35-PERSONAL-SINGLE-FOCUS

P35-06 Calendar lens
- 월간 grid는 compact marker와 초과 개수만 보여 준다.
- 선택일 agenda는 Flow별 전체 dated Item을 보여 준다.
- Calendar 내부의 메모, 날짜 이동, 날짜 없는 tray, 상세 편집을 제거했다.
- 완료 / 다시 열기만 같은 실행 primitive로 유지했다.
- marker: P35-CALENDAR-LENS-ONE-TOGGLE

P35-07 Scope-first export
- 전체 / 선택 / 현재 항목 범위를 형식보다 먼저 정한다.
- 실제 가능한 형식만 primary 1개와 secondary 최대 2개로 보여 준다.
- preview count, output count, receipt count를 맞췄다.
- marker: P35-EXPORT-SCOPE-FIRST, P35-EXPORT-COUNT-PARITY

P35-08 Final local MECE gate
- 위 P35-01~07을 로컬 build와 자동화로 통합 확인했다.
- 판정은 pass_local_gate였다.
- marker: P35-FINAL-MECE-GATE

주의:
`pass_local_gate`는 production publish 완료나 실제 사용자 검증 완료가 아니다.

5. 구현 후 Codex 독립 재검토 판정
======================================================================

독립 검토 최종 판정:

- P35 방향: revise
- 최종 권고: bounded_composition_revision
- 선택 대안: C, Artifact preflight + contextual personalization
- Blocking: 0
- High: 6
- 실제 관찰 사용자: 0
- 데이터 migration: 권고하지 않음

유지할 것:

- 3탭 entry router
- public result-first
- 한 번에 한 종류만 여는 조정 방식
- My Flow library와 focused workspace 분리
- Calendar date lens
- 기존 identity와 저장 계약

그대로 publish하기 전에 고칠 것:

1. Public artifact와 export 결과 불일치
- 화면에서 약속한 primary artifact와 실제 가져가기 형식, 수량, 개인 수정본이
  같지 않은 경우가 있다.

2. 저장 확인 중복
- public receipt 뒤에 My Flow post-save hub가 다시 나타난다.
- 두 번 저장을 확인하고 다시 4개 행동 중 하나를 선택하게 된다.

3. 콘텐츠 형태를 무시한 My Flow 고정 탭
- 모바일의 `다음 행동 / 전체 계획 / 기록`이 모든 콘텐츠에 동일하다.
- 날짜형, 체크리스트형, 반복형, Sheet형, memo형의 자연스러운 다음 실행 단위가
  서로 다른데 한 row로 축약한다.

4. 저장 전 Item 수정 부족
- 저장 전에는 포함 여부만 조정할 수 있다.
- 제목, 상세, 개별 날짜는 저장 후에만 수정된다.

5. Memo draft 문법 불일치
- memo draft는 P35 공통 result-first 문법 대신 14개 입력의 긴 form에 가깝다.

6. Routine preview와 저장 결과 단절
- 시작일이 확정되지 않은 날짜형 반복 미리보기가 저장 후 날짜 없는 한 항목으로
  달라질 수 있다.
- preview, receipt, Calendar, export가 같은 계획을 읽지 못한다.

Medium findings:

- `기록`은 독립 탭으로 둘 만큼 고유한 역할이 명확하지 않다.
- public 가져가기가 disclosure를 여러 번 거쳐 다시 길어진다.
- 모바일 Calendar의 선택일 agenda가 월간 grid 아래 멀리 있다.
- My Flow filter가 상태와 콘텐츠 형태를 섞는다.
- `첫 할 일 시작`으로 연 상세에서 완료할 수 없다.

6. 사용자 피드백 F01~F07에 대한 기존 Codex 판정
======================================================================

F01. Flow 조정에서 상세와 날짜 수정
- 판정: 필요
- 방향: 저장 전 full editor가 아니라 contextual Item edit
- 제목, 상세, 개별 날짜 세 필드만 먼저 연결

F02. 저장 직후 오늘 할 일 화면 필요 여부
- 판정: 별도 Today 화면으로 바로 보내지 않음
- 짧은 receipt 뒤 선택한 전체 personal Flow workspace를 연다.
- 중복 post-save hub는 제거한다.

F03. 같은 날짜의 다음 할 일 묶음
- 판정: 필요
- 날짜형은 한 항목이 아니라 가장 가까운 날짜의 미완료 Item 묶음을 먼저 보여 준다.
- 체크리스트는 다음 1~3개, routine은 occurrence, Sheet는 current row를 사용한다.

F04. 저장 전 5개 또는 필요한 결과 미리보기와 export
- 판정: 필요
- 고정 5탭은 만들지 않는다.
- 콘텐츠별 primary artifact 1개와 eligible secondary 최대 2개만 실제 결과로
  미리 보여 준다.
- FlowMe 저장과 외부 가져가기를 같은 preflight에서 예측할 수 있게 한다.

F05. 되돌리기 노출 조건
- 판정: 행동별로 다르게 처리
- 완료 후 행이 사라지면 즉시 undo
- 행이 남으면 같은 위치의 완료 / 다시 열기 toggle
- 삭제와 보관은 지속적인 복구 경로

F06. `다음 행동` 탭의 모호함
- 판정: 맞음
- 별도 탭을 제거하고 전체 personal Flow 상단의 shape-aware 실행 영역으로 통합

F07. `기록` 탭의 모호함
- 판정: 맞음
- Item memo, execution history, run reflection, reuse를 각각 해당 object와 시점으로
  분산한다.
- 기록 데이터 자체를 삭제하는 것이 아니라 presentation만 다시 배치한다.

7. 선택한 개선안과 거절한 안
======================================================================

선택:
C. Artifact preflight + contextual personalization

선택 이유:
- 쓸 만한 실제 결과를 먼저 보여 주는 P35 장점을 유지한다.
- 사용자가 필요한 항목만 수정한다.
- FlowMe 저장과 외부 destination 결과를 저장 전에 비교할 수 있다.
- 기존 personal overlay를 재사용한다.

거절:
B. 저장 전 full editor

거절 이유:
- 첫 useful result가 늦어진다.
- 모바일 form 복잡도가 다시 커진다.
- source와 personal write path가 섞일 위험이 있다.
- 한 번에 한 종류만 조정하는 P35 원칙을 되돌린다.

따라서 허용되는 변경은 대대적인 데이터 재설계가 아니라, 필요하면 화면
composition을 크게 바꾸되 안정된 identity와 projection 계약은 유지하는 방식이다.

8. 확정된 후속 개발 순서
======================================================================

P35-R0. Temporal first-group correction
- 과거 날짜 항목 수를 저장 전에 짧게 경고
- 저장 후 오늘 또는 가장 가까운 미래 날짜의 미완료 묶음을 먼저 표시
- 미래가 없으면 가장 가까운 과거 날짜 묶음 표시
- 같은 날짜 미완료 Item을 전부 함께 표시
- 지난 Item은 접힌 목록에 보존

P35-R1. Primary artifact preflight parity
- public preview, CTA, export가 같은 artifact plan, 수량, 개인 수정본을 읽음
- routine의 provisional schedule과 committed schedule 구분

P35-R2. Contextual pre-save Item personalization
- 저장 전 제목, 상세, 개별 날짜만 bounded edit로 연결
- full editor는 만들지 않음

P35-R3. Receipt와 workspace continuity
- receipt를 한 번만 표시
- 중복 post-save hub 제거
- 전체 personal workspace로 자연스럽게 연결

P35-R4. Shape-aware execution과 optional history
- 날짜형: 같은 날짜 미완료 group
- 체크리스트형: 다음 1~3개
- 반복형: current occurrence
- Sheet형: current row
- memo형: relevant next unit
- 고정 `다음 행동 / 전체 계획 / 기록` 탭 재구성

P35-R5. Memo proposal grammar
- 긴 full-form을 공통 result-first, one-kind adjustment 문법으로 변경

P35-R6. Mobile Calendar selected-day composition
- Calendar date lens 계약은 유지
- 모바일 선택일 agenda를 bottom sheet 또는 동등한 가까운 composition으로 개선

P35-R7. Final independent gate
- R0~R6 acceptance 전체 재검증
- High finding 0 확인
- 390/1024/1440 browser evidence
- 자동화와 실제 사용자 evidence 분리

순서:
R0 -> R1 -> R2 -> R3 -> R4 -> R5 -> R6 -> R7

한 slice의 acceptance, screenshot, targeted test, rollback 확인 전에 다음 slice를
시작하지 않는다.
