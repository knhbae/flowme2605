2026-06-25 · source-backed expansion

실제 원컨텐츠 기반 Flow 5개 확장 리포트

목적은 기존 중1 수학, 영유아 일정, 이사 D-30 외에도 한글 원컨텐츠가 FlowMe의 저장·실행 구조로 옮겨질 수 있는지 확인하는 것이다. 이번 산출물은 사용자용 화면이 아니라, 원문 선정 근거, 변환 판단, 내부 시뮬레이션, 테스트 결과를 분리해 기록한 검토 문서다.

결론: 5개 모두 source-backed Flow Map 경로에 추가했고, 공개 화면에서 저장 후 My Flow record가 생성되는 E2E까지 통과했다. 실제 사용자 검증 완료를 의미하지는 않는다.

Selection Gate

선정 원칙

원문 하나

여러 링크를 섞어 종합 가이드로 만들지 않고, 각 Flow는 primary source 1개를 기준으로 만들었다.

입력 0~1개

사용자가 저장할 때 필요한 값은 없음 또는 날짜 1개로 제한했다. 세부 정보는 Step detail, memo, URL로 내려보냈다.

일반인 실행성

전문 판단이 아니라 조회, 제출, 신고, 청소, 보관 확인처럼 사용자가 직접 할 수 있는 행동만 남겼다.

Simulation

비전문 일반인 관점 시뮬레이션

페르소나 1 · 이사 직후 직장인

전입신고는 했지만 우편물 전송을 신청했는지 기억이 흐릿하다. 원문에서 신청/결제/무료 조회 조건을 보고, FlowMe에는 전입신고일과 접수번호 여부만 남긴다.

페르소나 2 · 의심 문자를 받은 사용자

택배 사칭 문자를 보고 당황했지만 보안 지식은 많지 않다. FlowMe에서는 악성 여부 판정이 아니라 118, 보호나라, 통합신고센터 중 어디까지 확인했는지만 체크한다.

페르소나 3 · 회사 마감이 있는 직장인

연말정산 간소화자료 제출 마감 전, 홈택스에서 월 선택과 근무처 제출을 빠뜨리지 않으려 한다. 세액 판단은 하지 않고 제출 상태와 회사 보완 요청만 기록한다.

페르소나 4 · 집 관리 담당자

에어컨 필터 청소 방법을 한 번 읽고 매번 원문을 다시 찾기 싫다. 다음 청소일만 넣고 2주 반복 일정, 필터 리셋 여부, 모델별 원문 링크만 남긴다.

페르소나 5 · 아이와 나들이 가는 보호자

도시락을 준비하면서 장보기, 조리, 운반, 섭취 전 확인을 놓치고 싶지 않다. 나들이일 기준으로 전날/당일 할 일만 체크하고, 증상 판단은 FlowMe에서 하지 않는다.

페르소나 공통 기준

원문을 완전히 대체하지 않고, 캘린더/투두 앱 수준의 입력으로 다시 볼 일과 완료 여부만 관리한다. 민감 정보와 판단은 공식 서비스 또는 전문가 영역으로 남긴다.

시나리오 A · 원문에서 저장

  1. 사용자가 원문을 보다가 “나중에 다시 확인해야겠다”는 지점을 만난다.
  2. FlowMe 공개 화면에서 원문 제목, 저장 결과, 필요한 입력 0~1개를 본다.
  3. 날짜가 필요한 경우 날짜 1개만 입력하고 전체 저장한다.
  4. 저장 직후 My Flow에 child Flow record와 map snapshot이 생긴다.

결과 E2E에서 5개 모두 저장 record 생성 확인.

시나리오 B · 첫 실행

  1. 사용자는 My Flow에서 오늘 또는 Flow 목록으로 들어온다.
  2. Step을 열면 Item fallback, 원문 URL, 완료 기준을 본다.
  3. 민감한 정보는 직접 저장하지 않고 상태나 접수번호 수준만 남긴다.
  4. 다음 날짜가 필요한 Flow는 calendar row로 이어진다.

결과 모델 테스트에서 모든 Step이 source URL과 3개 이상 Item fallback을 보존.

시나리오 C · 재방문

  1. 우편물, 세금, 도시락 Flow는 기준일 이후 다시 확인할 수 있다.
  2. 에어컨 Flow는 2주 반복 일정으로 다시 나타난다.
  3. 스미싱 Flow는 반복 사용보다 긴급 체크리스트로 유지된다.

주의 재방문 UX 자체는 기존 My Flow surface를 사용한다. 새 5개 전용 UI를 별도로 만들지는 않았다.

UX 리뷰 결과

  • Blocking: 없음.
  • High: 없음. 다만 국세청/스미싱은 민감 정보를 저장하지 않는 경계가 필요하다.
  • Medium: 공개 화면에서 Step detail을 저장 전 더 자세히 보는 UI는 아직 약하다.
  • Low: source-backed public page의 한글 표시 인코딩 문제는 기존 파일 전반에 남아 있다.
