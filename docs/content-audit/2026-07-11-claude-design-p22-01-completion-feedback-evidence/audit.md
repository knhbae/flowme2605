# P22-01 완료 후 최소 회고·원본 메모 Audit

## 사용자 문제

기존 FlowMe는 발견, 저장, 개인화, 실행, 완료까지 이어졌지만 완료 뒤 제품이 아무것도 묻지 않았습니다. 사용자는 다음 실행에 남길 개인 메모와 다른 사용자에게도 영향을 주는 원본 오류를 구분할 수 없었습니다.

## 이번 판단

### 1. 진입 시점

- Flow의 실제 실행 row가 모두 완료된 경우에만 후속 기록을 노출합니다.
- 하나라도 미완료로 돌아가면 진입점이 사라집니다.
- 완료 전 실행 흐름과 오늘 할 일 위계를 방해하지 않습니다.

### 2. 개인 회고

- `도움됐어요` / `고칠 점이 있어요` 중 하나를 고릅니다.
- 선택 메모는 다음에 다시 쓸 때 기억할 개인 기록입니다.
- 공개 평점이나 다른 사용자에게 보이는 리뷰로 표현하지 않습니다.

### 3. 원본에서 고칠 점

- Flow 전체 또는 특정 할 일을 선택할 수 있습니다.
- 저장 record에는 Flow slug, 선택한 할 일 id/title, 사용자 설명, 원 URL만 보존합니다.
- personal overlay나 source-backed 원본을 수정하지 않습니다.
- 서버 제출 수단이 없으므로 `아직 누구에게도 전송되지 않아요`와 `전송 전 메모 저장`을 명시합니다.

### 4. 저장 경계

| 데이터 | 저장 위치 | 다른 모델에 미치는 영향 |
| --- | --- | --- |
| 완료 체크 | 기존 per-flow checks | 회고와 독립 |
| 제목·날짜·메모 수정 | 기존 personal overlay | 회고와 독립 |
| 내 실행 회고 | `flow:my-flow:completion-feedback:{slug}` | 개인 기록만 갱신 |
| 원본 수정 메모 | 같은 feedback record의 `sourceCorrectionDraft` | 원본·overlay 미변경 |

Flow 기록 삭제 시 해당 feedback record도 함께 삭제합니다.

## 화면 판정

### 모바일 390px

- 완료 카드 안에서 남은 항목 0 다음에 후속 기록이 나타납니다.
- 기본 상태의 경쟁 행동은 두 개이며 목적이 분리됩니다.
- 각 editor는 한 번에 하나만 열립니다.
- textarea와 저장 버튼은 가로 overflow 없이 동작합니다.

### wide 1024px

- 완료 카드 안에 저장 상태가 한 줄로 남습니다.
- 별도 5번째 탭이나 Studio 화면으로 이동하지 않습니다.
- 기존 Flow 목록과 진행률 구조를 유지합니다.

## Guardrail

- 사용자 표면 internal term hit: 0
- visible raw ISO hit: 0
- structural display hit: 0
- 공개 리뷰/별점/전송 완료 오해 문구: 0
- feedback 저장으로 완료 check 변경: 0
- feedback 저장으로 personal overlay 변경: 0

## 남은 위험

1. localStorage는 계정·기기 연속성을 제공하지 않습니다.
2. 원본 메모를 실제 전달하려면 인증, 개인정보, abuse, moderation, 처리 상태, 제작자 소유권 정책이 필요합니다.
3. 공개 유용성 신호는 실제 제출·검토 데이터가 쌓이기 전까지 노출하면 안 됩니다.
4. 반복 Flow의 회고 시점은 “한 회차 완료”와 “Flow 종료”를 더 구체적으로 구분해야 합니다.
