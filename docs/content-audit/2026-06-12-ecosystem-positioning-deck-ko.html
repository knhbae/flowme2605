Layer ① Sources

원천 분석: 한국어-퍼스트 + 소스 결속이 수급 전략이다

Phase 1 컨텐츠 소스 맵 + 검증된 공개 라우트 5종 기준

블로그 (네이버 · 티스토리)

받는 것: 체크리스트, 타임라인, 살림 · 절약 노하우

리스크: 비공식 정보 → "실용 가이드"로 분리 표기, 공식 공지 확인 행을 항상 추가

유튜브

받는 것: 따라하기, 준비 루틴, 연습 구조

리스크: 구조 추출 난이도 → 원본 링크 보존, 단계만 가져온다

공식 기관 (학교 · 정부 · 기업)

받는 것: 날짜, 필수 서류, 자격 요건, 절차

강점: 신뢰도 최고 → 최신 공지 우선(latest-notice-first) 원칙으로 가장 안전한 축

크리에이터 자료 (PDF · 템플릿)

받는 것: 실행 단계만. 원본 에셋은 복제하지 않고 링크 보존

기회: 트래픽을 돌려주는 구조 → 크리에이터가 적이 아니라 공급자가 된다

검증 완료: 공개 라우트 5종 (카테고리 대표성 확보)

전세 계약 사전점검 (공식 문서) · 초등 입학 D-30 (공지+블로그 하이브리드) · 키즈 프린터블 공작 (크리에이터) · 원격지원 사전점검 (공식 매뉴얼 → 내부 체크) · 냉장고 파먹기 (블로그 → 시트)

차별점의 뿌리가 여기다: ChatGPT는 "그럴듯한 요약"을 주지만, FlowMe는 실제 출처에 묶인(source-bound) 실행물을 준다. 출처 · 주의 · 완료기준이 산출물과 함께 이동하는 것이 원천 전략의 핵심.

Stage 0 원칙: 계정 없는 휴대성

OAuth · 토큰 · 동기화 없이, 파일과 복사만으로 모든 목적지에 도달한다. 연동 전에 export 마찰을 측정하는 것이 Stage 0의 일.

연동 게이트 (integration-readiness-gate)

반복 사용 증거 + import 마찰 + 안정 스키마 + 권한 명확성 + 되돌리기 가능성 + 출처/안전 경계 이전 — 6가지 전부 증명돼야 Stage 1 진입. 현재 통과 후보는 캘린더 직접 저장, 시트 append 단 2개.

Competition

경쟁 구도: 누가 진짜 위협이고, 무엇을 배울 것인가

위협 강도 순 정렬 — 경쟁 분석의 목적은 "FlowMe가 되지 말아야 할 것"의 확정

서비스관계위협 시나리오FlowMe의 방어 / 교훈
ChatGPT · Perplexity 최대 위협 "이 글 캘린더로 만들어줘"가 범용 AI 한 마디로 가능해지는 순간, 변환 계층이 통째로 흡수된다 소스 결속 + 카테고리별 검증된 변환 플레이북 + 실행 기록 — 요약이 아니라 책임지는 실행물로 차별화
Notion 목적지 겸 경쟁 템플릿 갤러리 + Notion AI가 "컨텐츠 → 워크스페이스" 변환을 자체 제공 워크스페이스 앞단에서 승부. 템플릿은 빈 구조를 주지만 FlowMe는 소스에서 채워진 구조를 준다
Todoist · TickTick 목적지 겸 경쟁 범용 할일 인박스로서 모든 실행을 흡수 범용 todo 앱이 되지 않는다. 태스크가 아닌 맥락 있는 산출물(출처+주의+완료기준)을 공급
캘린더 · Sheets 순수 목적지 직접 경쟁 가능성 낮음 — 이미 신뢰받는 그릇 복제 금지. 정확한 import 형식(.ics 반복, CSV 헤더)을 지키는 것이 곧 제품 품질
Zapier · Make 인접 레이어 자동화 수요를 선점 — 단 Stage 0 사용자층과 다름 지금은 무시. Stage 3에서 FlowMe 이벤트의 트리거화로 활용 가능
구조적 결론: FlowMe의 경쟁자는 "같은 제품"이 아니라 "같은 일을 흡수할 수 있는 더 큰 플랫폼들"이다. 따라서 기능 경쟁이 아니라 ① 한국어 컨텐츠 특화 ② 소스 결속 신뢰 ③ 실행 기록 축적 — 큰 플랫폼이 굳이 안 하는 좁고 깊은 영역으로 파고든다.

Positioning

포지셔닝: 왜 이 빈틈이 존재하고, 왜 우리가 차지하는가

사용자의 현재 행동

좋은 글/영상을 본다 → 북마크 · 저장한다 → 실행하지 않는다. 실행하는 소수는 캘린더 · 시트 · 메모에 손으로 옮겨 적는다.

빈틈의 정체

컨텐츠 플랫폼은 소비까지만, 생산성 도구는 입력 이후부터만 책임진다. 그 사이의 변환 노동은 누구의 제품도 아니다.

왜 지금인가

LLM으로 변환 비용이 급락한 지금, 이 틈을 먼저 메우고 실행 행동 데이터를 쌓는 쪽이 유리해진다.

FlowMe = Action Compiler
"읽고 본 것을, 쓰던 도구에서 바로 실행되는 산출물로"

① 소스 결속

출처 URL · 주의 · 완료기준이 산출물과 함께 이동. 요약 AI와의 결정적 차이.

② 산출물 우선

첫 화면이 곧 실행물(캘린더 행 · 시트 행 · 체크 행). 설명이 아니라 미리보기로 말한다.

③ 도구 중립 휴대성

사용자에게 이주를 요구하지 않는다. 모든 목적지에 export로 도달 → 목적지들과 비적대 관계 유지.

Evolution

발전 로드맵: Export → 연동 → 기록 → 네트워크

각 단계는 기능 욕심이 아니라 앞 단계의 행동 증거(gate)로만 열린다

Stage 0 · 현재

Export-First 검증

  • 공개 라우트 5종 운영
  • .ics / CSV / 복사로만 전달
  • 계정 · 연동 · 자동화 없음
  • 손으로 배포 (share packet)
다음 단계 게이트: 반복 export 행동 + import 마찰의 실측 증거
Stage 1

경량 연동

  • 캘린더 직접 저장 (단건)
  • 시트 직접 append
  • 이 2개 외 연동 금지
  • 최소 권한 · 되돌리기 보장
게이트: 같은 목적지로의 반복 사용 + 안정된 산출물 스키마
Stage 2

실행 기록 레이어

  • 체크 · 진도 · 재방문이 FlowMe에 남기 시작
  • 기존 도구 이탈 강요 없음
  • "이어서 하기" 경험 제공
게이트: export 후 자발적 재방문 · 체크 행동의 반복 관측
Stage 3

피드백 네트워크

  • 실행률 데이터 → Flow 품질 개선 루프
  • 크리에이터 피드백 · 공급 관계
  • 자동화 (Zapier/Make류) 개방
게이트: 기록 데이터 임계량 + 크리에이터 측 수요 신호
구조 요약: 도구(0–1) → 기록 보관소(2) → 데이터 네트워크(3). 단계를 건너뛰는 기능(OAuth 전면 도입, 워크스페이스, 자동화 빌더)은 전부 분석방에서 future_platform / reject로 이미 기각되어 있다.
7 / 11
Moat

해자: 처음엔 없다 — 그래서 무엇을 쌓는가가 전부다

정직한 진단: 변환 그 자체는 해자가 아니다. LLM이 있는 누구나 컨텐츠를 체크리스트로 바꿀 수 있다. FlowMe의 해자는 변환이 아니라 변환 이후에 쌓이는 것에서 나온다.
축적물 ①

변환 플레이북

카테고리별 "무엇이 실행되는 구조인가"의 노하우. 입학 준비는 D-30 타임라인, 냉장고는 재고 시트, 원격지원은 권한 사다리 — 이미 5개 카테고리에서 검증된 형태가 레포에 룰로 박혀 있다.

축적물 ②

실행 기록 데이터

어떤 Flow가 실제로 완료되는가. 이것은 범용 AI가 갖지 못하는 데이터다. 실행률은 곧 컨텐츠 신뢰 지표가 되고, 다음 Flow 생성 품질로 되먹임된다.

축적물 ③

크리에이터 관계

원본 링크 보존 + 트래픽 환원 구조는 크리에이터를 공급자로 만든다. 컨텐츠 플랫폼이 긁어가기를 경계할 때, FlowMe는 허락받고 들어가는 변환 채널이 될 수 있다.

시간축으로 보면

0–6개월: 해자 없음, 속도와 카테고리 선점이 전부 → 6–18개월: 플레이북 + 실행 데이터 초기 축적 → 18개월+: "실행되는 컨텐츠"의 데이터를 가진 유일한 플레이어 포지션 도전. 그래서 Stage 0에서 행동 증거 수집이 기능 개발보다 우선이다.

8 / 11
Risks

리스크와 대응: 무엇이 이 전략을 무너뜨릴 수 있나

R1 · 범용 AI의 흡수 높음

ChatGPT가 "이 링크 캘린더 파일로" 를 기본 기능화하는 시나리오.

대응: 한국어 생활 카테고리 특화 + 소스 결속 품질 + 실행 기록으로 좁고 깊게. 범용성이 아니라 책임성으로 경쟁한다. 속도가 생명 — Stage 0 검증을 늘어뜨리지 않는다.

R2 · 목적지 플랫폼의 자체 개선 중간

Notion AI import, Google 캘린더의 Gemini 통합 등이 변환을 내장.

대응: 단일 목적지 종속 금지(멀티 목적지 중립성). 플랫폼 내장 기능은 자기 생태계 안에서만 작동 — FlowMe는 크로스 목적지 + 한국 컨텐츠에서 우위 유지.

R3 · 원천 플랫폼 정책 중간

네이버 크롤링 제한, 크리에이터 저작권 분쟁.

대응: 원본 미복제 + 링크 보존 원칙은 이미 제품 룰. 사용자가 가져온 컨텐츠의 변환(이용자 주도)과 크리에이터 제휴 모델로 전환 여지 확보.

R4 · 자기 파괴: 클론化 상시

기능 욕심으로 todo 앱 · 워크스페이스 · 캘린더 클론이 되어 모든 목적지를 적으로 만드는 시나리오.

대응: do-not-build 경계(분석방에 명문화)와 feature filter를 모든 리뷰의 마지막 게이트로 유지. 이 리스크만은 전적으로 우리 손에 달려 있다.

  • 공개 라우트 무증거 확장 · 검증/론칭 클레임
  • OAuth · 계정 연동 · 자동 포스팅 · 회신 수집
  • 같은 축의 기획 문서 추가 (documentation stop gate 발동 중)

Conclusion

컨텐츠 플랫폼과 생산성 도구 사이의 변환 계층에서 시작해,
export로 신뢰를 얻고 → 연동으로 마찰을 줄이고 →
실행 기록이 쌓이는 곳으로 진화한다.

원칙 1

목적지를 복제하지 않는다 — 모든 도구의 앞단에 선다

원칙 2

소스 없이 생성하지 않는다 — 출처가 신뢰의 단위다

원칙 3

행동 증거 없이 승격하지 않는다 — 게이트가 로드맵이다
