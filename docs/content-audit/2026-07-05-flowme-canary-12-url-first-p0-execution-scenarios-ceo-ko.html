1. CEO 결론

이번 목표의 결론은 “Canary 12개를 서비스에 넣자”가 아니다. URL-first P0에서 어떤 결과가 통과이고 어떤 결과가 차단인지 판정하는 운영 기준을 확정하는 것이다.

승인 요청

hit의 통과 기준

P0-now 4개는 URL 입력 후 기존 Flow가 매칭되고, 시작일/옵션을 받으며, 기본 export와 My Flow 저장이 열려야 한다.

승인 요청

needs_review의 잠금 기준

P1-review 6개는 미리보기만 허용한다. 원문 row, import 권리, 민감 문구가 확인되기 전에는 export와 저장을 열지 않는다.

승인 요청

miss/hold의 처리 기준

P2-hold 2개는 보류 이유와 비교 목적만 남긴다. AI 생성, fake usage, 바로 저장 CTA를 보여주지 않는다.

P0의 성공 신호는 “많은 후보를 보여주는 것”이 아니라, 같은 URL에서 같은 상태와 같은 잠금 규칙이 반복적으로 작동하는 것이다.

8. P0/P1/P2 검증 로드맵

검증 순서는 기능 추가 순서가 아니라 신뢰 리스크를 줄이는 순서다.

Phase A

P0-now 4개 통과

  • 4개 URL이 hit로 매칭된다.
  • 기본 export가 canary별 artifact와 맞는다.
  • My Flow 저장 record에 ledger 필드가 남는다.
  • 민감 caution이 export에도 포함된다.
Phase B

P1-review 6개 잠금 유지

  • preview-only가 가능하다.
  • export/save/start CTA가 열리지 않는다.
  • 해제 조건이 reviewer가 실행 가능한 문장으로 남는다.
  • source/import 권리와 민감 문구 확인 후 hit로 승격한다.
Phase C

P2-hold 2개 보류

  • 비교/백업 이유만 남긴다.
  • P0-now 실패 또는 coverage gap 때만 승격한다.
  • AI-first 생성 기대를 만들지 않는다.
  • 다음 batch 후보로만 관리한다.

10. 임원 의사결정 항목

이번 목표에서 잠글 결정은 화면 디자인이 아니라 운영 원칙이다.

승인 요청

hit만 export/save 허용

sourceStatus real이 아닌 URL은 시작일, export, My Flow 저장을 열지 않는다.

승인 요청

P1-review는 의도적 잠금

review 후보는 실패가 아니라 trust gate다. preview-only로 남기고 해제 조건을 명확히 쓴다.

승인 요청

AI-first 금지 유지

miss에서 즉시 AI 생성 기대를 만들지 않고, 요청/수집/검토 큐로 보낸다.

최종 문장: FlowMe P0는 “URL을 넣으면 AI가 새로 만들어주는 서비스”가 아니라, “이미 검증된 실행 구조를 찾아 기존 도구로 안전하게 옮기는 서비스”다.
