전문 UX 디자이너 관점으로 개선 방향을 잡고 테스트해야 함 충족 리허설 문서에 페르소나별 경로, Cognitive load, 버튼 affordance, Rubric 점수, 남은 리스크를 분리했습니다.
정말 깔끔하고 직관적인 UX로 만들어야 함 내부 기준 충족 카드 수와 설명을 줄이고, 정적 요약 카드와 실제 액션 카드를 분리했습니다. 실제 누르는 카드는 열기/접기/보기/선택됨 라벨로 결과를 예측하게 했습니다.
사용자 PoC와 리뷰를 분리해야 함 충족 사용자 화면은 `2026-06-24-my-flow-saved-execution-v11-ko.html`, 리허설/리뷰는 `2026-06-24-my-flow-saved-execution-v11-rehearsal-ko.html`로 분리했습니다.
버튼인지 설명인지 모호한 부분을 줄여야 함 충족 좌측 지도 요약은 button이 아닌 summary card로 낮췄고, Step/Flow/지도 선택에만 조작 라벨을 붙였습니다.
사용자 입장에서 상세히 시뮬레이션해야 함 충족 이사 D-14, 일정 확인, 중1 수학 진도, 지도 전환 경로를 사용자 행동 순서대로 리허설했습니다.

제품 판단

왜 이 상태를 완료로 볼 수 있는가

현재 목표 안에서 충분한 것

  • 저장한 여러 Flow를 오늘, 날짜, Flow, Flow Map 관점에서 찾을 수 있습니다.
  • Step은 캘린더/투두의 최소 실행 단위처럼 보이고, Item은 Step 내부 메모/체크로만 남습니다.
  • Progress Flow인 중1 수학에는 억지 Item을 만들지 않았습니다.
  • Timeline Flow인 이사는 날짜와 체크 Item이 함께 보입니다.
  • 공식 일정 성격인 아이 건강 일정은 Step 단위로만 보여 과도한 기간 task를 만들지 않습니다.

다음 목표로 넘길 것

  • 실제 `/my` 프로덕션 컴포넌트에 반영하는 개발 작업
  • localStorage/DB 저장, 버전 업데이트, sync 정책
  • Step의 ICS/캘린더 export 데이터 계약
  • 20개 이상 저장했을 때 검색, 정렬, grouping 최적화
  • 실제 사용자 관찰 세션으로 첫 클릭, 체크, 메모, 재방문을 확인하는 일

리허설 요약

사용자 관점 시뮬레이션 결과

사용자 상황 핵심 행동 판정
이사 D-14를 처리하는 사용자 오늘 탭에서 열린 Step을 보고 Item 체크, 업체 메모, 원문 링크 확인 통과 첫 화면에서 실행으로 바로 들어갑니다.
다음 날짜 할 일을 찾는 사용자 일정 탭에서 7월 23일 선택 후 D-7 Step 확인 통과 날짜 버튼과 Step 버튼 역할이 분리됩니다.
중1 수학 진도를 이어 보는 사용자 Flow 탭에서 수학 필터, 소인수분해 Flow 열기, Step 완료 통과 진도형 Flow가 체크리스트형으로 과해지지 않습니다.
큰 묶음을 훑어보는 사용자 지도 탭에서 생활 일정, 아이 건강 일정, 중1 수학 진도 전환 통과 지도는 실행 대시보드가 아니라 상위 구조 확인으로 좁혔습니다.

검증 기록

브라우저와 문서 검증

  • `npm run docs:check` 통과
  • Playwright 390px 모바일에서 Step 열기/접기, Item 체크, 메모 입력 확인
  • Playwright 390px 모바일에서 일정 날짜 선택, Flow 열기/접기, 지도 전환 확인
  • 1280px 데스크톱에서 가로 overflow 없음 확인
  • 사용자용 PoC에 내부 평가/리허설/제작자/개발자 문구 없음 확인
  • 좌측 지도 요약에 button이 없고, 실제 조작 카드에만 action label이 있음을 확인
