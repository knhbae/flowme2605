# FlowMe 자동 회귀 기준선 복구 감사

## 결론

2026-07-11 통합 E2E 첫 실행에서 `tests/e2e/flow-mvp.spec.ts`의 29개 시나리오가 실패했다. 신규 로컬 백업 기능의 회귀가 아니라 P18~P22에서 바뀐 사용자 계약을 과거 문구·날짜·내보내기 위치로 계속 검증하던 장기 스펙 부채가 대부분이었다.

제품을 과거 UI로 되돌리지 않고 테스트를 현재 기준으로 갱신했고, 실제 사용자 화면에서 확인된 문구 문제도 함께 정리했다.

## 유지한 제품 계약

- 홈의 첫 진입은 `URL이나 메모로 Flow 찾기`이며 기존 `/flows` lookup을 재사용한다.
- public `/f`의 1차 행동은 `내 Flow에 저장`, 내보내기는 Flow 단위 2차 행동이다.
- 모바일 public `/f`에 항목별 내보내기 버튼을 다시 만들지 않는다.
- My Flow와 Calendar의 제목·상세는 첫 할 일과 Flow명을 불필요하게 반복하지 않는다.
- native date input 값은 ISO를 유지하되 보이는 날짜 문구는 사용자 형식으로 검증한다.
- 원문 브랜드는 source 영역에서 보존하고 primary 사용자 문구의 source slug 노출과 구분한다.

## 실제 UI 정리

- 공개 creator profile에서 `수동 검토`, `1차 분류`, `샘플 준비` 같은 운영 통계 묶음을 제거했다.
- 운동·식단 도구의 `... 적용 Flow` 제목을 `이번 주에 적용할 운동 기준`, `오늘 한 끼 적용하기`처럼 실행 결과 중심으로 바꿨다.
- 새 Flow editor 헤더와 미리보기에도 trailing `Flow` 제거 정본을 적용했다.
- 수동 등록 URL hit 테스트는 Flow 성격별 날짜 test id와 사용자 문구를 사용한다.

## 해석 제한

이 결과는 자동 회귀 기준선이 현재 제품 계약과 다시 일치한다는 뜻이다. 실제 사용자가 Flow를 발견하고 저장·수정·완료·재사용하거나 백업 파일을 다른 기기로 옮길 수 있다는 관찰 증거는 아니다. P22-00 관찰 세션은 여전히 별도로 수행해야 한다.
