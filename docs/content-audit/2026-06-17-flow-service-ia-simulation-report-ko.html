Flow of Flow가 아니라 서비스 운영 구조부터 다시 확인했다

이 리포트는 내부 시뮬레이션이다. 실제 사용자 행동 데이터가 아니며, 제품 성과나 시장 반응을 확정하지 않는다.

작은 Flow 기준선 회복 사용자 관리 화면 추가 제작자 운영 화면 추가 실사용 검증 전

확인할 산출물

  • Flow 서비스 IA 재정렬 리포트
  • 사용자용 저장 Flow 관리 화면
  • 제작자용 Flow 운영판

사용자 저니 A

여러 원문을 저장해 둔 사용자가 오늘 할 일과 보관 자료를 구분하는 상황.

원문 소비전세 계약 가이드, 이사 체크리스트, 중고차 점검 글, 스퀴시 도안 영상을 각각 저장했다.
Flow함 진입사용자는 전체 목록이 아니라 오늘/예정/보관/반복 필터를 먼저 본다.
오늘 실행전세 D-Day와 중고차 방문 체크가 오늘 항목으로 보이고, 각각 날짜/현장 체크 detail로 열린다.
자료 보관스퀴시는 버킷 자료로 남고, 날짜가 생겼을 때만 캘린더에 붙인다.
재방문이사 D-10과 스투키 다음 물주기 후보가 예정/반복 영역에서 다시 보인다.

제작자 저니 A

생활 준비 콘텐츠 제작자가 여러 Flow를 공개하고 채널/컬렉션으로 묶는 상황.

작은 Flow 확인이사, 입학, 스퀴시, 스투키 각각의 원문과 artifact를 먼저 확인한다.
공개 전 점검원문 cue, 자연 산출물, 입력 복잡도, 주의 정보, 사용자 미리보기를 체크한다.
채널 운영서로 다른 Flow는 제작자 채널에 모으되, 사용자에게 같은 구조라고 속이지 않는다.
컬렉션 운영이사/입학처럼 생활 전환 시점이 비슷한 Flow는 컬렉션으로 묶는다.
Flow of Flow 보류중1 수학처럼 반복 패턴이 명확한 후보만 별도 Flow of Flow로 남긴다.

기존 Flow of Flow v2 실패 학습

Blocking · 하위 Flow가 독립 artifact처럼 보이지 않았다

단원/과목/월령을 나열하고 버튼을 붙였지만, 이전에 통과한 이사·중고차·스퀴시처럼 각 항목이 자기 캘린더/체크리스트/표/버킷으로 살아나는 느낌이 약했다.

High · 사용자 관리 화면 없이 상위 지도부터 만들었다

사용자가 이미 저장한 여러 Flow를 어떻게 찾고 실행하고 재방문하는지 확인하지 않은 상태에서 상위 지도 UX를 만들었다.

High · 제작자 운영 화면이 단순 변환 폼에 가까웠다

제작자가 공개된 Flow를 관리하고, 수정 필요 항목을 보고, 채널/컬렉션/커리큘럼으로 묶는 실제 운영 감각이 부족했다.

이번 수정으로 바꾼 점

수정 1 · 작은 Flow 기준선을 먼저 세움

전세, 이사, 중고차, 초등 입학, 홈트, 스퀴시, 스투키를 기준선으로 두고 destination, 입력, 관리 화면 표시값을 정리했다.

수정 2 · 사용자 Flow함을 제품 화면으로 만듦

오늘/예정/보관/반복 필터와 선택한 Flow의 artifact detail을 만들었다. 화면은 내부 평가 문서가 아니라 실제 저장 관리 화면처럼 작동한다.

수정 3 · 제작자 운영판을 분리함

제작자는 Flow 목록, 공개 상태, 원문 URL, artifact, 공개 전 점검, 사용자 미리보기, 묶음 타입을 관리한다.

남은 리스크

  • 이번 HTML은 정적 클릭 PoC라 실제 사용자 저장/재방문 데이터가 없다.
  • 제작자 화면은 운영 감각을 확인하는 수준이며 실제 버전 관리, 분석, 권한 모델은 구현하지 않았다.
  • Flow of Flow는 아직 제품 대표로 완료된 것이 아니라, 작은 Flow와 운영 구조가 통과한 뒤 다시 다뤄야 한다.
  • 영유아/건강 영역은 공식 정보와 경험 정보 분리 규칙을 계속 강화해야 한다.
