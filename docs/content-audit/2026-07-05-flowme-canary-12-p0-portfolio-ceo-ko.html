1. 결론

최종 canary 12개는 “넓은 콘텐츠 확장”이 아니라 P0 loop의 약점을 드러내는 테스트 세트다.

P0-now

4개 즉시 기준선

AJD 이사, 겟차 신차, 질병관리청 예방접종, 삼성 에어컨 필터는 현재 구현/문서 근거가 강한 P0 기준선이다.

P1-review

6개 조건부 확장

오픽, KKday, 웨딩, 도시락, 이유식, 홈트는 row 추출, 권한, 민감 문구 확인 뒤 canary로 올린다.

P2-hold

2개 보조 후보

오늘의집 이사와 아정당 자취는 유용하지만 AJD 이사와 중복/인접성이 크므로 다음 배치 비교군으로 둔다.

CEO 결정안: 12개를 모두 앱에 넣지 않는다. P0-now 4개로 QA 기준선을 만들고, P1-review 6개는 source gate를 통과할 때만 승격한다.

4. Ledger 커버리지

12개 모두 source URL과 risk/caution이 필요하지만, P0-now와 P1-review의 필드 완성도는 다르게 본다.

운영 그룹 필수 ledger 필드 현재 기대 수준 통과 조건 실패 시 처리
P0-now source_url, canonical_url, source_title, source_status, checked_at, version_ref, risk_level, caution, completion, export_generated_at source-backed map 또는 curated implementation 근거 있음 hit에서 export와 My Flow 저장 가능 needs_review로 강등
P1-review source_url, source_type, source row, permission/import note, caution, completion 후보 점수는 높지만 row/권한/민감 문구 확인 필요 원문 row와 export fallback이 확인되면 hit 승격 preview-only 유지
P2-hold canonical_url, duplicate reason, hold reason, comparison target 중복/인접 후보라 대표 canary 아님 기존 P0 후보가 실패하거나 다른 source shape 검증 필요 URL lookup에서는 miss/hold

7. 운영 로드맵

canary는 기능 추가 순서가 아니라 위험을 줄이는 운영 순서로 적용한다.

Phase A

P0-now 4개 고정

  • AJD 이사, 겟차 신차, 예방접종, 에어컨 필터
  • hit URL lookup과 export 기본값 고정
  • ledger 필드가 export에 남는지 확인
Phase B

P1-review 6개 승격 심사

  • row extraction과 source permission 확인
  • 민감 영역 caution 문구 확정
  • sheet형 후보는 P1 export로만 실험
Phase C

P2-hold 2개 보조군

  • 오늘의집 이사는 AJD와 비교용
  • 자취 리스트는 생활 독립 2차 배치
  • P0-now 실패 또는 coverage gap 때만 승격
