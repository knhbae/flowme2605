Round 2 콘텐츠가 현재 FlowMe UX에 맞는가?

10개 신규 Content Bundle을 현재 탐색, 공개 상세, 저장, My Flow, Calendar 흐름과 canonical 데이터 계약에 대조했다. 이 보드는 앱 구현 지시서가 아니라, 무엇을 그대로 쓰고 무엇을 고쳐야 하는지 검토하는 판정판이다.

판정: 현재 UX shell은 재사용 가능하다. 다만 기존 Step 중심 adapter에 바로 넣으면 133개 Item 중 상당수가 독립 할 일로 남지 않는다. 데이터 정규화와 공개 상세 형태 분류가 먼저다.
10검토한 신규 번들
6단일 Flow가 적합
3선택형 Map이 적합
1순서형 Map이 필요
53 → 133Step을 Item으로 잘못 세면 생기는 수량 차이

공통 이슈

시각 디자인보다 데이터 단위, 라우팅, setup 입력 계약이 우선이다. 항목을 열면 근거와 권장 조치를 볼 수 있다.

P0기존 adapter는 Step 53개만 실행 항목으로 만들고 Item 133개를 보존하지 못한다⌃
영향: 사진·콘텐츠의 하루 한 개 일정, 고용24의 개별 체크가 설명 속으로 들어가 완료와 날짜를 따로 관리할 수 없다.
조치: Round 2를 canonical Item-first 구조로 정규화한 뒤 기존 runtime으로 투영한다. Round 2 전용 우회 adapter는 만들지 않는다.
P1단일 Flow까지 모두 Map으로 보이면 저장 전에 불필요한 단계가 생긴다⌃
원칙: 버전을 고르는 콘텐츠만 Map을 사용한다. 하나의 목표와 하나의 실행 방식이면 `/f/[slug]`에서 바로 저장한다.
예외: 반찬은 child를 고르는 Map이 아니라 앞 단계가 뒤 단계의 전제인 순서형 Map이다.
P1현재 화면은 Step 수를 “할 일 수”로 표시한다⌃
영향: 30일 사진은 실제 30개 할 일인데 “5개 할 일”로 보인다.
조치: Item을 할 일 수로, Step을 단계·주차·시기 그룹으로 표시하고 Step 아래 Item을 묶는다.
P1현재 빠른 필터가 식사, 커리어, 취미, 가족 행사를 다루지 못한다⌃
영향: 콘텐츠가 약 17개로 늘면 새 번들이 검색어에 묻힌다.
조치: canonical lifeArea를 탐색 metadata로 쓰고, 화면에는 사용자의 상황을 설명하는 소수 빠른 필터만 유지한다.
P1Round 2의 setupFields와 현재 날짜 한 개 입력 UI가 맞지 않는다⌃
영향: 제목 입력은 무시되고, 결과를 바꾸지 않는 선택 날짜가 필수처럼 보일 수 있다.
조치: 일정 생성에 필요한 anchor만 저장 전에 받고, 제목·메모·개별 Item 날짜는 저장 후 My Flow에서 수정한다.
P2반찬, 차량검사, 고용24 등 일부 Item은 화면에 올리기 전 문맥 보정이 필요하다⌃
예: 반찬은 실제 메뉴명을 detail에 남기고, 차량 재검사는 모든 사용자에게 활성 Item으로 만들지 않는다. 기관이 처리하는 고용24 상태는 사용자가 완료할 수 있는 문장이나 명시적 완료 기준이 필요하다.

권장 적용 순서

여러 콘텐츠를 한꺼번에 넣기보다 서로 다른 실행 패턴 세 가지를 먼저 통과시킨다.

1 · 날짜형K-MOOC 단일 Flow로 주간 일정과 Calendar 투영 검증
2 · 체크형고용24 일반 Flow로 날짜 없는 먼저 할 일과 완료 검증
3 · 선택형가족 행사 Map으로 child 한 개 선택·저장 검증
4 · 고밀도30일 사진으로 30개 Item의 Today·Calendar 밀도 검증
5 · 의존형반찬 데이터를 고친 뒤 순서형 Map 전체 저장 검증

현재 앱 shell의 모바일 동작은 기존 대표 콘텐츠로 검증했다. Round 2 자체는 아직 앱에 넣지 않았으므로, 위 판정은 현재 코드·타입·실제 동선과 준비 데이터를 대조한 사전 적합성 검토다.

상세 근거와 파일/라인 참조는 같은 날짜의 Markdown 검토 문서에 있다. 앱 코드와 seed는 이 검토에서 수정하지 않았다.
