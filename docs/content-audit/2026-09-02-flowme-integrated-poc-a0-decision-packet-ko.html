A0-1일반 텍스트는 Personal Flow로 명시적 handoff기존 방향 계승

선택과 이유

개발 2의 plain-text first를 유지하고, 통합 blueprint가 정한 개인공간 진입 목적지를 따른다. 사용자의 확인 전에는 Flow를 만들지 않는다.

채택하지 않은 안

CreatorDraft와 Personal Flow를 한 저장처럼 합치지 않는다. CreatorDraft lifecycle을 별도 구현할 때 다시 검토한다.

OWNER · WRITE

authoring source는 그대로 보존하고 handoff 결과만 PoC shadow namespace에 기록한다.

NEXT ACCEPTANCE

A0-2운영 데이터는 읽기만, 변경은 shadow staged command기존 owner 계승

선택과 이유

채택하지 않은 안

현재 단계에서 Calendar·trash·export writer를 연결하지 않는다. 운영 migration과 rollback 승인이 있어야 다시 연다.

OWNER · WRITE

A0-5고급 문법은 추정하지 않고 보존·차단·보류이번 PoC 제외

A0-6React는 제품 정본, standalone은 조작형 offline fixturePoC 역할 선택

선택과 이유

React만 live origin과 exact route 통합을 증명한다. standalone은 사용자가 파일을 직접 열어 core 시나리오를 조작·검토하는 동반 산출물이다.

채택하지 않은 안

standalone을 운영 integration과 동등하다고 표현하지 않는다. core UX가 달라지면 fixture라는 이유로 숨기지 않고 맞춘다.

OWNER · WRITE

각 파일은 자기 전용 PoC key만 사용한다. live origin·operating writer는 standalone 범위가 아니다.

NEXT ACCEPTANCE

QuickItem·이동·완료·Undo·reload·오류 상태의 사용자-visible 결과가 React와 같아야 한다.
