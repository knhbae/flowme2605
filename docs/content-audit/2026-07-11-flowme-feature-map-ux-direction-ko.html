FlowMe feature map · service comparison · 2026-07-11

기존 서비스와 vertical 앱을 기준으로 다시 그린 FlowMe 기능 맵

FlowMe는 todo, calendar, note, health, meal planner, travel itinerary 앱을 대체하는 제품이 아니다. 핵심 기능 맵은 “외부 콘텐츠와 사용자 메모를 실행 가능한 아티팩트로 컴파일하고, 사용자가 자기 도구나 My Flow에서 실행하게 하는 것”으로 다시 정리하는 편이 맞다.

1. 결론

Positioning

FlowMe의 기준 기능은 “계획 앱”이 아니라 “실행 아티팩트 컴파일러”다

사용자가 이미 찾은 글, 영상, 표, 공식 안내, 개인 메모를 가져오면 FlowMe는 일정, 체크리스트, 시트 행, Markdown, My Flow 실행 상태로 바꾼다. 이 위치가 Todoist, Google Calendar, Obsidian, Health, TripIt, Paprika와 구분되는 지점이다.

Current gap

기능은 많이 붙었지만, 사용자 머릿속 기능 맵은 아직 선명하지 않다

현재 repo에는 URL lookup, 후보 저장, 개인 사본, My Flow, Calendar, Step export가 들어와 있다. 다만 화면에서는 “가져오기 → 고치기 → 실행하기 → 옮기기 → 다시 쓰기”라는 큰 기능 맵이 한눈에 보이지 않는다.

Direction

다음 방향은 vertical 기능 추가보다 공통 루프를 먼저 단순화하는 것

여행, 식단, 건강, 운동, 학습, 행정 Flow를 많이 넣기 전에 같은 공통 루프를 안정화해야 한다. vertical 앱의 좋은 점은 카테고리별 “입력·기록·회고 표면”으로 빌려오고, 직접 연동과 자동 코칭은 뒤로 둔다.

한 줄 방향: FlowMe = URL·메모·원문을 가져와 실행 가능한 Flow로 만들고, My Flow와 사용자의 기존 도구에서 계속 쓰게 하는 layer. 화면 구조는 이 문장을 기준으로 다시 배치해야 합니다.

2. 기존 서비스 기준선

서비스군 대표 서비스 사용자가 이미 기대하는 기능 FlowMe가 맡을 일 따라 하면 안 되는 일
Todo / daily task Todoist, Microsoft To Do, TickTick 빠른 입력, Today, Upcoming, 반복, 체크 완료, 작은 daily scope. 외부 원문에서 할 일 row를 뽑아 Today와 체크리스트로 넘긴다. 빈 task manager나 모든 작업의 원천이 되려고 하지 않는다.
Calendar / scheduling Google Calendar, Notion Calendar, Reclaim 날짜 있는 task/event, 시간 배치, date property, 자동 time blocking. 날짜가 있는 Step만 Calendar/ICS로 만들고, 나머지는 checklist/memo로 유지한다. 초기부터 자동 스케줄러나 Google/Outlook 직접 sync가 되려고 하지 않는다.
Notes / workspace Obsidian, Notion Markdown, 링크, 데이터베이스, 시각적 canvas, 개인 소유와 확장성. Markdown, TSV, source link, 실행 메모를 깨끗하게 내보낸다. 초기부터 Obsidian vault나 Notion workspace를 대체하지 않는다.
Automation Zapier 수천 개 앱 연결, trigger/action, template, no-code workflow. 나중에 자동화가 쓸 수 있는 구조화된 Flow/Step/export payload를 만든다. Stage 0에서 automation builder를 만들지 않는다.
Meal / nutrition MyFitnessPal, Cronometer, Paprika 식사 기록, barcode/photo/voice 입력, 영양 정보, 식단표, 장보기 목록. 원문 식단표와 레시피를 주간 식단, 장보기, 오늘 기록으로 변환한다. 영양·의료 조언을 생성하거나 건강 데이터 앱이 되지 않는다.
Health / exercise Apple Health, Samsung Health, Strava 운동 기록, 추세, coaching, privacy, training log, community. 원문 운동 프로그램을 세션 일정, 체크, 회고 메모로 만든다. HealthKit, wearable sync, 의료 판단, 성과 보장을 초기에 넣지 않는다.
Travel / learning / finance TripIt, Duolingo, YNAB 여행 itinerary, daily streak, 목표/예산 progress. 여행 준비·코스·공식 절차, 학습 커리큘럼, 행정/금융 due date를 실행 Flow로 만든다. 항공 알림, 게임화 streak, 예산관리 엔진을 복제하지 않는다.

3. 새 기능 맵

기능을 화면 이름이 아니라 사용자 가치 사슬로 다시 묶으면 아래 5개 층입니다. 이 구조가 유지되면 vertical 카테고리가 늘어나도 제품이 todo 앱, 캘린더 앱, 건강 앱처럼 흩어지지 않습니다.

1. Intake

가져오기

  • URL 붙여넣기
  • 메모 붙여넣기
  • 대표 Flow 탐색
  • 공유 링크 진입

첫 질문: “무엇을 실행물로 바꿀까?”

2. Compile

Flow로 정리하기

  • URL canonical lookup
  • hit / miss / needs_review
  • source-backed manual registration
  • memo draft / AI gate

첫 기준: 출처와 실행 가능 상태를 섞지 않는다.

3. Configure

가볍게 고치기

  • 시작일
  • 개인 저장 이름
  • 포함/제외 Step
  • 내보내기 방식

전체 편집기가 아니라 시작 전 조정판.

4. Execute

실행하기

  • My Flow Today
  • 전체 Flow 관리
  • Calendar agenda
  • Step detail / check / memo

오늘 할 1~3개와 날짜 있는 Step이 먼저.

5. Portable loop

옮기고 다시 쓰기

  • Markdown / checklist
  • ICS / TSV
  • source trace 유지
  • feedback / version / creator loop

직접 연동보다 파일·복사 품질이 먼저.

5. vertical 앱별 FlowMe 방향

생활 영역 기존 vertical 앱 문법 FlowMe 기능 맵에 넣을 것 현재 repo와의 연결
여행·외출 TripIt처럼 예약·확인 정보를 itinerary로 묶고 reminder를 준다. 준비물, 공식 출국 절차, 입국 등록, 일자별 코스를 child Flow로 분리한 여행 Flow Map. content coverage 문서가 여행을 첫 breadth canary로 제안. 준비물+공식 절차부터 작게 시작.
식단·장보기 Paprika는 recipe, meal plan, grocery list를 연결하고 MyFitnessPal/Cronometer는 기록과 영양 snapshot을 준다. 원문 식단표 row, 장보기 항목, 오늘 먹은 것 메모, 주간 수정 회고. 영양 조언은 제외. 도시락/이유식/식단 후보가 있음. 일반 성인용 주간 식단은 canary 후보.
건강·운동 Apple/Samsung Health는 privacy와 trend, Strava는 training log와 community를 강조한다. source-backed 운동 세션, completion, 컨디션 메모, trend-like review. 의료 판단과 wearable sync는 제외. Allblanc, 5km 프로그램, 공식 검진 일정 후보가 있음. 민감도 때문에 source/risk 분리 유지.
학습·자격증 Duolingo는 짧은 daily habit과 streak, 학습 앱은 curriculum/progress를 보여준다. 원문 커리큘럼 row, 날짜 기반 학습 calendar, 오답/복습 TSV, 완료 회고. 중1 수학, OPIC, 학습 루틴 Flow가 sourceTrace 보완과 QA-pass 흐름으로 정리됨.
행정·금융 YNAB처럼 목표와 progress를 관리하거나 공공 서비스는 due date와 서류를 명확히 한다. 공식 due date, 제출 서류, 완료 기준, 주의사항을 하나의 check/calendar artifact로 만든다. 주소 이전, 연말정산, 운전면허 갱신, 자동차 검사 같은 lifecycle Flow에 적합.
집·가전·반려 maintenance 앱은 반복 주기와 준비물, pet 앱은 첫 주 루틴과 건강 주의 경계를 다룬다. 반복 청소/관리 세션, 준비물, 사진/메모 증거, 민감한 반려 건강 caution 분리. 에어컨 필터, 세탁조, 몬스테라, 새끼 고양이 첫 주 후보와 잘 맞음.

6. 화면 구조 방향

Current screen map

지금 화면은 기능이 route별로 흩어져 있다

  • /: Home과 URL·메모 진입.
  • /flows: URL lookup, 후보 저장, catalog, start panel.
  • /flow-maps/[map], /f/[slug]: 저장 전 public detail.
  • /my: saved execution, Today, 전체, Step detail, export.
  • /calendar: dated Step schedule-first execution.
  • /content-flows, /flow-lab: internal review/QA.
Recommended mental model

사용자에게는 4개 동사로 보여야 한다

  • 가져오기: URL 또는 메모를 넣는다.
  • 시작하기: hit Flow나 memo draft를 내 상황에 맞춘다.
  • 실행하기: 오늘 할 일과 날짜 있는 일정을 본다.
  • 옮기기: Markdown, checklist, ICS, TSV로 내 도구에 보낸다.

UI 방향은 “탭을 더 늘리는 것”이 아니라, 각 화면의 첫 viewport에서 이 동사 중 하나만 우선하도록 정리하는 것입니다. Home과 /flows는 가져오기, public detail은 시작하기, My Flow와 Calendar는 실행하기, Step detail은 옮기기와 조정하기입니다.

8. 다음 검토 질문

사용자에게 보여줄 질문

눈으로 볼 때 확인할 것

  • FlowMe가 “계획 앱”보다 “실행 아티팩트 컴파일러”로 보이는가?
  • URL, 메모, catalog, public share가 같은 시작 전 수정 패널로 이어지는가?
  • My Flow와 Calendar가 기존 todo/calendar 사용자에게 과하지 않은가?
  • vertical canary가 생활 문제 단위로 보이고 내부 데이터 타입처럼 보이지 않는가?
  • 내보내기가 Obsidian, 메모장, todo, calendar 사용자에게 충분히 자연스러운가?
다음 산출물 후보
