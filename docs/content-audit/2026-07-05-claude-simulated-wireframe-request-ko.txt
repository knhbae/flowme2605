Claude가 컨텐츠를 고르는 방법:
- 아래 필수 예시 6개는 반드시 포함하되, 위 인벤토리에서 추가로 6~10개 컨텐츠를 더 골라 화면 시뮬레이션에 반영해라.
- 한 분야만 보지 말고 생활/이사/자동차/육아/공부/운동/가전관리/행정문서처럼 서로 다른 사용 맥락을 섞어라.
- route가 있는 컨텐츠는 실제 route 기준으로 적어라. 예: single Flow는 `/f/[slug]`, Flow Map은 `/flow-maps/[map]`.
- route가 아직 public에 노출되지 않은 후보는 "후보/검토 큐"로 분리하고, 사용자 화면에 바로 노출하지 말아야 할 이유를 적어라.
- 모든 컨텐츠를 다 그릴 필요는 없다. 대신 12~16개 대표 컨텐츠를 골라, 어떤 화면 패턴을 검증하는 데 쓰는지 표로 정리해라.

중요 전제:
- 기존 4-tab IA인 Home / Flow 찾기 / Calendar / My Flow는 유지 기준이다.
- FlowMe는 새 캘린더/투두/노트앱을 대체하려는 서비스가 아니다.
- 사용자는 이미 Google/Outlook Calendar, Todoist, Microsoft To Do, Excel/Sheets, Notion, Obsidian, 일반 메모장을 쓰고 있다.
- 따라서 기존 도구 사용자들이 "이 정도면 복사해서 쓸 만하다"고 느끼는 사용성이 기준선이다.
- 초기에는 원 컨텐츠에 FlowMe 링크가 이미 붙어 있다고 가정하지 않는다.
- 현실적인 1차 진입은 사용자가 블로그/유튜브/사이트/PDF/커뮤니티 글 URL을 FlowMe에 넣는 것이다.
- 같은 URL이 이미 Flow로 변환된 적이 있으면 AI를 다시 쓰지 않고 기존 Flow를 먼저 보여준다.
- 사용자는 시작일, 기간, 강도, 목적지, 일부 항목을 바꾸거나, 마음에 안 들면 얇게 수정/fork할 수 있다.
- AI 생성은 기본 경로가 아니라 lookup miss, low-quality hit, 사용자의 재생성 요청 때만 fallback으로 쓴다.
- 사용자가 만든 Flow 링크가 원 컨텐츠 댓글/공유 경로로 돌아가고, 원 컨텐츠 주인이 나중에 그 Flow를 발견해 공식적으로 활용할 수 있는 adoption loop도 고려한다.
- memo-to-Flow는 일상화와 확산에 중요하다. 사용자가 메모장처럼 계획을 적으면 FlowMe가 보기 좋은 Calendar/Todo/Markdown 구조로 정리해주는 흐름도 설계한다.
- Flow를 개인 실행용으로 My Flow에 저장하거나, Flow 컨텐츠로 공유/발행하는 경계도 제안한다.

실제 컨텐츠 기반 시뮬레이션에 반드시 넣을 예시:

1. URL hit / duplicate reuse: 이사 준비
- 사용자가 AJD 이사 준비 체크리스트 URL을 붙여넣는다.
- 기존 컨텐츠: `원룸 이사 D-30 일정 지도`, `/flow-maps/moving-d30`, `source-backed-moving-d30`
- 사용자 입력 예: 이사일 `2026-08-24`
- 기대 산출물: D-30/D-7/D-3/D-1/D-Day 일정, 체크리스트, Calendar `.ics`, Markdown/메모 복사, My Flow 저장, Calendar agenda
- 화면에서 보여줄 것: "이미 변환된 Flow가 있음", 원문 제목/출처/검토일, 시작일 변경, export 목적지 선택, 얇은 수정 버튼

2. 공유/public Flow 저장: 자동차검사
- 기존 컨텐츠: `자동차검사 D-14 준비`, `/f/vehicle-inspection-prep`
- 사용자가 검사 예정일을 넣고 저장하거나 캘린더 파일을 받는다.
- 기대 산출물: 준비 서류/예약/검사 당일/결과 후속 체크, Calendar/Todo export, My Flow 저장 후 첫 항목
- 화면에서 보여줄 것: 공유 shell과 app shell의 경계, 저장 전 preview, 저장 후 My Flow 이동

3. 날짜 없는 구조형 컨텐츠: 중1 수학 목차 진도표
- 기존 컨텐츠: `/flow-maps/middle-school-math-1`
- 사용자가 날짜 없이 저장하고 단원별 진도표로 쓴다.
- 기대 산출물: checklist/sheet-like progress, My Flow 오늘/전체에서 첫 학습 항목
- 화면에서 보여줄 것: Calendar가 없어도 Flow가 쓸모 있는 구조, Markdown/Sheet export 우선순위

4. 특수 export/workbench 컨텐츠: 냉장고 파먹기 또는 이유식
- 후보 route: `/f/fridge-cleanout-weekly-plan`, `/f/baby-food-menu-recipe`
- 사용자가 시작일을 넣고 식단/재고/메뉴 캘린더 또는 시트형 산출물을 확인한다.
- 기대 산출물: Sheet/CSV/Markdown 중심 export, 필요한 경우 calendar 보조
- 화면에서 보여줄 것: 일반 Flow detail과 특수 workbench가 같은 앱처럼 보이는지

5. memo-to-Flow: 메모장에서 온 계획
- 사용자 메모 예:
  "8월 말 이사 예정. 이번 주에는 집 하자 점검, 이사업체 견적, 관리사무소 연락. 다음 주에는 전입신고 준비랑 주소 변경. 체크리스트랑 캘린더로 정리하고 싶음."
- 기대 산출물: private draft Flow, Calendar/Todo/Markdown preview, 기존 이사 Flow 추천, "원문 URL 없음" trust 표시
- 화면에서 보여줄 것: URL-first가 주 경로이고 memo-to-Flow는 secondary entry지만, 같은 export/My Flow 구조로 수렴해야 한다.

6. low-quality hit / lookup miss
- 예: 사용자가 일반 블로그 URL이나 유튜브 URL을 넣었는데 기존 Flow가 있긴 하지만 원문 매칭이 약하거나 변환 품질이 낮다.
- 화면에서 보여줄 것:
  - 기존 변환을 그대로 쓰기
  - 얇게 수정해서 쓰기
  - AI로 다시 초안 만들기
  - Park/보류하기
- 단, AI를 기본 CTA로 앞세우지 말고 비용과 품질 리스크를 낮추는 표현으로 설계한다.

6. Flow 컨텐츠화 흐름
- URL 변환 결과 또는 memo draft를 언제 private draft로 둘지
- 언제 shareable Flow로 만들지
- 언제 원 컨텐츠 댓글/공유 링크로 돌릴지
- 언제 source owner/creator claim으로 이어질지

- P0: 바로 구현해야 할 최소 화면/상태/데이터 5~8개
- P1: P0 이후 붙일 확장
- P2: 나중에 실험할 기능
- 각 항목에 관련 component/file path를 붙여라.

8. 사용성 리스크
- 사용자가 헷갈릴 수 있는 지점
- 기존 앱 구조와 충돌하는 지점
- 너무 복잡해지는 지점
- 모바일에서 가려지거나 중복 CTA가 생길 수 있는 지점

9. 만들지 말아야 할 방향
- 기존 앱과 무관한 새 서비스처럼 재설계 금지
- 새 랜딩페이지 중심 제안 금지
- AI-first 생성 UX 금지
- 원 컨텐츠에 FlowMe 링크가 이미 붙어 있다는 가정 금지
- fake usage count, fake review, fake creator 인증 금지
- full auto-scheduler 제안 금지
- Notion/Obsidian 대체 workspace 제안 금지
- creator marketplace를 P0처럼 크게 다루는 것 금지
- heavy editor/version graph를 P0로 제안 금지
- direct OAuth integration을 portable export보다 앞세우는 것 금지
- 기존 content/workbench route를 무시하고 완전히 새 UX만 제안하는 것 금지
