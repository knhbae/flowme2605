FlowMe 전략 세션 2026-07-05 Canary 12 URL-first P0

다음 할 일은 구현이 아니라, 구현이 충돌하지 않게 넘기는 것이다

이 보고서는 개발 계획서가 아니라 전략 handoff 문서다. URL-first, Export Pack v1, ledger, Canary 12, 실행 시나리오, implementation slice를 하나의 실행 순서로 재배열하고, 현재 다른 개발 흐름과 부딪힐 수 있는 영역을 CEO/임원 관점에서 분리한다.

CEO 결론

Canary 12 전략은 유지한다. 다만 다음 개발 세션은 바로 UI를 더 고치는 것이 아니라 worktree ownership 확인 → 정책/registry 고정 → `/flows` UI 연결 → export/ledger/storage → E2E 순서로 직렬화해야 한다.

이번 세션 범위

전략만 코드 구현 없음 handoff 기준 확정

6 연결해야 할 기존 전략 보고서: URL-first, Export, ledger, Canary 12, 실행 시나리오, implementation scorecard.
4 충돌 위험이 높은 핵심 개발 파일: `/flows` UI, source-backed map, storage, E2E.
0 이번 전략 세션에서 해야 할 app code 변경 수. 보고서만 추가한다.
5 개발 handoff 전에 잠글 의존성 단계: policy, UI, export, storage, QA.

1. 전략 세션의 정확한 역할

이 방은 “무엇을 왜 어떤 순서로 넘길지”를 정하는 곳이다. 코드 변경은 별도 개발 세션에서만 한다.

session boundary

전략 세션에서 한다

제품 우선순위, 운영 상태, 위험 분류, 의존성, handoff 조건, 제외 범위를 결정한다.

전략 세션에서 하지 않는다

AppClient.tsx, storage, E2E, source-backed map을 직접 고쳐 구현 완료를 주장하지 않는다.

개발 세션으로 넘긴다

registry 구현, UI 연결, export 생성, ledger 저장, Playwright E2E는 개발 세션의 책임으로 넘긴다.

3. 전략 의존성 다이어그램

아래 순서가 바뀌면 UI, 저장, export, QA가 서로를 끌고 가면서 충돌 범위가 커진다.

dependency
전략 승인 P0-now 4, P1-review 6, P2-hold 2 운영 분류와 제외 범위를 승인한다.
Policy / registry Canary status, risk, default artifact, export permission, lock reason을 코드 contract로 넘긴다.
`/flows` UI hit / needs_review / miss / hold 화면과 CTA를 연결한다.
Export Pack `.ics`, Markdown, checklist의 실제 output과 disabled state를 확정한다.
Ledger / storage source, checked date, risk, caution, version, export date를 저장과 파일에 남긴다.
QA / release gate unit, targeted E2E, docs:check, build, mobile screenshot으로 완료 여부를 말한다.

5. Canary 운영 순서

12개를 한 번에 제품화하지 않는다. P0-now는 증명, P1-review는 잠금 운영, P2-hold는 비교/백업이다.

portfolio order

P0-now 4개

URL-first loop, portable export, My Flow save, ledger 저장이 실제로 이어지는지 검증하는 주력 후보.

  • 이사 D-30
  • 차량구매/점검형
  • 예방접종/건강 민감형
  • 에어컨필터 routine형

P1-review 6개

source/import 권리, 민감 문구, creator/community 운영 기준이 정리되기 전까지 preview/lock만 허용한다.

P2-hold 2개

제품 방향 비교와 백업 후보로 유지한다. P0 성공 조건에 넣지 않고 export/save도 열지 않는다.

6. 전략 세션 결정 vs 개발 세션 handoff

회의에서 결정할 것과 코드로 넘길 것을 섞으면 논의가 길어지고 구현 충돌이 커진다.

handoff split
주제 전략 세션에서 결정 개발 세션으로 넘김
URL-first 포지션 FlowMe의 첫 진입은 URL lookup-first이고 AI는 fallback이라는 원칙을 유지한다. 입력 필드, result sheet, route 이동, 상태 copy 구현.
Export Pack v1 P0는 direct API가 아니라 `.ics`, Markdown, checklist 중심 portable export로 결정한다. 파일 생성, 다운로드, checklist rendering, disabled state 구현.
Ledger source/version/trust 최소 필드와 민감 영역 caution 원칙을 승인한다. map, export, storage, My Flow snapshot에 필드를 연결한다.
Canary 12 P0/P1/P2 운영 분류와 lock 원칙을 승인한다. registry, lookup policy, unit/E2E test case로 고정한다.
QA 어떤 증거가 있어야 “완료”라고 말할지 scorecard를 승인한다. 명령 실행, screenshot, build, E2E 결과를 남긴다.

7. 이번 전략 흐름 제외 범위

아래 항목은 제품적으로 중요할 수 있지만, Canary 12 P0 handoff를 흐리게 만든다.

do not mix

Home redesign

`/flows` URL-first loop 검증 이후 별도 전략으로 다룬다.

Direct API/OAuth

P0는 portable export다. Calendar/Notion/Todoist direct 연결은 P1/P2다.

AI-first generation

URL lookup-first 원칙을 흔들지 않는다. miss에서 AI가 앞에 나오면 안 된다.

Full editor

light edit/fork 방향은 유지하되 원본 편집기까지 열지 않는다.

Fake usage

사용자 검증 없는 인기, 사용량, 성공 claim을 넣지 않는다.

동시다발 구현

`/flows`, storage, export, E2E를 병렬로 건드리지 않는다.

8. 다음 handoff 문장
