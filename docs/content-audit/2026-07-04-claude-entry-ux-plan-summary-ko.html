좋은 방향이다. 다만 바로 구현하려면 더 얇게 잘라야 한다.

ZIP 안의 Claude 산출물은 현재 UI P0~P6 마감 감사와 별도의 URL-first 진입 UX 기획이 섞여 있다. 이 보드는 URL 기획을 제품 백로그로 옮기기 전에, 채택할 기준선과 조정할 지점, 첫 PoC 범위를 분리한다.

요약 판단

Core

Claude의 중심선은 현재 결정과 맞다.

사용자는 URL을 붙여넣고, FlowMe는 AI를 쓰기 전에 같은 canonical URL의 기존 Flow를 먼저 찾는다. 있으면 바로 재사용하고 옵션만 바꾼다. 없거나 품질이 낮을 때만 AI 생성 또는 생성 요청으로 간다.

1

URL 입력

링크 또는 직접 메모를 같은 진입구에서 받는다.

2

정규화

utm, 모바일 도메인, youtu.be 등을 하나의 key로 모은다.

3

기존 Flow

hit이면 AI 호출 없이 preview와 쓰기 CTA를 보여준다.

4

옵션

시작일, 강도, 목적지 등 내 실행 조건만 바꾼다.

5

실행

My Flow 저장 또는 캘린더/Markdown export로 끝낸다.

Important

바로 수정해야 할 해석

`N명이 사용`, 완주율, fork 수 같은 신호는 실제 데이터가 생기기 전까지 사용자 화면에 두면 안 된다. 초기에는 출처, 변환 시점, 미리보기, 입력 조건, export 결과만 보여주는 게 맞다.

채택할 기준선

기준판단이유
재사용 우선, AI는 fallback채택AI 비용을 낮추고 같은 URL의 Flow를 축적하는 현재 제품 결정과 일치한다.
한 화면에 한 결정채택`쓰기 / 고치기 / 새로 만들기`를 동시에 강하게 묻지 않아야 첫 진입이 가볍다.
출처가 카드, 상세, export까지 따라감채택source-backed Flow의 신뢰와 저작권 경계를 지키는 최소 조건이다.
저장은 실행 시작채택저장 직후 빈 성공 화면이 아니라 첫 실행 항목으로 이어져야 한다.
메모를 같은 입력구에 붙임조건부3번 사용성을 별도 앱처럼 키우기보다 같은 Flow 모델로 붙이는 방향이 좋다.

조정할 지점

Login

export는 로그인 뒤로 밀지 않는 편이 낫다.

Claude는 저장/export/fork에서 로그인을 요구하는 흐름을 제안했다. 하지만 초기 획득 동선의 핵심은 남의 콘텐츠를 빠르게 내 도구로 가져가는 것이다. 검색, preview, 캘린더 파일 받기, Markdown 복사는 가능한 한 비로그인으로 열고, My Flow 저장과 fork/public 공유에서 로그인을 요구하는 편이 낫다.

AI Cost

첫 PoC는 자동 생성 없이도 성립해야 한다.

기존 Flow가 없는 URL에서 바로 AI를 돌리는 것은 제품적으로는 자연스럽지만 비용과 품질 리스크가 있다. 첫 PoC는 lookup-only로 잘라도 된다. 없는 URL은 `생성 요청` 또는 concierge queue로 보내고, 자동 AI 생성은 비용 로그와 품질 gate가 붙은 뒤 켜는 편이 안전하다.

Source

full snapshot은 MVP에서 무겁다.

원문 변경 감지를 위해 snapshot/hash가 필요하다는 방향은 맞다. 다만 본문 전체 저장은 저작권과 저장 비용이 크다. MVP는 canonical URL, 제목, 작성자/매체, 변환 시점, 짧은 source row, hash/etag 후보 정도로 시작한다.

Edit

무거운 fork는 나중, 얇은 개인 수정은 빨리.

diff, fork graph, 좋은 fork 승격은 Later가 맞다. 하지만 사용자가 시작일, 제목, 날짜, 메모, 체크 Item을 내 사본에서 고치는 얇은 편집은 P1로 당겨야 한다. 현재 앱이 고정 구조라 느껴지는 문제를 바로 줄여준다.

추천 PoC 순서

P0

lookup-only URL 진입

AI 없이도 URL hit, 옵션 변경, export/My Flow 저장이 되는지 확인한다.

  • canonical URL 정규화 함수와 테스트
  • seed URL과 기존 Flow/Flow Map 매핑
  • hit 경로 AI 호출 0회 로그
  • 저장 후 My Flow/Calendar 첫 실행 항목
  • 비로그인 `.ics` 또는 Markdown export

P1

생성 요청과 얇은 편집

없는 URL을 바로 자동 대량 생성하지 않고 품질 gate와 비용 인식을 붙인다.

  • 없으면 `새 Flow 생성 요청` 상태
  • AI 초안은 명시적 선택
  • 원문 링크, 변환 시점, 근거 row 표시
  • 제목, 시작일, 메모, Item 얇은 수정

P2

fork, 후보 목록, 메모 입력

축적된 Flow가 여러 개일 때 추천/분기/개인화가 가능해진다.

  • 같은 canonical URL 후보 목록
  • 좋은 fork 승격 기준
  • `직접 쓰기` 메모 입력 탭
  • Obsidian/Markdown export 확장
추천 착수: `P0 lookup-only URL 진입`부터 한다. AI 생성 없이도 제품 핵심 가설을 검증할 수 있고, 비용과 품질 리스크를 뒤로 밀 수 있다.

다음 결정 질문

Decision

  1. 첫 PoC를 `lookup-only`로 자를지, `AI 초안 생성`까지 포함할지.
  2. URL 입력 진입을 기존 `/flows` 안에 붙일지, 별도 `/flows/new` 또는 `/import`로 둘지.
  3. 비로그인 export 허용 범위를 어디까지 둘지.
  4. canonical URL 매핑을 기존 seed 데이터에 어떻게 붙일지.
  5. 원문 snapshot을 얼마나 저장할지.

Do not build now

  • fake 사용 수, fake 완주율, fake 리뷰
  • 자동 AI 재생성
  • creator adoption 자동화
  • marketplace, 결제, 토큰
  • Google Calendar/Todoist/Notion 직접 계정 연동
  • full Obsidian 대체 workspace
  • 무거운 diff editor
