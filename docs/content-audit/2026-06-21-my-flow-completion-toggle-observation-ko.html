완료 액션 판단

상세 화면의 완료는 버튼이 아니라 작은 토글이어야 한다

현재 목표는 My Flow를 프로젝트 관리 도구처럼 만들지 않고, 캘린더/투두 앱 수준의 단순한 실행 화면으로 정리하는 것이다. Step 완료 신호는 필요하지만, 상세 drawer의 큰 CTA는 과하다.

판정

제거가 아니라 축소

완전히 제거상세에서 실행을 마친 사용자가 어디서 완료 표시를 해야 하는지 다시 목록으로 돌아가야 한다.
큰 완료 CTA상세가 메모/원문 확인보다 상태 처리 화면처럼 보인다. 현재 목표와 맞지 않는다.
작은 완료 토글완료 신호는 유지하되, 메모와 상세 확인을 방해하지 않는다. 현재 선택안이다.

비교 PoC 상세 완료 있음과 상세 완료 없음을 같은 화면에서 바꿔 볼 수 있다. docs/content-audit/2026-06-21-my-flow-completion-toggle-ab-poc-ko.html
결정 문서 item drawer의 완료는 large primary CTA가 아니라 small check toggle이어야 한다고 기록했다. docs/DECISIONS.md

관찰할 것

다음 실제 관찰 질문

질문 유지 신호 제거 신호
사용자가 상세에서 메모를 남긴 뒤 완료까지 표시하는가? 메모 후 작은 완료 토글을 자연스럽게 누른다. 항상 목록으로 돌아가거나 완료 표시 자체를 하지 않는다.
작은 완료 토글이 메모 입력을 방해하는가? 사용자가 먼저 메모를 확인하고 필요할 때만 토글한다. 사용자가 토글을 primary action으로 오해하거나 메모를 놓친다.
목록의 체크 컨트롤과 상세 토글이 중복으로 느껴지는가? 목록에서는 빠른 완료, 상세에서는 확인 후 완료로 역할이 갈린다. 둘 다 같은 동작으로 보여 혼란이 생긴다.

현재 결론

현 단계에서는 유지

  • 유지 Step 완료 신호는 캘린더/투두 이식성과 재방문 상태에 필요하다.
  • 축소 다만 상세에서는 큰 CTA가 아니라 작은 체크 토글로만 둔다.
  • 관찰 필요 실제 사용자가 메모만 쓰고 완료 토글을 거의 쓰지 않으면 상세에서는 숨기는 쪽으로 다시 줄인다.
