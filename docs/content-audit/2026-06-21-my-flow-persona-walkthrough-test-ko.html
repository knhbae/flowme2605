내부 UX 검증

My Flow 페르소나 Walkthrough 테스트

목적은 AI가 만든 그럴듯한 평가가 아니라, 실제 관찰 전에 화면이 어디서 막힐지 더 엄격하게 걸러내는 것입니다. 이 문서는 사용자용 화면이 아니며, 현재 My Flow v5/v6 후보를 페르소나 기반 과업으로 다시 본 내부 검증 리포트입니다.

실제 사용자 검증 아님 Proto-persona Task scenario Cognitive walkthrough Blocking 0 관찰 필요

결론

가능하다. 다만 AI 페르소나는 “검증”이 아니라 관찰 전 필터로 써야 한다

NN/g 기준으로 cognitive walkthrough는 신규 사용자의 학습 가능성을 전문가가 과업 단위로 훑는 방법이고, usability testing은 실제 사용자가 현실적인 과업을 수행하는 모습을 보는 방법입니다. 따라서 FlowMe에서는 아래처럼 나눠야 합니다.

1. 내부 선별

AI/전문가 페르소나로 화면을 열고 10초 안에 목적, 다음 행동, 체크/메모 위치가 보이는지 본다.

2. 클릭 리허설

Playwright로 저장 1개, 4개, 8개, 20개 이상 상태를 눌러보고 버튼 결과와 화면 밀도를 확인한다.

3. 실제 관찰

대표 사용자 3~5명에게 과업만 주고 말로 생각을 풀게 하며, 설명 없이 막히는 지점을 기록한다.

즉, “페르소나 테스트로 완성 판정”이 아니라 “페르소나 테스트로 화면을 줄이고, 실제 사용자 관찰로 후보 신호를 본다”가 맞습니다.

검증법

이번 테스트에 적용한 기준

방법 FlowMe에 적용한 질문 이번 판단에서의 역할
Proto-persona가설 페르소나 저장한 Flow 개수, 디지털 자신감, 날짜/진도 필요성이 다른 사용자가 같은 화면을 어떻게 볼까? 실제 리서치 전 가정 기반. 검증이라고 부르지 않는다.
Task scenario현실 과업 “오늘 해야 할 항목을 찾고 체크한다”, “다른 Flow를 찾는다”, “날짜별 항목을 확인한다”처럼 결과가 있는 과업을 준다. 화면 설명을 읽히지 않고 실제 행동으로 평가한다.
Cognitive walkthrough인지 단계 점검 올바른 목표를 세우는가, 올바른 컨트롤을 보는가, 버튼명과 결과를 연결하는가, 실행 후 피드백을 이해하는가? 새 기능이 필요한지, 또는 숨겨야 하는지 판단한다.
Think-aloud 관찰실제 사용자 다음 단계 사용자가 보이는 화면만 보고 무엇을 생각하는지 말하게 하고, 진행자는 설명하지 않는다. 후보 신호를 얻는 실제 관찰 단계. 내부 시뮬레이션과 분리한다.
FLOW UX gate제품 기준 오늘 Step, 체크, 메모, 원문/상세, 외부 앱 fallback이 캘린더/투두 앱 수준의 복잡도 안에 있는가? FlowMe 특화 기준. 내부 용어와 리뷰 문구가 사용자 화면에 나오면 실패로 본다.

테스트 범위

v5와 v6를 같은 과업으로 비교

화면 장점 위험 판정
v5 정리 화면 저장 1개/4개/8개에서 오늘 항목과 Flow 찾기가 단순하다. 캘린더/진도를 기본 노출하지 않아 Todo 앱에 가깝다. 날짜형 Flow가 많거나 학습 진도형 Flow를 쓰는 사용자는 “전체 일정/전체 진도”를 찾기 어렵다. 기본값
v6 조건부 보조 보기 v5를 유지하면서 날짜형에는 일정 보기, 진도형에는 전체 진도 보기를 조건부로 붙인다. 저장 4개부터 보조 버튼이 2개 보이면 다시 관리 앱처럼 느껴질 수 있다. 후보

페르소나 테스트

5개 페르소나별 walkthrough 결과

페르소나 시나리오 인지 Walkthrough 결과
P1. 저장 1개 사용자전세계약/이사 Flow 하나만 저장 오늘 해야 할 항목을 열고 체크, 짧은 메모를 남긴다. v5/v6 모두 상세 화면이 바로 열려 목표와 컨트롤 연결이 쉽다. `나중에 보기`나 큰 완료 CTA가 없는 점이 맞다. 통과
P2. 4개 저장 사용자생활 Flow 몇 개를 저장한 직장인 오늘 할 일을 먼저 보고, 다른 Flow를 찾는다. `오늘 할 일`과 `Flow 찾기`는 이해된다. v6의 `일정 보기`는 날짜형이 많을 때만 보여야 한다. 조건부 통과
P3. 진도형 사용자중1 수학/자격증 학습 지도 저장 현재 단원을 체크하고, 전체 진도에서 다음 단원을 확인한다. 세부 Flow 화면은 기존 Flow UI처럼 오늘 Step 중심이어야 한다. 전체 진도는 접힌 보기면 충분하다. v6 적합
P4. 날짜 밀도 높은 사용자검진/입학/이사 일정이 섞인 보호자 오늘 말고 이번 주와 특정 날짜의 항목을 확인한다. v5만 있으면 날짜 탐색이 약하다. v6의 `일정 보기`가 필요하지만 기본 첫 화면을 밀어내면 안 된다. v6 필요
P5. 20개 이상 저장 사용자여러 제작자 Flow를 많이 저장 특정 Flow를 검색해서 열고 오늘 항목으로 돌아온다. 초기 목록을 8개만 보여주고 검색으로 찾게 하는 방향이 맞다. 전체 목록을 기본 노출하면 실패한다. 통과

판정

이번 내부 테스트에서 남긴 제품 규칙

규칙 이유 상태
v5를 기본 My Flow 홈으로 둔다 저장 수가 적은 사용자는 관리가 아니라 실행을 원한다. 오늘 Step, 체크, 메모, 원문 링크가 먼저다. 유지
v6는 조건부 실험 후보로 둔다 날짜형/진도형 사용자는 일정과 전체 진도 보기가 필요하지만, 모든 사용자에게 기본 노출하면 과하다. 관찰 필요
페르소나 테스트 결과를 검증이라고 부르지 않는다 proto-persona는 팀의 가정이다. 실제 사용자 행동 데이터가 없으면 후보 신호까지만 말한다. 고정
관찰은 과업 중심으로 한다 “이 버튼이 좋아 보이나요?”가 아니라 “오늘 할 일을 찾아 체크해보세요”처럼 사용자가 실제 행동하게 해야 한다. 적용

다음 실제 관찰 스크립트

사용자에게 줄 말은 짧게 유지

공통 안내 “저장해 둔 Flow 화면입니다. 설명 없이 화면만 보고 오늘 해야 할 일을 찾아서 처리해보세요. 생각나는 말을 그대로 해주세요.”
기록할 것 첫 클릭, 멈춘 지점, 버튼명 오해, 체크/메모 위치, 날짜/진도 보기를 찾는지, 화면이 무겁다고 느끼는 순간.
중단 조건 30초 이상 다음 행동을 못 찾거나, 화면의 목적을 다르게 이해하거나, 원문/상세/메모 위치를 찾지 못하면 P1로 기록.
통과 조건 10초 안에 오늘 할 일을 찾고, 체크와 메모를 남긴 뒤, 필요할 때만 Flow 찾기/일정/진도를 열면 통과.
