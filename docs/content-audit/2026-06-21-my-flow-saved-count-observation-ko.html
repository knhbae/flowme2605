My Flow는 저장 개수가 늘어날 때 어디서 어려워지는가

목표는 기능을 더 붙이는 것이 아니라, 저장한 Flow가 1개, 4개, 8개 이상으로 늘어날 때 사용자가 자연스럽게 오늘 실행, Flow 찾기, 체크, 메모로 이동하는지 확인하는 것이다. 이 문서는 실제 사용자 검증이 아니라 다음 관찰을 위한 기준표이며, 실제 진행에는 관찰 키트를 함께 사용한다.

현재 사용자용 v4 저장 개수별 UX 판정 관찰 키트 실제 /my 정렬 확인 20개 이상 저장 상태 상태별 PoC 통합 시뮬레이션 완료 토글 관찰 서비스 UX 백로그

Apple/Galaxy/Toss식 결과

1개 저장관리 화면이 아니다. 저장됨, 오늘 열 항목, 체크, 메모, 원문 링크 정도면 충분하다.
4개 저장Today에서 시작하되, 사용자가 다른 Flow를 찾고 싶을 때만 목록을 연다. 상태 버튼은 상세 안에만 둔다.
8개 이상첫 화면에서 검색창과 필터를 바로 보여주면 도구가 무거워진다. 기본은 오늘 항목, 다음은 Flow 찾기다.

1개 저장 나중에 보기, 이 항목 완료가 관리 도구처럼 보였다. 버튼을 숨기고 저장됨 안내, 체크, 메모, 외부앱 fallback만 남겼다.
4개 저장 상태 전환 버튼이 많으면 실제 앱보다 무거운 관리 화면처럼 보인다. 상세 안에서는 큰 CTA 대신 작은 완료 토글만 남기고, 오늘 미룸/보류는 메모로 남기는 기준으로 낮췄다.
8개 이상 검색창과 상태 필터가 첫 화면에 바로 보여 관리툴처럼 느껴졌다. 첫 화면에서는 접고, Flow 찾기를 눌렀을 때만 검색/필터를 연다.

관찰 시나리오

사용자에게 시켜볼 일

시나리오 사용자에게 줄 상황 성공 신호 실패 신호
1개 저장 전세계약 Flow 하나를 저장했다. 오늘 해야 할 항목을 확인하고 메모를 남긴다. 사용자가 목록/필터를 찾지 않고 바로 체크 또는 메모를 한다. 사용자가 “완료 버튼은 어디 있지?”, “나중에 보기는 없나?”라고 묻는다.
4개 저장 전세, 이사, 홈트, 중1 수학 Flow가 저장되어 있다. 오늘 할 일을 하나 처리한다. Today 항목을 먼저 열고, 다른 Flow가 필요할 때만 전체 목록을 연다. 처음부터 전체 Flow 목록을 훑거나, 어떤 항목이 오늘 일인지 헷갈린다.
8개 이상 여러 생활/공부/루틴 Flow가 쌓여 있다. 특정 Flow를 다시 찾아 메모를 본다. Flow 찾기를 누르고 검색어 또는 상태 필터를 쓴다. 첫 화면의 오늘 항목과 Flow 찾기 사이의 차이를 이해하지 못한다.

진행 순서

다음 테스트 루프

  1. 현재 사용자용 v4와 실제 /my 모바일을 함께 본다.
    1개, 4개, 8개 상태를 차례로 누르고 첫 화면에서 사용자가 해석해야 하는 요소 수를 센다.
  2. 첫 클릭을 본다.
    오늘 항목을 누르는지, Flow 찾기를 누르는지, 20개 이상에서 전체 펼침이나 검색을 쓰는지 기록한다.
  3. 메모와 체크를 본다.
    사용자가 상세에서 체크/메모를 자연스럽게 남기는지, 작은 완료 토글도 과한지 본다.
  4. 재방문을 본다.
    다음 날 다시 들어왔을 때 오늘 항목과 밀린 항목을 구분하는지 확인한다.
  5. Blocking/High만 즉시 수정한다.
    버튼 이름과 결과가 다르거나, 첫 화면이 관리툴처럼 보이면 바로 줄인다.

현재 판정

완료가 아니라 관찰 준비

  • 정리됨 1개 저장 화면은 이제 상태관리 버튼을 기본 노출하지 않는다.
  • 정리됨 8개 이상 화면은 검색/필터를 첫 화면에서 접었다.
  • 관찰 필요 4개 저장 상태에서 작은 완료 토글이 필요한지, 체크박스와 메모만으로 충분한지 봐야 한다.
  • 관찰 필요 Flow Map과 단일 Flow가 섞였을 때 사용자가 목록 이름만으로 차이를 이해하는지는 아직 모른다.
