FlowMe 4탭 IA 시뮬레이션 리포트

대상: /ia-compare/b. 목적은 4탭 구조가 저장 후 실행과 보관/관리를 더 명확히 나누는지 확인하는 것입니다.

결론

B안은 계속 볼 가치가 있음

B안은 저장 직후 사용자를 캘린더로 보내는 흐름이 A안보다 직접적입니다. `내 Flow`가 실행 탭 묶음이 아니라 저장한 Flow 관리 공간으로 읽혀, 여러 Flow가 쌓일 때 역할 분리가 더 명확합니다.

다만 4탭이 최종 결정은 아닙니다. 실제 제품 반영 전에 홈/Flow 찾기 중복, 빈 캘린더 상태, 대량 저장 상태를 더 실데이터에 가깝게 봐야 합니다.

시뮬레이션

저니관찰판정
처음 진입 홈은 `따라 할 콘텐츠를 내 일정으로`라는 약속과 이사 추천 카드 1개를 보여줍니다. 통과 이전 문구보다 덜 설명적입니다.
Flow 찾기 3개 대표 콘텐츠를 고르고, 상세에서 저장 결과와 항목 수를 확인합니다. 통과 Flow Map/단일 Flow는 뱃지 수준으로만 남습니다.
저장 직후 `저장하고 캘린더 보기`를 누르면 캘린더 탭으로 이동하고 첫 실행 항목 detail이 열린 상태입니다. 통과 저장 후 다음 행동이 A안보다 명확합니다.
세부 항목 열기/닫기 항목을 다시 누르면 detail이 닫히고, 다시 누르면 같은 자리에서 열립니다. 통과 스크롤 하단에 detail이 열리는 문제를 피합니다.
내 Flow 내 Flow는 저장한 Flow의 전체 구조, 원문, 진행률, 실행 보기 버튼을 보여줍니다. 통과 실행은 캘린더, 관리는 내 Flow로 역할이 갈립니다.
대량 저장 가정 현재 PoC는 2개 저장까지 클릭 검증했습니다. 8개 이상은 기존 UX20 자료와 별도 비교가 필요합니다. 추가 필요 최종 결정 전 대량 상태가 필요합니다.

UX 판단

  • Execution Clarity: B안이 더 높습니다. 저장 후 캘린더가 실행 목적지가 됩니다.
  • Cognitive Load: 4탭이 늘어나지만, 내 Flow 내부 탭이 줄어 전체 구조는 오히려 덜 꼬입니다.
  • Portability: 캘린더에 들어가는 항목과 내 Flow에 남는 구조가 분리되어 export/ICS 사고와 더 잘 맞습니다.
  • Copy Specificity: 사용자 화면에서는 `Step`보다 `항목`을 쓰는 쪽이 낫습니다. 내부 문서와 제작자 화면에서는 Step 용어를 유지할 수 있습니다.

다음 개선

  • B안에 저장한 Flow 8개 이상 상태를 추가해 캘린더와 내 Flow가 버티는지 본다.
  • 캘린더 빈 상태에서 Flow 찾기로 자연스럽게 이동하는지 본다.
  • 현재 제품 `/my`에 바로 적용하지 말고, 한 번 더 실제 대표 콘텐츠 후보가 정리된 뒤 글로벌 탭 결정을 한다.
