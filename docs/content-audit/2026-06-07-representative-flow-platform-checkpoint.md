# 대표 Flow 콘텐츠 플랫폼 검토 체크포인트

작성일: 2026-06-07

이 문서는 지금까지 반복했던 `원문 → Flow 콘텐츠화 → UX/UI 확인` 작업을 적당한 수준에서 멈추기 위한 체크포인트다.

중요한 점은, 여기서 말하는 검토 완료는 **실제 사용자 검증 완료**가 아니다. 현재 단계는 외부 콘텐츠를 FlowMe가 제대로 분류하고, 실행 가능한 Flow UI로 바꿀 수 있는지 보는 **source-to-Flow QA** 단계다.

## 핵심 질문

FlowMe가 외부 콘텐츠를 가져왔을 때 다음을 할 수 있는가?

- 원문이 어떤 카테고리인지 분류한다.
- 캘린더, 루틴, 체크리스트, 시트, 메모 중 맞는 실행 형태를 고른다.
- 원문에서 사용자가 따라해야 할 행동만 뽑는다.
- 입력 복잡도를 캘린더/리마인더/시트 앱 수준으로 유지한다.
- 사용자가 저장 후 실제로 볼 실행 화면을 이해할 수 있게 보여준다.
- 원문 단서가 Flow UI에 살아 있는지 검토자가 판단할 수 있게 한다.

## 현재 판단

대표 케이스 기준으로는 **부분적으로 가능성이 보인다.**

현재 예시들은 다음 방향을 보여준다.

- 외부 원문을 카테고리와 실행 패턴으로 나눌 수 있다.
- 설명보다 먼저 실행 산출물, 즉 캘린더/체크/시트/메모를 보여줄 수 있다.
- public Flow 화면에서 단순 요약이 아니라 실제 실행판을 보여줄 수 있다.
- `/content-flows`에서 원문 단서와 Flow UI 대응을 비교할 수 있다.
- 입력은 대체로 시작일, 반복 주기, 선택 메모 정도로 줄일 수 있다.

다만 아직은 실제 사용자가 반복적으로 쓰겠다는 행동 데이터가 없으므로, **검증됨**이라고 말하면 안 된다.

## 현재 대표 케이스

| 케이스 | 카테고리 | 주요 실행 형태 | 현재 상태 | 멈춰도 되는 기준 |
|---|---|---|---|---|
| 세탁기 통세척 | 가전 관리 | 월간 루틴 캘린더 + 날짜 안 체크리스트 + 메모 | 검토 가능 | 준비물/구매 링크/원문 링크가 입력이 아니라 메모로 정리됨 |
| 정수기 필터 주기 | 가전 관리 | 필터별 관리 시트 | 검토 가능 | 날짜 없는 시트형 Flow가 일반 체크리스트처럼 보이지 않음 |
| 몬스테라 관리 | 식물 관리 | 루틴 캘린더 + 관찰/보류 선택 | 검토 가능 | 보류/관찰이 실패가 아니라 정상 결과로 보임 |
| 결혼 준비 | 생활 이벤트 | D-300 타임라인 캘린더 | 검토 가능 | 원문의 기간별 준비 흐름이 실행 화면에 남아 있음 |
| 중고차 점검 | 구매 결정 | 현장 체크리스트 + 구매/보류/거절 결정 | 검토 가능 | 사진/증빙 앱이 아니라 가벼운 현장 체크와 결정 흐름으로 보임 |

## 카테고리별 대표 케이스 매트릭스

플랫폼 가능성을 보려면 후보를 많이 늘리는 것보다, 각 카테고리마다 대표 케이스가 있어야 한다.

대표 케이스는 점수가 가장 높은 콘텐츠가 아니라, 그 카테고리의 원문 형태와 Flow 전환 방식, UX 리스크를 가장 잘 드러내는 콘텐츠다.

| 카테고리 | 대표 케이스 | 보조 케이스 | 대표 실행 형태 | 이 카테고리를 보는 이유 | 아직 남은 갭 |
|---|---|---|---|---|---|
| 가전 관리 | 세탁기 통세척 | 정수기 필터 주기 | 루틴 캘린더 또는 관리 시트 | 반복 관리, 준비물, 원문 메모, 체크리스트가 모두 필요함 | 어떤 가전은 캘린더, 어떤 가전은 시트가 맞는지 기준 필요 |
| 식물 관리 | 몬스테라 관리 | 스투키 과습 방지 | 루틴 캘린더 + 관찰/보류 | 오늘 실행보다 “오늘은 물을 줄지 말지” 판단이 중요함 | 보류가 정상 결과라는 표현을 더 명확히 해야 함 |
| 생활 이벤트 | 결혼 준비 | 이사 D-30 | D-day 타임라인 캘린더 | 긴 체크리스트가 날짜별 실행 흐름으로 바뀌는지 보기 좋음 | 모바일 캘린더에 정보가 과하게 들어가지 않아야 함 |
| 구매 결정 | 중고차 점검 | 신차 인수 체크 | 현장 체크리스트 + 최종 결정 | 사용자가 확인하고, 보류하고, 결정하는 흐름이 중요함 | 사진/증빙이 기본 입력처럼 보이지 않게 유지해야 함 |
| 공부/자격증 | 컴활 공부 또는 시험 트래커 | 한능검 3주 플랜 | 공부 캘린더 + 진도/오답 체크 | 챕터, 반복, 시험일, 완료 기준이 있는지 보기 좋음 | 고품질 public route 수준의 대표 화면이 아직 필요함 |
| 여행/행정 | 여권 준비 또는 해외여행 준비 | 일본 여행 준비물 | 체크리스트 또는 타임라인 + 메모 | 공식 정보, 출국일, 준비물, 오프라인 메모가 섞임 | 공식 정보와 블로그 팁을 분리해야 함 |
| 육아/식단 | 이유식 4주 식단 | 주말 놀이 로테이션 | 식단 캘린더 또는 반복 루틴 | 날짜별 식단/활동표가 Flow로 잘 바뀌는지 보기 좋음 | 건강/육아 민감 정보는 주의 문구와 출처 분리가 필요함 |
| 운동/챌린지 | 30일 플랭크 | ThankyouBUBU exact workout video | 챌린지 캘린더 또는 영상 반복 루틴 | Day별 표나 단일 영상이 반복 실행으로 바뀌는지 확인 가능 | 원문에 없는 운동 계획을 새로 만들면 안 됨 |
| 돈 관리 | 월말 가계부 | 비상금 통장 | 시트 또는 체크리스트 후보 | 수요는 높지만 조언처럼 보이기 쉬움 | 구체적이고 실행 가능한 비조언형 원문이 필요함 |

## 지금은 멈춰야 할 일

- 200개 후보를 계속 늘리지 않는다.
- 모든 후보 UI를 계속 다듬지 않는다.
- 원문 문단을 전부 입력 필드로 바꾸지 않는다.
- 증빙/사진/파일 첨부를 기본 기능처럼 넣지 않는다.
- 실제 사용자 행동 데이터 없이 “검증됨”이라고 말하지 않는다.

## 다음에 해야 할 일

대표 케이스를 놓고 작은 관찰 리뷰를 한다.

각 케이스마다 사용자가 다음을 할 수 있는지 본다.

1. 원문을 연다.
2. 해당 Flow 프리뷰 또는 public Flow 화면을 연다.
3. 이 Flow가 캘린더, 체크리스트, 시트, 메모 중 무엇으로 저장되는지 말해본다.
4. 첫 행동, 입력값, 완료 기준, 선택 메모가 무엇인지 찾아본다.
5. 실제로 저장해서 쓸 것 같은지 1~5점으로 평가한다.

## 관찰할 질문

- 사용자가 카테고리를 바로 이해하는가?
- 저장하면 어떤 실행 산출물이 생기는지 이해하는가?
- 입력이 너무 무겁다고 느끼는가?
- 원문 핵심 내용이 Flow UI에 남아 있다고 느끼는가?
- AI가 대충 만든 설명처럼 보이는 부분이 있는가?
- 캘린더/체크/시트/메모 중 목적지가 자연스러운가?

## 다음 단계로 넘어가는 기준

어떤 카테고리가 다음 제품 단계로 갈 수 있으려면, 사용자가 아래 질문에 일관되게 답할 수 있어야 한다.

- 이 Flow는 어떤 원문 콘텐츠에서 왔는가?
- 저장하면 어떤 실행 산출물이 생기는가?
- 첫 행동은 무엇인가?
- 완료 기준은 무엇인가?
- 어떤 정보가 필수 입력이고, 어떤 정보가 메모/출처 참고인가?

이 기준을 만족하기 전까지는 해당 카테고리를 “검증된 제품 기능”이 아니라 **source-to-Flow QA 후보**로 둔다.
