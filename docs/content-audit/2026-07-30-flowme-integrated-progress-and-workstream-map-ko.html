05 · 일 사이의 연결

잘 이어진 부분과 막힌 부분

FlowMe가 느리게 진행되는 것처럼 보이는 이유는 한 일이 적어서가 아니라, 조사·설계가 끝난 뒤 실제 제품에 들어가기까지 오래 걸리기 때문이다.

P25~P35의 화면 결정을 실제 제품에 차례로 넣었고, 기존 기능이 깨지지 않는지 검사하고 되돌릴 길도 남겼다.

문제 → 데이터 규칙

콘텐츠 모양, 수정한 사람, 반복 일정, 캘린더·목록에 보여주는 방법을 공통 규칙으로 정리했다.

막힌 경로

최근에 조사한 19건은 모두 고쳐야 하거나 보류해야 한다. 현재 제품에 넣은 콘텐츠는 0건이다.

배포 → 학습

직접 관찰한 사용자가 0명이고 이용 기록도 모으지 않아, 왜 다시 쓰거나 그만두는지 알 수 없다.

연구 → 결정

함께 수정하기, 버전 관리, 결과를 보여주는 방식, 콘텐츠 조사가 사용자 판단을 기다리며 쌓여 있다.

문서상 모순처럼 보이는 부분의 실제 의미

기본 작업본의 STATUS.md와 docs/specs/README.md에는 글로 Flow 만들기가 ‘설계 완료, 구현 전’으로 적혀 있다. 반면 D:\flowme2605\flow-text-authoring-ta에는 작동하는 기능과 최신 검사 결과가 있다.

서로 틀린 기록이 아니라 별도 작업본의 결과가 아직 기본 코드와 공개 제품에 들어가지 않은 상태다. 그래서 ‘현재 공개된 것’과 ‘별도 작업에서 끝난 것’을 나눠 표시했다.

별도 작업 결과가 기본 코드에 없음

글로 Flow 만들기의 코드, 검사 결과, 공개 미리보기가 서로 다른 시점이라 한 번에 확인하기 어렵다.

진행상황 파악 어려움

콘텐츠에 실행 정보가 부족함

최근 할 일 225개에 완료 기준, 날짜, 주의사항이 없어 화면에 넣어도 실제로 쓰기 어렵다.

실제 사용을 막음

사람이 직접 써본 결과가 없음

자동 검사는 기능이 작동하는지만 보여준다. 이해하기 쉬운지, 다시 쓰는지, 캘린더로 잘 옮겨지는지는 알 수 없다.

다음 판단 근거 없음

작업 문서를 읽고 정리하기 어려움

확인 시작 당시 수정한 파일 22개, 새 파일 22개가 정리되지 않았고 일부 긴 문서는 한글이 깨져 있었다.

확인하는 데 오래 걸림
08 · 추천 순서

다음은 이 순서가 가장 합리적이다

여러 일을 동시에 더 벌이는 것이 아니라, 이해하기 쉬운 사용 흐름 하나를 공개 제품과 실제 사용 결과까지 끝내는 것이 목표다.

1

현재 공개된 P35를 직접 보고 결정

그대로 사용, 한 가지만 수정, 다시 검토 중 하나를 고른다. 문제가 있다면 어느 화면에서 무엇이 어려운지 적는다.

내가 지금 결정
2

다음 개발을 하나만 선택

P35에 큰 문제가 없으면 검사까지 끝난 글로 Flow 만들기를 우선 검토한다. 문제가 있으면 P35의 한 가지만 고친다.

나 + AI
3

대표 사용 흐름 하나를 처음부터 끝까지 확인

예: 하루 메모 → 구조 확인 → 저장 → 오늘 할 일 → 캘린더 → 내 도구로 옮기기. 외부 테스트 전에 내가 먼저 이해되는지 확인한다.

제품 확인 단계
4

대표 콘텐츠 3건만 제대로 완성

원문 위치, 완료 기준, 필요한 날짜, 주의사항을 채워 같은 할 일이 목록·캘린더·표·메모에 자연스럽게 보이는지 확인한다.

콘텐츠 + 데이터
5

이해 가능한 상태가 된 뒤 관찰을 연다

기록할 항목을 미리 정하거나 수기 관찰표를 써서 첫 행동, 막힌 곳, 저장, 실행, 내보내기, 다시 방문했는지를 적는다.

사용자 조사 + 운영
6

근거가 생기면 큰 기능을 차례로 연다

다시 쓰는 사람이 생기면 계정 저장, 이용 기록, 제작자 버전 관리, 함께 수정하기, 경험 가치 연결을 차례로 만든다.

나중에 결정
지금 동시에 열지 않을 것

옵시디언 같은 전체 작업 공간, 마켓·커뮤니티, 캘린더 양방향 연결, 대규모 제작자 협업, 성장·감정 분석, 모바일 앱은 장기 방향으로 남긴다. 지금은 대표 사용 흐름 하나와 다시 쓰는 근거가 먼저다.
