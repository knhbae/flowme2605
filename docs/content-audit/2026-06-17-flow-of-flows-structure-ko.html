Corrected model

Flow Pack은 번들이 아니라 Flow of Flows다

사용자의 정정 기준에 맞춰 구조를 다시 잡았다. Flow Pack은 관련 Flow 몇 개를 옆으로 묶은 상품이 아니라, 상위 Flow가 하위 Flow들을 품고 사용자가 전체, 구간, 단일 Flow 단위로 저장하고 실행할 수 있는 계층형 실행 구조다.

정정: flow of flows parent Flow child Flow 사용자 화면 용어는 자연어 우선

이전 예시가 별로였던 이유

너무 납작했다

Flow Pack을 “관련 Flow 3~7개 묶음”처럼 처리했다. 사용자가 말한 구조는 상위 Flow 안에 하위 Flow가 있는 계층이다.

제작자성이 약했다

운동 제작자, 공부 유튜버, 육아 콘텐츠 제작자가 자기 콘텐츠 체계를 쌓는 방식이 아니라 범용 템플릿처럼 보였다.

단계 깊이가 없었다

중1 수학 아래 단원별 Flow, 백신 체크리스트 아래 각 백신 Flow처럼 하위 레벨이 더 생길 수 있다는 점을 반영하지 못했다.

정정된 방향: `Creator Channel -> Parent Flow -> Section/Sub Flow Group -> Child Flow -> Execution Items`.

시트

중요한 점은 “중1 전체 저장”이 실제로 하위 단원 Flow들의 일정/표/메모를 만든다는 것이다. 단순 폴더 저장이면 Flow of Flows가 아니다.

제작자 화면은 이렇게 작동해야 한다

제작자가 하는 일

  • 상위 Flow 제목을 만든다: 러닝 루틴 모음집, 중1 수학, 육아 백신 체크리스트.
  • 하위 Flow를 추가한다: 단원, 백신, 월령, 루틴 주차.
  • 각 하위 Flow의 목적지를 정한다: 캘린더, 표, 체크리스트, 메모.
  • 공통 입력값을 지정한다: 시작일, 요일, 아이 생년월일, 시험일.
  • 원본 링크와 제작자 경험, 주의사항을 하위 Flow마다 분리한다.

사용자에게 생기는 결과

  • 상위 Flow 전체를 저장하면 하위 Flow들이 함께 개인화된다.
  • 중간 구간만 저장할 수 있다: 중1만, 6개월 식단표만, 5K 루틴만.
  • 각 실행 item은 캘린더/표/메모에서 독립적으로 실행 가능하다.
  • 나중에 상위 Flow로 돌아와 다음 하위 Flow를 추가 저장할 수 있다.
  • 완료 상태는 하위 Flow별로 쌓이고, 상위 Flow는 진행 지도를 보여준다.

용어 정리

개념 내부 모델 사용자 화면 표현 예시

중간 묶음 FlowSection 단원, 월령, 주차, 난이도, 목표 소인수분해, 6개월 식단표, 4주 걷뛰기
하위 Flow ChildFlow 저장 가능한 실행 단위 문제풀이 루틴, 접종 예약 일정, 영상 따라하기
실행 항목 ExecutionItem 캘린더 일정, 체크 항목, 표 row, 메모 월요일 20분 달리기, 2개월 접종 예약, 오답 5번 다시 풀기
사용자 저장본 UserFlowTreeCopy 내가 저장한 전체/부분 흐름 중1 수학 중 소인수분해만 저장, 5K 루틴만 저장

사용자 화면에는 `Flow Pack`, `ParentFlow`, `ChildFlow` 같은 내부 용어를 그대로 노출하지 않는 편이 좋다. “중1 전체 저장”, “이 단원만 저장”, “6개월 식단표 저장”처럼 결과 중심으로 말한다.
