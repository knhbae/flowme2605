# Context Split 확산 원칙

**작성일:** 2026-06-17  
**목적:** 같은 Flow 콘텐츠가 제작자, 저장 전 사용자, 내 앱 실행 화면에서 어떻게 다르게 보여야 하는지 정리한다. 이 문서는 다음 HTML PoC들의 기준선이다.

## 1. 출발점

최근 중1 수학 화면에서 가장 잘 맞았던 점은 화면을 하나로 합치지 않은 것이다.

- 제작자는 원문 구조와 변환 규칙을 본다.
- 저장 전 사용자는 저장하면 내 앱에 무엇이 생기는지 본다.
- 내 앱 사용자는 오늘 할 항목, 체크, 메모, 원문 링크만 본다.

이 구조는 단일 Flow에도 필요하고, Flow of Flow에도 필요하다. 다만 Flow of Flow는 상위 지도와 반복 하위 실행 단위를 추가로 다룬다.

## 2. 세 화면의 역할

| 화면 | 사용자의 질문 | 보여줄 것 | 숨길 것 |
|---|---|---|---|
| 제작자 | 내 원문이 어떤 실행물로 바뀌는가? | 원문 구조, 변환 규칙, 발행 전 미리보기, 하위 실행 단위 패턴 | 오늘 체크 카드, 개인 메모 입력 |
| 저장 전 | 저장하면 내 앱에 무엇이 생기는가? | 생성될 캘린더/체크리스트/표/메모, 최소 입력, 전체 또는 일부 저장 결과 | 내부 점수, 긴 설명, 제작 규칙 |
| 내 앱 | 지금 무엇을 하면 되는가? | 오늘 또는 선택 항목, 체크, 짧은 메모, 원문 링크, 다음 항목 | 원문 분석, 변환 근거, 과한 전체 지도 |

## 3. 유형 구분

| 유형 | 정의 | 예시 | 이번 확산 처리 |
|---|---|---|---|
| 단일 Flow | 하나의 실행 artifact로 충분한 콘텐츠 | 전세계약 점검, 이사 D-30, 중고차 방문 체크 | 3화면 분리만 적용 |
| Flow map / collection | 여러 Flow가 한 주제에 모이지만 하위 실행 패턴이 서로 다름 | 이사 전체 지도, 자격증 전체 로드맵 일부 | 서비스 IA에서는 보일 수 있으나 Flow of Flow 대표로 두지 않음 |
| 반복 하위 실행 구조 | 같은 실행 패턴이 여러 대상에 반복 적용됨 | 중1 수학 단원별 공부, 자격증 과목별 진도/기출/오답 | 상위 지도 + 하위 실행 단위로 검증 |

## 4. 단일 Flow 기준

단일 Flow는 한 화면에서 실행이 끝나야 한다.

- 입력은 0-2개가 기본이다.
- 상세 설명은 메모, detail, URL로 내려간다.
- 저장 전 화면은 "어떤 artifact가 생기는지"를 먼저 보여준다.
- 내 앱 화면은 "오늘 또는 선택한 항목"을 먼저 보여준다.
- 캘린더, 탭, 전체 일정은 콘텐츠 구조가 요구할 때만 둔다.

## 5. 반복 하위 실행 구조 기준

상위 구조가 있다고 모두 Flow of Flow가 아니다. 아래 조건을 만족해야 한다.

- 원문 또는 제작자 콘텐츠에 상위 구조가 있다.
- 하위 실행 단위가 3개 이상 자연스럽다.
- 하위 실행 단위들이 같은 패턴을 반복한다.
- 전체 저장과 일부 저장이 모두 의미 있다.
- 사용자가 현재 위치와 다음 실행 항목을 볼 이유가 있다.
- 제작자가 나중에 단원, 과목, 월령, 주차 같은 하위 단위를 추가할 수 있다.

## 6. 확산 금지 조건

아래가 보이면 다시 줄인다.

- 모든 Flow에 같은 카드 수와 같은 탭 구조를 강제한다.
- 원문에 없는 체크 항목을 그럴듯하게 만든다.
- 사용자 화면에 제작 규칙, 점수, 내부 평가 문구가 보인다.
- 내 앱 화면이 전체 설명서처럼 보인다.
- 하위 실행 구조가 아닌 단순 묶음을 상위 실행 구조처럼 보이게 한다.
- 버튼 이름만 좋아 보이고 클릭 후 결과가 예측되지 않는다.
- 모바일 첫 화면에서 사용자의 다음 행동보다 설명이 먼저 보인다.

## 7. 이번 확산의 우선순위

1. 전세계약 수준으로 가벼운 내 앱 실행 화면을 유지한다.
2. 단일 Flow 5개에 화면 분리 원칙을 적용한다.
3. 중1 수학과 자격증 과목별 공부로 반복 하위 실행 구조를 검증한다.
4. 제작자 운영 화면과 내 Flow 관리 화면을 연결해 서비스처럼 보이는지 확인한다.
5. 시뮬레이션 결과는 실제 사용자 검증이 아니라 PoC 판단으로 기록한다.

## 8. 최종 판단 질문

- 이 콘텐츠는 하나의 Flow로 충분한가?
- 하위 실행 단위가 반복되어야 하는가?
- 저장 전 사용자는 결과물을 예측할 수 있는가?
- 내 앱 사용자는 다음 행동을 5초 안에 찾는가?
- 제작자는 자기 콘텐츠가 실행형 자산으로 바뀌는 과정을 이해하는가?
