판단 원칙

저장 개수별 UX 기준

1개 저장전체 관리 UI보다 현재 Flow를 바로 이어 보는 것이 우선이다. 모바일에서는 불필요한 체크/루틴 탭을 숨긴다.
4개 저장Today와 Flow 찾기 사이의 균형이 필요하다. 전체 목록은 sheet로 열고, 체크는 Flow를 먼저 선택한다.
8개 이상상태 카드보다 검색, 필터, 접힘이 우선이다. 첫 화면은 Today와 찾기 버튼만 남긴다.

발견한 문제와 수정

사용자 화면에서 과했던 부분

문제 사용자 영향 수정
1개 저장에서도 5개 탭 노출 사용자는 저장한 Flow 하나를 보러 왔는데 체크/루틴 같은 빈 탭까지 해석해야 한다. 모바일 단일 Flow에서는 실제 쓸 수 있는 탭만 남김. 이사 D-30은 오늘 / 캘린더 / Flow만 표시.
모바일 목록 행마다 완료 텍스트 버튼 반복 리스트가 검토용 체크 테이블처럼 보이고, 행 열기와 완료가 경쟁한다. compact row의 완료 액션은 접근 가능한 체크 컨트롤로 낮추고, 텍스트 반복은 제거.
늦게 저장한 D-day Flow가 과거 항목을 한 번에 많이 보여줌 첫 화면이 밀린 일 더미처럼 보일 수 있다. 모바일 Today의 밀린 항목은 4개부터 보여주고 나머지는 밀린 항목 더 보기로 접음.
이전 상태별 PoC의 1개 저장 화면에도 나중에 보기, 이 항목 완료가 남아 있음 1개만 저장한 사용자가 관리/상태 변경 화면으로 오해할 수 있다. 1개 저장 모드에서는 해당 버튼을 숨기고 저장됨, 체크, 메모, 외부앱 fallback만 남김.

시뮬레이션 결론

Apple/Galaxy/Toss 관점의 판정

  • 통과 단일 저장 상태는 이제 빈 탭을 덜 보여주며, 사용자는 현재 Flow와 캘린더로 바로 갈 수 있다.
  • 통과 4개 이상에서는 전체 목록을 첫 화면에 펼치지 않고 sheet로 연다.
  • 주의 Today에서 밀린 항목이 있는 상황은 여전히 무겁다. 다만 접힘과 체크 텍스트 제거로 검토용 화면 느낌은 줄었다.
  • 주의 실제 사용자 관찰 전에는 “이 구조가 검증됐다”고 말하면 안 된다.

남은 일

아직 목표 완료는 아님

현재는 My Flow의 모바일 P0 사용성을 정리한 상태다. 전체 목표를 완료하려면 실제 저장/실행 관찰에서 사용자가 Today, Flow, 체크, 루틴 중 어디로 가는지 헷갈리지 않는지 확인해야 한다. 다음으로는 데스크톱 최소 점검과 전체 gate 실행 후, Stage 0 관찰 태스크로 넘기는 것이 적절하다.
