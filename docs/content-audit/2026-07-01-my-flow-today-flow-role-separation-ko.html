My Flow v2.1 follow-up

Today / Flow 탭 역할 분리 설계

같은 row/detail 원칙은 유지하되, Today는 실행 inbox, Flow는 저장한 구조 보기로 분리한다. 이번 수정의 목적은 두 탭이 같은 Flow 카드 반복처럼 보이는 문제를 줄이는 것이다.

현재 문제

High

Today도 Flow 카드처럼 보임

Today 탭에서 Flow 제목, 진행률, progress bar가 먼저 보여서 사용자는 오늘 할 Step보다 Flow 구조 카드를 먼저 읽게 된다.

High

Flow 탭과 시각적 차이가 약함

Flow 탭도 Flow row와 다음 항목을 보여주기 때문에, Today와 Flow가 같은 화면의 다른 정렬처럼 보인다.

Figma v2.1 해석

원칙 유지 이번 분리
요약 → row → 필요한 detail 두 탭 모두 row를 누르면 바로 아래 detail이 열린다. row의 주인공은 탭마다 다르게 둔다.
Flow 맥락 유지 Step이 어느 Flow에 속하는지는 항상 보인다. Today에서는 Flow 맥락을 작은 보조 메타로 낮춘다.
정보량 축소 메모, 일정, 원문, 내보내기는 필요할 때만 연다. Today에는 progress bar를 기본 노출하지 않는다.

탭별 새 기준

Today

실행 inbox

  • Step 제목이 카드의 주 제목이다.
  • 날짜, 기준일, 섹션은 Step 아래에 둔다.
  • Flow 이름과 진행률은 작은 보조 줄로만 남긴다.
  • 체크리스트 detail은 Step을 열었을 때만 보인다.
Flow

저장 구조 보기

  • Flow 제목과 진행률이 row의 주 제목이다.
  • progress bar와 남은 항목 수를 유지한다.
  • 다음 Step은 Flow row 안의 미리보기로 둔다.
  • Step detail은 열린 Flow row 아래에서만 보인다.

반영 범위

영역 변경 보류
Today 첫 카드 Flow row형 카드에서 Step 실행 카드로 변경. 완료/수정/메모 편집의 근본 정보구조 재설계.
Today detail 기존 detail은 유지하되 Today 맥락에서는 Step 제목을 유지. Step scheduling metadata 확장.
Flow 탭 Flow row와 progress 중심 구조 유지. Flow Map 전체 drilldown 고도화.

완료 판단

  • Today 첫 화면에서 사용자가 Flow 구조보다 실행할 Step을 먼저 본다.
  • Flow 탭 첫 화면에서 사용자가 저장한 Flow의 진행 구조를 본다.
  • 두 탭의 detail은 같은 컴포넌트를 써도, 진입 카드의 목적이 다르게 보인다.
  • 모바일에서 카드 수와 설명량이 캘린더/투두 앱 수준을 넘지 않는다.
