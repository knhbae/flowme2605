FlowMe 분석방 / 외부 생태계 운영 인덱스
작성일 2026-06-09 · 상태: 다음 작업 진입점

외부 앱, 서비스, 플랫폼 분석을 이어가기 위한 한글 운영 인덱스

이 문서는 FlowMe와 연결될 수 있는 외부 생태계를 분석할 때 먼저 열어보는 안내판이다. 기능 후보를 바로 만들지 않고, 사용자 실행 순간, 자연스러운 산출물, Stage 0 행동, 만들지 않을 경계, 검증 대기 상태를 한 화면에서 확인하게 한다.

주요 진입점 로드맵 HTML, 연결 문서 HTML, Phase 5 압축표를 먼저 읽는다.
현재 기준 목적지 플랫폼은 통합 대상보다 내보내기 대상으로 먼저 본다.
현재 후보 기숙사, 초등 입학, 원격 도움, Naver Search Advisor가 핵심 큐다.
주의 표현 실사용 관찰 전에는 validated, integration ready, 대표 사례로 쓰지 않는다.
현재 실행 상태 distribution-channel-handoff는 no signal, 세션 0 / 3. 초대 문구 발송 후 tracker를 invited로 갱신하고, 답장 확인 뒤 agreed 슬롯만 관찰한다. 3 completed usable sessions 이후 rollup.

먼저 읽을 문서

이 순서대로 열면 현재 결정과 남은 리스크를 가장 적은 맥락으로 복원할 수 있다.

1

CEO brief

완료된 일, 현재 판단, 남은 외부 증거, 다음 행동을 한 화면에서 확인한다.

2

임원용 근거 appendix

어떤 질문을 어떤 근거문서와 스크린샷으로 확인할지 먼저 고정한다.

3

외부 생태계 분석 로드맵 시각화 HTML

분석방의 전체 진행 방식, 5단계 로드맵, 현재 결정 축을 먼저 확인한다.

4

연결 내부 문서 한국어 HTML 묶음

로드맵에서 연결된 내부 문서를 한글 요약 카드로 이어서 본다.

5

외부 생태계 HTML 커버리지 감사

어떤 내부 문서가 한국어 HTML로 읽히고, 어떤 Markdown 링크가 원문 추적용인지 확인한다.

6

Phase 5 최종 압축표

현재 후보의 A, A-, B+, 보류 판단과 다음 행동을 확인한다.

7

내보내기 목적지 선택 제품 규칙

캘린더, 시트, 메모, 내부 체크, Todoist CSV 같은 목적지를 고르는 기준이다.

8

통합 준비도 제품 규칙

OAuth, API 저장, 직접 append 같은 Stage 1 통합을 언제까지 미룰지 정한다.

현재 결정 축

새 후보를 볼 때마다 이 다섯 줄을 먼저 통과시킨다.

사용자 순간에서 시작

플랫폼 기능 목록이 아니라 사용자가 지금 실행하려는 일을 한 문장으로 쓴다.

자연스러운 산출물 우선

calendar, sheet, memo, internal_check, hybrid 중 실제로 옮겨갈 형태를 고른다.

Stage 0 제한

열기, 앵커 입력, 복사/내보내기, 체크, 피드백까지만 기본 행동으로 본다.

목적지는 통합보다 먼저

외부 플랫폼은 초기에는 계정 연결 대상이 아니라 내보내기 대상이다.

검증 표현 보류

사용자 행동 근거가 없으면 validated, integration ready, public promotion을 쓰지 않는다.

소스와 리스크 동행

출처 URL, 주의 문구, 완료 기준은 복사/내보내기에도 같이 이동해야 한다.

현재 후보 큐

지금 바로 구현할 목록이 아니라, 다음 판단을 어디서 해야 하는지 보여주는 큐다.

college-dorm-move-in-checklist A 리뷰 후보

현재 가장 강한 공개 승격 검토 후보.

최신 공식 공지 하나를 주 소스로 고정하고, 민감정보 제외와 최신 공지 우선 행동을 더 확인한다.

elementary-school-entry-d30 A- 공개 라우트

공개 라우트가 있으나 source-review 상태로만 말해야 한다.

보호자 관찰 세션 전에는 대표 사례, 검증된 사례, 일반화된 UX로 표현하지 않는다.

remote-help-session-precheck A- 리뷰 후보

원격지원 전 신뢰, 범위, 권한 사다리를 확인하는 후보.

공개 라우트, 원격지원 통합, 접속값 저장은 만들지 않는다.

naver-search-advisor-site-readiness A- 리뷰 후보

한국 우선 사이트 준비 체크 후보.

검증값, DNS 값, OAuth, API 키, 색인 성과는 저장하거나 보장하지 않는다.

site-search-console-setup-precheck B+ 문서 우산

Google, Naver, Bing 계열을 묶는 디지털 설정 문서 축.

한국 우선 시나리오가 확정될 때까지 `/content-flows` 후보로 승격하지 않는다.

이 방에서 만들지 않을 것

경쟁서비스 분석이 기능 과잉으로 번지지 않게 막는 현재 금지선이다.

플랫폼 클론

Notion, Todoist, Calendar, Sheet 자체를 대체하는 편집기나 워크스페이스를 만들지 않는다.

계정 통합

OAuth, 계정 동기화, 토큰 저장, webhook 자동화는 Stage 0 범위 밖이다.

성과 보장

DNS 자동 변경, SEO 점수화, 순위 추적, 검색 노출 보장은 하지 않는다.

접속값 저장

원격지원 접속 코드, 비밀번호, 세션 링크, 화면 캡처, 채팅 로그를 저장하지 않는다.

민감정보 저장

학교, 기숙사, 건강, 결제, 학생 식별 정보는 FlowMe 밖에 둔다.

자동 판정

법률, 보안, 건강, 학교별 자격 같은 결론은 체크 보조를 넘어서 판정하지 않는다.

다음 작업 순서

다음 세션에서 하나만 고르고, 구현보다 먼저 후보 압축 문장부터 만든다.

1. 초등 입학 관찰

`elementary-school-entry-d30`의 보호자 관찰 스크립트 또는 source-review 문구 노출을 확인한다.

2. 기숙사 공개 승격 전 점검

현재 공식 공지 하나를 주 소스로 고정할 수 있을 때만 다음 단계로 보낸다.

3. 새 축 선택

creator material, household table/sheet, distribution/channel 중 반복되지 않는 축을 고른다.

4. Phase 5 전 압축

목적지 산출물, 금지 저장값, public route 필요 여부, 통합 필요 여부를 먼저 적는다.

현재 선택된 다음 축

다음 분석 축은 distribution-channel-handoff로 둔다. Flow 산출물이 만들어진 뒤 가족방, 학교/기숙사 그룹, 팀 채널, 카페 글, 폼/시트 같은 외부 채널로 어떻게 전달되는지 확인하는 축이다.

한국어 HTML 허브

배포 채널 핸드오프 HTML 허브에서 게이트, 공유 패킷, 관찰 스크립트, 로그, evidence board, 파일럿 실행 팩을 한 번에 읽는다.

왜 이 축인가

creator material과 household table/sheet는 이미 선행 문서와 소스선택 규칙에 예시가 많다.

무엇을 볼 것인가

KakaoTalk, Naver Cafe, Google Forms/Sheets, Notion/Markdown handoff, 팀 메신저 유사 패턴을 공식 자료로 확인한다.

무엇을 만들지 않는가

계정 연결, 자동 게시, 댓글 수집, 연락처 저장, 채널 분석, 커뮤니티 도구를 만들지 않는다.

다음 문서

다음 분석 축 선택 HTML에서 세부 매트릭스를 본다.

검증 기준

완료 표현은 검증 명령과 화면 확인 뒤에만 쓴다.

문서만 변경

`npm run docs:check`를 통과해야 한다.

HTML 변경

데스크톱과 모바일 스크린샷으로 겹침과 링크 진입을 확인한다.

UI 변경

관련 단위 테스트, 빌드, 표적 Playwright 검증을 별도로 돌린다.

표현 제한

결과는 source-to-Flow QA 또는 roadmap artifact로만 말한다.

목차

메인 로드맵 연결 문서 묶음 먼저 읽을 문서 현재 결정 축 현재 후보 큐 만들지 않을 것 다음 작업 선택된 다음 축 검증 기준 Markdown 원문

이 인덱스는 시장조사 보고서가 아니라 다음 분석 세션의 출발점이다. 후보를 고른 뒤에도 사용자 행동 검증 전에는 검증 완료 표현을 쓰지 않는다.
