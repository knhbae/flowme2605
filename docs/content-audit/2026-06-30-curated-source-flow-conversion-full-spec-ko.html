공통 변환 게이트

1. 목적지 먼저

calendar, sheet, memo, internal check, hybrid 중 어디로 옮겨야 사용자가 바로 실행하는지 먼저 고릅니다. 화면 구조는 그 다음입니다.

2. 원문 spine 보존

원문에 날짜, 회차, 표, 단계, 영상, 플레이리스트가 있으면 그것만 Step 후보로 씁니다. 부족한 단계는 설명으로 채우지 않습니다.

3. 위험 분리

공식 정보, 창작자 경험, 주의/중단 조건을 분리합니다. 육아, 건강, 금융, 차량, 운동 영역은 보장 문구를 쓰지 않습니다.

일괄 검토에서 결정할 질문

  1. 첫 구현을 이사로 확정할지, 오픽/신차처럼 source row가 강한 후보와 비교할지 결정합니다.
  2. 민감 카테고리에서 공식 링크와 creator source를 화면상 별도 블록으로 고정할지 결정합니다.
  3. Park 판정 대상은 전체 사이트/채널 페이지를 만들지, 아니면 카테고리/플레이리스트 하나를 바로 고를지 결정합니다.
  4. 결혼처럼 다중 원문이 있는 경우 “버전 선택 Map”을 우선 만들고 각 원문 Flow를 별도 관리할지 결정합니다.
  5. 구현 승인 전, 이 문서의 각 후보가 Draft only인지 Public MVP 후보인지 다시 rubric으로 잘라냅니다.
