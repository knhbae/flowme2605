01 / 전략 결론

모든 좋은 URL을 Flow로 만들지 않는다

이번 목표는 새 실행 객체를 발명하는 일이 아니다. 실제 원문을 발굴한 뒤 지금 안전한 편입 단계와 보강 후 목표 단계를 분리해, 콘텐츠팀이 같은 기준으로 제작 큐를 만들게 하는 일이다.

Flow는 원문 근거가 있는 최소 행동만 실행시키고, 나머지는 Link/Bucket·detail·memo 또는 Hold로 남긴다.

16이번 실제 URL 추가 검토
8다음 제작 후보

02 / 목표 보정

콘텐츠 발굴 레이어만 추가한다

재사용

Canonical hierarchy, Taxonomy v1.1, Output Quality v2, P25/P26 날짜·export 계약.

새로 결정

Link/Bucket·Quick·Full·Hold 편입 판정과 source scout 원장.

제외

앱 코드, seed, 편집기, Calendar API, 새 runtime type.

중복 방지: Calendar·checklist·todo·sheet·memo는 기존처럼 같은 Item의 projection이다. 이번 문서는 새로운 Flow 종류를 만들지 않는다.

03 / 증거 범위

확인한 것과 아직 모르는 것을 분리했다

원문

현재 P0 갤러리 24개 URL과 Item, 기존 후보 36개, 신규 URL 16개.

수요

조회·스크랩·모집·학습인원처럼 화면에 보인 수치만 visible로 기록.

불확실성

보이지 않는 조회·다운로드는 unknown. PDF 직접 추출 실패도 그대로 기록.

검증 경계

실제 사용자 관찰이나 제작자 허가가 완료됐다는 뜻은 아니다.

04 / 최소 계약

한 사용자의 한 목표, 한 자연스러운 결과물

SourceRow→Item→Step→Flow→Bundle / Map
Item에 필수

행동 제목 · 실행 방법/detail · 완료/기록 기준 · sourceRowIds · 순서.

Item이 아닌 것

원문 설명 · 참고 · 주의 · 팁 · 비행동 링크 · 조건부 후속 안내 · 개인 메모.

05 / 편입 모델

구조 tier와 공개 gate는 서로 다른 축이다

Link/Bucket

정확한 URL과 저장 이유. 실행행을 만들 근거가 없거나 링크 보존이 목적.

Quick Flow

한 세션·한 결정에서 끝나는 최소 행동. 항목 수는 보조 신호다.

Full Flow

날짜·순서·분기·역할·진도 중 하나 이상이 성공에 중요.

Hold/Reject

행·최신성·권리·안전·적용 범위가 부족해 실행시키면 안 됨.

같은 후보에도 구조상 Quick과 공개 전 권리 검토가 동시에 존재할 수 있다. 이를 하나의 readiness 점수로 뭉개지 않는다.

08 / 결과물 변환

한 Item을 다섯 결과물로 투영한다

Calendar

사용자가 확정한 날짜만. 날짜 없음·예시는 제외.

Checklist / Todo

행동 제목과 완료 상태. detail은 접어서 표시.

Sheet

Item 행, 상태·날짜·담당·메모·source URL 열.

Memo

목표·설명·주의·출처·개인 기록. 실행 상태와 분리.

09 / 현재 UX·UI 적합

틀은 맞지만 콘텐츠 밀도 규칙이 더 엄격해야 한다

/flows

카드에서 “저장하면 무엇이 생기는지”와 Item 수보다 첫 결과를 먼저 보여준다.

/my

Quick은 한 화면, Full은 현재 Step과 다음 Step 우선. 전체 Item을 평면 나열하지 않는다.

Calendar·export

확정 일정만 보낸다. source link와 detail은 메모에 보존하고 예시 날짜를 저장하지 않는다.

P26 충돌 없음: schedule now · keep undated · preview only 세 상태와 같은 방향이다. 필요한 것은 새 화면보다 콘텐츠 admission과 압축이다.
