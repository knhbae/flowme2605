이번 산출물은 실사용 검증이 아니라 현재 화면과 클릭 동작 기준의 제품 흐름 검토입니다. 사용자 화면에는 내부 평가를 넣지 않고, 검토 내용은 이 문서에만 남깁니다.

피드백/코멘트

더 매끈하게 만들 때의 기준

제품 화면은 설명하지 않는다사용자 화면에는 “왜 이렇게 만들었는지”를 쓰지 않고, 저장·체크·메모 같은 행동만 남긴다.
제작자와 사용자의 말을 분리한다제작자 화면은 원문 행과 매핑을 다뤄도 되지만, 공개 상세와 내 Flow는 학습자가 이해하는 말만 쓴다.
내 Flow는 가장 작아야 한다저장 후에는 전체 구조보다 오늘 이어서 볼 Step, 완료 체크, 오답 메모가 먼저 보여야 한다.
평가 문구는 리포트로 보낸다제품 화면에는 검토, 기준, 내보내기 규칙 같은 내부 표현을 두지 않고 리포트에만 남긴다.

시뮬레이션

제작자와 사용자의 흐름

  1. 제작자가 EBS 강좌 URL과 강의 목록을 가져옵니다.
  2. 원문 행을 단원 Flow와 강의 Step으로 묶고, 강의 열기·교재 쪽수·오답 메모를 Item으로 둡니다.
  3. 제작자는 공개 상세를 발행합니다. 공개 화면에는 저장 판단에 필요한 요약, 원문 링크, Flow 목록만 보입니다.
  4. 사용자는 전체 지도 또는 선택 Flow를 내 Flow로 저장합니다.
  5. 내 Flow에서는 현재 Step, Item 체크, 오답 메모, 시트/투두 미리보기만 남습니다.

수정 판단

과해서 줄인 것과 남긴 것

줄임진행 페이스 입력, 날짜 강제 입력, 학습 진단, 상태 버튼을 넣지 않았습니다.
남김제작자 구조 확인, 공개 저장 판단, 내 Flow 실행 체크는 제품 흐름 확인에 필요해 남겼습니다.
시트/투두 미리보기Step은 시트/투두 행이 되고, Item은 Step 메모 텍스트로 접힙니다.
남은 리스크실제 제작자가 원문 행을 얼마나 잘 고치는지와 사용자가 전체/일부 저장을 어떻게 고르는지는 행동 데이터가 필요합니다.

검증 결과

로컬 브라우저 검증

  • 모바일 390px, 데스크톱 1280px에서 가로 overflow 없음.
  • 제작자 발행, 공개 상세 저장, 내 Flow Step 선택, Item 체크, 메모 입력, Step 완료, 다음 Step 이동 동작 확인.
  • 메모는 시트/투두 미리보기에 반영되고, 다른 Step으로 이동했다가 돌아와도 유지됨.
  • 사용자 화면에 내부 평가 문구를 노출하지 않음.
