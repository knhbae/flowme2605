2026-07-05 · FLOW UX review · Claude 03 zip

채택 가능하지만, 구현 전 보정이 필요하다

03.zip은 실제 컨텐츠 기반 URL-first 스토리보드라는 점에서 이전보다 좋아졌지만, fake usage 신호, repo path 오해, needs_review export, canonical URL 불일치, AI P0 범위가 걸린다.

Verdict

좋은 방향

실제 seed 컨텐츠를 넣고 URL hit, export, My Flow, Calendar, memo-to-Flow를 장면으로 연결했다.

그대로 구현 금지

신뢰 신호와 source gate 오류가 있어 바로 구현 백로그로 넘기면 안 된다.

다음 행동

Claude에게 보정 요청을 보내거나, 우리가 P0 구현 slice 요청서로 다시 압축한다.

Findings

High fake usage처럼 보이는 카운트

Scene A2의 `추천 124명 저장`은 현재 사용량 데이터가 없으므로 제거해야 한다. `같은 URL로 변환된 Flow 있음`, `원문 검토일`, `최근 수정일` 같은 검증 가능한 신호로 바꾼다.

High repo path 오해

와이어플로우가 실제 앱을 repo root라고 적었지만, GitHub 기준 active app은 `flow-mvp/`다. 모든 path와 branch 표기를 고쳐야 한다.

High needs_review 컨텐츠 export 허용

`vehicle-inspection-prep`는 `needs_review`인데 비로그인 `.ics` 다운로드와 저장을 자연스럽게 허용한다. 검토 전에는 export/save를 제한하거나 명시 확인을 요구해야 한다.

Medium canonical URL fidelity

이사 hit 장면의 `ajd-blog.tistory.com` 예시는 실제 AJD source URL과 다르다. URL-first UX에서는 canonical URL 자체가 핵심 데이터다.

Medium AI fallback이 P0로 들어감

P0는 lookup/reuse/export를 먼저 닫아야 한다. AI generation은 P1 fallback 또는 disabled/stub으로 낮춘다.

Recommended Fixes

  • `추천 124명 저장` 등 숫자 신뢰 신호 제거.
  • 모든 GitHub 기준 path를 `flow-mvp/`로 통일.
  • needs_review 컨텐츠는 preview만 허용하고 export/save는 gate 처리.
  • 이사 예시는 실제 AJD canonical URL 기준으로 수정.
  • AI generation은 P0 core에서 제외.
  • P0 slice를 `URL input -> lookup HIT -> reuse/options -> export -> My Flow/Calendar`로 압축.

검토 대상 zip 자체는 수정하지 않았다. 이 보드는 다음 Claude 재요청 또는 내부 P0 구현 요청서의 기준이다.
