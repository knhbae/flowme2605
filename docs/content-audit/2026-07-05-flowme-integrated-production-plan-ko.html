P0 Production Plan

P0-01. /flows URL lookup strip

P0

기존 catalog 상단에 source URL 입력, canonicalization, duplicate hit, needs_review, miss 상태를 붙인다.

  • 주요 파일: components/flow/AppClient.tsx, lib/flow/url-first-lookup.ts
  • 완료 조건: URL hit가 기존 Flow detail로 이어지고, miss는 AI 실행이 아니라 대기/요청 상태로 보인다.
  • 검증: unit test, mobile /flows Playwright, internal label/copy scan.

P0-02. Result sheet states

P0

Claude entry 03의 상태 흐름을 production copy로 재해석해 조회 결과를 한 장의 decision sheet로 보여준다.

  • 상태: hit, needs_review, miss, unsupported, memo_draft.
  • 완료 조건: 각 상태가 하나의 primary action과 하나의 next option만 가진다.
  • 검증: 390px 첫 화면에서 CTA와 결과 설명이 겹치지 않는다.

P0-03. Export pack v1 QA

P0

사용자가 “내 캘린더/메모/시트로 옮겼다”고 느낄 수 있는 export 결과를 route detail과 My Flow detail에 맞춘다.

  • 범위: ICS, Markdown checklist, plain copy, table/CSV row preview.
  • 완료 조건: Step detail의 edited values가 export 결과에 반영된다.
  • 검증: export unit test, My Flow Step detail browser check.

P0-04. Source/trust layer

P0

원문, 변환 시점, review 필요 여부, 공식/creator/user edit 경계를 사용자에게 과하게 노출하지 않고 분리한다.

  • 완료 조건: fake count 없이도 “왜 이 결과를 믿을 수 있는지” 최소 단서가 보인다.
  • 주의: user-facing copy에서 source-backed, candidate, audit 같은 내부어는 금지한다.
  • 검증: P7 guardrail scan과 docs/SERVICE_STRUCTURE 원칙 대조.

P0-05. Canary content set

P0

URL lookup을 보여줄 수 있는 실제 source-backed 후보 5-8개를 정비한다.

  • 우선 후보: 이사 체크리스트, 시험/공부법, 해외여행 체크리스트, 웨딩 타임라인, 주간 식단/도시락, 중고차 구매.
  • 완료 조건: 각 후보가 natural artifact, source link, export destination, first action을 가진다.
  • 검증: content conversion review, source/risk gate, route smoke.

P0-06. Evidence capture

P0

실제 검증 없이 “검증됨”이라고 말하지 않기 위해 save/export/check/return 관찰 계획을 붙인다.

  • 완료 조건: 첫 사용자 세션에서 기록할 질문, 관찰 포인트, 실패 기준이 문서화된다.
  • 검증: observed-user evidence와 browser QA를 명확히 분리한다.

다음 목표 제안

다음 개발 목표: “/flows URL 조회 production slice”를 만든다. 내부 lab의 상태 모델을 재사용하고, Claude entry 03의 화면 케이스를 참고하되, 최종 UI는 현재 /flows catalog와 P7 guardrail에 맞춘다.

  1. 스펙 생성: docs/specs/2026-07-05-url-lookup-production-slice/에 spec/plan/tasks/qa를 만든다.
  2. UI 반영: /flows 상단에 URL lookup strip과 result sheet를 붙인다.
  3. Export 연결: hit 결과에서 ICS/Markdown/plain copy/table preview가 보이도록 export pack v1 범위를 확정한다.
  4. Content 연결: canary 후보 중 3개 이상이 lookup hit demo로 동작하도록 source URL mapping을 정리한다.
  5. 검증: npm.cmd run docs:check, unit test, build, 390px /flows browser QA, user-route copy scan을 수행한다.

이 목표는 Home redesign, full editor, direct OAuth, creator marketplace, AI-first generation을 포함하지 않는다. 이 네 가지는 P0 결과가 실제로 반복 사용되는지 본 뒤에 열어야 한다.

충돌 정리

충돌 정리
Claude 디자인을 그대로 앱에 적용할까? 아니다. Claude 산출물은 상태/흐름 참고자료로 쓰고, 앱 반영은 P7 baseline과 현재 route 책임에 맞게 재설계한다.
Home에 URL 입력을 바로 넣을까? 지금은 /flows가 맞다. Home은 약속과 대표 시작점, /flows는 실제 찾기/가져오기 작업면이다.
Memo-to-Flow를 먼저 만들까? 중요하지만 P2다. URL lookup/export 루프가 제품의 첫 가치와 비용 구조를 더 잘 증명한다.
AI를 전면에 세울까? 아니다. 먼저 찾고 재사용한다. AI는 miss/revise fallback으로 둬야 비용과 품질 위험이 낮다.
캘린더/투두/노션을 직접 연동할까? 아직 아니다. portable export를 먼저 증명하고, 반복 friction이 생기면 direct integration을 검토한다.
