# P24-00A 백로그 권고

## 바로 수정할 것

1. **[B1] 빌드 복구.** `package.json`/`package-lock.json`을 커밋하기 전에 `npm run build`가 통과하는 상태로 되돌린다. 가장 안전한 경로는 `c14c262`가 커밋한 의존성 버전(Next 15.3.8 등)으로 되돌리는 것이다. Next 15.5.20으로의 업그레이드가 필요하면 P25-02(controlled dependency upgrade)로 범위를 분리하고, 그 안에서 `PageNotFoundError` 원인을 먼저 해결한 뒤 전체 회귀(`npm run build`, `npm run test:e2e` 포함)를 통과시킨다.
2. **[B4] My Flow 요약 위젯의 날짜 계산 로직을 override-aware하게 수정.** 전체 목록/Calendar/ICS가 이미 정확한 effective-date 계산 로직을 갖고 있으므로, 위젯도 같은 소스를 참조하도록 고치는 것이 안전해 보인다(새 계산 로직을 만들지 말고 기존 정확한 경로를 재사용). Persona 1과 2에서 동일 패턴으로 재현되므로 공유 컴포넌트/훅 문제일 가능성이 높다.
3. **[B5] "이 Flow 다시 쓰기"의 `keep_fixed_dates` 옵션이 실제로 override를 이관하도록 수정.** 현재는 라디오 선택과 무관하게 항상 anchor 재계산값으로 리셋된다. 과거 실행 기록에는 override가 정확히 스냅샷되므로, 새 실행 생성 시 그 스냅샷을 참조해 이관하는 경로가 빠진 것으로 보인다.

## 관찰 후 수정할 것 (P24-00B 실제 사용자 세션에서 재확인 후 판단)

4. **[B2] 반복 회차가 1개만 렌더링되는 문제.** 두 개의 독립된 반복 경로(요일 기반, daily/weekly/monthly)에서 재현되므로 High confidence이지만, 실제 사용자가 Session 2에서 이 문제를 어떻게 마주치는지(즉시 이상하다고 느끼는지, 완료 후 다음 회차가 생기길 기대하며 기다리는지) 관찰한 뒤 우선순위를 정한다. 다만 **기능 자체가 실행되지 않는 수준의 결함**이므로 P24-00B 착수 전에 최소 원인 조사(어느 코드 경로가 회차를 1개로 제한하는지)는 먼저 하는 것을 권고한다.
5. **[B3] 메모 분할 시 `type: "todo"` 항목이 숨겨지는 문제.** My Flow 렌더링이 `type: "calendar"`만 그리고 `type: "todo"`를 거르는 필터가 있는지 코드 확인이 필요하다. 사용자가 메모에 여러 할 일을 적는 것이 실제로 흔한 패턴인지 P24-00B에서 관찰한 뒤, 흔하다면 B1/B4/B5와 함께 즉시수정으로 승격한다.
6. **[H1] `/flows` 하드 네비게이션 무한 로딩.** B1을 먼저 고쳐 production 빌드로 재현 여부를 확인한 뒤 판단한다. 재현되면 즉시수정으로 승격해야 한다(핵심 진입점이므로).
7. **[H2] 저장 직후 `/my` 빈 상태.** 재현율이 낮아 patterns 확정에 추가 관찰이 필요하다.

## 보류할 것

8. **[M1] 범용 편집 필드(결정 상태 등)의 콘텐츠별 맞춤화** — UI 전면 개편 없이 손댈 수 있는 범위인지 먼저 검토. P24-03(발견성·밀도 UX 개선)에서 관찰된 실패로 정당화되면 착수.
9. **[M2] source-backed 구조 편집 잠금에 대한 안내 문구 추가** — 작은 카피 변경이지만 P24-00B 관찰에서 실제로 혼란을 일으키는지 먼저 확인.
10. **[M3] ICS 버튼 라벨/배치 개선** — 낮은 우선순위, 다른 카피 작업과 묶어서 처리.
11. **[L1] 자동화 클릭 실패 패턴** — 제품 버그로 취급하지 않는다. 실제 사용자 관찰에서 유사 보고가 나오면 재검토.

## P24-01A(source v2 merge contract) 착수 판단

**아직 착수하지 않는 것을 권고한다.**

이유:
- B1(빌드 실패)이 해결되지 않은 상태에서는 새 기능 구현의 검증 자체가 불가능하다(빌드도, e2e도 돌릴 수 없다).
- B2(반복 회차 미표시)와 B4/B5(날짜 override 불일치)는 **P23이 "닫혔다"고 선언한 핵심 실행 계약**(반복 실행 추적, override 유지)이 실제로는 부분적으로 깨져 있음을 보여준다. source v2 merge 정책은 이 위에 추가로 쌓이는 복잡도이므로, 기존 실행 계약이 실제로 작동하는지 먼저 확정하지 않은 채 병합 정책을 얹으면 어느 버그가 새 것이고 어느 것이 기존 것인지 구분하기 어려워진다.
- B3(todo 항목 은닉)은 개인 draft의 항목 타입 처리 자체에 구멍이 있다는 뜻이므로, source v2 merge가 다루게 될 "added/changed Item" 처리에도 같은 구멍이 이어질 위험이 크다.

**권장 순서**: B1 → B4/B5 → B2 원인 조사 → (필요시 B3) → 이 다섯 항목에 대한 targeted e2e 회귀 추가 → 그 다음 P24-01A 스펙 착수.
