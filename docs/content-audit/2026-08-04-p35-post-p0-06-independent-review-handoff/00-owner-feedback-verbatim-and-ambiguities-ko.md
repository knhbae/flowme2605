## 1. 원문

> 1. F-05: 내 flow 어디선가 에서 가져가야지. (내보내기를 말이지)
> 2. 전체: 도움말같은 성격은 모두 물음표를 누르면 팝업 뜨게하자. 너무 지저분함. 주의사항도 느낌표를 누르면 팝업이 뜨게하자.
> 3. 내 flow 탭 자체가 어떻게 구성되어야하는 전체적인 재 고민이 필요한 것 같음. 다른 앱 study 필요. 정보의 흐름 같은 것도 고민해서 뭐가 앞에 나오고 뭐가 뒤로 가고 그런거 고민 필요.
> 4. Item 상세,메모, 완료
>    - 실행할 일 바탕 색상의 통일감 필요(다른 영역과.. 말이지). 얘만 파란색 바탕임. 이상함
>    - "실행할 일" 이것도 삭제해도 되지 않겠니?
>    - "할일 수정"은 "수정"으로
> 5. Flow Map 잔여 구조 --> 3칸 요약하는 거 삭제해도 되지 않아? 꼭 필요해? 그럼 물음표를 누르면 뜨게 하면되지 않아?
> 6. flow 찾기 -> "시작일" 설정하는 부분에서 시작일 설정했는데 왜 또 바로 아래 시작일 선택한게 표시될까? 필요 없지 않음?
> 7. flow 찾기 탭에서 플로우 상세보기 하면 매번 "... 시작" 버튼이 다르니까 이상
>    - 왜 flow 미리보기가 한 종류씩만 나옴? 여러 종류가 나올 수 있도록 수정 부탁, 여기에서 캘린더/메모/체크리스트/투두/시트 가능하면 다 나와야지.
>    - 하단엔 "편집"/"완료" 버튼만 있음되지 않겠음?
>    - 완료 후에는 내 flow 탭으로 이동하고 원하면 캘린더/메모 ... / 보내기를 할 수 있는 버튼이 크게 하단에 있고(그 옆에 수정 버튼 있음 되겠음), 그거 누루면 팝업 떠서 내 플로우 찾기에서와 같은 UI로 여러 포멧 미리보기 가능하고..
> 8. 내 flow 탭 -> flow 관리 -> 편집 -> 하단에 편집 가능한 페이지가 나옴
>    - 이 UI와 flow 찾기의 편집 UI가 동일해야함.
>    - 그리고 하단으로 나오니까 헷갈림 팝업이든 다른 화면이든 해야함.
>    - 근데 아까 단에 편집/완료 버튼 있으면 중복인가? 만들면서 판단해보셈
> 9. 그냥 flow 찾기 -> 더보기 에선 수정 UI 없고 5개 format 미리보기만 있으면 되지 않나. 하단에 편집 / 완료 버튼 있는 거에서 편집 누르면 수정할 수 있는 UI뜨면 되는거 아님?

## 2. 문제·의도와 해결 제안을 분리한 읽기

| ID | 직접 제기한 문제·의도 | 원문에 함께 나온 해결 제안 | 아직 열려 있는 해석 |
|---|---|---|---|
| U01 | 실제 내보내기를 어디서 해야 하는지 예측하기 어려움 | 내 Flow에서 찾게 함 | 공개 화면의 제한 quick 결과까지 없애라는 뜻인지, 권위 있는 내보내기의 주 위치만 옮기라는 뜻인지 |
| U02 | 도움·주의가 상시 노출돼 화면이 지저분함 | 물음표·느낌표 popup | 안전·중복·비가역 영향도 모두 숨겨도 되는지, popup·popover·sheet 중 무엇이 맞는지 |
| U03 | 내 Flow의 정보 구조·순서가 납득되지 않음 | 다른 앱 study 후 전면 재고 | 저장 계획 library와 Today 중 무엇이 기준인지, 저장 직후와 일반 재방문의 첫 화면이 같은지 |
| U04 | Item 상세·메모·완료 흐름과 시각 위계가 이질적임 | 파란 배경 통일, 실행할 일 삭제, 할일 수정→수정 | 단순 시각 감산만의 문제인지, 메모 작성→완료→되돌리기까지 action/state 소유권 문제인지 |
| U05 | Flow Map 3칸 요약이 잔여 구조처럼 보임 | 삭제 또는 물음표 안으로 이동 | 세 값 모두 불필요한지, 선택 범위·개수·날짜 중 행동에 필요한 값이 있는지 |
| U06 | 시작일 입력값이 바로 아래에서 반복됨 | 중복 표시 삭제 | 결과에 날짜가 반영됐다는 확인 자체도 없애야 하는지, 확인 위치만 옮길지 |
| U07 | 공개 상세 CTA가 콘텐츠마다 다르고 결과 가능성이 한 종류만 보여 혼란스러움 | 여러 형식, 하단 편집/완료, 완료 뒤 내 Flow 이동과 큰 보내기 버튼 | 완료가 저장·편집 종료·실행 완료 중 무엇인지, 다섯 형식을 고정 노출할지 capability에 따라 다르게 할지 |
| U08 | 공개/저장 편집 UI가 다르고 본문 아래 인라인 편집이 맥락을 섞음 | 같은 UI family, popup 또는 별도 화면 | 같은 화면·문구까지 동일해야 하는지, 같은 family 안에서 commit 효과는 달라야 하는지 |
| U09 | 더보기·미리보기·편집의 역할이 뒤섞임 | 더보기에는 5형식 preview만, 편집은 하단 버튼에서 분리 | 더보기라는 숨김 이름을 유지할지, 지원 불가 형식은 어떻게 처리할지 |
| U10 | Flow라는 단어가 처음 보는 사람에게 이해될지 의문 | 명시 해결안 없음 | 사용자 label만 계획으로 바꿀지, FLOW 브랜드·URL·내부 type까지 바꿀지 |

## 3. 1차 독립 검토자가 먼저 답할 질문

다른 가설 지도·경쟁 앱 결론·승인 방향을 읽기 전에 아래를 자기 언어로 답한다.

1. 열 가지 현상 뒤에 있는 근본 문제를 최대 일곱 개로 묶으면 무엇인가?
2. 원문의 해결 제안 중 그대로 적용하면 새로운 혼란·데이터 손실·안전·접근성 문제를 만드는 것은 무엇인가?
3. 무엇은 단순 감산 문제이고, 무엇은 데이터·상태·행동 소유권 문제인가?
4. 어떤 화면·상태·실패 사례가 없어서 지금 판단할 수 없는가?
5. 제공된 요약에 없던 새로운 발견 후보를 최소 세 개 적는다.

1차 답변은 결과 파일의 생성 시각과 SHA-256을 기록해 고정한다. 그 뒤에만 나머지 패키지의 가설·승인 방향·benchmark를 읽고 2차 반증 검토를 진행한다.
