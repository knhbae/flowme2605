# 공개 Flow 시각 시스템 감사

## 판단

공통화 대상은 화면 모양이 아니라 실행 계약이다. 모든 콘텐츠는 제목, 귀속, 기준 날짜, 실행 항목, 상세 근거, 개인 수정본, 저장·반출 경로를 공유한다. 기본 화면은 콘텐츠 목적에 따라 다르게 투영한다.

| 실행 유형 | 기본 화면 | 기본 노출 | 점진 공개 |
| --- | --- | --- | --- |
| timeline | 일정 + 할 일 | 주요 8개 할 일, 작은 월간 개요 | 나머지 할 일, 상세 근거 |
| checklist | 현장/준비 체크 | 핵심 8개, 공통 주의 | 나머지 항목, 상세 기준 |
| decision | 점검 + 판단 | 점검 순서, 구매/보류/거절 | 보류 기록, 세부 근거 |
| routine | 현재 세션 + 프로그램 | 다음 회차, 이번 주 | 미래 주차, 지난 기록표 |
| record | 오늘 기록 + 전체 표 | 오늘 기록 행, 핵심 메모 | 전체 표 |

## 시각 변경

1. 페이지와 workbench를 감싸던 큰 흰 카드 프레임을 제거했다.
2. 반복 카드의 radius를 8px 이하로 낮추고, 섹션은 선과 여백으로 구분했다.
3. mobile sticky CTA를 떠 있는 카드가 아닌 하단 app bar로 바꿨다.
4. 저장 전 선택을 `N / 전체` 진행률처럼 표시하지 않고 `N개 미리 선택`으로 표현했다.
5. Flow 단위 export는 기본 접힘 상태이며 실행 미리보기 뒤에만 둔다.
6. 제작자 링크와 `원문 기준 실행본`을 제목 바로 아래에 배치했다.

## 가치사슬 coverage

| 구간 | 현재 연결 | 판단 |
| --- | --- | --- |
| 원문·제작자 | 첫 화면 귀속, 원문 링크, 근거 상세 | 이번 slice에서 강화 |
| 기준 Flow | 카테고리별 실행 표면과 공통 실행 항목 | 유지 |
| 사용자 개인본 | `내 버전`, 날짜·메모 overlay 경로 | 유지 |
| 실행 | My Flow 저장, 체크, Calendar 투영 | 기존 경로 유지 |
| 휴대성 | 캘린더·시트·메모 | 2차 행동으로 유지 |
| 성과 환류 | 리뷰, 수정 요청, 업데이트 수락, 제작자 집계 | 아직 미구현 |

## 시각 확인 결과

- 390px: 타임라인 목록 우선, 긴 체크리스트 8개 우선, 루틴 이번 주 우선, sticky save 고정.
- 1024px: 타임라인 목록 폭이 달력 폭의 2배 이상, 점검형 2열 목록, routine/record의 작업 표면 분리.
- 대표 공개 route의 horizontal overflow 0.
- export 형식 버튼은 기본 화면에서 숨김, Flow 단위 disclosure를 열면 접근 가능.

## 남은 리스크

- 공개 Flow 다음 단계인 My Flow와 Calendar는 이전 세대 카드 밀도와 시각 토큰이 일부 남아 있다.
- 콘텐츠 유형 자동 판정이 잘못되면 올바르지 않은 기본 표면을 선택할 수 있다.
- 제작자 성과는 외부 export 이후를 자동 추정할 수 없으며, 재방문·자기보고·업데이트 수락 같은 정직한 신호 설계가 필요하다.
- 리뷰·수정 요청을 바로 추가하면 기준본/개인본/공개 파생본의 권한 경계가 흔들릴 수 있으므로 별도 spec이 필요하다.
