Phase 1 후보 비교는 기숙사를 1순위로 두고, 초등·원격은 A-로 보류한다

첫 세 개 상세 후보인 기숙사 입사 준비, 초등학교 입학 준비, AnyDesk 원격지원 설정을 비교한 문서다. 결론은 기숙사를 먼저 `/content-flows` 리뷰 후보로 설계하고, 초등 입학과 원격지원은 같은 배치의 백업 후보로 문서화하되 공개 라우트 승격은 보류하는 것이다.

1순위: Dorm move-in preparation A- 후보: Elementary entry · AnyDesk remote support 공개 라우트 승격 전: source fidelity · artifact clarity · mobile fit 필요
Rank 1

기숙사 입사 준비

학교별 공지와 PDF가 날짜, 서류, 물품, 금지항목, 입실 절차를 직접 제공해 source-to-artifact 충실도가 가장 높다.

Rank 2

초등학교 입학 준비

사용자 수요는 넓지만 공식 안내와 부모 체크리스트를 분리하지 않으면 쇼핑 조언으로 흐를 위험이 있다.

Rank 3

AnyDesk 원격지원 설정

디지털 설정 축을 열지만 보안 보장이나 원격접속 권장처럼 오해될 수 있어 경계 부담이 크다.

1. 비교 테이블

세 후보의 결정, 사용자 순간, 자연 산출물, 최소 anchor, 강한 신호, 주요 리스크를 한 번에 비교한다.

순위 후보 결정 사용자 순간 자연 산출물 최소 Anchor 강한 신호 주요 리스크
1 기숙사 입사 준비 A 학생/부모가 학교별 기숙사 입사 공지를 실행한다. Hybrid: D-day reminders + checklist/memo 입사일 공식 PDF/page에 날짜, 서류, 물품, 금지목록, 입실 절차가 있다. 한 학교의 health/document/prohibited rule을 일반화하는 위험
2 초등학교 입학 준비 A- 부모가 공지와 체크리스트로 첫 등교일을 준비한다. Hybrid: D-60 to D-1 reminders + checklist/memo 입학식 날짜 넓은 부모 수요와 강한 checklist shape generic shopping advice가 되거나 blog list를 과장하는 위험
3 AnyDesk 원격지원 설정 A- 사용자가 1회 원격 PC 지원을 안전하게 준비한다. Internal checklist + closeout memo support type 또는 support time distinct digital setup axis와 명확한 closeout need security guarantee나 remote access 권장으로 오해될 위험

2. Stage 0 행동 적합도

1

기숙사

source-specific route preview, move-in date anchor, calendar + checklist copy, documents/items/prohibited/arrival checks가 모두 강하다.

2

초등 입학

entry date와 optional 예비소집 date, reminders + checklist copy, notice/purchase/defer/label checks가 맞다.

3

AnyDesk

open/anchor/export는 중간이지만 permission/closeout check와 feedback은 강하다. Calendar는 중심 산출물이 아니다.

3. Source와 Artifact 적합도

기숙사는 source precision과 artifact fit이 가장 고르게 높고, 초등은 수요가 넓지만 공식/부모 출처 분리가 필요하며, AnyDesk는 closeout checklist가 강하지만 security advice로 오해되지 않아야 한다.

4. 만들지 않을 것

기숙사 입사

초등 입학

AnyDesk 원격지원

AnyDesk integration, device/address-book storage, password vault, session log, support-ticket product, fraud detection claim.

5. 추천 리뷰 순서

First

기숙사 입사 준비

source-to-artifact fidelity가 가장 높고, 새 생활전환 축이며, one primary source를 붙이면 generic advice로 흐를 위험이 낮다.

첫 UI 조건: top action은 `최신 기숙사 공지 다시 확인`, artifact는 D-14/D-7/D-5/D-1/D-Day를 보여준다.
Second

초등학교 입학 준비

사용자 순간이 크고 부모 수요가 넓다. 다만 overbuying advice를 막기 위해 공식 process와 parent checklist를 분리해야 한다.

첫 UI 조건: `학교 안내 확인`, `먼저 살 것`, `안내 후 살 것`을 첫 화면에서 분리한다.
Third

AnyDesk 원격지원 설정

digital setup과 permission cleanup 학습에는 좋지만 caution burden이 가장 크다.

첫 UI 조건: `내가 먼저 요청한 지원인가?`에서 시작하고 one-time support는 manual approval을 기본으로 둔다.

6. Phase 1 결정

Phase 1은 research-only 분석에서 review-candidate design으로 넘어갈 만큼 충분한 상세 후보를 만들었다. 다만 세 후보 모두 source fidelity, artifact clarity, mobile first-screen fit을 보여주기 전에는 public `/f/[slug]`로 승격하지 않는다.

1. Promote to review UI

Dorm move-in preparation을 먼저 `/content-flows` review UI로 올린다.

2. Keep as backups

Elementary entry와 AnyDesk remote support는 같은 batch의 documented backup으로 둔다.

3. No public promotion yet

이 문서는 route, UI, user behavior를 검증하지 않는다. 검증은 문서 링크 확인만 요구한다.
