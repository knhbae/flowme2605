캘린더, Notion, Todo, 운동 계획, 여행 일정 제품의 공식 자료를 과업별로 비교해 FlowMe가 가져갈 구조와 버릴 복잡성을 정리했습니다.

공통으로 강했던 네 가지

밀도 분리

월간 개요와 선택일 상세를 같은 밀도로 보여주지 않습니다.

오늘 집중

오늘 화면은 프로젝트 전체가 아니라 지금 행동할 것만 모읍니다.

한 데이터, 여러 뷰

풍부한 속성은 보존하되 각 뷰에는 필요한 속성만 노출합니다.

단계 구분

계획, 현재 세션, 실행 기록, 회고를 한 화면의 카드로 겹치지 않습니다.

Todo

프로그램 전체보다 오늘 세션, 시간, 세트·반복, 다음 동작이 먼저입니다.

Travel

모든 기능을 나열하지 않고 콘텐츠 유형이 요구하는 첫 실행물만 전면에 둡니다.

화면별 적용

/f/[slug]

첫 대폭 수정 대상. 모든 artifact를 쌓지 않고 유형별 핵심 실행물을 먼저 보여줍니다. wide에서는 실행 목록이 캘린더보다 넓어야 합니다.

/my

Today는 작은 실행 큐, 전체는 저장된 Flow 관리로 분리합니다. 행에는 제목·완료·열기만 우선합니다.

/calendar

월간 grid는 compact 날짜 탐색, 선택일 agenda는 전체 Flow와 할 일의 읽기·실행을 담당합니다.

/flows

입력, hit, miss, draft를 한 intake 흐름으로 연결하되 결과는 해당 콘텐츠 유형의 자연스러운 artifact로 보여줍니다.

/

URL·메모 시작을 1차로 두고 대표 콘텐츠는 유형 다양성을 보여주는 보조 시작점으로 제한합니다.

결정

FlowMe는 Notion이나 캘린더의 복제품이 아니라, 외부 콘텐츠를 사용자의 실행물로 바꾸는 변환·실행 레이어를 유지합니다. 복잡한 메타데이터는 보존하지만 첫 화면에는 현재 행동에 필요한 정보만 보여줍니다.

현재 wide public Flow는 캘린더 빈 공간과 좁은 실행 목록의 불균형이 명확합니다. overflow 0은 디자인 완료를 뜻하지 않습니다.
