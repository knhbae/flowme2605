지금 사용자가 보는 실제 화면

아래는 2026-08-19 Vercel Production을 390px에서 직접 캡처한 증거입니다. 이후 UI는 이 화면을 재설계한 것이 아니라, 같은 요소를 더 일관되게 보이도록 정리한 구조 모형입니다.

02 · Visual direction

차분한 실행 노트 + 정밀한 생산성 도구

FLOW의 미색·잉크·코발트 블루는 유지합니다. 새 브랜드를 덧씌우지 않고, 각 색과 표면의 역할을 하나로 정리합니다.

같은 FLOW, 더 적은 시각 잡음

기능이 아니라 의미 위계를 정리합니다.

Typography

실제 구현 기준은 본문 16/24, 메타 12/16, 제목 28/36입니다. 아래 8개 화면 모형은 비교용 축척이며 12px 아래로 내리지 않습니다.

Spacing

4·8·12·16·24·32 체계로 카드 안 밀도와 화면 여백을 맞춥니다.

Action

전진=블루, 선택=잉크, 성공=그린, 삭제=레드로 역할을 고정합니다.

Surface

카드 12px, 시트 20px, 그림자는 오버레이와 고정 바에만 씁니다.

Mobile

핵심 CTA 48px, 보조 조작 44px, 가려지지 않는 focus ring을 적용합니다.

04 · Step-by-step diagnosis

예뻐진 화면 아래 남아 있는 문제

각 단계마다 현재 문제, 디자인으로 좋아지는 부분, 디자인으로는 해결할 수 없는 부분을 나란히 봅니다.

01

계획 찾기 · 시작 방식이 둘입니다

BEFORE

URL·메모 입력, 준비된 계획 검색, 카테고리가 같은 화면에서 모두 “시작점”처럼 경쟁합니다.

DESIGN-ONLY

표면·여백·제목 위계를 분리해 어디가 입력이고 어디가 카탈로그인지 빨리 훑을 수 있습니다.

REMAINS

사용자는 두 방식 중 무엇을 선택해야 하는지 여전히 판단해야 합니다. 역할·카피·우선순위 변경이 필요합니다.

02

계획 미리보기 · 결과 형식이 내용을 앞섭니다

BEFORE

계획을 이해하기 전에 Text·Todo·Calendar 중 하나를 고르게 하고, D-30 계획도 기준일 없이 날짜 없음으로 시작합니다.

DESIGN-ONLY

선택 상태·출처·결과 개수·저장 버튼을 더 명확하게 읽을 수 있습니다.

REMAINS

각 결과의 차이, 추천 기본값, 실제 목적지, 이사일 입력은 생기지 않습니다. 이는 projection·카피·데이터 계약 문제입니다.

03

계획 수정 · 24행의 모든 제어가 동시에 보입니다

BEFORE

이름·할 일, 현재·조정 후, 포함·순서·세부 수정이 한 시트에서 경쟁합니다.

DESIGN-ONLY

탭·영향 비교·목록 행을 정돈하면 복잡한 화면도 훨씬 차분하게 스캔할 수 있습니다.

REMAINS

계획 전체와 단일 할 일의 적용 범위, 24개 행의 인지 부하, 날짜 범위가 어디서 왔는지는 그대로입니다.

04

할 일 조정 · 수정 범위가 설명되지 않습니다

BEFORE

제목·메모·날짜를 고칠 수 있지만 이 변경이 한 항목에만 적용되는지, 언제 계획에 저장되는지 약합니다.

DESIGN-ONLY

라벨·입력·helper·focus·고정 CTA 문법을 통일해 폼 자체는 훨씬 조작하기 쉬워집니다.

REMAINS

Item 변경 → Plan 반영 → 최종 저장의 단계적 transaction은 시각 개선만으로 설명되지 않습니다.

05

내 계획 · 저장 뒤 다음 행동이 약합니다

BEFORE

사본 1, 날짜 미정, 24개 목록, 관리·수정·옮기기가 한 화면에 있고 무엇부터 할지 약합니다.

DESIGN-ONLY

성공 notice·진행률·다음 행·하단 행동의 위계를 강화해 현재 상태를 더 빨리 읽습니다.

REMAINS

가장 가까운 실행 항목, 날짜 미정 inbox, 날짜 묶음, 외부 도구 이동 우선순위는 새로 생기지 않습니다.

06

내 도구로 옮기기 · 실패한 결과가 먼저 선택됩니다

BEFORE

Calendar 0개가 선택된 채 날짜 있음 0·날짜 없음 24와 빈 ICS 원문을 보여줍니다.

DESIGN-ONLY

범위·형식·가능 여부·미리보기를 단계로 정리하면 왜 안 되는지는 더 빨리 파악합니다.

REMAINS

가능한 Text·Todo보다 실패한 Calendar가 우선이고, 날짜를 고치는 정확한 항목으로 돌아갈 경로가 없습니다.

07

캘린더 · 빈 상태가 더 예뻐질 뿐입니다

BEFORE

Calendar 결과를 가진 계획을 저장했지만 실제 일정은 0개이고, 빈 이유나 복구 행동이 없습니다.

DESIGN-ONLY

월 이동·선택일·0개 상태를 더 의도적이고 안정적으로 보여줍니다.

REMAINS

기준일·상대 날짜·저장 데이터 연결이 없으므로 캘린더는 실행 도구가 되지 못합니다.

08

계획 관리 · 보관인지 휴지통인지 모호합니다

BEFORE

행동은 “보관”인데 설명은 복구와 영구 삭제를 함께 말해, 보관함과 휴지통의 의미가 섞입니다.

DESIGN-ONLY

팝오버 계층·행 높이·배경 차폐를 정리하면 메뉴 자체는 읽기 쉬워집니다.

REMAINS

“휴지통으로 이동·복원·이 기기에서 영구 삭제”라는 lifecycle 카피와 실제 동작 계약이 필요합니다.

05 · Verdict & next goal

디자인 개선은 필요하지만, 종착점은 아닙니다

시각 정돈은 제품의 신뢰감과 조작성에 바로 기여합니다. 다만 UX 계약을 바꾸는 개발과 별도 트랙으로 관리해야 효과를 과장하지 않습니다.

디자인만으로 좋아지는 것

  • 제품 완성도와 FLOW 브랜드 일관성
  • 제목·출처·상태·행동의 가독성
  • 선택·focus·성공·위험 상태 인지
  • 48px CTA와 긴 목록의 모바일 조작성
  • 카드·폼·시트·리스트의 학습 비용 감소

구조 변경 없이는 안 풀리는 것

  1. 결과 형식과 실제 목적지의 의미
  2. 기준일 입력 → 저장 → Calendar의 연속성
