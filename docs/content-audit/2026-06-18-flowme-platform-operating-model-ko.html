플랫폼형 Flow 구조 재정의

Flow of Flow는 Flow 묶음이 아니라 운영 가능한 실행 지도다

기존 Top5 샘플은 여러 단일 Flow를 탭으로 모은 것에 가까웠다. 이번 기준은 프로젝트 관리, 운동 관리, 학습 관리 서비스의 공통 구조를 FlowMe에 맞게 번역하는 것이다.

상위 프로그램 반복 하위 Flow 오늘 실행 진행률 제작자 운영판

레퍼런스에서 가져올 구조

Jira / Linear

큰 목표는 Epic 또는 Project로 두고, 실제 실행은 Issue, Story, View, Progress로 나뉜다. 중요한 것은 큰 목표와 오늘 처리할 작은 단위가 계속 연결된다는 점이다.

참고: Atlassian Epics, Linear Projects

운동 관리

Trainerize류 서비스는 프로그램, 단계, 운동, 습관, 캘린더, 수행률을 분리한다. 여러 프로그램이 한 사용자 캘린더에 합쳐질 수 있다는 점이 FlowMe의 장기 구조와 맞다.

참고: Trainerize Features, Multiple Programming

공부 관리

학습 플랫폼은 Track, Course, Unit, Lesson, Practice, Project, Mastery를 분리한다. 사용자는 전체 커리큘럼을 보지만 실제로는 오늘 다음 학습을 실행한다.

참고: Khan Academy 중등 1학년, Coursera Skills Tracks

FlowMe 모델 번역

1

Program Map

제작자의 큰 콘텐츠 구조. 예: 중등 1학년 수학, 8주 러닝, 자격증 과목 운영판.

2

Child Flow Template

반복되는 실행 패턴. 예: 개념 보기, 연습, 오답, 복습.

3

User Artifact

사용자에게 생성되는 캘린더, 진도표, 체크리스트, 메모.

4

Execution Record

오늘 실행, 체크, 메모, 다음 단위, 진행률. 플랫폼 가치는 여기에서 쌓인다.

단일 Flow와 Flow of Flow의 판정 기준

구분 단일 Flow 진짜 Flow of Flow
상위 구조 없어도 된다. 하나의 일정, 체크리스트, 표로 충분하다. 상위 프로그램, 과정, 목표, 지도 구조가 필요하다.
하위 단위 항목들이 서로 다른 성격이어도 괜찮다. 같은 패턴의 하위 Flow가 3개 이상 반복되어야 한다.
사용자 가치 저장 후 바로 실행하면 끝난다. 전체 위치, 다음 실행, 진행률, 일부 저장이 의미 있어야 한다.
제작자 가치 한 번 변환하고 공개하면 된다. 단원, 주차, 과목, 월령을 계속 추가·수정·운영할 수 있어야 한다.
실패 신호 설명이 길고 실행이 안 보인다. 그냥 Flow 카드 목록처럼 보인다.

이번 대표 PoC 선택

대표 케이스는 중등 1학년 수학 학습 지도로 잡는다. 이유는 Khan Academy 중등 1학년 페이지가 단원 구조를 가지고 있고, 각 단원을 같은 학습 패턴으로 반복할 수 있으며, 사용자 화면과 제작자 운영판의 차이가 가장 선명하게 드러나기 때문이다.
