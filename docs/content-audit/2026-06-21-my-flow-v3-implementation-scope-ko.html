적용 범위 정리

My Flow v3를 실제 `/my`에 옮길 때

이 문서는 사용자형 v3 화면을 실제 My Flow 구현으로 옮길 때의 적용 범위와 우선순위를 정리합니다. v3는 새 제품을 더 붙이는 제안이 아니라, 기존 My Flow 실행 허브에서 사용자가 처음 보는 밀도를 줄이는 기준입니다.

v3 사용자 화면 · v2 상태별 검증 화면 · 기존 My Flow spec

현재 판단

새 IA가 아니라, 기존 IA의 첫 화면 정돈

이미 있는 것`/my`는 오늘 탭, 단일 Flow 상태, 완료 접힘, UX20 대량 목록 접힘, Flow별 진행 카드, 캘린더/체크/루틴 뷰를 이미 갖고 있습니다.
v3에서 얻은 것사용자 첫 화면은 테스트 상태 선택, 내부 구조 설명, 전체 목록보다 오늘 실행과 선택 항목 상세가 먼저 보여야 합니다.
하지 말 것새로운 관리 버튼, 상태 버튼, 별도 워크스페이스 용어, 제작자 구조 노출을 추가하지 않습니다.

구현 우선순위

실제 `/my` 반영 범위

우선순위 적용 항목 현재 구현 근거 v3 기준 검증 방법
P0 첫 진입 카피와 요약을 `저장한 Flow 관리`보다 `오늘 할 일부터 보기` 쪽으로 낮춤. 현재 `/my`는 저장한 Flow 섹션과 탭/스코프 선택이 먼저 보일 수 있음. 헤더는 `오늘 n개`, 본문은 오늘 항목, 다음 항목, 접힌 저장 목록 순서. 모바일 390px 첫 화면에서 오늘 항목 1개 이상이 보이는지 Playwright로 확인.
P0 6개 이상 저장 상태에서 전체 Flow 목록은 기본 접힘 유지. 검색/필터는 보조로 둠. UX20 E2E는 전체 목록 접힘과 그룹핑을 이미 검증함. `저장한 Flow 찾기`는 사용자가 필요할 때 여는 보조 동작. UX20 테스트가 `전체 Flow 보기` 기본 접힘을 계속 통과해야 함.
P1 오늘 상세에서 체크/메모/원문/외부 앱 텍스트를 한 덩어리로 더 가볍게 보이게 함. 현재 item detail은 calendar-style editor이며, 링크/첨부는 더보기 아래에 있음. 기본 상세는 제목, 체크, 메모, 원문 링크, fallback text만으로 충분. 상세 첫 화면에서 필드가 캘린더/리마인더 수준을 넘지 않는지 모바일 스크린샷으로 확인.
P1 토스트/상태 피드백은 필요한 경우만 유지. 체크박스 색상 변화가 충분하면 추가 피드백 생략. v3 PoC에서 토스트가 상세 하단을 가려 제거함. 체크 상태는 행 색상과 체크박스만으로 표시. 체크 후 겹침 없는지 모바일/데스크톱 스크린샷 확인.
Later 20개 이상 저장 상태에서 최근 사용, 고정, 보관함 같은 고급 관리 추가. UX20은 30개 그룹 목록을 이미 검증하지만 실제 사용자 포트폴리오는 아님. 관찰 전에는 고급 관리 기능을 붙이지 않음. 실제 저장 20개 이상 사용자 관찰 이후 판단.

사용자 저니

실제 사용 흐름으로 보면

1. My Flow 열기
2. 오늘 할 항목 보기
3. 항목 선택 후 체크/메모
4. 필요할 때 저장한 Flow 찾기

이 흐름에서 사용자가 처음 마주하는 것은 관리판이 아니라 오늘 할 일입니다. Flow Map, 제작자 구조, 원문 변환 근거는 공개 상세/제작자 화면에 남기고, 내 Flow에서는 현재 항목과 실행 기록만 보이게 합니다.

수용 기준

다음 구현 또는 관찰 전에 통과해야 할 기준

기준 통과 조건 현재 상태
첫 화면 모바일에서 저장 관리 설명보다 오늘 실행 항목이 먼저 보임. 구현 확인 필요 v3 HTML은 통과, 실제 `/my`는 별도 확인 필요.
인지부하 상태 버튼, 테스트 컨트롤, 내부 용어가 사용자 화면에 없음. PoC 통과 v3 HTML 기준 통과.
목록 관리 6개 이상 저장 시 전체 목록은 기본 접힘, 검색은 보조. 기존 구현 있음 UX20 E2E 근거 있음.
실행 상세 체크, 메모, 원문, 외부 앱 텍스트가 항목 안에서 해결됨. 부분 통과 v3 HTML은 통과. 실제 detail editor는 유지/축소 판단 필요.
검증 주장 실제 사용자 관찰 전에는 검증됨이라고 부르지 않음. 유지 내부 PoC/적용 후보로만 표기.

권장 다음 작업

바로 이어서 할 일

1. `/my` 모바일 현재 화면 캡처`/my?demo=ux12`, `/my?demo=ux20`을 v3 기준으로 다시 보고 첫 화면이 과한지 확인합니다.
2. P0 카피/배치만 반영처음부터 전체 재설계하지 않고 헤더, 오늘 요약, 전체 Flow 접힘 카피부터 줄입니다.
3. 관찰 태스크 준비사용자에게 “오늘 할 일 찾기, 하나 체크하기, 저장 목록에서 Flow 찾기” 3개 행동만 시켜 봅니다.
