사용자 저니 시뮬레이션

단계 사용자가 보는 것 판단 수정 반영
1. 발견 전세계약, 이사, 수학 커리큘럼 같은 콘텐츠를 선택한다. 통과 콘텐츠마다 자연 artifact가 먼저 보인다. 제목을 기능 설명보다 결과물 중심으로 정리했다.
2. 저장 전 확인 저장하면 내 앱에 생길 일정, 체크리스트, 진도표를 본다. 통과 단일 Flow는 입력 0-2개 안에 들어온다. 홈트와 중고차는 불필요한 상태 버튼 대신 체크/메모로 제한했다.
3. 전체 또는 일부 저장 중1 수학과 자격증은 전체 저장과 일부 저장을 고른다. 보완 필요 전체 저장 후 내 Flow에서 접힌 구조가 더 필요할 수 있다. 내 앱 첫 화면은 전체 지도보다 현재 위치와 다음 항목을 앞에 뒀다.
4. 실행 오늘 또는 선택한 날짜/단원/과목을 열고 체크한다. 통과 실행 화면은 전세 Flow 수준으로 가볍다. 각 실행 화면에 체크, 짧은 메모, 원문 링크만 남겼다.
5. 재방문 다음 날짜, 다음 단원, 다음 과목을 찾는다. 보완 필요 실제 앱에서는 알림/정렬/완료 상태가 더 필요하다. PoC에서는 현재 위치와 다음 항목 표시까지만 둔다.

제작자 저니 시뮬레이션

Loop A

  • 제작자가 원문 구조를 본다.
  • 단일 Flow인지 반복 하위 실행 구조인지 판단한다.
  • 저장 결과와 첫 실행 항목을 확인한다.

결과 제작자 화면은 사용자 체크 화면과 분리되어 이해 가능하다.

Loop B

  • 중1 수학은 단원별 반복 구조가 뚜렷하다.
  • 자격증은 전체 로드맵보다 과목별 운영판으로 볼 때 더 자연스럽다.
  • 이사는 현재 단계에서는 단일 timeline Flow가 더 적합하다.

결과 상위 구조형 후보와 단일 Flow 후보가 분리되었다.

문제 등급과 처리

등급 문제 처리 남은 리스크
Blocking 상위 구조가 단순 묶음처럼 보일 수 있음. 중1 수학과 자격증만 대표로 두고 이사/육아는 제외했다. 실제 제작자 콘텐츠에서 반복 단위가 약하면 다시 제외해야 한다.
High 내 앱 화면이 과한 대시보드처럼 보일 수 있음. 현재 위치와 오늘 열 항목을 우선하고 전체 지도는 사이드 목록으로 낮췄다. 많은 저장 Flow가 있을 때 검색/정렬은 별도 설계가 필요하다.
Medium 모바일에서 탭과 헤더 밀도가 높을 수 있음. 390px 기준 responsive grid와 짧은 제목을 적용했다. 실제 앱 컴포넌트로 옮길 때 bottom tab이나 compact header를 다시 봐야 한다.
Medium 자격증 콘텐츠는 실제 원문과 세부 항목 매핑이 더 필요함. PoC에서는 과목별 운영 패턴만 표현했다. 제품 후보로 올리기 전 실제 원문 단위 재확인이 필요하다.

최종 판단

단일 Flow로 충분

전세계약, 이사, 중고차, 초등 입학, 홈트는 작은 실행 artifact가 먼저다. 상위 구조로 키우면 오히려 복잡해진다.

반복 하위 실행 구조 가능

중1 수학은 단원별 실행 패턴이 반복되므로 강하다. 자격증은 전체 로드맵보다 과목별 진도/기출/오답 운영판으로 좁히면 가능하다.

제품화 전 조건

실제 원문 매핑, 저장 후 내 Flow 정렬, 많은 Flow 관리, 제작자 업데이트 흐름은 다음 단계에서 더 검증해야 한다.
