FlowMe product structure

큰 경험맵 이전에, 제작자 Flow는 Pack/Series로 묶이는 게 자연스럽다

블로그가 처음부터 거대한 카테고리 체계를 만들지 않듯이, FlowMe도 처음부터 모든 콘텐츠를 큰 경험맵으로 만들 필요는 없다. 개별 Flow가 쌓이고, 제작자가 3~7개를 하나의 실행 묶음으로 편집하면 플랫폼 느낌과 실행 가벼움 사이의 균형이 생긴다.

한 줄 판단

개별 Flow

블로그의 글 하나에 가깝다. 원컨텐츠 1개를 캘린더, 체크리스트, 메모, 표, 버킷으로 옮긴 결과물이다.

Flow Pack

블로그의 시리즈나 연재에 가깝다. 같은 사용자 상황에서 함께 쓰면 좋은 Flow 3~7개를 묶는다.

경험맵

여러 Pack이 쌓인 뒤 생기는 상위 지도다. 처음부터 강제로 만들면 코스/로드맵 서비스처럼 무거워질 수 있다.

따라서 다음 PoC는 “자격증 전체 로드맵”보다 “자격증 필기 D-30 준비팩”처럼 작지만 묶인 구조가 더 적합하다.

추천 묶음 단위: Flow Pack

Pack의 기준

  • 같은 사용자 상황에서 함께 쓰인다.
  • 3~7개 Flow로 끝난다.
  • 전체 저장과 일부 저장이 모두 가능하다.
  • 각 Flow는 독립적으로도 실행 가능하다.
  • 제작자 설명은 짧고, 실행 정보는 각 Flow detail로 내려간다.

Pack이 피해야 할 것

  • 강의 커리큘럼처럼 모든 것을 배우게 만들기
  • 제작자 소개와 철학을 첫 화면에 길게 노출하기
  • 하나의 Pack에 서로 다른 사용자 상황을 섞기
  • 실행 순서가 없는 묶음을 로드맵처럼 보이게 하기
  • 개별 Flow의 출처/URL/메모를 Pack 설명으로 합치기

Pack과 큰 경험맵의 차이

구분 Flow Pack 큰 경험맵 지금 판단
크기 3~7개 Flow 여러 Pack과 단계, 분기, 장기 목표 지금은 Pack이 적합
제작자 부담 블로그 시리즈처럼 만들 수 있음 코스 설계나 로드맵 설계에 가까움 초기 제작자는 Pack부터
사용자 저장 전체 저장 또는 필요한 Flow만 저장 전체 여정을 저장한 뒤 단계별 진입 부분 저장이 중요
UI 무게 카드 목록 + 선택 저장 + 오늘 실행 지도, 단계, 진행률, 하위 흐름 초기에는 지도 UI를 크게 만들지 않음
비즈니스 의미 제작자 콘텐츠 상품의 최소 단위 브랜드 프로그램이나 프리미엄 상품 Pack이 creator platform 증명에 더 빠름

추천 데이터 구조

Flow

원컨텐츠 1개, destination 1개 또는 lightweight hybrid, 출처 URL, 실행 항목.

FlowPack

title, audience, promise, creatorId, includedFlows, defaultInputs, saveMode.

PackSection

필수/선택/나중에 같은 작은 묶음. 큰 단계명은 최소화한다.

UserPackCopy

사용자가 저장한 Flow 목록, 공통 날짜 값, 숨김/선택 상태, 완료 상태.

핵심은 Pack의 입력값이 하위 Flow에 흘러가야 한다는 점이다. 시험일, 이사일, 입학일을 한 번 넣으면 하위 캘린더/체크리스트가 같이 만들어져야 한다.

사용자 화면

  • Pack 첫 화면: 무엇을 저장하는지 5초 안에 이해
  • 공통 입력: 시험일/시작일/요일처럼 2~3개
  • 포함 Flow 목록: 필수와 선택 구분
  • 전체 저장, 필요한 Flow만 저장
  • 저장 후 오늘/이번 주 실행 항목

제작자 화면

  • 개별 Flow를 만든 뒤 Pack에 추가
  • Flow 순서와 필수/선택 여부 지정
  • 공통 입력값이 어느 Flow에 쓰이는지 확인
  • 출처 URL과 제작자 경험을 Flow마다 분리
  • 미리보기에서 사용자 저장 결과 확인
