전세계약 UX 기준을 다른 Flow 형태에 적용해보기

이 문서는 제품 구현이 아니라 사용자 화면에 가까운 HTML wireframe입니다. 전세계약에서 확인한 가벼운 UX 원칙을 유지하면서, 날짜형이 아닌 체크리스트형, 버킷형, 루틴형, 상태 체크형에는 어떤 최소 UI가 필요한지 검토합니다.

검토 범위
5개 wireframe 입력 0-3개 validated 아님

전세계약 UX/UI에서 유지할 기준

첫 화면은 실행 도구

상단 설명보다 입력값, 오늘 할 일, 저장 결과가 먼저 보여야 합니다. 검토용 설명은 사용자 화면 밖으로 분리합니다.

입력은 캘린더 앱 수준

기준일, 요일, 항목명처럼 사용자가 바로 이해하는 0-3개 입력만 받습니다. 복잡한 도메인 폼은 만들지 않습니다.

detail/URL로 밀어내기

출처, 제작자 경험, 주의사항, 긴 원문 맥락은 detail, memo, URL에 둡니다. 화면에는 실행 action만 남깁니다.

  • 계약일 입력이 이사일 입력으로 바뀜.
  • D-3/D-Day/D+1 구조가 D-30/D-14/D-7/D-1/D-Day로 확장됨.
  • 캘린더 미리보기와 전체 보기 탭은 그대로 유효함.

새로 필요한 최소 UI

  • 견적 후보 3곳처럼 countable한 작은 메모 슬롯.
  • 전입신고/확정일자는 단독 Flow가 아니라 D-Day 하위 item으로 표시.

저장 후 사용

calendar에 5개 일정, checklist에 각 날짜 action, memo에 업체 후보와 예약 정보를 저장합니다.

동작 순서는 앱에 재작성하지 않음. 통증/어지럼/호흡곤란 시 중단 조건은 detail에 고정 표시

전세계약 UX 재사용

  • 첫 입력 후 실행 카드가 생기는 구조는 유지.
  • 상세 설명은 detail/URL로 보내는 원칙 유지.

새로 필요한 최소 UI

  • D-day가 아니라 반복 요일 선택이 핵심 입력.
  • 완료 후 상태칩이 있어야 다음 회차 조정이 가능함.

저장 후 사용

routine에 반복 일정, record에 완료/강도/통증 상태, memo에 원문 영상 URL을 저장합니다.

  • 상태칩이 먼저이고, 물주기는 조건부 action.

다음 제품 구현 우선순위

1. 이사 D-30

전세계약 UX를 가장 많이 재사용할 수 있으면서 다른 생활 전환 카테고리 확장성을 보여줍니다.

2. 중고차 체크

체크리스트형의 핵심인 진행/보류 UI를 검증할 수 있습니다.

3. 홈트 또는 식물

반복 루틴형과 상태 체크형 중 하나를 실제 화면으로 만들면 날짜형 외 확장성이 보입니다.

이 문서는 UX/UI pattern draft입니다. 실제 사용자 검증, 콘텐츠 검증 완료, 법률·의료·안전 자문을 의미하지 않습니다. 원문 링크와 출처는 wireframe의 detail/URL 위치를 보여주기 위한 검토용입니다.
