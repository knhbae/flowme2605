# P24-00U4 실행 중 메모 Audit

## 사용자 문제

기존 회고는 Flow가 모두 끝난 뒤에만 드러났다. 실행 도중 항목별로 알게 된 점을 남기려면 제목·날짜·구조 설정이 함께 있는 상세 편집의 메모를 사용해야 했다. 개인 경험과 원본에서 고칠 점도 완료 화면의 별도 form까지 기억해서 옮겨야 했다.

이 구조는 실행 기록의 시점을 놓치게 하고, 구조 메모와 관찰 메모의 책임을 섞는다.

## UX 결정

1. 메모 진입은 실행 행에서 한 번 탭으로 연다.
2. 제목·날짜·반복을 바꾸는 구조 편집과 별도 패널로 둔다.
3. 기본 상태는 `내 메모`다.
4. 원문 링크가 있는 항목에만 `원본에 알릴 점`을 함께 제공한다.
5. 두 메모는 같은 항목·회차에 동시에 존재할 수 있다.
6. 원본 보완 의견은 저장되지만 실제 전송으로 표현하지 않는다.
7. 완료 시 별도 입력을 강제하지 않고 기존 메모를 자동 집계한다.
8. 메모가 없으면 집계 UI를 만들지 않는다.
9. 새 실행은 빈 메모로 시작하고 과거 실행에는 snapshot을 보존한다.

## 목업 대조

Claude Design `(8)` G안은 항목 옆 말풍선/메모 진입, 단계별 기록, 완료 시 자동 수집, 별점·태그의 비필수화를 제안했다.

| 목업 | 구현 | 판단 |
| --- | --- | --- |
| 항목별 인라인 메모 | 행 오른쪽 연필 아이콘 | 한 번 탭 유지, 완료·열기와 분리 |
| 자유 텍스트 | 1,000자 실행 메모 | 입력 부담 제한 |
| 완료 시 자동 모음 | 완료 영역의 항목별 목록 | 추가 제출 없이 반영 |
| 수정 요청 | `원본에 알릴 점` | 실제 전송 전 상태를 명시 |
| 평가/태그 | 추가하지 않음 | 현재 단계의 복잡도 억제 |

## 데이터 소유권

### 구조·개인 값

- 제목 alias
- 날짜·시간·반복
- 구조 메모
- 추가·삭제·복구·순서

기존 personal overlay 경로가 계속 소유한다.

### 현재 실행 메모

- `flow:my-flow:execution-notes:{flowSlug}`
- stable row/occurrence key
- `private` 또는 `source_correction`
- 항목 제목, 당시 날짜, optional source URL

### 완료 실행

- `FlowRunCompletionSnapshot.executionNotes`
- 새 실행으로 전환하기 전 현재 메모를 snapshot
- 현재 key는 초기화
- 과거 실행 화면과 memo export는 snapshot을 읽음

source Item, source detail, source URL은 수정하지 않는다. 완료·재개 상태도 실행 메모 record에 넣지 않는다.

## 상태 전이

| 행동 | 현재 실행 | 완료 snapshot | 다음 실행 |
| --- | --- | --- | --- |
| 개인 메모 저장 | 같은 row key에 저장 | 아직 없음 | 해당 없음 |
| 원본 보완 메모 저장 | 개인 메모와 별도 저장 | 아직 없음 | 해당 없음 |
| 메모 지우기 | 선택한 종류만 제거 | 이미 완료된 과거 snapshot은 유지 | 해당 없음 |
| Flow 완료 | 현재 메모 유지 | 두 종류를 함께 snapshot | 해당 없음 |
| 완료 뒤 메모 수정 | 현재 key와 최신 완료 snapshot 동기화 | 갱신 | 해당 없음 |
| 다시 쓰기 | 현재 key 제거 | 과거 snapshot 유지 | 빈 메모로 시작 |

## 접근성·밀도

- 메모 버튼 accessible name은 `{할 일 제목} 실행 메모 남기기/수정`이다.
- 버튼의 저장 여부는 작은 점으로 보조하며 색만으로 의미를 강제하지 않는다.
- 패널에는 항목 제목과 명시적 닫기 accessible name이 있다.
- 메모 종류는 `aria-pressed` segmented control이다.
- 빈 신규 메모의 저장 버튼은 disabled다.
- 이미 저장된 종류에만 `지우기`가 나타난다.
- 390px에서 완료·열기·메모가 겹치지 않고 horizontal overflow가 없다.

## 자동화 시나리오

1. 이사 Flow에서 마지막 미완료 항목의 실행 메모를 한 번 탭으로 연다.
2. 개인 메모를 저장한다.
3. 같은 항목에 원본 보완 의견을 별도로 저장한다.
4. 마지막 항목을 완료한다.
5. 완료 화면의 두 집계 구역을 확인한다.
6. 새로고침 뒤 집계가 유지되는지 확인한다.
7. 1024px에서 같은 집계를 확인한다.
8. 새 이사일로 다시 시작한다.
9. 현재 실행 메모가 비워지고 지난 실행 snapshot에 두 메모가 남는지 확인한다.

## 남은 관찰 질문

- 사용자는 연필 아이콘을 제목 편집이 아니라 실행 메모로 이해하는가?
- `내 메모`와 `원본에 알릴 점`의 구분이 충분히 명확한가?
- 완료 자동 집계가 별도 회고 form보다 자연스러운가?
- 원본 보완 의견을 실제 전송했다고 오해하지 않는가?
- 반복 회차가 많을 때 회차별 메모가 유용한가, series 공통 메모도 필요한가?

## 검증 환경 메모

P24, URL-first, public share, workbench 77개를 4 workers로 동시에 실행할 때 Next production server가 `Z_MEM_ERROR`로 종료되어 4개 navigation이 assertion 전에 실패했다. 같은 4개를 1 worker로 다시 실행하면 모두 통과했다. 따라서 기능 실패로 분류하지 않지만, 이 저장소의 대형 E2E 묶음은 현재 Windows 환경에서 1 worker 또는 작은 shard로 운영하는 편이 안정적이다.
