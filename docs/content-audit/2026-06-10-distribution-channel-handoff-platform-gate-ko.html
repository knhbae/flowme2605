FlowMe 분석방 / distribution-channel-handoff 플랫폼 게이트
작성일 2026-06-10 · 상태: docs-level gate

공유 패킷은 가능하지만 채널 통합은 아직 아니다

공식 자료를 기준으로 KakaoTalk, Naver Cafe, Google Forms/Sheets, Notion, Slack/Teams/Discord 유사 패턴을 확인했다. 결론은 단순하다. FlowMe는 출처와 주의가 붙은 공유 패킷을 준비할 수 있지만, 자동 발송·댓글 수집·연락처 저장·채널 분석은 Stage 0 밖이다.

현재 결정 `distribution-channel-handoff-precheck`는 B+ docs gate로 둔다.
허용되는 산출물 제목, 대상, 마감, 출처, 주의, 완료 기준, 응답 요청이 담긴 공유 패킷.
보류되는 기능 public route, 계정 연결, API, 자동 게시, 응답 수집.
금지 저장값 전화번호, 사용자명, 채팅 로그, 초대 링크, 채널 ID, webhook URL.

플랫폼별 공식 자료 판단

각 플랫폼은 FlowMe가 어디까지 머물러야 하는지 보여주는 경계 자료다.

KakaoTalk Share

카카오톡 공유는 사용자가 카카오톡에서 대상을 선택해 공유하는 흐름이다. 카카오톡 메시지 API처럼 권한과 대상 선택 UI를 직접 다루는 방식과 다르다.

  • Stage 0: 사용자가 복사하거나 직접 공유하는 패킷.
  • 보류: 친구 목록 조회, 채팅방 타깃팅, 대량 발송, webhook 성공 추적.
official source

Naver Cafe

카페 글은 공유 버튼과 댓글/답글 같은 수동 행동이 중심이다. 작성자가 공유를 막을 수 있고, 원본 삭제 시 공유 글에서도 원본 내용을 확인하지 못할 수 있다.

  • Stage 0: 카페 글 패킷과 짧은 댓글/답글 요청문.
  • 보류: 자동 글쓰기, 댓글 수집, 멤버십 처리, 검색 노출 관리.
official source

Google Forms + Sheets

폼 응답은 CSV로 받을 수 있고, 응답 수집 중단, 마감일, 응답 수 제한, 이메일 수집 같은 설정이 있다. 이메일 수집은 응답자 확인이 걸린다.

  • Stage 0: 폼 질문 문구, 마감 안내, 시트 행 라벨.
  • 보류: 폼 생성, 응답 가져오기, 이메일 수집, Sheets API 연결.
official source

Notion / Markdown

Notion은 Markdown, Text, HTML, CSV/XLSX 등을 가져올 수 있다. Markdown/Text/HTML은 페이지로, CSV/XLSX는 데이터베이스로 매핑된다.

  • Stage 0: Markdown/plain text 또는 CSV handoff.
  • 보류: Notion API, 페이지/DB 생성, workspace schema builder.
official source

Slack / Teams / Discord

세 플랫폼 모두 자동 게시 경로가 webhook, workflow, app, bot, channel endpoint 같은 인프라로 빠르게 넘어간다.

  • Stage 0: 경계 비교용 참고만 한다.
  • 보류: webhook URL, bot token, OAuth scope, channel ID, event subscription.
official source

공통 결론

이 축은 실사용 니즈가 있어 보이지만, 통합으로 가는 순간 개인정보, 권한, 비공개 채널, 응답 데이터, 자동화 리스크가 같이 열린다.

  • 결정: B+ docs gate.
  • 다음: 공유 패킷 파일 기반 preview만 설계한다.

공유 패킷 요구사항

FlowMe가 만들 수 있는 것은 채널이 아니라, 채널 밖으로 가져갈 수 있는 작은 실행 패킷이다.

포함해야 할 것
  • 원문 출처 URL 또는 출처명
  • 수신자가 다음에 할 일
  • 마감 또는 타이밍
  • 로컬/출처별 차이 주의
  • 완료 기준
  • 짧은 응답 요청
포함하면 안 되는 것
  • 전화번호, 사용자명
  • 채팅방 ID, 초대 링크
  • access token, webhook URL
  • 폼 편집 링크
  • 비공개 대화 내용
  • 학생, 건강, 결제, 주민 식별값
응답 모양
  • 답장 완료
  • 카페 댓글
  • 폼 제출
  • 시트 한 행 업데이트
  • 체크 확인
  • 보류 사유 메모

다음 테스트 시나리오

승격 전에는 하나의 한국 우선 시나리오로만 좁힌다.

작업명

`school-or-dorm-prep-share-packet`

사용자 순간

보호자, 학생, 소규모 조율자가 출처 기반 Flow 산출물을 마감 전 그룹에 보내야 한다.

자연 산출물

제목 1개, 마감 1개, 행동 3-5개, 출처 URL, 주의, 완료 기준이 붙은 공유 패킷.

앵커

계정 연결이 아니라 audience + deadline.

Stage 0 행동

채널 유형 선택, 패킷 복사, 외부 채널에 직접 붙여넣기, 응답 모양 선택.

아직 필요한 근거

수신자가 추가 설명 없이 패킷을 이해하는지 관찰해야 한다.

제품 결정

이 축은 유망하지만, 바로 구현하면 FlowMe의 경계가 무너진다.

결정

`distribution-channel-handoff-precheck`는 B+ docs gate.

이유

공유, 게시, 댓글, 폼 응답, CSV, Markdown, webhook 패턴은 확인됐지만 통합 경로는 권한과 개인정보 리스크가 크다.

다음 작업

기존 외부 생태계 후보 중 하나로 파일 기반 공유 패킷 preview를 만든다. public route는 만들지 않는다.
