[고정 결정]
1. canonical 문법
   # Flow 제목
   - 기준일: 2026-08-10
   ## Step
   - [ ] Item
     - 설명: ...
     - 날짜: 2026-08-03
     - 상대 날짜: D-3
     - 자료: [이름](https://example.com)

2. 표식 없는 일반 문장은 원문 텍스트로 보존하며 자동 Item으로 만들지 않는다. 기존의 일반 문장 자동 분할은 기본 저작 모드에서 끈다. 별도 import-assist가 있다면 승인 전 후보로만 둔다.

3. 들여쓴 공식 속성 bullet은 반드시 일반 목록보다 먼저 판정한다. 공백 2칸 이상, checkbox 없음, 직전 Item 존재, 공식 속성명이라는 조건을 모두 만족할 때만 속성이다.

4. 들여쓴 미정 colon bullet은 unknown_property issue다. 들여쓴 checkbox는 지원 전까지 unsupported_nested_item issue다. 둘 다 가짜 Item으로 만들지 않는다.

5. v1의 대시 없는 들여쓴 속성은 계속 읽되, writer는 v2 형식만 출력한다. authoring markdown, supported markdown, contract version을 v2로 올리고 v1/v2 parser 호환을 보존한다.

6. 정렬 축을 분리한다.
   - canonical, 체크/할 일, 표/엑셀, 텍스트: 작성 순서
   - Calendar와 ICS 미리보기: 계산 날짜 오름차순, 같은 날짜는 작성 순서
   - Calendar가 정렬되었다고 원문을 자동 수정하지 않는다.
   - 순서가 다를 때만 `입력도 이 순서로 맞추기`를 보여준다.
   - 클릭하면 같은 Step 안의 Item 블록과 소유 속성을 함께 이동하고, stable ID와 source lineage를 유지하며, 원문·구조·결과를 한 transaction으로 갱신한다. 되돌리기를 제공한다.

7. 상대 날짜의 절대 기준은 원문의 `- 기준일: YYYY-MM-DD`다. 기준일이 없으면 실제 날짜를 추정하지 않고 Calendar를 비활성화한다. UI에서 기준일을 선택하면 숨은 state에만 두지 말고 원문 줄을 즉시 추가·수정한다.

8. 결과 형태는 항상 고정된 네 슬롯을 같은 순서와 위치로 렌더링한다.
   캘린더 | 체크/할 일 | 표/엑셀 | 텍스트
   사용할 수 없는 슬롯은 제거하지 말고 disabled로 두며 짧은 이유를 ?/tooltip로 제공한다.

9. 표/엑셀은 원본이 table/CSV/TSV/Markdown table이거나, Item 2개 이상에 반복되는 의미 있는 필드가 2열 이상일 때만 활성화한다. 제목뿐인 일반 목록에는 활성화하지 않는다. 미리보기는 실제 열 이름과 URL 셀을 보여준다.

10. `정리 메모`를 `텍스트`로 바꾸고 `원문 그대로`와 `정리된 TXT/Markdown`을 분리한다. CSV/TSV/Markdown 같은 형식명은 첫 문법 화면이 아니라 결과별 내보내기 메뉴나 표 가져오기 도움말에서만 보여준다.

11. 설명, 완료 기준, 날짜·시간·장소, 반복·조건, 자료 링크가 Calendar 상세, 체크 하위정보, 표 열, 텍스트 Markdown에서 실제로 보이게 한다.

12. `나눈 항목`은 `항목 구조`로 바꾼다. 기본은 읽기 전용 Step/Item 요약이며 이동·분리·병합·역할 변경은 `구조 수정`을 눌렀을 때만 노출한다. 긴 설명은 ? 도움말로 숨긴다.

[구현 순서]
Phase 0. 현재 상태와 기존 변경 소유권을 기록하고, 집중 baseline test를 재실행한다. 실패가 있으면 변경 전 실패인지 구분한다.

Phase 1. 먼저 실패하는 v2 contract tests를 추가한다.
- property bullet ownership
- unknown property와 nested checkbox 경계
- plain text preservation
- v1 read/v2 write
- v2 export/reparse 동등성
- 기존 27개 fixture의 v2 변환

Phase 2. parser/writer/round-trip을 함께 수정한다.
- lib/flow/text-authoring/parser.ts
- lib/flow/text-authoring/authoring-grammar.ts
- lib/flow/text-authoring/markdown-roundtrip.ts
- contract JSON과 문법 안내
writer만 또는 parser만 단독으로 먼저 배포 가능한 상태로 두지 않는다.

Phase 3. 날짜 정렬 projection과 원문 재정렬 operation을 분리한다.
- Calendar/ICS row sort는 resolved date ascending + source order tie-break
- source rewrite는 명시적 operation + undo
- Step boundary, stable ID, source range, property ownership 보존

Phase 4. 결과 eligibility와 preview를 수정한다.
- 결과 슬롯 고정
- Sheet eligibility 축소와 실제 열 시각화
- Text 원문/정리 결과 분리
- 링크와 상세 필드의 결과별 표현

Phase 5. UI 밀도를 정리한다.
- InputPane의 긴 문법 설명을 ? popover로 이동
- StructurePane 기본 읽기 요약과 advanced correction 분리
- 27개 예제는 demo/QA catalog에 남기고 제품 화면은 대표 예시만 노출
- 모바일에서는 입력/구조/결과 탭이 고정되고 각 탭의 세로 스크롤이 독립적으로 끝까지 도달
- 390x600에서 구조 편집 toolbar가 Item 영역을 한 줄로 압축하지 않도록 drawer/sheet 등 분리된 표면을 사용
- 상단 빠른 예시 링크를 단일 선택기로 합치고 하단 저장/복사 버튼 문구가 잘리거나 내용을 가리지 않게 함

Phase 6. standalone HTML과 증거를 재생성한다. 새 변경만 근거로 남기고 기존 증거를 덮어쓸 경우 먼저 소유권과 생성 경로를 확인한다.
