다섯 가지 방향

이 다섯 항목이 고정돼야 Codex는 로직을, Claude는 구조를 서로 다르게 해석하지 않습니다.

01 · 명시적 구조

구조 줄에는 표식

`- [ ]`는 Item, 들여쓴 `- 속성:`은 그 Item의 필드. 표식 없는 문장은 원문으로 남깁니다.

02 · 순서 분리

보기와 원문은 별개

캘린더는 날짜순으로 보이되 원문은 자동으로 건드리지 않습니다. 사용자가 눌렀을 때만 맞춥니다.

03 · 기준일 가시화

D-Day 근거를 원문에

`- 기준일: YYYY-MM-DD`가 있어야 실제 날짜를 계산합니다. UI 입력도 이 줄을 수정합니다.

04 · 결과 고정

버튼은 움직이지 않음

캘린더 · 체크/할 일 · 표/엑셀 · 텍스트를 고정하고, 불가능한 결과만 비활성화합니다.

05 · 고유한 산출물

표는 진짜 표처럼

반복 열이 없으면 표/엑셀을 권하지 않습니다. 텍스트는 원문과 정리본을 명확히 나눕니다.

v2 후보

Obsidian에 가까운 문법

표준 Markdown의 heading, task, nested list 구조를 빌리되 속성 이름의 의미는 FlowMe 계약입니다.

표식이 만드는 포함 관계

명시적-only
  • # 제목Flow 한 개의 제목
  • - 기준일:Flow 단위의 절대 날짜. 상대 날짜 계산의 유일한 근거
  • ## 단계Item을 묶는 Step
  • - [ ] 항목실행 가능한 Item. 입력 순서가 기본 순서
  •   - 속성:바로 위 Item의 필드. 일반 목록보다 먼저 판정
  • 일반 문장Item으로 만들지 않고 원문으로 보존
왜 예시 문구만 바꾸면 18개가 실패하나요?
현재 파서는 일반 bullet을 속성보다 먼저 검사합니다. 그래서 `- 설명:`, `- 날짜:`, `- 자료:`를 각각 새 Item으로 만들고, 날짜와 URL까지 가짜 Item의 일정·자료로 다시 추출합니다. 새 parser 우선순위, v2 writer, v1 호환 parser, round-trip을 동시에 바꿔야 합니다.
중첩 항목과 모르는 속성은 어떻게 하나요?
` - [ ] 하위 작업`은 지원 전까지 검토 issue로, ` - 담당자: 홍길동`처럼 공식 목록에 없는 속성은 unknown-property issue로 원문을 보존합니다. 조용히 평탄화하거나 새 Item으로 만들지 않습니다.

          Claude는 GitHub HTML 파일만 주면 시뮬레이션할 수 있나요?
          
파일을 읽는 것은 가능하지만 링크 하나만으로 정확한 렌더·클릭·스크롤 검증이 보장되지는 않습니다. HTML 업로드는 지원하지만 비PDF 문서는 텍스트 추출 중심입니다. 가장 안정적인 방법은 self-contained HTML, 데스크톱·모바일 PNG, 두 JSON, Claude 프롬프트를 개별 첨부하고 `single-page HTML Artifact로 재구성해 상호작용을 구현하라`고 요청하는 것입니다.

        

        

          GitHub 연동은 언제 쓰나요?
          
별도 승인 후 branch를 push했을 때 사용합니다. Claude의 GitHub integration은 특정 branch의 선택 파일 이름과 내용을 동기화하며 commit history나 PR metadata 전체를 가져오지 않습니다. 변경 후에는 Sync Now가 필요합니다. 현재는 local-only이고 push하지 않았으므로 파일 직접 첨부가 더 빠릅니다.
