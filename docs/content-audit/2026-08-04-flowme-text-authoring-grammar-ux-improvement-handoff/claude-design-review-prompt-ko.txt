[역할]
당신은 FlowMe Text Authoring의 UX 구조를 개선하고 실제로 동작하는 self-contained single-page HTML Artifact를 만드는 제품 디자이너이자 프로토타이퍼다. 단순히 예쁜 정적 화면을 만들지 말고 첨부 시나리오를 직접 재현 가능한 인터랙션으로 구현한다.

[첨부 파일의 역할]
- flowme-text-authoring-ta-test.html: 현재 동작과 정보의 전체 범위를 확인하는 기준
- desktop/mobile PNG: 현재 화면의 실제 밀도와 반응형 문제를 확인하는 기준
- review-brief-ko.md: 사용자 피드백과 독립 감사 결과
- grammar-ux-contract-v2-candidate.json: 변경하면 안 되는 문법·정렬·결과 형태 계약
- simulation-matrix-v2.json: 시뮬레이션과 인수 조건
- 선택 첨부 Claude 0729_1412 시안: 구조와 정보 위계만 참고

[중요한 디자인 경계]
1. 색감과 기본 UI 토큰은 현재 FlowMe의 절제된 밝은 톤을 유지한다. 과거 Claude 시안은 구조만 참고하며, 색·그라디언트·장식 스타일을 그대로 이식하지 않는다.
2. AI 기능은 추가하지 않는다.
3. 문법·데이터 로직은 grammar-ux-contract-v2-candidate.json을 따른다. 이해가 안 되는 값을 추정해 만들지 않는다.
4. 사용자 검증을 했다고 쓰지 않는다. 당신이 수행하는 것은 내부 디자인 시뮬레이션이다.
5. 외부 라이브러리, CDN, API, 네트워크 요청, 로그인, 영구 저장에 의존하지 않는다. 모든 예시는 HTML 안의 seed data와 in-memory state로 동작한다.

[핵심 문법]
# Flow 제목
- 기준일: 2026-08-10
## 단계
- [ ] 항목
  - 설명: 설명입니다.
  - 날짜: 2026-08-03
  - 상대 날짜: D-3
  - 자료: [안내](https://example.com)

- 표식 없는 문장은 원문 텍스트다.
- `  - 공식 속성: 값`은 바로 위 Item의 속성이다.
- `  - 미정 키: 값`과 `  - [ ] 하위 항목`은 검토 issue이며 가짜 Item을 만들지 않는다.
- UI 입력을 바꾸면 구조와 결과가 저장 버튼 없이 즉시 반영되어야 한다.

[개선해야 할 사용자 문제]
1. 속성도 `- 설명:`처럼 Markdown 목록 관계가 보여야 한다.
2. Calendar는 날짜순으로 보이되 원문은 자동 변경하지 않는다. 두 순서가 다를 때만 `입력도 이 순서로 맞추기`를 보여주고, 누르면 원문 Item 블록도 같은 순서로 바뀌며 되돌릴 수 있어야 한다.
3. `표/엑셀`은 실제 표 열과 행이라는 정체성이 보여야 하고 일반 제목 목록에서는 비활성화한다.
4. 상대 날짜는 원문에 `- 기준일: YYYY-MM-DD`가 있을 때만 Calendar로 계산한다. UI에서 기준일을 넣으면 해당 줄이 원문에 생기는 것을 즉시 보여준다.
5. 결과 형태는 항상 같은 위치의 네 슬롯이다: 캘린더 | 체크/할 일 | 표/엑셀 | 텍스트. 불가능한 결과는 사라지지 않고 disabled와 짧은 이유를 가진다.
6. `정리 메모` 대신 `텍스트`를 쓰고 `원문 그대로`와 `정리된 TXT/Markdown`을 구분한다.
7. 설명, 완료 기준, 날짜·시간·장소, 반복·조건, 링크가 선택 결과의 자연스러운 위치에 실제로 보여야 한다.
8. CSV, TSV, Markdown table 같은 기술 형식은 첫 화면에서 나열하지 않고 표 가져오기 또는 내보내기 메뉴 안에서만 보여준다.
9. 사용자는 순서 번호를 입력하지 않는다. UI가 작성 순서로 번호를 보여준다.
10. `나눈 항목`은 `항목 구조`로 바꾼다. 기본은 읽기 요약이고 이동·분리·병합은 `구조 수정` 뒤에 둔다.

[추가 UX 원칙]
- 첫 화면의 주 작업은 입력 -> 항목 구조 확인 -> 결과 확인 -> 복사/저장/내보내기다.
- 긴 설명은 항상 기본 숨김이며 작은 `?` 버튼 또는 contextual popover로 연다.
- 27개 전체 예시는 QA/demo 모드에 두고, 기본 화면은 단일 `예시 불러오기`와 대표 예시만 보여준다.
- 내부 용어 SourceRow, projection, preflight, 27/27 통과는 사용자 화면에 보이지 않는다.
- `체크`와 `할 일`을 동급 버튼 두 개로 중복하지 않는다. Phase 1에서는 `체크/할 일` 하나로 표현하고, 내보내기 안에서 외부 할 일 형식을 선택한다.

[필수 인터랙션]
1. textarea 수정 즉시 구조와 결과 업데이트
2. 예시 선택: 기본 문법, 날짜 역순, D-Day 기준일 없음, 링크·상세, 원본 표
3. 고정 결과 형태 버튼의 enabled/disabled 전환과 위치 불변
4. 기준일 UI 입력 -> 원문 `- 기준일:` 줄 생성 -> Calendar 활성
5. 날짜 역순 -> Calendar 오름차순 + `입력도 이 순서로 맞추기` -> 원문 재정렬 + undo
6. 구조 수정 열기/닫기
7. `?` 문법 도움말과 비활성 이유 도움말
8. 원문 그대로 복사와 정리된 텍스트 복사 차이
9. 링크 클릭 가능한 미리보기
10. 모바일 입력/구조/결과 탭 전환과 끝까지 스크롤

[레이아웃]
Desktop 1440:
- 상단: 예시 불러오기, 작은 문법 ?
- 본문: 입력 / 항목 구조 / 결과의 3열
- 항목 구조는 가장 좁고 결과는 실제 미리보기를 읽을 수 있는 폭
- 결과 형태 네 버튼은 panel 상단 고정 위치

Tablet 1024:
- 입력+구조 두 열, 결과는 아래 또는 명확한 2-pane 재배치
- 가로 overflow 없음

Mobile 390 및 360:
- 입력 | 구조 | 결과 고정 탭
- 현재 탭만 표시
- 390x600에서도 각 탭 마지막 행동까지 도달
- 하단 CTA가 콘텐츠를 가리지 않음
- 구조 수정 도구는 본문 안에서 길게 펼치지 말고 drawer/sheet로 열어 Item 영역을 보존
- 빠른 예시 링크 여러 개를 단일 예시 선택기로 합치고 저장/복사 문구가 잘리지 않게 함

[시각 품질]
- 과도한 카드, 배지, 섹션 제목, 반복 설명을 제거한다.
- heading hierarchy와 whitespace로 구조를 만들고 경계선은 최소화한다.
- help는 ?에 숨기되 focus, ESC, 바깥 클릭, 터치로 닫힌다.
- disabled는 흐리기만 하지 말고 이유를 접근 가능한 이름으로 제공한다.
- 표/엑셀 미리보기는 실제 표처럼 보이게 하고 모바일에서는 가로 스크롤 또는 행 카드 대안을 선택해 일관되게 적용한다.
- focus-visible, label, aria-expanded, aria-controls를 포함한다.

[내부 시뮬레이션]
최소 다음을 직접 확인하고 결과표를 작성한다.
- 1440x900: 기본 문법, 날짜 역순과 원문 정렬, 링크 상세
- 1024x768: pane 재배치와 overflow
- 390x844: 탭 전환, 도움말, 기준일 반영, 결과 형태 위치
- 390x600와 360x640: 각 탭 마지막 요소 도달
- 844x390: 가로 모바일 스크롤
- plain text가 Item으로 보이지 않음
- 일반 목록에서 표/엑셀 disabled
- 기준일 없는 D-Day에서 Calendar disabled
- console error, page error, failed external request 0

[반환물]
1. 전체 self-contained single-page HTML Artifact
2. 변경 요약: 사용자 피드백 1~10 각각 무엇이 달라졌는지
3. 시뮬레이션 결과표: viewport, scenario, expected, observed, pass/fail
4. 남은 결정: 구현 계약이 필요한 항목만, 시각 취향 질문은 최소화
5. 적용하지 않은 제안과 이유

HTML 안에 테스트용 `시나리오` 메뉴를 두되 기본 사용자 화면에는 QA 정보가 보이지 않게 `데모 모드`로 분리하라. 결과물을 축약 코드 조각이 아니라 바로 저장해 열 수 있는 완전한 HTML로 제공하라.
