FlowMe는 도구를 복제하지 않고, 맞는 내보내기 형태를 고른다

이 문서는 Google Calendar, Apple Calendar, Google Sheets, Notion, Todoist를 Stage 0 export target으로 분류하고, FlowMe가 너무 빨리 calendar, sheet, workspace, task app, automation platform을 만들지 않게 경계를 세운다.

제품 규칙: flow-export-destination-selector 기본값: portable artifact 먼저 금지: 계정 연동·클론·자동화
Calendar

.ics 우선

D-day, 예약, 점검, 갱신, 연습 세션처럼 날짜/시간이 핵심이면 calendar artifact로 보낸다.

Sheet

CSV/XLSX-ready rows

재고, 비교, 진행률, 메뉴, 상태표처럼 행과 열이 핵심이면 sheet row로 만든다.

Memo / Checklist

맥락과 실행 상태 분리

소스 링크와 주의는 memo로, 실행 중 체크 상태는 FlowMe 내부 체크리스트로 유지한다.

1. 결정 요약

Stage 0의 질문은 “어느 계정을 연결할까?”가 아니라 “사용자가 이미 쓰는 도구로 옮길 산출물 모양이 맞는가?”다. 그래서 FlowMe는 먼저 파일과 복사 가능한 구조를 제공한다.

Calendar events

.ics 또는 필요한 경우 destination-specific CSV.

Sheet rows

CSV/XLSX-ready data로 행과 열을 분명하게 보낸다.

Memo/source notes

Markdown/plain text로 source URL, caution, completion criteria를 함께 보낸다.

Internal checklist

실행 중 완료 상태가 중요한 경우 FlowMe check state와 copyable text로 둔다.

Todoist CSV

사용자가 task manager 목적지를 명시할 때만 프로젝트 CSV를 고려한다.

Notion Markdown/CSV

workspace replacement가 아니라 handoff/archive 용도로만 사용한다.

2. 공식 소스 스냅샷

2026-06-08에 확인한 공식 import 문서 기반 비교다. 현재 최신성 재확인이 아니라 당시 판단 근거를 한국어 HTML로 재구성한 것이다.

플랫폼 Import 신호 FlowMe 해석
Google Calendar 컴퓨터에서 .ics와 .csv를 import한다. CSV header는 영어가 필요하고 반복 이벤트나 guest/conference 정보가 제한될 수 있다. 날짜가 있는 one-off event, D-day 일정, reminder의 기본 목적지. 반복성이 중요하면 .ics 우선.
Apple Calendar .ics events를 import/export한다. calendar archive import는 현재 calendar data를 대체할 수 있다. 유용한 calendar 목적지지만 archive-level import는 피하고 single-event/calendar-file handoff를 선호한다.
Google Sheets File > Import로 upload file을 가져오고 replace/append를 선택할 수 있다. inventory, comparison, progress, menu, status row의 기본 목적지.
Notion Markdown/text, CSV, HTML, PDF, ZIP, app data를 desktop/web에서 import한다. CSV는 database를 만들 수 있다. 강한 workspace 경쟁자이자 memo/database 목적지. FlowMe는 clean Markdown/CSV만 넘기고 workspace가 되지 않는다.
Todoist project CSV는 task, section, note, date, timezone, duration, deadline fields를 import한다. project checklist 목적지로는 유용하지만 FlowMe가 generic task app이 되면 안 된다.

4. 네 단계 선택 흐름

flow-export-destination-selector는 사용자가 플랫폼 이름을 말하기 전에 artifact의 주된 일을 고르게 한다.

Step 1

Artifact main job 선택

date, row/table, memo/source note, checklist state 중 primary output을 고른다.

Step 2

목적지별 format 선택

.ics, CSV/XLSX, Markdown/plain text, Todoist CSV, Notion Markdown/CSV 중 고른다.

Step 3

Source context 보존

source URL, warning, completion criteria를 description, memo, row note에 포함한다.

Step 4

Integration out of scope

portable file/copy shape만 제공하고 OAuth, sync, workspace automation은 제외한다.

5. 경쟁서비스 경계

플랫폼 배울 점 FlowMe 입장 지금 만들지 않을 것
Notion 사용자는 재사용 page, template, database를 좋아한다. 필요할 때 Flow artifact를 Notion-ready로 만든다. workspace builder, page editor, database automation, Notion AI competitor
Todoist task, project, due date, recurring task가 강하다. task-first Flow에만 structured task CSV를 export한다. generic task manager, task inbox, recurring-task engine
Google/Apple Calendar 사용자는 이미 calendar reminder를 신뢰한다. 정확한 calendar artifact를 생성한다. calendar replacement, account sync, scheduling assistant
Google Sheets rows, inventory, progress 관리에 익숙하다. clean sheet rows를 생성한다. spreadsheet editor, formula engine, live data connector
Zapier / Make 자동화는 나중에 friction을 줄일 수 있다. 미래 platform layer로 둔다. export behavior가 증명되기 전 automation builder

6. 제품 결정

이 문서는 public route가 아니라 A- product rule이다. 모든 source-to-Flow 후보가 export preview를 만들 때 같은 기준을 쓰게 하는 것이 목적이다.

Do not build: Notion/Todoist/Google Calendar/Apple Calendar/Google Sheets account integration, OAuth/account connection, recurring-task/full calendar engine, spreadsheet editor/formula layer, Notion-like workspace builder, Zapier/Make-style automation.

8. 2026-06-09 제품 규칙 반영

이후 flow-export-destination-selector는 재사용 제품 규칙으로 승격되었다. 공개 라우트나 `/content-flows` 후보가 아니라, export destination fit을 판단하는 기준이다.

Product rule

Yes. 후보 리뷰에서 산출물의 주된 일로 목적지를 고른다.

Public route

No. 사용자에게 별도 Flow로 판매할 대상이 아니다.

Integration

No. OAuth/account integration, persistent sync, automation builder는 제외한다.
