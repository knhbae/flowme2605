2. 사용자 여정 평가

Flow 찾기 / URL-first

강한 핵심 entry. 사용자는 URL을 붙여 기존 준비를 찾고, 없으면 비실행 후보로 남긴다. AI 생성기가 아니라 lookup-first action compiler로 유지해야 한다.

public `/f` 저장

공유 진입 저장 shell로 안정화됐다. 저장/setup path가 primary이고 export와 browse는 보조다. 4탭 shell로 강제 편입하지 않는다.

My Flow / Calendar

실행 허브와 dated execution tab의 역할이 분리됐다. 모바일 기준은 좋고, wide layout은 방향 확정 뒤 투자할 영역이다.

Export 가치

calendar/sheet/memo/checklist로 가져가는 능력은 여전히 핵심 가치다. FlowMe를 기존 도구와 경쟁시키기보다 보완하는 방향을 유지한다.

Creator / Studio

`/u/my-flow-studio`는 secondary surface로 남겨야 한다. 실제 콘텐츠가 있는 profile 검증 전에는 핵심 축으로 승격하지 않는다.

Evidence / Guardrail

많이 좋아졌지만 수치 자체가 목표가 되면 안 된다. route-evidence는 제품 방향 결정을 돕는 보조 증거다.

3. 유지할 기준선

제품/IA

  • 4탭 IA: Home / Flow 찾기 / Calendar / My Flow
  • Home은 promise, `/flows`는 catalog + URL-first
  • public `/f/[slug]`는 공유 저장 shell
  • My Flow는 saved execution hub
  • Calendar는 dated Step의 global execution tab

Guardrail / route tier

  • normal route guardrail 0
  • visible Markdown 0, raw ISO visible text 0
  • candidate user copy internal hit 0
  • `/restart`는 release-preview
  • `/flow-lab`는 internal-console, user nav link 0
