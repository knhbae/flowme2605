# P24-00B1 Detailed Goal

## 목표

실제 신규 사용자 2명이 설명 없이 FlowMe의 첫 가치 연결을 수행하는지 관찰한다. P1은 이사일 중심 Flow, P2는 날짜 없는 차량 점검 Flow를 사용한다. 두 세션은 인터페이스 선호 조사가 아니라 정확성, 발견성, 행동 범위 이해를 검증한다.

## 실행 순서

### 1. 사전 준비

- production URL과 baseline SHA를 기록한다.
- 실제 참가자마다 새 브라우저 profile 또는 새 localStorage를 사용한다.
- 가상 날짜와 가상 상황만 사용한다.
- 녹화 여부와 익명화 방식을 먼저 합의한다.
- 진행자는 과업 문장만 읽고 버튼명과 위치를 말하지 않는다.

### 2. P1-S1 기준일 역산형

- 시작 route는 `/`이다.
- 홈에서 이사 준비 Flow를 발견한다.
- `2026-08-20`을 이사일로 이해하고 지정한다.
- My Flow에 저장한다.
- 저장 직후 다음 할 일과 반영 날짜를 말로 설명한다.
- 저장 후 이사일 수정入口를 찾아 하루 바꿨다가 원래 날짜로 돌린다.
- 완료 하나를 체크한 뒤 잘못 눌렀다고 가정하고 취소한다.
- 전체 Flow export를 열기 전에 포함 범위를 예측한다.

### 3. P2-S1 날짜 없는 체크형

- 시작 route는 `/f/vehicle-inspection-prep`이다.
- 차량 점검 public Flow를 처음 본다.
- 저장 전 preview와 저장 후 완료 상태의 차이를 말한다.
- My Flow에 저장한다.
- 날짜 없는 할 일을 Calendar에서 발견한다.
- 한 항목을 `2026-07-21`에 배치한다.
- 완료 후 되돌린다.
- 선택 항목 export를 열기 전에 포함 범위를 예측한다.

### 4. 세션 직후

- 결과, 첫 행동 시간, 잘못된 경로, 힌트 수, 정확한 발화를 기록한다.
- 사용자가 설명을 읽지 않은 곳과 설명 없이는 이해하지 못한 곳을 분리한다.
- 신뢰 오류가 있으면 `blocking`으로 표시하고 다음 참가자 모집을 중단한다.
- 취향 의견 하나만으로 UI를 바꾸지 않는다.

### 5. 파일 반영

- 실제 기록을 참가자별 기록지에 넣는다.
- evidence 경로를 세션 등록부에 연결한다.
- 실제 완료 세션만 카운트한다.
- 두 세션 후 P24-00B1 결과를 `continue / fix_then_continue / stop`으로 판정한다.

## 완료 조건

- 실제 관찰 세션 `2 / 15`
- P1-S1, P2-S1 기록지 완성
- 실제 발화와 행동 근거 존재
- open Blocking `0`, 또는 다음 모집이 중단되고 수정 slice가 생성됨
- P24-00B2로 진행할지 근거 기반 판단 가능
