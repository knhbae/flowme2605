FlowMe 플랫폼 UX 1~4번 슬라이스 리포트

목표는 저장한 Flow가 많아지고 제작자가 내용을 업데이트하는 상황에서도 사용자의 My Flow가 캘린더/투두 앱 수준의 단순함을 유지하는지 확인하는 것이다. 이번 리포트는 사용자용 화면이 아니라, 리서치 근거와 구현·시뮬레이션·검증 결과를 분리해서 기록한 리뷰 문서다.

Step = 최소 저장 단위 Item = 체크/메모/text fallback creator/user 분리 localStorage PoC

이번에 다룬 4개 축

구현

1. Step 일정/할일 필드

날짜, 시간, 반복 preset, 장소, 메모, 링크를 Step detail 안에 둔다. 첫 화면에는 노출하지 않는다.

구현

2. 제작자 초안 → 발행 표시

초안 저장과 로컬 발행 표시를 분리했다. 실제 서버 공개 발행은 아직 아니다.

구현

3. 업데이트 적용 정책

새 snapshot 적용 시 기존 체크/메모를 보존하고, 누락 child Flow만 추가한다.

구현

4. 대량 관리 UX

Flow 목록에서 숨김/복귀를 지원하되 Today와 Calendar 실행 항목은 사라지지 않는다.

레퍼런스에서 가져온 판단 근거

영역 확인한 패턴 FlowMe 적용 판단
Todoist subtasks 큰 작업을 작은 sub-task로 나누고, 각 sub-task를 schedule할 수 있다. Flow Map 전체보다 Step이 사용자의 실제 실행 단위가 되어야 한다.
Trello advanced checklist 체크리스트 item에도 due date가 붙고 Calendar view에서 볼 수 있다. FlowMe의 Item은 기본적으로 text fallback이지만, Step은 날짜/할일 metadata를 가질 수 있어야 한다.
Apple Reminders Smart Lists 날짜, 시간, 위치, 리스트 같은 조건으로 reminder를 모은다. 대량 관리에서는 복잡한 보드보다 검색/필터/숨김 같은 smart-list 성격이 맞다.
Thinkific course builder chapter/lesson 생성과 draft 상태가 learner 진행 화면과 분리된다. 제작자 source-row 편집과 사용자 My Flow 실행은 화면·상태·문구를 분리해야 한다.

레퍼런스는 기능 복제 기준이 아니다. FlowMe 기준은 계속 "원컨텐츠 → 실행 가능한 Step → 사용자의 기존 도구/내 Flow에서 실행"이다.

구현 결과

축 변경 파일 현재 동작 남은 경계
Step fields components/flow/AppClient.tsx Step detail에서 날짜, 시간, 반복 preset, 장소, 메모를 저장한다. 날짜 변경은 My Flow 캘린더에 반영된다. My Flow에서 편집한 값을 ICS/export에 다시 반영하는 것은 아직 후속 작업이다.
Creator publish marker SourceBackedFlowMapCreatorEditor.tsx 초안 저장 후 flow:map:published-local:{mapId}에 로컬 발행 표시를 남긴다. 서버 공개 버전 발행, 계정 저장, 승인 workflow는 아직 아니다.
Update apply components/flow/AppClient.tsx 업데이트 적용 시 snapshot을 새 기준으로 맞추고, 새 child Flow가 누락됐으면 저장 목록에 추가한다. 삭제된 row 처리, row-level conflict, cross-device update history는 남아 있다.
Large inventory components/flow/AppClient.tsx Flow inventory에서 숨김/복귀를 지원한다. 숨겨도 Today와 Calendar에는 남는다. 계정 기반 archive, bulk edit, saved map 단위 hide는 후속 작업이다.

사용자 시뮬레이션

Persona A

이사 D-30 지도를 저장한 사용자

  • 이사일을 넣고 전체 지도를 저장한다.
  • 첫 Step을 열어 날짜를 조정하고, 시간·장소·메모를 추가한다.
  • 다시 My Flow에 들어오면 바꾼 날짜의 캘린더 셀에서 Step을 찾을 수 있다.
  • 판정: 캘린더/투두 앱 수준의 정보량으로 유지된다.
Persona B

영유아 검진 지도를 저장한 보호자

  • 아이 생년월일을 입력하고 검진/접종 지도를 저장한다.
  • 공식 일정이 변경됐다는 안내를 Flow 탭에서 본다.
  • 변경 내용을 보고 새 기준으로 표시한다.
  • 기존 체크와 메모는 유지되고, 새 child Flow만 추가된다.
Persona C

여러 Flow를 저장한 사용자

  • Flow 목록이 길어져 자주 보지 않는 Flow를 목록에서 숨긴다.
  • Today/Calendar에서 날짜가 있는 Step은 계속 볼 수 있다.
  • 숨김 필터에서 다시 목록에 보이게 할 수 있다.
  • 판정: 정리 기능이 실행 기능을 해치지 않는다.
Persona D

중1 수학 지도를 관리하는 제작자

  • source row가 어떤 Step/Item fallback으로 바뀌었는지 확인한다.
  • Step 제목, 저장 위치, 원문 링크, fallback item을 고친다.
  • 초안을 저장하고 로컬 발행 표시까지 남긴다.
  • 남은 점: 실제 공개 버전 발행은 아직 서버 모델이 필요하다.

UX 평가

기준 평가 근거
User Need Fit 4/5 저장 후 실행, 제작자 편집, 업데이트 관리, 대량 목록 정리가 실제 플랫폼 사용 흐름에 연결된다.
Execution Clarity 4/5 Step 상세에서 날짜/시간/메모를 고치고, Flow 목록에서 숨김/복귀를 수행할 수 있다.
Portability 3/5 Step-level metadata는 생겼지만 My Flow 편집값을 export/ICS에 재생성하는 연결은 아직 없다.
Cognitive Load 4/5 새 필드는 Step detail 안에 숨겼고, 대량 관리도 Flow 목록에만 둬 Today/Calendar를 무겁게 만들지 않았다.
Source/Safety 4/5 공식/민감 지도는 review-before-apply 정책을 유지하고 자동 삭제/변경을 피한다.
