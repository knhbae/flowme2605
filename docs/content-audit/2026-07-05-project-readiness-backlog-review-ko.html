FlowMe 프로젝트 완성도 및 출시 백로그 리뷰

2026-07-05 현재 문서, 서비스 구조, 최근 백로그, 테스트 변경, 작업트리 상태를 기준으로 본 스냅샷이다. 점수는 실제 사용자 검증 점수가 아니라, 현재 제품/문서/자동 QA 근거로 판단한 출시 준비도다.

기준 브랜치: codex/flowme-uxui-second-loop 상태: 내부 알파 / 제품 PoC 강함 / 공개 출시 보류 핵심 방향: URL-first, lookup-first, export-first 주의: 실제 사용자 행동 검증 아님

한 줄 판정

FlowMe는 “아이디어나 화면만 있는 상태”는 아니다. 4탭 IA, source-backed Flow, My Flow, Calendar, export, 테스트/훅/CI가 이미 있다. 하지만 최소 출시 MVP는 아직 아니다. 가장 큰 빈칸은 첫 유입 경로(URL 입력/기존 Flow 재사용), 사용자에게 바로 줄 수 있는 export pack, 실사용 evidence, 정리된 릴리스 백로그다.

완성도 스냅샷

프로젝트 전체

72%

제품 구조, 문서, PoC, 테스트 기반은 충분히 쌓였다.

최소 사용 MVP

62%

저장 후 실행은 보이지만 첫 유입과 재사용 루프가 아직 얇다.

공개 출시 준비

40%

QA는 강해졌지만 사용자 검증, 추적, 권리/신뢰, 릴리스 정리가 부족하다.

실사용 검증

15%

문서와 자동 QA는 많지만 관찰된 사용자 행동 데이터는 아직 낮다.

현재 단계

강함

리서치/기획 PoC

URL-first, 생산성 도구 연결, source scout, creator/community loop가 문서화되어 있다.

강함

제품 PoC

4탭 IA, public route, Flow 찾기, My Flow, Calendar, source-backed map이 실제 앱 구조로 존재한다.

현재

최소 MVP

사용자가 설명 없이 시작할 URL 입력/기존 Flow 재사용/export pack이 아직 제품 루프로 묶이지 않았다.

다음

Closed Beta

5-8개 canary 콘텐츠와 3-5명 첫 사용 세션으로 저장/export/check/재방문을 봐야 한다.

보류

Public Launch

검증 없는 social proof, AI-first 생성, 권한 불명확한 source import, 불안정한 dirty branch 상태에서는 보류.

P0 출시 백로그

우선순위 작업 현재 상태 Done when 근거
P0 릴리스 보드 단일화와 dirty worktree 정리 문서/테스트 수정 6개와 Claude 산출물/리서치 파일 다수가 untracked 상태다. 출시 후보 브랜치가 커밋 단위별로 나뉘고, 임시 zip/후보 문서의 처리 방침이 정해진다. git status -sb, 백로그 workboard
P0 URL 입력 -> canonical lookup -> 기존 Flow 재사용 thin slice 방향은 결정됐지만 제품 루트로 구현되지 않았다. URL 입력, hit/miss, 기존 Flow 재사용, 옵션 변경, export preview가 한 화면 흐름으로 동작한다. Flow 활용 입구 백로그
P0 Export pack: ICS, Markdown, clipboard, table/CSV export 모듈과 Step export는 있으나 “출시용 pack”으로 묶인 QA 기준이 부족하다. 대표 3개 콘텐츠에서 Calendar/Todo/Markdown/Sheet 결과물이 각각 자연스럽게 나온다. 생산성 도구 연결성 리서치, lib/flow/export.ts
P0 My Flow 저장 후 첫 실행 루프 확정 내부 QA와 E2E는 강하다. 다만 URL/memo에서 들어온 Flow까지 같은 기준으로 수렴하는지 봐야 한다. 저장 -> 오늘/전체 -> Step detail -> 수정 -> export 재생성 -> Calendar 확인이 모바일에서 설명 없이 통과한다. My Flow v2 spec, tests/e2e/flow-mvp.spec.ts
P0 Canary 콘텐츠 5-8개만 앱 적용 상위 후보는 정리됐다. 앱 적용은 아직 별도 배치로 쪼개야 한다. source row가 확인된 5-8개만 seed handoff -> 앱 적용 -> 모바일 저장/export 회귀 검증을 통과한다. creator/community loop review
P0 Source/version/trust 표시 source/risk 분리 원칙은 문서와 일부 UI에 있다. URL canonical, 버전, 검토일, 내 fork 관계는 더 필요하다. 사용자가 “원문 근거”, “내가 바꾼 부분”, “마지막 검토일”, “AI fallback 여부”를 혼동하지 않는다. DECISIONS, source-to-Flow gate
P0 첫 사용자 evidence 수집 자동 테스트와 브라우저 QA는 많지만, 실제 사용 세션 기록은 출시 판단 근거로 부족하다. 3-5명 세션에서 URL/저장/export/check/재방문/수정이 어디서 막히는지 기록된다. v0.2 Evidence Capture, quality gate

MVP 범위 재정의

최소 출시 MVP에 반드시 포함

  • 사용자가 URL을 붙여넣거나 대표 콘텐츠를 고르는 첫 행동
  • 중복 URL이면 AI 생성보다 기존 Flow 재사용을 먼저 보여주는 흐름
  • 시작일/목표일/간단 옵션 변경
  • Calendar, Markdown/메모, checklist, table 계열 export
  • 내 Flow 저장 후 오늘/전체/캘린더에서 이어서 보는 루프
  • 원문 링크, 주의 정보, 마지막 검토일, 내 수정 여부 표시
  • 사용자 행동을 과장하지 않는 feedback/evidence 기록

최소 출시 MVP에서 빼도 되는 것

  • OAuth 기반 Google/Todoist/Notion 직접 연동
  • Supabase/account-backed 저장소. 단, cross-device beta를 하려면 별도 판단 필요
  • creator marketplace, 결제, token, asset exchange
  • Motion/Reclaim식 full auto-scheduling
  • native Expo 앱, push 알림, app store 배포
  • 근거 없는 사용량, 리뷰 수, creator 인증 표시
  • 무거운 editor/diff/version graph

주요 리스크

리스크 심각도 왜 문제인가 처리
문서와 백로그가 너무 많고 릴리스 단위가 흐림 High 실무에서는 “다음 PR이 무엇인가”가 보여야 하는데, 현재는 연구/아이디어/앱/QA가 흩어져 있다. 릴리스 보드 하나로 P0/P1/P2, done-when, 검증 명령을 묶는다.
URL-first가 아직 문서 중심 High 현재 서비스의 가장 설득력 있는 유입 모델인데, 제품에서 바로 체험하기 어렵다. mock data라도 URL hit/miss thin slice를 먼저 만든다.
실사용 검증 부족 High 자동 QA 통과와 사용자 가치 검증은 다르다. 3-5명 closed beta 관찰 세션과 event checklist를 만든다.
콘텐츠 권리/source import 경계 Medium creator/video/template 후보는 유입 가치가 크지만 가져오면 안 되는 원문 자산이 섞일 수 있다. 원문 링크/요약/실행 row만 쓰고 이미지, PDF, 유료자료, 전문 복제는 제외한다.
My Flow가 장기 workspace처럼 커질 위험 Medium Obsidian/Notion 방향은 매력적이지만 너무 빨리 만들면 source-to-execution 가치가 흐려진다. 초기에는 export-first와 저장 후 continuation에 한정한다.

권장 작업 순서

이번 주

  • dirty worktree를 research/docs/test 단위로 나눠 정리
  • URL-first thin slice spec 생성
  • export pack QA 샘플 3개 선정
  • Canary seed 5-8개만 확정

다음 개발 배치

  • URL 입력 route 또는 Home 진입 모듈 구현
  • lookup hit/miss 상태와 reuse/edit/fork copy 구현
  • Calendar/Markdown/checklist/table export pack 정리
  • My Flow 저장 후 Step 수정/재export smoke test

출시 전

  • 3-5명 첫 사용 관찰
  • source/trust/privacy 문구 최종 점검
  • 모바일/데스크톱 E2E와 브라우저 QA
  • 배포 URL, 에러/empty/loading 상태, PR/CI 녹색 확인
