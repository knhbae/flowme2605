API 준비도는 통합 허가가 아니라 Stage 0을 지키는 게이트다

이 문서는 Google Calendar, Google Sheets, Notion, Todoist, Zapier, Make가 기술적으로 가능한지를 보는 동시에 FlowMe가 지금 계정 연결, 토큰 저장, 자동화 플랫폼으로 넘어가면 안 되는 이유를 정리한다. 결론은 단순하다. 반복 사용과 import friction이 증명되기 전까지는 portable export가 기본값이다.

제품 규칙: integration-readiness-gate Stage 1 후보: Calendar direct save · Sheets append Stage 0 금지: OAuth·토큰·웹훅·동기화
Default

stage0_export_only

모든 목적지는 사용자가 반복적으로 같은 산출물을 내보낸다는 증거가 생기기 전까지 파일/복사 기반으로 둔다.

Light Integration

Calendar와 Sheets만 선행 후보

스키마가 좁고 import friction을 관찰하기 쉬운 두 목적지만 Stage 1 후보로 남긴다.

Boundary

자동화 플랫폼이 되지 않기

Notion/Todoist/Zapier/Make는 지금 유용해 보여도 workspace, task inbox, trigger/action 비용이 크다.

1. 결정 요약

API 문서가 존재한다는 사실은 구현 승인과 다르다. FlowMe는 먼저 사용자가 실제로 어느 목적지로 반복 export하는지 확인하고, 파일/복사 import가 병목이라는 증거가 생긴 뒤에만 직접 저장을 검토한다.

지금의 기본값

.ics, CSV/XLSX-ready rows, Markdown/CSV, Todoist CSV 같은 portable artifact를 먼저 제공한다.

Stage 1 후보

Google Calendar direct save와 Google Sheets direct append는 반복 import friction이 증명된 뒤에만 연다.

미래 플랫폼

Notion, Todoist, Zapier, Make는 요구가 명확해질 때까지 future_platform으로 둔다.

거절 기준

계정 관리, credential handling, 자동화 빌더, 외부 플랫폼 복제에 가까워지면 지금은 만들지 않는다.

2. 공식 소스 스냅샷

2026-06-08에 확인한 공식 API/플랫폼 문서 기반 비교다. 이 HTML은 당시 판단 근거를 한국어로 읽기 쉽게 정리한 것이며, 오늘 기준 최신 문서 재검증은 아니다.

플랫폼/API API 신호 FlowMe 해석
Google Calendar API 이벤트 생성은 calendar ID와 events insert 호출, calendar 관련 authorization scope가 필요하다. Stage 1 후보 `.ics` import friction이 반복 증명된 뒤 검토한다.
Google Sheets API spreadsheet ID, range, value input option, Drive/Sheets OAuth scope로 행을 append한다. Stage 1 후보 sheet-first Flow의 row schema가 안정된 뒤 검토한다.
Notion API page/database/data source 관리, OAuth 2.0, Insert Content capability가 얽힌다. Future platform Notion-ready Markdown/CSV handoff가 먼저다.
Todoist API tasks, projects, reminders, OAuth token을 다루며 due date와 deadline 동작이 분리된다. Future platform task-manager 수요가 검증되기 전에는 CSV import면 충분하다.
Zapier Platform private-data integration은 인증이 필요하고 app connection이 유지된다. Future platform FlowMe trigger/action semantics가 안정된 뒤의 자동화 계층이다.
Make Webhooks/API custom webhook URL, queue, 즉시/예약 처리, reject/rate-limit 같은 운영 책임이 생긴다. Future platform event payload와 replay/error handling이 가치 있을 때만 검토한다.

3. 여섯 개 준비도 게이트

직접 통합은 아래 여섯 항목이 모두 증명될 때만 stage0_export_only에서 stage1_light_integration으로 이동할 수 있다.

반복 목적지 사용

사용자가 같은 산출물 유형에 같은 외부 도구를 반복 선택한다.

Import friction

파일/복사 import가 실제 병목이라는 관찰 증거가 있다.

안정된 스키마

calendar event fields, sheet columns, task fields가 후보마다 흔들리지 않는다.

권한 명확성

사용자가 FlowMe가 요청하는 계정 접근 범위를 정확히 이해한다.

되돌릴 수 있음

사용자가 외부 도구에서 생성 항목을 찾고, 수정하고, 삭제할 수 있다.

출처/안전 경계 이동

source URL, caution, completion criteria가 통합 산출물에도 함께 간다.

4. 준비도 매트릭스

목적지 현재 Stage 0 행동 API 가능성 결정 상태 열 수 있는 조건
Google Calendar .ics 또는 Google Calendar CSV export Calendar API event 생성 stage1_light_integration 사용자가 반복적으로 `.ics`를 import하고 direct save를 요청할 때
Apple Calendar .ics handoff 이 로드맵에서는 broad server-side account integration 없음 stage0_export_only 계속 `.ics` 유지, native/mobile integration은 지금 추적하지 않음
Google Sheets CSV/XLSX-ready row export Sheets API로 rows append stage1_light_integration row schema가 안정되고 같은 sheet append가 반복될 때
Notion Markdown/CSV workspace handoff Notion API page/database creation future_platform Notion이 지배적 목적지가 되고 page/database schema가 안정될 때
Todoist task-first Flow에 한해 Todoist-compatible CSV Todoist API task/project/reminder 생성 future_platform task-manager demand가 증명되고 FlowMe가 task inbox가 되지 않을 수 있을 때
Zapier 자동화 없음, export/copy only authenticated trigger/action app future_platform stable event types와 cross-app automation 수요가 있을 때
Make 자동화 없음, export/copy only webhook/scenario integration future_platform stable payload와 webhook replay/error handling을 감당할 가치가 있을 때

5. 지금 만들지 않을 것

이 문서의 실용적 가치는 “가능한 통합 목록”보다 “아직 만들지 않을 통합 경계”에 있다.

계정 연결과 credential 저장

OAuth/account connection, token, refresh token, API key, spreadsheet ID, Notion page ID, Todoist project ID를 Stage 0에 저장하지 않는다.

지속 동기화

calendar, sheet, task, workspace의 persistent sync를 만들지 않는다.

복제 제품

generic task inbox, spreadsheet editor, formula layer, Notion-like workspace/database builder를 만들지 않는다.

자동화 빌더

Zapier/Make action builder, arbitrary Flow event webhook endpoint, automation credential storage를 만들지 않는다.

7. Phase 5 압축

후보 사용자 순간 자연 산출물 Stage 0 행동 결정
Calendar direct save 날짜가 있는 Flow event를 반복 import함 calendar event .ics export, friction 측정 Stage 1 후보
Sheet direct append Flow row를 같은 sheet에 반복 append함 sheet row table CSV/XLSX export, friction 측정 Stage 1 후보
Notion page/database creation Flow note/row를 workspace에 넣고 싶어 함 Markdown/CSV handoff Markdown/CSV export Future platform
Todoist task creation Flow tasks를 task manager로 보내고 싶어 함 Todoist CSV CSV export Future platform
Zapier/Make automation Flow event가 앱 action을 trigger하길 원함 webhook/action payload 자동화 없음 Future platform

8. 2026-06-09 제품 규칙 반영

이 매트릭스는 이후 integration-readiness-gate라는 재사용 제품 규칙으로 승격되었다. 공개 라우트, `/content-flows` 후보, 실제 통합이 아니라, 앞으로 통합 요청을 심사할 기준이다.
