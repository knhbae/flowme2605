My Flow 저장 후 실행 관찰 키트

목표는 UI를 더 붙이는 것이 아니라, 저장한 Flow가 많아져도 사용자가 오늘 실행, 체크, 메모, Flow 찾기로 자연스럽게 이동하는지 확인하는 것이다. 이 문서는 진행자용이며, 사용자 화면에는 노출하지 않는다.

관찰 질문

사용자가 스스로 찾는가

1개 저장전역 탭 없이 바로 실행할 수 있는가.
4개 저장오늘 할 일을 먼저 열고, 다른 Flow는 필요할 때만 찾는가.
8개 저장Flow 찾기와 오늘 실행의 차이를 이해하는가.
20개 이상전체 목록보다 검색/전체 펼침을 적절히 쓰는가.

관찰 렌즈

Apple/Galaxy/Toss식으로 줄일 것부터 본다

상태유지할 UI먼저 의심할 UI
1개 저장 저장됨, 오늘/밀린 항목, 필요한 체크 또는 완료 표시, 메모, 원문 링크 전역 탭, 상태판, 나중에 보기, 큰 완료 CTA, 전체 목록
4~8개 저장 Today 기본 화면, 선택 항목 상세, 필요할 때 여는 Flow 찾기 첫 화면 검색창, 상태 버튼 묶음, 카테고리 대시보드, 항상 열린 캘린더
20개 이상 짧은 초기 목록, 검색, 명시적 전체 보기, 필요할 때 여는 일정 보기 30개 전체 카드 기본 노출, row마다 완료 버튼

진행자 스크립트

설명은 최소화한다

“지금은 저장한 Flow를 내 앱에서 다시 여는 화면입니다. 화면을 보고 오늘 해야 할 일을 하나 처리해 주세요. 막히는 부분이 있으면 소리 내서 말해 주세요.”

버튼의 의미를 먼저 설명하지 않는다. 사용자가 8초 이상 멈추거나 다른 화면을 계속 찾으면 그 지점을 기록한다.

테스트 순서

4개 상태를 같은 방식으로 본다

  1. 첫 화면 해석
    사용자가 5초 안에 오늘 할 일을 말할 수 있는지 본다.
  2. 첫 클릭
    오늘 항목, Flow 찾기, 캘린더, 기타 중 어디를 먼저 누르는지 기록한다.
  3. 항목 처리
    필요한 체크 또는 완료 표시를 누르고 메모를 짧게 남기는지 본다.
  4. 다른 Flow 찾기
    저장한 Flow가 여러 개일 때 특정 Flow를 다시 찾는지 본다.
  5. 재방문 상황
    다음 날 다시 들어왔다고 가정하고 오늘 항목과 밀린 항목을 구분하는지 본다.

과제 카드

사용자에게 줄 상황

상태상황 문장기대 행동실패 신호
1개 저장 전세계약 또는 이사 Flow 하나를 저장했다. 오늘 해야 할 항목을 확인하고 체크와 메모를 남긴다. 상단 탭이나 전체 목록을 찾지 않고 바로 항목을 연다. “어디서 시작하지?”, “목록은 어디 있지?”라고 묻는다.
4개 저장 전세, 이사, 홈트, 수학 Flow가 저장되어 있다. 오늘 처리할 일을 하나 끝낸다. Today 항목을 열고, 필요하면 상세에서 체크/메모를 쓴다. 처음부터 Flow 목록을 훑거나 오늘 항목과 전체 목록을 혼동한다.
8개 저장 저장한 Flow가 꽤 쌓였다. 예전에 저장한 여권 Flow를 다시 찾는다. Flow 찾기를 눌러 검색하거나 목록에서 찾는다. Today, 캘린더, Flow 탭의 역할을 구분하지 못한다.
20개 이상 저장한 Flow가 20개 이상이다. 자동차 관련 Flow를 찾거나 이번 주 날짜 항목을 살펴본다. 초기 목록에서 바로 길을 잃지 않고 검색, 일정 보기, 전체 펼침 중 하나를 쓴다. 전체가 처음부터 필요하다고 느끼거나, 검색/일정 보기를 발견하지 못한다.

판정 기준

Blocking/High만 즉시 수정한다

등급기준대응
Blocking 사용자가 오늘 실행 항목을 찾지 못하거나, 버튼 이름과 결과를 다르게 이해한다. 즉시 UI를 줄이거나 이름을 바꾸고 같은 과제를 다시 돌린다.
High 실행은 하지만 전체 목록, 탭, 상태 버튼 때문에 경로가 돌아간다. 첫 화면 노출을 줄이고, Flow 찾기나 상세 안으로 이동시킨다.
Medium 카피나 순서가 약간 헷갈리지만 사용자가 과제를 끝낸다. 다음 polish 묶음에서 수정한다.
Pass 첫 클릭이 기대 경로와 크게 다르지 않고, 체크/메모까지 60초 안에 끝낸다. 현재 구조를 유지하고 다음 저장 개수나 다른 Flow 유형으로 넘어간다.
