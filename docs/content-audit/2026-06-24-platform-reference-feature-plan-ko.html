2026-06-24 · 플랫폼 기능 기획 리서치

FlowMe는 Jira나 Notion이 아니라, 제작자 콘텐츠를 실행 가능한 개인 Flow로 바꾸는 레이어다

관련 서비스/툴을 훑어본 결론은 기능을 더 많이 붙이는 게 아니라, 제작자 편집과 사용자 실행을 분리하고 Step을 portable 실행 단위로 고정하는 것입니다.

creator source-row editor version review Step-level calendar fields update compare/apply account persistence later

기준

지금 FlowMe가 배워야 하는 것과 배우면 안 되는 것

배워야 하는 것 Jira/ClickUp/Asana처럼 큰 구조를 갖되, 사용자가 당장 해야 할 최소 단위는 명확해야 합니다. Trello/Todoist/Reminders처럼 날짜, 반복, 체크, 메모, 링크는 Step 안에 있어야 합니다.
배우면 안 되는 것 모든 계층, 필드, 뷰, 자동화, 템플릿 기능을 한 화면에 노출하면 FlowMe는 원래 의도한 “콘텐츠 실행 변환”이 아니라 무거운 프로젝트 관리 앱처럼 보입니다.

리서치 요약

서비스별로 참고한 패턴

영역 참고 서비스 패턴 FlowMe 적용
프로젝트 계층 Jira, ClickUp, Asana 큰 목표를 하위 작업으로 쪼개고, list/board/calendar/timeline 같은 view를 전환합니다. Flow Map > Flow > Step > Item은 유지하되, 사용자 화면은 Step 중심으로 단순하게 둡니다.
캘린더/투두 Google Tasks, Apple Reminders, Todoist, Trello 날짜, 반복, 체크리스트, subtasks, smart list/filter가 핵심입니다. Step은 캘린더/투두로 갈 최소 단위입니다. Item은 내부 체크리스트 또는 외부 앱 text fallback입니다.
제작자/학습 Thinkific, Moodle, Khan Academy 제작자는 chapter/lesson/completion criteria를 관리하고, 학습자는 진행률과 다음 할 일을 봅니다. 제작자 source-row 편집 화면과 사용자 My Flow 실행 화면을 분리합니다.
템플릿/자동화 Notion, Trello, Airtable 템플릿과 버튼은 반복되는 record를 만들지만, 설정이 많아지면 빈 워크스페이스가 됩니다. FlowMe는 빈 database builder가 아니라 원컨텐츠 기반 생성 도구여야 합니다.

결론

다음 구현 우선순위

P0

1. 제작자 source-row editor + version review

제작자가 원문 row가 어떤 Step/Item으로 바뀌었는지 보고, 제목/Item fallback/source URL/destination/risk/publish blocker를 수정할 수 있어야 합니다. 이게 없으면 FlowMe는 플랫폼이 아니라 내부 PoC 생성기에 머뭅니다.

P1

2. 저장 지도 update compare/apply

현재는 업데이트 notice와 숨김만 있습니다. 다음은 저장된 버전과 현재 발행본을 비교하고, 사용자가 명시적으로 적용할 수 있어야 합니다. 공식/민감 일정은 계속 review-before-apply가 기본입니다.

P1

3. Step-level calendar/task fields

Step 하나가 날짜, 시간, 반복, 장소, 메모, URL, completion state를 가질 수 있어야 합니다. 단, 첫 화면에 다 펼치지 말고 Step detail/edit 안에서 점진적으로 보여야 합니다.

P1

4. 많은 Flow 관리

검색, 필터, 숨김, 완료/보관 처리는 필요합니다. 하지만 Today와 Calendar는 실행 화면으로 유지하고, review/admin dashboard처럼 만들지 않습니다.

P2

5. 계정 저장과 실행 footprint

localStorage bridge를 DB/account persistence로 바꾸고, open → anchor → save/export → check → return 같은 행동 evidence를 남겨야 실제 검증으로 넘어갈 수 있습니다.

기능 경계

바로 만들 것과 아직 만들지 않을 것

바로 만들 것
  • creator source-row review를 editor로 확장
  • draft version과 publish blocker
  • generated Step/Item 편집
  • 사용자 화면과 제작자 화면 분리 유지
아직 만들지 않을 것
  • 마켓플레이스, 결제, 커뮤니티
  • AI 자동 발행
  • Jira식 전체 hierarchy 관리
  • Notion식 범용 database builder
  • LMS식 퀴즈/성적/수료증

실행 순서

다음 단계 작업안

  1. 제작자 editor 정보구조 설계: source row, generated Step, Item fallback, source URL, risk/readiness, blocker를 한 row에서 보이게 설계합니다.
  2. 중1 수학/영유아/이사 3개로 editor 시뮬레이션: 제작자가 무엇을 고치고 싶어 할지 확인합니다.
  3. 클릭 가능한 creator editor PoC: 실제 저장은 draft local state부터 시작합니다.
  4. 사용자 My Flow 영향 확인: draft/publish/update가 사용자 실행 화면에 섞이지 않는지 확인합니다.
  5. update compare/apply 설계: 편집된 published version이 기존 사용자 저장본에 어떻게 보이는지 연결합니다.

주의: 이 문서는 reference-informed planning입니다. 실제 사용자 행동 데이터가 없으므로 검증 완료나 상품화 완료로 표현하지 않습니다.
