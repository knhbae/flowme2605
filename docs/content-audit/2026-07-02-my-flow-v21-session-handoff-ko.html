My Flow v2.1 기준선과 다음 세션 작업

이번 세션은 저장한 Flow를 사용자가 어떻게 실행하고 관리해야 하는지 검증한 작업이다. 결론은 4탭 IA와 My Flow 실행 구조는 alpha 기준선으로 유지 가능하고, 다음 세션은 대표 콘텐츠 품질, 홈/탐색 신뢰도, 제작자 확장 구조를 다루는 쪽으로 넘어가는 것이 맞다.

현재 판정

기준선 통과 4탭 IA

홈, Flow 찾기, 캘린더, 내 Flow 구조를 유지한다. 캘린더는 글로벌 실행 탭이다.

완성도: UX alpha 기준 약 80%

기준선 통과 내 Flow 실행

Today는 실행 inbox, Flow는 저장 구조/진행률 관리로 분리했다.

완성도: UX alpha 기준 약 75~80%

다음 과제 홈/Flow 찾기

설명은 줄었지만 아직 신뢰 신호와 콘텐츠 매력이 약하다.

완성도: 서비스 후보 기준 약 55~60%

미검증 실사용 검증

현재 증거는 자동 테스트, 브라우저 시뮬레이션, 내부 UX 평가다.

실제 사용자 관찰은 별도 필요

결정된 구조

영역 현재 결정 다시 열 조건
홈 서비스 약속과 대표 시작점만 보여준다. 전체 카탈로그처럼 만들지 않는다. 콘텐츠와 사용 신호가 쌓여 실제 서비스 홈 구성이 필요해질 때.
Flow 찾기 저장할 콘텐츠를 고르는 catalog다. 대표 후보만 노출하고 검토/레거시 후보는 분리한다. 대표 콘텐츠 수가 늘고 검색, 필터, 리뷰, 사용량 신호가 필요해질 때.
캘린더 저장한 dated Step을 날짜 기준으로 실행하는 글로벌 탭이다. 저장된 dated 콘텐츠가 너무 적어 글로벌 탭으로 보이기 어렵거나, 사용자 관찰에서 중복으로 보일 때.
내 Flow / 오늘 오늘 또는 가까운 다음 Step을 먼저 보여주는 실행 inbox다. 전체 구조를 여기서 다 펼치지 않는다. 사용자가 오늘/다음 실행보다 전체 체크리스트를 먼저 찾는다는 관찰이 반복될 때.
내 Flow / Flow 저장한 Flow 구조와 진행률을 보는 공간이다. Flow를 열면 Step list, Step을 열면 detail이다. 저장 Flow가 많아져 검색, 필터, 묶음, archive가 주 사용 흐름이 될 때.

이번 세션에서 정리된 원칙

사용자 모델

  • Flow Map: 큰 구조 또는 상위 지도.
  • Flow: 사용자가 저장하고 실행할 수 있는 하나의 흐름.
  • Step: 캘린더, 투두, 시트에 저장되는 최소 실행 단위.
  • Item: Step 안의 체크, 메모, URL, 준비물, 설명 변수. 외부 앱에서는 텍스트 fallback으로 내려간다.

화면 원칙

  • 사용자 화면과 검토/기획/리포트 화면은 분리한다.
  • Step detail은 읽기/체크 우선이다. 편집, 원문, 내보내기는 보조로 접는다.
  • Today와 Flow는 같은 row/detail 원칙을 공유해도 첫 화면 목적은 달라야 한다.
  • 모바일 복잡도는 캘린더/투두 앱 수준을 크게 넘지 않는다.

탭별 최신 평가

탭 점수 판단 다음 개선
홈 3.0 / 5 중복 느낌은 줄었지만 아직 텍스트 설명형 입구다. 처음 보는 사용자가 즉시 체감할 시각적 예시와 신뢰 신호가 약하다. 대표 콘텐츠, 저장 후 결과 preview, 실제 사용 신호가 생긴 뒤 다시 설계한다.
Flow 찾기 3.3 / 5 저장 후보 catalog로 이해 가능하다. 다만 카드가 아직 '고르고 싶은 콘텐츠 마켓'보다는 '정리된 후보 목록'에 가깝다. 원문 신뢰도, 사용/리뷰 신호, 제작자 정보, 저장 결과를 카드에 더 자연스럽게 반영한다.
공개 Flow 상세 3.7 / 5 입력 복잡도와 저장 전 예상은 괜찮다. 긴 상세에서는 저장 CTA 위치와 미리보기 범위를 계속 봐야 한다. 하단 sticky CTA와 저장 전 preview 밀도를 다음 대표 콘텐츠에서 다시 검증한다.
캘린더 4.0 / 5 가장 자연스럽다. 날짜가 있는 Step을 실행하는 글로벌 탭으로 납득된다. 이벤트가 많을 때 셀 overflow, 날짜 선택 후 상세 위치, 필터 밀도를 개선한다.
내 Flow / 오늘 3.8 / 5 오늘 할 일이 없을 때 다음 할 일을 보여주는 방향이 맞다. 실행 inbox로 보인다. 지난 일정/완료 상태는 더 작게 접고, 실제 콘텐츠 3개 이상에서 반복 사용을 확인한다.
내 Flow / Flow 3.6 / 5 Flow를 열면 Step list, Step을 열면 detail이라는 구조가 맞다. 아직 많은 Flow inventory에서는 검색/필터가 필요해질 수 있다. 1개, 3개, 8개 이상 저장 시나리오를 실제 대표 콘텐츠로 다시 검증한다.

남은 백로그

P0 next 대표 콘텐츠 품질 재정리

이사, 전세, 중1 수학처럼 저장 이유가 분명한 후보만 대표로 둔다. 영유아/이유식/학습/결혼 등은 원문 기반으로 다시 판단한다.

P0 next 홈/Flow 찾기 신뢰 신호

가짜 리뷰나 사용량 없이, 원문 출처, 저장 결과, 항목 수, 업데이트일, 제작자 맥락을 어떻게 보여줄지 설계한다.

P1 Creator publish gate

제작자가 source row를 Step/Item으로 바꾸는 화면은 아직 다음 큰 축이다. 사용자 실행 화면과 분리해야 한다.

P2 대량 관리

18개 이상 Flow가 저장될 때 search, filter, archive, grouping이 필요해진다. 지금은 구조만 열어둔다.

새 세션에서 반복하지 말 것

  • 4탭 IA를 다시 처음부터 열지 않는다. 관찰 증거가 생기기 전까지는 유지한다.
  • 내 Flow 구조를 또 전면 재설계하지 않는다. 현재 기준선 위에서 실제 대표 콘텐츠를 넣어 검증한다.
  • 사용자 화면에 검토 점수, 내부 기준, source fit 같은 문구를 노출하지 않는다.
  • 원문에 없는 Step이나 Item을 UI에 맞춰 만들지 않는다.
  • 자동 QA나 Vercel preview를 실제 사용자 검증이라고 부르지 않는다.

새 세션 첫 작업

다음 세션은 UI polish보다 콘텐츠 품질과 서비스 신뢰도를 먼저 잡는 것이 맞다. 먼저 대표 콘텐츠 2~3개를 다시 고르고, 각 원문이 어떤 Flow Map / Flow / Step / Item으로 바뀌는지 기획 파일로 정리한 뒤, 홈과 Flow 찾기에 필요한 신뢰 신호를 설계한다.
