## 같은 이사 Flow의 상태별 비교

| 상태 | 화면에서 보이는 주 행동 | 보조 행동·정보 | 사용자가 구분해야 할 상태 |
| --- | --- | --- | --- |
| 저장 전 기본 | `캘린더 24개로 시작` | Flow 조정, Item 수정, 가져가기, 출처와 주의 | 아직 내 Flow에 저장되지 않은 미리보기 |
| Flow 조정 | `변경 적용` | 현재/조정 후 비교, 취소 | 전체 Flow 설정을 편집하는 중 |
| Item 수정 | `이 항목 저장` | 상세·날짜 수정, 취소 | 한 Item만 편집하는 중 |
| 저장 전 가져가기 | `형식 보기` | 결과 형식과 수량 | 저장하지 않고 외부 결과를 확인하는 중인지 여부 |
| 저장 완료 | `저장한 전체 Flow 보기` | 저장 결과 요약, 가져가기, 출처와 주의 | 내 Flow에 저장된 상태 |
| My Flow 작업 공간 | 이어서 할 일 열기·완료 | 행 메모, 전체 계획, 여러 할 일 조정, 이사일, 전체 가져가기 | 저장된 Flow를 실행·관리하는 상태 |
| My Flow Item 상세 | 할 일 수정 | 실행 메모, 메모·일정, 현재 항목 가져가기 | 저장된 Item의 실행 정보를 보는 상태 |
| My Flow 할 일 | 항목 열기·완료 | Flow 전환 | 여러 Flow의 실행 항목을 모아 보는 상태 |

## 현재 코드에서 공통인 것

- `/f`의 상단 Flow 정보와 결과 우선 화면 틀
- projection과 shape에 따른 결과 renderer
- Flow 전체 조정 패널
- Item 수정 바텀시트
- 저장 전 CTA frame
- 저장 완료 영수증
- `Flow 가져가기` disclosure

## 현재 코드에서 달라지는 것

- `/f`와 `/flow-maps`의 공개 화면 composition
- 결과 shape: calendar, checklist, sheet, memo, execution
- 준비 입력과 반복 설정
- Flow 조정에 노출되는 항목
- 저장 CTA 문구와 결과 수량
- 일부 slug의 workbench, reference rail, feedback layout, footer 노출
- My Flow와 공개 Flow의 Item 상세·수정 표면

## 기획 세션에서 정할 불변 계약 후보

아래는 결론이 아니라 검토 대상입니다.

| 영역 | 모든 Flow에서 같게 둘 후보 | 콘텐츠 유형별로 달라질 후보 |
| --- | --- | --- |
| 미리보기 | 현재 상태 표시, 결과 수량, 한 개의 주 CTA, 조정 진입 위치 | 결과 renderer, 준비 입력 |
| 조정 | 진입·닫기·적용 방식, 변경 전후 확인, 수정 가능 여부 표시 | 날짜 기준, 반복, 포함 항목 등 필드 |
| Item 수정 | 여는 방식, 저장·취소, 오류 처리 | 날짜·반복 등 해당 Item에 존재하는 필드 |
| 저장 | 내 Flow에 저장된다는 의미, 저장 전후 상태 변화 | 결과 유형과 수량 |
| 가져가기 | 범위·형식·수량 미리보기, 실행 위치 | 캘린더·체크리스트·시트·메모 결과 |
| My Flow | 열기·완료·되돌리기, 상세 진입 | 날짜형·반복형 보조 정보 |
| 출처 | 직접 원문 링크 | 위험도가 높은 내용의 주의 정보 |

## 검토자가 추가로 확인할 것

- 위의 후보가 실제 사용자 과업과 맞는지
- 공개 Flow와 My Flow에서 모양을 맞출 부분과 상태 때문에 다르게 둘 부분
- `할 일 / Flow`가 서로 다른 사용자 과업인지, 내부 구조를 노출한 것인지
- `실행 메모`와 `메모·일정`을 나눌 사용자 가치가 있는지
- route·slug 예외를 데이터 schema의 명시적 variant로 옮길 수 있는지
