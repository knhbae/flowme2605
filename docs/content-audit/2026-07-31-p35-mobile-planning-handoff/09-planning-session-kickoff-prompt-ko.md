## 이번 세션의 목표

- 사용자 피드백을 증상, 원인 가설, 결정 질문으로 분리
- 공통 UI와 콘텐츠별 변형의 경계 결정
- 저장 전부터 실행·가져가기까지 모바일 상태 모델 결정
- Flow 조정과 Item 수정의 화면 원칙 결정
- My Flow의 대표 과업과 정보 계층 결정
- 삭제, 통합, 필요할 때만 표시, 유지할 UI 결정
- P0·P1·보류와 수용 기준 결정

## 진행 방식

1. 먼저 현재 상태에 대해 `확인된 사실 / 해석 / 아직 모르는 것`을 정리하세요.
2. 결정을 바꾸는 정보가 부족할 때만 제품 소유자에게 한 번에 1~3개의 짧은 질문을 하세요.
3. 최소 두 개의 실제로 다른 구조 대안을 비교하세요.
4. 권고안은 MVP 범위와 코드 영향 범위를 함께 설명하세요.
5. 전면 재작성은 구조 사실로 필요성이 입증될 때만 제안하세요.
6. 제품 소유자가 권고안을 선택하기 전에는 구현하지 마세요.

## 반드시 결정할 순서

1. 사용자 상태: 미리보기, 조정, 저장, 실행, 가져가기
2. 상태별 주 행동 하나와 보조 행동
3. 공통 shell과 콘텐츠별 variant
4. Flow 전체 조정과 Item 수정
5. 공개 Flow와 My Flow의 공통 detail 계약
6. `할 일 / Flow`, 메모, 사본 관리의 정보 구조
7. 출처 링크와 중요한 주의의 노출 정책
8. P0, P1, 보류
