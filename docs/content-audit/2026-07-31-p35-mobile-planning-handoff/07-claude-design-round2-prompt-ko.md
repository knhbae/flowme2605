# Claude Design 2차 대조 작업 프롬프트

1차 독립 답변을 받은 뒤 `06-owner-feedback-normalized-ko.md`와 함께 아래 본문을 전달합니다.

---

이제 `06-owner-feedback-normalized-ko.md`를 읽어 주세요. 이 문서는 Production 모바일을 직접 사용한 제품 소유자의 관찰과 제안입니다. 외부 사용자 조사 결과는 아닙니다.

1차 독립 진단을 지우거나 사용자 의견에 맞춰 다시 쓰지 마세요. 먼저 작성한 판단을 기준으로 각 피드백을 대조해 주세요.

## 1. 피드백 대조표

모든 O·F·M 항목을 아래 중 하나로 분류하세요.

- 독립 검토에서도 확인됨
- 현상은 확인되지만 원인은 다르게 보임
- 일부만 확인됨
- 현재 증거로 확인할 수 없음
- 동의하지 않으며 다른 해결이 더 적절함

각 항목에 화면 증거 ID, 구조 사실, 판단 이유를 연결하세요.

## 2. 추가 발견

아래를 나눠 적으세요.

- 제품 소유자 피드백에는 없지만 1차 검토에서 발견한 문제
- 제품 소유자가 문제로 봤지만 유지해야 할 이유가 있는 요소
- 문제는 맞지만 제안된 해결 방식과 다른 해결이 나은 요소

## 3. 통합된 문제 정의

개별 증상을 나열하지 말고 3~5개의 근본 문제로 묶으세요. 각 문제에 아래를 포함하세요.

- 영향을 받는 사용자 상태
- 확인된 증거
- 원인 가설
- 해결하지 않을 때의 비용
- MVP에서 다룰 범위

## 4. 권고 UX 구조 한 가지

1차 대안 중 하나를 유지하거나 수정해 최종 권고안을 제시하세요. 다음을 구체적으로 적으세요.

- `Flow 찾기 → 미리보기 → 조정 → 저장 → My Flow → 실행 → 가져가기` 화면 흐름
- 각 화면의 주 행동과 보조 행동
- Flow 전체 조정과 Item 수정 표면
- 결과 미리보기와 가져가기 위치
- `할 일 / Flow`의 유지·변경 여부
- 메모와 일정 구조
- 중복 사본 정리 위치
- 출처 링크와 중요한 주의 정보의 노출 원칙
- 콘텐츠별 차이를 허용할 범위

간단한 모바일 wireframe과 상태 전환도를 포함하세요.

## 5. UI 정리 목록

다음 네 표를 만드세요.

1. 삭제할 UI
2. 합칠 UI
3. 필요할 때만 표시할 UI
4. 반드시 유지할 UI

각 항목에 현재 위치, 새 위치 또는 대체 방식, 근거, 데이터 보존 위험을 적으세요.

## 6. 아키텍처 판정

전면 재작성이 필요한지 아래 중 하나로 판정하세요.

- 현재 공통 코어 유지 + UX 표면 정리
- 공통 코어 유지 + route·variant·상태 모델 구조 개선
- 공통 코어 일부 교체
- 전면 재작성

화면 인상이 아니라 `03-architecture-facts-ko.md`와 변경 영향 범위를 근거로 설명하세요. 근거가 부족하면 추가 코드 검토가 필요하다고 표시하세요.

## 7. 실행 계획

`P0 / P1 / 보류`로 나누고 각 항목에 아래를 적으세요.

- 바뀌는 화면과 상태
- 재사용할 공통 컴포넌트 또는 새 계약
- 삭제할 예외
- 수용 기준
- 회귀 위험
- Codex가 코드에서 추가 확인할 사항

이번 답변에서도 코드를 작성하지 마세요. 최종 제품 결정과 구현 승인은 제품 소유자가 별도로 합니다.
