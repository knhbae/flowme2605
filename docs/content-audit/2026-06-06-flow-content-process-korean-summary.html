원 컨텐츠에서 Flow 컨텐츠를 뽑는 과정

2026년 6월 초에 진행한 한국어 원문 후보 발굴, AI 변환 결과 검토, 사용자 점수 반영, 변환 규칙 v2, UX/UI 적합성 점검을 한 화면에서 읽도록 다시 정리했습니다.

한눈에 보는 답

유지

Flow-able 컨텐츠는 “실행 모양”이 먼저 보여야 한다

날짜, 반복, 회차, 체크, 준비물, 제출, 예약, 결정 지점이 원문에 이미 있어야 좋은 후보로 남긴다.

주의

AI식 일반 정보글은 대표 후보로 약하다

글이 유용해도 제작자 경험, 댓글, 조회, 자료 요청, 후속 글 같은 상호작용 신호가 약하면 P0에서 내린다.

방향

Flow UI는 달력/리마인더 수준으로 얇게 유지한다

짧은 행동, 날짜/반복, 상태를 앞에 두고 방법, 준비물, 영상, 구매 링크, 출처는 상세 메모로 내린다.

이번 주 작업 메모

먼저 AI를 가르쳐 원 컨텐츠에서 Flow 컨텐츠를 뽑아본다. 결과가 usable하지 않으면 직접 원 컨텐츠를 찾고 사람이 Flow 컨텐츠를 제작한다.

실험실 UI

UX/UI 확인

판정 기준

기준 남기는 경우 내리는 경우
원문 실행 단서 날짜, 반복, 회차, 준비물, 체크, 제출/예약/결정 지점이 있음 설명은 많지만 사용자가 무엇을 해야 하는지 흐림
제작자성/상호작용 댓글, 조회, 자료 요청, 후속 글, 질문, 실제 경험이 보임 AI식 일반 정보글, 작성자 경험/이미지/반응이 약함
Flow 출력 형태 캘린더, 루틴, 체크리스트, 시트, 메모 중 하나로 자연스럽게 옮겨짐 Flow로 만들려면 새 구조를 많이 발명해야 함
원문 연결성 Flow 항목이 원문 내용과 직접 연결됨 원문 링크를 열어도 해당 근거를 찾기 어려움
민감/위험 경계 공식 정보, 제작자 경험, 주의를 분리할 수 있음 건강/법률/금융 판단처럼 보이거나 보장처럼 읽힘

UX 패턴

타임라인

결혼, 이사, 여행, 접종/검사

기준일 입력 → D-day 단계 → 짧은 캘린더 제목. 근거와 출처는 상세에 둔다.

반복 루틴

세탁기, 에어컨, 식물, 반려동물

반복 항목 1개에 내부 체크리스트를 붙인다. 캘린더 export에서는 description으로 넘긴다.

시트/표

필터, 이유식, 소모품, 독서 목록

행 단위 상태와 다음 날짜를 관리한다. 모바일에서는 표가 아니라 카드형 행으로 보여준다.

결정형

중고차, 사전점검, 셀프수리

완료/미완료 대신 구매, 보류, 거절, 업체 예약, 공식 확인 필요 같은 상태가 핵심이다.

공부/챌린지

컴활, 한능검, 30일 챌린지

회차/일차/챕터 표와 오늘 할 캘린더 블록을 분리한다. 완료가 결과 보장을 뜻하지 않게 한다.

루틴 + 카드

아이 놀이, 그림책, 영상, 공부 자료

고정 루틴에 이번 주 콘텐츠 카드를 매핑한다. 단독 Flow로 만들면 원문과 UX가 어색할 수 있다.

대표 후보 흐름

단계 강하게 남은 후보 내린 이유
초기 30개 결혼, 중고차, 컴활, 가전/식물 루틴 일부 교사용 계획안, AI 느낌 글, 개인이 따라 하기 어려운 원문은 약함
31개 UX 후보 결혼, 이사, 중고차, 세탁기, 에어컨, 스투키, 이유식, 플랭크 대상 프로필, 카드 매핑, 결정 상태 같은 새 UX 과제가 생김
사용자 점수 반영 컴활, 강아지 입양, 세탁기, 에어컨, 중고차, 그림책, 여행, 결혼 높은 점수여도 AI 느낌 원문은 대표 후보에서 최대한 제외
규칙 v2 이후 컴활 클러스터, 신축 사전점검, 세탁기, 에어컨, 결혼, 이사, 중고차, eSIM, 강아지 입양 제작자/상호작용 신호가 약한 후보는 P1/P2로 내림

날짜별 상세 메모

06-01: 후보 수집과 첫 사용자 평가

개인이 따라 하기 어려운 계획안, AI 느낌이 강한 정보글, 댓글/좋아요/후속 질문이 없는 원문은 대표 후보로 약하다는 판단이 나왔다.

  • 강하게 남은 유형: 결혼/이사 타임라인, 중고차 체크, 컴활 후기형 플랜.
  • 보류된 유형: 교사용 계획안, 일반 정보글, 원문이 너무 넓은 설명형 콘텐츠.
06-02~06-03: 31개 평가 UI와 변환 규칙 v2
  • 반복 루틴은 캘린더 항목 여러 개가 아니라 항목 1개 + 내부 체크리스트가 적합하다.
  • 외부 캘린더로 내보낼 때 내부 체크리스트는 이벤트 메모/description으로 이동한다.
  • 결정형 Flow는 완료 대신 구매/보류/거절/업체 예약 같은 상태가 필요하다.
  • 제작자성/상호작용 신호를 원문 적합성과 별도로 본다.
06-04~06-05: 생성 결과 재검토와 UX/UI 타입 확인
  • 국가장학금은 좋은 후보였고, 주택청약은 원문-Flow 연결성이 낮았다.
  • 표형 후보가 일반 체크리스트처럼 보이지 않도록 sheet-board가 필요하다.
  • 중고차는 단순 체크리스트가 아니라 decision-board가 맞다.
  • 모바일에서는 체크박스, 날짜/주기, 제목/완료 기준의 정렬이 유지되어야 한다.
