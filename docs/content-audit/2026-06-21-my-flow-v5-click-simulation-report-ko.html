내부 클릭 시뮬레이션

My Flow v5는 기본 실행 홈으로 통과, 기능 확장은 조건부로 남긴다

저장 1개, 4개, 8개, 24개 상태를 모바일 390px에서 열고 체크, 메모, Flow 찾기, 검색, 날짜 전환, 더 보기 동작을 확인했다. 이 리포트는 내부 UX 검토이며 실제 사용자 검증이 아니다.

Blocking 0 High 0 Medium 3 모바일 overflow 0

요약 판단

v5를 유지하고, v6는 새 기능 추가가 아니라 조건부 표면 검증으로 좁힌다

1개 저장탭 없이 현재 Step 상세만 보이는 구조가 맞다. 체크와 메모만으로 충분하며, 나중에 보기나 큰 완료 버튼은 필요하지 않다.
4-8개 저장오늘 항목과 Flow 찾기만으로 기본 탐색이 가능하다. 검색 결과 선택 후 검색 패널이 닫히고 검색어가 초기화되는 동작도 맞다.
20개 이상 저장처음부터 전체를 펼치지 않고 4개/8개 단위로 보여주는 방향은 맞다. 다만 일정형이 많아지면 캘린더 보조 화면이 필요해질 수 있다.

Medium 20개 이상 저장 초기 4개/8개 노출은 맞지만, 장기적으로는 검색과 그룹 접기가 더 필요하다. 관찰 전에는 첫 화면에 올리지 않고 Flow 찾기 안에 유지

다음 반복

v6에서 볼 것은 “기능 추가”가 아니라 조건부 보조 보기다

  1. v5 첫 화면은 유지한다.
  2. 날짜형 Flow가 많을 때만 열리는 일정 보기 후보를 만든다.
  3. 진도형 Flow가 선택됐을 때만 접힌 전체 진도 보기 후보를 만든다.
  4. 20개 이상 저장 상태에서는 Flow 찾기 안에서 검색과 전체 보기 균형을 다시 본다.
  5. 새 기능이 첫 화면의 가벼움을 해치면 v5로 되돌린다.
