Creator Publish Gate와 Step 계약을 분리해서 고정

이번 점검은 화면을 더 늘리는 작업이 아니라, 공개 저장 화면, 제작자 편집 화면, 내 Flow 실행 화면이 서로 섞이지 않도록 제품 계약을 코드와 테스트에 고정하는 작업입니다.

사용자/제작자 화면 분리 Step = 저장 최소 단위 Step 수정값 → 텍스트/ICS Item = 체크리스트 또는 text fallback 실사용 검증은 아직 필요

핵심 결정

Public route
저장 전 사용자 화면

원문 근거와 저장 결과를 보여주되 제작자 초안, 리뷰 점수, 내부 문구는 숨깁니다.

My Flow
저장 후 실행 화면

Step을 누르면 같은 자리에서 상세가 열리고, 날짜/반복/메모를 가볍게 수정합니다.

Creator route
원문 행을 Step으로 바꾸는 화면

source row, Step title, destination, Item fallback을 다루고 실행 UI는 보여주지 않습니다.

이번에 추가로 닫은 부분

My Flow Step 상세에서 날짜, 시간, 반복, 장소, 메모, Item 체크 상태를 수정하면 그 값으로 다시 메모앱에 복사 텍스트와 캘린더 파일 받기 ICS를 만듭니다. 이 액션은 첫 화면에 노출하지 않고, 사용자가 Step을 열었을 때만 보입니다.

Mobile single Flow

Step 계약

저장된 Flow Map은 이제 child Flow 아래에 Step 계약을 함께 보관합니다. 이 계약이 있어야 나중에 캘린더, 투두, 시트, 메모 export를 같은 데이터에서 다시 만들 수 있습니다.

필드 역할 사용자 UX 영향
stepId, title Step 식별자와 사용자에게 보일 제목 오늘/일정/Flow 탭에서 같은 Step을 추적합니다.
destination calendar, checklist, sheet, memo, progress 등 저장 형태 Flow마다 억지로 같은 UI를 쓰지 않게 합니다.
calendar 날짜, 기준일 offset, 반복, 기간 정보 Step 하나가 캘린더 일정 수준의 정보를 가질 수 있습니다.
textFallback 설명, Item 목록, 완료 기준, 메모 힌트, URL FlowMe 안에서는 체크리스트, 외부 앱에서는 텍스트로 내려갈 수 있습니다.
sourceUrl, riskLevel 원문 근거와 민감도 상세 정보는 필요할 때만 열고, 민감 후보는 자동 업데이트하지 않습니다.

대표 후보 상태

후보 현재 판단 이번 계약에서 확인한 점
이사 D-30 대표 후보 이사일 입력 후 D-30 기준 Step들이 calendar 계약과 Item fallback을 갖습니다.
중1 수학 후보 진도형 Step은 날짜를 강제하지 않고 progress destination과 단원 Item을 유지합니다.
영유아 검진/접종 Revise 공식 일정과 민감도 계약은 유지하되, 홈 대표 노출은 계속 막습니다.

남은 일

  • Todo/sheet export도 Step 수정값에서 재생성하는 후속 구현.
  • 제작자 publish를 로컬 초안이 아니라 계정/버전 기반 발행으로 확장할지 판단.
  • 영유아 검진/접종처럼 계약은 있지만 컨텐츠 품질이 약한 후보는 source와 action item을 다시 다듬기.
  • 실제 사용자 세션 없이 검증됐다고 표현하지 않기.
