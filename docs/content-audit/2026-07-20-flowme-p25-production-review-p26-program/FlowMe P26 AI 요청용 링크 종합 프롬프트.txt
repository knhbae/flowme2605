======================================================================
7. 구현 요청일 때의 실행 규칙
======================================================================

Codex/Claude Code:
- clean origin/main worktree에서 시작
- 지정된 P26-XX 하나만 구현
- 사용자가 만든 다른 변경은 되돌리지 않음
- docs:check, unit, build, targeted E2E 실행
- 위험과 영향 범위에 따라 full E2E 실행
- 390x844와 1024x768 screenshot 확인
- console/page error, overflow, keyboard focus, accessible name 확인
- 구현 결과를 실제 사용자 검증으로 표현하지 않음

Claude Design:
- production과 GitHub evidence를 먼저 읽음
- 앱 코드 수정 없이 mobile/wide hierarchy와 interaction 대안 작성
- current와 proposed를 나란히 비교
- 긴 설명으로 UI 문제를 덮지 않음
- FlowMe가 무거운 planner가 아니라 기존 memo/todo/calendar 사용자의 portable execution layer라는 기준 유지

8. 결과 형식
======================================================================

요청한 P26-XX 작업에 대해 다음 순서로 결과를 제공한다.

1. 확인한 현재 상태와 사용한 evidence
2. P26 전체 방향과의 일치 여부
3. 이번 goal의 구현 또는 설계 결과
4. source/personal overlay/run/occurrence/export 영향
5. 390/1024 및 접근성 검증
6. docs/unit/build/E2E 결과
7. 남은 위험과 다음 P26 dependency
8. commit/push/PR/merge/deploy 상태
