결정

URL-first의 첫 public 적용 위치는 /flows다. Claude Design 03은 Home에서 시작하는 장면까지 그렸지만, 현재 서비스 구조상 Home은 약속과 대표 시작점이고 /flows가 발견/탐색 job을 소유한다. URL을 붙여 기존 Flow를 찾는 행동은 생성보다 탐색에 가깝다.

따라서 production P1은 /flows 상단에 작고 명확한 URL로 Flow 찾기 입력을 추가하고, 결과는 기존 catalog를 밀어내지 않는 result sheet 또는 inline panel로 둔다.

P1 Backlog - 다음 구현 후보 3개

  1. /flows URL lookup strip

    상단 검색 근처에 URL로 Flow 찾기 입력을 추가한다. URL이면 canonical lookup, 일반 키워드면 기존 catalog search로 분리한다. AI 호출은 0회여야 한다.

  2. URL result sheet 상태 정리

    hit, needs_review, miss 3개만 public에 먼저 둔다. hit는 기존 route와 export preview, needs_review는 gate, miss는 검토 요청/URL 저장으로 분리한다. 내부 라벨은 제거한다.

  3. memo draft private path 분리

    메모 초안은 /flows 기본 URL lookup에서 빼고, 만들기/가져오기 또는 My Flow empty state의 메모에서 만들기로 이동한다. 공유 Flow 전환은 원문/근거 gate가 준비된 뒤 연다.

Findings

  1. High - Entry placement: Home에 URL input을 바로 올리면 Claude storyboard와는 맞지만 현재 IA에서 Home이 다시 복잡해진다. 첫 적용은 /flows가 맞다.
  2. High - State copy: 현재 lab은 상태 판정은 맞지만 HIT, Canonical, needs_review, sourceStatus가 그대로 보인다. public 전 사용자 언어로 바꿔야 한다.
  3. Medium - Miss state: miss preview가 needs_review와 같은 gate 문구를 재사용한다. unknown URL은 "검토 요청/대기"로 별도 설계해야 한다.
  4. Medium - Memo competition: memo_draft는 중요하지만 URL lookup의 첫 public 장면에 같이 두면 제품 초점이 흐려진다.
  5. Low - Export preview: hit의 export preview는 방향이 맞다. 다만 Calendar, Markdown, Checklist tab 라벨은 실제 결과 중심 문구로 바꿔야 한다.
