FlowMe 분석방 / 공유 패킷 롤업 이후 판정 가이드
작성일 2026-06-11 · 상태: 판정 가이드, 증거 아님

롤업 이후 다음 행동을 잘못 승격하지 않게 고정하는 가이드

이 문서는 school-dorm-share-packet-v2-2026-06-11-readable-preview의 롤업 결과를 다음 행동으로 바꾸는 표다. `candidate signal`이 나와도 public route나 플랫폼 연동이 아니라 `/content-flows` review candidate 준비까지만 허용한다.

전제: 3 completed usable sessions 이후 현재: no signal · 0 / 3 · agreed slot 이후 관찰 허용 판정: no signal / friction / candidate signal 금지: public route · integration · validation

1. 시작 조건

이 조건을 모두 만족해야 한다

  • 모든 세션에서 같은 패킷 버전을 사용했다.
  • 3개 이상 completed usable recipient session이 있다.
  • 롤업 템플릿에 선택된 판정이 하나만 있다.
  • 민감값이 기록되지 않았다.

하나라도 빠지면

이 가이드를 사용하지 않는다. evidence board는 `no signal`로 유지하고 세션을 다시 실행한다.

2. 판정별 다음 행동

no signal

관찰 세트가 부족하거나 기록이 모호하다.

다음 행동: evidence board를 유지하고 같은 패킷 버전으로 다시 관찰한다.

friction

라벨, 최신 공지, 민감값 제외, 수동 복사, 모바일 가독성 중 혼동이 남았다.

다음 행동: 공유 패킷 문구나 레이아웃을 수정하고 파일럿을 다시 실행한다.

candidate signal

첫 run 3개 세션이 이해 기준을 통과했다.

다음 행동: 후보 준비 템플릿을 먼저 채운 뒤 `/content-flows` review candidate만 준비한다. public route는 만들지 않는다.

3. 결정 매트릭스

롤업 판정 의미 허용 행동 계속 막는 것
no signal 세션 부족, 조건 불일치, 기록 모호 세션 재실행 후보 준비, public route, integration
friction 이해 혼동이 남음 패킷 문구 수정 후 재관찰 후보 준비, public route, 자동화
candidate signal 첫 run 3개 세션이 기준을 통과 `/content-flows` review candidate 준비 public `/f/...`, 플랫폼 연동, 자동 게시, 답변 수집, 연락처 저장

4. candidate signal일 때만 준비할 것

review candidate에 붙일 것

  • source URL, caution, completion criteria
  • 응답 라벨과 최신 공지 우선 문구
  • health, payment, identity, room, channel, invite, form edit, webhook, contact, chat-log 값의 no-store 문구
  • FlowMe는 발송, 게시, 답변 수집, 연락처 저장, 채널 추적을 하지 않는다는 문구

여전히 만들지 않을 것

  • KakaoTalk, Naver Cafe, Forms/Sheets, Notion, Slack, Teams, Discord 연동
  • 자동 게시, 답변 수집, 연락처 저장, 채널 분석
  • public route, validated, integration ready 표현

5. evidence board 업데이트

  1. evidence board 업데이트 절차를 먼저 연다.
  2. 선택된 판정 라벨 하나만 업데이트한다.
  3. 채워진 rollup을 링크한다.
  4. 다음 행동을 `rerun`, `revise packet`, `prepare content-flows review candidate` 중 하나로 쓴다.
  5. 금지된 제품 주장과 플랫폼 연동 표현은 쓰지 않는다.
