Claude Design 피드백 시나리오 보드

사용자의 최신 피드백을 Claude Design이 바로 이해할 수 있도록 시나리오, route, 판단 질문, 디자인 숙제, 우선순위로 분리한 보드다. 앱 구현 지시가 아니라 다음 디자인/제품 리뷰를 위한 작업 관리 표면이다.

기준일: 2026-07-09 핵심 문장: URL/메모 -> Flow -> 내 Flow/캘린더 현재 판단: studio는 secondary 우선순위: Calendar/My Flow/public /f/URL-first

우선 결론

P0

실행면부터 다듬기

Calendar, My Flow, public `/f`, URL hit customization은 사용자가 이미 막힘을 느낀 핵심 실행면이다.

P1

Miss -> AI 초안은 concept

AI draft는 private draft로 시작해야 하며, canonical Flow나 public demand로 바로 승격하면 안 된다.

P2

Studio는 보조 표면

Creator/studio는 중요하지만 아직 5번째 탭이 아니다. 실제 콘텐츠 fixture로 개념 검증만 먼저 한다.

사용자 피드백 매핑

영역 사용자 피드백 디자인 문제 Claude Design 숙제
Core flow 큰 흐름은 이해된다. 문장은 통하지만 실행면의 완성도가 낮으면 제품 신뢰가 떨어진다. Home -> Flow finding -> My Flow -> Calendar가 한 문장으로 이어지는 storyboard.
Calendar Flow 구분이 안 되고 색상이 같으며, `일정` 라벨이 약하다. Calendar가 보관 데이터처럼 보이고 실행 화면으로 읽히지 않는다. Flow별 색상/accent, event title 구조, same-day grouping, selected-day agenda 재설계.
URL hit Step 제외는 되지만 수정 자유도가 낮아 보인다. 플랫폼/개인화 기대에 비해 custom start가 너무 얇다. calendar event 수준의 lightweight edit 모델 제안.
URL miss 초안 만들기 -> AI 초안 -> 사용자 수정 흐름이 있으면 좋겠다. 현재 miss는 후보 저장으로 닫혀 있어 즉시 가치가 약할 수 있다. AI draft를 private draft로 두는 P1 concept flow.
Public `/f` Export가 Step 단위에 치우쳐 보이고 Flow/Step 저장 공존이 숙제다. 저장과 export의 주/보조 위계가 흔들릴 수 있다. Flow 전체 저장, Step만 저장, 저장 전/후 export 위치 모델.
My Flow 오늘 할 일 체크까지 depth가 많다. 실행 허브가 아니라 inventory/detail 탐색처럼 느껴질 수 있다. Today first action, one-tap check, Step detail hierarchy 재설계.
Studio 지금 키울지 기본 화면부터 고칠지 고민이다. creator platform으로 너무 빨리 가면 action compiler 기준이 흐려진다. secondary surface로 concept validation만 수행.

시나리오별 디자인 요청

A

첫 방문

//flows/my/calendar

질문: “URL/메모를 실행 가능한 Flow로 바꾸고 내 실행 공간과 캘린더로 이어진다”가 5초 안에 보이는가?

산출: 모바일 4장 이상, 데스크톱 2장 이상, CTA hierarchy 제안.

B

URL hit

/flows/my/calendar

질문: 기존 Flow 재사용으로 보이는가, Step 제외만으로 충분한가, 최소 edit 범위는 어디까지인가?

산출: direct start와 custom start 비교, Step/item edit 최소 모델.

C

URL miss

/flowscandidateAI draft concept

질문: Miss가 막힘이 아니라 이어갈 요청으로 보이는가? AI draft는 private draft로 안전하게 시작하는가?

산출: miss -> candidate -> draft -> user edit -> My Flow/production handoff flow.

D

Public `/f`

/f/vehicle-inspection-prep/f/moving-d30-basic

질문: 공유받은 사용자가 Flow 전체 저장, Step만 저장, export 중 무엇을 언제 선택해야 하는가?

산출: 저장 primary, Step-save secondary, export destination 위치 모델.

E

My Flow

/my?savedMap=moving-d30/my?savedMap=middle-school-math-1

질문: 오늘 할 일 체크가 첫 화면에서 바로 가능한가? 중요한 정보가 너무 깊지 않은가?

산출: Today first action, one-tap check, Step detail collapsed hierarchy.

F

Calendar

/calendarsame-day multiple events

질문: Calendar가 핵심 실행 화면처럼 보이는가? Flow 구분과 같은 날짜 다중 이벤트가 해결되는가?

산출: event color/accent, Flow grouping, agenda-first mobile pattern, event title rules.

G

Creator / Studio

/u/flow-curation-team/u/my-flow-studio

질문: Studio는 지금 핵심 축인가, secondary surface인가? Fresh/filled 상태가 자연스러운가?

산출: public creator profile, personal studio empty/filled concept, 5번째 탭 보류 판단.

P0/P1/P2 순차 작업

P0

기본 실행면

  • Calendar Flow 구분과 다중 이벤트 처리
  • My Flow 오늘 할 일 depth 축소
  • Public `/f` 저장/export 위계
  • URL hit custom start 수정 범위
P1

초안과 edit 모델

  • URL miss -> AI draft concept
  • calendar event 수준의 Step edit
  • private draft와 canonical Flow 경계
  • Flow/Step 저장 선택 모델
P2

Studio/creator

  • 실제 콘텐츠 creator profile
  • fresh/filled my-flow-studio 상태
  • user-added Step과 creator feedback loop
  • 5번째 탭 승격 보류
