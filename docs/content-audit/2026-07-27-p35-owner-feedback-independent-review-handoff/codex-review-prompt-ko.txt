======================================================================
3. 제품 목표와 현재 P35 방향
======================================================================

FlowMe는 캘린더, 할 일 앱, 노션을 대체하는 무거운 planner가 아니다.

원문 URL 또는 메모
→ 실행 가능한 전체 결과 확인
→ 필요한 최소 개인화
→ FlowMe에 저장하거나 기존 도구로 가져가기
→ 실행·완료·다시 열기
→ 수정·기록·재사용

을 연결하는 portable execution layer다.

P35 후보안은 다음을 구현했다.

1. 전역 탐색을 Flow 찾기 / 캘린더 / 내 Flow 3개로 단순화
2. public Flow에서 설명보다 실제 결과를 먼저 표시
3. 저장 전 한 번에 한 종류의 조정만 열기
4. 내 Flow를 저장 목록과 focused workspace로 분리
5. Calendar를 날짜가 있는 실행 항목의 lens로 제한
6. 가져가기를 whole/selected/current 범위와 개수부터 확인

이 방향은 자동화 gate를 통과했지만 실제 사용자 이해도는 검증되지 않았다.
이번 검토에서는 잘못됐으면 구조를 다시 열 수 있다.

유지할 데이터 계약:
- source / published Flow
- personal overlay / personal structural overlay
- execution run
- recurrence series / occurrence
- whole / selected / current export identity
- 기존 localStorage key와 saved data

UI 대안은 이 계약을 소비해야 한다. 새 임시 identity나 별도 projection을 만들지 않는다.

4. 사용자 피드백 F01~F07
======================================================================

F01. Flow 조정에서 항목 상세 내용과 개별 날짜 수정이 필요해 보인다.
현재 UI를 full editor로 만들기보다 contextual Item edit를 연결할 수 있는지 평가한다.

F02. 저장 완료 후 곧바로 다음 행동 또는 오늘 할 일 중심 화면으로 보내는 것이 필요한지
검토한다. 저장한 전체 결과를 먼저 확인하는 편이 맞을 수 있다.

F03. 날짜형 Flow의 다음 할 일은 한 행이 아니라 같은 날짜의 미완료 항목을 묶어
보여 주는 편이 자연스러운지 검토한다. 이 규칙을 날짜 없는 Checklist, routine,
sheet에 강제하지 않는다.

F04. Flow 찾기/public preview에서 자연스러운 Calendar, Checklist/Todo, Sheet,
Memo, Routine 결과를 먼저 확인하고 FlowMe 저장 또는 외부 도구 가져가기를 선택해야
하는지 검토한다. 다섯 고정 탭을 되살리지 말고 primary 1개와 eligible secondary
최대 2개를 비교한다.

F05. 완료한 항목이 현재 목록에서 사라지는 경우에만 즉시 되돌리기를 강조하고,
행이 남으면 checkbox 자체로 다시 여는 정책이 맞는지 검토한다. 완료, 제외, 삭제,
날짜 이동, 보관의 복구 정책을 구분한다.

F06. 내 Flow의 다음 행동 탭이 날짜, Checklist, routine, sheet에서 무엇을 뜻하는지
모호하다. shape-specific label 또는 탭 제거를 비교한다.

F07. 기록 탭에 완료 history, held occurrence, 회고, 다시 쓰기가 섞여 있다.
진행 기록으로 좁힐지, Item memo와 Flow reflection을 문맥별로 옮길지 검토한다.

사용자 피드백을 그대로 정답으로 사용하지 말고 evaluation-matrix.json의 대안을
비교해 supported / partly_supported / rejected / needs_observation으로 판정한다.

- 1024x768
- 60개 library 또는 wide workspace는 1440x900

각 시나리오는 세 session으로 본다.

Session A:
발견 → 전체 결과 → 조정 → artifact 확인 → FlowMe 저장 또는 외부 가져가기

Session B:
저장 receipt → 전체 저장 결과 → 다음 실행 묶음 → 완료 → 다시 열기 → 항목 수정

Session C:
기록 → 단계 메모/회고 → 전체·선택·현재 가져가기 → 새 실행으로 다시 쓰기

localStorage fixture를 사용했다면 fixture 기반 검증이라고 명시한다.
자동화 클릭 성공을 사용성 검증이라고 표현하지 않는다.

6. 전체 검토 범위
======================================================================

1. 3탭 entry router와 Home 제거가 맞는가

7. 긴 설명 대신 visual hierarchy와 실제 artifact로 이해되는가
8. 390/1024에서 keyboard, focus return, accessible name, overflow, fixed layer가 안정적인가

공식 reference pattern은 reference-patterns.md의 링크를 사용한다.
화면 모양을 복제하지 말고 surface ownership과 상태 전이만 비교한다.
