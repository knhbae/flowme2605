Source-to-Flow Conversion Gate

10개 후보 재심사 결과

기존 10개 화면을 고치는 대신, 원컨텐츠 1개를 기준으로 다시 판정했다. 사용자가 저장해서 실행할 자연 산출물이 명확한 후보만 새 사용자 화면으로 옮겼고, 약한 후보는 보류하거나 교체했다.

이번 판정 원칙

1

원컨텐츠 하나

여러 링크를 섞어 완성형 가이드를 만들지 않았다. 보조 링크는 구조를 바꾸지 않는 경우에만 허용했다.

2

destination 우선

캘린더, 체크리스트, 표, 버킷, 순서 목록 중 어디로 옮겨질지 먼저 정한 뒤 UI를 만들었다.

3

입력 최소화

상위 입력은 artifact 생성에 필요한 날짜만 남겼다. URL, 파일명, 안내문, 업체명은 상세 메모로 내렸다.

Figma는 사용하지 않았다. 이번 단계의 문제는 시각 polish가 아니라 원문 구조와 사용자 artifact 변환의 문제였기 때문이다. HTML에서 클릭 가능한 저충실도 화면을 먼저 만든 뒤, 살아남은 패턴만 나중에 Figma로 정리하는 순서가 맞다.
