My Flow v9 원문 기반 리허설

v8의 간단한 My Flow UI 틀은 유지하고, 화면 안의 Flow 데이터를 실제 원문 구조가 확인되는 항목으로 교체했다. 사용자용 PoC에는 내부 평가 문구를 넣지 않고, Step 상세에는 실행에 필요한 원문 링크만 남겼다.

사용자 화면 오늘, 일정, Flow, 지도 탭만 유지. 내부 평가·설명 문구는 제거.
Flow 데이터 원문 구조가 확인되는 전세, 이사, 여권, 중1 수학, 영유아 검진·접종만 사용.
계층 기준 Flow Map > Flow > Step > Item. Step은 캘린더/투두 최소 단위, Item은 체크리스트 또는 text fallback.

의도적으로 뺀 것

수 채우기보다 원문 충실도를 우선했다

  • 홈트, 스퀴시, 식물 등은 이번 v9 사용자 화면에서 제외했다. 현재 파일 기준으로는 원문 링크와 실제 세부 구조가 부족해 다시 넣으면 이전처럼 억지 Flow가 될 가능성이 높았다.
  • 진행 페이스, 의미 불명 상태 버튼, 별도 복사 버튼, 내부 평가 문구는 넣지 않았다.
  • 각 Step의 ICS/캘린더 이벤트 속성은 이번 화면에 노출하지 않았다. 다만 Step이 일정 최소 단위라는 전제를 유지했으므로 이후 데이터 모델에서 `start`, `end`, `allDay`, `url`, `description` 같은 필드로 확장할 수 있다.

남은 판단

다음에 볼 것

  • 현재는 UI shell과 원문 기반 fixture의 적합성 검증이다. 실제 상품화 전에는 저장된 Flow가 30개 이상일 때 필터·검색·카테고리 밀도를 다시 봐야 한다.
  • Step의 일정 데이터는 지금 화면에 보이는 날짜보다 더 정교해야 한다. 이후 ICS 수준으로 시작일, 종료일, 반복, 알림, URL, description을 모델링해야 한다.
  • 홈트, 스퀴시, 식물처럼 제외한 카테고리는 원문 1개를 다시 잡고 Flow 변환표를 먼저 만든 뒤 사용자 화면에 넣어야 한다.
